## 摘要
边缘设备上的 LLM 推理受限于计算和内存资源，使得高效的自回归解码颇具挑战。推测解码通过使用较小的草稿模型生成词元，并用一次批处理的目标模型前向传播并行验证多个词元，从而缓解这一瓶颈。然而，验证过程引入了一种运行时相关的中间态，介于解码阶段受内存限制的通用矩阵-向量（GEMV）运算与预填充阶段受计算限制的通用矩阵-矩阵（GEMM）运算之间，因为其算术强度随推测长度和接受率而变化。我们提出 SPECTRA，一种运行时可重构的瓦片式架构，可在整个推测解码流水线中保持高利用率。在每个瓦片内，计算引擎可在用于 GEMM 的脉动式执行与用于 GEMV 的向量通道执行之间切换。在瓦片之间，SPECTRA 通过选择瓦片数量、内核划分和通信模式来动态调整计算并行度。瓦片级和系统级重构均以逐内核方式进行，从而能够在这些多样的工作区间中实现高效执行。在涵盖 Pythia、SmolLM2 和 GPT-2 系列的 20 瓦片 FPGA 原型上进行评估，相比固定设计，SPECTRA 通过瓦片级重构实现了最高 2.09 倍的加速，并进一步通过系统级自适应获得了 1.25 倍的增益。

## Abstract
LLM inference on edge devices is constrained by computational and memory resources, making efficient autoregressive decoding challenging. Speculative decoding alleviates this bottleneck by generating tokens with a smaller draft model and verifying multiple tokens in parallel with a batched target model pass. However, verification introduces a runtime-dependent intermediate regime between memory-bound general matrix-vector (GEMV) operations in decoding and compute-bound general matrix-matrix (GEMM) operations in prefill, as its arithmetic intensity varies with speculation length and acceptance rate. We present SPECTRA, a runtime-reconfigurable tiled architecture that sustains high utilization across the full speculative decoding pipeline. Within each tile, the compute engine switches between systolic execution for GEMMs and vector-lane execution for GEMVs. Across tiles, SPECTRA dynamically adapts computation parallelism by selecting tile count, kernel partitioning, and communication pattern. Both tile-level and system-level reconfiguration operate on a per-kernel basis, enabling efficient execution across these diverse regimes. Evaluated on a 20-tile FPGA prototype across the Pythia, SmolLM2, and GPT-2 families, SPECTRA achieves up to $2.09\times$ speedup from tile-level reconfiguration and a further $1.25\times$ gain from system-level adaptability over fixed designs.

## 1. 核心问题与整体含义

- **边缘 LLM 推理瓶颈**：自回归解码逐 token 生成，每步需完整前向传播，计算以 GEMV 为主，算术强度低，受内存带宽和片上容量限制，计算资源利用率低。
- **投机解码的收益与代价**：用轻量 draft 模型一次预测 \(\gamma\) 个 token，再用 target 模型并行验证 \(\gamma+1\) 个 token，将多次串行 GEMV 合并为一次 GEMM，减少 target 模型调用次数，提高吞吐。
- **新问题：运行时相关的中间计算区间**：投机解码验证阶段的算术强度随推测长度 \(\gamma\) 和接受率变化，位于内存受限的 decode GEMV 与计算受限的 prefill GEMM 之间。
- **固定架构难以覆盖全流程**：vector-only 设计在 prefill/验证阶段低效，systolic-only 设计在 draft decode 阶段低效；固定分片和静态通信映射也无法适应不同 phase 的并行度与数据复用需求。
- **论文目标**：提出 SPECTRA，一种运行时可重构瓦片式架构，在 tile 内自适应切换 GEMM/GEMV 数据流，在 tile 间按 kernel 动态选择 tile 数量、分片轴和通信模式，从而在整个投机解码流水线中保持高利用率。

## 2. 方法论

### 2.1 总体思想

- SPECTRA 由多个可重构加速器 tile、NoC、分布式内存子系统和 host processor 组成。
- 重构分两级：
  - **Tile 级**：每个 tile 的计算引擎按 kernel 粒度在 systolic 模式与 vector-lane 模式间切换。
  - **系统级**：host 按 kernel 选择 tile 分配、分片策略、通信原语，并支持 inter-kernel pipelining。
- 关键动机：投机解码包含 prefill、draft decode、batched verification 三类 kernel，计算形态和并行需求不同，必须同时协调 tile 内数据流与 tile 间通信。

### 2.2 Tile 内可重构计算引擎

- 每个 tile 集成 4 个双缓冲本地内存：activations、weights、partial sums、outputs，支持数据搬运与计算重叠。
- 计算引擎核心为 **8×8 PE 阵列**，共 64 个 MAC PE；本地内存多 bank 化：64-bank weight memory，8-bank input/psum/output memory。
- 两种执行模式：
  - **Systolic 模式**：用于 \(M>1\) 的 GEMM，如 prefill 和 batched verification。权重逐列流入，激活按行偏移注入，形成对角波前，PE 本地累加，输出固定。
  - **Vector-lane 模式**：用于 \(M=1\) 的 GEMV，如 autoregressive draft decode。PE 阵列被重解释为 8 条独立点积 lane，单激活广播，weight memory 重索引，使 64 bank 并行访问，每周期取一个 \(8\times8\) 权重子块。
- 两种模式复用同一 PE 阵列和算术单元，运行时只改变控制逻辑与内存索引，不复制计算阵列。
