## 摘要
大语言模型（LLM）推理正在从引擎本地的优化问题，演变为一个分布式控制问题，涉及可复用状态、阶段放置、异构加速器、网络、自动扩缩容、可靠性以及服务级别目标。本文通过同行评审的系统研究、开源实现和已有记录的生产研究，将这一转变串联起来。本文将 vLLM 和 llm-d 视为互补的层次：模型服务引擎通过 PagedAttention、连续批处理、内核、量化和并行等机制优化执行，而推理控制平面则可以优化执行在整个机群中发生的位置、时间以及所依据的策略。本文的贡献在于综合梳理，而非提出新的基准；所有报告的性能和部署结果均仍归因于其原始来源。综合证据表明，现代推理中的稀缺资源正从单纯的原始 FLOPs 转向受管理的状态、放置、网络传输、可靠性和决策质量。我们提出一个推理执行规划器（Inference Execution Planner），它选择可行的执行计划，而不仅仅是端点，包括聚合式与解聚式拓扑、KV 来源与传输动作、硬件变体、路由/准入策略，以及较慢的扩缩容决策。我们还提供了一个按原始来源组织的基准图谱、一个瓶颈迁移分类体系、实用的部署指南、一个基于 SLO-goodput 的评估框架，以及面向智能体、多模态、异构和弹性推理的研究问题。

## Abstract
Large language model (LLM) inference is evolving from an engine-local optimization problem into a distributed control problem involving reusable state, phase placement, heterogeneous accelerators, networking, autoscaling, reliability, and service-level objectives. This paper connects that transition across peer-reviewed systems research, open-source implementations, and documented production studies. It treats vLLM and llm-d as complementary layers: model-serving engines optimize execution through mechanisms such as PagedAttention, continuous batching, kernels, quantization, and parallelism, while an inference control plane can optimize where, when, and under what policy execution occurs across a fleet. The contribution is synthesis rather than a new benchmark; all reported performance and deployment results remain attributed to their original sources. The combined evidence suggests that the scarce resource in modern inference is shifting from raw FLOPs alone toward managed state, placement, network movement, reliability, and decision quality. We propose an Inference Execution Planner that selects feasible execution plans rather than only endpoints, including aggregated versus disaggregated topology, KV source and transfer action, hardware variant, routing/admission policy, and slower scaling decisions. We also provide a source-local benchmark atlas, a bottleneck-migration taxonomy, practical deployment guidance, an evaluation framework based on SLO-goodput, and research questions for agentic, multimodal, heterogeneous, and resilient inference.

## 1. 核心问题与整体含义

- **背景转变**：LLM 推理已从"让单个模型在一个加速器上高效处理请求"的引擎本地优化问题，演变为跨机群的**分布式控制问题**——需要协调可复用状态（KV cache）、阶段（prefill/decode/encode）、异构加速器、网络传输、自动扩缩容、可靠性以及服务级别目标（SLO）。
- **系统边界的扩张**：一个生产请求如今可能依次经过网关、缓存感知路由器、prefill 池、KV 传输网络、decode 池、多层缓存、自动扩缩器与可观测性组件；agentic 负载可携带数十万复用输入 token，视觉语言模型引入资源画像不同的编码器，MoE 与异构机群使"一个副本=一个容量单位"的抽象失效。
- **核心张力**：若模型服务器执行高效但选错端点，可用前缀会被重算；若 prefill/decode 拆分未计入网络传输，TTFT 可能反而恶化；若路由器只追逐缓存局部性而缺少饱和逃生阀，热副本会变成排队热点——这些是**系统交互问题**，而非孤立的内核问题。
- **论文定位**：这是一篇**系统综合与研究方向论文（systems synthesis and research agenda）**，不是新的性能基准论文；所有速度、延迟、能耗与部署结果均归因于原始作者与机构，作者自身的贡献在于连接证据、提出分类体系与架构提案。

## 2. 方法论：核心思想、关键技术与公式

- **总体思路**：不做新基准，而是把 2022–2026 年 9 月的同行评审论文、arXiv 预印本、开源项目文档与云厂商生产报告按**证据层级**（A 同行评审 / B 预印本原型 / C 开源实现 / D 生产报告）分类综合，聚焦五类服务决策：执行、状态管理、放置、容量、可靠性。
- **优化边界扩张分类（图 1 的五阶段轨迹）**：
  1. 引擎/单副本（Orca、vLLM）——优化 token 与 KV 内存；
  2. 副本池/局部性（Sarathi-Serve、Preble、Llumnix）——优化副本负载与局部性；
  3. 阶段池+分布式状态（Splitwise、DistServe、Mooncake、MemServe）——优化阶段放置与 KV 状态；
  4. 机群/异构控制（Dynamo、llm-d）——优化机群容量与 SLO；
  5. 工作负载感知控制平面（llm-d v0.8–v0.9、M*、RaidServe）——优化执行图与可靠性。
- **瓶颈迁移模型**：每一次优化不是消除稀缺性，而是把稀缺资源转移到别处（调度→KV 内存→分布式局部性→prefill 干扰→端点选择→硬件多样性→可靠性→复合工作负载），因此原始 FLOPs 越来越难以预测实际交付的服务能力。
- **KV 状态的分布式决策**：提出缓存局部性不是二值路由规则，而是动态决策中的一项，给出传输/等待/重算的交叉条件：
  - `T_transfer(S,i,j) + T_queue(j) < min{T_queue(i), T_recompute(S,j)}`，可改写成成本或能耗形式。
- **vLLM 与 llm-d 的分层观（图 2）**：vLLM 是执行引擎/服务运行时（PagedAttention、连续批处理、chunked prefill、前缀缓存、投机解码、量化、多种并行、E/P/D 解聚）；llm-d 是**引擎无关的推理控制平面**（路由、全局 KV 索引、分层卸载、P2P 复用、P/D 与 E/P/D 编排、预测延迟与 SLO 策略、流控、自动扩缩、异构变体、HA、追踪、灰度安全）。
- **提出的推理执行规划器（IEP，图 5）**：
  - 计划元组：`p = (m, h, g, k, x, a, s)`，分别对应模型变体、硬件放置、执行图（聚合/P-D/E-P-D/通用阶段图）、KV 来源与动作、传输网络路径、准入路由策略、扩缩上下文。
  - **三时间尺度**：快路径（每请求毫秒级选计划）、中循环（秒到分钟改池比例与副本）、慢循环（分钟到小时改容量、硬件、预算策略与离线仿真），避免单体调度器的不可行延迟要求。
  - **约束优先选择**：先按硬约束过滤可行集 `F_r`（TTFT ≤ S_TTFT、TPOT ≤ S_TPOT、质量 ≥ Q_min、可用性 ≥ A_min、策略合规），再在可行集内最小化加权目标 `αL + βC + γE + δR`（延迟、成本、能耗、可靠性），并强调各项不可通约、宜用字典序或 Pareto 策略。
  - **状态动作显式化**：本地命中、回主路由、对等传输、分层恢复、重算、保留、驱逐。
  - **仿真内循环**：用 BLIS 等离散事件仿真器在消耗昂贵 GPU 时间前剪枝劣质计划。
- **可靠性指标**：提出"可用性调整有效吞吐" `G_avail = N_SLO满足请求 / T × (1 − P_服务中断)`，避免"健康时极快但故障时脆弱"的系统被误判为更优。
- **评估指标**：定义 SLO-goodput `G_SLO(W) = N_成功且满足SLO(W) / T`，并要求同时报告每美元 SLO-goodput、每满足请求的加速器小时数、缓存命中与可复用 token 分布。

## 6. 主要结论与发现

- **三点核心结论**：
  1. vLLM 与 llm-d 是**互补层次**而非替代品——引擎优化执行，控制平面优化执行发生的位置、时机与策略。
  2. 现代推理的稀缺资源正从单纯 FLOPs 转向**受管理的状态、放置、网络移动与决策质量**。
  3. 下一代调度器需要选择**执行计划**，而不仅仅是一个端点。
- **关键实证洞见**：
  - 解聚本身不是通用吞吐优化（vLLM 文档明确指出），其直接价值在于分离 TTFT/ITL 控制与尾延迟隔离；大分布式栈的吞吐收益来自完整配置。
  - 会话状态可主导执行成本：缓存命中率从 1.7% 提升到 92.2% 带来数量级差异。
  - 控制平面 CPU 可能成为新瓶颈（三厂商实验中 Endpoint Picker 单副本 CPU 饱和导致测试终止）。
  - 可靠性策略与性能策略消耗相同资源（KV 副本占内存/带宽、保守灰度降低瞬时容量），因此可靠性应进入同一规划目标。
  - agentic 负载的调度单元应从请求变为**会话/agent 程序**；多模态把 prefill/decode 推广为**通用数据流图调度**。
  - 独立收敛证据：NVIDIA Dynamo 独立复现了引擎/控制平面分层，说明这是领域趋势而非单一项目抽象。

- **写作与可视化克制**：图 1（优化边界五阶段）、图 2（vLLM 与 llm-d 分层）、图 3/4（证据图谱）、图 5（IEP）承担了主要论证负荷，文字不堆砌数字，避免了综述常见的"数字轰炸"。

## 8. 缺点与局限

- **无原创实验，核心提案未经验证**：IEP 计划元组、三时间尺度控制循环、约束优先选择、仿真内循环等均停留在设计层面，论文没有原型实现、没有端到端评估、也没有与现有调度器（如 Kubernetes 原生调度、Dynamo 规划器）的对照实验。因此其"可行性与收益"仍属论证性推断。
- **证据基础存在系统性偏差**：
  - 大量数据来自厂商工程博客、开源项目文档与云服务报告（证据层级 C/D），这类来源天然倾向于展示成功配置，失败与中性结果较少披露；
  - 部分关键数字来自仿真或特定长上下文/agentic trace（如 Mooncake 的缓存命中跃升、BLIS 的准入控制收益），其外推性受限；
  - 不同来源的模型规模、量化、网络拓扑、并发水平与 SLO 定义差异巨大，论文虽已声明不可比，但读者仍可能误读为可累加的趋势。
- **缺乏统一成本模型**：论文提出以延迟、成本、能耗、可靠性加权，并建议字典序或 Pareto 策略，但未给出这些量如何在同一单位或同一时间尺度上换算，也未讨论电价、实例定价、跨区带宽成本、GPU 折旧等现实约束，导致"成本"项在实操中仍难落地。
- **分类体系的时间敏感性**：五阶段轨迹与"瓶颈迁移"模型是对 2022–2026 年观测的归纳，属于事后叙事。它可能低估同时并存的多重瓶颈（例如 KV 内存与网络传输在同一时刻共同构成约束），也难以为尚未出现的新硬件形态（如超长片上内存、光互联、专用解码加速器）预留位置。
- **可靠性指标的理想化**：`G_avail = N_SLO满足请求 / T × (1 − P_服务中断)` 形式简洁，但"服务中断"的定义、检测窗口、部分降级（如只损失部分副本）如何计入，论文未给出可操作定义，不同团队可能得出差异很大的数值。
- **覆盖范围的取舍未充分说明**：论文声明覆盖 2022 年至 2026-09，但对为何排除某些方向（如纯训练侧、端侧推理、隐私/合规调度、跨云联邦）缺乏明确交代，读者难以判断其"综合"的完备边界。
- **对组织与人力因素的忽略**：控制平面意味着跨团队职责（模型团队、平台团队、SRE、网络团队）的协调成本，论文几乎只从技术架构角度讨论，未涉及运维复杂度、故障域划分、发布流程等社会技术因素。
- **部分建议存在内部张力**：既主张"缓存局部性路由"，又强调"饱和逃生阀"；既主张"预测延迟路由"，又承认预测本身有误差与开销——论文承认这些张力但未给出系统性的消解机制（例如如何在路由决策中同时量化局部性收益与热点击穿风险）。

## 9. 对研究与实践的启示

- **对研究者**：论文把"推理服务"重新定义为一个**受约束的规划问题**，这为后续工作提供了可形式化的接口——执行图、KV 来源动作、传输路径、准入策略、扩缩上下文可以被建模为搜索或强化学习问题；同时，`G_SLO` 与 `G_avail` 为跨系统比较提供了潜在的公共指标，值得社区进一步标准化与基准化。
- **对平台工程师**：最有价值的是"先诊断瓶颈迁移、再选择优化手段"的方法论，以及把缓存、阶段、可靠性纳入同一控制平面的架构直觉；但落地时应警惕论文自身承认的"无普适加速比"，任何方案都需在自有 trace 上实测。
- **对评测社区**：论文暴露了当前推理系统评测的碎片化——建议建立包含 agentic trace、多模态输入、异构硬件、故障注入在内的**共享基准与统一 harness**，否则跨论文数字将持续不可比。

## 10. 总体评价

这是一篇**定位清晰、诚实克制、概念贡献大于实证贡献**的系统综合与议程论文。其最大价值不在于报告了某个新的加速比，而在于：

1. 用"优化边界扩张"与"瓶颈迁移"两条线索，把 2022 年以来散落在引擎、调度、KV 复用、阶段解聚、异构机群、可靠性等方向的工作编织成一个连贯叙事；
2. 明确提出 vLLM（执行引擎）与 llm-d（推理控制平面）的分层关系，并给出 IEP 这一可讨论的计划抽象；
3. 以证据层级与"证据图谱"的方式处理跨来源数据，主动标注不可比性，在同类综述中较为少见地保持了方法论诚实。

其主要短板同样明显：缺少原创实验与原型验证，核心提案停留在设计层面；证据来源偏向厂商与仿真；成本、可靠性等指标缺乏可操作定义；对组织与运维维度几乎未涉及。因此，它更适合被当作**研究议程与架构讨论的起点**，而非可直接照搬的工程规范或性能预期依据。读者若将其结论用于容量规划或采购决策，仍需以自身工作负载的受控实验为准。
