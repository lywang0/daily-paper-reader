## 摘要
边缘和嵌入式推理受限于功耗和数据移动。Mamba 家族状态空间模型用序列线性递归替代注意力，但其推理路径结合了稠密投影、短归约 SSD 内核和递归状态更新。本文将这几类内核映射到 IMAX，一种可编程的 CPU-Grounded Linear Array（CGLA），并从内核执行到 token 级集成进行测量。投影内核与长归约 IMAX 流水线相匹配，而 SSD Step-1 受限于短归约和内核边界开销。Mamba-130M 的 token 级集成表明投影 GEMV 是解码瓶颈。这些结果表明，可编程 CGLA 适合长归约投影内核，而 SSD 和解码时投影支持需要边界归约和持久权重执行。

## Abstract
Edge and embedded inference is constrained by power and data movement. Mamba-family state-space models replace attention with sequence-linear recurrence, but their inference path combines dense projections, short-reduction SSD kernels, and recurrent-state updates. This paper maps these kernel groups onto IMAX, a programmable CPU-Grounded Linear Array (CGLA), and measures them from kernel execution to token-level integration. Projection kernels match the long-reduction IMAX pipeline, whereas SSD Step-1 is limited by short reductions and kernel-boundary overheads. Mamba-130M token-level integration identifies projection GEMV as the decode bottleneck. These results show that programmable CGLAs fit long-reduction projection kernels, while SSD and decode-time projection support require boundary reduction and persistent-weight execution.

## 1. 核心问题与整体含义（研究动机与背景）

- **边缘推理的约束**：边缘与嵌入式场景下的序列模型推理受限于功耗与数据搬移，长上下文下基于注意力的模型在边缘系统上代价高昂。
- **SSM 的替代方案**：Mamba / Mamba-2 等状态空间模型（SSM）以序列线性递归替代注意力，但其推理路径并非单一加速器内核，而是混合了**长规约稠密投影**、**短规约 SSD 内核**与**顺序递归状态更新**三类形态差异很大的算子。
- **硬件问题**：这三类内核虽以 MAC 为主，但在规约长度、流水线占用、数据搬移和递归依赖上差异显著，给可编程加速器带来不同压力。核心问题是：**可编程 CGLA 能否高效承载 Mamba 家族的各类内核，瓶颈在哪里？**
- **研究定位**：本文将 Mamba 推理视为可编程 CGLA 的**诊断性负载**，在不修改模型、不引入固定功能 SSM 数据通路的前提下，映射并测量主要内核组，从内核执行一直测到 token 级集成，目标是判断哪些阶段契合流水线、哪些受短规约/内核边界/token 级投影 GEMV 限制。

## 2. 方法论

- **加速器平台 IMAX**：一种可编程 CPU-Grounded Linear Array（CGLA），将宿主 CPU 与一维流式 PE（处理单元）+ LMM（本地存储模块）流水线耦合。评估用的 IMAX3 原型在 AMD Versal Premium VPK180 FPGA 上实现单条 CGLA 通道：**64 级 PE 线性链**，每通道 512 KiB LMM，**145 MHz**；由 conv-c2d 编译器将 PE 静态分配为操作数加载、算术或排出/存储阶段。
- **投影 GEMM 映射（in-proj / out-proj）**：复用既有 IMAX GEMM 模板，占用阶段 0–63，其中**阶段 2–61 构成 60 级 FMA 链**，阶段 1 加载操作数，阶段 62 完成最终加法与存储，阶段 0/63 做迭代控制；仅修改编译期常量（RMGRP、W、BSTEP）。投影的规约长度 L 分别为 1024（in-proj）与 2048（out-proj），属长规约、深度占用。
- **SSD Step-1 映射**：将 Eq.(3)(4) 拆为三次 IMAX 内核调用：
  - GEMM1：`R ← C·Bᵀ`，形状 (Q×N)×(N×Q)→(Q×Q)，用 7 级流水线；
  - Hadamard：`R ← R ⊙ Λ`，元素级掩码，用 3 级流水线、两路并行 OP_FML 通道（每行 Q/2 对）；
  - GEMM2：`Y ← R·X`，形状 (Q×Q)×(Q×d)，7 级流水线。
  - 自定义 `imax_hadamard()` 将掩码更新保留在 IMAX 上原地写回，**省去一次 DMA 往返**；通过把外层批轴聚合为 `M1 = N_heads × Q` 来摊销每次启动开销。该阶段规约长度 N、Q ≤ 128，属短规约。
- **Step-3 递归状态更新**：`h_c = A_c·h_{c-1} + B_cᵀ·X_c`，是每 chunk 的 N×d 小矩阵—向量乘，存在顺序依赖（chunk 间不可并行），由宿主 CPU 承担，IMAX 侧作为独立的传输调度研究。
- **公式要点**：输入投影 `[z,x,B,C,Δ] = u·W_in`；输出投影 `y = (o ⊙ σ(z))·W_out`；SSD 内 chunk 计算 `M = (C·Bᵀ) ⊙ Λ`、`Y = M·X`。

## 3. 实验设计

- **模型与配置**：Mamba-370M 用于层级的核函数刻画（d_model=1024, d_inner=2048, H=32, d_head=64, N=128, Q=64）；Mamba-130M 用于 token 生成集成；递归状态实验还涉及 Mamba-1.4B。全部使用 **FP32**。
- **Benchmark / 参照**：以**同机共置的 ARM Cortex-A72 软件路径**作为正确性与 CPU 计时参照；另列出 IMAX ASIC 模型（28 nm，840 MHz，仅作上下文参考）。**未与 GPU 系统对比**（作者明确说明是避免不同功耗边界下的比较）。
- **测量对象**：
  - 投影 GEMM（in-proj 记录 37.8 ms EXEC、1.17 s DMA 含总时间）；
  - SSD Step-1 扫描，M1 从 64 到 4096，代表性设置 N=Q=d_head=64、batch size 16；
  - 单 GEMM 扫描（最大扫描点 M1=4096 时 EXEC 组件相对 ARM 有 1.43× 加速）；
  - 递归状态运行（Q=64, N=128, d_head=64，含内联 DMA，比较 block 自动调优前后）；
  - Mamba-130M 自回归解码 200 token 的 IMAX offload 集成运行（含正确性校验与解码各阶段时间占比）。
- **FLOP 分布**：Mamba-370M 单层总 FLOP 约 7415 MF（T=512），其中投影占 **91%**，SSD Step-1 与 Step-3 各占较小份额。

## 5. 实验数量与充分性

- **实验组数概览**：大致包括投影 GEMM（3 次归档运行取均值，DMA 含总时间 min–max 离散度 <0.1%）、SSD Step-1 的 M1 扫描（64→4096）、单 GEMM 扫描、递归状态在 Mamba-370M 与 Mamba-1.4B 上的 block 调优对比、以及 Mamba-130M 200-token 解码集成。整体规模偏小，**没有传统意义上的消融实验**。
- **充分性与客观性**：

## 6. 主要结论与发现

- **长规约投影契合 IMAX 流水线**：投影 GEMM 能用满 60 级 FMA 链，是负载中长规约 CGLA 的适配点；但当前 in-proj 的 DMA 时间（1.17 s）远大于 EXEC（37.8 ms），**DMA 主导总时间**。
- **SSD Step-1 受限**：短规约（N、Q ≤ 128）与内核边界开销导致未融合的三内核路径端到端不划算——GEMM1/Hadamard/GEMM2 的 EXEC 分别为 7068/1178/7052 μs，但边界传输把总墙钟时间抬到 48,922 μs，慢于 ARM 参照的 19,407 μs。单 GEMM 组件在最大扫描点有 1.43× 加速，但不足以抵消边界与传输开销。
- **递归状态更新是传输调度问题**：block 调优使墙钟时间从 29.3→28.1 ms（Mamba-370M）和 124.4→107.0 ms（Mamba-1.4B），加速范围 1.04–1.16×，与 CPU 参照最大偏差 3.46×10⁻³；说明 Step-3 更应作为传输调度而非计算受限目标。
- **token 级解码瓶颈是投影 GEMV**：Mamba-130M 集成运行达 **0.345 tokens/s**，保持 ARM 参照的贪心 token 序列且零输出错误；解码时间中 **in-proj 占 66.8%、out-proj 占 32.7%**，x-proj、dt-proj、状态更新与卷积各低于 0.3%。
- **总体判断**：可编程 CGLA 适合长规约投影内核；SSD 与解码时投影支持则需要**边界规约（算子融合）与持久权重执行**。

## 7. 优点

- **诊断视角清晰**：把 Mamba 推理当作可编程 CGLA 的诊断负载，而非设计固定功能 SSM 加速器，能干净地分离投影、SSD、递归、解码四类瓶颈，避免模型改动带来的干扰。
- **同一执行栈贯穿全程**：从内核 EXEC 测量到 token 级集成使用同一套栈，并把 EXEC 与 DMA 含总时间分开报告，能真实暴露“PE 侧加速但端到端收益有限”的现象。
- **Hadamard 内核融合**：自定义 `imax_hadamard()` 原地写回，消除一次 DMA 往返，并绕开 conv-c2d 要求 load/store 基地址为编译期常量的限制。
- **学术诚实度高**：明确区分测量到的 FPGA 时序与仅作参考的 ASIC 核心估计；明确声明不用于跨平台能耗主张；对无统计支撑的加速比主动降调表述。
- **正确性有保障**：所有内核输出均与 ARM 参照核对，token 级集成保持贪心序列一致、零错误。
