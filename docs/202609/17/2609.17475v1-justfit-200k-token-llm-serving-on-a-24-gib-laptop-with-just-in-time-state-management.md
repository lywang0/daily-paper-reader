## 摘要
能力强大的开放权重模型使本地编码与推理颇具吸引力，但其上下文与执行状态会给笔记本电脑内存带来压力。我们提出 JustFit，一个基于 MLX 的推理运行时，它结合了用于压缩 KV 执行的 KVExec、用于组件驻留的 PhaseSwap，以及用于状态保持的服务转换的 StateTrans。这些机制融合了重建，并协调即时物化与释放，且独立于模型权重量化。在 24 GiB M4 Pro MacBook 上运行 Qwen3.8-27B MXFP4 的全执行容量测试中，三次独立运行完成了 196,608 个输入 token 和 16,384 个输出 token，将完成的单请求上下文从 mlx-vlm 基线的 30,720 个位置提升至 212,992 个（6.93 倍）；另一项双请求运行总计保留了 229,376 个位置。在单独的性能测试中，一项 32K 输入、64 输出的探测达到 19.11 tokens/s，而重复的 32K+6K 工作负载的进程峰值占用中位数为 16,374 MiB。集成运行时正确回答了 30 道 AIME 2026 题目中的 29 道，表明紧凑状态与生命周期感知执行如何扩展本地服务容量，同时支持扩展的生成式推理。

## Abstract
Capable open-weight models make local coding and reasoning attractive, but their context and execution state strain laptop memory. We present JustFit, an MLX-based inference runtime that combines KVExec for compressed KV execution, PhaseSwap for component residency, and StateTrans for state-preserving serving transitions. These mechanisms fuse reconstruction and coordinate just-in-time materialization and release, independently of model-weight quantization. In full-execution capacity tests on a 24 GiB M4 Pro MacBook running Qwen3.8-27B MXFP4, three independent runs complete 196,608 input and 16,384 output tokens, increasing completed single-request context from the mlx-vlm baseline's 30,720 positions to 212,992 (6.93x); a separate two-request run retains 229,376 positions in aggregate. In separate performance tests, a 32K-input, 64-output probe reaches 19.11 tokens/s, and a repeated 32K+6K workload has a median peak process footprint of 16,374 MiB. The integrated runtime answers 29 of 30 AIME 2026 problems correctly, showing how compact state and lifetime-aware execution expand local serving capacity while supporting extended generated reasoning.

## 2. 方法论：核心思想、关键技术细节与流程

### 2.1 核心思想：即时状态管理

- 论文将运行时状态分为五类，并优化其同时存活集合：
  - \(M_{live}(t) = W(t) + K(t) + S(t) + X(t) + H(t)\)
  - 其中 \(W\) 为可达权重存储，\(K\) 为打包 KV 后备，\(S\) 为循环与推测状态，\(X\) 为执行工作区，\(H\) 为其他宿主与分配器存储。
- 核心策略：
  - 持久 KV 保持压缩；
  - 执行操作数靠近消费者再重建；
  - 模型组件在有活跃拥有者时保持附着；
  - 离开的请求在安全执行边界释放状态。

### 2.2 三个协作子系统

#### KVExec：即时 KV 执行

- 基于 TurboQuant 的归一化、旋转 MSE 分支，使用 TQ4 四比特 KV 表示。
- 每个 K 或 V 向量存储：
  - 128 字节打包索引；
  - 2 字节 FP16 范数。
- 论文给出的每位置 KV 负载：
  - \(\beta_{TQ4} = 16 \cdot 2 \cdot 4 \cdot (128 + 2) = 16{,}640\) 字节/位置。
  - FP16 为 65,536 字节/位置。
  - 在 229,376 位置下分别约 3,640 MiB 与 14,336 MiB，压缩比约 3.94 倍。
- 重建一层注意力浮点 K/V 需要：
  - \(B_{layer}(T,s) = 2hTds\)。
  - 在 \(h=4, d=256\)、BF16、192K 位置时约 768 MiB。
- 关键机制：
  - **页面原生访问**：KV 池以 256 token 页管理，页 ID 可复用而不重新分配后备数组。
  - **融合逆重建**：prefill 时直接读取物理页 ID，解包 Q4 索引，查质心，逆 Hadamard 旋转，恢复范数，写出当前层连续 K/V，交给标准 SDPA。
  - **层作用域评估**：在层返回前完成注意力结果，限制跨层惰性依赖的生命周期。
  - **执行路径分离**：单查询 decode 使用页面原生注意力；多查询 prefill 使用直接逆重建；短验证 tile 可使用打包验证器；否则回退 gather/SDPA 或反量化。

#### PhaseSwap：组件驻留

- 观察：相对模型很小的组件也会占用大量上下文余量。
  - 未绑定 LM head 占 644.14 MiB，相当于约 40,591 个位置的 KV 负载。
- 驻留规则：
  - 若组件 \(c\) 的拥有者集合 \(O_c(t)\) 非空，则其评估数组保持附着：
    - \(|O_c(t)| > 0 \Rightarrow a_c(t) = 1\)。
- 具体策略：
  - 中间 prefill 阶段可分离 LM head，在最终 prefill/首 logits 边界前重建。
  - 生成行在混合 prefill/decode 期间保持 head 租约，避免每个调度步重复重建。
  - MTP 预测器约 215.21 MiB，仅在单例推测时物化，并引用目标 embedding/head。
  - 视觉塔按媒体 embedding 阶段加载，嵌入评估后释放，再进入普通文本 prefill。

#### StateTrans：跨请求保持状态

- 将队列到达、准入与执行分离。
- 请求转换策略：
  - 排队的文本对等请求不改变现有请求模式；
  - 在页与阶段预算满足后，准入等待完整推测轮，将现有请求转为自回归 AR 批处理，并复用目标提示缓存；
  - 目标 KV 与 Gated DeltaNet 状态保持，单例 drafter 在轮边界释放；
  - 媒体请求遵循更严格阶段边界，不插入活跃文本 decode cohort。
- 调度策略：
  - 活跃生成行时，每四次 decode forward 允许一次 prefill 机会，chunk 上限 64 token，即 N4/PF64。
  - 当仅剩一个合格行、无待处理 prompt、无新准入且允许再提升时，恢复 MTP，并绑定幸存者已有目标状态。
- 准入预留：
  - \(R_i = \lceil (p_i + \min(o_i, 8192)) / 256 \rceil\) 个物理页等价。
  - 共享前缀使用引用计数。
  - 超出保证部分的输出视为盈余，允许有界绕过容量阻塞请求。
- 释放顺序：
  - 完成当前生成步；
  - 评估待处理 token/cache 状态与页写入；
  - 过滤完成/取消行；
  - 递减页引用；
  - 引用计数为零后页 ID 回到空闲列表；
  - 池后备保留给未来 cohort。
