## 摘要
大语言模型（LLM）推理常同时受计算和内存制约，尤其是在基于卸载的部署中，模型权重会在自回归解码过程中跨内存层级传输。在此场景下，减少执行的层数可以降低每token延迟，同时避免代价高昂的权重移动。受此观察启发，我们提出 FlexEE，一种面向资源受限和基于卸载的LLM推理的提前退出框架。FlexEE 通过逐层退出监督以实现可靠的中间层预测、在 Top-K 局部词表上进行自推测解码以实现低成本的退出决策，以及动态隐藏状态管理以实现 KV 缓存正确且内存感知的执行，使提前退出在 LLM 解码中变得实用。在生成任务和下游任务中，FlexEE 实现了高效提前退出，且精度下降极小；在 0\%/50\% 权重卸载下，分别在 Llama2-7B 和 Llama3-8B 上带来最高 1.27$\times$/3.16$\times$ 和 1.25$\times$/2.83$\times$ 的端到端加速。

## Abstract
Large language model (LLM) inference is often constrained by both computation and memory, especially in offloading-based deployments where model weights are transferred across memory hierarchies during autoregressive decoding. In this setting, reducing the number of executed layers can lower per-token latency while also avoiding costly weight movement. Motivated by this observation, we present FlexEE, an early exiting framework for resource-constrained and offloading-based LLM inference. FlexEE makes early exiting practical for LLM decoding through layer-wise exit supervision for reliable intermediate-layer prediction, self-speculative decoding over a Top-K local vocabulary for low-cost exit decisions, and dynamic hidden state management for KV-cache-correct and memory-aware execution. Across generative and downstream tasks, FlexEE enables efficient early exit with minimal accuracy degradation, delivering up to 1.27$\times$/3.16$\times$ and 1.25$\times$/2.83$\times$ end-to-end speedups on Llama2-7B and Llama3-8B under 0\%/50\% weight offloading, respectively.

## 1. 核心问题与研究动机

- **背景**：Transformer 大语言模型（LLM）在机器人、图像生成、代码生成等领域表现优异，但参数规模急剧膨胀，使得在资源受限环境中的部署变得困难——模型参数常超出片上内存容量。
- **卸载式部署的瓶颈转移**：常见做法是将部分层参数卸载到片外内存，推理时按需加载（如 FlexGen、ZeRO、DeepSpeed、PagedAttention）。这使推理瓶颈从**计算**转为**片外访存**，加速的关键变为减少参数加载的**数量与频率**。
- **为什么选择提前退出（Early Exiting）**：通过在中间层动态终止计算，减少每个输入执行的层数；在卸载式推理下，这同时减少了从片外加载的层参数，直接缓解数据搬运瓶颈。
- **论文指出的三大挑战**（对应 Figure 1a）：
  - **挑战 1：中间层建模能力弱**。LLM 中间层隐状态语义可解码性差（熵高、PPL 差），直接对现成模型做早退会导致严重质量下降。
  - **挑战 2：退出开销高**。早退预测需将中间隐状态投影到完整词表空间（如 Llama2-7B 的 32K 词表），矩阵乘法代价大，常抵消跳层带来的加速。
  - **挑战 3：KV 缓存不兼容**。在中间层退出会导致后续层无法为未来 token 生成所需 KV 对；已有的"状态复制/KV 复制/KV 驱逐"方案要么引入额外计算，要么破坏语义一致性，且在卸载场景下仍需加载剩余所有层权重，抵消早退收益。
- **整体含义**：论文提出 FlexEE，一个基于**系统–算法协同设计**的卸载感知早退框架，目标是让早退在卸载式 LLM 解码中真正实用化，兼顾低延迟与高精度。

## 2. 方法论

### 2.1 核心思想
- 通过**逐层退出监督**提升中间层可解码性，通过**基于自推测的 Top-K 局部词表预测**降低退出决策开销，通过**动态隐藏状态管理**解决 KV 缓存一致性问题，并让三者与权重卸载的执行特性对齐。

### 2.2 逐层早退监督（Layer-wise Early-Exit Supervision）
- 训练时把**共享 LM head** 连接到多个关键 Transformer 层，对不同深度隐状态施加统一语言建模目标，使中间表示对齐最终层的解码能力，且**不引入额外推理开销**。
- 目标函数：对第 $l$ 层隐状态 $x_l$ 与共享 LM head $g(\cdot)$，训练损失为各层交叉熵的加权和
  $J(X,Y,t)=\sum_{l=0}^{L-1}\tilde{e}(t,l)\,J_{CE}(g(x_{l+1}),Y)$
  其中 $\tilde{e}(t,l)$ 为归一化的层间权重，调度策略**从深层逐渐移向浅层**，避免对浅层表示过度正则化。
- 效果（Figure 3）：监督后 Llama2/Llama3 中间层的熵与 WikiText PPL 大幅下降，最终层性能几乎不变。

### 2.3 轻量级自推测早退预测器
- **退出特征选择**：比较四类候选特征——Top Prob、Gap（top-1 与 top-2 概率差）、Top Logit、Prob Shift。离线统计表明 Top Prob 与 Gap 阈值随层平滑、覆盖率高、跨模型一致性好；Top Logit 不稳定，Prob Shift 覆盖率低。最终选用 **Top Prob + Gap**。
- **阈值推导**：对每个特征求层间最小阈值 $\lambda_l^*$，使满足退出条件的 token 中至少有 $\tau$ 比例与最终层预测一致；再定义覆盖率 $r_{\lambda_l}=|S_{\lambda_l}|/N$。
- **局部词表可行性验证**：
  - $H_l(N)=P(y^*\in \text{Top-}N(\hat p_l))$：最终层 top-1 token 是否落在第 $l$ 层 Top-N 候选集中。
  - $E_l(N)=E_t[p^{(l)}_{1,\text{Top-}N}(t)-p^{(l)}_{1,\text{full}}(t)]$：局部与全局 top-1 概率的近似误差。
  - 实验发现 $N$ 增大时覆盖快速提升、误差快速下降，**$N=30$ 为较优折衷**（Llama3-8B 因词表 128K 取 $N=80$）。
- **两阶段预测流程**（Figure 2c）：
  1. **Self-Spec 层**：在某个中间层做一次完整 LM head 投影，选出 Top-K token 构成局部候选词表；
  2. **Early-Exit 层**：后续早退层仅在 $K$ 个候选 token 上做 LM head 投影，计算局部 top-1 概率与局部 gap，两者同时超过预计算的层间阈值时才触发退出。
- **阈值标定**：在 WikiText 上离线搜索层间阈值，保证校准集上早退准确率 > 0.99（$\tau=0.99$）；跨数据集（LAMBADA/SST/BoolQ）阈值趋势高度一致（余弦相似度 0.997–0.999）。

### 2.4 动态隐藏状态管理（KV 兼容）
- **问题回顾**：已有三种补救方案各有缺陷——(i) *state copying*：把退出层隐状态传播到后续所有层重建 KV，需加载全部剩余层权重；(ii) *KV copying*：直接广播退出层 KV；(iii) *KV eviction*：掩蔽后续层注意力，破坏语义一致性。
- **本文方案**（Figure 5）：
  1. 当某 token 在中间层退出时，**保留该退出层的隐状态**；
  2. 生成下一个 token 时，前向传播到达退出层的**第一个后继层**时，把保留的隐状态与当前 token 表示**联合参与**后续计算；
  3. 待该后继层 KV 缓存完整更新后，**清除缓存隐状态**以回收内存。
- **优势**：① 无需跨层强制复制 KV 即可保持跨 token 语义连续性；② 只在必要时引入额外隐状态参与，避免对所有剩余层做冗余 KV 重建；③ 系统层面**无需在退出后更新后续层 KV**，也就不必加载这些层的权重，非常契合卸载式推理。
- **执行流程**（Algorithm 1）：逐层计算并评估退出准则的同时**异步预取下一层权重**，实现权重加载与层计算的重叠；退出则缓存隐状态并终止当前 token 解码。

## 6. 主要结论与发现

- **精度保持良好**：在多个生成与下游任务上，FlexEE 的早退精度接近甚至等于 Dense 解码。例如 Llama2-7B 自推测层 16 时平均退出层 24.9（名义深度减少 22.2%），MMLU 43.0 vs Dense 43.1，多个任务（SST、BoolQ、PIQA、WinoGrande）甚至略优于 Dense。
- **显著端到端加速**：0%/50% 权重卸载下，Llama2-7B 达 **1.27×/3.16×**，Llama3-8B 达 **1.25×/2.83×**；卸载比例升至 75% 时加速分别可达 3.29×（Llama2-7B）、2.68×（Llama2-13B）、3.10×（Llama3-8B）。
- **卸载比例越高收益越大**：加速随卸载比例提升而增强，但 50%→75% 边际收益递减，因为早退多发生在较深层，无法充分利用额外卸载的层。
- **自

推测层位置与加速–精度权衡**：Self-Spec 层的位置是可调的超参数。论文发现，把 Self-Spec 层前移（更浅）能带来更大的名义跳层幅度与吞吐收益，但候选词表基于更弱的中间表示构建，退出准确性下降、精度损失变大；把 Self-Spec 层后移则精度更稳但加速空间被压缩。因此需要在"自推测层深度–平均退出层–任务精度"三者间做显式权衡（对应 Table 1 中报告的 Dense 与不同 Self-Spec 起点配置）。
- **局部词表预测是退出开销的关键削减手段**：消融显示，全词表早退虽然能获得更低的平均退出层（理论上跳层更多），但其投影开销吞噬了大部分收益，端到端吞吐反而低于 Self-Spec 局部词表方案（Figure 8/9）；局部词表使早退决策的开销与跳层节省相匹配，这是 FlexEE 能在卸载场景下真正转化为端到端加速的前提。
- **Top-K 规模的敏感度可控**：K 从 5 增大到 200 时，退出准确率与精度单调改善但边际递减，而开销随 K 近似线性增长，K≈10–30 处于较优区间；Llama3-8B 因词表更大（128K）需要更大的 K（约 80）才能达到同等覆盖。这说明 K 应随词表规模与层间表示质量自适应设定，而非固定常数。
- **动态隐藏状态管理优于已有 KV 补救方案**：与 state copying、KV copying、KV eviction 相比，本文方案在不重建全部剩余层 KV 的前提下保持了跨 token 语义连续性，精度损失最小，且因退出后无需更新后续层 KV，可避免加载这些层的权重——这一点在卸载式部署中直接体现为加速比优势。
- **与基线方法的比较**：在相同归一化 FLOPs 口径下，FlexEE 在多数任务上同时取得优于 ShortGPT、AdaInfer、SpecEE 的精度–吞吐折衷；LayerSkip 被限制在 FlexEE 的退出层终止，用于剥离"浅层推测"本身的贡献，从而说明增益主要来自退出机制而非解码策略。
- **批量推理下的稳健性**：批量规模增大（B=1→8）时，早退触发的层分布会因不同样本的退出点分散而变宽，导致实际跳过的层数减少、单样本加速比下降，但总体吞吐仍随批量上升；这提示批处理与早退存在张力，需要在调度层面（例如按退出层分组）进一步优化。
- **阈值与配置的可迁移性**：离线标定的层间阈值在 WikiText 与 LAMBADA/SST/BoolQ 之间高度一致（余弦相似度 0.997–0.999），且在 Llama3.2-1B 等更小模型上同样成立，说明该标定流程不依赖特定数据集或模型规模，具备免训练即插即用的性质。
- **退出层分布特征**：多数 token 在较深层退出，浅层退出主要出现在"简单"token（如高频词、功能词、重复性上下文）上，这与"深层才需要复杂推理"的直觉一致，也解释了为何卸载比例提升到 75% 后边际收益递减——被卸载的浅层本就不是早退的主要节省来源。

## 7. 局限性

- **依赖 LayerSkip 预训练 checkpoint**：逐层监督并非从零引入，而是建立在已有的逐层监督权重之上；若换成标准预训练模型（未做逐层监督），中间层可解码性差的问题会重新出现，方法能否以较低成本迁移尚未充分验证。
- **离线阈值标定仍需数据**：虽然免训练，但阈值搜索依赖校准集（300K WikiText token）与目标退出准确率 τ 的先验设定，τ 越严格则覆盖率越低、加速越小，这一超参数与业务精度要求的匹配关系需要人工调参。
- **加速上限受退出层位置约束**：早退集中在深层意味着浅层权重仍需全部加载，因此卸载收益存在结构性上限；论文也观察到 50%→75% 卸载的边际收益递减。
- **批量场景优化不足**：批量推理仅报告了 Llama2-7B，且未提出针对多退出点的批调度策略，批内样本退出点分散会削弱加速。
- **算力与训练细节披露有限**：仅报告推理硬件平台，未给出标定耗时、能耗或训练规模，复现成本难以评估。
- **评测偏差的残余风险**：开放式生成采用 LLM-as-judge 并以随机化顺序缓解位置偏差，但裁判模型与提示词的影响仍未完全排除；SpecEE 为复现值、AdaInfer/ShortGPT 部分数据取自原论文，跨实现比较存在不可控差异。
- **消融覆盖面**：多数消融（局部词表、KV 策略、退出层分布）集中在单一模型上，跨模型一致性的证据链相对薄弱。

## 8. 总体评价与启示

- **贡献定位清晰**：论文把"早退"从纯算法问题重新表述为**卸载式推理下的系统–算法协同问题**，明确指出在片外访存成为瓶颈时，减少层数执行与减少层参数加载是同一件事，这一视角转换是其核心价值。
- **三处设计彼此咬合**：逐层监督解决"能不能退"，局部词表解决"退得起"，动态隐藏状态管理解决"退得干净"，三者分别对应论文提出的三大挑战，且都朝"减少参数搬运"这一统一目标对齐，工程自洽性较高。
- **实用性强于新颖性**：单个组件（逐层监督、自推测、Top-K 局部词表、KV 复用）在文献中均非首创，创新主要来自组合方式与面向卸载场景的取舍；但正因如此，其落地可行性较高。
- **可迁移的方法论**：Top Prob + Gap 的层间阈值标定、Self-Spec/Early-Exit 两阶段预测、退出后仅在后继层合并隐状态等做法，对其他"动态计算 + 权重卸载"的推理系统（如 MoE 卸载、稀疏激活）具有参考意义。
- **后续可探索方向**：将退出预测与批调度联合优化、把卸载决策与退出层分布耦合（按退出概率预取/驻留权重）、以及在未做逐层监督的开源模型上以轻量适配恢复中间层可解码性。
