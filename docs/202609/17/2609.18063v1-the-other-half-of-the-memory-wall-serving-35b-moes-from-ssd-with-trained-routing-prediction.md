## 摘要
消费级硬件上的专家混合（MoE）推理受限于权重内存：35B 级模型在 4 位下为 19.5GB，而稀疏性缩减的是每个 token 的计算量，而非必须持有的字节数。单纯卸载到 SSD 本身无济于事，因为第 N+1 层的专家必须在第 N 层输出产生之前就被选定，因此无法足够早地开始读取以将其隐藏在计算之后。我们提出 Edge0，一种流式 MoE 推理引擎，通过预路由器弥合这一差距：逐层头提前一个 token 预测下一层的路由，并且该预测被直接用作路由本身，因此暂存的专家集合等于路由集合，且不会丢弃任何专家。一个在学生路径上训练的未合并恢复 LoRA，补偿了因 int4 量化和路由替换而损失的质量。在单台 24GB 机器上，Edge0 能在 3GiB 峰值活跃内存内以 20tok/s 服务一个 35B MoE，在五个公开基准上平均与其 fp16 教师模型相差几个点。8B 档位可在同一框架上运行，且框架、检查点和适配器均已开源。

## Abstract
Mixture-of-experts (MoE) inference on consumer hardware is bounded by weight memory: a 35B-class model is 19.5GB at 4-bit, and sparsity shrinks the compute per token, not the bytes that must be held. Naive offloading to SSD does not help on its own, because layer N+1's experts must be chosen before layer N's output exists, so the reads cannot start early enough to hide behind compute. We present Edge0, a streaming MoE inference engine that closes the gap with a prerouter: a per-layer head predicts the next layer's routing one token ahead, and the prediction is consumed as the routing itself, so the staged expert set equals the routed set and nothing is dropped. An unmerged recovery LoRA, trained on the student path, pays back the quality lost to int4 quantization and routing replacement. On a single 24GB machine, Edge0   serves a 35B MoE at 20tok/s inside 3GiB of peak active memory, within a few points of its fp16 teacher on average across five public benchmarks. An 8B tier runs on the same framework, and the framework, checkpoints, and adapters are open source.

## 1. 核心问题与整体含义

- **内存墙的"另一半"**：1995 年 Wulf 与 McKee 提出内存墙。三十年后，AI 推理面临同样约束——decode 阶段每读取一字节权重只做几个 FLOP，瓶颈是字节数而非算力。
- **两类内存数据的不对称**：状态（KV cache）是动态的，随生成 token 增长；权重是静态的，训练结束即固定。产业界集中攻克动态一半（MLA 压缩 KV、稀疏注意力、线性状态模型），而静态权重（数十 GB）的唯一答案是"放进数据中心"（专家并行、分片服务）。
- **35B 规模下两条本地路径均失效**：
  - 量化：4-bit 已是实用下限，更低误差不可恢复；35B 模型 4-bit 仍占 19.5 GB。
  - MoE 稀疏性：只减少**计算量**（每 token 约激活 3B 参数），不减少**必须驻留的字节**。
  - 24 GB 桌面机被 19.5 GB 权重挤占后，KV cache 与操作系统几乎无空间。
- **朴素 SSD 卸载无效的根本原因**：第 N+1 层的专家选择依赖第 N 层的输出，而该输出在需要发起读取时尚不存在，因此读取无法提前到足以隐藏在计算之后，每层每 token 都要停顿于磁盘延迟。
- **整体含义**：论文主张权重的内存墙本质是一个**存储放置决策**，并用"训练侧预测 + 推理侧流式"的组合给出消费级可用方案。

## 2. 方法论

### 2.1 总体架构（Edge0）

- 流式 MoE 推理框架，MLX 代码全部藏在 backend facade（`core` / `nn` / `io` / `quant`）之后，核心逻辑仅依赖该 facade，便于扩展后端。
- 模型由单一 `MoESpec` 描述（专家数、K、路由族、量化、权重布局、键模板），一个通用流式层服务所有模型。
- LoRA 与 prerouter 权重以 safetensors 文件形式随模型目录解析，**永不合并**进基础权重。

### 2.2 SSD 流式专家层

- **动机算例**：40 层 × 256 专家，int4 下每层 453 MB（每专家 1.77 MB），路由专家合计 18 GB，占 24 GB 机器的约四分之三。
- **机制**：mmap 量化专家 safetensors，按需读取字节区间；OS 页缓存承载热数据，**峰值内存跟踪活跃集而非参数量**。
- **四条执行路径**：
  1. `exact`：去重后按需构建 bundle、堆叠、量化 gather（正确性基线）；
  2. `staged`：固定槽双缓冲，decode 主力。路由索引经槽表用 `take` 映射，索引不离开 GPU；重复专家集复用图节点；持久粘滞槽张量原地更新（`incr stack`），仅重写变化的专家，而非重建每层 9 个堆叠张量（gate/up/down × 权重/scale/bias）× 40 层；
  3. `hot`：每层固定 LRU 常驻热专家，命中走堆叠 gather，未命中回落 `exact`；
  4. `whole-layer`：prefill 时整层一次性加载（每层 9 次直接读取），CPU 加载与上一层 GPU 执行重叠。
- **数学契约**：所有路径计算 `down(silu(gate(x)) · up(x))`，使用同一量化 gather 核；测试套件逐元素对齐反量化参考（相对 L2 < 1%，实测残差 ≈ 0.24%，为核内 bf16 精度）。该契约使执行器可按层、按阶段自由切换路径而不改变输出。

### 2.3 Prerouter：预测即路由

- **双重位移**：由第 N 层持有的头，在 token t 上基于第 N 层 post-attention norm 输出，预测第 N+1 层在 token t+1 的路由。第 N+1 层消费的是**一个 token 之前**做出的预测，其槽位填充的 SSD 读取与当前前向传播重叠。
- **为什么必须提前一个完整 token 而非一层**：Pre-gated MoE 式的同 token 逐层选择需要每层同步与头求值，在本引擎中会排空 GPU 流水线（30–100 ms/步，超过其能隐藏的加载时间），且下一层注意力尚未计算；论文实测所有同 token 变体均低于朴素 LRU 基线。提前一个 token 使头求值移出逐层关键路径——每步一次 flush 即预测所有暂存层（35B 档 32 层，8B 档 16 层）。
- **头结构**：每层 `fc1 → erf-gelu → fc2`，外加线性残差路径 ℓ，训练时从下一层的 router 权重热启动（默认置零），使训练起点为"直接把下一层 router 应用于当前隐状态"，MLP 学习修正量。输入特征拼接隐状态与两个 top-k one-hot（本 token 本层实际路由到的专家、上一 token 的专家），维度 = `d_model + 2E`（35B：2048 + 2×256 = 2560，隐宽 512；8B：1536 + 2×128）。头以 fp16 运行（训练导出精度），fp32 无精度收益但有可测时间成本。35B 档 33 个头（owner 6–38），预测在 7–38 层被消费；8B 档 16 个头（owner 7–22），在 8–23 层消费。
- **Prediction-as-routing**：decode 时 MoE 层用 prerouter logits 替代 router logits 路由，走与原始 router 相同的 softmax-topk 或 sigmoid-group 数学（附录 A）。由于**路由集即预测集**，暂存槽精确映射、无任何丢弃，从构造上消除了 pre-gating 系统需在运行时处理的覆盖率–质量权衡；近似代价被转移到训练阶段一次性偿付。
- **特征漂移**：头输入包含本层实际执行的路由——训练时是 base router 的选择，decode 时是头自身的预测。头不针对该偏移重训；恢复 LoRA 在学生路径（prerouting 已生效）上训练，因此见到部署时的输入分布，§5 的质量测量把该偏移与 int4、路由近似一起计价。
- **两种消费画像**：8B 档 K=8、每层 8 个暂存槽；35B 档 K=4、使用增量粘滞槽堆叠。Prefill 两档均走 whole-layer 路径（每层所有专家都被命中，无需预测）。

### 2.4 恢复 LoRA：按设计保持未合并

- 服务模型 =（int4 基础）+（路由替换）+（LoRA），LoRA 用于补偿前两者。在学生路径（prerouter 路由）上以对教师数据的交叉熵训练，联合补偿量化与路由近似。
- **部署保持未合并**：`y = W4bit(x) + αr BAx` 作为并行 delta 计算，4-bit 基础字节不动。
- **合并失败是算术问题而非实现问题**：LoRA delta 的 RMS 为 10⁻³ 量级，低于 4-bit group 步长，反量化合并后再量化会擦除大部分权重级 delta（注意力投影保留 34%，dense 投影仅 2%，logits 层保留 18%）。
- 未合并路径代价为 42 MB 适配器权重、解码时间无可测开销，且严格更忠实。适配器作为文件随检查点发布：一份只读基础服务所有适配器世代，重训一档只需替换两个文件。

### 2.5 训练三阶段

- 全部在 4-bit 部署检查点的反量化 bf16 重建上进行（"训练所服务之物"），基础权重全程冻结。
- **Phase 1：蒸馏头**。预路由头是唯一可训练参数，损失模仿下一层真实 router，使头学会预测路由而非拟合文本。
- **Phase 2：学生路径 SFT**。LoRA 挂在 attention、linear-attention 与 shared-expert 投影上，**不挂路由专家**（其权重需流式且保持可替换）；完整前向在 prerouter 路由生效下运行，约 200 万行教师生成文本。此阶段使近似可用：仅蒸馏检查点配学生路由会产出重复、塌缩文本，同样头 + SFT 则输出连贯。
