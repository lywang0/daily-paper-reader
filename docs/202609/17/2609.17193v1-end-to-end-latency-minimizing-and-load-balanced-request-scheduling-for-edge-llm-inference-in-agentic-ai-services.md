## 摘要
由大语言模型（LLM）驱动的智能体AI服务日益需要低时延推理，这推动了将LLM部署在分布式边缘服务器上。然而，异构的通信与计算能力，以及动态演化的推理状态，使得针对每个到达请求的边缘服务器选择具有时变性，并在不同时隙之间紧密耦合。本文研究面向边缘LLM推理的在线请求调度框架，该框架联合最小化长期平均端到端时延，并调控异构边缘服务器间的工作负载分布。在此背景下存在两个主要挑战。首先，传统时延模型无法准确刻画多阶段LLM执行的细粒度动态。其次，调度决策的时延后果只有在请求完成后才能被观测到，这使得即时评估决策变得困难。为应对这些挑战，我们构建了一个跨时隙推理模型，该模型能够刻画每个多样化请求的传输、预填充、迭代级解码以及键值（KV）缓存演化，并通过KV缓存内存-时间消耗指标来刻画服务器工作负载。我们提出了LYREO方法，该方法通过Lyapunov优化转化长期负载均衡约束，并采用奖励重分配与基于序列的回报预测，将延迟结果转化为用于更早决策的及时学习信号。各种配置下的仿真表明，与代表性的基于学习的和启发式基线方案相比，LYREO能够持续实现更低的时延和更均衡的负载分布。

## Abstract
Large language model (LLM)-powered agentic AI services increasingly demand low-latency inference, motivating the deployment of LLMs across distributed edge servers. However, heterogeneous communication and computing capabilities, together with dynamically evolving inference states, make the edge server selection for each incoming request time-varying and tightly coupled across slots. In this paper, we investigate an online request scheduling framework for edge LLM inference that jointly minimizes long-term average end-to-end latency and regulates workload distribution across heterogeneous edge servers. Two main challenges arise in this context. First, conventional latency models cannot accurately capture the fine-grained dynamics of multi-stage LLM execution. Second, the latency consequence of a scheduling decision is observed only after request completion, making immediate decision evaluation difficult. To address these challenges, we develop a cross-slot inference model that captures transmission, prefill, iteration-level decoding, and key-value (KV) cache evolution for each diverse request, and characterize server workload through a KV cache memory-time consumption metric. We propose the LYREO approach that transforms the long-term load-balancing constraint via Lyapunov optimization and employs reward redistribution with sequencebased return prediction to convert delayed outcomes into timely learning signals for earlier decisions. Simulations under various configurations demonstrate that LYREO consistently achieves lower latency and more balanced load distribution than representative learning-based and heuristic baseline schemes.

## 2. 方法论：核心思想、关键技术细节、公式与算法流程
- **核心思想**：提出 **LYREO**（Lyapunov-guided reward-redistribution online request scheduling），将长期负载均衡约束通过 Lyapunov 优化转化为每时隙可处理的“漂移加罚”目标，并用奖励重分配机制把延迟的时延反馈转化为即时学习信号，最后用 PPO 学习调度策略。
- **细粒度跨时隙推理模型**：
  - 端到端时延分解为传输时延、批等待时延、预填充时延、解码时延：
    \[
    D^{tot}_{i,s}(t)=D^{tx}_{i,s}(t)+D^{wa}_{i,s}(t)+D^{pre}_s(t)+D^{dec}_{i,s}(t)
    \]
  - 支持连续批处理与动态进出解码（DEED）：已完成请求及时释放 KV 缓存，新请求在内存足够时加入正在解码的批次。
  - 显式建模 KV 缓存随解码迭代的演化，并定义峰值 KV 占用约束：
    \[
    M^{pk}_s(t)=\max_{k=1,\dots,K_s(t)} m_s(k,t)\le M_s
    \]
- **负载指标**：用归一化 KV 缓存“内存—时间”消耗刻画服务器工作负载：
  \[
  \eta_s(t)=\frac{\sum_{k=1}^{K_s(t)} m_s(k,t)\tau_s(k,t)}{M_s\Delta}
  \]
  该指标同时反映内存占用强度与持续时间，并能体现异构服务器的内存和处理能力差异。
- **问题建模**：
  - 原问题 P1：最小化长期平均端到端时延，约束包括长期负载均衡方差不超过 \(\epsilon\)、峰值 KV 内存不超限、每请求唯一分配到一台服务器。
  - 长期负载均衡约束：
    \[
    \lim_{T\to\infty}\frac{1}{T}\sum_{t=1}^T(\eta_s(t)-\bar{\eta}(t))^2\le \epsilon,\ \forall s
    \]
- **Lyapunov 转化**：
  - 为每台服务器定义虚拟队列：
    \[
    Z_s(t+1)=\max\{Z_s(t)+Y_s(t)-\epsilon,0\},\quad Y_s(t)=(\eta_s(t)-\bar{\eta}(t))^2
    \]
  - 构造二次 Lyapunov 函数与条件漂移，得到漂移上界，并将 P1 转化为每时隙问题 P2：最小化“时延惩罚 + 虚拟队列负载偏差惩罚”。
- **延迟反馈处理：奖励重分配**：
  - 将问题建模为序列马尔可夫决策过程（SDP），状态包括请求属性和服务器状态，动作是请求到边缘服务器的分配，奖励包含时延项、负载偏差项和内存越限惩罚。
  - 使用 LSTM 回报预测器 \(g_\psi(\cdot)\) 预测状态—动作序列的期望回报。
  - 构造截断加自举的回报目标：
    \[
    \hat{y}_H=\sum_{h=0}^{H-1}\gamma^h r_{h+1}+\gamma^H V_\phi(s_H)
    \]
  - 重分配奖励：
    \[
    r'_{t+1}=g_t-g_{t-1}
    \]
    从而把延迟结果归因到更早的调度决策，提供即时学习信号。
- **策略优化**：
  - 使用 PPO 的 actor-critic 结构，actor 输出每请求对各边缘服务器的分类分布，critic 估计状态价值。
  - 采用 GAE 计算优势，使用裁剪代理目标更新 actor，用 MSE 更新 critic。
- **算法流程概述**：
  - 初始化 actor、critic、回报预测器。
  - 收集一批轨迹。
  - 用截断—自举目标训练 LSTM 回报预测器。
  - 冻结回报预测器，计算重分配奖励。
  - 计算 TD 误差与优势，执行 PPO 多轮更新 actor 和 critic。
- **理论分析**：给出定理 1，说明学习策略与最优策略的性能差距受截断长度 \(H\)、值估计误差、回报预测误差和 PPO 优化误差约束；随 \(H\) 增大，截断偏差相关项下降。

- **Benchmark / 对比方法**：
  - **Ly-PPO**：Lyapunov 辅助 PPO，但不含奖励重分配。

  - **Random**：随机选择边缘服务器。
- **消融方法**：
  - **LYREO-Count**：用活动请求数替代 KV 缓存内存—时间消耗作为负载指标。
  - **LYREO-NoLB**：移除长期负载均衡约束。
- **评价指标**：
  - 平均端到端时延。
  - 平均负载均衡偏差 / 负载均衡队列长度。
