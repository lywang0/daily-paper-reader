## 摘要
大语言模型（LLM）日益超出商用GPU的内存容量，使得内存超售在实际部署中变得普遍。NVIDIA统一虚拟内存（UVM）提供了对主机内存的透明访问，但其缺页驱动的迁移引入了严重的性能开销。尽管UVM提供了原语（如预取和放置提示）来缓解这些开销，但它们需要底层CUDA修改，限制了大多数LLM用户的适用性。与此同时，现有的UVM优化以粗粒度的托管对象粒度运行，无法捕获深度学习框架内部的张量级内存行为，导致过多的数据移动和CPU-GPU互连瓶颈。我们提出了AutoUVM，一个自动的、框架感知的UVM预取系统，用于在内存超售下高效执行LLM。AutoUVM通过暴露张量级访问信息并以细粒度实现策略驱动的预取，弥合了深度学习框架与UVM之间的语义鸿沟。作为透明扩展实现，AutoUVM无需修改模型代码，并动态适应运行时内存压力。我们用一个灵感源自屋顶线（roofline）的策略实例化AutoUVM，以识别性能关键的数据传输。在十个LLM上，AutoUVM相对于基线UVM平均实现了3.1倍加速，并持续超越最先进的现有UVM预取器1.9倍，相对于对象级预取器改进高达4.7倍，同时显著减少了缺页。

## Abstract
Large language models (LLMs) increasingly exceed the memory capacity of commodity GPUs, making memory oversubscription common in practical deployments. NVIDIA Unified Virtual Memory (UVM) provides transparent access to host memory, but its page-fault-driven migrations introduce severe performance overhead. While UVM exposes primitives (e.g., prefetching and placement hints) to mitigate these costs, they require low-level CUDA modifications, limiting their applicability for most LLM users. Meanwhile, existing UVM optimizations operate at coarse managed-object granularity and fail to capture deep learning frameworks' internal tensor-level memory behavior, leading to excessive data movement and CPU-GPU interconnect bottlenecks.   We propose AutoUVM, an automated, framework-aware UVM prefetching system for efficient LLM execution under memory oversubscription. AutoUVM bridges the semantic gap between deep learning frameworks and UVM by exposing tensor-level access information and enabling policy-driven prefetching at fine granularity. Implemented as a transparent extension, AutoUVM requires no changes to model code and dynamically adapts to runtime memory pressure. We instantiate AutoUVM with a roofline-inspired policy to identify performance-critical data transfers. Across ten LLMs, AutoUVM achieves an average 3.1x speedup over baseline UVM and consistently surpasses the best-performing prior UVM prefetcher by 1.9x, with improvements of up to 4.7x over object-level prefetchers, while significantly reducing page faults.

### 1. 核心问题与整体含义（研究动机与背景）

- **问题背景**：大语言模型（LLM）不断增长的内存需求已超过单张商用 GPU 的显存容量。NVIDIA 的统一虚拟内存（UVM）通过主机内存扩展和按页迁移实现了“内存超订阅（oversubscription）”，允许 GPU 在物理显存不足时透明访问主机数据，是大模型在有限显存设备上运行的少数实用路径之一。
- **核心瓶颈**：UVM 的默认按需缺页迁移会产生极高延迟；尽管提供 `cudaMemPrefetchAsync`、`cudaMemAdvise` 等预取/放置原语，但这些底层 CUDA API 要求手动修改代码，对大多数用户不可行。
- **深层矛盾——语义鸿沟**：PyTorch 等现代深度学习框架使用缓存分配器（如 PCA），向 CUDA 申请大量连续内存块后再划分为众多张量复用。UVM 驱动无法看到张量级的分配与访问，只看到少数大对象的重复访问，导致现有对象级 UVM 预取策略（如 SUV、Forest）产生大量无效迁移。
- **论文含义**：填补“深度学习框架的张量级内存行为”与“UVM 驱动粗粒度管理单位”之间的间隙，是实现高内存超订下 LLM 高效执行的关键。

### 2. 方法论：核心思想、技术与流程

**总体思路**：AutoUVM 将框架语义引入 UVM 预取路径，只迁移“即将被访问且迁移敏感的张量”，实现免改模型代码的细粒度、策略化预取。系统分为两个阶段：**离线剖析（profiling）**与**在线执行（execution）**，中间共享执行配置文件库。

**核心技术细节**：

- **两层张量标识符（Two-Level Tensor Identifier）**：由张量“创建点调用栈哈希 + 单调分配计数器”构成稳定身份，克服地址随机化影响，保证离线配置在后续运行中可用。
- **Kernel–Tensor 访问追踪**：针对动态计算图导致的算子序列不稳定问题，不依赖静态计算图，而是离线记录“内核—张量”访问对，在线运行时只需要在下一个内核执行前预取其所需张量。
- **Roofline 启发策略**：利用多层 roofline 视图将内核分为三类——**GPU 计算受限**、**GPU 内存带宽受限**、**CPU–GPU 互连（CGI）受限**。只对 CGI 受限且对迁移延迟敏感的内核对应的张量进行预取；计算受限和 GPU 内存受限的则不预取，从而节约 PCIe/NVLink 带宽并降低显存压力。
- **前向亲和性分析（Look-ahead Tensor Affinity）**：识别跨连续内核反复复用的张量，在复窗口内用 `cudaMemAdvise` 将其固定/驻留于 GPU。
- **在线执行器与运行时监控**：轻量监控各内核的实际执行时间；当内存超订导致驱逐行为变化、内核重新分类时，动态调整预取决策。
- **系统实现方式**：不改模型代码，通过修改 PyTorch CUDA 缓存分配器使其使用 `cudaMallocManaged`，并结合分配器钩子记录张量创建信息、NVBit 统计 FLOP 与访存、Compute Sanitizer API 注入 prefetch/affinity 操作，以保证低叠加开销。

- **评测场景**：约束有效 GPU 容量构造超订场景，采用内存超订因子（factor）衡量，主要按 2.0 评估，另巡检 1.5 与 1.75。

### 6. 主要结论与发现

- **核心效果**：在 oversubscription factor = 2.0 时，AutoUVM 平均实现 3.1 倍于 Baseline UVM 的加速；相比最佳的已有 UVM prefetcher（DeepUM）再快 1.9 倍；与对象级预取器相比最多高达 4.7 倍的提升。
- **对象级预取器的失败**：在 LLM + PyTorch 分配器下对象级方法经常比 Benchmark 更差，由于无效预取（对象中数据均被迁移但多数未被后续 kernel 使用）浪费 CGI 带宽、加大显存压力。
- **页故障显著减少**：与执行时间呈明显正相关，AutoUVM 在所有方法中页故障数量最少。
- **行为趋势**：超订越重，AutoUVM 相对优势越大（factor 1.5→1.4×、1.75→2.2×、2.0→3.1×）；
- **跨架构泛化**：在 RTX 3060、A100、H100 上分别 3.1×、2.9×、2.7× 加速，且在 kernel 融合（fused kernels）下仍能达到平均 2.3× 加速比。
- **能源**：AutoUVM 几乎不改变平均功率（+3-4 W），因缩短运行时间，总能耗平均减少 31%，相对对象级方案最高可削减 74%。

### 7. 方法亮点

- **清晰的语义鸿沟洞察**：首次明确提出 DL 缓存分配器导致的 tensor 级行为对 UVM 隐藏这一核心不匹配，并以量化有效/无效迁移比例证明了对象级预取不可用。
- **免改模型代码 + 透明集成**：基于 PyTorch 分配器钩子和计算流注入实现，可解释性好，对框架升级具备鲁棒性。
- **剖析—策略解耦设计**：将“知道内核访问了哪些张量”（框架语义提取）从“哪些迁移值得做”（策略设计）中解耦，使策略可针对新硬件或新模型替换。
- **Roofline 启发的选择性机制**：相比“多预取”逻辑，优先级定义“少但准”，切中 CPI/显存带宽两侧的瓶颈本质。
- **完备的运行时自适应闭环配置**：静态分析提供结构，运行时 Monitor（同时连续监控 kernel 执行时间）纠偏，使策略在驱逐改变工作结构后可保持适用。
- **面向工程现实的长期稳定 ID 方案**：以调用栈+计数器消除地址随机化干扰，设计层面考虑部署一致性。
