## 摘要
大语言模型（LLM）推理越来越多地跨越在规模、能力、价格和提供商上各不相同的模型。这种转变给开发人员带来了两类成本：一是从众多模型中选择和切换的集成成本；二是当KV缓存不可用或与选定模型不兼容时重建KV缓存的推理成本。我们将统一AI网关定义为边缘部署的AI流量中枢的一种系统设置。它协调端设备、边缘资源和云模型服务之间的模型路由、KV缓存管理和计算放置。在请求时，网关在任务质量、延迟、成本和资源约束下联合选择目标模型、执行位置和KV缓存操作。同时，后台缓存管理操作优化后续请求的KV缓存放置、复制、检索和生命周期决策。我们综合了关于KV缓存重用、压缩、跨模型映射、分布式存储和传输的现有证据，并讨论了将这些能力整合到一个系统中的剩余挑战。在八种典型工作负载配置中，我们的工作负载级分析模拟报告了TTFT加速比1.25倍至13.28倍，以及输入成本效益1.20倍至6.16倍。

## Abstract
Large language model (LLM) inference increasingly spans models that differ in size, capability, price, and provider. This shift creates two costs for developers. One is the integration cost of choosing among and switching between many models. The other is the inference cost of rebuilding a KV cache when it is unavailable or incompatible with the selected model. We define and analyze the Unified AI Gateway as a system setting for an edge-deployed AI traffic hub. It coordinates model routing, KV cache management, and compute placement across end devices, edge resources, and cloud model services. At request time, the gateway jointly selects a target model, an execution site, and a KV cache action under task-quality, latency, cost, and resource constraints. In parallel, background cache-management actions optimize KV cache placement, replication, retrieval, and lifecycle decisions for subsequent requests. We synthesize existing evidence on KV cache reuse, compression, cross-model mapping, distributed storage, and transfer, and discuss the remaining challenges of integrating these capabilities into one system. Across eight typical workload profiles, our workload-level analytical simulation reports TTFT speedups of 1.25$\times$--13.28$\times$ and input-cost benefits of 1.20$\times$--6.16$\times$.

# 统一AI网关：联合模型路由与KV缓存管理的框架

## 1. 核心问题与整体含义（研究动机与背景）

- 大语言模型生态日益多样化，应用开发者常需在不同规模、能力、价格和提供商的模型之间进行选择与切换。例如长上下文编程智能体，其规划、编码、执行、审查等环节可能偏好不同的模型，且对话历史、工具输出和仓库状态会在多轮之间反复出现。
- 这种多模型切换带来两类成本：
  - **集成成本**：在众多模型间选择与切换的接口与调度开销；
  - **推理成本**：当KV缓存不可用或与目标模型不兼容时，目标模型必须重新进行完整的上下文预填充（prefill），造成大量重复计算。
- 现有的AI网关（如统一接口、负载均衡、故障转移）不协调KV缓存与模型/提供商选择；vLLM、SGLang、LMCache、Mooncake等系统虽支持缓存复用、生命周期管理或分布式存储，但能力分散，未与跨设备/服务的模型选择联合优化。
- 路由决策若忽视缓存状态，会导致：TTFT升高、输入成本上升，并造成“缓存诱导的模型锁定”（cache-induced model lock-in）。
- 为此，论文提出**统一AI网关（Unified AI Gateway）**：一种边缘部署的AI流量中枢系统设置，将模型路由、KV缓存管理和计算放置放在同一请求路径上联合协调，跨越端（End）、边缘（Edge）和云（Cloud）三层。

## 2. 方法论

- **核心思想**：用一个全局控制平面（Global Control Plane）同时协调“选哪个模型”“在哪个位置执行”“如何获得KV缓存”三个耦合决策。请求时，按模型、执行位置和缓存动作的可行组合做代价优化；后台则持续管理缓存的放置、复制、迁移、淘汰等，为后续请求提供更好的缓存状态。
- **系统架构**：End–Edge–Cloud三层协同：
  - **端侧**：终端设备发起请求，也可参与解码（PD分离场景下接收边缘送来的KV缓存）；
  - **边缘侧**：承载全局控制平面与边缘设备，提供缓存查询、预填充、跨模型映射、推理等能力；
  - **云侧**：模型提供商的推理服务集群，接收网关路由的请求；云侧也可被网关指示执行预填充并回传KV缓存。
- **五条缓存路径**（根据候选模型与执行位置）：
  1. 精确缓存命中（直接复用）；
  2. 跨模型映射（将源模型缓存转换为目标模型可用形式）；
  3. 远程缓存传输（将已有缓存传送到目标执行位置）；
  4. 边缘预填充（在边缘生成新缓存）；
  5. 目标端重新预填充（完全重算）。
- **统一缓存选择器**从四个维度评价候选路径：可用性（缓存是否存在、能否查找/生成）、保真度（映射或压缩带来的质量损失）、成本（查找、传输、压缩、映射、重算等）、资源（带宽、算力、存储等）。
- **形式化联合决策**：
  - 目标函数：在满足延迟和质量约束的前提下，最小化归一化延迟与归一化成本的加权和；
  - 约束条件：`L ≤ L_t`（延迟阈值）、`Q ≥ Q_t`（质量阈值）；
  - 可行集合由当前缓存放置、模型兼容性、资源状态、网络条件、授权策略共同决定。
- **跨模型映射判定条件**（当从源模型 `Mi` 切换到目标模型 `Mj` 时）：
  - 当“缓存传输时间 + 映射时间 < 目标端重新计算时间”，且映射误差低于质量阈值时，选择映射；
  - 否则若缓存格式兼容，直接传输；仍不兼容则回退到目标端全量重预填充。
- **关键计算模型**（简化延迟模型）：
  - KV缓存大小与上下文长度近似线性关系；
  - 预填充时间采用线性+二次项近似（`a_prefill·L + b_attn·L² + τ`）；
  - 传输时间 ≈ 压缩后大小 / 带宽 + RTT + 排队 + 拷贝 + 恢复开销；
  - 在重叠（overlap）假设下，映射与分块传输可流水化，数学建模中使映射+传输≈纯传输时间。
- **论文贡献三要素**：
  1. 提出统一网关抽象与联合控制方法；
  2. 形成“缓存复用—压缩—映射—存储—传输—路由”的端到端分类体系并指出系统缺口；
  3. 通过负载级仿真量化TTFT与成本收益。

## 6. 主要结论与发现

- **主要收益**：在八种工作负载与25%–75%切换率下：
  - TTFT加速比：**1.25×–13.28×**；
  - 输入成本比（成本下降）：**1.20×–6.16×**；
  - 端到端token成本比：**1.17×–5.04×**；
  - 端到端延迟作为二次诊断指标也获收益，但小于TTFT收益（被输出token解码时间稀释）。
- **场景差异**：
  - 高命中率、长上下文的负载获益最大（如编程任务在75%切换率下达13.28×；长周期编码智能体在75%切换率下达12.87×）；
  - 短上下文、低命中率的RAG场景收益较低（最低1.25×）。
- **成本角度**：缓存命中并成功映射可以使输入token按缓存价格计算（0.1×未缓存价），从而显著降低输入账单；输出token较多的负载其成本收益被输出token摊销而降低。
- **系统层面结论**：单纯的路由或单纯的缓存优化无法解决多模型切换造成的重复预填充；网关级联合控制能够显著降低切换成本，并可能进一步促进路由策略在更大模型池中选择更合适的模型。
- 当前实现仍缺跨模型映射通用性、边缘异构硬件适配、分布式缓存一致性、安全隐私、系统经济学与生态互操作标准。
