## 摘要
在边缘设备上部署大规模语言模型通常依赖于模型压缩或分割推理。然而，压缩会降低推理能力，而分割推理则遭受严重的广域网通信瓶颈。边云投机解码成为一种有前景的替代方案，利用边缘小模型为云端验证起草令牌。然而，在不稳定的广域网环境下，不可避免的预测拒绝会触发灾难性的流水线停顿和全网回滚，抵消协作增益。为克服此问题，我们提出AceSpec，一种非对称边云协作框架。AceSpec利用未饱和的边缘计算主动构建概率状态缓存，有效将全网流水线刷新转化为O(1)局部内存查找。为节省带宽，它采用非对称通信协议，上行传输最小主链索引，下行传输紧凑稀疏分布。此外，我们引入一种网络感知的、基于拉格朗日优化的资源分配策略，动态最大化局部缓存命中率。评估表明，AceSpec实现了高达3.52倍的吞吐量加速，并展现出卓越的带宽抗性，即使在严重受限的50 Kbps广域网条件下也能维持接近峰值的推理性能。

## Abstract
Deploying Large Language Models (LLMs) on edge devices typically relies on model compression or split inference. However, compression degrades reasoning capabilities, while split inference suffers from severe Wide Area Network (WAN) communication bottlenecks. Edge-cloud speculative decoding emerges as a promising alternative, leveraging an edge small model to draft tokens for cloud verification. Yet, over volatile WANs, inevitable prediction rejections trigger catastrophic pipeline stalls and network-wide rollbacks, neutralizing collaborative gains. To overcome this, we propose AceSpec, an asymmetric edge-cloud collaborative framework. AceSpec utilizes un-saturated edge compute to proactively construct a probabilistic state cache, effectively transforming network-wide pipeline flushes into $\mathcal{O}(1)$ local memory lookups. To preserve bandwidth, it employs an asymmetric communication protocol that transmits minimal main-chain indices uplink and compact sparse distributions downlink. Furthermore, we introduce a network-aware, Lagrangian-optimized resource allocation strategy that dynamically maximizes the local cache hit rate. Evaluations demonstrate that AceSpec achieves up to a 3.52$\times$ throughput speedup and exhibits exceptional bandwidth immunity, sustaining near-peak inference performance even under severely constrained 50 Kbps WAN conditions.

### 1. 论文的核心问题与整体含义（研究动机与背景）

大语言模型（LLM）在边缘设备上的部署需求日益迫切，但面临两个核心困难：

- **资源限制**：纯端侧推理受限于边缘设备的算力与显存，不可行；
- **传统协作方案的困境**：
  - **模型压缩**：过度压缩会显著损害模型的推理与生成能力；
  - **分割推理（Split Inference）**：将模型切分到边云两端，需要在广域网（WAN）上传输海量中间隐状态，形成所谓的"通信墙"（Communication Wall），在低带宽、高延迟的WAN环境下传输开销完全抵消了计算加速的收益。
- **投机解码的兴起与问题**：边云投机解码（Edge-Cloud Speculative Decoding）用小模型（SLM）在边缘草拟令牌、云端大模型（LLM）并行验证，可大幅压缩通信负载。但传统投机解码假设高速互联环境（NVLink/PCIe），直接部署在WAN上时，其同步"stop-and-wait"依赖会导致严重通信瓶颈。已有异步流水线方案（如PicoSpec、PipeSD、E2-SCI）虽然缓解了部分延迟，但仍存在三大缺陷：
  1. 单链状态同步机制使预测拒绝引发流水线停滞和大范围网络回滚；
  2. 为了满足带宽限制不得不放弃对随机核采样（nucleus sampling）的支持，退化为贪婪解码；
  3. 往往需要额外的微调或辅助网络，缺乏对现成（off-the-shelf）LLM的通用性。

论文的总体含义是提出一种**训练无关（training-free）、非对称的边云协作框架 AceSpec**，通过利用边缘设备充沛的并行计算资源，将高代价的网络回滚转化为本地O(1)内存查询，从根本上缓解WAN环境下边云协同LLM推理的通信墙与回滚惩罚问题。

### 2. 论文提出的方法论

#### 核心思想
AceSpec的核心理念是：**把计算与决策负担转移到边缘可用的并行算力上，从而最小化WAN上交换的数据量**。

#### 系统架构
系统由Edge Client（边缘客户端）和Cloud Server（云服务器）两个实体组成：
- **Edge Client**：部署轻量级Draft SLM，维护三个子系统——树状草拟器（Tree-based Drafter）、概率KV缓存管理器（Probabilistic KV Cache Manager）和本地重采样器（Local Resampler）。
- **Cloud Server**：部署目标LLM，仅作为"验证者"角色执行并行验证（Verify Loop），不控制最终token选择。

#### 关键技术与执行流程
1. **非对称传输协议**：上行仅发送主链（main chain）token索引的标量数组，下行仅在拒绝时返回拒绝位置索引（π）和稀疏化目标概率分布（P̂target），最大化节省带宽。
2. **异步多分支扩展（Asymmetric Branch Caching）**：在云端验证的等待窗口（Tcloud）内，边缘SLM利用空闲算力从主链各潜在拒绝深度处扩展多分支token树，并从草拟分布Q的剩余概率质量中提取Top-Fk候选token作为替代分支。
3. **定制Tree Attention Mask**：为避免分支数量N导致草拟延迟线性增长，所有分支被打包到单次并行前向传播中（O(1)墙钟时间）。Mask由三个子块构成：
   - Shared Prefix Block（共享前缀块）：允许所有分支关注已验证的历史上下文；
   - Main-Path Branch Block（主路径分支块）：约束分支只关注主草稿的前若干token；
   - Suffix Diagonal Block（后缀对角块）：对角线隔离，保证每个推测token只关注自身的祖先序列。
4. **O(1)状态恢复机制**：验证结果w = (π, x_resampled)作为查询键查找本地树缓存T；命中后执行COMPACT_KV操作将命中分支的KV条目对齐到已验证前缀前，使网络级回滚变为本地内存查找。
5. **网络感知预算（Network-Aware Budgeting）**：边缘执行时间须被云端周转时间掩盖，即 T_tree_draft(B) ≤ RTT(t) + T_verify，由此动态推导计算预算 B*(t) = min(B_max, ⌊T⁻¹_tree_draft(RTT(t) + T_verify)⌋)。
6. **任务感知形状分配（Task-Aware Shape Allocation）**：将预算 allocation 形式化为约束非线性优化问题——最大化树缓存命中率，目标函数为：

   max Σ_{k=0}^{γ-1} α^k · log[α + (1−α)R(F_k)]

   约束条件为 ΣF_k ≤ B_alloc(t)，F_k ≥ 0。

7. **拉格朗日求解与几何衰减分配**：利用LLM词汇分布的长尾（幂律）特征 R(F_k) ≈ 1 − cF_k^(−β)，构建拉格朗日函数求闭式解，最终得到**非均匀几何衰减分配策略**：

   F*_k = B_alloc(t) · (1−η)/(1−η^γ) · η^k

   其中 η = α^(1/(β+1)) ∈ (0,1)。该策略将更多分支分配给浅层位置（早期拒绝最易发生处），深层分支因到达概率随深度指数衰减而获得较少资源。

#### 算法流程（Algorithm 1 概要）
1. 初始化KV缓存并生成长度为γ的初始草稿 (x̃, Q)；
2. 循环执行：压缩概率分布并异步发送主链至云端 → 并行进行树状草拟 → 等待云端验证结果 → 本地重采样得到x_resampled → 以(π, x_resampled)为键查询树缓存 → 命中则O(1)状态恢复与KV压缩，未命中则回滚KV并顺序重草拟。
