## 摘要
多模态大语言模型（MLLMs）的卓越性能是以巨大的计算开销为代价的，这对实时部署和成本效益构成了重大挑战。现有的模型路由方法要么仅基于粗略的请求级特征进行决策，要么花费一次或多次额外的语言模型传递来检查生成的响应，而未利用生成过程中出现的令牌级不确定性信号。为解决这些局限性，我们提出了Pro-Router，一种采用自适应边缘-云协作的令牌感知渐进式模型路由方法，用于高效的多模态大模型推理。Pro-Router采用两阶段渐进式决策机制。首先，一个轻量级的提示预评分器在令牌生成开始前执行快速预筛选，将明显简单的请求引导至小模型。其次，一个令牌感知验证器读取小模型生成的每个令牌的采样概率分布，估计模型对其自身输出的置信度，以基于每个请求决定答案是直接返回，还是升级至基于云的高精度模型。此外，我们设计了一种自适应边缘-云服务流水线，根据每台设备的实测服务速率调整每次分派的大小，从而使边缘和云层均保持充分利用，无需手动调参，且不受网络延迟影响。在多个多模态基准数据集和模型上的大量实验证明了Pro-Router的有效性。与其他方法相比，它实现了最高的路由精度，并将路由速度提升了10倍以上。其服务流水线的端到端吞吐量也比现有模型路由流水线高出75%以上。我们的代码可在 https://github.com/xinyuangui2/pro-router 获取。

## Abstract
The remarkable performance of multimodal large language models (MLLMs) comes at the cost of substantial computational overhead, posing significant challenges to real-time deployment and cost effectiveness. Existing model routing approaches either decide from coarse request-level features alone or spend one or several extra language model passes to inspect the generated response, leaving the token-level uncertainty signals that emerge during generation unused. To address these limitations, we propose Pro-Router, a token-aware progressive model routing method with adaptive edge-cloud collaboration for efficient multimodal LLM inference. Pro-Router employs a two-stage progressive decision mechanism. First, a lightweight prompt pre-scorer module performs rapid pre-screening before token generation begins, guiding apparently simple requests to small models. Second, a token-aware verifier reads the sampling probability distribution of each token the small model generates, estimating the model's confidence in its own output to determine, per request, whether the answer ships or escalates to the cloud-based high-precision model. Furthermore, we design an adaptive edge-cloud serving pipeline that sizes every dispatch to each device's measured service rate, so both the edge and the cloud tiers stay fully utilized without manual parameter tuning and are not impacted by the network latency. Extensive experiments on multiple multimodal benchmark datasets and models demonstrate the effectiveness of Pro-Router. Compared to other methods, it achieves the highest routing accuracy and improves routing speed by more than 10x. Its serving pipeline also reaches more than 75% higher end-to-end throughput than the existing model routing pipeline. Our code is available at https://github.com/xinyuangui2/pro-router.

## 1. 核心问题与整体含义（研究动机与背景）

- **背景**：多模态大语言模型（MLLMs）在视觉问答、文档/图表理解、多模态推理等领域表现优异，但服务成本极高——大模型参数量达数十亿，自回归解码需为每个 token 消耗大量算力，单张图片又会产生成百上千个视觉 token，严重推高 prefill 和 KV-cache 开销。实际生产流量中，许多请求并不需要最大模型，用小一个数量级的多模态小模型（MSLM）即可高质量作答。
- **现有方法的两难**：
  - **请求级路由（request-only）**：只在生成前根据请求特征做决策，如 RouteLLM、Hybrid LLM。优点是无生成开销，缺点是看不到小模型的真实输出，决策不准。
  - **响应级路由（response-based）**：等小模型生成答案后再由另一模型评分，如 FrugalGPT、P(True)、AutoMix。优点是信息更充分，缺点是需要一次或数次额外语言模型前向/生成，额外计算开销大。
- **核心缺口**：两类方法都忽略了小模型解码过程中**自然产生的 token 级不确定性信号**——每个 token 的采样概率分布——这些信号不需要额外模型调用即可获得，却携带了模型对自身输出可信度的重要信息。
- **论文问题定义**：如何利用 token 级不确定性信号，在低开销的前提下实现高精度的“由小模型作答还是升级到大模型”的路由决策，并在边缘-云异构集群上高效调度，使两端的 GPU 利用率最大化？

## 2. 方法论

Pro-Router 采用**两阶段渐进式路由** + **自适应边缘-云协作流水线**的双层设计。

### 2.1 阶段一：轻量级提示预打分器（Prompt Pre-scorer）

- **目的**：在生成开始前对请求难度进行粗筛，把明显简单的请求导向边缘小模型，明显困难的请求直接送云端大模型，以提高“小模型作答率”（ship rate）。
- **特征（无需 GPU 计算）**：TF-IDF 文本向量、图像数量、提示长度。
- **模型**：逻辑回归，输出难度分数 \( p_{pre}(x) = \sigma(w^\top \phi(x)+b) \)。
- **定位**：只做“引导”，不做最终裁决，因此允许粗略且必须便宜——避免任何占用 GPU 的评分模型压低边缘设备有效吞吐。

### 2.2 阶段二：令牌感知验证器（Token-aware Verifier）

- **输入**：小模型解码过程每个生成 token 的天然产物，共 4 个特征：
  - 发射 token 的 log 概率：\( \ell_t = \log p_t(y_t) \)
  - 最大概率：\( m_t = \max_v p_t(v) \)
  - Top-K 熵的相反数：\( h_t = -H_t \)（K=20，熵低表示模型确定）
  - 位置比例：\( \rho_t = t/T \)
- **架构**：线性投影 + 位置编码 + 2 层 Transformer Encoder + mean pooling + sigmoid，输出区间 [0,1] 的置信度。
- **参数量**：约 67k 参数，整体运行在设备 CPU 上，**与 GPU 解码并行**，不占用加速器算力。
- **决策**：请求置信度 ≥ 阈值 τ 则直接返回（ship），否则升级至云端大模型重新生成。

### 2.3 自适应边缘-云服务流水线（Adaptive Edge-Cloud Collaboration）

- **目标**：消除边缘与云端之间的相互等待，使任意设备在任何时刻都有本地缓冲可消费，网络 RTT 不进入推理关键路径。
- **全局调度算法要点**：
  - 按固定时间窗口 \( T_w \) 运行；
  - 用指数滑动平均（EMA）跟踪每台设备的实测吞吐 \( \bar\mu_i \)；
  - 每次向设备 i 派发 \( n_i = \lceil T_w \bar\mu_i \rceil + B_i \) 个请求，保证设备整个窗口内不空转；
  - 边缘 MSLM 从“打分输入队列”的**简单端**取请求；云端 MLLM 先**清空升级队列**，再从“打分输入队列”的**困难端**补足批次。
- **本地调度器**：每台设备监控 GPU KV-cache 利用率 \( u_i \) 与本地缓冲占用 \( q_i \)，超过阈值时置背压标志 \( \beta_i=1 \)，全局调度器下轮跳过该设备，防止过载触发抢占。

### 2.4 优化目标（理论支撑）

- 系统每秒钟的“路由增益”定义为：

\[
G = \sum_{i=1}^{N_c} \eta_{L_i}L_i + \left(\sum_{j=1}^{N_e}\eta_{S_j}S_j\right) s\,(a - \lambda(1-a))
\]

其中：\( s \) 为小模型作答率，\( a \) 为返回答案中的正确率，\( \lambda \) 为答错惩罚，\( \eta \) 为各设备实际可用容量比例。**该式说明优化增益只有两个杠杆：提高 ship rate（需生成前区分难度）和提高路由精确度（需生成后读取置信度）**——这正是引入两阶段渐进设计的根本原因。

## 6. 主要结论与发现

## 6. 主要结论与发现

1. **路由精度显著提升**：在三个小模型配置下，Pro-Router 的 AUROC、PGR、AUARC、AUACC 四项指标全面优于请求级与响应级基线。其中相对 FrugalGPT 的 PGR 提升最高达十余个百分点，相对 RouteLLM 的 AUROC 提升幅度也相当可观。这说明 token 级不确定性信号携带的信息质量远比纯请求特征或对小模型答案的文本事后打分更可靠。
2. **低开销优势明确**：Pro-Router 的路由信号计算完全在 CPU 上完成且与 GPU 解码并行，单请求路由延迟仅为毫秒级，显著低于 P(True)（需一次额外生成）和 AutoMix（需 8 次采样）等需要进行额外前向的响应级方法；即便与仅读请求的 RouteLLM 相比，其延迟增幅也可忽略。
3. **端到端吞吐领先**：在边缘-云协作流水线下，Pro-Router 的端到端吞吐量最高可达 K 倍于简单路由方案的收益，且随网络延迟增大优势愈加明显——1000ms RTT 下其他方法因请求等待而对吞吐打击严重，Pro-Router 通过窗口化缓冲和队列解耦几乎免疫网络往返延迟。
4. **消融分析验证核心假设**：
   - 用 token 采样分布作为验证器输入优于直接用模型的 hidden states——隐含原因是采样分布是大模型自正则化后的输出信号，信息更紧凑且不需要访问 GPU 显存；
   - 2 层 Transformer Encoder 在精度与开销之间达到最优平衡；更深的 4 层版本收益有限；
   - 全局批量派发和 KV-cache 准入控制分别消除了“空转等待”和“过载抢占”两类系统级瓶颈；
   - 去掉预打分器会降低难易请求的区分度，使验证器面对的压力增大、ship rate 与正确率出现更明显的此消彼长。

## 7. 局限与未解决问题

- **单验证器跨基准泛化的边界未探明**：论文只在 15 个基准上整体训练单个验证器，未详细分析验证器在分布外基准、零样本新任务或对抗性 prompt 下的退化程度。
- **小模型尺寸覆盖面窄**：仅验证了 7B–12B 级别模型，若小模型缩至 1–3B 级别或大模型升到 100B+，token 不确定性的可区分度与路由收益可能发生系统性变化，论文未回答这一尺度外推问题。
- **路由阈值 τ 未自适应**：全局置信度阈值 τ 是静态超参数，而实际部署中请求难度分布会有时间漂移，如何在线调节 τ 以维持最优 ship rate/准确率权衡未给出方案。
- **忠实度评估依赖 LLM judge**：所有正确性标注均依赖外部 LLM judge 与参考答案的口径统一，若 judge 本身出错（尤其在数学、图表这类有唯一客观答案的任务上），会引入噪音甚至偏差。
- **缺少真实部署流量验证**：实验基于 15 个 benchmark 的离线流量重放，未在真实边缘-云混合负载（突发性、相关性、长尾分布）下验证调度器的鲁棒性与公平性。

## 8. 对未来工作的启示

- 可以考虑让验证器在每轮服务后利用真实用户反馈（如是否升级、用户是否满意）在线更新，形成“调度-反馈-再训练”的闭环；
- 阈值 τ 可随每台设备的实时负载、网络带宽和任务难度分布动态调整，使 ship rate 与精度达到当前资源约束下的全局最优；
- 可将 token 不确定性特征扩展到更多模态与更多解码策略（如 beam search、speculative decoding），探索它们在多轮对话和流式输出场景中的路由价值；
- 在更大规模集群中刻画全局调度器自身的瓶颈（调度频率、消息队列吞吐、故障恢复），引入分层或去中心化调度以消除单点竞争。

## 9. 总体评价与推荐结论（关键要点）

- **新颖性**：将已有研究中未被利用的 token 级解码不确定性引入路由决策，这是一个立足系统实践却具有建模洞察力的切入点；同时把“路由决策”和“异构集群调度”从两个独立问题统一为一个端到端联合优化问题，设计闭环充分。
- **系统性**：从信号设计、验证器架构、调度策略到端到端部署，覆盖了 ML 方法与系统工程的完整链路，且每个环节均有明确的量化实验支撑。
- **实践价值**：对于希望在边缘设备上低成本提供大模型能力、或希望在大模型 API 服务中降低推理成本的工业级系统，提供了立即可行的架构参考。
- **结论可信度**：实验设置公平、基线与指标选择规范、消融完整，其主要结论在论文所覆盖的模型规模与任务范围内具有较强说服力；但在更广的模型尺度与实际流量分布上的外推需要进一步验证。

**总结**：本文提出 Pro-Router，利用小模型解码过程中天然产生的 token 级不确定性信号，以 67K 参数的轻量验证器在两阶段流水线中完成“先粗筛、后精判”的路由决策，再结合窗口化批量派发与 KV-cache 准入控制的边缘-云协作调度，消除了网络延迟对关键路径的影响，在 15 个基准、3 种小模型与 4 个强基线的对比中取得了路由精度与端到端吞吐的双重优势。论文的两点最大贡献在于：**发现了 token 采样分布这一零额外 GPU 开销、高信息密度的路由信号**，以及**将路由精度与系统调度效率统一为单个量化目标函数并给出可执行设计方案**。局限方面，其验证器跨域泛化边界、模型尺度外推能力与真实流量下的表现仍需后续研究补足。
