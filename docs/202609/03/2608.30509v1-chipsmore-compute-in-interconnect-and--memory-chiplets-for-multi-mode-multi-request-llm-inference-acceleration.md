## Abstract
Large language model (LLM) inference exhibits substantial variability across adaptation modes, context lengths, and request concurrency, creating challenges for maintaining high utilization, memory efficiency, and scalable performance on compute-in-memory (CIM) accelerators. This paper presents CHIPSMORE, a multi-mode and multi-request LLM inference accelerator that integrates compute-in-interconnect and CIM to support both base-mode and low-rank adaptation (LoRA) inference under diverse workloads. CHIPSMORE employs heterogeneous processing elements consisting of resistive RAM analog compute-in-memory (RRAM-ACIM) and static RAM digital compute-in-memory (SRAM-DCIM) interconnected through a programmable Inter-PE computational network (IPCN). A composable hierarchical key-value (KV) memory scheme dynamically allocates router scratchpad, SRAM-DCIM, and embedded DRAM (eDRAM) resources according to workload requirements, enabling scalable support for long-context and batched inference. Furthermore, a non-replicated multi-request execution pipeline exploits request-level parallelism without duplicating pretrained weights, while a state-aware resource reconfiguration mechanism selectively retains runtime states and power-gates inactive resources to improve energy efficiency. Evaluation using cycle-accurate hardware-software co-simulation demonstrates that CHIPSMORE effectively sustains high throughput across varying model sizes, context lengths, and batch sizes while maintaining favorable power scaling. Compared with Nvidia H100, CHIPSMORE achieves up to $2.38\times$ higher throughput and $27\times$ higher energy efficiency on Mistral-7B inference while eliminating weight replication for multi-request serving.

## 1. 论文的核心问题与整体含义（研究动机和背景）

大语言模型（LLM）推理在不同**适应模式**（基础模式 vs. LoRA 微调）、**上下文长度**以及**请求并发度**之间存在显著的负载差异，这给基于**存内计算（CIM）**加速器实现高利用率、高内存效率与可扩展性能带来了巨大挑战。

现有 CIM 推理加速架构存在以下问题：

- **模式适配单一**：多数现有加速器只支持基础模式推理（base-mode），不支持 LoRA 低秩适配所需的可重编程参数存储。
- **KV Cache 扩展困难**：KV cache 容量随上下文长度和请求批量大小线性增长；仅依赖本地 SRAM 的设计在长上下文与大批次场景下容量受限。
- **并发扩展代价高昂**：现有提速策略普遍通过对权重进行**多副本复制**来获得请求级并行，造成 RRAM 容量、chiplet 数量、面积与功耗随复制因子近似线性膨胀。
- **预填充与解码阶段硬件需求错配**：专为 prefill 优化的设计在 decode 阶段可能闲置，专为长上下文 decode 设计则在短上下文场景下造成面积与静态功耗浪费。

论文的核心目标是设计一种**统一架构**，同时应对适应模式变化、KV cache 容量扩展和多请求并发执行这三大需求维度，在多样化工作负载下保持高利用率、高吞吐量、高能效和高内存可扩展性。

## 2. 论文提出的方法论

### 2.1 总体架构

CHIPSMORE 采用**分层的 chiplet 架构**，由多个计算瓦片（Compute Tile, CT）构成。每个 CT 包含：

- **异构处理单元（PE）**：每个 PE 集成了非易失的 **RRAM 模拟存内计算（RRAM-ACIM）** 与易失的 **SRAM 数字存内计算（SRAM-DCIM）** 宏。RRAM 用于存放不变的基础模型静态权重，SRAM 存放需要快速重新编程的 LoRA 矩阵。
- **可编程互连计算网络（IPCN）**：采用 2D mesh 拓扑连接各 PE，不仅负责数据通信，还能在**网络内部执行运行时动态数据的乘累加（DMAC）** 操作，如注意力分数 $Q\cdot K^T$ 的计算。PE 内 CIM 则执行静态权重相关的乘累加（SMAC）。
- **计算路由器（Unit Router）**：每个路由器与若干个 PE 组成 router-PE 对，路由器带有数据 I/O 端口、控制器和多功能计算宏。
- **嵌入式 DRAM（eDRAM）**：采用 2T0C 无电容单元，提供高密度、容量导向的第三级片上存储。
- **UCIe die-to-die 互连**：支持多个 CT 之间的片间通信，扩展系统规模。

### 2.2 关键技术机制与核心思想

- **持久性感知的计算划分（Persistence-Aware Compute Partitioning）**：将静态权重参与的运算（SMAC）分配给 CIM 宏，将运行时生成的动态中间数据（DMAC）交给 IPCN 内的计算路由器处理，从而实现通信与计算的协同执行，减少激活数据搬运。
- **IPCN 指令集与软件流水线**：IPCN 指令为 30 位控制字，支持单播/广播等通信原语与网内计算。NPM（网络程序存储器）采用 Bank 1/Bank 2 **双缓冲**组织，允许配置协处理器（CC）预载下一段指令，与当前网络执行重叠进行，减少配置暂停。
- **统一空间映射（Unified Spatial Mapping）**：预训练权重（$W_Q, W_K, W_V, W_O$）与 LoRA 适配矩阵采用**相同的几何切分和空间映射**到 PE 阵列，保证 LoRA 贡献可在本地计算并与基础模型投影输出累加，切换模式不重映射 PE。
- **分层 KV 内存分配（Hierarchical KV Memory Allocation）**：根据工作模式动态整合三级资源——路由器 Scratchpad（一级）→ SRAM-DCIM（二级，仅在基础模式用作 KV）→ eDRAM（三级，当容量超过前两级总量）。LoRA 模式下 SRAM-DCIM 保留给适配矩阵，排除在 KV 可用资源之外。
- **非复制多请求流水线（Non-Replicated Multi-Request Pipeline）**：每个 Transformer 层静态映射到唯一的、持有权重的 CT 集群上；多个请求以不同时间偏移注入流水线，穿插占用各层，形成层间流水。模型权重只保留一份物理副本，实现了不复制权重即可扩展的请求级并行。
- **状态感知资源重构（State-Aware Resource Reconfiguration）**：依据状态驻留特性（非易失权重 / 易失 KV 与 LoRA）决定电源关断范围。没有运行时状态的集群可全部 power-gate；有保留状态的集群只保活对应的存储资源，关闭路由器等计算模块。

## 6. 论文的主要结论与发现

- CHIPSMORE 与 Nvidia H100 相比，在 Mistral-7B 推理上实现了**高达 2.38 倍**的吞吐量提升、**27 倍**的能效提升，且在服务多请求时**无需复制权重**。
- 基于 RRAM 加 SRAM 的异构 PE 与基于 SRAM 与 eDRAM 的分层内层缓存的有意识联合，使系统只需要在**少量并发的 KV 需求**与**可配置负载（LoRA）的资源占用**间优化。
- 非复制多请求流水线在不同的批处理约束下运行得相当好，实现了**亚线性缩放**——batch 从 1 增加到 4 时，对于 Llama 3.2-1B 约获 3.91× 吞吐量提升，Mistral-7B 约获 2.71×，Qwen3-14B 约获 2.77×——但这受限于 pipeline 填充/排空时延、层独享阶段和通信带宽竞争等因素。
- LoRA 推理的性能代价主要取决于 **KV 存储层次的改变而非低秩计算本身的计算开销**——当 SRAM-DCIM 被 LoRA 占用而迫使 KV 数据推到 eDRAM 时，吞吐量因更高的 KV 访问延迟而大幅下降（batch=1 时可降至约 0.71×），但在 batch=4 时大多恢复至约 0.95×。对于小 KV 总量的 Llama-1B，短/长上下文下 LoRA 与 Base 的性能差距微乎其微。
- 在测量系统中，功耗的主导组件是**IPCN 与路由器子系统**，状态感知的功耗门控使空闲的流水级得以保持活跃，并以亚线性功耗扩展方式运行；更大模型和更多 batch 的功耗代价比吞吐量提升所需代价更低。
- 片间 UCIe 互连在 batch=4 时最大利用率仍低于 25%，证明大多数数据移动被高效本地化在 tile 内部，芯片间 fabric 不会成为系统瓶颈。

## 7. 优点

- **创新性高**：将“计算”嵌入互连网络（IPCN），改变了传统加速器中 Compute 与 Communication 相对独立的结构，实现了通信芯片上的原位计算（DMAC）与 CIM 之间对权重驻留分区运维的互补。
- **统一框架**：首次在统一架构中处理了**适应模式（Base/LoRA）× KV 容量扩展 × 请求并发/调度 × 供电管理**，闭环地**联合**处理这些变量，而非把它们当作孤立的垂直机构。这在现有表 I 中是比较罕见的。
- **权限/权重管理的透明度与灵活性**：权重的非复制策略降低了多请求服务的资源使用，用流水填充替代 RRAM 复制，不增加芯片面积即可增加吞吐量。
- **分级 KV 内存设计完善**：设计了面向不同上下文长度的三层内存分级，能根据 Base/LoRA 等需求动态重新划分已分配的硬件。能顺带给出可扩展**非易失性**内存架构设计的新思维。
- **发布环境良好**：通过周期精确模拟、RTL 逻辑验证、7nm 综合和真实模型配置对方法进行了校准，并对比了用于大规模推理的比较基准。
