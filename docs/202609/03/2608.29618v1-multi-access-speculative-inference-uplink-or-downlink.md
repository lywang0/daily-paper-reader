## 摘要
多接入推测式推理（Multi-SPIN）将SPIN扩展到多设备边缘网络，以加速协作式令牌生成。它允许设备端小语言模型（SLM）为各个生成任务自回归地草拟多个令牌，而边缘服务器上的大语言模型（LLM）则并行验证这些令牌。主要的通信开销出现在草拟令牌被服务器拒绝时，此时采样修正令牌需要同时访问SLM输出的草稿分布和LLM输出的目标分布，且二者均覆盖完整词表。现有设计通常通过上传草稿分布在服务器端执行修正，但传输全词表分布会造成严重的上行（UL）瓶颈。另一种方案是利用下行（DL）可用的高传输速率，通过下载目标分布在设备端执行修正。受此启发，我们将通信模式选择引入为Multi-SPIN的一个新设计维度。具体而言，每个设备可在UL与DL模式之间自适应切换，以在UL瓶颈与共享DL资源约束之间取得平衡，从而缓解整体通信负担。我们构建了一个总和令牌好put最大化问题，该问题联合考虑模式选择、草稿长度控制与功率分配。对于模式选择，我们揭示了一种简单的优化结构，可实现对上行设备数量的高效搜索，并相应优化其发射功率。对于草稿长度控制，我们提出了一种贪婪搜索算法，使设备特定的草稿长度适应异构的计算与通信能力。在Qwen2.5与DeepSeek-R1模型对上的实验结果表明，所提框架显著提升了令牌好put。

## Abstract
Multi-access speculative inference (Multi-SPIN) extends SPIN to multi-device edge networks to accelerate cooperative token generation. It allows on-device small language models (SLMs) to autoregressively draft multiple tokens for individual generation tasks, while an edge-server large language model (LLM) verifies them in parallel. The major communication overhead arises when a drafted token is rejected by the server, in which case sampling the correction token requires access to both the SLM-output draft distribution and the LLM-output target distribution over the full token vocabulary. Existing designs typically perform correction at the server by uploading the draft distribution, but transmitting a vocabulary-wide distribution creates a critical uplink (UL) bottleneck. Alternatively, the correction can be performed at the device by downloading the target distribution, leveraging the high transmission rates available on the downlink (DL). Motivated by this insight, we introduce communication-mode selection as a new design dimension for Multi-SPIN. Specifically, each device can adaptively switch between the UL and DL modes to balance the UL bottleneck against the shared DL resource constraint, thereby relieving the overall communication burden. We formulate a sum-token-goodput maximization problem that jointly accounts for mode selection, draft-length control, and power allocation. For mode selection, we reveal a simple optimal structure that enables efficient search over the number of UL devices, with the corresponding transmit powers optimized accordingly. For draft-length control, we develop a greedy-search algorithm that adapts device-specific draft lengths to heterogeneous computation and communication capabilities. Experimental results on Qwen2.5 and DeepSeek-R1 model pairs demonstrate that the proposed framework significantly improves token goodput.

## 1. 核心问题与整体含义（研究动机与背景）

- 论文关注 **边缘部署大语言模型（LLM）时的高效推理**。在边缘网络中，设备本地运行全尺寸大模型不现实，而仅依赖服务器执行会产生中心化推理瓶颈，尤其因为 LLM 解码是自回归的、逐 token 顺序生成，计算开销大。
- **推测式推理（Speculative Inference, SPIN）** 是一种新兴方案：设备端部署轻量级小语言模型（SLM）快速自回归生成多个草稿（draft）token；服务器端的大语言模型（LLM）对整段草稿进行并行验证。若草稿全部被接受，则一次前向即可产生多个 token；若某个 token 被拒绝，则需要从“残差分布”中采样修正 token。
- **关键瓶颈**：当 token 被拒绝时，修正采样需要同时访问 SLM 的全词表“草稿分布”和 LLM 的全词表“目标分布”。现代 LLM 词表可达十余万项（如 Qwen2.5 词汇约 15 万），传输这样的高维分布在无线链路上会产生巨大通信开销。
- 现有研究大多采用“上行（UL）模式”：设备将草稿分布上传至服务器，服务器执行修正。然而这会形成 UL 瓶颈。
- 本文提出利用“下行（DL）模式”：服务器将目标分布下载到设备，设备本地完成修正。DL 速率通常高于 UL，但在多设备系统中，若所有设备都选 DL 模式，又会竞争服务器有限的共享 DL 功率。
- 因此，论文引入 **通信模式选择（UL/DL mode selection）** 作为 Multi-SPIN 的新设计维度，让每个需要修正的设备自适应选择 UL 或 DL 模式，从而在“UL 速率瓶颈”和“DL 共享资源约束”之间取得最优平衡。
- 最终目标：协同优化模式选择、草稿长度（draft length）和发射功率，最大化系统总的**有效令牌吞吐量（token goodput）**，即所有设备每秒平均输出/提交的 token 数。

## 2. 方法论：核心思想、关键技术细节与算法

### 2.1 系统协议
- 每轮生成开始时，服务器**主动（proactive）** 选择每个设备的草稿长度 \( \gamma_k \)。
- 设备用本地 SLM 自回归生成 \( \gamma_k \) 个草稿 token，仅需上传“(token, token 的草稿概率)”标量对。
- 服务器对所有设备的草稿进行**批处理并行验证**（单次 LLM 前向覆盖多个 token 和多个设备）。
- 根据验证结果：
  - 全部接受：服务器采样一个 bonus token 返回设备，通信开销可忽略。
  - 有拒绝：进入修正流程，设备集合记为 \( R(o) \)。对每个被拒设备，服务器**响应式（reactive）** 地决策通信模式 \( m_k \in \{\text{UL}, \text{DL}\} \) 和发射功率 \( p_k \)。
- UL 模式：服务器下发被拒位置，设备上传该位置的草稿分布，服务器采样修正 token，再下发。
- DL 模式：服务器下发被拒位置及目标分布，设备采样修正 token，再上传给服务器。
- 这种“先主动定草稿长度，后响应式定通信模式和功率”的时序，构成两阶段随机优化结构。

### 2.2 优化问题
- 定义每轮输出 token 数期望：
  \[
  \bar{L}(\gamma)=\sum_{k\in K} \frac{1-\alpha_k^{\gamma_k+1}}{1-\alpha_k}
  \]
  其中 \( \alpha_k \) 为每个 draft token 的平均接受概率。
- 计算延迟 = 最大本地草稿延迟 + 服务器批验证延迟：
  \[
  T_{\text{comp}}(\gamma)=\max_{k}\gamma_k T_k^{\text{dft}} + T_{\text{ver}}
  \]
- 通信延迟 = 在一次验证结果 `o` 下，所有被拒设备传输分布的最大延迟（正交带宽分配，UL 用设备最大功率，DL 受服务器总功率约束）。
- 目标函数定义为期望有效令牌吞吐量（goodput）：
  \[
  G(\gamma,\chi)=\frac{\bar{L}(\gamma)}{T_{\text{comp}}(\gamma)+\mathbb{E}_{o|\gamma}[T_{\text{comm}}^{\min}(o)]}
  \]
  其中 \( \chi \) 是响应式通信策略，\( T_{\text{comm}}^{\min}(o) \) 为给定结果下最优通信延迟。
- 问题分解为：
  1) **响应式模式选择与功率分配**：对每个结果 \( o \)，最小化通信延迟；
  2) **主动式草稿长度控制**：在期望意义下最大化 goodput。

### 2.3 响应式模式选择与功率分配的最优解
- **固定模式下的功率分配**：
  - UL 设备一律采用最大可用 UL 功率，最小化传输延迟。
  - DL 设备在服务器总功率约束下，通过“延迟均衡”求解最优功率分配（Lemma 1，闭式解可通过二分求出）：
    \[
    p_k^\star=\frac{N_0^{\text{dev}} B_k}{|h_k|^2}\left(2^{\frac{V_{\text{eff}}(\lceil \log_2 V\rceil+Q)}{B_k \tau_{\text{dl}}}}-1\right)
    \]
    其中 \( \tau_{\text{dl}} \) 由总功率约束唯一确定。
- **模式选择的“前缀结构”（Lemma 2）**：
  - 将所有被拒设备按各自的最小 UL 延迟从小到大排序。
  - 存在最优解：第一个到第 \( n \) 个设备选 UL，其余选 DL。也就是说，UL 设备集合必然是排序后的前缀 \( U(n) = \{1,\dots,n\} \)。
  - 这使组合搜索退化为对分裂点 \( n \) 的一维搜索。
- **二分搜索（Proposition 1）**：
  - UL 延迟随 \( n \) 单调递增，DL 延迟随 \( n \) 单调递减，因此二者之差 \( \Delta\tau(n)=\tau_{\text{dl}}(n)-\tau_{\text{ul}}(n) \) 单调递减。
  - 最优分裂点在 \( \Delta\tau(n) \) 穿越零点附近，只需比较 \( \bar{n}-1 \) 与 \( \bar{n} \) 两个候选即可，且 \( \bar{n} \) 可二分定位。
  - 每次评估都调用最优 DL 功率分配，因此模式选择和功率分配是**联合优化**，而非两阶段分离近似。

### 2.4 主动式草稿长度控制（贪心算法）
- 草稿长度优化是随机、非凸的，且目标没有闭式形式。
- 采用**两阶段贪心**：
  1) 同步更新：所有设备草稿长度同时加 1，只要 goodput 提高就继续；
  2) 坐标更新：每次只给单个设备草稿长度加 1，选择收益最大的设备，直到无改善。
- 为了避免对全部 \( 2^K \) 个验证结果枚举，使用**样本均值近似（SAA）**，按接受概率分布采样 \( N_{\text{SAA}} \) 个验证结果，用样本平均估计期望通信延迟，从而降低复杂度。

## 6. 主要结论与发现

1. **自适应 UL/DL 模式选择能显著提升 token goodput**：在共享 DL 功率受限、UL 功率不对称的情况下，没有一种固定模式全局最优；只有将一部分设备放在 UL、一部分放在 DL 才能同时避免 UL 瓶颈和 DL 竞争。
2. **最优模式具有前缀结构**：按 UL 延迟排序后，最优选择是“前 \( n \) 个设备走 UL，后面对设备走 DL”，可将指数级搜索降至二分搜索，且与最优功率分配联合实现。
3. **草稿长度应与通信能力耦合**：
   - DL 功率预算越大，平均最优草稿长度越长，因为接收更充分的并行验证收益，且拒绝触发高通信开销的概率影响变小。
   - 只考虑计算延迟而忽略通信开销的草稿长度控制会损失 goodput。
   - 采用“先同步后逐步调整”的贪心法可有效适配异构设备。
4. 在 Qwen2.5 和 DeepSeek-R1 两组模型对上，所提框架始终优于 all-UL、all-DL、随机模式、uniform 及 computation-only 草稿长度控制等基准。

  - 将随机验证结果建模为两阶段随机优化，区分“先验草稿长度”和“后验模式/功率选择”；
  - 使用 SAA 避免指数复杂度，具备可扩展性。
- **实验跨模型、跨任务、跨系统参数**，比较了不同模式选择和不同草稿长度策略，较有说服力。
- 从“计算卸载”延伸到“通信方向卸载”，思想具有启发意义。

## 8. 不足与局限

- **理想化通信假设**：假设正交带宽固定均分、信道状态完全已知、块衰落；未考虑调度、分配带宽的优化，也未考虑多天线、干扰和随机接入的不确定性。
- **计算延迟模型简化**：认为批验证

- **计算延迟模型简化**：认为批验证延迟与草稿长度、设备数之间呈简单线性关系，且将各设备的草稿生成延迟仅乘以一个均匀随机因子（1–1.15）来近似异构性，未细粒度建模真实解码中的 KV cache 管理、显存带宽、batch 尺寸对前向/生成时延的非线性影响；对 GPU 算力占用、并发调度开销也做了理想化处理。
- **接受率高度静态化**：将 token 接受率 \( \alpha_k \) 视为任务/模型对的一阶经验常数，忽略了其随生成上下文、已生成 token 内容动态变化的事实。真实 SPIN 中每轮草稿的接受概率与语义分布密切相关，而论文的优化式与 SAA 采样均基于固定均值，可能高估或低估拒绝概率与通信负载。
- **单轮孤立建模**：整个 goodput 优化只针对单轮草稿—验证过程，没有考虑多轮之间的状态依赖（如 cache 重用、草稿长度对后续上下文的反馈、自适应学习），也未处理设备异步到达、任务持续流入等实际边缘场景。
- **缺乏用户公平性约束**：最大化系统总 goodput 可能使部分信道差或距离远的设备长期处于低吞吐状态；文中没有加权公平性、时延分位数或最低 QoS 保证等考量。
- **DL 下行传输假设过于乐观**：假设服务器能在一次响应中把目标分布（如有效词表项、量化概率）无损下发给设备，未计入下行控制信令、广播/组播效率、ACK/NACK 开销及多设备间的下行干扰；对 OFDMA 资源块分配也仅为均分，未联合优化带宽与模式选择。
- **实验环境偏仿真化**：无真实无线信道波形验证，也未搭建多设备+多 GPU 实际测试床；所有结论依赖数学建模与数值仿真，对硬件同步、协议鲁棒性、端侧电池限制等现实问题考察不足。

总体而言，该工作为多设备边缘 SPIN 提供了一个重要的优化框架，理论贡献清晰、算法可操作性强，但其性能增益在真实系统中可能因非理想信道、动态语义和不精确时延模型而有所折扣；未来可在自适应接受率估计、联合带宽与模式分配、以及多轮公平性优化方向上进一步拓展。
