## 摘要
LLM 服务系统越来越多地将推理解耦为更细粒度的阶段，近期方法在解码期间将注意力与 FFN 或 MoE 执行分离。这种算子级解耦服务（ODS）可以改善硬件匹配并实现独立扩展，尤其是在异构设备上。然而，现有系统固定算子边界，并且缺乏对解耦何时降低服务成本的统一刻画。我们提出 OpWeave，一个面向异构 ODS 的端到端框架。OpWeave 提供一种分析成本模型，用于界定同构与异构 ODS 相对于共置服务的收益上界。它通过一个规律性感知规划器联合优化算子划分与部署配置，即使对于混合注意力模型也能保持搜索可处理。基于 vLLM 的运行时以跨异构设备组的灵活算子阶段执行合成方案。在我们的评估中，相对于最佳可行基线，OpWeave 在同构 GPU 集群上将服务成本最多降低 $1.78\times$，在异构 GPU 集群上最多降低 $1.89\times$，同时满足延迟 SLO。

## Abstract
LLM serving systems increasingly disaggregate inference into finer-grained stages, with recent approaches separating attention from FFN or MoE execution during decode. This operator-level disaggregated serving (ODS) can improve hardware matching and enable independent scaling, particularly across heterogeneous devices. However, existing systems fix operator boundaries and lack a unified characterization of when disaggregation reduces serving cost. We present OpWeave, an end-to-end framework for heterogeneous ODS. OpWeave provides an analytical cost model that bounds the gains of homogeneous and heterogeneous ODS over colocated serving. It jointly optimizes operator partitioning and deployment configuration through a regularity-aware planner that keeps the search tractable even for hybrid-attention models. A vLLM-based runtime executes the synthesized plans with flexible operator stages across heterogeneous device groups. In our evaluation, OpWeave reduces serving cost by up to $1.78\times$ on homogeneous and $1.89\times$ on heterogeneous GPU clusters relative to the best feasible baseline, while meeting latency SLOs.

- **背景**：LLM 推理占 AI 基础设施支出的很大比重，decode 阶段在生成密集型负载（如长输出推理任务）中主导延迟与成本。现代服务系统已从粗粒度解耦（prefill/decode 分离）走向**算子级解耦服务（Operator-level Disaggregated Serving, ODS）**，即在 decode 期间将 attention 与 FFN/MoE 执行分离。
- **动机（两类共置低效）**：
  - **硬件匹配差**：decode attention 受内存带宽限制、张量核利用率低；FFN/MoE 依赖矩阵乘、受益于高算力（图 2a）。
  - **内存容量耦合**：序列变长时 KV cache 膨胀，压缩整个工作负载的可行 batch size，拖累 FFN/MoE 吞吐（图 2b）。
- **异构 ODS 的潜力**：把不同算子阶段分配到最适合其资源瓶颈的设备类型上，并实现独立扩展（FFN/MoE 的 batch 不再受 attention 侧 KV cache 容量直接约束）。
- **现有工作的三大缺口**：
  - **理论缺口**：只有针对特定设计的经验证据/局部模型，缺少统一刻画"何时解耦能降本"及收益上界。
  - **规划缺口**：现有系统（如 AFD）固定 attention–FFN/MoE 边界，无法联合优化算子划分、硬件分配、并行策略与批大小；对**混合注意力模型**（层间结构不同）尤其受限。
  - **运行时缺口**：既有 ODS 运行时围绕固定切分组织执行与通信，缺乏灵活算子分阶段、流水编排与低开销跨异构设备组通信能力。
- **整体含义**：OpWeave 是首个把"理论分析—部署规划—运行时执行"打通的端到端异构 ODS 框架，主张**边界应可搜索而非固定**。

## 2. 方法论

### 2.1 核心思想
以**解析成本模型**界定收益上界，用**规律性感知规划器**在可处理的搜索空间中联合优化划分与部署，再由**基于 vLLM 的分布式运行时**执行合成方案。

### 2.2 解析成本模型（第 3 节）
- **设定**：稳态 decode；attention 视为内存受限（时间 ≈ 访存/带宽），GEMM 类算子视为算力受限（时间 ≈ FLOP/峰值算力）；每类 GPU 有单位时间成本 $c$、带宽 $\beta$、容量 $M$、峰值算力 $F$。
- **关键量**：$\alpha_j = c_j/\beta_j$（每字节访存成本）、$\gamma_j = c_j/F_j$（每 FLOP 成本）；$m_{kv}(s)$ 为每请求 KV cache，$P_{act}$ 为每请求激活的 GEMM 参数，$M_{weights}$ 为常驻权重占用。
- **同构 ODS 成本**：$CPT^{hom}_j(s) = \alpha_j m_{kv}(s) + 2\gamma_j P_{act}$
- **异构 ODS 成本**：$CPT^{het}_{j,k}(s) = \alpha_j m_{kv}(s) + 2\gamma_k P_{act}$（attention 放 $j$，GEMM 放 $k$）
- **共置成本**：受 $\bar b(s) = (M - M_{weights})/m_{kv}(s)$ 约束，$CPT^{coloc}_j(s) = \alpha_j m_{kv}(s) + \max\left(\frac{\alpha_j M_{weights}}{\bar b(s)},\ 2\gamma_j P_{act}\right)$
- **GEMM 阈值**：$b^* = \dfrac{M_{weights} F}{2 P_{act} \beta}$，即 GEMM 由"载权重受限"转为"算力受限"的批大小分界。

**定理 3.1（同构解耦 vs 共置）**：对可行序列长度，
1. 若 $\bar b(s) \ge b^*$，则增益 $G_{hom}(s)=1$（短序列无增益）；
2. 在 $\bar b(s) < b^*$ 区域，$G_{hom}(s)>1$ 且随 $s$ **严格递增**；
3. 增益有上界：$1 \le G_{hom}(s) < \dfrac{M}{M - M_{weights}}$。

**定理 3.2（异构 vs 同构解耦）**：设硬件比 $\eta = (\beta_1 F_2)/(\beta_2 F_1)$，
1. $G_{het}(s) \ge 1$（非负增益）；
2. 若某类 GPU 在 $\alpha$ 与 $\gamma$ 两个维度上均占优，则 $G_{het}(s)=1$；
3. 否则（$\alpha_1<\alpha_2$、$\gamma_2<\gamma_1$），以 $x = m_{kv}(s)$ 为自变量，增益**单峰**：在交叉点 $x^* = \dfrac{2P_{act}(\gamma_1-\gamma_2)}{\alpha_2-\alpha_1}$ 前递增、之后递减，峰值处有 $G_{het}(s) \le \dfrac{1+\sqrt{\eta}}{2}$。

### 2.3 CAD 及其局限（从界到方案）
- **Core-Attention Disaggregation (CAD)**：核心 attention 一个设备组、其余投影/FFN/MoE 另一设备组，可逼近理想 ODS 成本，但需**阶段时延平衡 + 充分微批隐藏通信**。
- **局限 1（平衡可行性）**：attention 侧最大可行时延 $T^{max}_{attn} = M_1/(\mu\beta_1)$ 与 GEMM 侧权重加载下界 $T^{min}_{rest} = M_{weights,2}(\pi_2)/\beta_2$ 若区间不相交，则必然出现流水气泡（图 6）；高带宽 GEMM 设备可降低该下界。
- **局限 2（层间差异）**：混合注意力模型（full / sliding-window / linear attention）层间时延差异巨大（Qwen3-Next 128K、batch=1 时全注意力约 700 μs vs 线性注意力 58 μs，12×），固定的两阶段划分无法同时平衡两类层（图 7）。

### 2.4 服务方案形式化（第 4 节）
- **划分块（partition block）抽象**：模型中最小、按层对齐、重复出现的算子模式，作为计划构造与复用的单位；块内选连续阶段模板 $q=(q_0,\dots,q_S)$，阶段可跨层边界。
- **结构化放置**：$K$ 个有序设备组类型，$S = kK$，轮转映射 $\sigma(j) = ((j-1)\bmod K)+1$，每类在每个划分块拥有相同阶段位置，从而可复用同一流水结构。
- **通信感知时延模型**：阶段执行时延 $t_j$、边界传输时延 $u_j$（含并行布局重分布），流水往返时间 $T_{rtt} = f_{rtt}(\mu, B_{total}, \mathbf t, \mathbf u)$，由调度模拟器评估（支持计算–通信重叠、资源竞争）。
- **优化问题**：$\min_{\mathcal P} CPT_{plan} = T_{rtt}\sum_{m=1}^{K}\frac{c_m}{b_m}$，约束 $T_{rtt} \le T_{SLO}$ 且 $M_{weights,m} + \mu KV_m(\hat b_m, s) \le M_m$。
- **表达力**：AFD、CAD 与共置分别对应该空间中的受限模板；OpWeave 可隔离昂贵全注意力算子、把高效注意力与相邻投影合并、跨层联合平衡。

### 2.5 规划算法（第 5 节，算法 1）
- **规律性感知子块模板**：把模板搜索限制在一个子块内并平铺 $n$ 次，模板数从 $\binom{N_{block}-1}{S-1}$ 降为 $\binom{N_{block}/n-1}{K-1}$（结构性限制，非代价启发式剪枝）。
- **网络安全 Pareto 前沿**：每个 owner 的点用 $z_m(p) = (\mathbf T_m(p), r_m(p), \rho_m(p), \hat b_m(p))$ 比较；仅在**相同张量并行度**下才可支配（传输量随 TP 非单调）；保留逐阶段时延向量，避免误删对某类层有利的点。
- **精确分支定界**：用前缀的乐观完成估计（串行计算下界 $L_{comp}$ 与网络端点下界 $L_{net}$ 取大者 $L_T$，再乘后缀最小归一化成本）剪枝；仅存活者进入调度模拟器。在配置的有限网格上**精确**，最坏复杂度 $\prod_m |\mathcal F_m|$。

### 2.6 运行时（第 6 节）
- 32K 行 Python/C++，基于 vLLM GPU model runner；worker 只加载分配到的模型组件与状态。
- 跨节点用点对点 NCCL，节点内用 CUDA IPC peer copy + GPU doorbell 扇出。
- **三项优化**：① **单次原生提交**（每个 token 一次 native call 入队所有 CUDA graph 启动、staging 拷贝、通信轮次与事件依赖，消除 Python/RPC 开销）；② **GPU 常驻解码**（token ID 在 GPU 上生成，一次 NCCL all-reduce 分发，仅 rank 0 保留历史）；③ **低开销通信**（打包共享缓冲、批量 NCCL 轮次、leader 单次跨节点拷贝 + 本地 IPC 扇出，leader 轮换）。

## 5. 实验结果与主要发现

### 5.1 同构端到端（图 9）

- 在 **2×H100 + 2×L40S（Gemma-3-27B）** 与 **4×H100 + 4×L40S（Qwen3-Next-80B-A3B）** 实机上，模拟器预测的成本/时延与实测吻合良好，支撑了后续在模拟器上开展的大规模异构评测的可信度。

### 5.4 异构端到端（图 13）
- 在 **H100+L40S** 与 **H100+A100** 两种异构组合、共 12 组配置中，异构 ODS 相对同构部署进一步降本，且异构收益同样随上下文长度增长。
- 结果与定理 3.2 的**单峰增益**预测一致：存在一个最优序列长度区间使异构收益最大，过长或过短序列下增益回落（因为此时 attention 或 GEMM 的瓶颈结构发生变化）。

### 5.5 规划器消融（表 3）
- 对比 **Full / No-PF（去掉 Pareto 前沿）/ No-B&B（去掉分支定界）/ Neither** 四种变体，在两种硬件上：
  - 去掉 Pareto 前沿会因过早剪枝丢失对特定层有利的候选点，导致最终方案成本上升；
  - 去掉分支定界会大幅增加搜索耗时（接近穷举），而方案质量提升有限；
  - 二者结合（Full）在**方案质量与搜索耗时的权衡**上最优。

### 5.6 网络敏感性（图 14）
- 在延迟 **5–500 μs**、带宽 **1–32 GB/s** 范围内扫描：OpWeave 在较宽的网络条件下仍优于基线；当网络极差（高延迟/低带宽）时，规划器会自动倾向**更少阶段、更少跨设备传输**的方案，体现规划对网络条件的自适应。

## 6. 贡献与创新点

1. **理论层面**：首次给出统一解析成本模型，刻画同构解耦相对共置的增益区间与上界（定理 3.1），以及异构相对同构解耦的单峰增益形态与峰值上界（定理 3.2），把"何时解耦能降本"从经验判断变为可解析结论。
2. **规划层面**：提出**规律性感知**的服务方案规划器，把算子划分、硬件分配、并行策略与批大小纳入同一联合优化空间；通过子块模板平铺、网络安全 Pareto 前沿与精确分支定界，在可处理规模内求得高质量方案，突破 AFD/CAD 固定边界的限制，并自然适配**混合注意力模型**。
3. **运行时层面**：基于 vLLM 构建支持灵活算子分阶段、流水编排与低开销跨异构设备组通信的分布式运行时，通过**单次原生提交、GPU 常驻解码、低开销通信**三项优化把规划方案落地为可执行的流水。
4. **系统性**：端到端打通"理论—规划—运行时"，并在同构与异构、多模型、多上下文、多 SLO 条件下给出系统性验证。

## 7. 局限与开放问题

- **理论模型的简化假设**：解析模型假设 attention 纯访存受限、GEMM 纯算力受限、稳态 decode，未充分覆盖 prefill/混合负载、算子融合带来的边界模糊、以及通信与计算的精细重叠效应；增益上界为理想化结果。
- **规划复杂度**：分支定界最坏复杂度为 $\prod_m |\mathcal F_m|$，在设备类型/副本数进一步扩大时可能难以保持可处理；论文将搜索限制在 ≤32 GPU、≤3 类设备、≤4 副本、≤4 微批，更大规模的扩展性未充分验证。
- **异构评测依赖模拟器**：异构端到端结论主要来自模拟器（虽有保真度验证），真实异构集群（尤其跨节点、跨厂商 GPU 混合）的部署可行性、驱动/通信栈兼容性与稳定性未充分展开。
- **运行时工程依赖**：实现深度绑定 vLLM 与 CUDA/NCCL，向其他推理栈或非 NVIDIA 加速器移植的成本与可行性未讨论。
- **成本模型输入**：$m_{kv}(s)$、$P_{act}$ 等量的估计精度、以及成本参数（$/GPU-h、带宽、算力）随云环境波动对规划结果的影响未做敏感性分析。
- **未涉及训练/微调**：论文聚焦推理服务，未讨论对模型结构或算子实现进行协同设计以进一步扩大解耦收益的可能。

---

## 8. 总体评价

OpWeave 的核心洞见是：**在 ODS 中，attention 与 FFN/MoE 的切分边界不应固定，而应作为可搜索的决策变量**，并由解析理论提供收益上界、由规划器在真实约束下求解、由运行时落地执行。它把此前零散的"是否解耦、如何解耦"经验证据提升为可解析、可优化、可执行的端到端框架，尤其在长上下文与混合注意力模型这两类现代负载上展现出对共置与固定划分基线的稳定优势。其主要待补强之处在于理论假设的覆盖面、大规模异构场景的实机验证与运行时的可移植性。
