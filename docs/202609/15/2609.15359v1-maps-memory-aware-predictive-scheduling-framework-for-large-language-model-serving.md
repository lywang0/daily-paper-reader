## 摘要
大语言模型（LLM）应用在个人设备上的激增，给云服务基础设施带来了大规模、突发性的负载。尽管预填充-解码分离提高了吞吐量和可扩展性，但受内存限制的解码实例常常遭受持续负载不均衡，因为请求到达云端时输出长度未知。为解决这一问题，我们提出 MAPS，一种面向分离式 LLM 服务的内存感知预测调度框架。MAPS 执行设备辅助的推测性输出长度预测，并与云端预填充重叠进行，仅引入可忽略的延迟开销。为处理生成不确定性，MAPS 采用不确定性感知校准来推导具有目标覆盖率的输出长度上界，从而支持安全的调度决策。基于这些上界，MAPS 采用分层全局-局部调度策略，以缓解解码器间队列堆积和解码器内队头阻塞。在两个真实工作负载和两个 LLM 上的大量实验表明，MAPS 显著优于三个最先进系统，将平均端到端延迟降低 42.6，并将尾部延迟最多降低 84.8。

## Abstract
The surge of large language model (LLM) applications on personal devices imposes massive, bursty workloads on cloud serving infrastructure. While prefill-decode disaggregation improves throughput and scalability, memory-bound decode instances often suffer from persistent load imbalance, as output lengths are unknown when requests arrive at the cloud. To address this, we propose MAPS, a Memory-Aware Predictive Scheduling framework tailored for disaggregated LLM serving. MAPS performs device-assisted speculative output length prediction overlapped with cloud-side prefilling, incurring negligible latency overhead. To handle generation uncertainty, MAPS applies uncertainty-aware calibration to derive output-length upper bounds with target coverage, enabling safe scheduling decisions. Building on these bounds, MAPS employs a hierarchical global-local scheduling strategy to mitigate inter-decoder queue buildup and intra-decoder head-of-line blocking. Extensive experiments on two real-world workloads and two LLMs show that MAPS significantly outperforms three state-of-the-art systems, reducing average end-to-end latency by 42.6 and tail latency by up to 84.8.

  - 长度预测调度多局限于**单解码实例内部**，难以扩展到跨实例请求放置。
  - 预测若在关键推理路径上执行，会引入额外延迟。
  - LLM 生成本身不确定，点预测不足以支撑安全调度。
  - 迁移式方案如 Llumnix 属于事后补救，长请求 KV Cache 迁移开销大。
- **论文含义**：MAPS 试图将“设备端轻量预测 + 云端不确定性校准 + 分层调度”结合，在 PD 分离式 LLM 服务中实现低开销、内存感知、预测驱动的调度，缓解负载不均与尾延迟问题。

## 2. 方法论：核心思想与关键技术

### 2.1 整体架构

MAPS 包含三条协调路径：

- **推理路径**：请求进入云端 prefiller 进行预填充，再路由到 decoder 解码。
- **预测路径**：请求源设备上运行轻量投机预测器 SP，预测输出长度；结果送入云端不确定性校准模块 UAC。
- **状态反馈路径**：运行时状态收集器 RSC 持续收集各 decoder 的空闲块、保留块、有效块、队列长度等信息，指导调度。

### 2.2 设备辅助投机预测（SP）

- **目标**：在解码前尽早估计输出长度，且不显著增加 TTFT。
- **实现**：
  - 在请求源设备上部署轻量 LLM，与云端 prefill **并行执行**，从而隐藏预测延迟。
  - 输入为原始 prompt 加预测指令，要求模型返回一个非负整数，估计“LLM 可能生成的最大输出 token 数”。
  - 使用 **LoRA** 对 SP 进行参数高效微调。
  - 训练监督目标来自多个下游 LLM（如 LLaMA、Qwen）在多个温度下的最大输出长度，偏向保守上界。
- **实现变体**：
  - SP-7B：Vicuna-7B backbone，代表较强边缘设备。
  - SP-160M：Vicuna-160M，面向内存受限设备。

### 2.3 不确定性感知校准（UAC）

- **动机**：LLM 生成随机性强，低估输出长度比高估更危险，可能引发排队、抢占和尾延迟。
- **方法**：采用 **保形预测（conformal prediction）**，将点预测转为具有覆盖保证的上界。
- **关键步骤**：
  - 维护最近 \(n\) 个已完成请求的校准集 \(D_{cal} = \{(X_i, L^{out}_i, \hat{L}^{out}_i)\}\)。
  - 定义单边非一致性分数，仅惩罚低估：
    \[
    s_i = \max(0, L^{out}_i - \hat{L}^{out}_i)
    \]
  - 给定误覆盖率 \(\alpha\)，计算经验 \((1-\alpha)\) 分位数：
    \[
    q_\alpha = \text{Quantile}(\{s_1,\dots,s_n\}, \lceil(1-\alpha)(n+1)\rceil)
    \]
  - 校准上界：
    \[
    \hat{L}^{up} = \hat{L}^{out} + q_\alpha
    \]
  - 理论上满足：
    \[
    P(L^{out} \le \hat{L}^{up}) \ge 1-\alpha
    \]
- **实现设置**：\(\alpha=0.1\)，滑动窗口最近 500 个请求，以适应非平稳分布。

### 2.4 分层全局-局部调度

#### 全局：内存感知调度

- 对每个请求 \(i\)，调度器获取校准上界 \(\hat{L}^{up}_i\)，若超时 \(\beta\) 未获得则回退 RR。
- 估算 KV Cache 需求：
  \[
  B^{need}_i = \left\lceil \frac{L^{prom}_i + \hat{L}^{up}_i}{S} \right\rceil
  \]
  其中 \(S\) 为 PagedAttention 的块大小。
- 对每个 decoder \(d_k\)，若其有效块 \(B^{eff}_k \ge B^{need}_i\)，则视为可行。
- 在可行 decoder 中，选择**等待队列长度最小**者 \(d^\star = \arg\min Q_k\)，以降低排队延迟。
- 若无可行 decoder，则退化为选择剩余容量最大者，保证前向进展。
- 路由后原子预留所需块，避免并发竞争。

#### 局部：SJF 重排序

- 每个 decoder 维护 ready queue，按校准上界 \(\hat{L}^{up}\) 升序重排，近似最短作业优先。
- 由于固定模型下解码时间约与输出长度成正比，\(\hat{L}^{up}\) 可作为执行时长代理。
- 为避免长请求饥饿，设置最大等待时间阈值，超过则提升优先级。
- 该策略缓解队头阻塞，降低平均完成时间。

### 2.5 时间线设计

- 设备端预测和校准与云端 prefill **重叠**，通常被 prefill 完全掩盖。
- 额外调度开销约 1–2 ms，相比解码时间可忽略。
- 主要延迟收益来自解码阶段：减少排队和 HOL 阻塞。
