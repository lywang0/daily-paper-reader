## 摘要
具备函数调用能力的大型语言模型（LLM）正成为现代智能体 AI 系统的关键。然而，当前部署通常将推理路由到强大的云端模型，导致大量能耗和碳排放。我们通过一个碳感知路由框架来应对这一可持续性挑战，该框架将函数调用查询分布到三层边缘-云架构中，并在异构硬件上结合边缘与云端 LLM。其核心是一个运行在统一语义-词汇嵌入空间中的轻量级 k-NN 预测器，用于估计每个边缘层级上针对具体查询的准确率、延迟和功耗。然后，将这些预测与实时电网碳强度相结合，将每个查询路由到能够成功执行它的最低排放层级。在最先进的函数调用基准和 LLM 系列上进行评估，我们的框架在达到云端级准确率的同时，平均将运营碳排放降低为原来的 1/4。

## Abstract
Large Language Models (LLMs) with function-calling capabilities are becoming critical for modern agentic AI systems. Nevertheless, current deployments typically route inferences to powerful cloud-based models, incurring significant energy use and carbon emissions. We address this sustainability challenge with a carbon-aware routing framework that distributes function-calling queries across a three-tier edge-cloud architecture, combining edge and cloud LLMs on heterogeneous hardware. At its core, a lightweight k-NN predictor operating in a unified semantic-lexical embedding space estimates query-specific accuracy, delay, and power consumption on each edge tier. These predictions are then combined with real-time grid carbon intensity to route every query to the lowest-emission tier capable of executing it successfully. Evaluated on state-of-the-art function-calling benchmarks and LLM families, our framework matches cloud-level accuracy while reducing operational carbon emissions by $4\times$ on average.

## 1. 核心问题与研究动机

- **背景**：具备函数调用（function calling）能力的 LLM 已成为现代智能体 AI 系统的基础构件，使模型能够自主选择并调用外部工具、访问外部数据、执行参数知识之外的运算并与 API 交互。
- **核心矛盾**：函数调用的复杂性与准确性要求，使当前部署普遍采用"一律上云"的默认策略——无论任务多么简单，都把推理路由到云端大模型，造成显著能耗与碳排放。
- **环境影响的量化证据**：
  - ChatGPT 单日服务超 25 亿次查询，耗电约 850 MWh（可充满 1.4 万辆电动车）；年耗电约 310 GWh，相当于 2.9 万户美国家庭全年用电。
  - 叠加 Gemini、Claude 等竞品后，合计年耗电达 15 TWh，接近两座核反应堆的发电量。
  - 推理已主导 ML 碳足迹：占云端 ML 算力需求的 80–90%、ML 相关能耗的 60%。
- **边缘侧的机遇与瓶颈**：边缘模型能耗极低（Llama3.1-8B 约 0.17 Wh/query，比云端 Llama3.1-70B 的 4.35 Wh 低约 25 倍），但准确率差距明显——BFCL V2 上云端 70B 达 97.8%，边缘 8B 仅 56.5%、1B 仅 13.6%。
- **关键洞察**：准确率差距在查询间**并非均匀分布**。单工具调用、简单检索、结构化查询等任务无需大模型推理能力，小模型即可正确完成。这种查询级异质性构成了设计机会。
- **现有工作的不足**：已有 LLM 路由器（TensorOpera、HybridLLM、Less-is-More）以准确率—美元成本为优化目标，**忽略了底层硬件、功耗以及各层所接电网的碳强度**，因而即便成功将负载移出云端，也只能捕获部分碳收益。
- **本文定位**：将函数调用推理建模为 **性能—功耗—碳（PPC）约束的路由问题**，在保持任务级正确性的前提下最小化碳足迹。

## 2. 方法论

### 2.1 三层异构边缘—云架构

| 层级 | 模型规模 | 硬件平台 | 特性 |
|---|---|---|---|
| Tier 1（Tiny/Micro LM） | 1–4B 参数 | 低功耗边缘 SoC（Jetson Orin Nano） | 每查询能耗最低，复杂任务推理能力有限 |
| Tier 2（Small LM） | 7–12B 参数 | 边缘加速器（Jetson AGX Orin） | 准确率高于 Tier 1，能耗远低于云端 |
| Tier 3（Large LM） | >100B 参数 | 数据中心（H100 SXM，Fireworks AI，GPT-OSS-120B） | 准确率最高，环境成本最大 |

运行时由**性能预测器**与**碳感知路由器**两部分协同完成层级选择。

### 2.2 性能预测器（核心思想与关键技术细节）

- **统一语义—词法嵌入空间**：将查询编码为两种信号的组合——(i) 语义嵌入，捕捉语言与结构内容；(ii) 词法复杂度分数，度量低频词使用情况（已有研究证明其与 LLM 感知的查询难度相关）。
- **离线校准阶段**：每条校准查询记录三项信息——对照 ground truth 的**二元成功结果**（函数调用不容忍部分正确，调用错误工具或遗漏必需工具即整体失败）、目标硬件上实测的**推理延迟**与**功耗**。
- **在线推理**：新查询映射到同一嵌入空间，用 **k-NN 回归**基于余弦距离找出 k 个最相似校准查询，做**距离加权预测**，输出每个边缘层级的：
  - 正确执行概率 `P(Success(qi, τ))`
  - 推理延迟 `D(qi, τ)`
  - 功耗 `w(qi, τ)`
- **一致性设计**：三个量共用同一邻域，保证预测相互一致，可捕捉"复杂查询在小模型上同时表现为准确率下降与延迟上升"这类联合相关性。
- **优势**：非参数化、无需训练、无过拟合风险、运行时开销可忽略，且无需实际调用底层 LLM 即可支持快速设计空间探索。

### 2.3 碳感知路由策略

- **碳足迹计算公式**：

  `CF(qi, τ) = CIτ · D(qi, τ) · w(qi, τ)`

  其中 `CIτ` 为层级 τ 所接电网的实时碳强度（gCO2/kWh），`D` 与 `w` 来自性能预测器。

- **路由决策规则**：先在满足准确率阈值 `P(Success(qi, τ)) ≥ θ` 的边缘层级中筛选，再从中选择碳足迹最小者；若无边缘层级达标，则回退到 Tier 3：

  ```
  τ*i = argmin_{τ∈{Tier1, Tier2}} CF(qi, τ),  若 ∃τ: P(Success) ≥ θ
  τ*i = Tier 3,                              否则
  ```

- 该策略保证 Tier 3（最高排放层级）仅在无边缘层级满足准确率要求时被触发。

## 6. 主要结论与发现

- **整体效果**：在保持云端级准确率的同时，**平均降低运行碳排放约 4 倍**；对较简单查询最高可达 **8 倍**。
- **BFCL V2（较简单）**：本方法成功率达 89.1–95.7%，对比 Cloud Only 的 96.7% 仅微小损失，平均碳减排约 **6 倍**，Falcon3 配置下最高 **8 倍**；Qwen3 与 Gemma3 约 70% 查询被路由到 Tier 1，仅 4.3% 上云。
- **GeoEngine（较难）**：成功率达 55.3–59.6%，接近 Cloud Only 的 60.9%，碳减排约 **1.39 倍

，Falcon3 配置下最高约 1.6 倍；仅约 35–40% 查询留在边缘，上云比例明显高于 BFCL V2，说明顺序依赖型任务确实更依赖大模型能力，但路由器仍能识别出一批可安全下放的查询。

### 6.1 层级分布与路由行为

- **BFCL V2**：Tier 1 承接了约 70% 的查询（Qwen3、Gemma3 配置），Tier 2 承接约 25%，仅 4.3% 回退至 Tier 3。这说明在任务相对简单的场景下，1–4B 的微型模型已足以完成大量单工具调用与结构化查询。
- **GeoEngine**：分布明显右移，Tier 1 占比下降，Tier 2 成为主力承接层，Tier 3 占比上升。路由器的决策与 benchmark 难度呈一致的正相关，表明 k-NN 预测器捕捉到的"查询难度信号"具有跨数据集的区分能力。
- **动态性**：同一模型家族内，层级选择随查询复杂度连续变化，而非退化为固定阈值切分——这是查询级异质性被有效利用的直接证据。

### 6.2 与基线的对比

- **vs. Cloud Only**：在 BFCL V2 上成功率损失仅约 1–7 个百分点，却换来约 6 倍碳减排；GeoEngine 上成功率差距压缩到约 1.3–5.6 个百分点。这一"微小精度代价换大幅碳收益"的权衡曲线是本方法的核心卖点。
- **vs. Edge Only**：Edge Only 碳足迹最低，但成功率显著塌陷（尤其 GeoEngine 上），Carbon-per-Success 反而可能恶化——说明"一味本地化"并非最优，路由器提供的准确率保障是必要的。
- **vs. TensorOpera（碳不感知）**：这是隔离"碳感知"贡献的关键对照。在成功率相近的前提下，本方法的碳足迹与 Carbon-per-Success 均更优，证明**即使成本感知路由器已经把负载移出云端，显式建模电网碳强度仍能带来额外收益**——因为不同层级/不同地点的碳强度差异（而非单纯的能耗差异）构成了独立的优化维度。
- **vs. HybridLLM（二路路由器）**：HybridLLM 仅能在 Tier 2 与 Tier 3 之间选择，无法利用 Tier 1 的超低能耗。本方法的增益主要来自对 Tier 1 的额外利用，这解释了为什么在 BFCL V2 这类简单任务上差距最大。
- **vs. Less-is-More**：该基线通过动态缩减工具集提升边缘端效率，但仅部署于 Tier 2，无法在层级维度上做权衡，因而碳收益上限受限于单层能耗。

### 6.3 关键洞察

1. **碳收益高度集中在简单查询上**：越简单的查询，可安全下放的层级越低，能耗差距（Tier 1 vs. Tier 3）也越悬殊，因此碳减排倍数与查询难度呈反比。这提示实际部署中，路由器的价值主要由"长尾中的大量简单请求"贡献。
2. **成本 ≠ 碳**：美元成本与碳足迹的相关性并不完全一致——同一美元成本下，不同层级所接电网的碳强度可能相差数倍。忽略碳强度的路由器会系统性地错失这部分收益。
3. **Carbon-per-Success 是必要的评价指标**：若只看碳足迹，Edge Only 永远最优；引入每成功一次碳耗后，才能在"准确率—碳"之间做有意义的比较，避免以牺牲正确性换取低碳的假象。

## 7. 局限性

- **预测器未做误差分析**：论文未报告 `P(Success)`、延迟、功耗三项预测的精度（如 MAE、校准曲线），因此无法判断碳收益对预测误差的敏感程度。若预测器高估边缘成功率，实际成功率将低于报告值。
- **碳强度数据的时序简化**：使用 Electricity Maps 的实时值做离线评估，但未模拟真实碳强度的日内波动与预测误差。在真实系统中，路由决策依赖的是**未来**的碳强度，而非当前值，这一时序不确定性未被建模。
- **未考虑网络传输开销**：云端推理的碳足迹仅计入 GPU 侧能耗（延迟 × 功耗），未包含数据上传/下载、排队等待与数据中心冷却（PUE）等间接开销。这可能低估云端的实际碳成本，从而低估本方法的减排潜力；但也可能因边缘设备功耗测量口径不同而引入偏差。
- **校准集依赖**：k-NN 需要每个层级、每个模型家族的标注校准数据。跨域迁移（如从 BFCL V2 校准集迁移到 GeoEngine）时的性能退化未被评估。
- **硬件平台单一**：Tier 1 与 Tier 2 均使用 NVIDIA Jetson 系列，Tier 3 固定为 H100 + GPT-OSS-120B，结论对其他硬件/模型组合的可迁移性未知。
- **θ = 0.9 的阈值未论证**：该阈值直接决定了上云比例与碳收益，但论文未说明其选取依据，也未展示不同阈值下的权衡曲线。
- **篇幅约束**：作为 4 页短文，缺少消融、敏感性分析与真实部署验证在所难免，但这些缺口削弱了方法论的完整性主张。

## 8. 结论与未来工作方向

- **核心结论**：将函数调用推理路由问题显式建模为性能—功耗—碳（PPC）约束优化，并用非参数化的 k-NN 性能预测器支撑在线决策，可以在**几乎不损失准确率**的前提下，把边缘—云 LLM 系统的运行碳排放降低约 4 倍（简单任务最高 8 倍）。这一结果表明，查询级难度异质性与层级间电网碳强度差异是两个可叠加的优化杠杆。
- **方法论贡献**：提出了一种无需训练、开销可忽略、支持快速设计空间探索的路由框架，把"碳感知"从被忽略的约束提升为一等优化目标，并明确了它与既有成本感知路由的增益边界。
- **未来工作（论文暗示或可自然延伸的方向）**：
  - 引入碳强度的短期预测，做前瞻性路由而非反应式路由；
  - 将网络传输与数据中心 PUE 纳入碳核算；
  - 探索预测器的主动学习式校准，降低校准数据采集成本；
  - 扩展到多区域、多数据中心的云端层级选择（即在"上云"时也选择最清洁的区域）；
  - 在真实负载下做端到端部署验证。

## 9. 总体评价

- **优点**：问题定义清晰且具有现实紧迫性；三层异构架构与 PPC 建模的抽象层次恰当；k-NN 预测器的"非参数化、免训练、多目标一致预测"设计在工程上简洁有效；实验跨 4 个模型家族与 2 个难度差异明显的 benchmark，并设置了碳不感知与二路路由两类关键对照，Carbon-per-Success 指标的使用尤为恰当。
- **不足**：实验深度受篇幅限制，缺乏消融、预测器误差分析与超参数敏感性研究；碳核算边界（是否含网络与 PUE）未充分说明；碳强度的时序动态性未被建模。
- **定位判断**：这是一篇以**问题提出与可行性验证**为主要贡献的短文，其价值更多在于指出"函数调用路由中的碳维度被系统性忽略"这一空白，并给出一个足够简单、可复现的基线方案。它为后续更严格的碳感知系统研究（时序预测、跨区域调度、真实部署）铺平了道路，但在方法严谨性与实验完备性上尚未达到长文水准。
