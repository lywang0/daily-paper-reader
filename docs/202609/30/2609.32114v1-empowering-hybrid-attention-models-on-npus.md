## 摘要
混合注意力模型已成为大语言模型（LLM）的关键架构（例如 Qwen3.5 和 Kimi 系列）。其内存与计算效率使其对端侧推理极具吸引力，并与边缘神经处理单元（NPU）形成有前景的协同。然而，在边缘 NPU 上朴素地执行这些混合模型无法带来这些收益，常常因线性注意力（LA）层中严重的内存系统低效和架构不匹配而使预填充阶段成为瓶颈。我们提出 HA-NPU，这是首个无需修改底层算法即可在边缘 NPU 上实现高效混合注意力 LLM 推理的系统。HA-NPU 通过从三个层次重组 LA 组件的数据流来提升执行效率：（1）在核心层次，它按头维度划分工作负载并融合依赖算子，消除跨核全局内存访问；（2）在算子层次，它重排执行顺序以及时消费中间张量，从而大幅降低本地缓冲区压力；（3）在张量层次，它采用数据流感知的布局规划，以最小化矩阵与向量处理单元之间的转换开销。与有竞争力的基线相比，HA-NPU 实现了最高 35.95 倍的 LA 内核加速和 36.14 倍的能耗降低，并带来最高 2.03 倍的端到端请求延迟加速。源代码将在 https://github.com/yinyuanzhang/HA-NPU 公开。

## Abstract
Hybrid attention models have emerged as a crucial architecture for Large Language Models (LLMs) (e.g., the Qwen3.5 and Kimi series). Their memory and computational efficiency make them highly attractive for on-device inference, forming a promising synergy with edge Neural Processing Units (NPUs). However, naive execution of these hybrid models on edge NPUs fails to deliver these benefits, often bottlenecking the prefill stage due to severe memory-system inefficiencies and architectural mismatches within the linear attention (LA) layers. We present HA-NPU, the first system to enable efficient hybrid attention LLM inference on edge NPUs without modifying the underlying algorithms. HA-NPU enhances execution efficiency by reorganizing the dataflow of the LA components across three levels: (1) At the core level, it partitions workloads by the head dimension and fuses dependent operators, eliminating cross-core global memory accesses; (2) At the operator level, it reorders execution to consume intermediate tensors immediately, drastically minimizing local-buffer pressure; (3) At the tensor level, it employs dataflow-aware layout planning to minimize transformation overhead between matrix and vector processing units. Compared to competitive baselines, HA-NPU achieves up to 35.95$\times$ LA kernel speedup and 36.14$\times$ energy reduction, delivering up to 2.03$\times$ faster end-to-end request latency. The source code will be made publicly available at https://github.com/yinyuanzhang/HA-NPU

- **背景趋势**：混合注意力模型（Hybrid Attention）已成为大语言模型（LLM）的重要架构方向，典型代表包括 Qwen3.5 系列、Qwen3.8-Flash-Next、Kimi K3、GLM-5.3-Flash 等。它们采用 **Gated DeltaNet（GDN）** 与 **Kimi Delta Attention（KDA）** 等 delta-rule 线性注意力（Linear Attention, LA）机制，用固定大小的循环状态（recurrent state）替代不断增长的 KV Cache，将 full attention 的 $O(T^2)$ 计算与 $O(T)$ 内存降为 $O(T)$ 与 $O(1)$。

- **端侧机遇**：LA 的内存与计算效率使其天然适合算力、内存、能耗都严格受限的边缘设备，而边缘推理通常依赖高能效的神经处理单元（NPU），因此 LA 与边缘 NPU 构成极具前景的“算法—硬件协同”。

- **现实悖论（核心痛点）**：在边缘 NPU 上朴素地执行混合模型时，**收益无法兑现**。在 Ascend 310P 上剖析 Qwen3.5-2B 发现：
  - 输入 4,096 token 时，完整 LA 层的乘加操作比 full attention 少 **8.7×**，却反而**慢 3.02×**；
  - LA 占据总预填充（prefill）延迟的 **75.16%–76.99%**（部分模型达 80.12%），矩阵单元利用率仅 **0.20%–0.41%**（full attention 为 16.8%–29.0%）。

- **根因诊断**：LA 执行模式与边缘 NPU 架构存在错配，导致**数据搬运主导的访存瓶颈**，可细分为三个层级：
  - **核心层（Core）**：chunk-head 映射（为 GPU 多线程并行设计）破坏了 NPU 偏好的粗粒度张量局部性，GM（全局内存）访问占 LA 延迟的 **56.2%**。
  - **算子层（Operator）**：默认语义执行顺序过早生成中间张量，其生命周期重叠超出片上缓存容量，引发严重溢出/重载，使 GM 流量膨胀 **93.4%（GDN）/ 63.8%（KDA）**。
  - **张量层（Tensor）**：矩阵单元偏好 Blocked 布局、向量单元偏好 Dense 布局，频繁切换导致布局转换开销占跨单元执行时间的 **41.58%**、内存流量增加 **16.7%**。

- **整体含义**：本文提出 **HA-NPU**，声称是**首个在不修改底层注意力算法的前提下**，让混合注意力 LLM 在边缘 NPU 上高效推理的系统，通过数据流重组把“序列维度并行”转变为“算子数据流局部性”优先。

## 二、论文提出的方法论

### 2.1 核心思想
- 将 delta-rule 类 LA 算子（GDN、KDA）抽象为统一的 **Map–Reduce–Map** 分块（chunkwise）推理范式：
  - **Map #1–#4**（Gate、KKᵀ、Solve、W/U）：块内预处理，捕获 token 级依赖；
  - **Reduce #5**（H）：跨块状态递推（唯一的序列串行瓶颈）；
  - **Map #6**（O）：块内输出投影。
- 核心洞察：**重排 LA 执行流以匹配边缘 NPU 架构特征**，在严格保持循环状态依赖的前提下最大化数据复用、最小化数据移动。

### 2.2 关键技术一：头级映射与跨算子融合（§4，核心层）
- **问题**：主流的 Chunk-Head-Chunk 与 Chunk-Seg-Seg 映射均为 GPU 中心设计，在核数稀少的 NPU 上造成核间同步与 GM 反复物化。
- **两个洞察**：
  1. 头间在整个 Map/Reduce 阶段均无数据依赖；
  2. 边缘 NPU 核数极少（1–10），而头数充足（16–64），因此头级并行已足以占满硬件，块级并行只是徒增核间 GM 开销。
- **机制**：以注意力头为基本调度单元，将整个 Map–Reduce–Map 流水线**融合为单一 kernel 固定到单个 AI Core**，块内顺序执行所有算子，使中间张量与状态 $S_i$ 常驻片上缓冲。
- **计算切分**：当头数不是核数整数倍时（如 16 头映射到 10 核），对剩余尾头沿 $S$ 的**列方向**切分（列切分天然无跨核归约，行切分则需要跨核归约），从而在不引入归约开销的前提下暴露更多并行度。
- **三级调度流水线**：Step I 充足头并行（一头一核）→ Step II 欠载尾部分列切分 → Step III 极端尾部退回 chunk-head-chunk 映射以保证核饱和。

### 2.3 关键技术二：生命周期感知的算子重排序（§5，算子层）
- **核心洞察**：只要输入就绪，算子不必遵循默认语义顺序，可借鉴处理器的乱序执行思想，**让中间张量生成后立即被消费**，缩短生命周期、压低峰值内存。
- **跨块场景：从 State-First 改为 Chunk-First（借助算子拆分）**
  - 默认顺序先算新状态 $S_{c+1}$（Op5）再完成块输出（Op6），导致新旧状态共驻内存、状态占用翻倍。
  - 关键观察：Op6 实际只需要**传入状态 $S_c$** 与中间张量 $v_c$，并不需要最终更新后的状态。
  - 因此将 Op5 拆为 **Read → Op6 → Update**，延迟状态提交，实现**原地覆写**，状态内存需求减半，且严格保持算法递推语义。
- **块内场景：从 Inversion-First 改为 GEMM-First（借助算子重写）**
  - 默认顺序把矩阵求逆 $A^{-1}$ 夹在共享输入（$K, Q, S, K^T$）的 GEMM 之间，导致共享输入闲置、L0 缓冲被求逆中间量占满、被迫驱逐重载。
  - 两步优化：① **算子重写**，将 $W = A^{-1}K$ 中的 $A^{-1}$ 因式分解出去，使新的 GEMM 直接消费 $K$，解除对求逆的依赖；② **GEMM-First 重排**，把共享输入的 GEMM（$KS, QS, KK^T, QK^T$）集中执行，保持输入在 L0 中直接复用，之后释放缓冲给求逆使用。

### 2.4 关键技术三：数据流感知的布局转换规划（§6，张量层）
- **问题建模**：布局规划是离散代价最小化问题
  $$\pi^* = \arg\min_{\pi} \left[ T_{exec}(\pi) + T_{transform}(\pi) \right]$$
  即权衡“用不匹配布局执行”与“插入布局转换”的代价。
- **复杂性**：布局决策沿数据流深度耦合，涉及三个维度——跨块序列传播、多分支共享张量、长向量链累积开销，整体构成 **Partitioned Boolean Quadratic Programming（PBQP）** 问题，属 NP-hard，朴素搜索空间达 $2^{m \cdot N_c}$，随序列长度不可行。
- **三种剪枝机会**：
  1. **全局解耦为块内子问题**：布局代价仅沿张量依赖传播，跨块仅循环状态存活，故块内决策相互隔离，只需保留少量状态布局组合下的最小块内代价。
  2. **固定矩阵接口简化分支规划**：分支共享张量必然作为下游矩阵单元操作数，而矩阵单元强制要求 Blocked 布局，可将其作为确定性锚点，把组合分支搜索降为一次性转换评估。
  3. **合并向量链为单一逻辑单元**：对保形向量链，全 Dense + 边界转换不比任何混合布局更差，故每条链只需评估“全 Dense + 边界转换”与“全 Blocked”两种候选。
- **最优规划**：搜索空间受界后，用动态规划求解
  $$D_i(s) = \min_p \left[ D_{i-1}(p) + c_i(p, s) \right]$$
  按拓扑序求值，块边界处布局状态坍缩为仅保留循环状态布局，使复杂度降为**线性 $O(N_c)$**。前向 DP 记录最优前驱状态，再回溯分配各张量物理布局与转换插入点，离线生成静态确定性执行计划，消除运行时布局调度开销。

### 2.5 实现要点
- 约 **13K 行 C/C++**，作为内核级 drop-in 替换，通过 `torch_npu` 绑定集成进 **vLLM-Ascend**，不修改上层服务流水线。
- 对 LA 层的输入/输出投影也做优化（算子融合 + 卷积元数据复用，较原生 vLLM-Ascend 有 1.62× 加速），但**所有基线共享同一投影后端**，以严格隔离核心改进的贡献。
- 跨 GEMM 复用固定形状的 Cube 例程，减少标量控制代码以降低 I-cache 压力。

## 三、实验设计

- **硬件平台**：两块边缘 Ascend NPU
  - **Ascend 310P**：10 个 AI Core，96 GB LPDDR4X，8 核 CPU；
  - **Ascend 310B**：1 个 AI Core，24 GB LPDDR4X，4 核 CPU。
  - 均使用 CANN 工具链，在 vLLM-Ascend 中做端到端评估。

- **模型与机制**：
  - GDN 机制：Qwen3.5-0.8B / 2B / 4B / 9B（多模态）；
  - KDA 机制：AFM-4.5B（纯文本）、Ling-3.0-tiny（MoE，纯文本）。

- **数据集 / 场景**：
  - 文本 QA：TriviaQA、HotpotQA；
  - 多模态：MMMU（用于 GDN 系列）；
  - 文本推理：MMLU-Pro（用于 KDA 系列）。
  - 工作负载特征：输入普遍较长（TriviaQA 9.8K–13.7K、HotpotQA 11.0K–13.4K、MMLU-Pro 约 2.1K–2.3K、MMMU 2.1K–5.6K token），输出极短（1–9 token），因此 prefill 主导端到端延迟（如 Qwen3.5-2B 在 HotpotQA 上 prefill 占 97.1%）。

- **对比基线（4 个）**：
  1. **vLLM-Ascend**（v0.19.1rc1）：原生推理后端；
  2. **Flash Linear Attention（FLA）**：chunkwise 执行；
  3. **FLA + MegaKernel**：单 kernel 变体，考察 kernel 启动开销；
  4. **FlashQLA**：融合式、段并行执行。
  - 由于官方 FLA / FlashQLA 无 NPU 支持，作者将其计算流严格移植到 Ascend 310P/310B，保留其核心融合与分段策略，并为 FlashQLA 补齐 KDA 版本。

- **评估指标**：内核前向延迟、端到端请求延迟、峰值内存、能耗（100 ms 采样积分、连续 10 秒执行后除以调用次数）、内存流量（硬件计数器）、矩阵利用率（硬件记录的 MAC 数除以无开销设备事件计时，并按实测 FP16 GEMM 峰值归一化）。所有实验取 3–5 次运行均值。
