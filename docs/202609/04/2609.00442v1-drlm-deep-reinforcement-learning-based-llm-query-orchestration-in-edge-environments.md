## 摘要
大语言模型（LLM）服务日益处理具有不同延迟、准确性和资源需求的异构查询。虽然边缘部署减少了响应时间，但设备的异构性以及模型家族、参数规模和量化级别的多样性使得高效的LLM查询编排具有挑战性。本文介绍了DRLM，一种边缘环境中基于深度强化学习的LLM查询编排框架。DRLM集成了两个轻量级预测器：（i）类条件质量估计器，将查询映射到语义类别并推断模型性能，以及（ii）特征驱动的延迟预测器，估计跨模型-设备配置的推理时间。这些预测与系统状态相结合，输入到一个分解的近端策略优化（PPO）智能体，该智能体执行状态感知的编排决策。为了实现数据驱动的编排，我们构建了一个大规模基准数据集，包含223 835次测量，涵盖1258个查询、6个查询类别、8个模型家族（32个部署实例）、5个量化级别和异构边缘设备。在64节点边缘集群上的评估以及与三个基线和两种最先进方法的比较表明，DRLM将推理延迟降低高达51%，排队延迟降低高达67%，同时最多引入8%的准确率损失。在不断增加的工作负载下，它将延迟改善高达61.4%，展示了稳健且稳定的编排性能。

## Abstract
Large language model (LLM) services increasingly process heterogeneous queries with diverse latency, accuracy, and resource requirements. While edge deployment reduces response time, the heterogeneity of devices and the diversity of model families, parameter scales, and quantization levels make efficient LLM query orchestration challenging. This paper introduces DRLM, a Deep Reinforcement Learning-based LLM query orchestration framework in edge environments. DRLM integrates two lightweight predictors: (i) a class-conditioned quality estimator that maps queries to semantic categories and infers model performance, and (ii) a feature-driven latency predictor that estimates inference time across model-device configurations. These predictions, combined with system state, feed a factorized Proximal Policy Optimization (PPO) agent that performs state-aware orchestration decisions. To enable data-driven orchestration, we construct a large-scale benchmarking dataset with 223 835 measurements spanning 1258 queries, 6 query classes, 8 model families (32 deployed instances), 5 quantization levels, and heterogeneous edge devices. Evaluation on a 64-node edge cluster and comparison with three baselines and two state-of-the-art methods show that DRLM reduces inference latency by up to 51% and queuing delay by up to 67 %, while incurring at most 8% accuracy loss. It improves latency under increasing workloads up to 61.4%, demonstrating robust and stable orchestration.

### 1. 核心问题与整体含义（研究动机与背景）

- **问题背景**：大语言模型（LLM）服务在现代AI应用中承担日益多元化的查询负载，不同查询在结构、语义复杂性、推理深度和延迟需求上差异巨大。与此同时，边缘计算环境中设备算力差异悬殊（从树莓派到高端Jetson设备），部署的模型在家族、参数量（0.27B–20B）、量化级别等多个维度上高度异构，模型配置与设备性能之间存在复杂的“质量-延迟-资源”权衡。
- **现有方法局限**：当前LLM查询编排研究存在两个割裂的视角——①面向固定模型的执行优化（如ExeGPT、Bullet、DynamoLLM），侧重于批处理、KV-cache管理或并行度调节，不涉及查询与模型间的动态选配；②简化的模型路由选择（如OptLLM、RouteLLM），将质量与延迟视为静态属性，忽略了查询语义特征和实时系统负载状态的耦合影响。二者均无法对异构边缘集群中的每一个查询做细粒度的状态感知编排。
- **核心问题**：如何在异构边缘集群中，通过对“查询语义—模型配置（家族/规模/量化）—设备状态（负载/队列）”三者的联合建模，实现兼顾响应质量与推理延迟的查询级编排决策。

### 2. 方法论：核心思想与关键技术细节

#### 核心思想
DRLM将查询编排建模为一个马尔可夫决策过程（MDP），利用深度强化学习（PPO）学习一个状态感知的编排策略：每个到达的查询被分配到一个最优的（模型实例，边缘设备）配置上，在延迟与精度之间取得动态均衡。其核心创新在于**用轻型预测器替代真实推理**以生成训练信号和决策依据，使强化学习可在大规模组合空间中高效训练。

#### 关键技术细节

- **问题形式化（MDP建模）**
  - 状态：$s_i = [\phi(x_i), \hat{y}, \hat{t}_{inf}, u, q]$，包含查询表示（语义与结构特征）、预测质量、预测推理延迟、设备资源利用率 $u$ 和队列状态 $q$。
  - 动作空间：$a = (m, e)$，即所有可行的模型-设备组合。
  - 奖励函数：$r(s_i, a) = \alpha \cdot \bar{\hat{y}} - \beta \cdot \Phi(\hat{t}_{e2e})$，其中 $\hat{t}_{e2e} = \hat{t}_{inf} + t_{wait}$，$\Phi$ 为归一化指数惩罚函数，对高延迟分配施加超线性惩罚。

- **策略网络：因子化PPO**
  - 为应对组合爆炸的动作空间，采用自回归因子分解：
$$\pi_\theta(a|s_i) = \pi_f(f,p|s_i) \cdot \pi_z(z|s_i, f, p) \cdot \pi_e(e|s_i, f, p, z)$$
  - 策略分解为三个决策阶段：模型家族/规模选择 → 量化级别选择 → 执行设备选择。各阶段使用独立输出头，并通过动态掩码屏蔽不满足部署约束的无效动作，提升样本效率与结构化信用分配。

- **两个轻量级预测器（决策基础）**
  - *类条件质量估计器*：通过 embedding 分类器（all-MiniLM-L6-v2 编码 + 随机森林分类）将查询映射到 6 个语义类别，对每类查询用预计算的经验查找表估计每个模型的期望准确率，避免逐查询的噪声预测。
  - *延迟预测器*：LightGBM 回归器（600棵树，63叶子，学习率0.05），输入查询结构特征（长度、词/句计数、词汇多样性）、模型配置特征（家族、参数规模、量化、层数、注意力头数）和设备硬件特征。$R^2=0.75$，单次推理时间仅0.78ms。

- **系统架构（五大模块）**：查询画像器（特征提取）、查询分类器（6类语义分类，低置信度回退到GPT-OSS 20B）、性能预测器（质量+延迟估计）、运行时监控器（模型实例管理 + 集群状态管理：CPU/GPU/内存利用率、队列长度和处理进度）、编排智能体（状态编码器 + 因子化策略网络）。

### 6. 主要结论与发现

- DRLM在64节点异构边缘集群上相比基线方法：

1. **问题建模完整**：将查询语义、模型配置和运行时系统状态统一纳入MDP框架，超越了传统“模型路由”或“资源调度”的单一视角。

1. **仅报告短期负载变化，未涉及长期漂移**：分布外查询、概念漂移和冷启动场景的鲁棒性仅在回退机制中简单提及，缺乏系统实验验证。
