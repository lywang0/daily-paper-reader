## 摘要
大型语言模型（LLM）越来越多地部署在移动设备上，使得能效成为关键的部署约束条件，然而提示设计对能耗的影响仍未得到充分探索。本文旨在理解两种提示属性——认知负荷与措辞模式——如何塑造端侧LLM推理的能耗行为。我们开展了一项广泛的实证研究，涵盖提示属性、数据集、模型和设备，并通过分阶段剖析来分离预填充和解码能耗。我们发现，认知负荷主要影响每令牌的能耗成本，而措辞模式主要通过令牌使用量影响能耗。我们的能耗-质量分析进一步表明，提示设计在不同模型上对可实现的边界产生不同影响，凸显了在能效优化的端侧LLM推理中需要采用模型感知的提示设计。代码、数据集和脚本可在 https://amai-gsu.github.io/PromptProperty/ 获取。

## Abstract
Large language models (LLMs) are increasingly deployed on mobile devices, making energy efficiency a key deployment constraint, yet the energy impact of prompt design remains underexplored. This paper aims to understand how two prompt properties, cognitive load and phrasing pattern, shape the energy behavior of on-device LLM inference. We conduct a broad empirical study covering prompt properties, datasets, models, and devices, with phase-level profiling that separates prefill and decode energy. We find that cognitive load primarily affects the energy cost per token, while phrasing pattern affects energy largely through token usage. Our energy-quality analysis further shows that prompt design reshapes the attainable frontier differently across models, highlighting the need for model-aware prompt design in energy-efficient on-device LLM inference. Code, datasets, and scripts are available at https://amai-gsu.github.io/PromptProperty/.

## 1. 论文的核心问题与整体含义（研究动机和背景）

- **背景**：大语言模型（LLM）的部署正从云端扩展至移动端/边缘设备，以增强隐私保护、降低延迟并提供离线能力。与云端不同，端侧推理由有限电池供电，能效是用户可感知的硬性约束。现有提升效率的研究几乎都聚焦于模型侧优化（量化、剪枝、架构压缩、蒸馏），而提示设计这一“模型无关”的额外优化维度长期被忽视。
- **核心问题**：提示（prompt）设计本身如何影响端侧 LLM 推理的能耗？不同提示变体即使在产出可比较结果的情况下，是否会导致显著不同的能量消耗？若成立，提示设计便可能成为一种不依赖模型参数优化的新型能效提升途径。
- **研究难点**：
  - 提示是语言产物，能耗由模型内部计算决定，二者不存在直接映射，需系统地将提示变化与计算行为及实测功率关联；
  - 难以在保持任务语义一致的前提下，构造仅针对某一属性的提示变体；
  - 需跨提示变体、任务、模型、硬件获得可泛化的结论，而不仅是零散案例。
- **整体含义**：论文通过大规模实证，揭示提示设计不仅是“使用体验/输出质量”问题，也是可操作的能效优化杠杆；未来端侧 LLM 部署应将提示视为与模型同等重要的可调维度，并采用“模型感知”的提示优化策略。

## 2. 论文提出的方法论：核心思想、关键技术细节、公式与流程

**核心思想**：将提示属性拆解为两个代表性维度——**措辞模式（Phrasing Pattern）** 与**认知负荷（Cognitive Load）**，并通过“受控生成 → 严格验证 → 端侧阶段级能耗剖析”的流水线，定量分离提示属性对每 token 能耗与 token 使用量的影响。

**关键技术细节**：

- **提示属性体系**：
  - 措辞模式：7 个子属性（激进语气、对话语气、思维链 CoT、格式差异、角色扮演、礼貌语气、技术/术语密集）；
  - 认知负荷：3 个子属性（内在负荷 Intrinsic、外在负荷 Extraneous、相关负荷 Germane，依据认知负荷理论）。
- **提示变体生成**（阶段 1）：对认知负荷，使用 Gemini-2.5-Pro API 基于手工模板生成候选变体，遵循三条规则：①单一属性隔离（每个变体只体现目标子属性）；②语义保持（不改变原任务意图与答案）；③子属性一致性（严格符合定义）。
- **提示变体验证**（阶段 2）：
  - **属性纯度打分**：使用基于规则的 LLM 评估器对每个候选生成三维得分向量 s=(sᵢ, sₑ, s_g)，仅保留“目标子属性得分 ≥8、非目标得分 ≤3（1–10 分制）”的变体；对于外在负荷，评分方向被反转（高分代表更多冗余/无关信息）。
  - **语义一致性过滤**：计算基础提示嵌入 e₀ 与变体嵌入 eᵢ 的余弦相似度，保留满足 minᵢ CosSim(e₀, eᵢ) ≥ τ 的整组变体，其中 τ=0.6（放宽是为了容纳认知负荷附加信息）。
- **端侧推理能耗剖析**（阶段 3）：
  - 基于 MLC-LLM 运行时和 LM-Meter 工具构建剖析框架，记录 prefill（预填充：请求到达至首个 token 采样，覆盖 tokenization、排队、嵌入、前向与首 token 采样）和 decode（解码：后续所有 token 生成）的起止时间戳；
  - 通过 Android Debug Bridge (ADB) 同步采样设备电流 I(t) 与电压 V(t)，计算瞬时功率 P(t)=I(t)·V(t)；
  - 阶段能耗由功率对时间积分得到：
    \[
    E_{phase} = \int_{t_s}^{t_e} P(t)\,dt \approx \sum_{i \in \mathcal{I}_{phase}} P_i \Delta t
    \]
    其中 \(\Delta t\) 为有效采样间隔。
- **能耗归因公式**：将阶段能耗分解为 \(E_{phase}=e_{phase}\cdot T_{phase}\)，其中 e 为每 token 能耗，T 为该阶段处理/生成的 token 数，从而区分“单价成本”与“规模成本”。
- **响应质量评估**：
  - 认知负荷任务（有标准答案）：采用 Exact Match 准确率；
  - 措辞模式任务（开放式）：使用 DeepEval 进行六维度无参考评估（相关性、正确性、连贯性、完整性、指令遵循、内部一致性），每个维度 0–1 打分，并人工核验随机子集。

## 6. 论文的主要结论与发现

- **RQ1（每 token 能耗）**：
  - 绝对每 token 能耗主要由模型决定，提示子属性内差异远小于模型之间差异；
  - 大多数端侧模型上 prefill 每 token 能耗高于 decode（3–6 倍），但 Gemma-2-2B 呈现反转，反映端侧运行时的计算/带宽瓶颈与 prefill 窗口摊销效应；
  - **措辞模式对每 token 能耗影响很小**（归一化值多在 1.0 附近）；
  - **认知负荷显著影响 decode 每 token 能耗**：外在/相关负荷在 Qwen-2.5-0.5B、Qwen-2.5-1.5B、SmolLM2-360M 上提高解码每 token 能耗（最高 1.29× on Qwen-2.5-1.5B extraneous）。
- **RQ2（token 使用量）**：
  - 措辞模式主要通过 token 使用量影响能耗：
    - CoT 和激进语气一致增加总 token 比；
    - 格式、礼貌、技术语气更接近基线甚至减少 token；
  - token 扩张效果具有模型依赖性（如 CoT 对 SmolLM2-360M 与 Qwen-2.5-0.5B 影响更大）；
  - 不同措辞模式将负担转移到不同推理阶段：CoT 与激进语气增加 decode 负担；格式提示增加 prefill 负担而对 decode 影响较弱。
- **RQ3（能耗-质量前沿）**：
  - 响应质量高度依赖模型能力，较大模型普遍得分更高，较小模型波动更大；
  - 措辞模式对相关性/连贯性/内部一致性影响较稳，但正确性/完整性/指令遵循变化更大；
  - **措辞模式可将能耗-质量边界向“更低能耗 + 更高质量”方向移动**（如 LLaMA-3.2-1B、Qwen-2.5-1.5B、SmolLM2-360M 上的帕累托改进点；Gemma-2-2B 上格式/对话提示超越基线）；
  - 这种效应**不跨模型泛化**——同一措辞子属性在不同模型上给出不同权衡，故需模型感知的提示优化。
- **总结论**：认知负荷主要影响每 token 推理成本、措辞模式主要影响 token 消耗与相位负担，且两种效应都与模型架构高度交互；因此提示设计应为端侧能耗优化提供新杠杆，不能以“统一最优提示风格”替代逐模型优化。

## 7. 优点：方法或实验设计上的亮点

- **首次系统化实证**：将“提示设计”与“端侧能耗”连接，填补了该交叉领域的空白。
- **Prompt 属性双维度细分**：区分“表达形式”与“推理需求”两类正交属性，使“语言形式 vs. 计算负担”的归因更清晰。
- **严格控制提示变体质量**：引入“属性纯度得分 + 语义相似度阈值”双重自动过滤，并辅以人工核验，有效减少语义漂移与属性污染。
- **阶段级能耗剖析**：将能耗分为 prefill 与 decode 两个相位，并给出功耗采样积分公式，能揭示 token 数量与每 token 成本在不同阶段的不同作用，避免粗粒度总能量带来的误导。
- **能耗归因公式**：利用 E=e·T 将能耗分解为“单价”与“规模”，结合归一化热力图与固定基线负担图，直观区分不同属性路径。
- **能耗-质量联合分析**：引入帕累托前沿视角，在多指标质量评估下展示提示选择可在“更低能耗 + 更高质量”范围改进，而不仅是单一维度的节能。
- **跨模型、跨设备、跨数据集验证**：强调模型依赖性并直白报告 negative/不一致结果，避免了“全局最优提示”那样过度简化的结论。
- **开源资源**：提供代码、数据集与脚本，有利于复现与后续扩展。

## 8. 不足与局限

- **提示属性覆盖有限**：仅考察认知负荷与措辞模式两类属性（虽然其下有 10 个子属性），但未包含情绪效价、对抗性框架、风格限制等更广提示维度。
- **长度难以解耦**：外在负荷定义自带“冗余信息”，内在负荷定义自带“步骤列表”，其变体必然更长；作者承认无法完全区分“认知负荷框架效应”与“长度效应”。
- **自动评估可能引入偏差**：单一 LLM（Gemini-2.5-Pro）同时担任提示生成器和评分器，可能产生系统性评分偏差；DeepEval 或嵌入相似度只是近似，不能完全替代人类判断。尽管有随机子集人工复核，但比例与判据不够详细。
- **硬件覆盖不高**：仅 Pixel 7/8 Pro 两台设备，且认知负荷提示只在一台上测试；不同 SoC（NPU/GPU/CPU）、内存系统和运行时后端可能有不同电源谱。
- **剖析粒度仍为阶段级**：未深入到 KV-cache 行为、硬件计数器或算子级 trace，无法解释特定硬件上能耗差异的底层机理。
- **统计推断不足**：虽多次重复取均值，但未提供显著差异检验、效应量或置信区间，无法判断报告差异（如 1.29×）是否在统计上稳健。
- **模型均为较小规模量化模型**：结论未必能推广到更大端侧模型或不同量化方案。
- **任务类型限制**：认知负荷仅覆盖算数、是非、科学选择；措辞模式为开放式任务，不同任务类型下结论可能不同。
