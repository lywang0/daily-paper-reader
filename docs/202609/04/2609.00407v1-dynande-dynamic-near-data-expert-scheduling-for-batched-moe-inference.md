## 摘要
混合专家（MoE）模型能够高效扩展大规模语言模型（LLM）推理，但在基于神经处理单元（NPU）的系统上部署时会遭遇大量数据移动开销。近数据处理（NDP）通过NPU-NDP协同执行为缓解这一瓶颈提供了一种有前景的方法。然而，现有的NPU-NDP MoE系统并未充分考虑硬件异构性、动态专家级并发性以及批量推理期间专家的时间复用。本文提出了DynaNDE，一种利用NPU-NDP协作加速批量MoE推理的动态近数据专家调度框架。DynaNDE引入了一个分析性能模型，该模型捕获了协作NPU-NDP执行中的硬件异构性、数据移动成本和通信-计算重叠。在该模型的指导下，DynaNDE在考虑专家级并发的同时确定跨NPU和NDP的逐层专家调度。DynaNDE还整合了感知复用的运行时，当专家驻留在NPU内存中时，可避免冗余的参数移动。实验结果表明，与最先进的NPU-NDP MoE服务框架相比，DynaNDE在预填充和解码阶段分别实现了平均2.6倍和2.2倍的吞吐量提升。

## Abstract
Mixture-of-Experts (MoE) models enable efficient scaling of large language model (LLM) inference but suffer from substantial data-movement overhead when deployed on neural processing unit (NPU)-based systems. Near-Data Processing (NDP) provides a promising way to mitigate this bottleneck via cooperative NPU-NDP execution. However, existing NPU-NDP MoE systems do not fully account for hardware heterogeneity, dynamic expert-level concurrency, and temporal expert reuse during batched inference. This paper presents DynaNDE, a dynamic near-data expert scheduling framework that exploits NPU-NDP collaboration to accelerate batched MoE inference. DynaNDE introduces an analytical performance model that captures hardware heterogeneity, data-movement costs, and communication-computation overlap in cooperative NPU-NDP execution. Guided by this model, DynaNDE determines per-layer expert scheduling across the NPU and NDP while accounting for expert-level concurrency. DynaNDE also incorporates a reuse-aware runtime that avoids redundant parameter movement when experts reside in NPU memory. Experimental results show that DynaNDE achieves substantial throughput improvements over the state-of-the-art NPU-NDP MoE serving framework, with average speedups of 2.6$\times$ and 2.2$\times$ for the prefill and decoding stages, respectively.

## 1. 论文的核心问题与整体含义

- **研究背景**：混合专家（MoE）模型通过稀疏激活机制，在增加模型容量的同时控制计算成本，是大规模 LLM 推理的主流方案之一。然而 MoE 层通常包含大量专家参数，无法全部驻留在 NPU 内存中，推理时需要按 gating 结果从外部存储搬运专家参数到 NPU，造成严重的 `PMove` 数据移动开销。
- **问题定位**：近数据处理（NDP）可通过将专家计算下沉到存储端、只搬运激活（`AMove`）来缓解数据搬运瓶颈，但现有 NPU-NDP 协同框架（如 MoNDE）采用简单启发式调度，未统一考虑：
  - NPU 与 NDP 的硬件异构性；
  - batch 推理中动态变化的专家级并发数；
  - 解码阶段专家在 NPU 缓存中的时间复用。
- **论文主张**：通过“解析性能模型 + 动态逐层调度 + 复用感知运行时”的联合设计，才能真正发挥 NPU-NDP 异构协作的潜力，显著加速批量 MoE 推理。

## 2. 方法论：核心思想、关键技术细节与算法流程

### 核心思想
- 提出 **DynaNDE**：以 NPU-NDP 协作为基础，在每个 MoE 层根据实际 gating 结果，动态地为每个专家决定“在 NPU 执行”还是“在 NDP 执行”，使总层延迟最小化。
- 调度决策由一个**统一解析性能模型**驱动，避免基于带宽比的粗糙启发式。

### 解析性能模型
- 定义三类延迟：
  - **计算延迟**：`T_NPU(i)=OP(i)/P_NPU`，`T_NDP(i)=OP(i)/P_NDP`；
  - **通信延迟**：`T_PMove(i)=V_exp/BW`，激活移动延迟 `T_AinMove`、`T_AoutMove`；若专家已在 NPU 内存中，则 `PMove=0`，从而纳入复用；
  - **层总延迟**：`T_layer = T_1 + T_2 + T_3`。
- 采用**三阶段无冲突执行流**：
  - Phase 1：先把输入激活传输到 NDP（输入 AMove）；
  - Phase 2：NPU 侧执行 PMove-计算流水线，同时 NDP 侧并行执行剩余专家计算，两设备计算重叠；
  - Phase 3：在 PMove 全部完成后，输出 AMove 与 NPU 最后一个专家计算重叠。
- 模型显式刻画了：
  - NPU 路径内“参数搬运与计算”的重叠；
  - NPU 与 NDP 之间的跨设备计算重叠；
  - 通过分阶段避免 PMove 与 AMove 在共享 PCIe/CXL 链路上的带宽争抢。

### 调度算法流程
DynaNDE 在每个 MoE 层中执行以下步骤：
1. 对每个激活专家计算调度收益得分：
   `s(i)=T_NDP(i)-[T_NPU(i)+T_PMove(i)]`；
2. 按得分降序排列专家，优先选择“放到 NPU 收益更高”的专家；
3. 初始化全部专家置于 NDP，记录累计参数移动时间 `S_PMove`、累计 NPU 计算时间 `S_NPU`、累计 NDP 计算时间 `S_NDP`，以及 NPU 流水线的 `head` 和 `tail`；
4. 进行**前缀扫描**：依次把排序后的前 `p` 个专家转移到 NPU，并用三阶段模型计算对应层延迟；
5. 记录使总延迟最小的切分点 `p*`，最终前 `p*` 个专家在 NPU 执行，其余在 NDP 执行；
6. 这种线性扫描使在线调度开销低（综合复杂度 `O(|E| log |E|)`），避免指数级搜索。

### 复用感知
- 对于已缓存在 NPU 内存中的专家，`PMove` 置 0，从而自然进入高优先级调度，减少冗余参数搬运。

## 3. 实验设计

### 系统与模拟器
- 单 NPU + 单 NDP 设备，通过 PCIe/CXL 互连；
- NPU 配置：4 个 128×128 systolic array，1 GHz；
- NDP 配置：64 个 4×4 systolic array，1 GHz，264KB buffer；
- 互连为 PCIe Gen4 ×16；
- 基于 **NeuPIMs + DRAMsim3** 开发 cycle-accurate 模拟器；
- 先收集 MoE 模型的 token-to-expert 激活轨迹，再注入模拟器统一评估。

### 评估模型/数据集
- 使用了三个不同规模和结构的 MoE 模型：
  - Switch-Base（12 层，64 路由专家，top-1）；
  - FLAME-MoE（9 层，64 路由专家，top-6）；
  - DeepSeek-V2-Lite（26 层，64 路由专家，top-6）。
- 数据集：DCLM-Baseline。
- 默认 batch size = 32；解码阶段生成 10 个输出 token（在可控成本内捕捉时间复用行为）。

### 对比方法
- **NPU**：所有专家 PMove 到 NPU 执行；
- **NDP**：所有专家在 NDP 执行，只做 AMove；
- **MoNDE**：NPU-NDP 协同的 SOTA 基线，依据 PCIe/NDP 带宽比固定分配专家；
- **HybriMoE**：原是 CPU-GPU 异构 MoE 调度，被改写到 NPU-NDP 场景，启发式地结合 cache 状态与请求数调度。

## 6. 主要结论与发现

- DynaNDE 在 prefill 阶段比 NPU、NDP、MoNDE、HybriMoE 平均分别快 1.8×、2.9×、2.6×、1.1×；
- 在 decoding 阶段比上述方法平均分别快 30.5×、1.1×、2.2×、1.4×；
- 与 MoNDE 相比，论文标题级结论为 **prefill 平均 2.6×、decoding 平均 2.2× 的吞吐提升**；
- 调度分析表明：DynaNDE 并非单纯提高 NPU 占用率，而是根据计算收益与数据移动成本选择性地把专家放到 NPU；它的 NPU 分配中仅有 3.6% 需要重新 PMove，明显低于 HybriMoE 的 5.3%；
- 即使去掉复用感知（N-DynaNDE），仍比 MoNDE 和 HybriMoE 平均高 2.0× 和 1.3×，说明核心收益来自**解析模型引导的动态调度**，而不仅是缓存复用；
- 在不同缓存替换策略下 DynaNDE 均稳定优于 HybriMoE 约 1.3×，说明其调度对替换策略具有鲁棒性。

## 7. 优点

- **问题选取精准**：直击 MoE 推理中“专家参数搬运占主导”的痛点，并识别出现有 NPU-NDP 方案忽略的三大因素（异构性、专家并发、时间复用）；
- **方法论统一**：用解析性能模型串起“调度目标—调度算法—运行时执行流”，调度决策与真实执行间的一致性较强；
- **算法开销低**：采用排序+前缀扫描代替指数级搜索，适合逐层在线调度；
- **复用感知设计轻量**：只需将 PMove 置 0 即可自然融入调度，无需改动 NDP 硬件数据通路；
- **实验设计较为系统**：覆盖三模型、prefill/decoding、batch size、cache size、cache 替换策略、消融和硬件成本估计，能够较好支撑论文观点。

## 8. 不足与局限

- **实验规模偏小**：模型选择偏向中小型 MoE（Switch-Base、FLAME-MoE、DeepSeek-V2-Lite），未覆盖稠密大 MoE 或真实生产级 MoE（如 DeepSeek-V3 规模）；
- **无真实系统验证**：所有数据来自模拟器，调度器运行在 host 上的软件延迟、驱动开销等未被真实测量；
