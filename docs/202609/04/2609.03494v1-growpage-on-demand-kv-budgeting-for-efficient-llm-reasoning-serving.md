## 摘要
长输出推理使得键值（KV）缓存成为高效LLM服务的关键内存瓶颈。现有的KV压缩方法通常依赖预定义的每请求预算，并仅调整保留哪些KV状态，在整个解码过程中保持总容量固定。然而，推理工作负载表现出显著的需求变化：不同的请求需要不同的KV容量，且单个请求的注意力需求在生成过程中会演变。我们提出了GrowPage，一个将KV容量视为运行时资源的按需KV预算框架。GrowPage维护轻量级的双时间尺度查询摘要，以捕捉近期和长期的注意力行为，并利用其相对注意力工作集来估计需求演变。在每个容量边界处，GrowPage要么在当前分配内压缩KV状态，要么在出现更广泛需求时获取额外的物理页面。通过与PagedAttention的页面级内存抽象集成，GrowPage保持了连续批处理和前缀缓存。在多个模型的推理基准上的实验表明，GrowPage在性能与吞吐量的权衡上优于现有方法。

## Abstract
Long-output reasoning has made the key--value (KV) cache a critical memory bottleneck for efficient LLM serving. Existing KV compression methods usually rely on a predefined per-request budget and adjust only which KV states are retained, leaving the total capacity fixed throughout decoding. However, reasoning workloads exhibit substantial demand variation: different requests require different KV capacities, and the attention demand of an individual request evolves during generation. We introduce \textbf{GrowPage}, an on-demand KV budgeting framework that treats KV capacity as a runtime resource. GrowPage maintains lightweight dual-timescale query summaries to capture recent and long-term attention behaviors, and uses their relative attention working sets to estimate demand evolution. At each capacity boundary, GrowPage either compresses KV states within the current allocation or acquires an additional physical page when broader demand emerges. By integrating with PagedAttention's page-level memory abstraction, GrowPage preserves continuous batching and prefix caching. Experiments on reasoning benchmarks across multiple models show that GrowPage achieves a superior performance--throughput trade-off over existing approaches.

## 一、核心问题与研究动机

- **背景**：大型推理模型（如 DeepSeek-R1、Qwen3）通过超长思维链（CoT）进行数学推理和代码生成，输出可能持续数千甚至上万 token，导致 KV cache 不断膨胀，成为 GPU 内存和高效 LLM 推理服务的主要瓶颈。
- **现有方法不足**：
  - 大多数 KV 压缩方法（如 H2O、R-KV、G-KV、ThinkKV 等）沿用**固定每请求 KV 预算**，只决定“保留哪些 KV 状态”，不改变总容量。
  - 推理任务的 KV 需求存在**两个维度动态变化**：
    1. **请求间差异大**：不同请求所需的最小 KV 预算差异巨大；固定预算会过度供给简单请求，同时不足供给复杂请求。
    2. **请求内随时间变化**：同一请求在不同解码阶段，注意力分布会在集中与扩散之间反复切换，固定容量要么过保守、要么不足。
- 由于上述需求与固定容量天然不匹配，仅靠手工调参固定预算只能平移“内存浪费 vs. 推理退化”的权衡，无法真正高效服务长推理负载。
- **论文主张**：把 KV 容量看作“运行时资源”，按需动态分配，而非静态预留。

## 二、方法论：GrowPage 框架

### 1. 核心思想
- 将“每条请求的 KV 总容量”本身作为在线决策变量，结合 PagedAttention 的物理页抽象，在解码过程中动态选择以下动作之一：
  - **Compress & Hold（压缩保持）**：在当前容量内压缩历史 KV，腾出一页空间继续写入新 token。
  - **Grow by One Page（增长一页）**：当注意力需求变扩散时，从全局空闲页池申请一页新物理 KV 页。
- 只在 KV 容量边界触发需求评估，普通解码路径开销极小。

### 2. 关键技术细节

#### 双时间尺度查询摘要
- 对每条请求、每个注意力层维护两个按指数滑动平均（EMA）的 query 向量：

\[
\bar{q}^{x}_{t} = \beta_x \bar{q}^{x}_{t-1} + (1-\beta_x)q_t,\quad x \in \{S, L\}
\]

- 默认参数：短期 \(\beta_S = 0.9\)，长期 \(\beta_L = 0.999\)。
- query 在 **pre-RoPE 空间**中平滑，避免不同旋转位置下直接平均失效；在决策点再按当前 position 对齐和施加 RoPE。

#### 注意力工作集与需求趋势信号
- 构造历史候选集合 \(C_t\)，排除最近一个 KV block 以减少局部注意力主导。
- 对未来候选集计算短期、长期 query 的注意力分布，按 Top-p（默认 p=0.99）求得覆盖率所需最小 KV 数：

\[
K^x_{t,\ell,h} = \min\left\{k : \sum_{i=1}^k a^x_{t,\ell,h,(i)} \ge p\right\}
\]

- 聚合得到层/头平均工作集比例 \(r^S_t\) 与 \(r^L_t\)，定义需求趋势信号：

\[
\Delta_t = r^S_t - r^L_t
\]

- 若 \(\Delta_t > \tau\)（默认 \(\tau=0\)），则“Grow by One Page”；否则执行压缩保持。

#### 压缩时 KV 选择
- 对每一层和每个 KV head 独立决策，重要性分数取短期与长期注意力分数的最大值：

\[
s_{i,\ell,h} = \max(a^S_{i,\ell,h}, a^L_{i,\ell,h})
\]

- 先块级局部保留，确保历史区域覆盖，再全局取 Top-k，使总保留数恰好等于少掉一页后的容量目标。通过局部配额 \(k_{loc}=64\) 平衡“区域覆盖”和“全局重要性”。

#### 系统级设计
- 复用并扩展 PagedAttention/Compressed PagedAttention：
  - 预分配 query summary 状态池，大小与序列长度无关，避免动态内存申请。
  - “增长”由调度器从全局 free-page pool 分配并追加到 block table。
  - 内存不足时回退到压缩；仍不足时允许调度器抢占/重排，保证全局内存管理优先。
  - 保持连续批处理、前缀缓存与 CUDA Graph 兼容性；异步 KV 压缩与解码重叠，降低关键路径阻塞。
- 容量只单调增长，不主动收缩已启动请求的物理页，避免不可逆的信息损失。

## 六、主要结论

- 固定预算不能匹配两维异质性（请求间差异 + 请求内时变），而 **按需 KV 预算** 能更好地把内存转化为吞吐和并发。
- GrowPage 与全量 KV 相比，吞吐量在 DeepSeek-R1-Distill-Llama-8B 上平均提升约 64.3%，在 Qwen3-8B 上平均提升约 60.2%，且几乎不损失 pass@1 精度。
- 在异质混合负载中，GrowPage 优于 Zipage 的整个固定预算 Pareto 前沿：例如 Qwen3-8B 上达到 84.9% pass@1 和 2213 tokens/s，同时把驻留并发请求数从固定预算的 ~100 提升到 121，接近 Zipage-8192 的精度但吞吐几乎翻倍。
- 需求趋势信号 \(\Delta_t\) 与未来注意力工作集的真实变化有强正相关（Spearman ρ=0.78，符号一致率 80.3%），说明双时间尺度摘要能有效跟踪需求演变。
- 双时间尺度（短期 0.9、长期 0.999）+ Top-p 工作集是精度和吞吐的最佳组合。

## 七、方法优点

- **视角创新**：将“总 KV 容量”本身纳入在线决策，而不是只做 token 选择或预算分配，与现有方法形成本质区别。
- **理论支撑清晰**：从最坏情况输出误差出发，证明注意力集中度 Dp 直接决定所需最小 KV 容量，为“跟随注意力浓度动态增减容量”提供理论基础。
- **系统亲和性强**：直接建立在 PagedAttention 的页粒度抽象之上，能保留连续批处理和前缀缓存等关键系统能力，避免算法节省无法转化为实际服务效率的问题。
- **轻量开销**：在线评估仅在容量边界触发；短/长 query summary 预分配、更新近乎零成本；实验显示容量控制总开销小于解码时间 0.32%。
- **反事实与消融设计较扎实**：使用同一参考轨迹下 replay 的方法隔离生成轨迹影响，验证“增长”决策的收益；并用频率匹配的随机控制说明决策“时机”比“频率”更重要。

## 八、不足与局限

- **数据集规模有限**：AMC23、AIME24 题目数量少，即使多次采样，其统计学代表性仍低于更大规模题库。
- **模型覆盖面窄**：只测试了两类 8B 模型，缺少对更大规模、稀疏注意力原生模型（如 DeepSeek 稀疏注意力类模型）或更小边缘模型的研究。
- **实验环境单一**：单卡 A100 上运行，没有报告分布式、多卡或多租户生产环境下的内存竞争效果；调度器面临压力时 GrowPage 仍会引入较多 fallback 和预emption。
- “Grow”决策会提升瞬时内存占用，虽然设计了内存压力回退机制，但仍可能挤占同批其他请求的资源。
- 论文承认容量单调增长，没有在默认方案中实现双向收缩；若加入主动回收，则会带来明显的精度损失，说明“收缩”与精度保护之间的张力尚未完全解决。
- 相关对比方法（MorphKV、R-KV、G-KV）本身并不直接面向服务系统，采用“最大可执行 batch”作为吞吐测量的公平性值得商榷；但论文也通过与同系统集成的 Zipage 对比来弥补该问题。
