## 摘要
设备端LLM推理因其隐私性和响应性而具有吸引力，但在移动和嵌入式设备上仍面临挑战，因为模型权重远超可用DRAM。现有系统利用激活稀疏性并将权重卸载到SSD或闪存，但面临一个基本的系统权衡：准确的稀疏执行决策需要最新上下文，而高效的计算-I/O重叠则需要早期预测。因此，现有设计要么串行化执行，要么产生冗余的权重获取、额外计算和较大的缓存开销。我们提出了LeanStream，一种用于高效设备端LLM推理的流式推测与细化框架。LeanStream利用部分GPU结果逐步细化计算、加载和缓存保留优先级，从而实现GPU执行与存储I/O之间的细粒度重叠。我们在移动和嵌入式平台上实现了LeanStream。与先前的设备端LLM推理系统相比，在先前工作达到的最佳吞吐量下，LeanStream将内存使用量减少了4.8倍到7.5倍，同时进一步将token生成吞吐量提高了1.6倍到2.1倍。

## Abstract
On-device LLM inference is attractive for privacy and responsiveness, but remains challenging on mobile and embedded devices because model weights far exceed available DRAM. Prior systems exploit activation sparsity and offload weights to SSD or flash storage, but face a fundamental systems trade-off: accurate sparse execution decisions require the latest context, whereas efficient computation-I/O overlap requires early prediction. As a result, existing designs either serialize execution or incur redundant weight fetches, extra computation, and large cache overheads. We present LeanStream, a streaming speculate-and-refine framework for efficient on-device LLM inference. LeanStream progressively refines computation, loading, and cache-retention priorities using partial GPU results, enabling fine-grained overlap between GPU execution and storage I/O. We implement LeanStream on both mobile and embedded platforms. Compared with prior on-device LLM inference systems, LeanStream reduces memory usage by 4.8$\times$ to 7.5$\times$ at the best throughput achieved by prior work, while further improving token generation throughput by 1.6$\times$ to 2.1$\times$.

## 1. 论文的核心问题与整体含义

### 研究动机
- 设备端（on-device）LLM 推理因隐私保护和响应性需求而日益重要，尤其在移动与嵌入式设备上。
- 核心矛盾：LLM 模型权重量级远超移动设备可用的 DRAM，直接部署几乎不可行。
- 现有解决方案的普遍思路：利用激活稀疏性，将权重存储于 SSD/闪存中，仅动态加载和执行当前输入相关的权重子集（可减少约 80% 计算和内存开销）。
- 此方案面临一个**根本性的系统权衡（fundamental trade-off）**：
  - 一方面，准确的稀疏执行/加载决策需要尽可能最新的上下文（即前一层输出），这要求等待 GPU 完成计算；
  - 另一方面，高效的 I/O 与计算重叠要求早期预测（speculation），从而提前预取权重以隐藏存储延迟。
- 现有系统（DejaVu、PowerInfer-2 等）不能同时满足这两个目标，被迫在以下选项中取舍：
  - 串行化执行（准确性高但硬件利用率低）；
  - 层间推测式加载（重叠好但预测精度低，造成冗余加载、多余计算）；
  - 大规模内存缓存（缓解 I/O 但占用大量内存，且缓存保留决策仍基于不完整的上下文）。

### 关键问题
> 如何在不牺牲预测准确性的前提下，实现高效细粒度的计算–I/O 重叠，从而在资源受限设备上实现高吞吐的 LLM 推理？

### 整体含义
论文主张不要二元对立地在“等最新上下文的准确决策”与“长视野推测的提前决策”之间做选择，而是将二者统一为**持续的推测-细化（speculate-and-refine）流式管线**，让系统在做计算、加载和缓存保留决策时，能够随计算进展不断改进。

## 2. 方法论：核心思想、关键技术细节

### 核心思想
LeanStream 采用“边推测、边细化”的流式执行范式：

> 在 GPU 尚在处理前一层（或当前层前一阶段）时，LeanStream 利用已产生的**部分中间结果**不断更新对下一层激活模式的预测，并据此动态调整权重加载优先级、GPU 执行顺序和缓存驱逐策略；反之亦然—当任何一批所需权重到达 DRAM 时，GPU 不必等待该层全部权重，而是立刻执行当前已就绪的最高优先级子计算。

这实现了 GPU 计算与存储 I/O 之间的 **双向、细粒度、渐进式协同**。图1(d)展示了这一核心思想：通过流式 pipeline 替代传统方法中的串行、粗粒度推测、或大缓存方案。

### 技术手段 1：细粒度流式控制（Fine-Grained Streaming Control）
**挑战**：
- 移动/嵌入式 SoC 上 CPU、GPU、I/O 异构处理器之间高频协调困难。
- 传统同步机制（cudaDeviceSynchronize、clFinish）开销巨大（实验显示同步频率提高可导致 MLP 层执行时间数倍增长，图3(b)）。
- 事件原语（如 cudaEvent_t）仅支持单向通知且是 kernel 粒度的，无法进行实时双向控制，且常需要手动切分 kernel，增加开销。

**解决方案 A: Thread-Block 级、非阻塞、非对称协调机制**
- 利用 SoC 统一内存架构（unified memory），使 CPU 与 GPU 可直接共享 DRAM 数据。
- 在 GPU kernel 内部每个 thread-block 执行前，由 leader thread 对 `gpu_rd_flg` 做非阻塞检查，等待权重是否加载完成。
- 计算完成后 thread-block 写回部分结果并通过 `gpu_wr_flg` 标记完成。
- CPU 侧 I/O worker 同样通过原子标志与计算侧保持异步协作，一个 `io_rd_flg` 更新可聚合多个 GPU 信号（many-to-one），体现非对称性。
- 通过合理的组同步（pthread_barrier）与异步 I/O 提交（libaio）实现并行加载。
- Algorithm 1 给出的伪代码描述了完整的 GPU 与 I/O worker 之间的标志位同步流程。

**解决方案 B: 协调开销分析与消除**
- *I/O Placement with Co-Activated Neurons*：按优先级加载权重会破坏权重在 SSD 上的物理连续性从而降低 I/O 带宽利用率；LeanStream 将神经元分组打包视为分布表示学习问题，通过对比学习（co-activation 正对/负对）学习神经元嵌入，再聚类以确定 I/O 友好的权重块物理布局（实验中 Qwen2.5-7B 每块 3 个权重，Mistral-7B/Llama2-7B 每块 2 个权重）。
- *Permutation-Invariant Execution*：由于 SwiGLU 的输出为各隐藏神经元的加权求和，其在隐藏维度上天然具有排列不变性，因此乱序到达的权重块可以直接按到达顺序拼接为逻辑连续的稠密矩阵，无缝执行，无需重排列或复杂索引。

**解决方案 C: 自适应协调频率—基于随机模型预测控制的在线控制策略**
- 稀疏推理存在显著运行不确定性：缓存缺失率随层变化（图4a）、同一层不同 prompt 也变化（图4b）。固定离线调度不能适应这种运行时变化。
- LeanStream 将问题建模为**有穷视野随机最优控制**（finite-horizon stochastic predictive control）：
  - 状态：当前层剩余待加载权重体积经量化得到（qₙ）；
  - 动作/计划：GPU 与 I/O 的协调频率分段计划（φₙ）；
  - 模型：分层段的执行时间建模（Interval I/II）、GPU 残余工作量、基于条件分布 Dₙ(q,φ) 的下一层剩余加载量转移概率；
  - 求解：采用随机动态规划（公式(7)）离线求最优动作，并以 **LUT（查找表）**形式存储，在线只做状态测量与表查询（公式(9)），实现近似零决策开销的自适应控制。

### 技术手段 2：轻量系统控制—堆叠可学习哈希（Stacked Learnable Hashing）
**挑战**：
- 现有 DNN（如两层 MLP）预测器在 CPU 上开销过大（表1：在 Jetson AGX Orin 上预测时间可超过 GPU 稀疏计算本身），且内存占用超过 1 GB，无法支撑高频协调。
- 高协同频率下预测必须极快且极省内存。

**解决方案**：
- 将可学习 LSH（Locality-Sensitive Hashing）作为**可微的索引-查找表原语**，以极低的计算与内存开销替代传统神经网络层：
  - 每层堆叠哈希输出 yₖ = Tₖ·φ(fₖ(xₖ))，从哈希桶中读取预存的学习向量。
  - 使用超平面哈希（hyperplane hashing）计算哈希码，配合 XNOR + bitcount 操作加速。
  - 用**直通估计器（straight-through estimator）**处理 sign 函数的不可导；用将 argmax 等价改写（公式(12)）后再以 **Gumbel-Softmax** 近似实现查找操作的反向传播，从而支持端到端监督训练。
- 最终任务：
  - **分类任务**（神经元激活预测）：预测哪些权重子矩阵应被加载并优先计算；
  - **回归任务**（缓存驱逐）：预测缓存条目下次复用的时间（reuse distance），辅助驱逐策略。
- 同时配合 PCA 线性降维降低预测器输入维度，并可与 GPU kernel 融合以近似零开销计算。

- 但一个潜在偏差是：自研基线 DejaVu+（加入 LRU）是一种“弱化增强”而非公认基线；PowerInfer-2 的官方最优设置（50% 缓存）也被用作文中的参照上限，而 LeanStream 的内存预算上限与其持平或更低，这是有利于论文对比眼光的做法，但也符合其目标内存受限场景。

## 6. 主要结论与发现

1. **显著端到端性能收益**：在 PowerInfer-2 最优配置（50% 权重量缓存）同吞吐的情况下，LeanStream 内存占用降低 4.8×–7.5×；在同等或更小内存预算下，token 吞吐再提升 1.6×–2.1×。
2. **核心论断得到验证**：将执行、加载与缓存保留的决策从“一次性”变为“渐进式细化”，确实可以在消除 I/O 与计算彼此等待的同时减少冗余工作。
3. **细粒度同步的有效性**：Thread-block 级非阻塞非对称通信原语显著低于传统 device sync 的开销（甚至 16 分片时仍低于原计算时长的一半，而传统 device sync 已超过原始时间）。
4. **缓存优先级是最具产出比的组件**：在低内存预算时（如 20% 缓存），优先级缓存策略带来的性能增益最大，尤其在 I/O 带宽受限的手机平台上。
5. **缓存命中率大幅改善**：在 25% 内存预算下缓存 miss 率可以从 0.56（PowerInfer-2）降到 0.11；50% 预算时从 0.19 降至 0.05（接近 4 倍改进）。
6. **动态在线控制优于最优静态方案**：leanStream 的动态协调频率策略比通过离线搜索得到的最优静态配置高出相当大的吞吐（约 1.5×，表5）。
7. **堆叠可学习哈希的有效性**：在仅需约 1.5% 大小的 DNN 预测器内存（24 MB vs 1.4 GB）和低于 100 微秒延迟的同时，保证了足够低的加载冗余（12%–14%），略低于但接近 BNN 的 9%–11%，同时大幅减低了延迟与内存占用。
8. **精度保持性**：在 70%–80% 稀疏度范围内，LeanStream 输出质量与 dense 模型和各基线几乎一致（差异都在基准噪声量级内）。
9. **识别解码阶段为主要延迟瓶颈**：即使 256 个输入 token 的 prefill，其后解码 256 个 token 仍占总延迟的绝大部分；对端侧优化启示：应重点优化解码 I/O 流。
10. **无热节流风险**：连续 2 小时高利用率运行，峰值 GPU 温度 76℃ 低于热节流阈值（99℃），但能量/token 略高于低利用率竞争系统（因更高的硬件利用带来功率升高）。

## 7. 方法/实验亮点

- **提出统一的执行–I/O解耦架构**：把计算/缓存决策从“一次性静态分流”变革为“流式双向协同”，切中端侧硬件现状的本质（DRAM 小、统一内存架构）。
- **考虑工程嵌入式系统的现实**：低开销通信、kernel 不切分、利用 permutation invariance 消除重索引、I/O 布局学习等，都是高度工程化、有实用价值的系统贡献。
- **算法与系统结合紧密**：利用随机动态规划与显式 MPC / LUT 实现可承受的在线决策，以离线 profiling 平衡在线不可预测性，方法新颖且落地性强。
- **轻量预测器的设计有启发性**：利用 LSH 的查找替代神经网络算术运算，实现了推理速度/内存两方面的数量级降低，同时保留端到端可训练性。
- **多平台三档硬件对照**清楚地展示了系统在不同 IO/Compute 比例上的弹性与可推广性。
- **引入随机建模来控制协调频率**，打破了固定调度带来的僵化，使系统有很强的运行时鲁棒性。
