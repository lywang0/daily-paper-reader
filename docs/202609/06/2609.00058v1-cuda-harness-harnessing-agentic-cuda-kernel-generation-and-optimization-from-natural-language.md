## 摘要
开发高性能CUDA内核需要算法实现、正确性验证和硬件感知并行优化方面的专门知识，这构成了巨大的专业壁垒，使得直接从自然语言生成CUDA内核（Text2CUDA）变得至关重要。与此同时，大语言模型（LLMs）的通用代码生成能力催生了一系列探索基于LLM的CUDA内核生成的工作。这些工作主要关注从高级框架（如PyTorch）到CUDA的转译（Torch2CUDA），而非Text2CUDA——在后者中，模型必须理解高级输入语义并处理底层内核实现和验证。此外，由于依赖预定义的测试输入，这些方法容易受到奖励黑客（reward hacking）的影响。在本文中，我们提出CUDA-Harness，一个利用智能体从自然语言生成和优化CUDA内核的框架。具体而言，我们引入中间结构化生成（Intermediate-Structured Generation）来连接高级语义理解与底层内核生成。为了稀释Text2CUDA中的奖励黑客，我们构建了基于综合的验证（Synthesis-Based Verification）以提供隔离的测试数据和渐进式验证。此外，我们提出反馈自适应进化（Feedback-Adaptive Evolution），一种在优化性能的同时优先保证正确性的内核进化策略。最后，通过大量实验，我们证明了CUDA-Harness的有效性，并进一步评估了其在LLMs、硬件平台上的泛化能力以及向C到CUDA转译的泛化能力。

## Abstract
Developing high-performance CUDA kernels demands specialized knowledge in algorithm implementation, correctness validation, and hardware-aware parallel optimization, creating a substantial expertise barrier and making generating CUDA kernels directly from natural language (Text2CUDA) essential. Meanwhile, the general-purpose code generation capability of Large Language Models (LLMs) prompts a series of works exploring LLM-based CUDA kernel generation. They mainly focus on transpilation from high-level frameworks such as PyTorch to CUDA (Torch2CUDA) rather than Text2CUDA, where models must understand the high-level input semantics and handle low-level kernel implementation and validation. Additionally, these methods are vulnerable to reward hacking due to reliance on predefined test inputs. In this paper, we propose CUDA-Harness, a framework for harnessing agentic CUDA kernel generation and optimization from natural language. Specifically, we introduce Intermediate-Structured Generation to connect high-level semantic understanding with low-level kernel generation. To dilute reward hacking in Text2CUDA, we construct Synthesis-Based Verification to provide isolated test data and progressive validation. Furthermore, we propose Feedback-Adaptive Evolution, a kernel evolution strategy that prioritizes correctness while optimizing performance. Finally, through extensive experiments, we demonstrate the effectiveness of CUDA-Harness, with further evaluations illustrating generalization across LLMs, hardware platforms, and to C-to-CUDA transpilation.

## 2. 提出的方法论

CUDA-Harness 是一个三层式智能体框架，包含三个相互衔接的核心组件：

### 2.1 中间结构化生成（Intermediate-Structured Generation）
用于连接“高层语义理解”与“低层内核实现”，主要解决自然语言描述不完整的问题：
- **内核实现清单（Kernel Implementation Manifest）**：从自然语言生成每个待实现 kernel 的结构化条目，包括 kernel 名称、输入输出描述、功能描述、语言无关的参考伪代码，以及测试输入/输出的形状与数据类型。此阶段不让模型写具体 CUDA 代码，只专注于补齐原始提示中缺失的算法细节。
- **自包含 CUDA 脚手架（Self-Contained CUDA Scaffold）**：提供统一代码模板，把内存管理、数据拷贝、kernel 启动等“外部逻辑”封装成独立 launcher，使模型只专注于 kernel 主体和启动配置。
- **防奖励黑客措施**：脚手架禁止使用 dummy inputs；测试数据通过命令行参数以二进制文件传入，调用约定通过编译期的 `#pragma message` 暴露，从而让 kernel 实现过程“看不到”具体测试数据，无法为其量身定制。但由于 launcher 会显式设定启动配置，可能与 kernel 内部隐含的访存模式冲突，此时智能体需要反思并回溯修改 kernel。

### 2.2 基于综合的验证（Synthesis-Based Verification）
为应对 Text2CUDA 场景下没有现成测试数据的问题，该方法将“测试数据合成”与“kernel 生成”彻底解耦：
- **解耦式测试数据合成**：在独立环境中使用标准数值库（NumPy/PyTorch）生成测试输入和参考输出，避免上下文交叉污染。
- **扩大数值范围**：要求测试输入分布在较大数值区间（例如均值 5.0、标准差 10.0 的高斯分布），以抑制仅在小数值下出现的验证异常。功能验证公式为：
  \[
  \mathrm{V}(K,x,y)=\mathbb{I}\big[|K(x)-y|\le \epsilon_{\text{atol}}+\epsilon_{\text{rtol}}|y|\big]
  \]
  若测试值过小，\(|y|\) 很小，相对容差项会失效，易导致错误 kernel 通过验证。
- **渐进式多阶段验证（Progressive Multi-stage Validation）**：按“先编译，再功能验证，最后性能剖析”的顺序执行 fail-fast 验证，避免无效 kernel 在真实硬件上浪费算力。验证工具基于 Model Context Protocol（MCP）封装，提供编译检查、功能校验和 Nsight 性能剖析等接口。

### 2.3 反馈自适应进化（Feedback-Adaptive Evolution）
用于在保证正确性的前提下持续优化 kernel 性能：
- **正确性优先的修正（Correctness-First Refinement）**：根据失败阶段决定修复策略；编译失败则根据报错修复；功能验证失败则**回退到更保守、更简单的实现**，防止模型在错误的“看似高性能”代码上继续堆积优化手段。
- **奖励驱动的优化（Reward-Driven Optimization）**：奖励函数基于编译、功能验证和性能剖析结果，定义为：
  \[
  r(K) = -1 + C(K) + C(K)V(K)P(K)
  \]
  其中 \(P(K)=1/\text{Latency}(K,x)\)。由于模型没有可更新的参数，该方法引入**优化洞察摘要**，即让模型根据代码差异与奖励变化提炼优化经验：
  \[
  e = M_e\left(\text{Diff}(K_{\text{post}},K_{\text{pre}}), r(K_{\text{post}})-r(K_{\text{pre}})\right)
  \]
  通过多轮迭代，使后续 kernel 生成继承之前有效的优化知识，同时避开无效策略。

总体而言，CUDA-Harness 是一篇思路清晰、问题定位准确、模块设计合理的系统论文。它抓住了 Text2CUDA 任务中容易被忽略的“测试数据缺失”和“验证信号不可信”等问题，通过解耦生成与验证的思路给出了一个可行的 agentic 方案。在当前 LLM 编程智能体大多依赖外部验证器或固定测试样例的趋势下，这篇文章提出了一种不依赖测试数据的替代路径，并给出了翔实的实验支撑。若能补齐统计严谨性、成本核算以及更大规模场景的测试，这一工作对 GPU 编程自动化的工程价值和研究启发意义都将更进一步。
