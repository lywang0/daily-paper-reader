## 摘要
边缘设备上的协同微调可让大语言模型适配领域特定数据，同时将每个设备的数据保留在本地。当前最先进（SOTA）的协同微调技术主要面向基于GPU的边缘设备设计，并依赖流水线并行（PP）。然而，许多边缘平台，包括物联网网关、智能家居中枢和车载计算机，主要基于CPU。本文指出，PP在基于CPU的边缘设备上效率低下，因为同一CPU同时处理模型计算和通信，导致严重的CPU争用。我们的分析表明，这平均会导致比GPU设备高5.75倍的计算停顿比例。张量并行（TP）可以通过将计算与通信分离来缓解这种争用，但现有TP技术假设设备是同构的。在异构CPU边缘设备上，我们发现这一假设会导致较快的工作节点在同步点等待较慢设备时空闲高达34%。为解决这些局限，我们提出Xronos，一种面向异构CPU边缘设备的协同微调框架。Xronos以TP作为执行骨干，并结合轻量级性能剖析与异构感知的张量划分，以缓解掉队者瓶颈。在多种设备、模型和基准任务上，与SOTA技术相比，Xronos将微调时间减少18%（TP）至56%（PP），并将设备空闲时间比例降低约5.9倍，同时保持准确率。

## Abstract
Collaborative fine-tuning on edge devices adapts large language models to domain-specific data while keeping each device's data local. State-of-the-art (SOTA) collaborative fine-tuning techniques are largely designed for GPU-based edge devices and rely on pipeline parallelism (PP). However, many edge platforms, including IoT gateways, smart-home hubs, and in-vehicle computers, are primarily CPU-based. This paper reports that PP is ineffective on CPU-based edge devices because the same CPU handles both model computation and communication, which causes severe CPU contention. Our analysis shows that this leads to 5.75$\times$ higher computation stall ratios than on GPU devices on average. Tensor parallelism (TP) can alleviate this contention by separating computation and communication, but existing TP techniques assume homogeneous devices. On heterogeneous CPU edge devices, we find that this assumption causes faster workers to remain idle for up to 34% while waiting for slower devices at synchronization points. To address the limitations, we propose Xronos, a collaborative fine-tuning framework for heterogeneous CPU edge devices. Xronos uses TP as its execution backbone and combines lightweight profiling with heterogeneity-aware tensor partitioning to reduce the straggler bottleneck. Across diverse devices, models, and benchmark tasks, Xronos reduces fine-tuning time by 18% (TP) to 56% (PP) and the ratio of device idle time by $\sim$5.9$\times$ over SOTA techniques, while maintaining the accuracy.

- **核心痛点二：PP 在 CPU 上失效**。在 CPU 设备上，同一颗 CPU 既负责模型计算又负责通信，导致严重的 CPU 资源争用，PP 的计算–通信重叠优势无法兑现。实测显示 CPU 上的计算停顿比（computation stall ratio）平均比 GPU 高 **5.75×**（GPT-2-Medium 为 7.26×，RoBERTa-Base 为 4.24×）。
- **核心痛点三：TP 虽可解耦，但假设同构**。张量并行（TP）将计算与同步分为顺序阶段，天然更适合 CPU，可显著降低上下文切换（降低约 95%–98%）。但现有 TP（如 Megatron-LM）假设设备同构，采用均匀划分；在异构 CPU 边缘上会导致最快设备在同步点空闲高达 **34%**（GPT-2-Medium）和 23%（RoBERTa-Base）。
- **整体含义**：本文首次系统研究了异构 CPU 边缘设备上的协同 LLM 微调，提出以 TP 为骨架、结合异构感知划分的 Xronos 框架，在保证精度的同时大幅降低迭代时间与设备空闲率。

## 2. 论文提出的方法论

### 2.1 核心思想
- 以 **张量并行（TP）** 替代 PP 作为执行骨干，避免 CPU 计算与通信争用。
- 引入 **轻量级性能剖析 + 异构感知的张量划分**，按各设备算力与内存能力非均匀分配计算负载，缓解掉队者（straggler）导致的同步等待。

### 2.2 三阶段工作流程
1. **Phase 1：Worker 性能剖析（Worker Profiling）**
   - 将模型分解为嵌入层（emb）、B 个 Transformer 块（blk）、输出层（out）。
   - 构造剖析集：1 个 emb + 1 个代表性 blk（含 k 层）+ 1 个 out，共 **k+2 层**；仅跑约 10 次迭代，使用合成输入。
   - 每个 worker d 对每层 ℓ 记录：
     - 单层微调时间 `T_d^ℓ`（共 k+2 个值）；
     - 峰值内存，分解为权重 `M_w,ℓ^d`、激活 `M_a,ℓ^d`、临时缓冲 `M_t,ℓ^d`（共 3(k+2) 个值）。
   - **不剖析通信时间**：TP 中通信量 `V_comm` 仅由批量大小与隐藏维度决定，通信时间 `T_comm = V_comm / min_d B_d`，与划分比例无关，故视为常数。

2. **Phase 2：异构感知规划（Heterogeneity-aware Planning）**
   - **划分单元（partition unit）**：TP 中张量按不可分割的整数块分配（如一个注意力头对应一个单元），每层含 H 个单元；worker d 获得 h 个单元时，划分比 `p_d = h/H`，取值属于离散集合 `P = {h/H | h ∈ {0,…,H}}`。
   - **优化问题**（公式 2–5）：
     - 目标：最小化最慢 worker 的微调时间 `min max_d T_d(p_d)`；
     - 约束：`Σ p_d = 1`（全部分配）、`M_total^d(p_d) ≤ M_cap^d`（内存约束）、`p_d ∈ P`（离散约束）。
   - **成本估计**：
     - 时间估计 `T_d(p_d) = p_d·T_emb^d + T_out^d + B·T_blk^d(p_d)`，其中 `T_blk^d(p_d) = Σ_{ℓ∈part} p_d·T_ℓ^d + Σ_{ℓ∈repl} T_ℓ^d`；
     - 内存估计 `M_total^d = M_w^d(p_d) + M_a^d(p_d) + M_t^d(p_d)`，权重与激活按划分比缩放并累加 B 个块，临时缓冲取各层峰值（不累加）。
   - **TP 策略搜索**：全局最优搜索空间为 `C(H+N−1, N−1)`，呈指数复杂度；改用**贪心逐单元分配**，复杂度降至 O(HN)。每步向能容纳新单元且使估计时间最小的 worker 分配一个单元，直至 H 个单元分配完毕；若中途无可行 worker 则返回 null（内存不足）。

3. **Phase 3：基于 TP 的微调（TP-based Fine-tuning）**
   - 协调者按 `p*` 落地张量布局（复制张量与划分张量），初始化超参与数据集，启动同步 TP 微调。

## 6. 论文的主要结论与发现

- **PP 在 CPU 边缘失效**：由于同一 CPU 同时承担计算与通信，PP 的重叠优势转化为资源争用，计算停顿比平均比 GPU 高 5.75×；归一化 CPU 迭代时间达 2.33（GPT-2-Medium）与 1.70（RoBERTa-Base），说明存在超越 CPU/GPU 算力差距的额外开销。
- **TP 显著降低 CPU 争用**：相比 PP，TP 将上下文切换减少 95.02%（GPT-2）与 97.70%（RoBERTa），计算停顿比减少约 15%–20%。
- **现有 TP 在异构 CPU 上仍低效**：均匀划分使快设备（ASUS MiniPC）空闲达 34%（GPT-2）与 23%（RoBERTa）。
- **Xronos 的有效性**：
  - 迭代时间：相比 Asteroid 平均降低 31%（RoBERTa）、28%（GPT-2）、39%（MobileLLaMA），最高达 **56%**；相比 Megatron-LM 平均降低约 14%–18%；
  - 空闲时间比：相比 Megatron-LM 降低 **4.6×–5.9×**，Xronos 空闲率保持在 6% 以下；
  - 上下文切换：相比 Asteroid 平均降低 **96.7%–98.8%**；
  - 计算停顿比：相比 Asteroid 平均降低 18%–23%；
  - 精度：保持与现有方法相当的精度，达到 90% 精度的时间比 Asteroid 减少 **53.6%**、比 Megatron-LM 减少 **16.4%**；
  - 时间估计误差：平均 MAPE 为 **15.32%**（13.28%–16.65%）。
- **其他发现**：Megatron-LM 在 MobileLLaMA-1.4B 上因不考虑内存异构而出现 OOM 失败，说明异构感知规划对内存受限场景尤为关键。

## 7. 优点

- **问题定位精准且有系统级证据**：通过 perf_event_open 实测停顿比、上下文切换、空闲率，清晰论证 PP→TP 的转换动机，而非仅凭直觉。

- **优化建模完整**：同时考虑时间目标、内存约束与离散划分单元约束，贴合 TP 的实际实现约束。

- **通信假设

偏理想化**：论文假设 TP 通信时间仅由批量大小与隐藏维度决定，并以最慢设备带宽 `min_d B_d` 作为瓶颈，忽略了网络抖动、拥塞、跨交换机延迟差异以及 all-reduce 实现细节；在真实边缘网络中，通信时间可能波动，进而影响划分与迭代时间估计的准确性。
- **动态环境与容错未涉及**：未讨论设备掉线、算力动态变化、热降频、后台负载波动等场景；Xronos 的静态规划在运行时环境变化时可能失效，也缺乏重规划或容错机制。
- **隐私与安全机制未讨论**：虽然协同微调本身不共享原始数据，但论文未分析梯度泄露、成员推断等风险，也未结合差分隐私、安全聚合等机制。
- **可扩展性验证有限**：设备数量最多 5 台，未验证更大规模集群；模型最大 1.4B，未验证 7B/13B 等更大 LLM 在 CPU 边缘上的可行性。
- **评估任务偏分类**：仅覆盖 GLUE 分类任务，未涉及生成、指令微调、长序列建模等更贴近 LLM 实际应用的场景。

## 9. 对领域的影响与启示

- **重新审视 CPU 边缘的并行策略**：论文系统论证了 PP 在 CPU 边缘因计算–通信资源争用而失效，TP 则能显著降低上下文切换与停顿比。这提示边缘协同训练不应盲目照搬 GPU 集群的 PP 优先策略。
- **异构感知是边缘协同训练的关键**：均匀划分在异构 CPU 设备上会造成严重的掉队者等待与内存溢出。Xronos 的轻量剖析 + 离散划分优化为内存与算力异构场景提供了可落地范式。
- **轻量系统剖析与规划可迁移**：仅剖析代表性层、约 10 次迭代、合成输入的设计，可迁移到其他资源受限的分布式训练/推理场景，降低规划开销。
- **为后续研究提供基线**：Xronos 可作为 CPU-only 异构边缘协同 LLM 微调的新基线，后续工作可在动态异构、通信优化、量化训练、更大模型、隐私保护等方向继续推进。

## 10. 总体评价

Xronos 是一篇问题驱动、系统测量与算法设计结合紧密的工作。它准确抓住 CPU 边缘协同微调中被忽视的痛点：PP 在 CPU 上因资源争用而失效，TP 虽更适合 CPU 却假设同构。论文通过实测停顿比、上下文切换、空闲率等系统级证据支撑动机，并提出轻量剖析、异构感知规划与 TP 微调三阶段框架。方法简洁、约束建模完整、贪心算法可落地，实验覆盖多种模型、任务与设备组合，验证了迭代时间、空闲率、上下文切换与精度–时间方面的优势。

其主要局限在于：算力与能耗报告不足，缺乏消融实验，时间估计误差约 15%，模型规模与任务类型有限，通信与动态环境假设偏理想化，且未与更多 TP/PP 变体对比。总体而言，Xronos 在 CPU 异构边缘协同 LLM 微调方向具有明确贡献与启发意义，但距离生产级鲁棒部署仍需进一步验证与扩展。
