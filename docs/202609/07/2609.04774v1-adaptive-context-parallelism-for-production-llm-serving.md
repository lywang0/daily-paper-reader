## 摘要
随着大语言模型（LLM）上下文窗口的扩展和输入序列的不断增长，服务系统面临越来越高的计算和内存需求。上下文并行（CP）将输入序列划分到多个计算节点上以并行化计算，因此对于高效的LLM服务变得愈发重要。然而，现有的支持CP的系统要么依赖静态CP配置，要么仅针对活动请求或批次调整CP度。本文提出了Vertumnus，一个面向异构和动态工作负载的自适应CP服务系统。在请求级别，Vertumnus通过结合预测排队延迟、缓存感知的预填充时间和GPU时间成本的放置代价，将请求路由到具有不同CP度的工作节点之间。在集群级别，Vertumnus根据工作负载需求的变化，通过秒级的分裂和合并操作来调整工作节点组成。Vertumnus进一步引入了一种全局前缀缓存管理策略，协调具有相同或不同CP度的工作节点之间的缓存放置和复制，从而在请求分配和工作节点组成变化时保持缓存局部性。在包含公共和生产工作负载的64-GPU集群上的实验表明，在最高评估负载下，相比于最强基线，Vertumnus将平均首令牌时间（TTFT）降低了高达28.1%，并将令牌加权SLO达成率提高了高达13.3个百分点。

## Abstract
As LLM context windows expand and input sequences grow longer, serving systems face increasing computational and memory demands. Context parallelism (CP), which partitions the input sequence across multiple ranks to parallelize the computation, has therefore become increasingly important for efficient LLM serving. However, existing CP-enabled systems either rely on static CP configurations or adjust the CP degree only for active requests or batches. In this paper, we present Vertumnus, an adaptive CP serving system designed for heterogeneous and evolving workloads. At the request level, Vertumnus routes requests among workers with different CP degrees using a placement cost that combines predicted queuing delay, cache-aware prefill time, and GPU-time cost. At the cluster level, Vertumnus adapts the worker composition through seconds-scale split and merge operations as workload demand changes. Vertumnus further introduces a global prefix-cache management policy that coordinates cache placement and replication among workers with the same or different CP degrees, preserving cache locality as request assignments and worker composition change. Experiments on a 64-GPU cluster with public and production workloads show that, under the highest evaluated loads, Vertumnus reduces mean TTFT by up to 28.1% and improves token-weighted SLO attainment by up to 13.3 percentage points over the strongest baseline.

## 1. 核心问题与研究动机

- **背景**：大语言模型上下文窗口不断扩展，长输入序列日益普遍；同时生产环境中请求长度高度异构、负载随时间动态变化、前缀复用（prefix reuse）成为常态。这些特征使“上下文并行”（Context Parallelism, CP）成为降低长请求首令牌时间（TTFT）的关键技术。
- **问题**：现有支持 CP 的 LLM 服务系统主要存在三类不足：
  1. 多数系统不支持 CP，或未将 CP 度作为一类可调度的系统级资源；
  2. 已有 CP 系统通常在部署时静态固定 worker 的 CP 度，无法根据工作负载的长期变化调整 worker 组成；
  3. 动态调整 CP 的方案（如 LoongServe、NanoCP）往往只针对当前活跃请求或执行批次，缺乏对持久 worker 组成的维护，且会破坏前缀缓存的稳定复用。
- **目标**：在固定 GPU 预算下，设计一个**自适应 CP 服务系统 Vertumnus**，使 CP 度成为集群级、可动态控制的资源，在请求级和集群级两个时间尺度上适应异构、动态、前缀密集的生产负载，从而降低 TTFT、提升 SLO 达成率并保持较高 GPU 效率。

## 2. 方法论与核心设计

### 2.1 总体思想
Vertumnus 在 P/D 分离（prefill/decode disaggregation）架构的 prefill 池中运行，将固定 GPU 资源划分为持久 CP worker，每个 worker 具有固定的 CP 度。系统通过**请求级调度**和**集群级重配置**两个互补层次协调资源：
- 请求级：为新到请求选择最优 CP worker；
- 集群级：通过 worker 分裂/合并操作，动态调整不同 CP 度 worker 的数量；
- 跨层次：全局前缀缓存管理器保持缓存局部性。

### 2.2 缓存感知的 prefill 时间模型
- 对请求，定义输入长度 \(L = P + R\)，其中 \(P\) 为缓存命中的前缀长度，\(R\) 为未缓存的后缀长度。
- 剩余注意力工作量：
  \[
  W(R,P)=RP+\frac{R(R+1)}{2}
  \]
  其中 \(RP\) 对应未缓存查询对已缓存前缀的注意力，后半项对应后缀内部的因果注意力。
- prefill 执行时间模型：
  \[
  \hat{E}_C(R,P)=d+aR+bP+\frac{1}{C}[cR+\alpha W(R,P)]
  \]
  参数 \(d,a,b,c,\alpha\) 通过不同模型–硬件配置的离线和在线 profiling 拟合。该模型同时捕获 CP 度、前缀复用、剩余计算量对延迟的影响。
- 对每个“请求–worker”对 \((i,w)\)，预测服务时间：
  \[
  s_{i,w}=\hat{E}_{C_w}(R_{i,w}(t_i),P_{i,w}(t_i))
  \]

### 2.3 请求级调度器：自适应放置代价
调度器为每个候选 worker 计算放置代价：
\[
J_{i,w}=q_w(t_i)+\beta s_{i,w}+\lambda\left[C_w s_{i,w}-C_{\min}\hat{E}_{C_{\min}}(R_{i,w},P_{i,w})\right]
\]
- **排队延迟代价** \(q_w(t_i)\)：用该 worker 未完成请求的预测服务时间之和估算等待时间。
- **服务时间代价** \(s_{i,w}\)：来自缓存感知 prefill 模型；当 \(\beta>1\) 时强调前缀命中带来的低时延，增强缓存局部性。
- **额外 GPU 时间代价**：衡量使用较大 CP 度相对最小合格 CP 度 \(C_{\min}\) 占用的额外 GPU 时间成本，系数 \(\lambda\) 控制其对放置的影响。

### 2.4 集群级重配置：split 与 merge
- **容量 profiling**：离线测量每个 CP 度 worker 在满足 SLO 前提下的最大负载能力 \(\kappa_C\)；运行时按固定观察窗口估计实际需求 \(D(k)\)。
- **初始化**：根据历史工作负载的请求分布和需求选择初始 worker 组成；倾向于在能力足够时放入更多大 CP 度 worker。
- **触发决策**：
  - 需求持续高于上阈值 → 分裂（split），增加并发服务 lane；
  - 需求低于下阈值 → 合并（merge），为个体请求提供更多并行度；
  - 负载稳定但长请求占比明显变化时，长请求占比上升倾向 merge，下降倾向 split；
  - 容量约束优先于长请求比例信号。
- **操作机制**：仅进行相邻转换（将一个 degree-\(2C\) worker 拆为两个 degree-\(C\) worker，或反向），保持 GPU 总数不变。转换在排空（drain）后于配置 epoch 切换，参与者无需重启进程或重新加载模型权重；KV 数据保留在 GPU 上，其所有权和寻址随新 CP 几何结构异步和解。

### 2.5 全局前缀缓存管理
- 建立**全局前缀 trie**，记录每个节点的复制持有者、CP 度以及动态统计量：
  - \(access[z,C]\)：节点 \(z\) 在 degree-\(C\) worker 上被实际复用的次数；
  - \(missed[z,C]\)：因 degree-\(C\) worker 上无该前缀而损失的预测缓存收益。
- **按需统计更新**：请求被调度后，沿 reuse path 增加 access；对匹配路径上每个无 degree-\(C\) 副本的节点，用 prefill 模型计算以其父节点为结束与以该节点为结束的预测服务时间差，累加到 missed 中。
- **自适应复制与回收**（周期性扫描）：
  - 若 \(ReplicaCount(z,C)=0\) 且 \(missed[z,C]>\theta_{inter}\) → 跨 CP 度复制；
  - 若 \(ReplicaCount(z,C)>0\) 且平均 access 超过阈值 \(\theta_{intra}\) → 度内复制；
  - 若平均 access 低于 \(\theta_{reclaim}\) → 回收冗余副本；
  - 按优先级和有限操作数执行，并采用超时衰减因子使统计更关注近期需求。

## 6. 主要结论与发现

- 在最高评估负载下，与最强基线相比，Vertumnus 可将 **平均 TTFT 降低最高 28.1%**，**P90 TTFT 降低最高 55.0%**，**令牌加权 SLO 达成率提升最高 13.3 个百分点**。
- 与 vLLM 和 SGLang 相比，Vertumnus 在使用异构 CP 度的 prefill 池中能显著减少队列堆积和尾延迟。
- 动态 worker 重配置可在数秒内（约 1.1~5.1 秒，其中切换阶段 <1 秒）完成 split/merge，并能随负载中长请求占比变化自动选择更优组成。
- 全局前缀缓存管理在负载增大时主要通过“复制”增加缓存命中的放置自由度（在相同或不同 CP 度之间），以在保持前缀复用与降低排队延迟之间取得更好平衡，并非简单提高缓存命中率。

## 7. 优点

- **问题定位清晰**：将 CP 度从静态配置提升为集群级可动态调节的资源维，填补了现有系统在长上下文生产服务中的空缺。
- **时间尺度分工明确**：请求级调度与集群级重配置分别处理短时路由和长时资源结构，符合生产负载的动态特征。
- **优化目标综合考虑**：放置代价融合排队延迟、前缀复用、CP 并行效率和 GPU 占用机会成本，避免“只选缓存最优”或“只选最小度”的单向偏差。
- **工程可行性考虑充分**：worker split/merge 不重启进程、不加载权重；KV 副本不阻塞切换关键路径；全局缓存使用异步复制与回收，控制开销。
- **实验设计较全面**：覆盖真实生产 trace、公共数据集、不同模型、不同负载速率、动态场景和消融实验，报告了贴近用户感知的 TTFT/SLO 指标。

## 8. 不足与局限

- **实验场景限制**：实验仅在 H20 GPU 集群上完成，结果可能不完全外推到其他架构（如 Hopper、Blackwell 或不同网络拓扑）；CP 度集合也只考虑了 2、4、8 的有限配置。
- **Baseline 覆盖不足**：未来工作可加入更多支持弹性的系统（如 LoongServe）进行比较，但论文指出这些系统无法直接适配当前的 MoE 模型，因此存在实现的客观障碍。
- **两层决策均为启发式控制**：请求级代价函数中的 \(\beta\)、\(\lambda\) 和 cache manager 的多个阈值（\(\theta_{inter}\)、\(\theta_{intra}\)、\(\theta_{reclaim}\)）需要离线校准，在不同负载分布下是否保持最优并未提供自动调优机制。
- **前缀缓存管理存在一定滞后和推测成本**：复制/回收周期性触发，且跨 CP 度复制需要进行 KV 状态重新分区，可能带来额外通信和协调开销；删除等操作依赖异步确认，可能造成短暂不一致。
- **性能目标聚焦 prefill/TTFT**：TPOT 和 decode 池只是被假定独立满足，未做联合优化；若 decode 池成为瓶颈，论文中的增益可能无法完全转化为端到端服务质量。
