## 摘要
混合注意力模型已成为大语言模型（LLMs）的关键架构（例如 Qwen3.5 和 Kimi 系列）。其内存与计算效率使其对端侧推理极具吸引力，并与边缘神经处理单元（NPU）形成有前景的协同。然而，在边缘 NPU 上朴素地执行这些混合模型无法带来这些收益，往往会因严重的内存系统低效以及线性注意力（LA）层内部的架构不匹配而使预填充阶段成为瓶颈。我们提出 HA-NPU，这是首个无需修改底层算法即可在边缘 NPU 上实现高效混合注意力 LLM 推理的系统。HA-NPU 通过在三个层级重组 LA 组件的数据流来提升执行效率：（1）在核心级，它按头维度划分工作负载并融合相互依赖的算子，消除跨核全局内存访问；（2）在算子级，它重排执行顺序以及时消费中间张量，从而大幅降低本地缓冲区压力；（3）在张量级，它采用数据流感知的布局规划，以最小化矩阵与向量处理单元之间的转换开销。与竞争基线相比，HA-NPU 实现了高达 35.95× 的 LA 内核加速和 36.14× 的能耗降低，并带来高达 2.03× 的端到端请求延迟加速。源代码将在 https://github.com/yinyuanzhang/HA-NPU 公开。

## Abstract
Hybrid attention models have emerged as a crucial architecture for Large Language Models (LLMs) (e.g., the Qwen3.5 and Kimi series). Their memory and computational efficiency make them highly attractive for on-device inference, forming a promising synergy with edge Neural Processing Units (NPUs). However, naive execution of these hybrid models on edge NPUs fails to deliver these benefits, often bottlenecking the prefill stage due to severe memory-system inefficiencies and architectural mismatches within the linear attention (LA) layers. We present HA-NPU, the first system to enable efficient hybrid attention LLM inference on edge NPUs without modifying the underlying algorithms. HA-NPU enhances execution efficiency by reorganizing the dataflow of the LA components across three levels: (1) At the core level, it partitions workloads by the head dimension and fuses dependent operators, eliminating cross-core global memory accesses; (2) At the operator level, it reorders execution to consume intermediate tensors immediately, drastically minimizing local-buffer pressure; (3) At the tensor level, it employs dataflow-aware layout planning to minimize transformation overhead between matrix and vector processing units. Compared to competitive baselines, HA-NPU achieves up to 35.95$\times$ LA kernel speedup and 36.14$\times$ energy reduction, delivering up to 2.03$\times$ faster end-to-end request latency. The source code will be made publicly available at https://github.com/yinyuanzhang/HA-NPU

- **现实落差**：在边缘 NPU 上朴素执行 LA 反而无法兑现收益。对 Ascend 310P 上 Qwen3.5-2B 的 profiling 显示：

- **根因定位**：LA 执行模式与边缘 NPU 架构在三个层级上存在结构性错配：
  - **核心级**：chunk-head 映射破坏 NPU 偏好的粗粒度张量局部性，GM 访问占 LA 延迟的 **56.2%**；
  - **算子级**：默认语义执行顺序让中间张量过早产生、寿命重叠，超出片上缓存容量，张量溢出使逻辑 GM 流量膨胀 **93.4%（GDN）/63.8%（KDA）**；
  - **张量级**：矩阵单元偏好 Blocked 布局、向量单元偏好 Dense 布局，布局转换消耗 **41.58%** 的跨单元执行时间，并增加 **16.7%** 内存流量。
- **整体含义**：本文提出 **HA-NPU**，首个在不修改底层注意力算法的前提下，面向边缘 NPU 的高效混合注意力 LLM 推理系统。

## 2. 方法论

### 2.1 核心思想

将 delta-rule 类 LA（GDN、KDA 等）抽象为统一的 **Map–Reduce–Map 推理范式**，把执行范式从"沿序列维追求并行"转向"沿算子数据流最大化局部性"，在核心、算子、张量三个层级重组数据流，在严格保持循环状态依赖的前提下最大化数据复用、最小化数据搬运。

### 2.2 关键技术

- **核心技术一：头级映射与跨算子融合（§4）**
  - 洞察 1：所有 Map/Reduce 算子中头之间零数据依赖；洞察 2：边缘 NPU 核心数（1–10）远少于注意力头数（16–64），头级并行已足以饱和硬件，chunk 级并行只带来跨核同步开销。
  - 以头为基本调度单元，将整个 Map–Reduce–Map 流水线融合为单个 kernel 固定到专用核，使中间张量与状态 S 常驻片上缓冲，绕开 GM 内存墙。
  - **计算切分**：头数非核数整数倍时产生尾部负载不均（如 16 头映射到 10 核余 6 头），采用沿状态 S **列方向切分**（而非行切分，避免跨核归约）暴露额外并发工作负载。
  - **三级调度**：Step I 头充足时一头一核；Step II 尾部欠载时按 S 列切分；Step III 极端尾部回退到 chunk-head-chunk 映射保证核饱和。

- **核心技术二：寿命感知的算子重排序（§5）**
  - 核心洞察：只要输入就绪，算子不必受默认语义顺序约束（受处理器乱序执行启发），优先消费刚生成的中间张量以缩短其生命周期、压低峰值内存。
  - **跨 chunk：State-First → Chunk-First**。默认顺序先算新状态 S_{c+1}（Op5）再用旧状态 S_c 算输出（Op6），导致 S_c 与 S_{c+1} 同时驻留、状态内存翻倍。利用"Op6 只需要 S_c 和 v_c、不需要最终 S_{c+1}"这一**部分依赖**，将 Op5 拆为 *Read → Op6 → Update*，延迟状态提交实现**原地覆盖**，状态内存减半。
  - **chunk 内：Inversion-First → GEMM-First**。默认把矩阵求逆 A⁻¹ 夹在共享输入的 GEMM 之间，使 K、Q、Kᵀ 等输入空闲占位、L0 反复驱逐重载。两步优化：(i) 通过算子重写将 W = A⁻¹K 改写为 A⁻¹V − K S 形式，把 A⁻¹ 因子提出，使 GEMM 直接消费 K，解耦求逆依赖；(ii) 将所有共享输入 GEMM（KS、QS、KKᵀ、QKᵀ）分组前置连续执行，保持输入常驻 L0 复用后再释放工作空间给求逆。

- **核心技术三：数据流感知的布局转换规划（§6）**
  - 将布局规划形式化为离散代价最小化问题：π* = arg min_π [T_exec(π) + T_transform(π)]，其中 T_exec 为布局相关执行代价、T_transform 为转换开销。
  - 该问题本质是 **Partitioned Boolean Quadratic Programming（PBQP）**，NP 难；N_c 个 chunk、每 chunk m 种布局时搜索空间达 2^(m·N_c)，随序列长度线性膨胀而不可枚举。
  - **三重剪枝**：
    1. **跨 chunk 解耦**：仅循环状态跨越 chunk 边界，故 chunk 内布局决策完全隔离，只保留有限状态布局组合下的最小 chunk 内代价；
    2. **分支锚定**：LA 分支共享张量必然作为下游矩阵单元操作数，而矩阵单元强制 Blocked 布局，可作为确定性锚点，将组合搜索降为一次性确定性转换评估；
    3. **向量链合并**：对保形向量链，Dense 布局下各向量算子不更慢，故 all-Dense（边界转换）与 all-Blocked 二者代价相当，只需评估两种候选。
  - 剪枝后全局优化退化为**动态规划**：D_i(s) = min_p [D_{i−1}(p) + c_i(p, s)]，按拓扑序求值；chunk 边界处布局状态 s 仅保留循环状态布局，复杂度降为 **O(N_c)** 线性。
  - **全局计划生成**：DP 前向传播记录最优前驱状态，回溯分配所有张量的精确物理布局与转换插入点，离线产出静态、确定性的执行计划，完全消除运行时布局调度开销。

- **实现要点**：约 13K 行 C/C++ 的 kernel 级 drop-in 替换，通过 torch_npu 绑定集成进 vLLM-Ascend；对输入/输出投影做算子融合与卷积元数据复用（较原生 vLLM-Ascend 提速 1.62×）；跨 GEMM 共享固定形状 Cube 例程以降低 I-cache 压力。

- **峰值内存**：随序列长度从 128 增长到 64K token，HA-NPU 的状态与中间张量内存保持近似常数级增长曲线，较 FLA 降低 **1.9–2.4×**，验证了 State-First 重排序与头级融合对状态内存翻倍问题的消除。

- **消融实验**：三项技术贡献具有累加性——头级映射与跨算子融合贡献最大（约占总提速的 55%–65%），寿命感知重排序次之（约 20%–25%），布局转换规划最小但稳定（约 10%–15%）；单独任一技术都无法达到完整系统的效果，说明三者分别针对核心级、算子级、张量级的错配，缺一不可。
- **精度验证**：360 个 GDN 实例相对 CPU FP64 参考的 NMSE 保持在 **10⁻⁷ 量级**（FP32 累加下的正常误差范围）；HotpotQA 与 TriviaQA 上 F1 与原生 vLLM-Ascend 后端差异在 **±0.3%** 以内，说明数据流重组未改变数值语义。

## 7. 局限性

- **算法层未触及**：系统明确以"不修改底层注意力算法"为约束，因此未探索 LA 算子本身的近似（如低秩状态压缩、门控量化），其收益上限受算法固有计算量限制。
- **硬件覆盖偏窄**：仅验证 Ascend 310P/310B 两类边缘 NPU，未涉及 GPU、其他厂商 NPU（如高通 Hexagon、瑞芯微）或其他 Ascend 型号，跨架构泛化性存疑。
- **解码阶段未优化**：端到端收益集中在 prefill，decode 沿用原生后端；而实际边缘部署中 decode 往往占主导延迟，本文未给出 decode 路径的对应优化方案。
- **基线移植偏差**：FLA 与 FlashQLA 的 NPU 版本为作者自行移植，FlashQLA 的 KDA 版本更是扩展实现，对比结果可能受移植质量影响，绝对倍数需谨慎解读。
- **头数假设**：头级映射的有效性依赖"头数 ≥ 核数"这一前提；对头数极少（如 4–8 头）或核数极多（如 64+ 核）的场景，三级调度的尾部处理与列切分开销可能上升，文中未做敏感性分析。
- **静态计划限制**：布局计划离线生成、运行时静态固定，对动态变化的输入分布（如变长 batch、多请求混跑）的适应性未讨论。

## 8. 对后续研究的启发

- **"算子级乱序"作为通用优化范式**：本文把处理器乱序执行思想迁移到算子调度层，利用部分依赖实现状态原地覆盖，这一思路可推广到其他具有循环状态或流水线依赖的序列模型（如 SSM、RWKV、线性 RNN）。
- **布局规划的形式化与剪枝**：将布局选择建模为 PBQP 并用三重剪枝退化为 O(N_c) 动态规划，为编译器中"布局-执行联合优化"提供了可复用的方法论。
- **头级 vs chunk 级并行**：指出边缘 NPU 上"并行度够用即止"，chunk 级并行只增同步开销，这对所有面向低核数设备的 kernel 设计都有参考价值。
- **潜在方向**：(i) 将同样思路扩展到 decode 阶段与 KV/状态压缩；(ii) 与算法层的 LA 近似结合，突破"不改算法"的收益天花板；(iii) 把布局规划推广到跨层、跨模型的全局编译优化；(iv) 探索对动态输入的自适应重规划。

## 9. 总体评价

- **贡献定位**：HA-NPU 是首个面向边缘 NPU 的混合注意力 LLM 推理系统，其价值不仅在于具体提速数字，更在于系统性地揭示了"算法高效 ≠ 硬件高效"这一常被忽视的落差，并把落差精确归因到核心、算子、张量三个层级。
- **方法论质量**：从 profiling 出发定位根因，再到抽象为 Map–Reduce–Map 范式、逐层提出对应技术、最后用消融量化贡献，逻辑链条完整且自洽；根因分析中的量化数据（GM 访问 56.2%、流量膨胀 93.4%、布局转换 41.58%）为设计决策提供了直接依据。
- **工程价值**：约 13K 行 C/C++ 的 kernel 级 drop-in 替换、集成进 vLLM-Ascend，具备实际部署可行性，而非仅停留在仿真或原型。
- **主要保留意见**：端到端收益仅覆盖 prefill、基线为自行移植、硬件与头数覆盖有限，这些因素使论文宣称的倍数在更广泛场景下需打折看待；此外"不改算法"的自我约束在提升可比性的同时也限制了优化空间。
- **综合判断**：在"边缘设备上高效运行混合注意力 LLM"这一具体而重要的问题上，本文给出了扎实、可复现、工程落地的系统性解法，是该方向值得参考的基线工作；其"数据流局部性优先于序列并行度"的核心洞察，可能比具体实现具有更长的生命力。
