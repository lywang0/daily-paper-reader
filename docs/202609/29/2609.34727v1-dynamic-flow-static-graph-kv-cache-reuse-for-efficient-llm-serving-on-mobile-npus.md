## 摘要
端侧大语言模型（LLM）服务是本地优先个人智能的基石，为用户提供数据主权、强隐私保障，并摆脱云端 API 的延迟和成本。尽管 KV 缓存被广泛用于降低长上下文推理的延迟，但现有设计主要针对具有动态执行环境和充足内存带宽的云端 GPU 进行优化。这些架构假设在移动 NPU 上并不成立：在移动 NPU 上，计算图必须静态编译，且内存容量和 I/O 带宽都受到严重限制。在这项工作中，我们提出了一种面向移动端的计算-存储协同设计，用于前缀和非前缀 KV 复用。我们首先提出一种图内机制，将选择性 KV 重计算映射到静态 NPU 图上，从而调和算法的动态性与 NPU 的静态性。我们进一步开发了一种图间调度器，利用动态规划优化块合并并最小化填充。为解决移动端带宽限制，我们引入了一种分层 KV 管理器，具有树-哈希-语义混合结构，以及成本感知的预取和淘汰策略。我们还构建了一个二维流水线，将 KV 加载、重旋转和存储与 NPU 执行重叠，从而隐藏数据移动延迟。在代表性端侧工作负载和 LLM 上的实验表明，与无复用和仅前缀缓存相比，我们的设计将首 token 时间（TTFT）降低了 40-60%。

## Abstract
On-device large language model (LLM) serving is a cornerstone of local-first personal intelligence, offering users data sovereignty, strong privacy guarantees, and freedom from cloud API latency and cost. Although KV caching is widely used to reduce latency in long-context inference, existing designs were primarily optimized for cloud GPUs with dynamic execution environments and abundant memory bandwidth. These architectural assumptions do not hold on mobile NPUs, where computation graphs must be statically compiled and both memory capacity and I/O bandwidth are severely constrained. In this work, we present a compute-storage co-design for mobile-centric prefix and non-prefix KV reuse. We first propose an intra-graph mechanism that maps selective KV recomputation onto static NPU graphs, reconciling algorithmic dynamicity with NPU staticity. We further develop an inter-graph scheduler to optimize chunk merging and minimize padding with dynamic programming. To address mobile bandwidth limitations, we introduce a hierarchical KV manager featuring a tree-hash-semantic hybrid structure, along with cost-aware prefetching and eviction policies. We also build a two-dimensional pipeline that overlaps KV loading, rerotation, and storage with NPU execution, hiding data-movement latency. Experiments across representative on-device workloads and LLMs show that our design reduces time-to-first-token (TTFT) by $40-60\%$ compared with no reuse and prefix-only caching.

## 2. 方法论：核心思想与关键技术

- **总体思想**：计算-存储协同设计，把动态 KV 复用算法适配到移动 NPU 的静态、量化执行模型，并同时优化分层 KV 存储、预取淘汰和流水线重叠。

- **图内设计：动态重计算映射到静态 NPU 图**
  - 将非前缀 token 切块为固定大小，不足则 padding。
  - 使用 valid mask 排除 padding token，防止其被 Top-K 选中；同时强制最后一个 token 被选中，保证 logits 正确。
  - 通过 scatter-gather 将高 KV 偏差 token 的重算结果写回复用 KV cache。
  - 图大小优化：根据代表性工作负载的 token 长度频率，最小化期望延迟，选择最优 prefill 图大小 \(L_P\) 和选择性重计算图大小 \(L_S\)；限制为 32 的倍数，实验中 \(L_P=128\)、\(L_S=512\)。
  - 混合精度：权重 INT4、激活 UINT16、KV INT8（SpinQuant + Hadamard），但 KV 偏差计算和 Top-K 比较使用 FP16；用 \(1/\sqrt{D_{head}}\) 缩放防止 FP16 溢出。

- **图间设计：动态复用模式调度**
  - 输入 prompt 中前缀复用、非前缀复用、新 token 可能交错出现，朴素调度会造成填充浪费。
  - 关键观察：新 token 总会被重计算，因此可安全合并进相邻的选择性重计算图。
  - 用动态规划求最小延迟：
    \[
    T[i]=\min\{T[i-l_s(i)]+t_s,\ T[i-l_p(i)]+t_p\}
    \]
    其中 \(l_s(i)\) 是可放入一次选择性重计算图的最长有效后缀，\(l_p(i)\) 是可放入一次 prefill 图的最长有效后缀；合并新 token 时需满足最小重计算比 \(r\)。
  - 该 DP 全局决定每个尾块由重计算图还是 prefill 图处理，减少图调用和 padding。

- **分层 KV 存储管理**
  - **NPU KV Manager**：管理 CPU-NPU 共享缓冲区中的固定上下文长度 KV buffer，约 10^1 MB。
  - **CPU KV Memory Pool**：约 10^2 MB，基于轻量 hash 表索引 KV chunk，缓存新生成或预取的 KV。
  - **Flash KV DB**：基于 SQLite 元数据 + 外部文件系统存储 KV tensor，避免大 BLOB 碎片化。
  - **树-哈希-语义混合结构**：前缀树支持前缀复用；64-bit hash 支持相同非前缀 chunk 查找；语义索引（关键词稀疏向量 + 截断稠密向量）支持非完全相同的候选 chunk；线性时间 LCS / 后缀自动机定位可复用子串。

- **成本感知预取与淘汰**
  - 局部性评分：
    \[
    R(c_i)=w_sR_s(c_i)+w_tR_t(c_i)+w_mR_m(c_i)
    \]
    分别表示空间、时间、语义局部性。
  - 淘汰按 \(R(c)\cdot C(c)\) 排序，优先保留高复用概率且恢复成本高的 chunk。
  - Flash 淘汰成本考虑重计算成本和破坏前缀链的级联成本：
    \[
    C_{flash}(c_i)=Latency_P(|c_i|)+C_{cascade}(c_i)
    \]
    避免淘汰前缀链中间节点导致后续 chunk 失去前缀复用资格。
