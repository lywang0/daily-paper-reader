## 摘要
SymbolicLight V2 在一种混合神经形态语言架构中将稀疏事件计算与连续状态处理相结合。它扩展了 V1 的脉冲门控双路径，在后续投影中加入分级带符号事件，并采用无 softmax 的局部注意力。我们在 Alveo U50C FPGA 上使用数字定点运算、在 ARM CPU 上使用稀疏整数执行，实现了该 194M 参数模型。在 175 MHz 下的三种同一检查点 FPGA 实现中，活跃行权重收集与有效状态 KV 加载将 32-token 前缀和 128 个输出下的解码吞吐量从 474.6 提升至 643.2 tokens/s。估计的整卡总能耗从每生成 token 0.06087 J 降至 0.04407 J，降低 27.6%。包括预填充在内的完整请求能耗在三种前缀长度下降低 24.4–27.7%。一项独立的空闲拆分将 82.8% 的整卡总能耗归因于带载空闲，这解释了更短 token 延迟带来的收益。与记录的 RTX 5090 编译 FP32 基线相比，整数 FPGA 执行在短上下文解码期间使用的估计整卡能耗少 89.1%；算术精度不同，且 GPU 基线并非所测试的最低能耗配置。在 ROCK 5T 的四个 Cortex-A76 核心上，完整请求在适配器交流输入处达到 65.4 tokens/s，功耗为 9.80 W，每生成 token 为 0.151 J。这些结果将事件稀疏性与省略的计算和数据移动联系起来。这些机制也支持其他专用 V2 实现：以比有功功率更大的倍数提高吞吐量，可降低每生成 token 的能耗。评估保持部署检查点固定；其质量落后于同等预算的稠密对照，因此这些结果并不能确立同等质量下的效率。

## Abstract
SymbolicLight V2 combines sparse event computation with continuous-state processing in a hybrid neuromorphic language architecture. Extending V1's spike-gated dual paths, it adds graded signed events at further projections and softmax-free local attention. We implement the 194M-parameter model on an Alveo U50C FPGA using digital fixed-point arithmetic and on an ARM CPU using sparse integer execution. Across three same-checkpoint FPGA implementations at 175 MHz, active-row weight gathering and valid-state KV loading raise decode throughput from 474.6 to 643.2 tokens/s for a 32-token prefix and 128 outputs. Estimated gross card energy falls from 0.06087 to 0.04407 J per generated token, a 27.6% reduction. Complete-request energy, including prefill, falls by 24.4-27.7% across three prefix lengths. An independent idle split attributes 82.8% of gross card energy to loaded idle, explaining the benefit of shorter token latency. Against the recorded RTX 5090 compiled-FP32 baseline, integer FPGA execution uses 89.1% less estimated card energy during short-context decode; arithmetic precisions differ, and the GPU baseline is not the lowest-energy tested configuration. On four Cortex-A76 cores of a ROCK 5T, complete requests reach 65.4 tokens/s at 9.80 W and 0.151 J per generated token at the adapter's AC input. These results connect event sparsity to omitted computation and data movement. The mechanisms also support other dedicated V2 implementations: increasing throughput by a greater factor than active power lowers energy per generated token. Evaluation holds the deployed checkpoint fixed; its quality trails a same-budget dense control, so the results do not establish equal-quality efficiency.

## 1. 核心问题与整体含义

- **研究动机**：激活稀疏性只有在执行系统真正跳过相应算术运算与内存访问时才能降低推理能耗。SymbolicLight V1 虽然以稀疏激活训练，但其稠密 GPU 实现仍为大量零值付出了计算与访存代价。
- **核心问题**：如何让"事件稀疏性"从训练属性转化为**可执行的**计算与数据移动省略，从而在语言推理中实现真实的低能耗。
- **整体含义**：论文提出 V2 混合神经形态语言架构，将稀疏事件计算与连续状态处理结合，并在 FPGA 与 ARM CPU 上落地为端到端定点/整数推理原型，把事件稀疏性与省略的运算、权重读取、KV 状态传输直接关联，为低能耗语言推理提供可落地的专用实现路径。

## 2. 方法论

### 核心思想
- **混合神经形态**：稀疏事件（二值脉冲 + 分级带符号事件）负责**选择**投影贡献；连续残差流、循环衰减状态与局部注意力负责携带时序与特征信息。
- 并非纯事件驱动 SNN：归一化、注意力输出投影、输出头仍为连续值（部署时用定点表示）。

### 关键技术细节
- **分级带符号事件编码**（式1）：`e_θ(x) = 1[|x|≥θ]·clip(round(x/θ), −L, L)`，零值表示无事件，非零整数携带符号与幅值；训练用直通估计器，代理导数 `∂e/∂x = 1/θ`。
- **事件消费投影**（式2）：`y = Σ_{j∈A(e)} e_j W_{:,j}`，活跃集 `A(e)` 只选择非零输入对应的权重列（硬件存 `Wᵀ`，即按行取）。节省来自省略的贡献与权重搬运，而非把每个事件当作纯加法。
- **事件位置**：V2 在 FFN 上投影输入与 Q/K/V 输入新增编码器；衰减投影与 FFN 下投影保留 V1 的二值脉冲输入。
- **事件注意力**（式4-5）：ReLU–L1 归一化替代 softmax，避免指数运算；使用 ALiBi 线性位置偏置替代旋转位置编码；可见集为局部窗口（训练 w=256，部署 w=475，480 KV 槽环形缓冲）+ 前 4 个全局锚点。
- **双路径与残差**（式3, 6-7）：衰减状态 `h = α⊙h_{t-1} + (1−α)⊙z`；融合 `u = LN₁(c + W_O[g·o + (1−g)h])`；FFN 为 `c' = LN₂(u + W_down·H(W_up·e_θ(u) − τ))`，`s' = H(c'−τ)`。

### 硬件执行
- **ARM（RK3588, 4×Cortex-A76）**：INT8 权重，NEON 整数 MAC，事件投影仅遍历非零贡献。
- **FPGA（Alveo U50C, 175 MHz）**：INT8 权重、定点激活/KV、宽累加器、确定性重量化；权重常驻 HBM，设备自主生成 token。
- **三级实现演进**：驻留稠密（枚举全权重行）→ 稀疏收集（按活跃事件索引只取贡献行）→ 部分 KV（环形缓冲未满时只加载已填充状态）。

### 能耗分解（式8）
`E_gross = P_idle/R + (P_active − P_idle)/R = E_idle_share + E_incremental`，将平台空闲基线与活跃增量分摊到每个 token。

## 6. 主要结论与发现

- **吞吐与能耗提升（同检查点）**：p32/n128 解码吞吐 474.6 → 643.2 tok/s（+35.5%）；估计毛解码能耗 0.06087 → 0.04407 J/token（−27.6%）；完整请求能耗降低 24.4–27.7%。
- **空闲占比**：独立拆分显示 **82.8%** 的整卡毛能耗为带载空闲份额（23.62 W 空闲 vs 28.53 W 活跃），因此更短 token 延迟直接降低每 token 平台能耗。

- **FPGA vs GPU**：相比记录的 RTX 5090 编译 FP32，短上下文解码估计少用 89.1% 整卡能耗（1.58× 吞吐）；但精度不同、传感器未校准。
- **设计原则（式12）**：若吞吐提升倍数大于活跃功率变化倍数（`R_H/R_B > P_H/P_B`），则可同时实现更快生成与更低单 token 能耗。
- **质量结论**：部署检查点 PPL 14.75，比同预算稠密对照 12.50 高约 18%，程序化精度下降 20.05 个百分点，**未通过预设质量门槛**，故**未建立等质量效率**。

## 7. 优点

- **问题定位精准**：把"稀疏激活"与"实际省略的计算/访存"直接挂钩，指出 V1 稀疏训练但稠密执行的矛盾。
- **架构与执行协同设计**：分级带符号事件、ReLU–L1 事件注意力、ALiBi 位置偏置均针对定点/整数事件向量友好，避免旋转与指数运算。
- **同检查点实现演进**：固定权重对比驻留稠密 / 稀疏收集 / 部分 KV，清晰区分权重读取省略与 KV 传输省略两类机制。
- **测量严谨**：明确区分 AC 积分与 DC 卡级估计、仿真流量与实测能耗、预填充与解码吞吐；报告轮间离散度与热条件。
- **诚实的边界声明**：反复强调不等价比较、未隔离热效应、不构成 ASIC 能耗投影、不建立等质量效率。
- **可迁移设计原则**：式12 给出跨硬件移植的定量条件，具有工程指导意义。

## 8. 不足与局限

- **质量短板**：部署检查点落后于同预算稠密对照（PPL +18%，程序化精度低于四选一随机水平），无法证明等质量下的能效优势。
- **消融不彻底**：无同一比特流的稀疏开/关对照；未隔离每个硬件改动与热效应；FPGA 增量能耗不能作为 ASIC 投影。
- **测量边界不一致**：FPGA/GPU 为卡级传感器估计（排除主机与供电损耗），ARM 为 AC 输入（含适配器与预填充）；两传感器未交叉校准，热条件不同。
- **跨设备比较受限**：同板六路径模型、tokenizer、量化格式、运行时均不同，仅能定位为"部署基准"而非隔离稀疏执行效应。
- **功能覆盖有限**：仅贪婪解码、单序列、有限 KV 环形缓冲；连续多 token 模式因状态故障禁用早停；不支持片上非贪婪采样与完整 logits 读出；预填充逐 token 处理，长上下文吞吐下降明显。
- **训练算力信息缺失**：未报告训练 GPU 型号、数量与时长，影响复现与成本评估。
- **应用限制**：ARM 实现仅在短请求上具竞争力，p256 时能耗高于 NPU 路径与 LFM CPU。
