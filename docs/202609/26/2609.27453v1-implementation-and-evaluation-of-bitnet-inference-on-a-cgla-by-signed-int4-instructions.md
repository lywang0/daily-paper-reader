## 摘要
大语言模型（LLM）推理每生成一个 token 都要传输模型权重和激活值，使内存流量及其能耗成为解码路径的一部分。BitNet b1.58 使用三值表示其低位权重，并使用整数激活。然而，该运算与传统的 int8 或浮点通用矩阵乘法不匹配，现有 BitNet 加速器在专用数据通路中实现该运算。我们转而将该运算映射到 CPU-Grounded Linear Array（CGLA），这是一种可编程 ASIC，具有显式直接内存访问、本地存储器和可复用的编译器可见整数通道。该映射添加了 OP_SMA4 作为可复用的有符号 int4 乘累加指令，而不是仅用于 BitNet 的数据通路。每个三值权重占用一个有符号 4 位通道。每个 int8 激活被拆分为两个有符号 int4 片段，并通过移位加法重建。将 145 MHz FPGA 测量结果按频率缩放到 840 MHz 28 nm CGLA，实现了每个有符号 int4 乘积 0.390 ns。我们表明，卸载到 CGLA 的 BitNet C++ 执行测得 2.52 tokens/s。

## Abstract
Large language model (LLM) inference transfers model weights and activations for every generated token, making memory traffic and its energy cost part of the decode path. BitNet b1.58 represents its low-bit weights by ternary values and uses integer activations. However, this arithmetic does not match conventional int8 or floating-point general matrix multiplication, and existing BitNet accelerators implement it in specialized datapaths. We instead map this operation to a CPU-Grounded Linear Array (CGLA), a programmable ASIC with explicit direct memory access, local memories, and reusable compiler-visible integer lanes. The mapping adds OP_SMA4 as a reusable signed-int4 multiply-accumulate instruction rather than a BitNet-only datapath. Each ternary weight occupies one signed 4-bit lane. Each int8 activation is split into two signed-int4 fragments and reconstructed by shift-and-add. Frequency scaling of the 145 MHz FPGA measurement to an 840 MHz 28 nm CGLA achieved 0.390 ns per signed-int4 product. We showed that CGLA-offloaded BitNet C++ execution measures 2.52 tokens/s.

## 1. 核心问题与整体含义

- **背景**：LLM 以自回归方式在 GPU 上服务，每生成一个 token 都要重新遍历全部权重与激活，导致内存带宽与访存能耗成为解码路径的关键瓶颈，解码延迟/能耗不仅取决于峰值算力，也取决于访存带宽与访存能耗。
- **BitNet b1.58 的特殊性**：其权重为三值 w ∈ {−1, 0, +1}，激活为 8 位整数，核心算子仍是权重-激活点积，但**算术形态与常规 int8 或浮点 GEMM 不匹配**。
- **现有做法的局限**：BitNet 专用加速器（TeLLMe、TerEffic、VitaLLM、BitROM、LUT 类生成器等）普遍采用**专用数据通路**，为单一算子定制硬件，牺牲了通用可编程性。
- **本文目标**：不新增 BitNet 专用通路，而是把三值–int8 点积映射到**可编程 ASIC——CPU-Grounded Linear Array（CGLA）**上。CGLA 具备显式 DMA、本地存储（LMM）分级暂存、编译器可见的可复用整数通道，并向编译器呈现"有序逻辑行"，无需二维布局布线搜索。
- **整体含义**：验证"通用可编程空间架构 + 一条可复用低比特指令"能否高效承载 BitNet 推理，为低比特 LLM 的软硬件协同提供**通用化、可复用**的路径，而非一次性定制加速器。

## 2. 方法论

### 2.1 核心思想
- 复用 CGLA 已有的 DMA/LMM/同步/行调度通路，仅在**软件可见指令集**中新增一条可复用的**有符号 int4 乘累加指令 OP_SMA4**（替代原有的 int8 版本 OP_SMA8）。
- 原有 OP_SMA8 会给每个三值权重分配 8 位字段，而三值只需 log₂3 ≈ 1.58 位，存在浪费；改为 int4 后每个 32 位通道可容纳 8 个乘积。
- BitNet 专有处理被限制在**操作数打包**与**输出 drain 后的重建**两个环节，指令本身对任意有符号 int4 操作数通用（也支持非三值点积）。

### 2.2 指令定义
- 对操作数宽度 p，每个 32 位通道含 32/p 个有符号字段；一条 64 位指令含两条通道 ℓ ∈ {0,1}。
- 累加公式：d′_ℓ = d_ℓ + Σ_{j=0}^{32/p−1} sext_p(x_{ℓ,j}) · sext_p(z_{ℓ,j})，其中 sext_p 把 p 位字段按二进制补码符号扩展后累加。
- OP_SMA4 取 p = 4，每通道累加 8 个有符号 int4 乘积，两通道独立更新。

### 2.3 三值权重 × int8 激活的两流分解
- 每个三值权重直接放入一个 signed int4 通道。
- 将 int8 激活拆分：a = 16·a_hi + a_lo
  - a_lo：符号扩展的低半字节残差，∈ [−8, 7]
  - a_hi = (a − a_lo)/16：调整后的高片段
- 当 −128 ≤ a ≤ 119 时，两个片段都能落入 signed int4 范围，两条 OP_SMA4 流可**精确**重建原始 int8 激活的点积。
- **边界修正**：a ∈ [120, 127] 时 a_hi = 8 无法表示，被编码为 −8，使重建乘积少 256w；主机侧做稀疏修正 c = 256 · Σ_{i: a_i ∈ [120,127]} w_i。
- 重建公式：y = 16·s_hi + s_lo + c（s_hi、s_lo 为两条流的 32 位整数部分和），重建结果是 32 位整数点积而非 8 位输出。
- **融合变体**：在阵列内先形成 s_lo + 16·s_hi 再输出（行 5 归约通道半部、行 6 左移高位和、行 7 相加、行 63 存回，共 64 行跨度），从而减半输出搬运量；非融合变体则把两个和分别传回主机再做移位加法。

### 2.4 主机–CGLA 执行流程
1. 主机在 DMA 可见缓冲区准备三值权重、低片段、编码高片段及修正量 c；
2. DMA 把操作数 tile 从 /dev/mem 暴露的可缓存 DDR 路径搬入 LMM；
3. 生成的 CGLA 行调度在 PE 行上执行有符号点积；
4. 32 位部分和 drain 到主机可见缓冲区；
5. 主机做修正、按 q8 激活块 scale 与 I2_S 权重块 scale 缩放并累加，回到 BitNet C++ 层。
- 单层超过 LMM 容量时按 tile 切分，每个 tile 重复 staging/执行/drain，各 tile 部分和累加为同一层输出。
- 报告的 CGLA 时间包含 DMA staging + 行执行 + drain，而非仅算术延迟。

### 2.5 对照基线（仅激活量化的单流 int4）
- 用一条 OP_SMA4 流、把 int8 激活块量化为单个 signed int4 块 q₄，产生**近似**点积；权重、指令、调用边界完全一致，只改激活表示与主机重建。
- 四种标度方案：Max-abs（s = max|a|/7）、Power-of-two（就近取 2 的幂）、非对称仿射（s = (a_max−a_min)/15，含零点 z 与 clip）、Activation-MSE 搜索（在 0.5–2.0 倍 max-abs 之间试 10 个标度，选激活重建 MSE 最小者）。
- 所有基线在调用前仅依据激活块确定量化参数，不使用权重、CGLA 输出或精确点积。
