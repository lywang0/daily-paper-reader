## 摘要
我们提出 IronLLM-0.6B，一个 654M 参数的语言模型，专为高效端侧推理而设计。IronLLM-0.6B 将混合注意力架构与 X-MTP 相结合；X-MTP 是一种轻量级共享 KV 的多 token 预测设计，消除了逐深度的 KV 缓存重放，并采用轻量级验证头实现无回滚草稿生成，从而实现 1.48 倍解码加速。该模型使用面向质量的数据流水线在约 6.2 万亿 token 上进行预训练，并通过多领域同策略蒸馏进行进一步后训练，以整合领域专用教师模型的能力。为更好地满足端侧场景的低延迟需求，IronLLM-0.6B 采用 Instruct-Only 设计。评估表明，相较于 Qwen3.5-0.8B 和 MiniCPM5-1B 等更大模型，IronLLM-0.6B 取得了有竞争力的性能，同时在许多任务上生成更简洁的回复。我们进一步提出 IronLLM-0.6B-Light，它用 Dynamic Tanh 替换 RMSNorm，并简化了若干计算开销较大的组件，以提高推理和量化效率。总之，IronLLM 系列模型为资源受限部署提供了有效的性能-效率权衡。

## Abstract
We present IronLLM-0.6B, a 654M-parameter language model designed for efficient on-device inference. IronLLM-0.6B combines a hybrid attention architecture with X-MTP, a lightweight shared-KV multi-token prediction design that eliminates per-depth KV-cache replay and employs a lightweight verification head for rollback-free drafting, achieving a 1.48x decoding speedup. The model is pretrained on approximately 6.2 trillion tokens using a quality-oriented data pipeline and is further post-trained with Multi-Domain On-Policy Distillation to integrate capabilities from domain-specialized teachers. To better meet the low-latency requirements of on-device scenarios, IronLLM-0.6B adopts an Instruct-Only design. Evaluations show that IronLLM-0.6B achieves competitive performance relative to larger models such as Qwen3.5-0.8B and MiniCPM5-1B, while producing more concise responses on many tasks. We further present IronLLM-0.6B-Light, which replaces RMSNorm with Dynamic Tanh and simplifies several computationally expensive components to improve inference and quantization efficiency. Together, the IronLLM models provide an effective performance-efficiency trade-off for resource-constrained deployment.

## 2. 方法论：核心思想与关键技术细节

### 2.1 混合注意力主干（IronLLM-0.6B）

- **架构**：24 层 decoder-only Transformer，隐藏维度 1024，FFN 中间维度 3584，总参数 654M；embedding 与 LM Head 权重绑定。
- **混合注意力**：Gated DeltaNet（GDN）线性注意力层与全局注意力（GA）层按 **3:1** 交错分布（18 层 GDN + 6 层 GA）。
  - GDN 层：对投影后的 Q/K/V 施加短因果卷积捕捉局部混合，Q/K 做 ℓ2 归一化；维护固定尺寸循环状态 `S_t ∈ R^{d×d}`，用门控 delta 规则更新（状态衰减门 α_t、写入强度门 β_t 均为输入相关），并有输出门补偿 softmax 归一化的缺失。
  - GA 层：标准 GQA（8 个 Q 头 / 2 个 KV 头，头维 256）+ QK-Norm + Partial RoPE（仅作用于头维前 64 通道），保证长程检索精度。
- **训练稳定性设计**：
  - **Zero-RMSNorm**：可学习增益 γ 初始化为 **0**（而非传统 RMSNorm 的 1），避免系统性尺度漂移。
  - 线性层与全局注意力层均使用输出门控，抑制 attention/residual sink。
- **Tokenizer**：采用 Qwen3 tokenizer（词表 152K），相比 Qwen3.5 tokenizer 节省约 100M 参数（对端侧小模型至关重要）。

### 2.2 X-MTP：轻量共享 KV 多 token 预测

- **标准 MTP 的问题**：每个预测深度使用独立 MTP 块，训练时依赖 teacher forcing 的真实未来 token，推理时依赖前序草稿 token，存在 train–inference 分布偏移，误差沿链传播；且 K 个深度需 K 套 Q/K/V 投影与 K 份 KV 缓存。
- **X-MTP 设计（跨步参数与 KV 共享）**：
  1. **参数共享**：用单个 MTP 块 `D_θ` 在所有深度循环复用（embedding 归一化、隐状态归一化、融合投影、注意力、FFN、输出归一化全部共享）。
  2. **首步 KV 共享**：仅在第 1 个 MTP 深度构建静态 KV bank（`K̄ = RoPE(W_K Z̃^(1))`, `V̄ = W_V Z̃^(1)`）；后续深度**只计算自己的 query**，复用同一份首深度因果记忆，不再执行 W_K/W_V 投影，也不追加缓存条目。
  - 效果：辅助参数开销约降为 1/K；K/V 投影与缓存成本从 K(C_Q+C_K+C_V) 与 K·M_KV 降为 KC_Q+C_K+C_V 与 M_KV。
  - 参数对比：单 MTP 块仅 **20.45M**（约主模型 653.70M 的 3.1%）；K=3 时标准 MTP 总参数 715.05M，共享 KV 版仅 **674.15M**。
- **推理期缓存管理**：主干缓存与共享 MTP 缓存分离；只有第 1 深度对"已提交"token 追加 K/V，更深层只读——被拒绝的草稿 token 永不污染共享缓存，因此**无需逐深度缓存重放**。

### 2.3 轻量验证头（无回滚草稿）

- **动机**：传统草稿调度必须跑完所有 K 个深度（含代价最高的词表级输出投影）才能验证，前缀接受会丢弃首个拒绝之后的全部计算；同时 GDN 的固定尺寸循环状态与卷积状态无法像 softmax 注意力那样通过截断 KV 缓存回滚，精确回滚需重跑前缀或快照/恢复状态。
- **设计**：每个 MTP 深度后接一个**两层 MLP**（跨深度共享参数），输入为该深度的融合输入状态 `z^(k)_t` 与输出隐状态 `h^(k)_t`（分别归一化后拼接），输出标量置信度 `c^(k)_t ∈ (0,1)`，即草稿被主干接受的预测概率。开销仅 **2.10M 参数（约主干 0.32%）**，与 K 无关。
- **置信度门控草稿**：每个深度设阈值 τ_k，用**联合置信度** `C^(k)_t = ∏_{j≤k} c^(j)_t` 决策——不满足则立即终止草稿，后续深度完全不执行。因各因子 ∈(0,1)，C^(k) 单调非增，近似"整个长度为 k 的草稿前缀全对"的概率，防止局部可信的深度延长已衰减的前缀。
- **收益**：接受与否在主干前向之前就确定，主干前向只覆盖已提交前缀，被拒草稿不进入主干 KV 缓存、GDN 循环/卷积状态与共享 MTP 缓存，**彻底消除回滚、重放与状态快照需求**。
- **训练策略（两阶段，参照 PIPO）**：
  - 头为纯辅助回归器，输入隐状态与回归目标均 detach，梯度不扰动主干与 MTP 块（行为保持）。
  - **Stage I（SFT，概率匹配）**：以 MTP 头对 ground-truth 续写的概率 `sg[p^(k)_t(x_{t+k+1})]` 为监督目标，信号稠密且几乎零成本。
  - **Stage II（OPD，接受匹配）**：草稿由 MTP 链自身生成，以教师分布充当验证器，目标为 `sg[min{1, p_tea(ŷ)/p^(k)(ŷ)}]`。

### 2.4 IronLLM-0.6B-Light：面向极致的结构精简

- **核心哲学**：系统性识别并简化计算开销大或不利于量化部署的模块。
- **DyT（Dynamic Tanh）替代全部 RMSNorm**：`DyT(x)=γ⊙tanh(αx)+β`，消除 RMS 统计量计算；同时移除 QK-Norm（功能被 DyT 覆盖）。
- **ReLUx**：可学习上界 ReLU，`ReLUx(x)=min(max(0,x), θ)`，提升量化下数值稳定性。
- **可学习 embedding 缩放**：`e'_t = γ_emb · e_t`，γ_emb 初始化为 √d_model，改善收敛与训练稳定性。
- **门控与核模块简化**：
  - 完全移除全注意力层的输出门控（0.6B 规模收益可忽略）。
  - 移除 GDN 中因果 Conv1D 后的 SiLU——实验发现 ReLU 风格门控会把大量特征通道压为 0，过度限制紧凑模型的表征容量，**直接去掉激活反而优于替换为 ReLU/ReLUx**。
  - 将 GDN 递推中的遗忘/写入系数从数据相关（需 σ/softplus 与 W_a/W_b 投影）改为**数据无关的 per-head 可学习标量**；衰减 logits 采用 Lightning-Attention 风格斜率初始化与逐层缩放。

### 2.5 数据与训练流程

- **数据流水线**（六环节闭环）：Data Source → Construction（schema 统一、语种识别、元数据抽取、解析归一化）→ Curation（质量打分、改写精炼、合成数据、数据治理、去重）→ Strategy（采样权重、阶段配方、数据混合）→ Training → **Data Flywheel**（评测→能力缺口分析→数据缺口归因→定向数据迭代→配方更新）。
- **污染分析**：IDF 加权 5-gram 重叠检测（污染分数 `s_c = 0.75×stem_idf_overlap + 0.25×aio`）+ 基于 embedding 的语义检索（余弦 >0.8 后由 LLM judge 与人工复核）。
- **三阶段预训练（WSD 学习率）**：
  - Stage 1：4.2T token，通用网页为主（80.5% 通用网页 + 12% 中文网页 + 5% 代码推理 + 2.5% 数学），刻意降采样高专业度内容（arXiv/PDF）。
  - Stage 2：1.0T token，降低网页比例，提升数学/代码，引入少量合成 QA。
  - Stage 3：1.0T token，仅保留最高质量网页子集，继续提高数学/代码/合成数据，学习率线性衰减至 0。
  - 超参：AdamW（β=0.9/0.95，weight decay 0.1 仅作用于二维参数），梯度裁剪 1.0，峰值学习率 4.0e-4（warmup 80B token），全局 batch 1024，序列长度 4096；Stage 3 起启用单 MTP 头（损失权重 0.1）。
  - 其他发现：严格 per-batch 数据配比**未带来提升**（全局 shuffle 的随机性起隐式正则作用），故仅在全局层面控制配比；主预训练阶段不启用 cross-document attention（视为隐式数据增强），但长上下文训练中必须启用；预训练中采用**模型合并**（X_merge）稳定训练，在 GSM8K（+7.51）与 MATH（+5.18）上显著增益。
- **长上下文 mid-training**：两阶段将 4K → 32K（42B token）→ 64K（21B token），RoPE base 在 Stage 1 从 10,000 缩放至 1,000,000 后固定；采用**长度分桶数据混合**与**定向合成长上下文数据**（检索、计数等）。
- **后训练三阶段**：
  1. **General SFT**：数百万条高质量对话样本，数学推理 42.4%、通用 38.3%、代码 10.3%、工具调用 2.3%、其他 6.7%；训练 3 epoch，峰值 lr 8.0e-5，cosine 衰减，loss 仅作用于 assistant 回复 token。
  2. **Domain-Specialist Training**：五个专家（数学、代码、指令遵循、MCQA、开放式 QA），按领域采用 SFT / RL / 二者串行；RL 使用 **GRPO**（组内相对优势估计，无需 value network），配合领域验证器（数学等价性校验、代码执行断言、指令约束打分、选项比对、偏好奖励模型）。
  3. **MOPD（多领域同策略蒸馏）**：解耦"能力生产"与"能力整合"。冻结的领域教师对学生**自生成轨迹**提供 token 级 log-prob，最小化 token 级 reverse KL（用 sampled-token k1 估计器，clip 后转为 detached 蒸馏优势）；同时用领域验证器提供序列级**可验证奖励（VR）**，总目标 `L_total = L_KD + λ_VR·L_VR`。各域采样量均衡。
  - **Light 变体策略**：跳过 Stage 2，直接在 General SFT 后应用 MOPD，复用 IronLLM-0.6B 训练的专家（理由：更高性能上限、两变体分布对齐、迭代效率）。
- **Instruct-Only 设计**：不设 thinking 模式，牺牲部分复杂任务推理上限换取显著更短的输出与更低时延。
