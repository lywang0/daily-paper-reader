## 摘要
专家混合（MoE）模型是一种极具吸引力的架构，可用于扩展模型容量，因而尤其适合部署在资源受限的单 GPU 系统上。然而，这一优势难以实现，因为专家参数主导了内存占用，而 token 级路由是动态、不可预测且倾斜的。先前使用卸载和缓存的工作本质上仍是被动的：系统需等待路由器输出后才移动专家，导致缓存利用率低下，并且在 VRAM 预算紧张时无法将传输与计算重叠。为应对这些挑战，我们提出 Mira，一种算法-系统协同设计，可在单 GPU 上实现高容量 MoE 推理。Mira 通过将预测性专家管理与定制量化格式相结合，从被动转向主动。它引入轻量级逐层预测器，可提前两层预测专家使用情况，从而实现主动预取。这些预测输入一个由 token 级路由遥测管理的两级 HOT+STAGE GPU 缓存，以保留频繁使用的专家，同时暂存预测到的专家。为最小化传输开销，Mira 为专家参数实现了自定义压缩，这减少了元数据并提高了打包效率，同时仅带来极小的精度下降。Mira 实现为一个完全集成的运行时，协调预测器、缓存策略和量化传输，以最大化通信与计算的重叠。我们的实验表明，Mira 减少了专家引发的停顿。与最先进的基线相比，Mira 在内存受限的 GPU 上实现了平均吞吐量 5.71 倍的加速。它将首 token 时间（Time-to-First-Token）加速了 11.71 倍，并在束搜索推理中实现了平均 3.84 倍的加速，证明了其在不同推理场景中的有效性。

## Abstract
Mixture-of-Experts (MoE) models are a compelling architecture for scaling model capacity, making them especially attractive for deployment on resource-constrained, single-GPU systems. However, this benefit is difficult to realize because expert parameters dominate memory, and token-level routing is dynamic, unpredictable, and skewed. Prior work using offloading and caching remains fundamentally reactive, as systems wait for router outputs before moving experts, leading to inefficient cache utilization and an inability to overlap transfers with compute under tight VRAM budgets.   To address these challenges, we propose Mira, an algorithm-system co-design that enables high-capacity MoE inference on a single GPU. Mira shifts from a reactive to a proactive stance by coupling predictive expert management with a tailored quantization format. It introduces lightweight per-layer predictors that anticipate expert usage two layers ahead, enabling proactive prefetching. These predictions feed a two-tier HOT+STAGE GPU cache managed by token-level routing telemetry to retain frequently used experts while staging predicted ones. To minimize transfer overhead, Mira implements a custom compression for expert parameters, which reduces metadata and improves packing efficiency, while minimally degrading accuracy.   Mira is implemented as a fully integrated runtime that coordinates predictors, caching policies, and quantized transfers to maximize overlap between communication and compute. Our experiments show that Mira reduces expert-induced stalls. Compared against state-of-the-art baselines, Mira achieves a 5.71x speedup in average throughput on a memory-constrained GPU. It accelerates Time-to-First-Token by 11.71x and achieves a 3.84$x average speedup in beam search inference, demonstrating its effectiveness across diverse inference scenarios.

## 1. 核心问题与研究动机

- **背景**：大模型本地/单 GPU 推理需求上升（隐私、个性化、可及性），但模型参数规模与消费级 VRAM 之间存在巨大鸿沟；MoE 通过稀疏激活将模型容量与单 token 计算解耦，理论上适合单 GPU 部署。
- **核心矛盾**：
  - MoE 的**专家参数主导内存占用**，而 token 级路由**动态、不可预测且高度倾斜**。
  - 全部专家无法以高精度常驻 GPU，按需从 CPU DRAM 加载又会把 PCIe 延迟放到关键路径上。
- **现有方案的根本缺陷**：
  - 卸载 + 量化 + 通用缓存（LRU/LFU、静态热门专家）本质上是**被动反应式**的——必须等 router 输出后才移动专家，导致缓存利用率低、无法在紧张 VRAM 下重叠传输与计算。
  - 静态缓存（如 Fiddler 固定 pinned 热门专家）假设路由分布稳定，无法适应查询分布漂移、长上下文主题漂移或用户本地负载偏移。
  - 激进低比特量化（INT4/INT3/INT2）虽减小传输量，但精度损失明显，且细粒度分组量化带来的 scale/metadata 开销在 PCIe 迁移中不可忽略。
  - `i→i+1` 的下一层预取在单 batch 交互式解码中重叠窗口不足。

## 2. 方法论：算法-系统协同设计

### 2.1 整体思路
Mira 从"被动"转为"主动"：用**轻量逐层预测器**提前两层预测专家使用，配合**定制 INT8 量化**与**两级 HOT+STAGE GPU 缓存**，通过 token 级路由遥测驱动的**自适应再平衡**，最大化通信与计算重叠。设计目标为模型通用性、单 GPU 效率、自适应自管理。

### 2.2 量化感知专家存储（自定义 INT8）
- 仅对 MoE 专家 FFN（W1 上投影、W2 下投影、W3 门控矩阵）做 INT8 PTQ；非专家层、attention、LayerNorm、LM head 保持 BF16，接口语义与基线完全一致。
- **关键创新：三矩阵共享逐行 scale**。对行索引 r：
  - `α_r = max(‖W1[r,:]‖∞, ‖W3[r,:]‖∞, ‖W2[:,r]‖∞)`
  - `s_r = max(α_r, ε) / 127`
  - W1、W3、W2 均用同一 `s_r` 量化并 clamp 到 [-127, 127]。
- **收益**：标准 per-row INT8 每个矩阵各存一组 scale，而共享 scale 每个专家只需一个 BF16 向量，减少元数据搬运和 CPU→GPU copy 调用次数。scale-only 微基准显示 scale 传输延迟降低 1.64×（Mixtral-8x7B）、1.62×（Mixtral-8x22B）、1.68×（DeepSeek-V2-Lite）。
- **刻意选择 INT8 而非超低比特**：避免 INT3/INT2 的复杂打包、额外反量化元数据与明显精度损失；INT8 简单、硬件可移植、易融合反量化。

### 2.3 HOT+STAGE 两级 GPU 缓存
- 运行时按**字节级预算**管理 GPU 专家内存：先扣除非专家层与 BF16 workspace reserve，剩余按"专家槽位"划分给 HOT 与 STAGE。
- **HOT 区**：长期复用、常驻的 INT8 专家，零 H2D 流量。
- **STAGE 区**：预取窗口，存放预测器判定即将使用的专家，条目短生命周期，目标层过去后即丢弃。
- **两种模式**：大 VRAM 模式下 STAGE 配置宽松、驻留时间长、淘汰不激进，便于观察频率后晋升；小 VRAM 模式下 STAGE 只容纳极少量 `i+2` 预测专家，计算后激进回收，STAGE 满则放弃暂存、回退 CPU 路径。
- 由于小 VRAM 下 HOT 管理至关重要，Mira 用 STAGE 作为"试用区"：只有观察到持续高频访问的专家才被晋升到 HOT，避免 LRU 的"污染 HOT"和 LFU 的"旧热门永不淘汰"问题。

### 2.4 自适应 HOT 再平衡
- 维护 token 级计数：每个专家的**被路由 token 数**与**服务来源层级**（HOT / STAGE / CPU），在滑动窗口内累计，每个再平衡间隔后重置。
- 三类服务路径指标分别量化：缓存利用率（HOT-served）、预测有效性（STAGE-served）、miss 代价（CPU-served）。
- 再平衡三阶段：
  1. **Victim Scoring**：HOT 中窗口内路由量低者得高分，标记待淘汰，并纳入 recency/frequency 等元数据。
  2. **Candidate Scoring**：非 HOT 中近期有流量者，路由量高且 CPU-served 多（高需求 + 高 miss 代价）者优先。
  3. **Bounded Swapping**：有限次交换，防止 cache thrashing；触发阈值与交换次数为离线调优超参数。

### 2.5 预测性专家暂存
- 对除最后两层外的每个 MoE 层 i 附加小型预测器，预测 **i+2 层**的专家分布。
- **输入特征**（低成本）：token 维平均池化的隐状态（语义上下文）、平均 router logits（路由边际倾向）、该层实际选中专家的直方图、top-k 高频专家。
- **MixtureHead**：动态混合两个子模型——ActHead（处理语义上下文与 router logits）与 HistHead（处理历史选择特征），两路 logits 由一个上下文门控网络学习动态权重 α 后融合。
- **训练**：完全离线，采集"层 i 特征 → 层 i+2 实际激活"轨迹，用交叉熵损失对齐目标层路由 token 分布，不修改基础模型。
- **执行**：预测专家若已在 HOT/STAGE 则跳过；否则异步拷贝到 STAGE（高优先级 CUDA 流），并记录目标层避免重复拷贝。
- **为何选 i+2**：即使 INT8 压缩，专家获取（PCIe 传输 + 反量化 + 预测器自身开销）延迟仍不可忽略；`i+1` 实测不足以完全隐藏延迟，更远则预测不确定性上升、浪费带宽；`i+2` 提供了足够 slack，且预测精度与 `i+1` 相当。

### 2.6 系统实现
- 自定义 kernel 将 INT8 反量化**融合进 FFN 计算**，不在 VRAM 中物化全精度权重。
- 预分配并复用 BF16 工作缓冲，消除关键路径上的 allocator churn。
- 双 CUDA 流：反量化流负责 INT8 数据与 BF16 scale 的搬运/反量化，计算流执行 FFN，实现重叠。
