## 摘要
新兴的多智能体LLM需要隐私保护的边缘部署，但当前的推理系统难以应对这些协作工作流。具体而言，受内存限制的解码阶段会在统一内存架构（UMA）上造成严重的总线争用，使朴素的CPU-GPU协同执行陷入瘫痪。此外，多智能体工作负载中的投机解码面临草拟难度的极大波动，在复杂推理与可预测的结构化生成之间交替。再加上频繁由工具调用引起的停顿，这种高度碎片化的执行严重未充分利用硬件，并使传统静态批处理失效。

我们提出EdgeAgent，一个专为边缘UMA和多智能体工作负载协同设计的跨层推理系统。在微架构层面，它绕过僵化的图编译器约束，实现零拷贝的UMA感知张量并行，利用非对称内存布局充分饱和CPU和GPU计算单元。在调度层面，它基于实时序列可预测性动态分配草稿预算，以限制带宽浪费。同时，异步挂起-让出机制主动驱逐停滞的智能体，确保在不可预测的工具调用期间硬件持续饱和。

在Apple M4 SoC上的大量评估表明，仅UMA感知执行就比批量投机解码带来1.29倍加速。加入智能体感知调度后，完整的EdgeAgent系统在极端工具使用延迟下提升至1.77倍加速。

## Abstract
Emerging multi-agent LLMs demand privacy-preserving edge deployment, yet current inference systems struggle with these collaborative workflows. Specifically, the memory-bound decode phase causes severe bus contention on unified memory architectures (UMA), paralyzing naive CPU-GPU co-execution. Furthermore, speculative decoding in multi-agent workloads faces extreme variance in drafting difficulty, alternating between complex reasoning and predictable structured generation. Compounded by frequent tool-induced stalls, this highly fragmented execution severely underutilizes hardware and defeats traditional static batching.   We present EdgeAgent, a cross-layer inference system explicitly co-designed for edge UMA and multi-agent workloads. At the micro-architectural level, it bypasses rigid graph-compiler constraints to enable zero-copy UMA-aware tensor parallelism, utilizing asymmetric memory layouts to fully saturate both CPU and GPU compute units. At the scheduling level, it dynamically allocates draft budgets based on real-time sequence predictability to bound bandwidth waste. Concurrently, an asynchronous suspend-and-yield mechanism actively evicts stalled agents, ensuring continuous hardware saturation during unpredictable tool invocations.   Extensive evaluations on an Apple M4 SoC demonstrate that the UMA-aware execution alone contributes a 1.29x speedup over batched speculative decoding. Adding the agent-aware scheduling lifts the full EdgeAgent system to a 1.77x speedup under extreme tool-use latencies.

# EdgeAgent 论文总结

## 1. 核心问题与整体含义

- **背景趋势**：LLM 应用正从单体聊天界面转向协作式多智能体系统（LangGraph、OpenClaw、ReAct 范式），Orchestrator 负责规划、Worker 负责代码生成与工具调用。多智能体获得更高系统权限后，隐私与安全顾虑推动推理向端侧（on-device）下沉。
- **核心矛盾**：现有推理系统无法在终端设备上高效支撑此类工作负载。
  - 云端系统（vLLM、Orca、Mooncake）面向多用户、离散多 GPU、高吞吐批处理，缺乏对节点内细粒度内存争用的感知，直接移植到边缘设备极低效。
  - 边缘框架（llama.cpp、MLX）面向单用户单请求串行推理，缺乏对动态并发的碎片化请求的编排能力，算力严重闲置。
- **三重系统性瓶颈**：
  1. **UMA 内存墙**：解码阶段为内存带宽受限，CPU-GPU 协同（张量并行）在共享总线上产生破坏性仲裁。实测在 4096×128256 矩阵上，协同相对纯 GPU 仅 0.99×（GPU 已占用 >80% 的 120 GB/s 峰值带宽）。
  2. **草稿难度极端方差**：推理任务（LongBench）与结构化生成任务（MBPP）的最优草稿长度差异巨大；SD 加速随草稿长度先升后降（结构化任务在 L=16 达 1.69× 峰值），而传统 SD 对所有请求强制统一草稿长度，导致带宽浪费或截断高可预测序列。
  3. **工具调用停顿**：Agent 等待外部工具（脚本、API）时占用活跃 token 槽位，造成队头阻塞，静态批处理无法回收空闲投机预算。
- **软件层障碍**：现代图编译器（ExecuTorch、MLX）以张量级粒度追踪依赖，无法安全表达对同一共享缓冲区的无锁正交写入，被迫插入硬件栅栏并退化为 eager 同步，破坏零拷贝优势。

## 2. 方法论

### 2.1 总体架构
跨层设计，含两层：**UMA 感知执行层**（硬件饱和）+ **智能体感知调度层**（全局资源编排）。

### 2.2 UMA 感知执行层

**（1）零拷贝张量并行（Zero-Copy TP）**
- **非对称权重布局**：GPU 分片保持 SIMT 线性布局；CPU 分片离线预打包为 SME 的 16×64 FP16 二维 tile，同时满足两类单元的内存 stride 约束。权重仅存一份（打包后释放未打包副本）。
- **列并行切分**：所有线性投影（MLP gate/up/down、Attention Q/K/V/O）沿输出 N 维切分，`W ∈ R^(K×N)` 分为 `W_cpu ∈ R^(K×n)` 与 `W_gpu ∈ R^(K×(N-n))`，其中 `n = α·N`，切分比 α 由各层 K/N 维度计算以均衡 CPU/GPU 计算时间。两设备读同一激活、写同一预分配输出缓冲区的**不相交列区间**，无需跨设备归约。
- **注意力核心按 head 切分**：GPU 跑其 head 范围的融合 SDPA，CPU 对剩余 head 跑分组 matmul，score/softmax/context 全设备本地；两组 context 沿 head 轴 concat 后再做列并行 O 投影。
- **绕过图编译器的两个轻量机制**：
  - *逻辑依赖屏障（Logical Dependency Barrier）*：用自定义 barrier 节点替代标准 concat。逻辑上是 DAG 同步点，物理上零内存分配，仅将输出指针别名到共享缓冲区。
  - *异构快速路径（Heterogeneous Fast Path）*：该子图在框架通用调度循环之外执行，直接向 CPU/GPU 并发下发任务，不插入保守的跨设备硬件栅栏。
- **一致性与内存模型假设**：不引入新一致性协议，依赖 UMA SoC 自身的单一物理地址空间与系统级缓存一致性；Metal 为弱松弛内存模型，因此只建立设计所需的 producer–consumer happens-before 关系。因写入区间不相交，不存在数据竞争，无需细粒度行级一致性。

**（2）SME 微内核优化**
- **指令级**：将矩阵负载划分为 16×64 微 tile，配合连续多向量加载 `svld1_x4` 并填满 4 个 2D ZA 寄存器 tile；沿 K 维激进展开循环，使连续内存加载与外积累加重叠（软件流水），掩盖访存延迟。
- **缓存级**：系统性调优宏 tile 参数，将活跃内存足迹严格限制在 8MB 有效 L2 工作集内，避免带宽陡降。
- **负载均衡**：针对 P-core/E-core 非对称多处理拓扑，实现基于松弛一致性原子操作的无锁动态 work-stealing 队列，按实时执行速率自主窃取微 tile，无锁竞争开销。

### 2.3 智能体感知调度层

**（1）全局草稿预算的硬件对齐**
- SME matmul 性能在 batch size 为 16 的倍数处呈阶梯式跃升，超过草稿长度 16 后性能急剧下降；端到端 SD 也在 L=16 达峰值（1.69×）。故固定全局草稿预算 **M = 16 token 槽位**。

**（2）动态草稿预算分配（HAL）**
- 用 **历史接受长度（HAL）** 作为草拟难度的客观代理，追踪**绝对接受 token 数**而非接受率（避免浅草稿树高接受率但低产出的误导）。EMA 更新：
  `A_i(t) = γ·k_i(t) + (1-γ)·A_i(t-1)`
  其中 `k_i(t)` 为当前步接受 token 绝对数；γ=0.3、A_i(0)=4.0 由异构多智能体负载画像的网格搜索选定。
- 分配公式（保证无饥饿）：
  `L_i(t+1) = L_min + ⌊(L_total − N·L_min) · exp(A_i(t)/τ) / Σ_j exp(A_j(t)/τ)⌋`
  其中 L_total=16，L_min 为每智能体不可抢占的基线容量。双向受限：最高 HAL 智能体也无法独占全部 16 槽位；HAL 每步重算，瞬时突发不会永久锁死其他智能体。

**（3）协作式挂起-让出机制**
- 在每个验证步的同步边界检查智能体状态，检测到工具阻塞即触发协作式让出：迁移至挂起队列，将其 token 槽位归还全局草稿预算，由动态分配器立即重分配，活跃流借此扩张草稿树而不突破 16 阈值。
- 利用 UMA 物理共享寻址，对挂起智能体的 KV cache 做**原地元数据冻结**；工具返回后直接提升回活跃队列，借助原地冻结与硬件感知偏移重映射压缩，**无需昂贵的上下文重预填充**，实现零开销状态恢复。

  - **不足**：多智能体工作负载并非真实采集，而是由自建 trace 合成器按已知统计特性生成；工具停顿以对数均匀分布人为注入，与真实工具调用的长尾、突发、嵌套特征存在差距；并发规模仅覆盖 N=2–4，未探测更高并发下的调度退化点；HAL 的超参（γ、τ、L_min）来自网格搜索，论文未给出对分布漂移的鲁棒性验证。

## 6. 主要结论与发现

- **零拷贝张量并行是可用的，但前提是消除框架层的同步税**。在 UMA 总线上做 CPU-GPU 张量并行，其收益并非来自算力叠加，而是来自绕过图编译器插入的硬件栅栏与中间 concat 缓冲：一旦执行层退化为 eager 同步，带宽争用会抵消全部收益（实测协同仅 0.99×）。这构成对"UMA 上跨单元并行天然低效"这一直觉的反例。
- **投机解码的草稿预算应按"智能体"而非"请求"分配**。将全局预算固定为硬件对齐的 16 槽位，再由 HAL 按历史接受长度动态切分，可在不改变验证步结构的前提下同时服务多个草稿难度迥异的流；这实际上把草稿预算从静态配置变成了可调度的稀缺资源。
- **工具停顿是边缘多智能体推理中被忽视的调度机会，而非单纯的延迟**。阻塞的智能体既是队头阻塞的来源，也是可回收的投机预算来源；挂起-让出 + 原地 KV 冻结使活跃流获得额外草稿深度，且状态恢复无需重预填充，因此停顿的"代价"被部分转化为其他流的加速。
- **端到端表现**：在 M4 与 M4 Pro 上，完整系统相对最强并发基线 Batch-SD 显著压缩 makespan 并提升全局吞吐；增益随并发度与工具停顿占比上升而扩大，说明收益主要来自并发编排而非单流内核优化。纯代码生成场景收益最小，因为其草稿可预测性最高、最优草稿长度与固定预算偏离最小。
- **组件归因**：消融显示 SME 内核、零拷贝 TP、HAL 三者贡献可分离且非冗余——内核决定单层算力上界，TP 决定 prefill/TTFT 的可扩展性，HAL 决定多流下的有效吞吐。

## 7. 局限与不足

- **场景合成而非真实 trace**：缺少确定性多智能体 benchmark 是客观困难，但这也意味着结论的生态效度未被外部数据验证。
- **硬件覆盖面窄**：两个 SoC 同属 Apple SME2 生态，跨指令集（如 x86 AVX-512/AMX）与跨加速器（NPU、DSP）的移植性未讨论；系统的关键机制强依赖 UMA 单一物理地址空间与系统级缓存一致性，本质上是 Apple Silicon 特化的。
- **模型规模有限**：仅 8B 稠密模型，未涉及 MoE、长上下文稀疏注意力或更大模型在 UMA 上的带宽/容量权衡。
- **功耗维度缺失**：边缘设备的真实约束是能效与热设计功耗，而论文只报告延迟与吞吐，未给出每 token 能耗或热降频下的表现。
- **框架耦合**：对 MLX C++ 图执行器的重构是方案成立的前提，移植成本与维护风险未评估；"逻辑依赖屏障"与"异构快速路径"的安全性论证依赖设计者手工保证写入区间不相交，缺少自动化验证或形式化检查。
- **对比面偏窄**：基线均在 GPU 上执行，未与 CPU-only 的 llama.cpp 路径或 NPU 加速方案对照，因此"UMA 协同优于其他边缘方案"的结论尚不完整。

## 8. 启示与可迁移性

- **对边缘推理系统的设计启示**：调度层的自由度（草稿预算分配、挂起-让出）往往比算子层优化更具边际收益，因为它作用于系统级资源而非单点算力。
- **对图编译器的启示**：当前编译器以张量级依赖追踪为安全边界，无法表达"不相交区间并发写"，这在异构执行场景下会强制引入同步开销；作者提出的逻辑屏障 + 快速路径是一种务实的绕过手段，但也暴露出编译器中缺少"内存区间级依赖"这一抽象层。
- **可迁移的方向**：HAL 的按难度分配思路可迁移至异构草稿模型路由；挂起-让出的原地 KV 冻结可迁移至任何存在外部 I/O 阻塞的服务化推理系统；非对称权重布局（按执行单元 stride 约束离线预打包）可迁移至其他 CPU+加速器协同场景。

## 9. 总体评价

论文的贡献在于把"边缘多智能体推理"从工程拼装提升为具有明确瓶颈分解的系统问题：它先量化了 UMA 内存墙、草稿难度方差、工具停顿三类瓶颈，再分别以执行层与调度层的机制对应解决，并给出可分离的消融归因。方法的代价是较强的平台与框架耦合，以及评测环境的人工合成性质；其结论更适合作为"在统一内存边缘 SoC 上做多智能体并发推理"的设计参考，而非可直接复制的通用方案。
