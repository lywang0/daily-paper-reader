## 摘要
普适智能应用正越来越多地部署在移动和物联网（IoT）边缘设备上。因此，大语言模型（LLM）也越来越多地被用于支持这些应用。然而，由于资源需求很高，LLM 大多部署在云端。逐层边缘-云推理使资源受限的边缘设备能够为它们无法完整托管的 LLM 贡献计算。然而，异构切分点引入了两种相互耦合的低效问题。首先，边缘执行与通信会在云端调用之间产生空闲间隙。其次，到达不同模型深度的请求无法按常规方式进行批处理。我们提出 DySCo，这是一种协同运行时，它将 KV 缓存保留在本地，并引入 dyForward，这是一种模型感知的层范围执行器，可在无需重新加载权重的情况下，从驻留模型分片运行可配置的连续层范围。针对多边缘服务场景，我们引入深度同步批处理（DSB），它将异构请求推进到最深的切分点，并对其公共后缀进行批处理。跨异构设备、两个模型系列以及本地和广域链路的实验表明，即使排除等待时间，空闲间隙也会增加后续 GPU 前向调用的延迟；在我们的测量中，每个解码步骤最多增加 25 ms 的云端后缀延迟。在平均并发度为 8 时，DSB 相比 FIFO 将吞吐量提升 275%，相比精确匹配批处理提升 48%，相比轮询交错提升 79%，同时降低平均每会话延迟。总之，这些结果表明，具有不同边缘-云切分点的请求可以复用驻留的云端权重，并共享批处理后缀计算。本工作的 artifact 仓库公开可用，地址为：https://github.com/Large-scale-Sustainable-Computing-LSC/dysco-artifact

## Abstract
Pervasive intelligent applications are increasingly deployed on mobile and Internet of Things (IoT) edge devices. Consequently, Large Language Models (LLMs) are increasingly used to support these applications. Yet, due to their high resource demands, LLMs are mostly deployed in the cloud. Layer-wise edge-cloud inference lets resource-constrained edge devices contribute computation to LLMs they cannot host in full. However, heterogeneous split points introduce two coupled inefficiencies. First, edge execution and communication create idle gaps between cloud invocations. Second, requests arriving at different model depths cannot be conventionally batched. We present DySCo, a collaborative runtime that keeps KV caches local and introduces dyForward, a model-aware layer-range executor that runs configurable contiguous layer ranges from resident model shards without reloading weights. For multi-edge serving settings, we introduce depth-synchronized batching (DSB), which advances heterogeneous requests to the deepest cut and batches their common suffix. Experiments across heterogeneous devices, two model families, and local and wide-area links show that idle gaps increase the latency of subsequent GPU forward calls even when waiting time is excluded, adding up to 25 ms of additional cloud-side suffix latency per decoding step in our measurements. At an average concurrency of eight, DSB improves throughput by 275% over FIFO, 48% over exact-match batching, and 79% over round-robin interleaving while reducing mean per-session latency. Together, these results show that requests with different edge-cloud splits can reuse resident cloud weights and share batched suffix computation. The artifact repository for this work is publicly available at: https://github.com/Large-scale-Sustainable-Computing-LSC/dysco-artifact

# DySCo 论文总结

## 1. 核心问题与整体含义（研究动机与背景）

- **背景**：普适智能应用（移动、IoT）越来越多地依赖 LLM，但 LLM 资源需求高，通常只能部署在云端，边缘设备资源被排除在推理路径之外；而全本地部署又受限于边缘设备的内存、算力与能耗预算。
- **中间路线**：逐层（layer-wise）边缘-云协同推理——边缘执行模型前缀 `[0, c)`，云端执行后缀 `[c, L)`，无需改变模型权重即可池化算力与内存。
- **核心痛点（两个耦合低效）**：
  - **时间维度**：边缘计算与通信导致云端 GPU 调用之间出现**空闲间隙**，即使排除等待时间，也会拖慢下一次前向调用的延迟（实测每解码步最多额外增加约 25 ms）。
  - **结构维度**：不同会话使用不同切分点（cut layer），导致请求以不同模型深度到达云端，**无法进行常规批处理**，即使它们共享很长的公共后缀。
- **整体意义**：揭示切分点选择与云端调度是**耦合**的——切分点既决定请求何时到达云端，也决定其能与多少其他请求共享计算。论文提出 DySCo 运行时与深度同步批处理（DSB）来同时缓解这两类低效。

## 2. 方法论：核心思想与关键技术

- **总体架构**：
  - 一个共享云后端 + 多个边缘客户端；控制面（请求控制器、会话管理器、调度器）与推理数据面分离。
  - **KV 缓存随层本地保留**：边缘持有前缀层 KV 缓存，云端持有后缀层 KV 缓存，正常推理路径不传输 KV 缓存。
  - 正常通信仅含：边缘→云传递切分层隐状态，云→边缘返回下一个 token ID；prefill 阶段额外传输注意力 mask 与位置编码。

- **dyForward（动态层范围执行器）**：
  - 模型感知的连续层范围执行器，支持 Llama 与 Qwen 系列。
  - 输入隐状态、起始层与可选结束层，动态调用选定的解码器层，构造因果 mask 与位置输入，更新对应 KV 缓存，仅在模型末端应用最终归一化。
  - 好处：无需为每种切分点复制权重或重建模型，多个会话可复用驻留权重与共享云端模型实例；会话初始化时选定切分点后**在生成过程中保持固定**。

- **DSB（深度同步批处理）**：
  - 设调度窗口 `W`，会话 `i` 的切分层为 `c_i`，选择最深到达层作为同步检查点：`d = max_{i∈W} c_i`。
  - 算法流程（Algorithm 1）：
    1. 计算 `d = max c_i`；
    2. 对每个不同切分点 `c < d`，将该切分点的会话分组，在其私有范围 `[c, d)` 上执行前向；
    3. 切分点恰为 `d` 的会话直接使用边缘传来的隐状态；
    4. 合并所有会话的隐状态、KV 行与 mask；
    5. 在公共尾 `[d, L)` 上执行一次批量前向；
    6. 拆分更新后的 KV 行并返回各自 token。
  - 当所有切分点相同（`d = c_i`）时，私有范围消失，DSB **退化为精确匹配批处理**。
  - 设备加入/离开只影响下一个窗口的组成与检查点，无需全舰队切分点协调；当前实现中 **prefill 不参与批处理**，DSB 仅改变云端解码调度。

- **通信与张量规模**：
  - 使用 gRPC 通信，张量序列化、RPC 开销与网络传输均计入端到端测量。
  - 主要张量规模可解析估算：隐状态 `S_hidden = B·T_in·b_h`，位置 `S_pos = B·T_in·b_pos`，mask `S_mask = B·T_ctx·b_mask`。缓存解码时 `T_in = 1`，重复负载主要由单 token 隐状态主导。

## 6. 主要结论与发现

- **切分层数不能单独预测延迟**：云端延迟随后缀深度减小先升后降，存在设备相关的拐点，甚至可能超过 A6000 全模型基线。原因在于空闲间隙引入的额外开销。
- **空闲间隙效应**：任何非零间隙都会引入超出等待时间本身的额外执行延迟；该开销在较窄范围内上升后达到与切分点相关的上限（切分 1 约 25 ms，切分 12 约 13 ms），且更大后缀需要更长间隙才达到上限。
- **DSB 效果**（平均并发 8，Llama-3.2-3B，16 个边缘 worker，切分 2–9）：
  - 吞吐量相比 FIFO **+275%**、相比精确匹配批处理 **+48%**（t = 26.9）、相比轮询交错 **+79%**。
  - 平均每会话延迟最低（4.93–6.45 s，FIFO 为 26.56–28.34 s），且吞吐提升**不以排队延迟为代价**。
- **收益的决定因素**：
  - 共享尾深度：8 个连续切分层从浅到深，DSB 相对精确匹配的增益从 **+78.1%**（20 层尾）单调降至 **−0.2%**（1 层尾），r = 0.981，每层约 +4.48%；Qwen2.5-3B 复现（r = 0.950，每层 +3.18%，接近 28/36 的比例）。
  - 切分层多样性：尾固定时，k = 2 时增益 −6.7%，随后线性上升（r = 0.995，每多一个切分层 +14.6%）至 k = 8 时 +81.3%；5 个不同设备类别即可获得可观收益。
  - 收益由窗口内**最深切分设备**决定，而非典型设备。
- **适用边界（Operating envelope）**：DSB 在至少 4 个并发会话、至少 4 个不同切分层、共享尾约 ≥5 层、上下文 ≲2048 token 时有益；在聚集型舰队（clustered fleets）上可能反而比精确匹配批处理差最多 **−8.9%**。相对轮询交错，交叉点依赖到达模式（突发同步下从 6 会话起 DSB 领先，持续到达下从 `N̄ = 4` 起领先）。
- **调度线程本身贡献显著**：突发实验中，轮询交错与 FIFO 执行相同的单会话调用，却已比 FIFO 高 +67% 到 +114%，说明部分收益来自单一调度线程而非批处理。
- **上下文长度影响**：增益在 ≤512 token 时保持 +78% 到 +84%，2048 token 时降至 +42.0%，4096 token 时不再显著（+4.2%），因为 KV 缓存的合并/拆分从约 18% 升至每解码步的 43%。

## 7. 优点

- **问题识别新颖且系统**：明确区分并实证了切分点带来的"时间空闲间隙"与"结构批处理不兼容"两类耦合低效，并用受控重放将后者从层计算与网络传输中隔离出来。
- **机制设计简洁可复用**：dyForward 无需为每种切分重建或复制权重，DSB 在切分点相同时自然退化为精确匹配批处理，且无需全舰队切分点协调。
- **KV 缓存本地化**：正常推理路径只传输单 token 隐状态与 token ID，通信开销低且分析可解析。
- **实验严谨性**：随机化条件顺序、Welch t 检验、明确噪声下限对照、正负结果均报告（如聚集舰队的负增益、无显著性的场景）。
- **开源 artifact**：提供公开仓库，可复现性较好。
- **诚实的边界刻画**：明确给出 DSB 的适用包络与失效场景，而非只报告最优结果。

## 8. 不足与局限

- **异构性为模拟而非真实**：多边缘实验使用相同物理边缘 GPU，仅通过切分层模拟容量差异，未真正测试异构边缘硬件的耦合效应。
- **prefill 未批处理**：DSB 当前只作用于云端解码调度，prefill 保持未批处理，限制了端到端收益。
- **切分点固定**：会话初始化后切分点固定，未做联合的切分层选择与调度器自适应（作者列为未来工作）。
- **聚集舰队可能负收益**：在多个少数派切分点的舰队上 DSB 可低于精确匹配批处理最多 8.9%，且论文表示**未能确定**区分"单个离群点"与"成对/聚集少数派"的机制。
- **空闲间隙成因未定论**：论文推测与 GPU DVFS 和功耗状态转换有关，但未通过频率锁定等实验确证（A6000 测试也未消除该效应）。
- **长上下文与高并发受限**：4096 token 上下文下增益不显著；KV 缓存合并/拆分开销随上下文显著增长。
- **广域多边缘与在线切分未评测**：作者明确将地理分布式边缘舰队、动态网络与负载下的在线切分选择留作未来工作。
- **算力/能耗数据缺失**：未报告总 GPU 小时、能耗或频率控制细节，对可持续性评估的支撑有限。
