## 摘要
推测解码通过使用轻量级草稿模型提出多个令牌进行并行验证，从而加速自回归生成。然而，现有方法通常需要额外的草稿模型或权重表示，在资源受限设备上引入不可忽视的内存开销。自推测方法降低了这种开销，但仍面临草稿质量、目标质量与存储效率之间的权衡。我们提出 BitNest，一种位嵌套推测解码框架，将低精度草稿直接嵌入到更高精度的目标表示中。BitNest 并非从预定义目标中导出草稿，而是先构建一个强大的低精度基础模型，再通过残差精化恢复更高精度的目标，使两个模型共享单一物理权重表示。BitNest 进一步将这种渐进式精度设计扩展到 KV 缓存，以支持长上下文推理。在多个 7B--8B 边缘友好型 LLM 和多样化工作负载上，BitNest 实现了平均 95.2% 的推测接受率，同时很好地保持了更高精度模型的质量，并在 FP16 自回归解码上实现 1.48--1.61 倍的端到端加速。在所有代表性自推测基线均支持的 LLaMA 模型上，BitNest 也取得了一致具有竞争力或更高的解码加速。

## Abstract
Speculative decoding accelerates autoregressive generation by using a lightweight draft to propose multiple tokens for parallel verification. However, existing methods often require an additional draft model or weight representation, introducing non-negligible memory overhead on resource-constrained devices. Self-speculative approaches reduce this overhead, yet still face trade-offs between draft quality, target quality, and storage efficiency. We propose BitNest, a bit-nested speculative decoding framework that embeds a low-precision draft directly into the higher-precision target representation. Instead of deriving a draft from a predefined target, BitNest first constructs a strong low-precision base and then recovers the higher-precision target through residual refinement, enabling both models to share a single physical weight representation. BitNest further extends this progressive-precision design to the KV cache for long-context inference. Across multiple 7B--8B edge-friendly LLMs and diverse workloads, BitNest achieves an average speculative acceptance rate of 95.2% while closely preserving higher-precision model quality, and delivers 1.48--1.61x end-to-end speedup over FP16 autoregressive decoding. On the LLaMA models supported by all representative self-speculative baselines, BitNest also achieves consistently competitive or higher decoding speedup.

## 1. 核心问题与整体含义

- **研究背景**：LLM 自回归生成面临计算成本高、模型与 KV 缓存内存占用大、内存带宽需求密集等瓶颈，在单 GPU、消费级 GPU、边缘设备等资源受限场景尤为突出。
- **推测解码的两难**：
  - 使用独立小模型作草稿：草稿与目标能力差距大 → 接受率低；同时引入额外模型存储开销，在 16GB 设备上（FP16 7B 模型已接近容量上限）难以承受。
  - 现有自推测方案（层跳过、量化复用）虽省去独立草稿模型，但仍存在**草稿效率、目标质量、存储开销**三者之间的权衡：
    - QSpec 将目标限制为共享低比特表示，牺牲目标质量；
    - QuantSpec 仍保留额外的低精度草稿权重。
- **核心问题**：能否用**单一物理模型表示**同时支持轻量草稿与高质量目标，且不增加额外内存，并保持足够的草稿-目标一致性？
- **整体含义**：提出"位嵌套推测解码"（Bit-Nested Speculative Decoding）新范式，让低精度草稿作为高精度目标的**位平面子集**物理嵌套于同一表示中，为内存受限场景下的推理加速提供新思路。

## 2. 方法论

### 2.1 核心思想
- 不"从目标导出草稿"，而是**反向构造**：先构造强 W4 基座，再将其量化残差编码为 4-bit 精化位，组合得到 W8 目标。使 W4 草稿成为 W8 目标的**精确子集**，两者共享一份物理权重。
- 整体流程：旋转变换 → 基座构建 → 残差精化 → 双平面存储 → 推测解码访问。

### 2.2 关键技术细节
- **函数保持旋转**：使用 SpinQuant 类旋转 R₁/R₂ 折入预训练权重 W，得 W′，抑制激活离群值，提升低比特鲁棒性。
- **W4 基座构建**：对 W′ 用 GPTQ（group size=128）量化得到 `q₄ ∈ [-8,7]` 与组尺度 `s₄`，草稿权重 `W_draft = q₄·s₄`；随后**固定 q₄ 与 s₄**。
- **固定基座残差精化**：
  - 残差 `ΔW = W′ − W_draft`；
  - 精化尺度 `s_ref = s₄/16`；
  - 精化码 `q_r = clip(round(ΔW/s_ref), 0, 7)`（当 q₄=−8 时）或 `clip(..., −8, 7)`（否则），避免组合整数越过 int8 下界；
  - 目标重构：`W_target = q₄s₄ + q_r·s_ref = (16q₄ + q_r)·s_ref`。
- **双平面权重存储**：因内存按字节寻址，若 base 与 refinement 打包在同一字节，草稿仍需取回精化位。故将两者存为**两个独立的 4-bit 位平面**，各占 N/2 字节。草稿仅读 base 平面（4 bit/weight 流量），验证读两个平面。精化无需额外 scale 元数据（由 `s₄/16` 派生）。
- **KV 缓存嵌套**：
  - 在线逐 token、逐 KV head 的对称 RTN 量化，头维度 d=128；
  - `s = max|xᵢ|/7`，`q₄ = clip(round(x/s), −8, 7)`，`x̂_draft = q₄·s`；
  - 精化 `q_r = clip(round((x − q₄s)/(s/16)), −8, 7)`，目标 `x̂_target = (16q₄ + q_r)·s/16`；
  - 草稿仅读 KV4 base，验证读 KV4+精化得 KV8；草稿阶段候选 token 的 KV 为临时值，验证时重算，接受者保留、被拒后缀丢弃；
  - **上下文感知策略**：短上下文时草稿与验证均用 KV8 以保一致性；长上下文时草稿用 KV4、验证用 KV8 以省带宽；另支持 Recent-N 策略（最近 N 条 KV 用高精度供草稿读取）。

### 2.3 实现
- 使用自定义 Triton kernel 实现双平面 GEMM 与 flash decoding；激活采用 per-token INT8 量化。

## 6. 主要结论与发现

- **加速**：在 4 个模型、6 个负载上相对 16-bit AR 实现 **1.48–1.61×** 端到端加速，工作负载间一致性高。
- **接受率**：平均 **95.2%**（模型级均值 94.8%–95.7%），说明 W4A8 草稿与 W8A8 目标对齐良好。
- **质量保持**：接近 FP16 与独立 W8A8。例如 LLaMA-3-8B 上 GSM8K 达 49.8% vs W8A8 的 50.0%。
- **长上下文**：草稿读 KV4、验证读 KV8 时，32K 上下文加速达 1.66×（全 KV8 时降至 1.38×）；在 32K 下峰值内存 21.0 GiB，优于 QSpec（24.0）与 QuantSpec（25.1）。
- **内存节省**：LLaMA-2-7B 嵌套权重占 6.22 GiB，与独立 W8 相同；而独立 W4 草稿 + INT8 目标需 9.38 GiB。
- **边缘设备**：Orin NX16 上 LLaMA-2-7B-32K 约 1.5× 加速，decode 能耗 1.52 → 0.95 J/token；最大可执行上下文从 W8A8 的 6K 扩展到 **10K**（FP16 仅 2K）。NX8 上 Llama-3.2-3B 加速达 1.57×。
- **VLA 探索**：OpenVLA-7B 上 decode 加速 1.35×，任务成功率 89% vs FP16 86%、直接 W4A8 仅 80%。
- **关键洞见（消融）**：低精度表示足以做草稿，但作为最终目标会明显掉质——LLaMA-3-8B 上 W4A8 GSM8K 仅 41.4%，提升激活精度到 W4A16 也仅 41.8%，说明退化主要来自 4-bit 权重；读取精化平面可恢复到 49.8%。因此"低精度草稿 + 高精度目标"的嵌套设计是必要的。

## 7. 优点

- **思想新颖**：把"草稿是目标的子集"从逻辑概念落到**物理位平面嵌套**，实现真正零额外草稿存储，区别于共享低比特（QSpec）或额外低精度副本（QuantSpec）。
- **构造方向巧妙**：base-first（先优 W4 基座再精化残差）避免独立量化 W8 破坏嵌套关系，同时规避 W4 目标的质量上限。
- **工程落地细致**：识别出字节寻址会抵消 W4 收益的问题，设计双平面位打包；精化 scale 由 base scale 派生，节省元数据；自定义 Triton kernel。
- **KV 缓存同源扩展**：把嵌套原则延伸到 KV，配合上下文感知策略（短上下文 KV8/KV8、长上下文 KV4/KV8）与 Recent-N 策略，解决长上下文 KV 流量主导的问题。
- **实验全面**：速度、质量、内存、能耗、接受率、多架构（MHA/GQA）、边缘设备、VLA 场景均有覆盖，消融设计有洞察力（明确回答"为什么目标仍需高精度"）。
- **公平性处理得当**：速度统一归一化到同一引擎的 16-bit AR 基线；基线用官方实现与推荐配置。

## 8. 不足与局限

- **未利用辅助草稿架构**：论文自述不适用于扩散类并行草稿（如 DFlash），在可接受额外草稿开销时可能获得更强加速，扩展嵌套表示以兼容此类草稿是未来方向。
- **VLA 场景 prefill 开销**：当前大 M 路径将打包权重反量化为 FP16 走 cuBLAS，prefill 比 FP16 慢约 1.7×，导致 OpenVLA 单动作总延迟（212.7 ms）略高于 FP16 AR（201.5 ms），decode 收益被 prefill 抵消；需专用 INT8 大 M kernel。
- **精度实例化较窄**：主要围绕 W4/W8 与 KV4/KV8 组合，其他比特宽度（如 W2/W3、KV2）未探索。
- **长上下文收益依赖架构**：MHA 模型（LLaMA-2，32 个 KV head）受益明显，GQA 模型（Qwen2.5）因 KV 流量本已较小，低精度草稿 KV 的吞吐提升有限（50.7 → 51.4 tok/s）。
- **跨方法比较受限
