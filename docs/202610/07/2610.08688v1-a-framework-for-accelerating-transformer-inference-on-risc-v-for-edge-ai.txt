# A Framework for Accelerating Transformer Inference on RISC-V for Edge AI 

Ajay Kumar M ∗, Vishnu PS ∗, Yike Li ∗, Shreejith Shanker †

Dimitrios S. Nikolopoulos ‡, Bo Ji ‡, Hans Vandierendonck §, Deepu John ∗∗University College Dublin, Ireland †Trinity College Dublin, Ireland 

‡Virginia Tech, USA §Queen’s University Belfast, UK 

Abstract —This work presents a framework for accelerat-ing transformer-based language models (LMs) on resource-constrained IoT devices. The framework targets compact LMs: BERT-Tiny (B-Ty), MobileBERT (M-Bt), MiniLM (M-Lm), Elec-tra (E-Lt) and DeBERTa (D-Bt) — selected for their architectural diversity and use in edge inference scenarios. The proposed flow derives lightweight instruction set extensions tailored to the non-obvious computational patterns of these models. In addition, a custom instruction is introduced to accelerate the address generation stage of batch matrix multiplication, achieving aperformance improvement of 15.39–21.74% with modest ASIC overheads of 6.79% in area and 2.33% in power. To further enhance performance without incurring additional processor core hardware cost, an optional compiler-directed loop unrolling strategy is employed, trading increased code size for overall reduced execution time. Evaluation on the Synopsys trv32p3f RISC-V core demonstrates inference speedups of up to 2.19×, and FPGA implementation on the AMD Zynq UltraScale+ ZCU102 shows a 32.94% area overhead at 75 MHz, whereas the ASIC implementation using the TSMC 28 nm library incurs a 21.08% area overhead while operating at 250 MHz. 

Index Terms —RISC-V, Language models, TVM, Hardware acceleration, FPGA 

I. I NTRODUCTION 

Deploying deep neural networks (DNNs) on bare-metal IoT platforms remains difficult under tight energy, memory, and compute budgets. Many acceleration frameworks still depend on heavyweight stacks, or lack fine-grained architec-tural customisation, hindering practical deployment in deeply embedded settings. As modern edge workloads increasingly incorporate transformer-based architectures, particularly in vision[1] and language tasks[2], there is a growing need for model class-specific optimisations targeting these networks. Recent efficient edge Transformers and LMs[3–8] still present distinct computational characteristics. The higher reliance on attention patterns and more extensive use of matrix multiplica-tions introduce new challenges in data movement for existing instruction-level optimizations designed for CNN workloads, which leads to inefficient performance on edge platforms. Prior work in vision [9], NLP [10–12], and general DNN acceleration [13, 14] shows that pruning, quantization, ISA extensions, and dedicated acceleration units can enable ef-ficient RISC-V deployment. However, existing works do not address the limited compiler support for the proposed extensions, often requiring users to generate manual assembly implementations to extract per-formance gains. In this work, instead of targeting vector extensions on dedicated compute components, we focus on scalar extensions that can execute solely on a standalone RISC-V core. By avoiding the area and power-intensive overhead of vector units, our approach reduces hardware cost, preserves ease of compiler integration and programmability, and enables practical acceleration of LMs under strict edge constraints. The key contributions of this work are as follows: 1) A framework for model-class-aware RISC-V ISA exten-sion generation targeting compact transformer LMs. 2) A custom fused instruction accelerating batch matrix multiplication with minimal area/power overhead. 3) An optional compiler-directed loop-unrolling strategy that improves inference throughput without incurring additional hardware resources. II. M ETHODOLOGY 

The trv32p3f processor core from Synopsys is used as a baseline. It has a 32-bit wide data path and a three-stage pipeline. This core implements the RV32IMFZfinx ISA and has floating-point hardware support. The extended core is tested with variants of standard language models’ C codes. A. Model Preparation Phase 

Our flow targets encoder-only Transformer models. A pre-trained Hugging Face model with a reinitialized classification head is fine-tuned on SST-2 dataset [16]. B. Compilation Phase 1) Profiling: The TVM-generated C is compiled in ASIP Designer (version W-2024.12). The workloads are unquantized FP32. With RV32IM (no F-extension), the compiler realizes FP operations using software emulation libraries, severely degrading performance. Compiling for RV32IM F maps FP32 operations to FPU instructions and removes soft-float libraries. The resulting binaries are executed on the Instruction Accurate (IA) simulator for profiling. Custom scripts extract hot instruc-tions and patterns; the top ten by cycle count are examined. Beyond memory operations, several ALU operations (like 

slli , add , addi , ori ) account for a significant share of cycles. Subsequently, an analysis of instruction sequences with high cycle costs was conducted. Fig. 2 illustrates how much of the overall code is made up of these instructions and the extracted sequences, across models. 

2) ISA extensions: We employ a data-driven methodology to propose targeted, and non-standard ISA extensions aimed at mitigating computational bottlenecks. Guided by profiling results, the baseline core is augmented with these custom extensions. Implemented using reserved/custom opcode space, these extensions reuse the core’s existing general-purpose registers, no new architectural registers are added. The design and impact of these extensions are described below. 

add3i : Profiling shows frequent sequences of three indepen-dent addi instructions. We introduce add3i , which performs three parallel immediate additions in a single cycle using a shared 10-bit signed immediate broadcast to all operations. This width covers most observed cases in our evaluated models, capturing 94.76% of B-Ty, 97.50% of M-Bt, 96.72% of M-Lm, 96.75% of E-Lt, and 93.94% of D-Bt cases. The instruction requires six registers; therefore, we reserve x22 ,

x23 , and x30 .

add2i : Profiling shows frequent back-to-back addi instruc-tions. Across the evaluated models, one immediate operand

We therefore encode one immediate in 10 bits and one in 5 bits — covering 96.92% of B-Ty, 96.49% of M-Bt, 86.97% of M-Lm, 97.43% of E-Lt, and 88.57% of D-Bt cases. add2 : This instruction merges execution of two consecutive add instructions. Since there can be six distinct registers in two add instructions, we repurpose the RISC-V U-type instruction format for encoding. Four registers are mapped to the 20-bit immediate field, while the fifth register is fixed to ( x21) . The sixth register is encoded in the source register field. 

or2i : This custom instruction is introduced to fuse two consecutive OR operations that each perform a bitwise OR with an immediate operand. Profiling reveals that the imme-diate values in these consecutive instructions remain identical across all evaluated models, with their magnitudes constrained below 1023. Therefore, a 10-bit field is sufficient to encode the immediate. Since the instruction requires encoding four registers but the available bit width is limited, one destination register is fixed to x29 .

sll2i : This custom instruction fuses two consecutive ”shift left logical immediate ( slli )” operations. Since this instruc-tion is encoded using the RISC-V I-type format, only two registers can be directly specified. To address this, we utilize the 12-bit immediate field to encode a third register, while the fourth register is fixed to x24 in our design. The compiler automatically substitutes eligible sequences of consecutive 

slli instructions with sll2i , internally using x24 . On a 32-bit processor, the maximum shift amount is 31, requiring 5 bits to represent each immediate. Thus, two 5-bit fields are allocated within the instruction encoding. 

batmatmul : Profiling identified batch matrix multiplica-tions as one of the dominant consumers of clock cycles, motivating an atypical ISA extension to accelerate this work-load. Although prior works like [18] present high-performance matrix multiplication units, such designs incur significant area and power overhead. In contrast, we introduce a compact acceleration unit tightly integrated into the CPU pipeline that targets the address-generation stage of batch matrix multiplica-Fig. 3: batmatmul HW

As illustrated in Fig. 3, the unit computes the parameter addresses that the floating-point unit subsequently fetches and multiplies, providing a practical trade-off between area, power and performance. Across the evaluated models, the proposed extension accelerates the batch matrix multiplication operation by 15.39–21.74% on average. FPGA implementation shows hardware area and power overhead of 22.26% and 4.42%, re-spectively, while ASIC implementation shows 6.79% area and 2.33% power overheads. The microarchitecture compresses ten baseline instructions into a single fused operation. Guided by profiling of immediate values, two immediates are hardcoded and the remaining variable immediates are encoded in 10-bit fields; two of those variable immediates are identical, which further simplifies the encoding. Because the extension refer-ences eleven registers while encoding space is constrained, eight operand registers are fixed. 

C. Hardware Generation Phase 

The obtained instruction set extensions are modeled in ASIP Designer using its domain-specific modeling language, nML. Fig. 4 shows an example nML snippet implementing the proposed batmatmul ISA extension. This is subsequently translated into synthesizable hardware. Given the significantly larger size of the models under consideration, functional validation of the generated RTL was performed via behavioral simulations. The functionality of the generated FPGA bit-stream for AMD’s ZCU102 FPGA platform has been validated through the execution of a small hand-coded transformer model, as described in [19]. 

D. Loop Optimization Strategy 

TVM-generated C code typically contains numerous for 

loops. These loops translate to frequent branch instructions, which incur significant cycle overhead. Profiling shows that branch operations ( bne, beq ) are among the most cycle-intensive instructions, making loop optimization an important target. While MARVEL [20] demonstrates hardware loop extensions, this work explores a lightweight alternative using compiler-provided loop unrolling hints. Although this may increase code size, it requires no additional hardware, allows unrestricted unrolling, and provides fine-grained control to balance performance and memory usage. That said, hardware loop extensions remain preferable in scenarios where processor area constraints are less critical. Chess ® compiler allows users to annotate loops with unrolling hints. C. Software Loop Unrolling vs. Hardware Loop Extensions 

This section compares loop optimizations applied through Chess compiler hints against hardware-based loop accelera-tion. For the latter, we employ the Synopsys trv32p3fx core, which incorporates a hardware loop ISA extension, an address generation unit, and several DSP extensions. Although this core includes additional features beyond hardware loops, it provides a useful baseline for comparison. Fig. 5 illustrates the variation in program memory usage and cycle counts between trv32p3f U and trv32p3fx, normalized with respect to trv32p3f, across the evaluated LMs. Incorporating compiler hints can more than double inference speed, making them ideal when program memory size is unrestricted and processor core area is tightly constrained. IV. C ONCLUSION AND FUTURE WORK 

This paper introduces a framework for accelerating trans-formers, particularly encoder-only, on RISC-V. With the pro-posed extensions and compiler hints, inference speed more than doubles. Future work includes adding quantization to reduce C code memory footprint, and assessing a core without an FPU for higher speed operations. REFERENCES
