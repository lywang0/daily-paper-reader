## 摘要
本工作提出了一种在资源受限的物联网设备上加速基于Transformer的语言模型（LM）的框架。该框架面向紧凑型LM：BERT-Tiny（B-Ty）、MobileBERT（M-Bt）、MiniLM（M-Lm）、Electra（E-Lt）和DeBERTa（D-Bt）——选择它们是因为其架构多样性以及边缘推理场景中的使用。所提出的流程推导出针对这些模型不明显的计算模式定制的轻量级指令集扩展。此外，引入了一条自定义指令来加速批量矩阵乘法的地址生成阶段，在面积和功耗分别仅为6.79%和2.33%的适度ASIC开销下，实现了15.39--21.74%的性能提升。为了在不增加额外处理器核心硬件成本的情况下进一步提升性能，采用了一种可选的编译器指导的循环展开策略，以增加的代码尺寸换取整体执行时间的缩短。在Synopsys trv32p3f RISC-V核心上的评估表明推理加速最高可达2.19倍，在AMD Zynq UltraScale+ ZCU102上的FPGA实现显示在75 MHz下面积开销为32.94%，而使用TSMC 28 nm库的ASIC实现则在250 MHz下运行时产生21.08%的面积开销。

## Abstract
This work presents a framework for accelerating transformer-based language models (LMs) on resource-constrained IoT devices. The framework targets compact LMs: BERT-Tiny (B-Ty), MobileBERT (M-Bt), MiniLM (M-Lm), Electra (E-Lt) and DeBERTa (D-Bt) -- selected for their architectural diversity and use in edge inference scenarios. The proposed flow derives lightweight instruction set extensions tailored to the non-obvious computational patterns of these models. In addition, a custom instruction is introduced to accelerate the address generation stage of batch matrix multiplication, achieving a performance improvement of 15.39--21.74% with modest ASIC overheads of 6.79% in area and 2.33% in power. To further enhance performance without incurring additional processor core hardware cost, an optional compiler-directed loop unrolling strategy is employed, trading increased code size for overall reduced execution time. Evaluation on the Synopsys trv32p3f RISC-V core demonstrates inference speedups of up to 2.19x, and FPGA implementation on the AMD Zynq UltraScale+ ZCU102 shows a 32.94% area overhead at 75 MHz, whereas the ASIC implementation using the TSMC 28 nm library incurs a 21.08% area overhead while operating at 250 MHz.

# 论文总结：面向边缘AI的RISC-V Transformer推理加速框架

## 1. 核心问题与整体含义

- **研究动机**：在裸机 IoT 平台上部署深度神经网络（DNN）仍受限于严苛的能量、内存与计算预算。现有加速框架要么依赖重量级软件栈，要么缺乏细粒度的架构定制能力，难以在深度嵌入式场景中落地。
- **背景挑战**：随着边缘工作负载越来越多地采用 Transformer 架构（视觉与语言任务），其高度依赖注意力模式与大量矩阵乘法，为面向 CNN 工作负载设计的指令级优化带来了新的数据搬运难题，导致边缘平台性能低下。
- **现有工作不足**：
  - 已有 RISC-V 扩展工作（如 RISC-VTF、VEXP、V-SEEK）多关注向量扩展或专用计算单元，带来显著面积/功耗开销；
  - 部分工作缺少编译器支持，需手工编写汇编才能获得性能收益；
  - 部分工作仅评估吞吐/延迟，忽视功耗这一边缘关键指标。
- **整体含义**：本文提出一个面向紧凑型 Transformer 语言模型的、模型类别感知的 RISC-V ISA 扩展生成框架，采用**标量扩展**而非向量单元，以低硬件成本实现实用加速。

## 2. 方法论

### 2.1 核心思想
- 面向仅编码器（encoder-only）Transformer 模型，通过**数据驱动的性能剖析**识别高频非显然计算模式，生成轻量级、非标准的标量 ISA 扩展，并配合可选的编译器循环展开策略，实现 HW/SW 协同优化。

### 2.2 关键技术细节

**模型准备阶段**
- 目标模型：BERT-Tiny（B-Ty）、MobileBERT（M-Bt）、MiniLM（M-Lm）、Electra（E-Lt）、DeBERTa（D-Bt）。
- 预训练 Hugging Face 模型重初始化分类头后，在 SST-2 数据集上微调，导出为 ONNX，再用 TVM 编译生成 C 代码。

**编译与剖析阶段**
- 基线核：Synopsys trv32p3f（32 位数据通路、三级流水线、RV32IMFZfinx、带浮点硬件）。
- 在 ASIP Designer（W-2024.12）中编译，工作负载为**未量化 FP32**；使用 IA 模拟器剖析，提取热指令与前十大周期消耗模式。
- 发现除内存操作外，ALU 操作（slli、add、addi、ori）及分支指令（bne、beq）占据大量周期。

**自定义 ISA 扩展（复用保留/自定义 opcode 空间，不新增架构寄存器）**

| 指令 | 功能 | 编码策略 | 覆盖率 |
|------|------|----------|--------|
| `add3i` | 单周期完成三条并行立即数加法 | 共享 10 位有符号立即数；占用 x22、x23、x30 | 93.94%–97.50% |
| `add2i` | 融合两条连续 addi | 一操作数 10 位、另一 5 位；占用 x22、x23 | 86.97%–97.43% |
| `add2` | 融合两条连续 add | 复用 U-type 格式；x21 固定，第六寄存器在源寄存器域 | — |
| `or2i` | 融合两条连续 OR 立即数 | 10 位立即数；x29 固定 | 立即数均 < 1023 |
| `sll2i` | 融合两条连续 slli | I-type；12 位立即数域编码第三寄存器，x24 固定 | 两个 5 位立即数 |
| `batmatmul` | 加速批矩阵乘法**地址生成阶段** | 将 10 条基线指令压缩为 1 条融合操作；两个立即数硬编码，其余变长编码于 10 位域；11 个寄存器中 8 个固定 | 加速 15.39–21.74% |

**硬件生成阶段**
- 使用 ASIP Designer 的 nML 领域专用建模语言建模 ISA 扩展，转换为可综合硬件。
- 通过行为仿真做功能验证；FPGA 比特流在 ZCU102 上用小型手写 Transformer 模型验证功能。

**循环优化策略**
- TVM 生成的 C 代码含大量 for 循环，分支指令开销大。
- 使用 Chess 编译器提供的循环展开提示（annotate hints），自定义脚本解析 C 代码并注入到所有最内层 for 循环。
- 与 MARVEL 的硬件循环扩展对比：软件方案无额外硬件、允许无限展开、可细粒度平衡性能与内存；但 M-Bt 因循环过多未完全展开。

## 6. 主要结论与发现

- **batmatmul 地址生成扩展**：在面积开销 6.79%、功耗开销 2.33%（ASIC）的代价下，将批矩阵乘法加速 15.39–21.74%；FPGA 下面积/功耗开销分别为 22.26% 和 4.42%。
- **整体性能**：仅应用 ISA 扩展时，5 个模型的加速为 1.19–1.24×；叠加编译器循环展开后，加速提升至 1.50–2.19×（B-Ty 2.13×、M-Bt 1.50×、M-Lm 2.10×、E-Lt 2.19×、D-Bt 2.07×）。
- **硬件开销**：
  - FPGA：整体面积开销 32.94%，功耗开销 7.23%（DSP 用量不变，逻辑用 CARRY8 实现）；
  - ASIC：面积开销 21.08%，功耗开销 9.47%。
- **循环优化对比**：编译器循环展开可在无额外硬件成本下使推理速度翻倍以上，适合程序内存不受限且核心面积受限的场景；硬件循环扩展（trv32p3fx）在面积约束不紧张时更优。

## 7. 优点

- **方法亮点**：
  - 采用**标量扩展**而非向量单元，避免面积/功耗密集型开销，保持编译器集成与可编程性；
  - 基于**数据驱动剖析**提出非显然的指令融合模式（如 add3i、or2i、sll2i），立即数位宽设计有实证覆盖率支撑；
  - `batmatmul` 只加速地址生成阶段而非整个矩阵乘法单元，是一种务实的面积-性能折中；
  - 提供**可选**编译器循环展开，不强制增加硬件成本，灵活性高。
- **实验亮点**：
  - 同时给出 FPGA 与 ASIC 两套资源/功耗数据，评估较全面；
  - 与硬件循环扩展核 trv32p3fx 做了直接对比，体现软件方案的适用边界；
  - 开源了生成脚本（GitHub 链接），有利于复现。

## 8. 不足与局限

- **实验覆盖局限**：
  - 仅评估编码器型 LM 和单一分类任务（SST-2），未涉及解码器/生成式模型或更复杂 NLP 任务；
  - 未与其他 RISC-V Transformer 加速工作做端到端横向对比；
  - 未验证量化（INT8 等）场景下的扩展有效性。
- **偏差风险**：
  - 立即数位宽与寄存器固定策略基于特定模型集合的剖析结果，可能对模型类别分布敏感，泛化性存疑；
  - 未说明微调算力与训练细节，复现门槛较高。
- **应用限制**：
  - 仅针对 FP32 未量化推理，功耗与内存优势有限；
  - M-Bt 因循环过多无法完全展开，说明方法对复杂控制流模型存在适用性边界；
  - 扩展核寄存器被大量保留占用（x21–x24、x29、x30），可能影响通用程序寄存器分配；
  - 作者也指出未来需评估无 FPU 核心与量化方案，当前结果尚未覆盖这些方向。
