## 摘要
现代边缘片上系统（SoC）集成了异构处理单元（PU），如CPU、GPU和NPU，它们各自具有不同的性能和能耗特征。在实时延迟和能耗约束下将AI推理工作负载部署到这些PU上，需要联合地将工作负载映射到PU，并为每个PU进行配置（例如，选择活跃核心数量和运行频率）。这种联合空间呈组合式增长，使得穷举搜索不可行。此前大多数设计空间探索（DSE）工作采用黑盒优化（BBO），如进化搜索，其中每次评估仅返回延迟和能耗等聚合指标。近期由LLM引导的DSE也依赖于同样稀疏的反馈。我们观察到，这限制了其效率：它无法提供对设计空间的洞见，也无法解释某一设计选择为何表现如此，并且很大程度上未利用LLM的推理能力。我们提出TraceDSE，一种智能体式DSE流程，用于在异构SoC上为AI推理执行联合的工作负载映射和PU配置选择。TraceDSE是一个由更丰富反馈（以系统执行轨迹的形式）驱动的迭代式提议者-批评者循环。LLM提议者智能体生成候选映射和PU配置，以供硬件评估。LLM批评者智能体配备程序化轨迹分析工具，分析执行轨迹以识别瓶颈并提出有针对性的改进建议。该循环可产生对每个设计点更深入的洞见、更高质量的决策以及更有效的搜索。在Intel Meteor Lake SoC上的四个AI推理工作负载（不同复杂度的模型以及一个多模型流水线）中，TraceDSE持续优于两种最先进的BBO工具，将Pareto前沿超体积较NSGA-II提升最高35%，较贝叶斯优化提升最高68%，同时所需的硬件评估次数减少约6-9倍。

## Abstract
Modern edge Systems-on-Chip (SoCs) integrate heterogeneous processing units (PUs) such as CPUs, GPUs, and NPUs, each with distinct performance and energy characteristics. Deploying AI inference workloads on them under real-time latency and energy constraints requires jointly mapping workloads to PUs and configuring each PU (e.g., selecting the number of active cores and the operating frequency). This joint space grows combinatorially, making exhaustive search infeasible. Most prior work on design space exploration (DSE) applies black-box optimization (BBO) such as evolutionary search, where each evaluation returns only aggregate metrics such as latency and energy. Recent LLM-guided DSE relies on the same sparse feedback. We observe that this limits its efficiency: it offers no insight into the design space or the reasons a design choice performs the way it does, and it leaves the reasoning abilities of LLMs largely unused. We present TraceDSE, an agentic DSE flow that performs joint workload mapping and PU configuration selection for AI inference on heterogeneous SoCs. TraceDSE is an iterative proposer-critic loop driven by richer feedback in the form of system execution traces. The LLM proposer agent generates candidate mappings and PU configurations for hardware evaluation. The LLM critic agent, equipped with programmatic trace-analysis tools, analyzes the traces to identify bottlenecks and suggest targeted refinements. This loop yields deeper insight into each design point, higher-quality decisions, and a more effective search. Across four AI inference workloads (models of varying complexity and a multi-model pipeline) on an Intel Meteor Lake SoC, TraceDSE consistently outperforms two state-of-the-art BBO tools, improving Pareto frontier hypervolume by up to 35% over NSGA-II and up to 68% over Bayesian optimization, while requiring ~6-9x fewer hardware evaluations.

- **研究背景**：手机、可穿戴设备、智能眼镜、AR/VR 头显等边缘设备普遍搭载异构 SoC，集成 CPU、GPU、NPU 等处理单元（PU），各自具有不同的延迟—能耗权衡特性。
- **核心问题**：部署 AI 推理负载时，需要**联合求解两个耦合的设计空间**：
  - **工作负载映射空间**：以计算图（DAG）表示的网络中，每个节点（卷积、全连接、注意力等）分配到哪个 PU；
  - **PU 配置空间**：每个 PU 的运行时可配置参数（CPU 的 P-core/E-core 选择与活跃核心数、GPU/NPU 频率、NPU tile 数量等）。
- **规模困境**：两空间交叉导致组合爆炸。例如 HRNet（98 节点）× 3 种 PU × 每 PU 2 种配置 ≈ 4.6×10⁴⁷ 个候选；单次硬件评估需 30–60 秒，穷举不可行。
- **现有方法局限**：
  - 黑盒优化（BBO，如遗传算法、贝叶斯优化）仅依赖延迟/能耗等**聚合指标**，缺乏领域知识，收敛慢；手工启发式虽可缓解，但需针对每个平台/负载人工设计。
  - 近期 LLM 引导的 DSE（gem5 Co-Pilot、LEMOE、iDSE、LLM-DSE、LLAMBO、LLM-Box 等）虽引入预训练知识，但**反馈仍然是稀疏的聚合指标**。
- **核心洞察**：稀疏反馈限制了 LLM 驱动 DSE 的效率——(i) 无法解释某设计选择为何表现如此；(ii) 未能发挥 LLM 处理丰富结构化信息进行高质量推理的能力。
- **整体含义**：硬件评估可产出远比聚合指标更丰富的**执行轨迹**（每节点耗时/能耗、跨 PU 数据传输、PU 利用率、空闲区间、关键路径等），将轨迹转化为可操作反馈，可显著提升搜索效率。

## 2. 方法论

### 2.1 问题形式化

- 负载表示为 DAG：\(G=(N,E)\)；平台提供 PU 集合 \(P=\{p_1,\dots,p_{|P|}\}\)；配置空间 \(H=H_1\times\cdots\times H_{|P|}\)。
- 映射 \(m:N\to P\)；给定 \((h,m)\) 后由调度器产生满足数据依赖的调度 \(S(G,h,m)\)。
- 两个优化目标：
  - 延迟 \(L(h,m)=\text{Makespan}(S(G,h,m))\)
  - 能耗 \(E(h,m)=\text{Pow}(h,m)\cdot L(h,m)\)
- 以 **Pareto 前沿超体积 HV(F)** 衡量解集质量，目标是在延迟—能耗空间最大化 HV。

### 2.2 核心思想：提议者—批评者（Proposer–Critic）智能体循环

- 整体是一个 **evaluate–analyze–refine 闭环**，由两个 LLM 智能体协作，通过"执行轨迹"这一丰富反馈介质连接。
- **关键洞察**：执行分析需要细粒度逐节点轨迹（且随迭代增长），而候选生成需要设计空间的宏观视角——两者任务性质不同，因此**解耦为两个专门化智能体**。

### 2.3 流程细节

**I. 输入与一次性节点剖析（Node Profiling）**
- 将全部节点分别整体映射到每个 PU（最大资源设置）各运行一次，测得**逐节点延迟与能耗**，称为 *profiling priors*。
- 作用有二：(a) 为提议者生成初始候选**热启动**；(b) 使批评者能在**不额外硬件评估**的前提下，估算"某节点换到某 PU"的端到端延迟影响。

**II. 迭代 DSE 循环**
1. **提议者（Proposer）**：每轮生成一批候选 \(c_i=(h_i,m_i)\)，并附带解释其设计选择的**推理陈述**。
   - 初始输入：工作负载 DAG、PU 配置空间、优化目标、profiling priors。
   - 后续轮次额外输入：**Pareto 前沿**（引导往能提升 HV 的区域）、**探索摘要**（避免重复访问已评估区域）、**上一轮批评意见**（逐候选反馈 + 建议改动）。
2. **调度与评估（Scheduler & Evaluator）**：
   - 调度采用 **HEFT（Heterogeneous Earliest Finish Time）** DAG 调度器；
   - 在真实目标平台上执行，产出端到端延迟、能耗、**逐 PU 能耗分解**，以及执行轨迹（每节点：分配 PU、起止时间戳、计算时间、跨 PU 数据传输延迟）。
   - 所有结果存入搜索状态。
3. **搜索状态（Search State）**：记录已评估候选、Pareto 前沿、探索摘要。
4. **批评者（Critic）**：产出三段式 critique——(a) 逐候选反馈，指出哪些设计选择驱动了指标（哪些该保留/该改）；(b) 跨迭代综合观察（如某节点—PU 映射持续表现不佳）；(c) 对每个候选映射与配置的具体修改建议。
5. **终止条件**：连续 5 轮 Pareto 前沿超体积相对提升低于 0.5%。

**III. 输出**：延迟—能耗 Pareto 前沿及对应 \((h^*,m^*)\) 与 HV(F*)。

### 2.4 批评者的六个程序化轨迹分析工具

| 工具 | 返回内容 |
|---|---|
| 关键路径提取 | 关键路径节点及其延迟与占总延迟比例 |
| 延迟瓶颈排序 | 按延迟降序的 Top-k 节点及在替代 PU 上的预估加速比 |
| PU 利用率与空闲区间分析 | 各 PU 利用率与空闲区间 |
| 节点级检查 | 单节点的计算时间、调度与通信延迟、在各 PU 上的预估延迟 |
| 能耗分解 | 各 PU 能耗占系统总能耗百分比 |
| 延迟估计 | 给定映射/配置变更后的预测延迟 |

批评者**自主选择并调用**这些工具（例如先提关键路径定位瓶颈节点，再检查这些节点在哪个替代 PU 上更快），并用 profiling priors 过滤掉不太可能带来收益的改动。

- **消融结论**：
  - **执行轨迹反馈是最关键组件**——去掉后在所有 benchmark 上均显著退化（Δ = 0.066–0.111，均值 0.082）；等延迟下 ImageBind 能耗上升最多 **73%**；两个 benchmark 上失去低延迟极端点（ImageBind 差 12%，DAv2 差 15%）。
  - **批评者不可省**——原始轨迹直接给提议者会使上下文从约 10K 膨胀到 **250K+ token**，LLM 输出质量下降；Speech-based VQA 上甚至比"仅聚合指标"变体更差。
  - **搜索状态**对 HRNet、DAv2 有影响（重复拓扑导致反复精修同一区域），对 ImageBind、Speech-based VQA 影响有限（瓶颈天然在编码链间迁移）。
  - **工作负载 DAG** 对 ImageBind（−0.111）与 Speech-based VQA（−0.106）关键，对 HRNet（−0.001）、DAv

2（−0.002）影响很小——前者因重复 fork–join 拓扑使 DAG 信息冗余，后者基本串行，节点顺序本身已隐含依赖关系。

## 7. 方法亮点与潜在局限

**亮点**

- **反馈介质的升级**：把"执行轨迹"而非聚合指标作为 LLM 与硬件之间的接口，是本文最本质的贡献。它把 DSE 从"黑盒调参"推向"可解释的因果归因"，使 LLM 的推理能力真正被用在了它擅长的地方（结构化信息分析），而非仅仅做模式记忆。
- **提议者—批评者解耦**：抓住了"生成需宏观视角、分析需细粒度轨迹"这一任务异质性，既避免了单智能体上下文爆炸（250K+ → 10K token），又让两个角色的 prompt 与输入可以分别优化。
- **工具化的批评者**：批评者不靠"读轨迹文本"，而是调用六个程序化分析工具（关键路径、瓶颈排序、利用率、节点检查、能耗分解、延迟估计），既压缩了 token，又提高了分析的准确性和可复现性——这是把 LLM 与经典程序分析结合的良好范式。
- **profiling priors 的巧妙复用**：一次性逐节点剖析同时服务于热启动和"无硬件评估的替代方案预估"，等于把 N×|P| 次评估的成本摊薄成后续所有轮次的免费先验。
- **实验设计较为严谨**：相同种子、相同墙钟预算、统一归一化、多种子重复、多 LLM 验证、完整 12 轮案例研究，且明确报告了评估次数与成本，可比性较好。

**局限**

- **单平台验证**：全部结论基于 Intel Meteor Lake 单一 SoC，映射粒度也仅"节点→CPU/GPU/NPU"三选一。跨 SoC（如高通、Apple、AMD）以及更细粒度切分（层内并行、算子融合、量化配置）是否同样有效，尚未验证。
- **依赖强 LLM 与 API 成本**：主实验使用 Gemini 3.1 Pro Preview，批评者 LLM 推理占总墙钟的 25–35%。若换成小模型或本地模型，工具调用与推理质量是否仍能支撑，文中未做低端 LLM 的充分对比（仅 4 个高端模型对比）。
- **调度器固定为 HEFT**：TraceDSE 优化的是映射与配置，调度策略本身未纳入搜索空间。若换用其他调度器（如列表调度、基于 RL 的调度），轨迹形态与批评者结论可能改变。
- **能耗测量精度**：采用外部传感器轮询 + idle 功耗扣减，变异系数最高达 10.8%，虽对结论方向性影响不大，但在等延迟下比较 7–18% 的能耗差异时，误差已接近效应量级。
- **HRNet 上优势有限（+1%）**：说明当拓扑高度重复、瓶颈节点稳定时，轨迹反馈带来的信息增量相对有限；方法的增益与负载的"并行异构性"正相关，这一点论文虽诚实报告，但也划定了方法的适用边界。
- **批评者的可靠性未单独评估**：文中未报告批评者建议的采纳率、正确率，或其是否会产生误导性建议（幻觉性瓶颈定位）。

## 8. 对领域的意义与启示

- **对 LLM 驱动 DSE（LLM4DSE）方向**：本文提出了一条与"提示工程/思维链"不同的路径——**让 LLM 消费程序化提取的结构化证据**，而不是消费更多文本。这为 gem5 Co-Pilot、LLM-DSE 等后续工作提供了直接可借鉴的反馈接口设计。
- **对边缘 AI 部署实践**：在资源受限设备上做异构调度时，"哪个节点该放哪个 PU、PU 该开几个核/多大频率"这类决策目前多靠人工经验；TraceDSE 表明可以用 10–30 次真实评估快速逼近高质量 Pareto 前沿，具有落地潜力。
- **对多目标优化的方法论**：展示了"领域知识 + 结构化反馈 + 少量真实评估"可以在样本效率上显著超越通用多目标进化算法与贝叶斯优化，提示未来可将类似范式迁移到编译器优化、数据库调优、芯片布局等其他组合优化场景。

## 9. 可改进方向

- 跨平台、跨映射粒度的泛化验证；引入层内并行/量化等更细配置维度。
- 引入更轻量的批评者（如小模型 + 工具蒸馏），降低 25–35% 的 LLM 开销。
- 将调度器纳入搜索空间，或与轨迹反馈形成"映射—调度"联合优化。
- 增加批评者建议质量的定量评估（采纳率、命中率、误报率）。
- 提升能耗测量精度（如片上 PMU 直接读取），或对能耗差异做误差传播分析。
- 探索在线/持续 DSE 场景：负载或平台配置动态变化时，能否复用历史轨迹与批评结论做快速再优化。
