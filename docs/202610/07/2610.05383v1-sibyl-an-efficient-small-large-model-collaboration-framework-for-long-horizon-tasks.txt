## ABSTRACT 

Small language models (SLMs) offer a promising foundation for on-device agents through low-latency, resource-efficient inference, yet limited reasoning and plan-ning capabilities constrain their performance on long-horizon tasks requiring multi-step interaction with the environment. Step-level collaboration between SLMs and larger cloud-hosted models can bridge this gap, but identifying states that warrant cloud assistance remains challenging: the contribution of each cloud call is entan-gled with subsequent actions and can be assessed only from the final task outcome. Compounding this challenge, the SLM must balance two competing objectives: maximizing task success and minimizing cloud calls. To address this, we propose Sibyl, an algorithm that trains SLM agents to selectively consult cloud models at the step level and internalize their guidance for subsequent decisions, achieving strong task performance with minimal cloud reliance. Sibyl follows a three-stage training pipeline that (1) builds a robust base policy through consultation-free self-evolving reinforcement learning (RL); (2) cold-starts consultation behavior via decisive-disagreement state mining; and (3) jointly optimizes consultation deci-sions and guidance internalization through consultation-aware RL. Experiments on ALFWorld and WebShop demonstrate that Sibyl, using only a 0.6B-parameter model, outperforms state-of-the-art baselines, including agent training and routing methods, by 95.2% and 80.4% in success rate while averaging only 0.8 and 3.9 cloud calls per trajectory, respectively. We release the code and trained model weights at https://github.com/real-fzw/Sibyl 

## 1 INTRODUCTION 

Language model agents have recently shown strong promise on long-horizon tasks such as embodied interaction (Seo et al., 2026; Kwon et al., 2026), web navigation (Yang et al., 2025b; Liu et al., 2026), and software engineering (Antoniades et al., 2025; Zhang et al., 2025a), which require sustained iteration over reasoning, tool use, observation, and revision across many interdependent steps (Shinn et al., 2023; Xu et al., 2026). However, much of this progress has been driven by cloud-hosted large language models (LLMs) (e.g., GPT-5.6 (OpenAI, 2026), Gemini 3.1 Pro (Gemini Team, 2026), Qwen3.7-Max (Qwen Team, 2026), and Kimi K3 (Kimi Team, 2026)), while small language models (SLMs) suitable for edge deployment remain markedly less capable, particularly in the 3B-and-below regime (Liu et al., 2024; Mai et al., 2026). Their limited reasoning and planning degrade decision quality over sustained interaction with the environment, undermining reliability on long-horizon tasks and posing a critical barrier to autonomous-agent deployment in latency- and resource-constrained applications that require efficient on-device execution (Wan et al., 2025; Wen et al., 2024). A natural solution is edge–cloud collaboration: on-device SLMs handle most steps locally and selectively consult stronger cloud-hosted LLMs (Ong et al., 2025; Liao et al., 2026), combining efficient local execution with advanced reasoning and planning. However, collaboration on long-horizon agentic tasks is fundamentally more challenging than conventional SLM–LLM routing. Right: success-rate comparisons with representative baselines; see § 5 for further results. model selection is no longer a one-time decision for each task, but a sequence of decisions throughout an evolving trajectory (Zhang et al., 2026). Consequently, the utility of step-level consultation is entangled with subsequent actions and often discernible only from the final outcome, complicating the precise identification of beneficial consultation states required to maximize task success with minimal cloud calls (Feng et al., 2025). Second, existing SLM–LLM collaboration methods typically rely on an external router (Ong et al., 2025; Chen et al., 2024), which is ill-suited to long-horizon agents: routing decisions are tightly coupled with the agent’s acting policy, making it difficult to train a separate router that generalizes across diverse, evolving states and remains aligned as the policy is updated. Moreover, a separate router adds supervision overhead and system complexity, complicating end-to-end agent training. We address these challenges with Sibyl, a policy optimization method that trains SLM agents to selectively consult cloud-hosted LLMs and internalize their guidance; Figure 1 illustrates the step-level collaboration paradigmd. Without a separate router, Sibyl treats consultation as an SLM action and optimizes it alongside local actions from trajectory-level outcomes, while progressively reducing cloud reliance through guidance internalization. Sibyl training proceeds in three stages: (1) consultation-free self-evolving reinforcement learning (RL) distills hindsight skills from on-policy trajectories to strengthen SLM agent before introducing cloud assistance; (2) decisive-disagreement state mining identifies states where a one-step cloud intervention turns a failed SLM trajectory into a successful one, providing targeted supervision to cold-start consultation behavior; (3) consultation-aware RL jointly optimizes local actions and cloud calls using trajectory-level outcomes while internalizing LLM guidance through hindsight skill distillation, thereby improving task success and reducing cloud reliance. Experiments on challenging ALFWorld and WebShop benchmarks demonstrate that Sibyl establishes a new task-success–execution-cost Pareto frontier relative to both state-of-the-art agent training and routing methods. Notably, with only a 0.6B-parameter SLM, Sibyl achieves success rates of 95.2% and 80.4% while averaging only 0.8 and 3.9 cloud calls per trajectory, respectively. Our contributions are threefold: • We formulate long-horizon SLM–LLM collaboration as SLM policy optimization over local actions and step-level cloud consultation, eliminating the need for an external router. • We propose Sibyl, a three-stage training algorithm that enables SLM agents to learn when to ask for cloud assistance and internalize the resulting guidance, thereby minimizing cloud calls while preserving task success. • Across challenging agent benchmarks, Sibyl advances the success–cost Pareto frontier over state-of-the-art agent training and routing methods. 22 RELATED WORK 

Reinforcement learning for language-model agents. Language-model agents show substantial promise for autonomous decision-making by coupling reasoning with sustained environment inter-action (Yao et al., 2023; Shinn et al., 2023). RL has become a central paradigm for training agents through direct policy improvement from interaction outcomes. Building on the widely adopted clipped actor–critic objective (Schulman et al., 2017), GRPO (Shao et al., 2024) replaces the learned critic with group-relative advantage estimation. GiGPO (Feng et al., 2025) further introduces hierar-chical trajectory- and step-level grouping for long-horizon credit assignment. RAGEN (Wang et al., 2025) studies stability in self-evolving agentic RL, while SEED (Wu et al., 2026) uses on-policy distillation (OPD) to distill hindsight skills from on-policy trajectories into the acting policy. However, these methods optimize individual agents rather than multi-agent collaboration, making them less effective for capacity-limited SLMs, particularly those with < 1B parameters. 

SLM–LLM collaboration. Leveraging assistance from stronger LLMs has emerged as a prominent approach to mitigating SLM capacity limitations while balancing execution efficiency and cost (Zhang et al., 2025b). FrugalGPT (Chen et al., 2024) and Hybrid LLM (Ding et al., 2024) route requests based on predicted quality–cost trade-offs, while Eagle (Zhao et al., 2024) and RouteLLM (Ong et al., 2025) use historical similarity or preference-based predictions. MinionS instead assigns subtask decomposition and verification to the cloud model (Narayan et al., 2025). However, these methods target independent requests rather than evolving long-horizon trajectories. Most related to our work, Hera (Zhang et al., 2026) extends collaboration to the step level but relies on a separately trained router over fixed device and cloud policies, leaving SLM capability unchanged. In contrast, Sibyl integrates consultation and guidance internalization into the SLM policy, eliminating the external router while improving the system’s capability ceiling and cost efficiency.

## 4 METHOD 

4.1 OVERVIEW 

Building on § 3, we present Sibyl, a method that trains SLM agents to selectively consult stronger cloud models and internalize their guidance to maximize task success while minimizing cloud calls. Sibyl follows a three-stage training pipeline, as illustrated in Figure 2: • Consultation-Free Self-Evolving RL (§ 4.2). The SLM is first trained through RL with skill-conditioned on-policy distillation, providing a reliable basis for consultation. • Consultation Cold Start (§ 4.3). Matched local and one-step cloud-assisted branches identify decisive-disagreement states to cold-start selective consultation. • RL with Consultation and Internalization (§ 4.4). On-policy RL uses step-level credit to jointly optimize local actions and consultation decisions while internalizing cloud guidance to strengthen local capability and reduce repeated calls. 4.2 CONSULTATION -F REE SELF -E VOLVING RL Learning effective consultation requires a sufficiently capable base policy; otherwise, the SLM may improve task success by overusing cloud assistance rather than identifying states where consultation is truly necessary. We therefore first train πθS as a robust standalone agent without consultation. Inspired by self-evolving agent training (Wu et al., 2026), we distill reusable hindsight guidance from the agent’s own trajectories, providing dense supervision beyond sparse outcome rewards for long-horizon behaviors such as subgoal planning and failure avoidance. 

Trajectory-level skill supervision. We first execute training task x using the SLM policy πθS alone, yielding a trajectory τ S. Given x, τ S, and its return R(τ S), the cloud LLM πθL serves as a trajectory teacher TθL to extract a concise causal summary and reusable hindsight skill: 

zτ S = TθL (x, τ S, R (τ S)) . (5) Beyond the sparse return, zτ S captures trajectory-level behavioral structure, such as effective subgoal ordering, decisive observations, and failure-avoidance rules. We then fine-tune πθS on the resulting trajectory–skill pairs, using the trained model both as the trajectory analyzer TθS for subsequent on-policy distillation and as the initialization of πθS itself. This bootstrapping eliminates repeated cloud queries for trajectory annotation during online training.

The higher score despite similar exact success suggests better partial progress on episodes that do not result in a complete purchase. With Qwen3-1.7B, Sibyl exceeds the strongest training-time baselines by 5.4 and 7.3 success points on the two benchmarks, indicating that selective consultation remains useful as local model capacity increases. Among methods that use cloud assistance at inference time, Sibyl achieves higher success than RouteLLM and Hera with fewer cloud calls, as detailed in the next section. Both baselines train an external router to allocate decisions between fixed device and cloud policies. Although RouteLLM and Hera use external routers to coordinate fixed device and cloud policies, Sibyl jointly learns local actions and consultation while internalizing cloud guidance. On ALFWorld, Sibyl reaches 94.3% success at an approximately 8% call ratio, or 92.1% with fewer than 5% of steps delegated; the corresponding WebShop frontier reaches 80.4% at 67% and 77.8% at 45%. These settings outperform random consultation, RouteLLM, and Hera, indicating that the gains stem from learning when to seek assistance rather than simply having access to the cloud. Moreover, neither removing consultation-specific credit ( αcf = 0 ) nor assigning it excessive weight ( αcf = 1 ) reaches the frontier. Intermediate weights most effectively reward consequential consultations while suppressing unnecessary cloud calls. 5.4 ABLATION STUDY 

Figure 4 traces the contribution of each training stage on ALFWorld and WebShop. Starting from base SLM success rates of 0.7% and 0.8%, Stage 1 raises success to 90.0% and 60.8% without inference-time consultation, establishing a capable local policy. ## 6 CONCLUSION 

We presented Sibyl as a policy-optimization framework that trains SLM agents to selectively consult stronger cloud models and internalize their guidance. By treating consultation as a native policy action, its three-stage training jointly strengthens local capability, learns when to ask, and reduces repeated cloud dependence. Experiments on challenging long-horizon benchmarks show that Sibyl achieves strong task success while substantially reducing cloud calls, advancing the success–cost trade-off over existing agent training and routing methods. More broadly, Sibyl offers an integrated framework that unifies coordination and capability transfer across heterogeneous language-model agents; its limitations and future directions are discussed in Appendix F.

## B BENCHMARK PROTOCOL AND DATA SPLITS 

We evaluate the Sibyl on two interactive benchmarks, ALFWorld and WebShop, under the benchmark-specific protocols described below. 

ALFWorld. ALFWorld (Shridhar et al., 2021) provides a text-based view of household tasks aligned with the embodied ALFRED environment. An agent receives a natural-language goal, observes the environment through text, and selects admissible actions until the goal is completed. The benchmark covers six task types: Pick & Place , Examine in Light , Clean & Place , Heat & Place , Cool & Place ,13 and Pick Two & Place . The official split contains 3,553 training games, 140 Seen games, and 134 Unseen games. Seen games use rooms encountered during training with new object configurations, whereas Unseen games use previously unseen rooms and layouts. We report the main results on the 140-task Seen split and use the 134-task Unseen split to assess out-of-distribution generalization. Each episode is limited to 30 steps, and the prompt contains the most recent 5 interaction steps. The prompt and response limits are 2,048 and 512 tokens, respectively. 

WebShop. WebShop (Yao et al., 2022) is a simulated shopping website built from more than 1.1 million products and 12,087 crowdsourced instructions. Each instruction specifies requirements such as product attributes, options, and a price limit. The agent searches the catalog, navigates product and detail pages, selects options, and buys a product. The environment computes a reward from the match between the selected product and the instruction, including its type, attributes, options, and price. We report Task Score, defined as 100 times the mean reward, and Success Rate, the fraction of episodes with reward one. We evaluate all methods on 500 test samples, with a maximum of 15 steps per episode and the most recent 5 interaction steps included in the prompt. The prompt and response limits are 12,288 and 512 tokens, respectively.

## E CASES STUDY 

Success rates quantify the overall benefit of consultation but do not establish whether the cloud model’s input was strictly necessary. To examine this question, we analyze four representative rescue cases from the evaluation traces in Table 7 under aligned comparison settings. Both ALFWorld branches use the same 30-step budget, while both WebShop branches use the same 15-step budget, start from the same restored session, and share the same frozen edge continuation, differing only in the action taken at the disputed state. We present two representative cases from each benchmark to illustrate our central finding: targeted cloud consultation can resolve decision bottlenecks and recover successful trajectories. In all four cases, the on-device SLM makes an incorrect decision when operating alone. The cloud model is consulted at this decision bottleneck and provides an executable corrective action; the on-device SLM then resumes control and completes the task successfully. This reflects Sibyl’s intended division of labor: the cloud model resolves a difficult local decision, while the edge model executes the remaining routine steps. The two ALFWorld cases involve cloud-guided search and target disambiguation. Once the cloud model identifies the correct location or target, the on-device SLM correctly performs subsequent actions such as picking up, cleaning, and placing the object. The two WebShop cases are more localized: the on-device SLM fails to select the required product option on its own, whereas the cloud model selects the correct option. The on-device SLM then executes the same final “buy now” action, which succeeds with the correct option in place. Together, these traces provide qualitative evidence that Sibyl invokes the cloud at decision bottlenecks, corrects local edge-model errors, and delegates the remaining workflow to the on-device model. 

## F LIMITATIONS AND FUTURE WORK 

Sibyl focuses on when an on-device agent should request one-step assistance from a fixed cloud model. This formulation assumes that the cloud service is available when needed and that the agent can share sufficient task context to obtain a useful action. Privacy-sensitive applications and intermittent connectivity introduce additional constraints: the agent may need to limit the context it transmits or continue safely when a consultation fails. Future work could incorporate privacy-aware context selection and fallback behavior into the consultation policy. The current formulation also treats the cloud as a single source of assistance. A deployed agent may instead have access to models with different capabilities, prices, and response times.
