## 摘要
在边缘设备上运行GUI智能体可以将敏感屏幕和交互历史保留在本地，但每个动作步骤的推理计算开销使部署面临挑战。现有的GUI智能体系统要么在每个动作步骤执行完整的视觉语言模型（VLM）推理，要么复用与先前任务匹配的粗粒度知识。然而，动态的移动环境和用户任务使得在不进行额外微调或任务特定离线探索的情况下，难以充分利用先前的任务执行。为解决这一挑战，我们提出PastForward，一个通过经过验证的、细粒度复用普通任务执行过程中积累的计算经验来加速GUI智能体的系统。在解码过程中，PastForward检索先前的输出序列作为设备自适应的多token提议，并在单次VLM前向传播中验证它们。跨动作步骤，它利用先前的GUI转换，在设备执行当前动作时开始下一步推理；仅当预测屏幕与观察到的屏幕匹配时保留早期计算，并向前传递可复用的KV状态。我们使用多个VLM骨干模型，在服务器和边缘平台上，对源自真实移动使用模式的AndroidWorld工作负载评估PastForward。在设备端，PastForward在保持任务成功率的同时，实现了1.63-2.36倍的动作步骤延迟加速。

## Abstract
Running GUI agents on edge devices can keep sensitive screens and interaction histories local, but the computational cost of inference at every action step makes deployment challenging. Existing GUI agent systems either perform full vision-language model (VLM) inference at each action step or reuse coarse-grained knowledge matched to prior tasks. However, dynamic mobile environments and user tasks make it difficult to fully utilize prior task executions without additional fine-tuning or task-specific offline exploration. To address this challenge, we present PastForward, a system that accelerates GUI agents through validated, fine-grained reuse of computational experience accumulated during ordinary task execution. During decoding, PastForward retrieves prior output sequences as device-adaptive multi-token proposals and verifies them in a single VLM forward pass. Across action steps, it uses prior GUI transitions to begin next-step inference while the device executes the current action, retains the early computation only when the predicted screen matches the observed screen, and carries reusable KV states forward. We evaluate PastForward on AndroidWorld workloads derived from real mobile usage patterns using multiple VLM backbones across server and edge platforms. On device, PastForward achieves action-step latency speedups of 1.63-2.36$\times$ while maintaining task success rates.

## 1. 核心问题与整体含义（研究动机与背景）

- **背景**：移动 GUI 智能体（如智能手机自动化）需要视觉语言模型（VLM）反复"看屏幕—决策—执行动作"。将 VLM 放在云端可保证性能，但需上传敏感屏幕与交互历史，存在隐私风险；放在端侧则受限于算力。
- **核心痛点**：端侧每个动作步骤都要完整 VLM 推理。作者在 Galaxy S26 Ultra 上实测：单步推理耗时 8.57 s，占动作步延迟的 **77.26%**（其中 prefill 2.62 s、decoding 5.95 s、A2O 间隔 2.52 s）。多步任务中该开销沿关键路径累加，导致端侧部署困难。
- **现有方法不足**：
  - 现有 GUI 智能体系统要么每步做全量 VLM 推理，要么复用**粗粒度**知识（应用知识、子任务、工作流、动作序列），且多依赖离线探索、模型微调或记忆预构建。
  - 模型/运行时层面的优化（视觉 token 剪枝、视觉计算复用）只利用单次调用内部结构或相邻屏幕间关系，**未把跨任务执行积累的执行记录当作可复用资源**。
- **核心挑战**：细粒度执行记录不能直接复用——指令、任务参数或屏幕一变，输出可能分叉；同一屏幕同一动作也可能产生不同下一屏（如弹窗）。因此必须**只复用经当前 VLM 或观测屏幕验证过的计算**。
- **整体含义**：论文提出将"普通任务执行中自然积累的计算经验"转化为细粒度推理复用，无需离线探索、无需微调、不改动 VLM 骨干与智能体策略，即可在端侧降低延迟，且收益随经验积累而增长。

## 2. 方法论

### 2.1 核心思想

- 把历史任务执行记录视作**计算经验（computational experience）**，在三个层面做"检索—验证—复用"：
  1. **解码层**：复用历史输出 token 序列，用单次前向完成多 token 验证（类推测解码，但提议来自历史执行而非草稿模型）。
  2. **交互层**：用历史 GUI 转移在 A2O 间隔内**提前推理**下一步。
  3. **状态层**：跨动作步传递可复用 KV 状态，减少重复 prefill。

### 2.2 关键技术细节

**（1）Experience-Guided Adaptive Decoding（经验引导自适应解码）**

- **解码经验记忆 Mdec**：以每个 token 位置的最终层隐状态 `h_i` 为检索键（而非 token 本身，因同一 token 在不同多模态上下文下含义不同），关联其后缀 `y_{i:T}`。为节省存储，输出序列只追加一次到共享 token 数组，每条记录存 `(h_i, p_i, b_i)`，其中 `p_i` 是 token 位置、`b_i` 是所属输出序列边界，防止提议跨越到下一次输出。
- **上下文兼容检索**：用当前 `(h_i, y_i)` 查询，先按 token 匹配与位置合法性过滤，再做余弦相似度排序选最优条目，返回相似度 `s_d`；无命中则退化为普通贪心解码。
- **单次前向验证**：给定提议 `ŷ_{i+1:i+ℓ}`，一次前向同时计算每个提议位置及提议后一个位置的预测，接受最长匹配前缀并追加首个不匹配处的模型预测（若全匹配则追加提议后位置的预测），即每次迭代推进 `ℓ_acc + 1` 个 token。
- **无损保证**：所有被接受的 token 都等于当前 VLM 的贪心预测，因此输出序列与贪心解码完全一致，**无精度损失**。
- **运行时自适应提议长度控制器**：每轮迭代按在线估计选择长度

  `L*_d = argmin_{0≤ℓ≤ℓ_max} T̂(ℓ) / (Â(ℓ, s_d) + 1)`

  其中 `T̂(ℓ)` 为延迟估计（在线对数二次拟合），`Â(ℓ, s_d)` 为期望接受 token 数（在线逻辑回归估计首 token 接受概率与后续条件延续概率），`+1` 对应每轮必得的贪心 token。`ℓ_max = 64`，并受输出序列边界截断。控制器还会偶尔探索相邻长度。

**（2）Early Inference via Next-Screen Prediction（基于下一屏预测的提前推理）**

- **交互经验记忆 Mint**：每条完成的 GUI 转移存为 `(φ(S_j), σ(a_j), h^a_j, S_{j+1})`，其中 `φ` 是感知哈希（pHash）、`σ` 是动作类型与参数签名、`h^a_j` 是生成该动作时模型上下文的均值池化表示。
- **双索引检索**：**直接索引**以 `(φ(S_j), σ(a_j))` 为键，要求屏幕哈希与动作签名同时精确匹配；未命中时回退到**潜在索引**（以 `h^a_j` 查询，余弦阈值 0.98）。记录在 `a_j` 生成时计算键，但只有在应用真正暴露 `S_{j+1}` 后才补全，因此只包含真实观测到的转移。
- **A2O 间隔内提前推理与验证**：检索到候选下一屏 `S_{j*+1}` 后，仅用它替换下一步输入中的屏幕组件，在应用执行当前动作期间启动下一步推理；当真实 `S_{t+1}` 到达后，比较其应用内容与候选屏是否一致。一致则采用提前计算结果，否则丢弃并回退到普通推理。**验证通过前不向应用发送任何动作**，故同样无损。

**（3）Cross-Step State Carryover（跨步状态传递）**

- **Prompt 前缀 KV 复用**：对相邻动作步提示词的最长相同前缀，直接回收其 KV 状态，从共享前缀之后继续计算。
- **滚动图像 KV 复用**：多截图滑窗推进时，保留截图在提示词中的位置发生偏移，常规前缀缓存无法复用。PastForward 将保留视觉 token 块映射到新位置并用 RoPE 旋转校正键：
  `K̃_{m'} = R(m') R(m)^{-1} K̃_m`，值状态不变。该操作仅修正位置编码、无法重建已改变的因果上下文，因此**是近似复用**，仅施用于保留截图，新观测屏幕与变更文本照常计算。
