## 摘要
大型语言模型（LLMs）在自然语言理解和生成方面取得了显著成功，但其部署受到高计算需求的限制。直接在边缘部署较小的LLM可以规避这一问题，但会降低准确性。在云端部署较小的超大模型可以保持性能，但代价是昂贵的逐token计算。我们提出了一种分布式推理框架\our{}，它在边缘和云之间集成了推测解码（SD）。部署在边缘的紧凑草稿模型快速生成候选token，而云端的大型验证模型并行验证这些token。接受的token被保留，只有被拒绝时才触发验证模型的纠正，从而大幅减少了云端查询次数。我们的即插即用设计将大部分计算转移到边缘，显著降低了推理时间和云成本，并在无需任何重新训练的情况下保持了大型模型的准确性。我们的方法展示了一条在真实环境中实现可扩展、成本高效且准确部署LLMs的实用路径。使用SpecBench和CNN/Dailymail数据集进行的多项自然语言处理任务的实验结果表明，与完整模型相比，\our{}在零精度损失的情况下将云端模型调用减少了76%。

## Abstract
Large Language Models (LLMs) have achieved remarkable success in natural language understanding and generation, but their deployment is constrained by high computational demands. Deploying smaller LLMs directly on the edge can circumvent this, but with degraded accuracy. Deploying smaller cloud-based big LLMs preserves performance, but at the cost of expensive per-token computation. We present a distributed inference framework, \our{}, that integrates speculative decoding (SD) across edge and cloud. A compact draft model deployed on the edge generates candidate tokens rapidly, and a large verifier model on the cloud validates these tokens in parallel. Accepted tokens are retained, while only rejections trigger verifier correction, substantially reducing the number of cloud queries. Our plug-and-play design shifts the bulk of computation to the edge, significantly lowers inference time and cloud cost, and preserves the accuracy of the big model without any retraining requirement. Our approach demonstrates a practical path toward scalable, cost-efficient, and accurate deployment of LLMs in real-world environments. Experimental results across multiple Natural Language Processing tasks using SpecBench and CNN/Dailymail datasets demonstrate that \our{} reduces the cloud model calls by $76\%$ with zero loss in accuracy as compared to the full model.

### 1. 论文的核心问题与整体含义（研究动机和背景）

大型语言模型（LLM）虽在自然语言处理领域取得了显著成功，但其部署面临一个根本性的两难困境：

- **边缘端部署**：在移动设备或边缘设备上部署小型LLM，虽然计算开销低，但模型精度明显下降，无法满足复杂任务需求。
- **云端部署**：在云端托管大型模型可获得最佳性能，但LLM的自回归生成机制需要对每个token进行完整模型推理，导致推理延迟高、云端计算成本和资源占用随会话时长线性增长。

现有的模型压缩技术（如剪枝、量化、知识蒸馏）虽然能降低计算负担，但均以牺牲一定精度为代价；即便专为高效设计的模型变体，其性能也始终不及完整模型。因此，核心研究问题是：**如何在保证大型模型精度的前提下，同时降低推理延迟和云端成本？**

SPADE提出了一种分布式推理框架，通过在边缘设备与云端之间进行智能分工，在代价与性能之间实现了有效平衡。其核心理念是：**将大部分生成计算迁移至边缘，同时利用云端资源保证最终输出质量不低于大模型独立推理**。

### 2. 论文提出的方法论

#### 2.1 核心思想

SPADE将推测解码（Speculative Decoding, SD）应用于边缘-云分布式推理场景：

- **边缘草稿模型（Draft Model, Mq）**：在边缘部署一个小型轻量模型（如LLaMA-3.2-1B），在本地快速生成候选token序列。
- **云端验证模型（Verifier Model, Mp）**：云端托管一个大型高精度模型（如LLaMA-3.1-8B），以单次前向传播并行验证边缘生成的候选token块，仅对不匹配的token进行纠正。

#### 2.2 关键技术细节

**验证标准**：设 `p(x)` 为云端目标模型的概率分布，`q(x)` 为边缘草稿模型的分布。候选token `x ~ q(x)` 被接受的概率为组合函数：

```
α(x) = min(1, p(x) / q(x))
```

**拒绝修正**：若token被拒绝，则从调整后的分布中重新采样替代token：

```
p′(x) = norm(max(0, p(x) − q(x)))
```

该机制保证了生成的序列在分布上严格等价于仅由验证模型（云端大模型）单独解码的结果，即**零精度损失**。

#### 2.3 算法流程

SPADE的整体流程如下：

1. **初始化**：输入用户提示，设定草稿长度参数 d。
2. **边缘生成**：边缘草稿模型 `Mq` 自回归生成 d 个候选token。
3. **云端验证**：将候选token块传输至云端，大模型 `Mp` 在单次前向传播中并行计算所有候选位置的概率。
4. **接受与修正**：依据 α(x) 接受最长前缀；首个被拒token用修正分布采样替换；丢弃其余候选token。
5. **上下文更新**：将接受和修正后的token追加至输出序列，更新上下文后边缘模型继续生成下一个候选块。
6. **迭代**：重复上述过程直至生成结束符。

**草稿长度 d 的作用**：d 是平衡计算与通信的关键超参数——较小的 d 增加验证频率和同步开销，较大的 d 则增加token拒绝概率和边缘计算成本。论文指出d通过监测初始验证集上的接受率来经验性选取。
