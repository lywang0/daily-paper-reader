## 摘要
混合大语言模型（LLM）的快速演进——其交错堆叠分组查询注意力（GQA）、状态空间模型（SSM）和混合专家（MoE）层——给近内存处理（NMP）架构带来了两大根本性挑战。第一，技术墙：传统的6F^2 DRAM单元在10纳米级节点正接近其物理缩放极限，难以满足拥有数百个专家的MoE模型的内存容量需求。第二，架构墙：现有的NMP设计针对狭窄的算术强度（Op/B）范围，无法高效支持混合LLM的异构计算特征，涵盖内存受限的SSM层、计算密集的GQA层，以及各专家间巨大的Op/B差异。我们提出了NOVA，一种技术-架构协同设计的NMP系统，克服了这两大壁垒。在技术层面，NOVA将4F^2垂直沟道晶体管（VCT）DRAM单元与单元上外设（POC）结构相结合，在相同面积下相较于传统基于6F^2的DRAM实现了约2倍的内存密度，从而可继续扩展至10nm以下节点。在架构层面，NOVA重新利用POC外设晶圆（peri-die）来承载处理单元，形成两层NMP架构：第1层（peri-die NMP）负责低至中等Op/B操作，第2层（base-die NMP）负责中至高等Op/B操作。跨层并行执行支持混合LLM的多样化计算模式，最大化推理性能。在最先进的混合与MoE LLM（包括Nemotron3-Nano、Nemotron3-Super、Falcon-H1R和Qwen3）上的评估表明，与GPU基线相比，NOVA平均实现4.5倍的吞吐量提升、69.8%的端到端延迟降低以及5倍的能效提升，而面积开销仅为3.9%，且内存容量无损失。

## Abstract
The rapid evolution of hybrid large language models (LLMs), which interleave grouped-query-attention (GQA), state-space model (SSM), and Mixture-of-Experts (MoE) layers, introduces two fundamental challenges for near-memory processing (NMP) architectures. First, the Technology Wall: the conventional 6F^2 DRAM cell is approaching its physical scaling limits at 10nm-class nodes, making it difficult to meet the memory capacity demands of MoE models with hundreds of experts. Second, the Architecture Wall: existing NMP designs target narrow arithmetic intensity (Op/B) ranges and cannot efficiently support the heterogeneous compute characteristics of hybrid LLMs, spanning memory-bound SSM layers, compute-intensive GQA layers, and large Op/B variations across experts. We propose NOVA, a technology-architecture co-designed NMP system that overcomes both walls. On the technology side, NOVA combines a 4F^2 vertical channel transistor (VCT) DRAM cell with a peri-over-cell (POC) structure to achieve approximately 2x memory density at iso-area over conventional 6F^2-based DRAM, enabling continued scaling into sub-10nm nodes. On the architecture side, NOVA repurposes the POC peripheral-die (peri-die) to host processing units, forming a 2-tier NMP architecture: Tier-1 (peri-die NMP) for low-to-mid Op/B operations, and Tier-2 (base-die NMP) for mid-to-high Op/B operations. Parallel execution across tiers supports diverse compute patterns for hybrid LLMs, maximizing inference performance. Evaluated on state-of-the-art hybrid and MoE LLMs including Nemotron3-Nano, Nemotron3-Super, Falcon-H1R, and Qwen3, NOVA achieves on average 4.5x higher throughput, 69.8% lower end-to-end latency, and 5x better energy efficiency over a GPU baseline, with only 3.9% area overhead and no loss in memory capacity.

### 1.1 背景
- 现代 LLM 推理系统的核心瓶颈已从算力转向**内存带宽与容量**，长上下文、多模态处理、推理任务及大规模批处理导致 KV cache 体积激增。

### 1.2 两大挑战：技术墙与架构墙
- **技术墙**：传统 6F² DRAM 单元在 10nm 级节点逼近物理缩放极限，最小单元电容难以维持，导致感测裕度退化与数据保持问题。HBM 容量增速（每代约 2×）远远落后于算力增速（60,000×/20 年），难以满足混合 LLM 对内存容量的指数级需求。
- **架构墙**：混合 LLM 中 GQA、SSM、MoE 三种层的计算特征高度异构：
  - SSM 为内存受限型，Op/B 极低（约 2）；
  - GQA 的 Op/B 较高（约 16）；
  - MoE 内部由于动态路由，hot/cold expert 的 Op/B 差异可达 5 倍以上。
  - 现有 NMP 方案（in-die、base-die、HB NMP）均只针对特定窄 Op/B 区间优化，无法高效覆盖全谱段。

### 1.3 核心含义
需要一种**同时突破技术缩放限制和架构异构适配瓶颈**的协同设计方法，在高内存密度、高带宽、高计算灵活性的统一架构中支撑混合 LLM 推理。

## 二、方法论：NOVA 技术架构

### 2.1 核心思想
NOVA 通过**技术-架构协同设计**同时应对两大挑战：
- 技术层面：以 4F² VCT DRAM 单元 + POC 结构实现约 2× 内存密度提升，突破 6F² 单元缩放极限。
- 架构层面：将 POC 结构中外设晶圆（peri-die）重新利用为 NMP 处理单元承载体，与 base-die NMP 构成双层异构计算架构。

### 2.2 关键技术细节

**（1）4F² VCT DRAM + POC 结构**
- 4F² VCT 单元：通过垂直沟道布局将存取晶体管与电容在垂直方向解耦，在保持单元整体尺寸的同时实现 4F² 紧凑布局，细胞面积较 6F² 缩小 1.5 倍。
- POC 结构：将传统并置于单元阵列旁的外围电路（SWD、BLSA 等）通过混合键合（HB）堆叠到独立外设晶圆上，使外设区域与单元阵列完全重叠。相比 PUC（Peri-Under-Cell），POC 避免了 BEOL 路由资源占用约 30% 的开销。
- 综合效果：4F² 的 1.5× 与 POC 的 1.39× 面积缩减相结合，实现约 2.09× 的等面积密度增益。
- 关键创新：将外设晶圆改用**逻辑工艺**制造，利用其更高的面积效率在释放的空白区域内集成处理单元，且不占用任何单元面积。

**（2）2-Tier NMP 架构**
- 层次结构：
  - 单元晶圆（cell-die）与外设晶圆（peri-die）通过 HB 堆叠构成 **NOVA-die pair**；
  - 多个 NOVA-die pair 垂直堆叠在共享 base-die 上；
  - **Tier-1**：peri-die NMP，利用 HB 高内部带宽，优化低至中 Op/B（SSM、cold expert）；
  - **Tier-2**：base-die NMP，基于 TSV 连接，利用 4nm 逻辑工艺的高算力，优化中至高 Op/B（GQA、hot expert）。
- 两种粒度处理单元：
  - **BAPU（Bank-level PU）**：每个 bank 一个，支持 2Kb 粒度读取，执行 SSM 状态更新和 GEMV；
  - **BGPU（Bank-group-level PU）**：每 2 个 bank-group 一个，执行 softmax、激活、累加等后处理。
- **Base-PU**：每个伪通道（pCH）配备 32 个 GEMV 单元，提供 64 TFLOPS 峰值算力。

**（3）三层执行模式**
- **Tier-1-only**：低 Op/B 操作（如 SSM）仅用 peri-die，充分挖掘 bank 级并行；
- **Tier-2-only**：高 Op/B 操作（如高复用 GQA）仅用 base-die；
- **Cross-tier parallel**：中等 Op/B 操作（如热/冷 MoE、中等复用 GQA）两 tier 并行执行，通过 pCH 级交错实现 TSV 传输与计算重叠。

**（4）数据映射与执行流程**
- 数据按 batch/head（GQA、SSM）或 experts（MoE）维度跨 cube 静态划分，无需跨 cube 通信；
- GQA 采用 FlashAttention-2 风格的 fused tiling，Tier-1 使用 2-tile 交错隐藏 softmax 延迟；
- SSM 状态更新、写回和 GEMV 输出在 BAPU 内并行执行，重叠写回延迟；
- MoE 中 hot expert 在 Tier-2 执行（权重复用率高），cold expert 在 Tier-1 执行（逐 token 处理），按 1:9 静态比例划分，支持自适应动态分配策略。

## 六、主要结论与发现

1. **性能提升**：相比 GPU 基线，NOVA 平均实现 4.5× 更高吞吐量、69.8% 端到端延迟降低、5× 能效提升（论文摘要数据；正文 Fig. 11 显示混合模型上吞吐平均 4.2×，Qwen3 上 4.8×）。
2. **技术优势**：4F² VCT + POC 结构的 2× 密度增益使得 256K 长上下文推理在单 GPU + 5 HBM 配置下**仅 NOVA 可行**，其余基线均 OoM。
3. **架构优势**：双层 NMP 并行执行有效覆盖全 Op/B 谱系，跨层并行模式比单层模式在 Nemotron3-Nano 和 Qwen3 上分别提升 1.7× 和 3.0×。
4. **Per-operator 加速**：
   - GQA：较 AttAcc/Duplex/PIMBA 平均加速 2.61×/1.96×/2.67×；
   - SSM：较 PIMBA 平均加速 5.78×；
   - MoE：较 Duplex 平均加速 1.64×。
5. **面积开销**：总面积增加仅 5.55 mm²（约 3.94%），其中 BAPU 可完全隐藏于 POC 结构空白区，Base-PU 利用 base-die 自身多余空间，实际**有效面积开销接近零**。
6. **自适应分配策略**：相比静态 1:9 划分，在路由分布偏移场景下最高可获 2.1× 加速。

## 七、优点

1. **技术-架构协同创新**：率先将 4F² VCT DRAM 和 POC 结构从单纯的密度增强手段升级为 NMP 架构设计的使能技术，开创了工艺/架构协同设计范式。
2. **无容量折损的 NMP 设计**：相较于传统 in-die NMP（牺牲 20%+ DRAM 面积），NOVA 将 PUs 完全置于逻辑工艺 peri-die 的冗余空间，实现 NMP 能力与内存容量兼得。
3. **双层 roofline 叠加理念**：利用 HB 与 TSV 两条独立带宽路径实现跨层并行，将两个窄 Op/B 优化区间的 NMP “拼接”为连续宽带覆盖，突破单一架构的性能上限。
4. **灵活性**：
   - 数据映射 tier 无关，热/冷专家划分为纯计算分配决策，可在解码步骤间以零迁移成本切换；
   - 天然支持连续批处理（KV/状态分区的固定地址运算）；
   - 三种执行模式可根据实际 Op/B 动态选择。
5. **实验深度**：多模型、多配置、多基线、多维度评估 + 消融、容量可行性、分配鲁棒性验证，结论扎实。

## 八、不足与局限

1. **能效的权衡**：在 Qwen3 上，NOVA 将能效优先让位于性能最大化（能效提升仅 2.4× vs Duplex 的 6.7×），SSM 状态更新的频繁 DRAM 激活消耗大量动态功耗，更重负载下能效有下降趋势——**性能-能效平衡需要更精细的调节机制**。
2. **MoE 覆盖程度有限**：仅处理了 FFN 层的 up/down projection，GQA/SSM 的输入/输出投影（In/Out Proj.）和 prefill 阶段仍在 GPU 上执行，留有大量未卸载的计算（Falcon-H1R 中占比最显著）。
3. **对新兴技术成熟度的依赖**：4F² VCT 和 POC 仍属未来技术，尚无大规模量产验证；TSV 数量翻倍（4096）的工艺可行性与成本未做详细评估。
4. **模拟而非实测**：所有结果基于周期精确模拟与 RTL 综合，缺乏真实芯片原型验证，功耗/时序数据可能偏离实际。
5. **对比基线覆盖不足**：未包含 HB-NMP 代表（H2-LLM、Stratum）和预填充加速方案（HLX）的直接对比，不公平性风险客观存在。
6. **批次与上下文范围有限**：最大 batch 为 64，最大输入序列为 8K（除容量可行性测试），未覆盖更大批次和更长序列下的实际表现。
7. **服务场景假设理想化**：假设预填充在 xPU 上完成且新请求在迭代边界加入，对在线流式场景中请求交错到达的处理复杂度提及较少。
