## 摘要
思维链（CoT）提示通过将复杂问题分解为中间步骤来提升大语言模型（LLM）的推理能力，但其顺序性增加了解码延迟和内存占用。混合专家（MoE）模型通过稀疏专家激活来扩展容量，然而其完整的专家权重往往超出GPU内存，需要昂贵的GPU-CPU传输。现有运行时对所有令牌一视同仁，忽略了CoT轨迹的一个关键结构特性：连续的推理阶段表现出连贯且可预测的专家激活模式。忽视这种阶段级规律会导致缓存效率低下和不必要的数据移动。我们提出SAEM，一种阶段感知的MoE推理运行时，它检测推理阶段的边界，并利用阶段级激活一致性来指导专家放置。SAEM结合了阶段感知缓存、专家对齐的令牌重打包和原位CPU执行，以减少数据传输和内核碎片化。在数学和科学推理工作负载上，在受限GPU内存下，SAEM相比最强的现有缓存和卸载基线，平均实现了1.33倍的吞吐量提升；当校准数据与工作负载匹配时，提升可达1.54倍，这证明了阶段感知、局部性驱动的MoE推理在CoT推理中的有效性。

## Abstract
Chain-of-thought (CoT) prompting improves LLM reasoning by decomposing complex problems into intermediate steps, but its sequential nature increases decoding latency and memory usage. Mixture-of-Experts (MoE) models scale capacity through sparse expert activation, yet their full expert weights often exceed GPU memory and require costly GPU-CPU transfers. Existing runtimes treat all tokens uniformly, overlooking a key structural property of CoT traces: consecutive reasoning stages exhibit coherent and predictable expert activation patterns. Ignoring this stage-level regularity leads to inefficient caching and unnecessary data movement. We propose SAEM, a stage-aware MoE inference runtime that detects reasoning stage boundaries and exploits stage-level activation coherence to guide expert placement. SAEM combines stage-aware caching, expert-aligned token repacking, and in-situ CPU execution to reduce data transfer and kernel fragmentation. On mathematical and scientific reasoning workloads, SAEM achieves an average 1.33x throughput improvement over the strongest state-of-the-art caching and offloading baselines under constrained GPU memory, rising to 1.54x when calibration data matches the workload, demonstrating the effectiveness of stage-aware, locality-driven MoE inference for CoT reasoning.

## 1. 论文的核心问题与整体含义

- **研究背景**：思维链（Chain-of-Thought, CoT）提示能显著提升大语言模型（LLM）在复杂推理任务（如数学、科学）中的表现，但自回归生成过程会带来长序列解码，导致延迟升高和显存压力增大。Mixture-of-Experts（MoE）模型通过稀疏专家激活扩展模型容量，但完整专家权重往往超出 GPU 显存，需要频繁进行 GPU–CPU 权重传输，成为推理瓶颈。
- **核心问题**：现有 MoE 推理运行时（如基于 token 级缓存、专家预取或 CPU 卸载）将所有生成的 token 一视同仁，忽略了 CoT 轨迹中的**阶段级结构规律**——推理过程可划分为多个语义连贯的阶段（如初始推导、替代路径探索、自我纠正、结论验证），且相邻阶段的专家激活模式高度相似（平均时序一致性约 89%）。因此，现有方法产生冗余的专家迁移、缓存效率低、内核碎片化严重。
- **整体含义**：论文提出 **SAEM（Stage-Aware Expert Management）**，一个利用 CoT 阶段级激活一致性来指导专家放置的运行时系统，在受限 GPU 显存下显著提升 MoE 推理吞吐量，为资源受限环境中的高效 CoT 推理提供了新的“数据感知/结构感知”优化思路。

## 2. 论文提出的方法论

- **核心思想**：通过轻量级手段检测 CoT 推理中的**阶段边界**，并依据阶段级专家激活统计来更新 GPU 专家缓存，同时配合 token 重打包和 CPU 原位执行，减少 PCIe 传输和内核启动开销。
- **关键技术细节**：
  - **推理阶段边界检测**：
    - 采用轻量级**词汇模式匹配**，识别如“Alternatively”“Instead”“On second thought”等话语转换线索，避免引入额外神经网络语义解析。
    - 离线阶段：基于校准数据，通过 `TC_seq`（相邻阶段专家激活矩阵的平均层间余弦相似度）指标对全局候选转移词集进行剪枝，得到模型专用紧凑词集 `T_model`。
    - 在线阶段：使用**有限状态机 + 滑动窗口**，对生成的 token 流进行部分匹配，跨子词跟踪线索；一旦匹配成功，触发阶段转换事件并收集/重置该阶段的激活统计。
  - **阶段感知缓存管理**：
    - 初始化时，非 MoE 层常驻 GPU；MoE 专家按用户指定的 Expert Cache Ratio（ECR）分配固定 GPU 缓存区。
    - 在每个阶段边界，根据前一个阶段的专家激活频率，对每层 GPU 缓存槽进行局部替换；利用相邻阶段 >90% 的激活重叠，使缓存更新与推理语义变化同步。
    - **延迟隐藏预取**：在阶段边界触发后，通过异步 DMA 将下一阶段可能需要的专家权重预取到 GPU，并利用 GPU 事件机制与计算重叠，最小化缓存更新代价。
  - **专家对齐 token 重打包（Expert-Aligned Token Repacking）**：
    - 在每层 MoE 中，按专家 ID 将 token 分组并连续放置，消除书签方式（Bookkeeping）中分散的 token 访问和碎片化内核启动，使每个专家在一次批处理内核调用中完成计算。
    - 预分配工作区，重打包开销仅为轻量级重索引。
  - **原位 CPU 执行（In-Situ CPU Execution）**：
    - 对非 GPU 驻留专家，决定是否直接在当前 CPU 节点执行（避免 PCIe 传输）或传输到 GPU，依据是专家对应的 token 数量；token 少时 CPU 执行更优。
    - 支持 NUMA 感知的 CPU 执行，线程和内存绑定在同一 CPU 插槽，减少跨 socket 访存；GPU 和 CPU 路径输出通过轻量级同步合并。

## 3. 实验设计

- **模型**：
  - Qwen3-30B-A3B（Qwen3）：48 个块，128 个 routed experts，top-8，总参数 30.5B。
  - ERNIE-4.5-21B-A3B-Thinking（ERNIE-4.5）：28 个块，2 个 shared experts，64 个 routed experts，top-6，总参数 21.8B。
- **数据集**：
  - MATH-500（500 道奥林匹克数学题，7 个领域）——主要基准，也用于离线校准。
  - AIME 2024（30 道竞赛数学题）——held-out。
  - GPQA-Diamond（198 道研究生级科学选择题，物理/化学/生物）——held-out 且领域偏移。
- **对比基线**：
  - MoE-OnDemand：非驻留专家按需从 CPU 取到 GPU。
  - Mixtral-Offloading：基于 LRU 的 token 级专家缓存迁移。
  - Fiddler：非驻留专家直接在 CPU 执行。
  - DAOP：基于句子级激活统计的专家划分与预测预计算。
- **实验参数**：
  - batch size：1、4、8。
  - Expert Cache Ratio（ECR）：3.125%、6.25%、12.5%、25%、50%。
  - 评价指标：端到端吞吐量（tokens/s）。
- **附加分析**：
  - **预测-预言机（Prediction-Oracle）上界分析**：比较在线预测策略（用上一阶段 EAP 指导缓存）与“完美预知下一阶段 EAP”的缓存命中率效率和吞吐效率（仅切换提供给放置规划器的激活档案，固定序列重放）。
  - **消融研究**：在 Qwen3、12.5% ECR 下，分别测试“仅阶段感知缓存更新”“仅原位 CPU 执行”“仅 token 重打包”“三者全开”，以及“关闭原位 CPU 执行、改用 GPU 按需传输”的变体。

## 6. 论文的主要结论与发现

- **阶段级激活规律真实存在且可被利用**：在 CoT 推理中，相邻阶段的专家激活矩阵平均时序一致性约 89%（MATH-500、AIME、GPQA 上均 >85%），不同推理阶段激活的专家子集不同。
- **SAEM 在受限显存下显著提升吞吐量**：
  - 整体平均比最强基线提升 **1.33×**；当校准数据与工作负载匹配时提升 **1.54×**（MATH-500 上 Qwen3 平均 1.60×、ERNIE-4.5 平均 1.47×；AIME 上 1.20×/1.21×；GPQA-Diamond 上 1.14×/1.34×）。
  - 低 ECR、高 batch size 时优势更明显（如 Qwen3 batch 8、3.125% ECR 下比 Mixtral-Offloading 提升 2.10×）。
- **各机制互补而非独立**：单独使用原位 CPU 执行反而会降低性能（因为没有正确的缓存策略，GPU 驻留专家集不合适）；只有三者结合才能实现最高吞吐。
- **预测滞后不是主要瓶颈**：预言机分析显示，即使有完美下一阶段 EAP，吞吐提升也仅 1.08–1.14×（batch 1），说明当前系统已接近预测局部最优；主要性能差距来自 GPU 缓存容量本身不足。

## 7. 优点

- **研究方向具有新颖性**：首次明确将 CoT 推理的阶段结构引入 MoE 专家管理，打破 token 级别“一视同仁”的假设。
- **设计轻量、部署友好**：阶段检测仅需词汇模式匹配和自动机，无需额外神经网络；重打包工作区预分配，开销可控；原位 CPU 执行利用了闲置 CPU 算力。
- **系统级协同优化**：缓存管理、预取调度、token 重打包、CPU 执行四者统一设计，而非简单组合。
- **实验分析深入**：包含预言机上界分析、消融研究、时序一致性量化，以及校准匹配/失配对比，对方法有效性和边界条件给出了较全面的证据。
- **代码与硬件设置具体**：硬件配置、NUMA 绑定、固定序列重放等细节提升了实验的可复现性。

## 8. 不足与局限

- **阶段边界检测依赖显式话语线索**：仅关注替代路径探索等有明确词汇提示的阶段；若无“Alternatively”等 cue，或生成风格更自由，边界检测会失效，论文也提及未来可用专家激活熵等隐含信号。
- **校准数据依赖**：离线准备（主导专家统计和 `T_model` 剪枝）依赖代表性校准集；跨域（GPQA）加速比明显下降，说明面对不同推理分布时需要重新校准。
- **实验覆盖有限**：仅单 GPU、单节点、batch size ≤ 8；未验证更大 batch、更长序列、多卡分布式、更多模型族（如 DeepSeek-R1）下的效果。
- **缺少端到端准确率/生成质量指标**：只比较吞吐量，没有报告 SAEM 是否影响输出 token 或推理正确性（虽然理论上缓存不改变路由决策，但未明确验证）。
- **未与量化/剪枝等内存压缩技术深入结合**：论文提到这些方法但未联合评估。
- **预测概率分析中部分数据有测量噪声**（如 100.78% 的吞吐效率），虽解释为亚 1% 波动，也说明实验存在微小不确定性。
