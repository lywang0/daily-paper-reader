## 摘要
在边缘设备上部署大型语言模型日益受到模型大小与可用内存之间不断扩大的差距的限制。现有方法如量化、更小模型和卸载可以提高有效内存上限，但它们仍然假设模型可以被压缩或分区以适配某个预算。我们针对更困难的模型超出内存设置，即在整个执行过程中模型始终大于常驻内存，存储成为关键路径上权重的活跃来源。我们观察到自回归解码过程中的MLP活动具有很强的时间局部性：大约82-85%的活跃神经元从一个token持续到下一个token。这意味着当前token所需的大多数稀疏权重已经驻留，只有新需要的行必须从存储中获取。我们提出了NeuroPrefetcher，一种利用这一特性通过预测性增量预取实现的存储后端LLM推理系统。在第0层之后，一个仅占用基础模型参数2.86%的GPU驻留预测器，在一次前向传播中预测所有下游MLP层的稀疏活动。运行时将这些预测与驻留GPU缓冲区进行比较，仅对新增的增量行发起应用调度的NVMe读取，用显式的、模型感知的权重移动取代反应式的操作系统按需分页。在真实的统一内存边缘硬件上，NeuroPrefetcher在受限内存预算下比llama.cpp实现了7.9-12.0倍的加速。

## Abstract
Deploying large language models on edge devices is increasingly limited by a widening gap between model size and available memory. Existing approaches such as quantization, smaller models, and offloading can raise the effective memory limit, but they still assume that the model can be compressed or partitioned to fit within some budget. We target the harder model-exceeds-memory setting, in which the model remains larger than resident memory throughout execution and storage becomes an active source of weights on the critical path. We observe that MLP activity during autoregressive decoding has strong temporal locality: approximately 82-85% of active neurons persist from one token to the next. This means that most sparse weights needed for the current token are already resident, and only the newly needed rows must be fetched from storage. We present NeuroPrefetcher, a storage-backed LLM inference system that exploits this property through predictive delta prefetching. After layer 0, a single GPU-resident predictor, occupying 2.86% of base model parameters, predicts sparse activity for all downstream MLP layers in one forward pass. The runtime compares these predictions against resident GPU buffers and issues application-scheduled NVMe reads only for incoming delta rows, replacing reactive operating-system demand paging with explicit, model-aware weight movement. On real unified-memory edge hardware, NeuroPrefetcher achieves 7.9-12.0x speedup over llama.cpp across constrained memory budgets.

### 1. 核心问题与整体含义（研究动机与背景）

- **模型-内存差距不断扩大**：过去五年，模型规模以每代约 **10×** 的速度增长，而边缘设备DRAM容量仅增长约 **2×**，导致越来越强大的模型在边缘设备上不仅运行缓慢，甚至根本无法装入内存。
- **现有方法的共同假设缺陷**：量化（GPTQ/AWQ）、小型模型（Phi-3/MobileLLM）、常规卸载（llama.cpp/FlexGen）都试图将模型“压缩/分区”到某一内存预算之内。它们均未针对**模型在整段执行过程中持续大于常驻内存**的更困难场景进行设计。
- **存储成为关键路径**：当内存不足时，存储（NVMe）成为权重的活跃供给层，权重搬运效率直接决定推理性能。llama.cpp依赖操作系统按需分页（demand paging），在 Jetson AGX Orin 上运行 Mistral-7B 时产生 **11,453 次/秒的 major page faults**、CPU iowait 高达 **77%**、GPU 利用率仅 **3%**——推理被反应式的权重搬运所主导。
- **核心观察与机会**：自回归解码中，MLP 激活具有极强的时间局部性——**82–85% 的活跃神经元会从当前 token 持续到下一个 token**。这意味着当前 token 所需的大多数稀疏权重已驻留，只需从存储中获取**新增量（delta）**。现有系统（PowerInfer、LLM in a Flash、Neuralink 等）都没有同时具备"跟踪驻留行集合"与"提前预测下一 token 活跃集"两个能力。

### 2. 方法论

**核心思想：预测性 Delta 预取（Predictive Delta Prefetching）**

系统预测下一 token 所需的稀疏权重，与已驻留权重比较，仅提前获取二者差集（delta），用应用层显式、模型感知的权重移动替代操作系统反应式按需分页。

**架构组成**

1. **离线稀疏质心准备（Offline Sparse Centroid Preparation）**
   - **阈值化**：在每个 MLP 层上按百分位数阈值 $T_{l,\alpha}$ 过滤低幅值激活，将稠密激活向量转为稀疏二值掩码。
   - **聚类**：对高维稀疏二值掩码进行聚类（簇数 $K=512$），每个簇用一个稀疏二值质心表示，将运行时预测空间从逐神经元决策（14,336 维）降为**每层一个质心 ID 选择**。

2. **共享激活预测器（Shared Activation Predictor）**
   - 在第 0 层之后**一次性前向传播**，同时输出第 1~31 层 gate 和 up 投影的质心 ID（共 62 个）；与 DejaVu 的逐层预测不同——后者直到执行到该层才知道活跃集，来不及驱动存储预取。
   - 输入五类特征：token embedding、pre-attention LayerNorm 输出、attention-head sketch、post-attention RMS norm、第 0 层 gate 质心 ID（结构特征）。
   - 架构：四个投影块（Linear→LayerNorm→SiLU→Dropout）→ 残差 MLP trunk → 31 组独立线性 head（gate/up 各一组）。
   - 参数规模：**206.8M 参数（2.86% 基础模型）**，FP16 占用 414 MB，运行一次 token 一次。

3. **预测性 Delta 预取运行时（Predictive Delta Prefetching Runtime）**
   - 有效活跃集为 gate 与 up 质心掩码的交集（SwiGLU 神经元需两者同时激活）。
   - 每层维护容量为 $K_{max}$ 的 GPU 驻留行缓冲区，通过**集合差**更新：
     - $D^{(l)}_{in} = A^{(l)}_t \setminus A^{(l)}_{t-1}$（需从 NVMe 获取的新行）
     - $D^{(l)}_{out} = A^{(l)}_{t-1} \setminus A^{(l)}_t$（释放缓冲区槽位）
   - 每层维护槽位映射表 $S^{(l)} \in \mathbb{Z}^M$，记录神经元对应缓冲区槽位；释放槽位直接复用，无需压缩。
   - 首个 token 冷启动加载完整预测活跃集，后续 token 仅走 delta 路径。

4. **I/O 路径（NVMe-to-GPU 稀疏行传输）**
   - **神经元中心化权重布局**：离线将 gate/up/down^T 每行 24.5 KiB 重打包为连续记录，单次读即可取齐一个活跃神经元所需的三投影行。
   - **io_uring 异步读取**：O_DIRECT 模式，队列深度 256，排序相邻 ID 合并为连续读区间。
   - **缓存一致性暂存**：Jetson 统一内存上直接 I/O 绕过 CPU 缓存相干性，可能向 GPU 暴露陈旧数据；因此先落入 `cudaHostRegisterMapped` 的页对齐暂存缓冲区，再由融合的 `launch_deinterleave_scatter` CUDA 内核（解交织+散布）写入各投影专属缓冲区。
   - **内存自适应稠密/稀疏切分**：前 $d$ 层稠密且完全驻留，后 $N-d$ 层稀疏并维护活跃行缓冲区；内存越紧，稀疏层越多，但不退化为整层 NVMe 读取。

### 6. 主要结论与发现

- **大幅加速**：在"模型超出内存"区间（9.0–13.2 GiB CUDA 内存），NeuroPrefetcher 较 llama.cpp 实现 **7.9–12.0× 加速**；14 GiB 上限下达到 3.22 tok/s（llama.cpp 为 0.34 tok/s）。
- **Delta 复用显著**：82–85% 的稀疏后缀行跨 token 复用，NVMe 每 token 读取量仅 103 MiB（14.8 GiB）至约 1 GiB（9.0 GiB），远低于整模型 13.49 GiB。
- **I/O 仍为主导瓶颈**：延迟分解显示 NVMe I/O 占每 token 延迟的 80–87%，即便 delta 预取之后亦然。
- **质量损失可控**：在 $d=20$ 时，Mistral-7B 保留约 95–96%、Llama-3-8B 约 92–93% 的稠密 HellaSwag 准确率；质量可通过增大 $d$（更多稠密层）换取。
- **生态缺口**：20 个主流推理系统中，16 个在"模型超出内存"场景下无法完成生成——6 个分配失败、6 个统一内存架构不匹配、4 个无 ARM/JetPack 版本；仅 4 个可运行，NeuroPrefetcher 是其中唯一专门为稀疏存储支持执行设计的引擎。

### 7. 优点

- **问题定位精准**：直击现有方法的共同盲区——模型持续超出常驻内存的硬场景，而非重新包装已有的"在内存预算内适配"思路。
- **机制新颖且自洽**：将"激活稀疏性"从纯计算优化提升为 **I/O 调度信号**；跨 token 的 delta 集合差更新机制（驻留集跟踪 + 增量获取）是该领域首创。
- **一次性预测器设计巧妙**：layer 0 后单次前向输出全部 31 层的稀疏图，解决了逐层预测（DejaVu 式）对存储预取而言"太晚"的根本问题。
- **内存自适应分裂**：稠密前缀/稀疏后缀的动态切分提供了 **内存预算-吞吐-质量** 三者的显式控制旋钮，工程实用性强。
- **I/O 路径工程细致**：神经元中心化布局、io_uring 批量读取、缓存一致性暂存、融合解交织散布内核等处理扎实，且明确指出 Jetson 特定组件与可移植部分的边界。
- **能力研究有说服力**：对 20 个系统的生态扫描揭示了大模型边缘部署的系统性架构错配，增强了工作的现实意义。
- 实验报告了预测器 2.86% 额外参数开销为净成本，报告诚实。

### 8. 不足与局限

- **实验覆盖以单平台为主**：所有端到端实验只在 Jetson AGX Orin 上运行；未覆盖 x86+独立 GPU、其他统一内存平台（如 Apple Silicon）或不同的存储介质（eMMC/UFS）。
- **仅支持 FP16 权重格式**：未评估与 4-bit/8-bit 量化结合的效果——虽然文中声称量化"正交"且可适用，但缺少实证数据。
- **I/O 仍占 80–87% 延迟**：delta 预取并未根本改善 I/O 主导地位，论文自己也承认未来需在更深预取流水线、更强读合并、量化稀疏行格式等方面继续突破。
- **模型范围有限**：主要验证 Mistral-7B 和 Llama-3-8B；缺少更大模型（如 30B+）或 MoE 结构的验证；Llama-3-8B 在高稀疏度下质量下降较明显，说明方法对模型族的普适性有待检验。
- **对比基线受限**：无法直接与 PowerInfer、LLM in a Flash、Neuralink 等最相关方法进行系统级对比（受平台限制），削弱了相对排名的说服力。
- **离线步骤开销未量化**：质心聚类训练、预测器训练（8×A100）的算力消耗、时间与能源成本未报告；生产部署的准备工作流成本不透明。
- **质量评估面窄**：困惑度和 HellaSwag 不足以覆盖开放生成、代码、数学推理等任务上的实际质量退化；且仅在 WikiText-2 上构造质心，跨领域的迁移虽初步验证（HellaSwag），但证据仍有限。
