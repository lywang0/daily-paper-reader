## 摘要
大型语言模型已成为底层代码和内核优化的日益强大的智能体，但孤立的内核基准测试仅能提供对语言模型推理中实际部署行为的一种近似评估。我们识别出基准测试与实际部署之间的差距：在独立测试框架中看似正确且快速的候选内核，在集成到实际推理工作负载后可能表现出不同的性能、安全性或阶段行为。我们提出LLM4LLM，一种部署感知的闭环优化框架，该框架从目标推理脚本出发，提取阶段感知的优化任务，通过经验引导的情景化智能体进行搜索，并通过模型内验证接受补丁。在A100和H100 GPU上的十个语言模型推理工作负载中，LLM4LLM显著改善了每个评估模型的端到端延迟，在A100/H100上实现了3.91倍/6.98倍的几何平均加速；作为支持性的内核级证据，它还在KernelBench Level 2上取得了高达2.745倍的几何平均加速。

## Abstract
Large language models have become increasingly capable agents for low-level code and kernel optimization, but isolated kernel benchmarks provide only a proxy for the deployment behavior that matters in language-model inference. We identify a benchmark-to-deployment gap: candidate kernels that appear correct and fast in standalone harnesses can exhibit different performance, safety, or phase behavior after integration into a real inference workload. We introduce LLM4LLM, a deployment-aware closed-loop optimization framework that starts from a target inference script, extracts phase-aware optimization tasks, searches with an experience-guided episodic agent, and accepts patches through in-model validation. Across ten language-model inference workloads on A100 and H100 GPUs, LLM4LLM improves end-to-end latency for every evaluated model, achieving 3.91$\times$/6.98$\times$ geometric-mean speedups on A100/H100; as supporting kernel-level evidence, it also attains up to 2.745$\times$ GeoMean speedup on KernelBench Level 2.

## 1. 论文核心问题与整体含义（研究动机与背景）

- **核心问题**：大语言模型（LLM）已被用于自动化生成和优化 GPU 内核，但现有评估主要以孤立的内核基准（如 KernelBench）为准：候选内核在独立测试框架中通过正确性检查并表现出较低延迟，并不代表它在真实语言模型推理部署中同样有效。论文将这种不一致称为 **benchmark-to-deployment gap（基准到部署的差距）**。
- **背景与动机**：
  - 自回归推理包含 Prefill（预填充）和 Decode（解码）两个语义不同、缓存状态与内存访问模式迥异的阶段；在孤立环境中优化的内核可能在某个阶段无效或性能不迁移。
  - 集成到真实模型后，候选内核可能因分配器状态、缓存状态、调度逻辑、形状守卫等因素出现运行期崩溃、性能回退或阶段行为异常。
  - 作者以卷积层为例说明：同一候选内核在孤立冷缓存测试中显著加速，但在模型内暖缓存上下文中反而变慢，说明无法仅凭孤立基准判断部署收益。
- **整体含义**：LLM 驱动的内核优化应当从“单内核快速评测”转向“部署感知的闭环优化”，将真实推理脚本、目标模型、阶段语义和端到端延迟纳入候选生成、验证与接受的全流程。

## 2. 论文提出的方法论：核心思想、关键技术细节、公式与算法流程

- **总体框架**：LLM4LLM 将优化建模为一个闭环循环：目标推理脚本 → 真实模型 Profiling → 阶段感知任务提取 → 经验引导的智能体搜索 → 部署时模型内验证 → 生成优化部署。
- **阶段划分与部署约束**：
  - 将部署评估划分为四个层级：孤立资格验证、搜索期验证、部署时接受、最终端到端评测。
  - 明确将“基准到部署差距”归因于执行上下文、阶段行为（Prefill/Decode）和集成约束（形状守卫、分配器状态、调度开销等）。
- **热点发现与阶段感知任务提取**：
  - 对目标模型实例 \(M\) 和部署工作负载 \(W\) 做分阶段 profiling，记录模块 \(m\) 在阶段 \(p\) 的耗时 \(t(m,p)\) 与阶段总延迟 \(T(p)\)。
  - 使用工作量加权热点分数选择可部署优化单元：
    \[
    s(m) = \sum_{p \in P} \omega_p \frac{t(m,p)}{T(p)}
    \]
  - 对 Prefill 与 Decode 分别构造任务；当两个阶段都被优化时，提取“分派模板”以将阶段专用内核重新组装为统一补丁。
- **经验引导的情景化（Episode）优化**：
  - 每次 episode 执行“生成候选 → 编译 → 正确性检查 → 延迟测量 → 失败分析”的验证轨迹。
  - 搜索期效用定义为：
    \[
    u(c,\tau) = \frac{t_{\rm ref}(\tau)}{t_c(\tau)} \cdot \mathbb{1}\{\mathrm{err}(c,\tau) \le \epsilon,\ \mathrm{safe}(c,\tau)\}
    \]
    其中包含数值误差约束和编译/运行期安全性检查。
  - **关键设计**：在每个 episode 结束时，不将完整对话轨迹直接传给下一轮，而是将验证轨迹蒸馏为“紧凑经验”，包括有效 tiling 选择、边界掩码要求、阶段谓词、数值约束、失败模式、最佳候选系列；下一 episode 从“原始任务信息 + 紧凑经验”重新开始。
  - 这样既保留可利用的验证知识，又避免长时间局部修复轨迹主导后续搜索。
- **部署时接受与打补丁**：
  - 候选内核需插入真实模型实例，进行模型内正确性、运行时兼容性和形状守卫覆盖检查。
  - 定义规范化部署延迟 \(\ell(c) = L(M[c], W)/L(M, W)\)，并选择满足最小提升阈值 \(\delta\) 的最优候选：
    \[
    c^\star = \arg\min_{c \in C_{\rm dep}} \ell(c), \quad \ell(c^\star) \le 1 - \delta
    \]
  - 被接受的补丁保留分派逻辑与 fallback 路径，确保未优化形状/阶段仍可正确执行。

## 6. 论文的主要结论与发现

- **端到端加速显著**：
  - 在 A100 上所有模型平均几何加速 **3.91×**，在 H100 上为 **6.98×**。
  - Transformer 模型提升较稳定但幅度有限（Qwen3-4B 为 3.03×/3.78×，Llama-2-13B 为 1.79×/1.92×）；Mamba 类模型提升极大（A100 上最高 22.37×，H100 上最高 32.79×）。
- **部署上下文决定收益**：
  - 不同模型家族的最优优化对象不同：Transformer 以注意力为主，Mamba 以状态空间 mixer 为主，RecurrentGemma 以 RGLRU 循环核心为主。
  - 同一补丁在不同 GPU 上的表现不同，说明硬件执行上下文也必须纳入接受标准。
- **LLM4LLM 可与强部署内核竞争**：
  - 注意力场景下，LLM 生成内核在部分 shape 下接近 FlashAttention-2，但在成熟专家内核覆盖良好的场景仍有差距；
  - Mamba mixer 场景下，由于优化边界包含 reshape、投影和 elementwise 更新，LLM4LLM 可达到或优于 mamba_ssm/causal-conv1d。
- **KernelBench 支持性结果**：
  - A100/H100 上 Pass 率 100%/99%，Fast2 39%/41%，GeoMean 2.745×/2.628×。
  - restart 策略优于单纯加大候选预算；采样多样性比线性迭代修复更能发现全新优化范围。
- **总结性观点**：LLM 内核优化应“profile 真实模型、在阶段感知约束下搜索、通过目标运行环境验证后再接受”。

## 7. 优点

- **问题定位准确且有实际价值**：明确提出“基准到部署差距”，并用内存驻留、越界读、阶段不迁移等反例说明孤立内核基准的局限。
- **方法设计闭环且部署导向**：Profiling → 阶段任务提取 → 经验引导搜索 → 模型内验证 → 补丁部署，形成完整闭环；接受标准直接绑定端到端延迟，而不是孤立内核指标。
- **Episodic restart 机制新颖合理**：保留紧凑经验、丢弃长尾修复轨迹，兼顾知识复用与搜索方向多样性。
- **实验覆盖丰富**：涵盖 Transformer、状态空间、循环模型三大架构，兼顾注意力、mixer、RGLRU 等不同算子类型；消融实验跨多个 LLM 骨干。
- **对比方式相对严谨**：
  - 报告端到端、模块级、内核级三层结果；
  - 对 FlashAttention 与 Mamba fast path 做 scope-matched 对比；
  - KernelBench 中区分 Mean/GeoMean 和 Fast 指标，避免误导性聚合。
- **附录提供了可复现的机制解释**，如 restart 在 Problem 97 中将 1.03× 提升到 5.80×，能直观说明搜索状态控制的价值。

## 8. 不足与局限

- **算力开销不透明**：
  - 未报告每次优化所需的候选生成轮数、GPU 小时、LLM API 调用成本或搜索失败样本占比。

- **可解释性有限**：
