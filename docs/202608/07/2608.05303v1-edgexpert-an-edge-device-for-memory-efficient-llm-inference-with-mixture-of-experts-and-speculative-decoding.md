## 摘要
大型语言模型（LLM）的设备端部署已成为个性化边缘应用的关键。主要瓶颈是前馈网络（FFN）层中的外部内存访问（EMA）。投机解码和混合专家（MoE）是有前景的解决方案。投机解码通过每阶段生成多个token来减少解码阶段数量，而MoE通过稀疏专家激活最小化每阶段成本。然而，这两种技术结合时存在不兼容性。我们提出EdgeXpert，一种软硬件协同设计的LLM加速器，解决了这种不兼容性。在预填充阶段，提示级专家重用将路由重新定义为提示级专家重用，而非独立的逐token专家选择。它使用轻量级编码器识别重要token，从中构建共享专家集，并以减少的专家预算路由不太重要的token，以降低专家EMA。在解码阶段，深度感知的专家合并利用同深度候选token的上下文相似性和互斥性。EdgeXpert不是加载所有所需通道的并集，而是仅加载显著通道，并应用计算校准以恢复准确性而无需额外内存访问。EdgeXpert在三星28nm工艺、800 MHz频率下综合实现，与先前工作相比，延迟降低高达56.3%，能耗降低44.1%，同时保持接近基线的准确性。

## Abstract
On-device deployment of Large Language Models (LLMs) has become essential for personalized edge applications. A primary bottleneck is external memory access (EMA) in feed-forward network (FFN) layers. Speculative decoding and mixture-of-experts (MoE) are promising solutions. Speculative decoding reduces the number of decoding stages by generating multiple tokens per stage, and MoE minimizes per-stage cost through sparse expert activation. However, there is an incompatibility when combining these two techniques. We propose EdgeXpert, a software-hardware co-designed LLM accelerator that resolves this incompatibility. In the prefill stage, the prompt-wise expert reuse reformulates routing as prompt-level expert reuse rather than independent per-token expert selection. It identifies important tokens using a lightweight encoder, constructs a shared expert set from them, and routes less important tokens with a reduced expert budget to lower expert EMA. In the decode stage, depth-aware expert coalescing exploits the contextual similarity and mutual exclusivity of same-depth candidate tokens. Rather than loading the union of all required channels, EdgeXpert loads only salient channels and applies computational calibration to recover accuracy without additional memory access. Synthesized in Samsung 28nm technology at 800 MHz, EdgeXpert achieves up to 56.3% latency reduction and 44.1% energy reduction compared to prior works, while maintaining near-baseline accuracy.

# EdgeXpert：一种面向内存高效LLM推理的边缘设备（论文总结）

## 1. 论文的核心问题与整体含义

- **背景**：边缘设备上部署大型语言模型（LLM）具有个性化、低延迟等优势，但单批次自回归推理中，每个输出 token 都需从外部内存加载全部模型参数，导致**外部内存访问（EMA）**成为系统瓶颈，其中**前馈网络（FFN）层的权重 EMA** 占比最大。
- **已有方案**：
  - **投机解码（Speculative Decoding, SD）**：用轻量草稿模型一次生成多个候选 token，再由目标模型并行验证，从而减少解码阶段次数，降低 EMA（每 token EMA ≈ P_total / N_A）。
  - **混合专家（Mixture-of-Experts, MoE）**：每个 token 只激活少量专家，减少每阶段的 FFN 参数加载（EMA = P_total − S × P_expert）。
- **核心问题**：将投机解码与 MoE **直接结合时不兼容**——投机解码产生的多个候选 token 会激活更多专家（如 Qwen3 + EAGLE-3 每阶段激活 52.1 个专家，是原来的 6.5 倍），导致 MoE 层 EMA 反而大幅上升；实际系统能量比自回归解码还高 24.3%。因此，需要专门设计以解决“MoE 与 SD 的内存不兼容性”。
- **整体含义**：EdgeXpert 通过**软硬件协同设计**，在预填充（prefill）和解码（decode）两个阶段分别提出优化策略，将 MoE 与 SD 的优势互补，实现真正内存高效的边缘 LLM 推理。

## 2. 论文提出的方法论

### 2.1 核心设计思想
- 在不改变模型精度语义的前提下，通过**运行时动态路由和通道加载优化**直接减少 EMA，而不是仅仅减少计算量。
- 将“逐 token 独立选专家”重构为**提示级（prompt-level）专家复用**，并在解码阶段利用候选 token 的**深度维特征**来压缩专家通道加载。

### 2.2 预填充阶段：提示级专家重用（Prompt-wise Expert Reuse）
- **思路**：先用轻量级编码器（如 all-MiniLM-L6-v2）基于 CLS 注意力识别 token 重要性，将输入 token 分为三类：**major（重要）、minor（次要）、trivial（不重要）**。
- **流程（Algorithm 1）**：
  1. major token 按原始路由预算（top-k）选择专家，这些专家构成**共享专家集 E**。
  2. minor token 保留 top-1 专家，其余名额优先从与 E 的交集中选择（reuse_route），若不足则用 top_k_route 补充。
  3. trivial token 使用更激进的预算（k 更大、n 更小），同样优先复用更新后的 E。
- **关键参数**：通过搜索 MoE 层输出 MSE 与激活专家数 REMA 之间的帕累托前沿确定 (k, n)，既控制精度损失又最小化 EMA。
- **硬件支持**：分区网络（partitioning network）用并行比较器和蝴蝶重排单元，支持 128 token/cycle 的可变长度输入，避免全局排序带来的高延迟，预填充专家 EMA 降低 55.7%。

### 2.3 解码阶段：深度感知专家合并（Depth-aware Expert Coalescing）
- **动机**：已有细粒度通道剪枝（如 SMoLPU）能降低计算量，但硬件仍需加载所有候选 token 所需通道的**并集**，EMA 减少有限。
- **关键观察**：
  - 同深度候选 token 具有**上下文相似性**（≥3 个专家共激活比例高达 88.4%）；
  - 同一深度只有一个 token 会被接受（**互斥性**），其余都被丢弃。
- **方法**：
  - 不加载全部通道并集，而是计算每个通道的**显著分数（S_s）与通道分数（S_c）**（基于输入幅度 × 注意力权重聚合），仅加载分数超过阈值（sr × S_C）的“显著通道”。
  - 引入**计算校准（Computational Calibration）**：让所有路由 token 在已加载的显著通道上重新计算，而不是只计算各自剪枝子集；这虽增加计算，但无需额外 EMA，可恢复精度和接受长度。
  - 选择比例 sr 通过保证接受 token 的通道覆盖率 ≥75% 来确定。
- **硬件支持**：双可重构加法树（dual RAT）同时处理多个深度组，减少合并单元延迟 76.7%。

### 2.4 系统架构要点
- 8 个簇，每簇 4 个核，共 8K MAC，512 KB 全局 SRAM，支持 A8W4（8-bit 激活、4-bit 权重），峰值吞吐 13.1 TOPS。
- 预填充阶段采用广播 NoC 高复用；解码阶段按输出通道维加载权重，保持 DRAM 访问连续性。
- 顶层控制器包含 PRU（提示级专家重用单元）和 DCU（深度感知合并单元），通过动态跳过不必要的专家/通道数据，从硬件层面将稀疏性转化为 EMA 缩减。

## 6. 论文的主要结论与发现

- EdgeXpert 成功解决了投机解码与 MoE 的内存不兼容问题，使两者互补：MoE 减少每阶段激活权重，SD 减少解码阶段数。

- **硬件开销低**：顶层控制器仅占芯片面积 14.1%、功耗 8.6%，且其执行与 MAC 操作重叠，不影响整体吞吐。

- **直接针对瓶颈 EMA**：与多数仅减少计算的剪枝方案不同，EdgeXpert 在软硬件层面直接将稀疏性转化为内存流量减少。

- **权重量化与精度报告的粒度有限**：虽然硬件支持 A8W4，但软件实验以 bf16 运行后模拟量化效果，未详细报告量化误差分项，也没有逐层分析 4-bit 权重与近似通道剪枝叠加后的交互效应。
- **能量模型依赖外部 DRAM 假设**：所有能耗估计基于固定的 16 GB/s 带宽和特定 DRAM 访问能耗模型，未考虑不同内存技术（如 LPDDR、HBM）或带宽变化对 EMA 能耗占比的影响，结论泛化性受限。
- **缺乏对多租户或并发请求场景的验证**：边缘设备可能同时服务多个用户请求，论文实验均为单请求（单提示）场景，未考察专家复用和通道合并策略在多请求交错下的公平性、吞吐稳定性和缓存失效开销。

## 9. 未来研究方向与开放性启发

- **扩展到更大规模模型与更长上下文**：将提示级专家复用和深度感知通道合并推广到 100B+ 级 MoE 以及 128K 以上长上下文场景，需要重新评估分区网络的多周期延迟和深度维相似性是否仍然成立。
- **适配更多投机解码框架**：探索与 Medusa、Big-Little、推测流式（speculative streaming）等不同候选生成结构的兼容性，特别是当候选 token 间深度维相关性减弱时，如何自适应调整显著通道比例 sr。
- **动态阈值与在线自适应**：目前 sr 和预算 (k, n) 依赖离线校准，未来可利用运行时反馈（如接受长度、路由分布漂移检测）实现阈值在线微调，增强对输入分布变化的鲁棒性。
- **软硬件协同的端到端验证**：将 EdgeXpert 控制器集成到真实 SoC（如与 RISC-V 处理器、NoC 和 DRAM 控制器共同流片），测量实际 EMA、功耗墙和热量约束下的真实性能，验证综合结果的可转化性。
- **跨层联合优化**：除 FFN 层外，可将注意力层（如 KV cache 压缩、FlashAttention 优化）与 EdgeXpert 的专家/通道跳过策略统一纳入 EMA 削减框架，进一步降低每 token 总内存流量。
- **安全性评估**：近似推理下模型输出的置信度校准、幻觉率和对抗鲁棒性尚未研究，这是实际医疗、金融等敏感边缘应用落地前必须补齐的一环。

## 10. 总体评价

EdgeXpert 是一篇高质量的系统论文，其最大贡献在于**准确识别并量化了 MoE 与投机解码直接结合时“专家激活膨胀”导致的内存流量反弹问题**，并从算法（提示级专家复用、深度感知通道合并、计算校准）和硬件（分区网络、双可重构加法树、顶层控制器）两方面给出了一套自洽且可实现的解决方案。实验设计上，统一的工艺/频率/带宽归一化和分布级超参数校准体现了良好的方法论规范性；性能数据（延迟最高降低 56.3%、能耗最高降低 44.1%、精度损失可控）也颇具说服力。虽然缺乏流片验证、只测试 EAGLE-3 以及与其他最新 MoE-SD 方案的定量对比仍是明显短板，但整体而言，该工作对边缘 LLM 推理的内存瓶颈理解深刻，所提出的“将冗余计算转化为内存跳过”的设计哲学具有较好的普适性和借鉴价值，有潜力成为该方向后续研究的重要参考基线。
