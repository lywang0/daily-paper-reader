## 摘要
我们推出了OptGear，这是一个为高效端侧部署、实时推理和强大任务能力而设计的基础模型。它包含一个密集模型（1M、270M和1B），上下文长度为64K。我们设计了一种新的混合架构，将卷积键值门控混合器与局部-全局注意力相结合，以减少随着长上下文呈指数增长趋势的KV缓存内存。与类似规模的模型相比，该架构在NPU上实现了高达X4.9倍的预填充和解码速度提升。OptGear从2T tokens候选语料库中，在无需知识蒸馏的情况下，使用精心筛选的0.5T tokens子集进行训练。这是现有基础模型中数据效率最高的。所有模型均开放权重，并附带适用于ONNX、Qualcomm NPU和Apple ANE的部署二进制文件，使OptGear成为需要快速、内存高效推理和强大任务能力的边缘应用的实用基础。此外，为了扩展端侧生成语言模型的生态系统，我们推出了OptGear-1M，这是一种可部署在微控制器单元（MCU）上的微型语言模型（TLM）。OptGear-1M是首个在STM32H747I-DISCO的ARM Cortex-M7 CPU上通过W4A32量化实现20 TPS的生成语言模型。

## Abstract
We introduce OptGear, a foundation model designed for efficient on-device deployment, real-tim inference, and strong task capability. It includes a dense model (1M, 270M, and 1B) with a context length of 64K. We designed a new hybrid architecture that combines a convolutional key-value gated mixer with local-global attention to reduce the KV-cache memory that tends to increase exponentially with long context. This architecture delivers up to X4.9 faster prefill and decoding speeds on the NPUs compared to models of a similar scale models. From a 2T tokens candidate corpus, OptGear is trained on a curated 0.5T tokens subset without knowledge distillation. This is the most data-efficient of the existing foundation models. All models are released with open weights and deployment binaries for ONNX, Qualcomm NPU, and Apple ANE making OptGear a practical base for edge applications that need fast, memory-efficient inference and strong task capabilities. Furthermore, to expand the ecosystem of on-device generative language models, we are introducing the OptGear-1M that can be deployed on Micro-Controller Units (MCUs), a Tiny Language Model (TLM). OptGear-1M is the first generative language model to achieve 20 TPS with W4A32 quantization on the ARM Cortex-M7 CPU of the STM32H747I-DISCO.

# Opt.Gear 技术报告 — 详细中文总结

## 1. 论文核心问题与整体含义（研究动机与背景）

- **问题背景**：随着大语言模型（LLM）在智能手机、平板、机器人、嵌入式设备等端侧场景的普及，低延迟、隐私保护和离线可用性成为关键需求。然而端侧设备受限于 SRAM 容量、能效约束和异构 SoC（CPU/GPU/NPU）的实时性要求，难以直接部署现有的大规模 LLM。
- **核心痛点**：
  - 现有开源模型（如 Llama、Gemma 等）为服务器级 GPU 设计，假设高带宽、大容量内存可用，不适用于移动/边缘设备。
  - Grouped-Query Attention（GQA）的复杂度为 O(N²)，滑动窗口注意力虽能缓解，但 KV-cache 的存储和访问仍随上下文长度线性（甚至更差）增长，成为移动 NPU/GPU 在延迟和功耗上的严重瓶颈。
  - 模型部署需同时优化硬件运行时画像、内存层次、内核兼容性和量化变体，这是一个多目标权衡问题。
- **论文含义**：Opt.Gear 旨在解决上述问题——通过硬件感知的混合架构设计，在不牺牲任务能力的前提下，实现**数据高效训练、内存高效推理、多平台可部署**的端侧基座模型系列（Opt.Gear-1M/270M/1B）。

## 2. 论文提出的方法论

### 核心思想
- 采用**混合序列混合架构**：将少量全局 GQA 注意力层与局部滑动窗口注意力、ConvKV-Gated Mixer 层结合。全局注意力负责远程信息路由，ConvKV-Gated Mixer 负责短程局部上下文混合。
- ConvKV-Gated Mixer **不构建 token 级注意力矩阵、不执行 softmax**，而是通过卷积和逐元素门控实现与注意力类似的内容依赖更新，从而将局部层的 KV-cache 替换为固定大小的卷积状态。

### 关键技术细节

**（1）ConvKV-Gated Mixer 计算流程**

输入序列 X = [x₁, ..., x_T]，先投影为 query/key/value：

- q_t = x_t W_q，k_t = x_t W_k，v_t = x_t W_v

key 和 value 流经过因果深度可分离 1D 卷积：

- ṽ_k_t = Σᵢ aᵢ ⊙ k_{t-i}，ṽ_v_t = Σᵢ bᵢ ⊙ v_{t-i}（i 从 0 到 L_conv−1，L_conv 为卷积核长度）

卷积后的 key 流通过元素级门控调制 query，门控选择卷积后的 value 信息：

- g_t = σ(q_t ⊙ ṽ_k_t)，y_t = g_t ⊙ ṽ_v_t，o_t = y_t W_o

该操作避免了构造 token 对注意力分数矩阵和局部窗口 softmax，使算子更适配现有 CPU/GPU/NPU 运行时，无需自定义序列内核。

**（2）高效缓存机制**

- 全局 GQA 缓存：O(2Cd_kv)（C 为上下文长度）
- 局部滑动窗口注意力缓存：O(2Wd_kv)（W 为窗口大小）
- ConvKV-Gated Mixer 缓存：仅保留固定卷积缓冲区 O(2L_conv · d_kv)，其中 Opt.Gear-270M/1B 的 L_conv=3，Opt.Gear-1M 的 L_conv=4。

Prefill 后，每个 ConvKV 层仅需保留最后 L_conv 个投影 key/value 状态；解码时追加当前投影、丢弃最旧条目、在固定缓冲区上执行深度卷积并计算门控。这大幅减少了解码期间必须保持活跃的序列相关状态。

**（3）模型配置要点**

- Opt.Gear-1B：d_model=1152，26 层，FFN=6912，GQA 4 头/1 KV 头，head_dim=256，SWA=512，最大长度 64K。
- Opt.Gear-270M：d_model=640，18 层，FFN=2048，其余同 1B。
- Opt.Gear-1M：d_model=128，5 层，FFN=272，GQA 2 头/1 KV 头，head_dim=64，上下文 512，面向 MCU 部署。
- 使用 QK-LN（query-key 归一化）、RoPE 位置编码（全局 theta=1e6，局部 theta=1e4）、GeGLU（1B/270M）或 ReLU6GLU（1M）激活函数、KORMo tokenizer（1B/270M）或 2048 词汇 BPE（1M）。

**（4）量化感知训练（QAT）**

- 采用 GPTQ 风格的分层输出重建目标初始化 INT4 量化尺度：

  Δ* = argmin_Δ ||WX − Q_Δ(W)X||²_F

- 初始化后使用 LSQ（Learned Step Size Quantization）将每组尺度 Δ_g 作为可学习参数，通过直通估计器训练。伪量化公式：

  Ŵ_g = Δ_g · clip(round(W_g/Δ_g), q_min, q_max)

- 初始化、QAT 和最终部署使用相同的分组 INT4 网格，避免量化器失配。

## 3. 实验设计

### 数据集与训练场景

- **候选语料**：约 2T tokens（英语、韩语、数学、通用网页），经筛选、去重和混合再平衡后得到 **0.5T tokens** 训练子集（92% 英语、6% 韩语、2% 数学，不含代码数据）。
- **长上下文扩展**：使用 prolong-data-64k 语料，分两阶段从 4K 扩展到 32K、再扩展到 64K。
- **Post-Training**：两阶段 SFT（通用指令 + 推理导向）应用于 270M/1B；Opt.Gear-1M 使用 GPT 生成的 50,000 对 stm32_cmd_synth 合成数据集，学习将自然语言命令映射为结构化 JSON 控制意图（LCD/LED/相机控制）。

### Benchmark

- **英文通用**：MMLU、MMLU-Pro、GPQA、ARC-Easy/Challenge、HellaSwag、PIQA、WinoGrande、OBQA。
- **韩语专项**：KMMLU、KoBEST、CLIcK、HAERAE。
- 评估工具：LM Evaluation Harness（perplexity-based）。

### 对比模型

- 量化对比：RTN、AWQ、GPTQ（应用于 QAT 基线之后）。

### 推理性能测试

- **硬件**：Qualcomm Snapdragon GEN4/GEN5（Hexagon NPU）、Apple iPhone 17 Pro/16 Pro（ANE）、llama.cpp（CPU/GPU/NPU）、CoreML Runtime。

## 4. 资源与算力

- 并行策略：8-way Pipeline Parallelism（PP）、1-way Tensor Parallelism（TP）、ZeRO-1 Data Parallelism（DP）。

## 6. 主要结论与发现

1. **架构有效性**：混合架构（ConvKV-Gated Mixer + GQA）显著降低 KV-cache 容量和内存带宽压力，在 Qualcomm GEN5 NPU 上 Opt.Gear-1B 达到 Prefill 7,042 tokens/s（对比 Llama3.2-1B 的 4,481 和 Gemma3-1B 的 3,226），在 iPhone 17 Pro 的 ANE 上达到 3,085 tokens/s（对比 Llama3.2-1B 的 1,073）。
2. **数据效率**：仅用 0.5T tokens 且无知识蒸馏，即可在多个 benchmark 上匹敌或超越训练数据量高出 4–72 倍（2T–36T tokens）的蒸馏模型。例如 Opt.Gear-1B 在 MMLU（43.2）和 GPQA（30.3）上超过 Gemma3-1B 和 EXAONE 4.0-1.2B。
3. **韩语优势**：受益于 KORMo tokenizer 和双语语料设计，Opt.Gear 在全部韩语 benchmark 上显著优于同规模竞品。例如 HAERAE 上 Opt.Gear-1B（44.2）领先 Gemma3-1B（35.3）和 Llama3.2-1B（32.6）。
4. **QAT 稳健性**：基于 Hessian 初始化的 LSQ QAT 使 Opt.Gear-1B 在 INT4 量化下性能降幅较小（如 MMLU 从 41.3 到 39.8），而 Gemma3-1B 在相同流程下降幅更大（35.8→32.5），说明 Opt.Gear 对量化的鲁棒性更强。
5. **MCU 可行性**：Opt.Gear-1M 在 STM32H747I-DISCO（Cortex-M7 @400MHz）上 W4A32 量化后达到 20 tokens/s，是首个能在 MCU 上交互式运行的生成式 LM，验证了固定卷积状态缓存在极低资源环境下的实用价值。

## 7. 优点

- **硬件感知的架构设计**：将动态 QKV 矩阵乘法和 softmax 替换为静态线性、卷积和逐元素操作，消除了对自定义序列内核的依赖，提升了在 NPU/MCU 上的可映射性。
- **KV-cache 优化有理论支撑**：论文明确推导了全局、局部窗口和卷积缓存各自的复杂度，展示了 ConvKV-Gated Mixer 如何将局部状态从 O(2W·d_kv) 降为 O(2L_conv·d_kv)。
- **数据效率实证**：在不使用知识蒸馏的前提下，以较少数据达到可比性能，提供了一种更可复现的训练范式。
- **QAT 初始化创新**：将 GPTQ 的分层重建目标与 LSQ 的可学习尺度结合，量化尺度考虑输入相关性而非简单统计，是一种实用的低比特量化训练方案。
- **部署生态完整**：开放权重并提供 ONNX、Qualcomm NPU、Apple ANE 的部署二进制，降低了实际落地门槛；MCU 实测（而非模拟器）数据可信度较高。
- **双语定位清晰**：韩语能力在多个专项 benchmark 上具有明确差异化优势。

## 8. 不足与局限

- **训练预算有限**：0.5T tokens 的规模限制了复杂推理和数学推理能力。作者也承认结果无法区分“推理差距”的根源是模型容量不足、任务相关数据不足还是训练效率问题。
- **缺乏代码能力**：作者明确表示未训练代码数据，限制了模型在编程类应用中的适用性。
- **无消融实验**：没有单独验证 ConvKV-Gated Mixer 相对标准滑动窗口注意力的净收益，也无法量化全局/局部/卷积层比例的影响。
- **硬件普适性局限**：Opt.Gear-1B/270M 仅验证了 Qualcomm 和 Apple 平台；llama.cpp 的 NPU 性能结果强烈受框架后端支持度影响，可能无法代表在不同推理引擎中的真实表现。
- **1M 适用面窄**：Opt.Gear-1M 仅面向 STM32 板级控制（LCD/LED/相机）的合成命令数据集，领域覆盖极窄，通用语言能力弱。
- **对比公平性风险**：论文强调“数据效率最高”，但未考虑 tokenizer 设计、数据配比、训练细节等差异；与训练量 4–72 倍于己的模型对比，更像数据效率展示而非架构能力公平比较。
- **个别数据可疑**：表 4 中 EXAONE 4.0-1.2B 的 MMLU-Pro 得分（42.8）高于其 MMLU（37.2），违背常识，可能为转录或测量错误。
