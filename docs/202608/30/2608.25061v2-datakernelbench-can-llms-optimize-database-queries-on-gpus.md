## 摘要
GPU越来越多地加速数据库系统，但查询特定的峰值性能仍然经常依赖于手写内核。现有的LLM内核基准测试专注于机器学习算子，而忽略了不规则、异构、数据移动密集的数据库风格算子。我们介绍了DataKernelBench，它将SQL转换为经过验证的PyTorch TorchPlan程序，并通过执行引导修复来评估在CUDA或Triton中优化核心张量受限代码片段或完整查询的LLM。在TPC-H SF10上使用H100 GPU的十个专有和开放权重模型中，最强的完整查询CUDA配置在完全通过率下比TorchPlan基线实现了2.11倍的加速。我们发现，性能更高的实现通常使用内核融合和执行策略更改，更强的模型从完整查询特化中获益最多，并且工作负载上下文比硬件上下文更重要。为了处理大于GPU内存的数据，我们使用Dask-cuDF扩展了TorchPlan，在TPC-H SF100上使用四个H100 GPU进行按需分区加载，实现了2.54倍的加速。项目页面：https://kerneldf.github.io/datakernelbench

## Abstract
GPUs increasingly accelerate database systems, but query-specific peak performance still often relies on hand-written kernels. Existing LLM kernel benchmarks focus on machine learning operators, leaving irregular, heterogeneous, data-movement-heavy database-style operators untested. We introduce DataKernelBench, which translates SQL into validated PyTorch TorchPlan programs and evaluates LLMs that optimize either the core tensor-bounded snippet or the full query in CUDA or Triton through execution-guided repair. Across ten proprietary and open-weight models on TPC-H SF10 with an H100 GPU, the strongest full-query CUDA configuration achieves $2.11\times$ speedup over the TorchPlan baseline at full pass rate. We find that higher-performing implementations commonly use kernel fusion and execution-strategy changes, stronger models benefit most from full-query specialization, and workload context matters more than hardware context. To handle data larger than GPU memory, we extend TorchPlan with Dask-cuDF for on-demand partition loading on TPC-H SF100 with four H100 GPUs, achieving $2.54\times$ speedup.
