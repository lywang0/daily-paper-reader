## 摘要
注意力-FFN解聚将LLM模块映射到专用池，为将混合专家（MoE）权重驻留在高带宽FFN池中创造了机会。然而，解码SLO限制了运行批次，而稀疏路由扩展了激活专家并集，导致权重流量分摊不佳，路由偏斜使冷专家资源闲置。因此，FFN池必须在稀疏并集下提供权重读取带宽密度，并在无全局共享结构的情况下恢复偏斜下的占用率。我们提出了一种ReRAM近内存架构，使专家权重驻留在高带宽本地读取之后。该设计将实际MFU分解为理想MFU和占用率，通过有界核心本地多播池化、共激活感知放置和负载感知获取来恢复占用率，并根据引发需求调整每个通信级别。对Qwen3.5-35B-A3B、Qwen3.5-397B-A17B和GLM-5.2的实测+建模研究表明，side-4池化将占用率从0.328提高到0.519，并在等峰值计算下，将每令牌FFN池延迟相比H20降低9.5倍，权重移动能耗降低20倍；H20注意力+ReRAM-FFN系统相比同质H20池，解码TPOT分别降低1.25-4.0倍、2.4-10.3倍和2.5-10.4倍。

## Abstract
Attention-FFN disaggregation maps LLM modules to specialized pools, creating an opening to keep Mixture-of-Experts (MoE) weights resident in a high-bandwidth FFN pool. Decode SLOs, however, cap the run-batch while sparse routing expands the activated-expert union, so weight traffic amortizes poorly and routing skew idles cold-expert resources. The FFN pool must therefore deliver weight-read bandwidth density under sparse unions and recover occupancy under skew without a global sharing fabric. We present a ReRAM near-memory architecture that keeps expert weights resident behind high-bandwidth local reads. The design factors actual MFU into ideal MFU and occupancy, recovers occupancy with bounded core-local multicast pooling, coactivation-aware placement, and load-aware fetch, and sizes each communication level from induced demand. A measured + modeled study on Qwen3.5-35B-A3B, Qwen3.5-397B-A17B, and GLM-5.2 shows that side-4 pooling raises occupancy from 0.328 to 0.519 and, at iso-peak compute, lowers per-token FFN-pool latency by 9.5x versus H20 with 20x lower weight-movement energy; an H20-attention + ReRAM-FFN system reduces decode TPOT by 1.25-4.0x, 2.4-10.3x, and 2.5-10.4x versus a homogeneous H20 pool.

## 1. 论文的核心问题与整体含义

### 研究动机与背景

- **注意力-FFN 解聚架构（Attention–FFN Disaggregation）** ：将 LLM 的注意力层与 FFN 层映射到不同的专用计算池，按各自瓶颈分别供给资源。注意力层反复读取不断增长的 KV 缓存，属于带宽受限；FFN 层复用跨 token 恒定的模型权重。
- **MoE 权重驻留的机遇**：该解聚方式天然支持将 MoE 专家权重常驻在高带宽的 FFN 池中，让激活流经本地权重。但实现这一机遇面临三重挑战：
  1. **SLO 约束批次**：解码服务级别目标（SLO）限制了可并行推进的序列数（run-batch），不能自由增大批次来摊薄权重读取。
  2. **稀疏路由扩大专家并集**：稀疏路由使激活的专家数量随批次超线性增长。实测 Qwen3.5-35B-A3B 路由中，专家并集从 B=1 时的 8 个专家增长到 B=64 时的 168.6/256，64 倍批次增长仅换来约 3.0 倍的权重流量摊销。
  3. **路由偏斜（Routing Skew）闲置资源**：热门专家成为关键路径，冷专家资源空转。热点专家负载可达均值的 6.77～12.5 倍（峰值达 9.83～47.3 倍），Gini 系数在 0.47–0.62 之间。

### 核心问题

> FFN 池必须在稀疏专家并集下提供 **权重读取带宽密度**（bandwidth density，即每驻留容量对应的权重读取带宽），并且在 **不依赖全局共享结构** 的前提下恢复路由偏斜下的资源占用率。仅靠权重驻留、去除片外权重搬运还不够——还需要解决 tile 填充不足和 PE 组等待尾车（straggler）导致的利用率损失。

## 2. 论文提出的方法论

### 核心思想：ReXpert 架构

提出 **ReXpert**——一种面向 MoE FFN 池的 ReRAM 近内存计算（NMC）架构，核心思路是：

> **将专家权重驻留在 ReRAM 中，通过高带宽本地读取送入相邻的数字 PE 执行；利用“读出的目的地是运行时决策”这一自由度，实现物理受限邻域内的 PE 重分配，无需复制专家或架设全局共享网络。**

### 关键技术细节

**1）MFU 分解（公式 2）**

\[
实际 MFU = 理想 MFU \times 占用率
\]

- **理想 MFU (Ideal MFU)**：因 tile 填充不足（underfilled tiles）导致的计算峰值损失。
- **占用率 (Occupancy)**：PE 组因等待尾车（straggler）而空闲的时间比例。
- 两个因子作为独立诊断指标，避免仅看平均负载混淆两者的成因。

**2）平衡的 ReXpert 单元（Unit）**

- 每个 Unit 存储 4 MiB（16 个 2Mib 宏单元，16K×128b），200 MHz 下提供 51.2 GB/s 本地读取带宽。
- 8 个偶/奇地址组装配 2048-bit 帧，经双时钟 FIFO 跨入 400 MHz PE 域，重打包为 MXFP8 行（128 E4M3 元素 + 4 个 E8M0 缩放字节）。
- PE 为 **4-token × 128-lane FP8 阵列**，每周期 512 MAC ≈ 400 GFLOPS。4 token 是能达计算峰值的最窄整数宽度（2w ≥ 7.81 FLOP/byte）。固定点累加器输出 BF16 结果。
- 每个层级按相同 Unit 数量扩展计算和带宽，保持 **0.128 bytes/FLOP** 恒定，即“机器平衡”。

**3）层级结构**：Unit → Core → Die → Package → Node

| 层级 | 驻留容量 | 本地读取带宽 | 峰值 FP8 |
|---|---|---|---|
| Unit | 4 MiB | 51.2 GB/s | 400 GFLOPS |
| Core（4×4 units, side-4）| 64 MiB | 819.2 GB/s | 6.4 TFLOPS |
| Die（20 cores）| 1.25 GiB | 16.4 TB/s | 128 TFLOPS |
| Package（4 dies）| 5 GiB | 65.5 TB/s | 512 TFLOPS |
| Node（8 chips）| 40 GiB | 524 TB/s | 4.1 PFLOPS |

**4）核心本地多播池化（Core-Local Multicast Pooling）**

- side-4 核心连接 16 个 Unit（K=4），16 个 PE 组可独立执行本地专家，也可为单个热门专家借出。
- 两阶段广播数据流：① 先通过各 owner 的本地输入驻留路径服务常驻专家；② 若某专家 tile 超出邻居资源，第二阶段多播该专家的读出，将剩余 token 分配给空闲 PE 组。
- 借出方接收相同权重行但持有不相交的 token 激活；BF16 部分和在离开 Core 前归约回 owner。
- **要点**：专家不复制、不重编程，收益是更短的关键路径轮数与更少的重复本地权重读取。
- 实测 side-4 将占用率从 0.328（side-2）提升到 0.519，实际 MFU 从 0.240 提升到 0.381；更大共享域（side-6/8）虽然进一步提高占用率，但轮次延长 1.69–2.50×，网络面积代价使有效 MFU 反而下降。

**5）共激活感知放置（Coactivation-aware Placement）**

- 从 profiling 窗口估计专家负载与两两共激活频率。
- 将频繁同火的专家分散到不同 Core，并在同一 Core 内搭配热门与冷门专家。
- 半静态放置：只改变元数据，不重写驻留的 ReRAM 权重。side-4 下将占用率从 0.519 提升至 0.532，轮次从 2.16 降至 2.07。

**6）负载感知获取（Load-aware Token Fetch）**

- 调度器可越过 FIFO 顺序，从已路由到驻留专家的排队 token 中提前取数执行。
- 仅重排序 token，不改变权重移动（区别于 EARTH 的推测性专家预取）。
- 在 G=2 时收益显著（占用率 0.422 → 0.552）；side-4/G=16 时池化已吸收大部分失衡，fetch 作为残余波动的补充手段。

**7）按需配置的通信层级（Hierarchy-aware Provisioning）**

- 每个通信层级有不同的物理职责，带宽和归约顺序须与放置匹配推导：
  - **Unit 外部 I/O**：1.57 GB/s 需求 vs 51.2 GB/s 供给
  - **Core mesh**（唯一承载权重的网络）：51.2 GB/s/流，p99 达 204.8 GB/s，供给 256 GB/s/core；多播是必要前提（单播复制需 15× 源端口、3.6× 流量）
  - **Die NoC**：GLM-5.2 最忙链路 24.68–24.81 GB/s，供给 64 GB/s/link
  - **Package D2D**：建模需求 47.0 GB/s/die，供给 96 GB/s
  - **Node residual**：16.7 GB/s，供给 34 GB/s
- **放置匹配的归约顺序**：专家并行优先（expert-parallel-first）归约先合并片内同索引分片，再跨 die 做张量并行归约；反向顺序会使 GLM-5.2 的 D2D 流量从 37.6 膨胀到 213.1 GB/s（5.7×）。
