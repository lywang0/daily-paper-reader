## 摘要
边缘LLM推理结合稀疏性和低比特量化以满足设备内存、延迟和功耗限制。然而，量化缩减了权重负载，却未按比例减少稀疏元数据，因此索引流量和非零值提取成为关键的SpMM瓶颈。我们引入了负载-元数据比（PMR），并表明提高PMR可提升解码过程中的有效计算强度。我们提出了UnionSparse，一个索引高效框架，将索引高效位图编码（IE-BME）与使用低比特共享内存并行解码（LSPD）的SpMM内核相结合。IE-BME分摊了元数据开销并将稀疏遍历与片段组装对齐，而LSPD改善了小批量执行。在W4A4量化和30%–70%稀疏度下，UnionSparse分别比FlashLLM和SpInfer快2.30倍和1.43倍，比CUTLASS和cuBLAS张量核心快1.56倍和3.46倍。这些结果表明，负载提取效率是边缘GPU上低比特稀疏推理的一阶关注点。源代码可在以下网址获取：https://github.com/Victor-Alen/UnionSparse。

## Abstract
Edge LLM inference combines sparsity and low-bit quantization to meet device memory, latency, and power limits. Yet quantization shrinks weight payloads without proportionally reducing sparse metadata, so index traffic and nonzero extraction become critical SpMM bottlenecks. We introduce the Payload-to-Metadata Ratio (PMR) and show that improving PMR raises effective compute intensity in decoding.   We present UnionSparse, an index-efficient framework that combines Index-Efficient Bitmap Encoding (IE-BME) with a SpMM kernel using Low-Bit Shared-Memory Parallel Decoding (LSPD). IE-BME amortizes metadata and aligns sparse traversal with fragment assembly, while LSPD improves small-batch execution. Under W4A4 quantization and 30%--70% sparsity, UnionSparse outperforms FlashLLM and SpInfer by 2.30x and 1.43x, and CUTLASS and cuBLAS Tensor Core by 1.56x and 3.46x, respectively. These results establish payload-extraction efficiency as a first-order concern for low-bit sparse inference on edge GPUs. Source code is available at: https://github.com/Victor-Alen/UnionSparse.

## 1. 核心问题与整体含义（研究动机与背景）

- **应用背景**：大语言模型（LLM）正逐步部署到边缘设备（如具身智能、自动驾驶、工业系统、个人终端），这些场景受限于内存带宽、功耗和散热预算，通常采用小批量自回归解码。
- **技术路线**：边缘 LLM 推理普遍结合两种压缩手段——**剪枝（Sparsification）**移除冗余权重，**低比特量化（Quantization）**将权重/激活压缩为 INT8/FP16/INT4 等格式，以减少计算和内存流量。
- **核心矛盾（关键洞察）**：量化缩小了权重负载（payload）的字节数，但**稀疏元数据（索引、偏移、位图）并未按比例缩小**。随着精度从 FP16 降到 INT8、INT4，元数据在总流量中占比越来越大，索引流量和非零值提取（nonzero extraction）成为 SpMM 的主要瓶颈。现有 GPU SpMM 工作（如 FlashLLM、SpInfer）主要关注调度、Tensor Core 利用率和运行时集成，但**边缘 GPU 带宽和并行度更弱**，对元数据开销和访存不规则性更为敏感。
- **论文定位**：作者主张将**索引效率（index efficiency）作为低比特稀疏推理的一阶设计目标**，并据此提出 UnionSparse 框架，在稀疏表示与内核执行两个层面协同设计。

## 2. 方法论：核心思想、关键技术细节

### 2.1 核心思想：负载-元数据比（PMR）与有效计算强度

- 定义 **PMR（Payload-to-Metadata Ratio）**：

  \[
  \text{PMR} = \frac{B_w \times M \times K \times (1-s)}{\text{Stor}_{\text{meta}}}
  \]

  其中 \(B_w\) 为每权重元素字节数，\(M\)、\(K\) 为权重矩阵维度，\(s\) 为稀疏度，分子即保留的非零负载存储量，分母为定位这些负载所需的元数据存储量。PMR 越高，单位元数据访问可获取的有效负载越多。

- 引入 **有效计算强度（effective CI）** 公式：

  \[
  \text{CI}_{\text{SpMM}} = \frac{2MN(1-s)}{B_w M(1-s)\left(1+\frac{1}{\text{PMR}}\right) + B_w N}
  \]

  元数据开销通过 \((1+1/\text{PMR})\) 项放大权重侧内存流量，降低有效 CI。Roofline 分析表明：高 PMR 格式使工作点右移，摆脱带宽受限区域；低 PMR 格式则贴近带宽上限，稀疏带来的算术削减难以转化为实际加速。

### 2.2 表示层优化：IE-BME（Index-Efficient Bitmap Encoding）

- **区域划分（Area Partitioning）**：将量化局部块（LT，local tile）按 \(R_A \times C_A\) 网格划分为 \(Q = R_A C_A\) 个区域，每个区域大小为 \((H_L/R_A) \times (K_L/C_A)\)。
- **共享联合掩码（Shared Union Mask）**：为每个区域内对齐的逻辑位置构造**单一逻辑联合位图** \(B_t(i,j)\)，只要 \(Q\) 个区域中任一值非零则该位为 1；全零组则掩码位为 0，不发射任何负载。这样**一个联合掩码位可表示 Q 个负载值的活性**，显著降低元数据开销。
- **存储布局**：编码后的 LT 由三个数组构成：
  - **Union Bitmaps**：按行主序将逻辑掩码打包为 64 位位图字；
  - **Union Value Offsets**：记录每个 LT 压缩负载段在全局数组中的起始位置（前缀和）；
  - **Compressed Values**：为每个活跃联合位分配紧凑秩（compact rank）\(\rho_t(i,j)\)，并让 Q 个区域流使用同一秩对齐存储（即使某区域该位置为 0 也写入以保持流对齐），保证后续可用一次位图遍历、一个索引同时收集所有区域流。

### 2.3 表示层优化：位图感知行重排（Bitmap-Aware Row Reordering）

- **动机**：在固定非零集合下，LT 内行的不同排列会激活不同数量的联合掩码项；合理分组行可减少活跃掩码条目，从而缩短压缩流。
- **分组代价公式**：对候选行组 \(r=(r_0,\dots,r_{R_A-1})\)，定义分组活性 \(\phi_t(r;j)\) 和分组代价 \(c_t(r)=\sum_j \phi_t(r;j)\)，目标为最小化总联合掩码活跃数。
- **求解算法**：采用**分组子集动态规划（Grouped Subset DP）**，状态 \(F(S)\) 表示剩余行集合 \(S\) 的最小分组代价，转移枚举包含最小行索引的所有大小为 \(R_A\) 的行组，最后对分组进行规范化排序（组内升序、组间字典序）得到重排置换 \(\pi_t^\star\)。
- **开销**：每 LT 时间复杂度为 \(O\left(\binom{H_L}{R_A}R_A K_L + 2^{H_L}\binom{H_L-1}{R_A-1}\right)\)，空间 \(O(2^{H_L}+\binom{H_L}{R_A})\)。重排为**离线一次性**步骤，运行时零开销；OPT-13B 重排约耗时 4.07 小时（14 线程）。

### 2.4 执行层优化：DW-PC 流水线（Decoupled Warp-Specialized Producer-Consumer）

- **双缓冲**：为权重流和激活流各维护两个共享内存缓冲区，读写缓冲交替（ping-pong）。
- **Warp 角色分工**：Warp 0 作为**生产者**，仅负责发起下一 tile 对的全局到共享内存异步预取（cp.async）；Warp 0–3 作为**消费者**处理当前 tile。预取发起后 Warp 0 立即回归消费者角色参与计算。
- **稳态调度**：下一 tile 预取与当前 tile 的 LSPD 解码、激活加载、Tensor Core MMA 计算重叠，仅在缓冲区交换屏障处同步。

### 2.5 执行层优化：LSPD（Low-Bit Shared-Memory Parallel Decoding）

- **线程-段映射**：每个逻辑行划分为等宽位图段（G 位），一个线程负责一个位图段，一个 warp 并行处理多个逻辑行。
- **位图引导偏移生成**：通过字级 PopCount 前缀和计算基址 `idx_base`，段内活跃位按顺序分配 `seg_rank`，最终索引为 `global_idx = idx_base + seg_rank`。
- **区域收集与寄存器打包**：同一 `global_idx` 同时索引 Q 个压缩区域流，一次活跃位取回 Q 个低比特值；非活跃位填零。收集结果直接打包为 Tensor Core MMA 所需的寄存器片段（FragW），实现"位图→MMA 就绪片段"的直接重建。

### 2.6 内核总流程（Algorithm 2）

初始化（预取首对 tile、就绪屏障）→ 稳态循环（生产者预取下一对 tile；消费者执行 PROCESS CURRENT TILE 融合 LSPD、激活加载与 MMA；缓冲区交换）→ 尾声（处理末对 tile、存储部分和、归约得到输出 Y）。
