## 摘要
混合专家（MoE）模型因其稀疏激活将模型容量与计算成本解耦，在大型语言模型中的应用日益广泛。然而，庞大的专家参数规模常常超出GPU显存容量，导致推理延迟主要由专家加载时的主机到设备PCIe传输所主导。为解决这些挑战，本文提出了SPICE，一种用于MoE卸载的推测性预取框架，将轻量级专家预测与置信度感知的CPU-GPU编排相结合。一方面，SPICE构建了与目标MoE架构对齐的轻量级草稿模型，采用置信度感知的自适应前视算法来预取高置信度专家。另一方面，当推测性预测未命中时，SPICE切换到成本感知的CPU-GPU异构编排：低置信度的未命中由驻留的共享专家及其低秩专家（LoRE）代理近似处理，而精确的剩余工作则卸载到CPU，并与正在进行的GPU计算异步并行执行。在DeepSeek-V2-Lite和Qwen2-57B-A14B以及多种GPU平台上评估表明，SPICE在每输出令牌时间（TPOT）上实现了高达3.12倍的加速比，且质量损失极小，这表明有效的MoE卸载不仅需要预测未来的专家，还需要决定哪些未命中值得近似处理、哪些需要精确恢复，以及精确的剩余工作应在何处执行。

## Abstract
Mixture-of-Experts (MoE) models are increasingly used in LLMs because sparse activation decouples model capacity from compute cost. However, the large expert parameter footprint often exceeds GPU memory capacity, making inference latency dominated by the host-to-device PCIe transfers for expert loading. To address these challenges, this paper presents SPICE, a speculative prefetching framework for MoE offloading that combines lightweight expert prediction with confidence-aware CPU-GPU orchestration. On one hand, SPICE builds a lightweight draft model aligned with the target MoE architecture, using a confidence-aware adaptive lookahead algorithm to prefetch high-confidence experts. On the other hand, when speculative predictions miss, SPICE switches to a cost-aware CPU-GPU heterogeneous orchestration: low-confidence misses are approximated by the resident shared expert with low rank expert (LoRE) surrogates, while exact residual work is offloaded to the CPU and executed asynchronously in parallel with ongoing GPU computation. Evaluated on DeepSeek-V2-Lite and Qwen2-57B-A14B across diverse GPU platforms, SPICE achieves up to 3.12 speedup in Time Per Output Token (TPOT) with minimal quality loss, showing that effective MoE offloading requires not only predicting future experts, but also deciding which misses deserve approximation, which require exact recovery, and where exact residual work should execute.

## 1. 核心问题与整体含义（研究动机和背景）

- **背景**：混合专家（MoE）模型通过稀疏激活在增加模型容量的同时控制计算成本，已成为大语言模型（LLM）的重要架构。然而，MoE 中所有专家 FFN 权重的总体规模远超单 GPU 显存容量，通常需将专家卸载至主机内存，在推理时按需通过 PCIe 加载。
- **核心瓶颈**：论文量化显示，专家权重加载延迟占 MoE 单层执行总延迟的 73%–88%，而实际计算仅占 12%–27%。因此，MoE 推理在显存受限场景下由“计算密集型”变为“I/O 密集型”，PCIe 传输成为决定推理速度的关键因素。
- **已有方法的不足**：
  - 简单按需加载会直接增加关键路径延迟；
  - 现有专家预取方法难以同时满足三个耦合条件：预测未来专家要准确；预取未命中后的恢复成本必须可控；激进预取会占用 PCIe 带宽和 GPU 缓存，反而延误紧急需求或驱逐有用专家。
- **整体含义**：有效解决 MoE 卸载问题不能只依赖“预测”，还必须决定哪些未命中可以使用近似计算、哪些必须精确恢复，以及精确残余计算在 CPU 还是 GPU 上执行。SPICE 正是围绕这一系统级视角给出完整框架，为资源受限环境下的 MoE 推理加速提供了新方案。

## 2. 方法论：核心思想、关键技术细节、公式或算法流程

### 核心思想
SPICE 将“推测性专家预取”与“缓存驻留代理替换”和“CPU–GPU 异构执行”相结合，形成三级恢复机制：
- 高置信度且可预取的专家 → 提前异步加载到 GPU，隐藏 PCIe 延迟；
- 低置信度未命中专家 → 使用共享专家 + 低秩代理（LoRE）近似，避免同步重载；
- 需要精确恢复的未命中专家 → 在 CPU 上利用主机驻留权重异步执行，与 GPU 计算并行。

### 关键技术细节

#### (1) 结构对齐的推测性预取
- 使用轻量级草稿模型（draft model）与目标 MoE 架构对齐，不改变解码轨迹，只预测未来层可能激活的专家集合。
- 在解码步 t、当前层 l 锚定隐藏状态，递归预测未来层 l+δ 的路由分布：
  - 预测分布：$\hat{\pi}^{(l+\delta)}_t \in [0,1]^N$
  - 预测专家集：$\hat{S}^{(l+\delta)}_t = TopK(\hat{\pi}^{(l+\delta)}_t, K)$
- 预取队列为所有预测专家集的并集：$Q_{prefetch} = \bigcup_{\delta=1}^{H} \hat{S}^{(l+\delta)}_t$，其中 H 为预取前视深度。
- 采用有界深度、低优先级拷贝队列，避免推测性传输独占 PCIe 拷贝引擎。

#### (2) 置信度感知的自适应前视算法
- 定义预测置信度为预测 Top-K 专家集合内的概率质量之和：$C(\hat{\pi}^{(l)}_t) = \sum_{i \in \hat{S}^{(l)}_t} \hat{\pi}^{(l)}_{t,i}$。
- 计算满足硬件重叠要求的最小前视深度：根据每层预取专家数 P、单专家内存占用 M_e、PCIe 带宽 B_PCIe 和每层计算窗口 T_comp，得到 $H_{min} = \lceil P \cdot M_e / (B_{PCIe} \cdot T_{comp}) \rceil$，其中 $T_{comp} = T_{attn} + K \cdot T_{expert}$。
- 自适应停止条件（Algorithm 1）：当深度达到 H_min 后，若当前层置信度 C < 阈值 τ 则停止继续扩展，否则继续直到 H_max。
- 算法流程：
  1. 用当前隐藏状态初始化预测隐藏状态；
  2. 通过目标 router 预测下一层路由分布并选出 Top-K 专家集；
  3. 将预测专家集入队；
  4. 计算置信度，若已过最小深度且置信度低于阈值则终止；
  5. 否则用注意力和低秩投影更新预测隐藏状态，继续下一深度的预测。

#### (3) 低置信度替换：共享专家 + LoRE 低秩代理
- 利用 MoE 层中天然存在的共享专家（如 DeepSeek-V2、Qwen-MoE）作为基础计算。
- 对每个路由专家 e，学习一个低秩残差模块 Δ_e(h)，用于近似“路由专家输出”与“共享专家输出”的差值：
  - $\Delta_e^{(l)}(h) \approx E_e^{(l)}(h) - S^{(l)}(h)$
  - 实现为低秩变换：$\Delta_e^{(l)}(h) = B_e^{(l)} A_e^{(l)} h$，其中 $A_e^{(l)} \in \mathbb{R}^{r \times d}$、$B_e^{(l)} \in \mathbb{R}^{d \times r}$，r ≪ d。
- 离线校准：在保留数据集上运行目标 MoE，记录隐藏状态、路由决策、共享专家输出和真实专家输出，然后最小化残差近似误差（公式 10）训练每个层-专家对的低秩矩阵。
- 运行时：低置信度的未命中专家直接使用共享专家输出加 LoRE 替代，即 $\tilde{y}_e^{(l)} = S^{(l)}(h^{(l)}) + B_e^{(l)} A_e^{(l)} h^{(l)}$，不触发专家权重传输或 CPU 执行。

#### (4) CPU–GPU 异构编排
- 对于不能近似且未命中的专家，SPICE 将缺失集 M 分为两部分：$M_{fetch}$（转移到 GPU 执行）和 $M_{cpu}$（在 CPU 上用主机驻留权重精确执行）。
- 调度决策依据当前 PCIe 压力和各层成本表；仅当 GPU 获取能有效减少端到端恢复时间时才选择 GPU 获取，否则交由 CPU 执行。
- 实现中，先比较“全部 CPU 执行”与候选拆分方案，只有拆分方案在估算成本上明显优于全 CPU 时，才采用 GPU 获取。
- 执行步骤：
  1. 将当前隐藏状态暂存到钉扎内存，启动 CPU 残留执行，同时为 GPU 获取专家发起异步 H2D 传输；
  2. CPU 专家计算与拷贝引擎并行；
  3. GPU 传输完成后，在 GPU 上执行驻留和已获取专家，与 CPU 输出合并形成下一层隐藏状态。

## 6. 主要结论与发现

- **性能**：SPICE 相比 AdapMoE 获得 2.04–2.70× 的 TPOT 加速，且始终优于 CG-MoE；在提示长度从 64 增至 1024 tokens 时，加速比保持在 2.44–3.12×。
- **质量**：在 GSM8K 上准确率下降约 3.0–3.5 个百分点，在 HumanEval 上 Pass@1 下降约 2.3–3.9 个百分点，表明近似替换带来的质量损失较小。
- **能量与流量**：
  - SPICE 能量为 3.48 J/token，相比 Naive 的 5.51 J/token 显著降低；
  - SPICE 的 H2D 流量为 54.7 GB，回退率仅 3.0%；相比 AdapMoE，H2D 流量减少 28%、回退率减少 51%。

- **PCIe 带宽利用率**：SPICE 通过有界深度、低优先级的预取队列，避免了推测性传输独占 PCIe 拷贝引擎，因此能在保持较高 H2D 带宽利用率的同时，为紧急的精确恢复预留通道；相比 AdapMoE 的激进预取策略，SPICE 在带宽占用和关键路径延迟之间取得了更优的平衡。

- **总体结论**：SPICE 首次将“推测预取、近似替换、异构执行”统一到同一系统框架中，证明了在显存受限的 MoE 推理中，通过显式区分“必须精确恢复”与“可以近似替代”的未命中专家，可以同时获得显著的端到端加速、可接受的质量损失和更低的能量消耗，为 I/O 密集型 MoE 推理提供了新的系统设计范式。

## 7. 局限性与开放问题

- **质量损失的不可忽视性**：在 GSM8K（约 3.0–3.5 个百分点）和 HumanEval（约 2.3–3.9 个百分点）上的下降，虽然作者将其定位为“较小”，但在对推理结果正确性要求苛刻的数学推理、代码生成等场景中，这一损失可能仍超出可接受范围；论文没有说明是否可以通过更高秩的 LoRE 或更精细的置信度阈值调节来进一步压缩这一损失。
- **部署复杂度**：SPICE 依赖额外的轻量级草稿模型用于预取预测，并需要离线校准集来训练每层每专家的低秩代理；这两项附加组件增加了系统部署的流程复杂度和维护成本，论文未评估其端到端部署开销（如校准数据规模、训练时间、草稿模型的推理开销）。
- **对无共享专家架构的适用性**：LoRE 替换的核心前提是 MoE 层中存在共享专家作为基础计算；对于不含共享专家的 MoE 架构（如早期 Switch Transformer 或部分 GShard 变体），该方法需要重新设计替代基准，通用性受限。
- **CPU 算力的依赖**：CPU 上的精确回退执行依赖主机端多核 CPU 的计算能力；在 CPU 较弱的主机或 CPU 已被其他负载占用的多租户场景下，CPU 回退路径可能成为新的瓶颈，论文未讨论该场景下的退化表现。
- **批处理与多请求并发场景缺失**：实验集中在单请求（single-request）解码场景，未考虑多请求并发、连续批处理（continuous batching）下的 PCIe 带宽竞争和预取队列调度，这限制了其在真实服务端的直接可迁移性。

## 8. 未来工作方向

- **扩展到更广泛的 MoE 架构**：将 SPICE 的框架推广到不含共享专家的模型，并探索用“其他已驻留专家的平均输出”或“量化版本专家”作为更通用的替代基准。
- **与模型压缩技术结合**：将量化专家权重、专家剪枝或蒸馏后的专家与 LoRE 低秩代理联合使用，进一步降低需要精确加载的权重规模，从而缓解 PCIe 带宽的根本瓶颈。
- **端到端联合训练**：将 LoRE 低秩残差参数的训练与路由器的置信度校准协同进行，使路由分布天然适配预取和近似替换策略，减少离线校准与在线运行之间的分布偏移。
- **多请求服务场景优化**：研究在连续批处理和多用户并发下的 PCIe 带宽公平分配、预取队列优先级调度以及缓存替换策略的全局优化问题。
- **自适应系统配置**：根据运行时观测到的 PCIe 带宽波动、CPU 负载和缓存命中率，动态调整预取前视深度、置信度阈值和 CPU/GPU 拆分比例，实现系统级的自适应闭环。

## 9. 总体评价

- **贡献的原创性**：SPICE 的独特价值在于将三个原本独立的研究方向——专家预取、近似计算和异构执行——统一在一个系统框架内，且显式区分了未命中专家的“恢复等级”。这一认知框架比单纯改进预测准确率或缓存策略更具系统性和可操作性。
- **工程完整度**：论文提供了完整的系统实现（包括草稿模型对齐、低秩代理校准、低开销调度器和多级回退机制），并在多个 GPU 平台、两种主流 MoE 模型上验证了效果，工程完成度较高，结论具备较强的可信度。
- **实验报告的不完整之处**：MT-Bench 和 LongBench 的详细结果缺失、LoRE 秩和置信度阈值的敏感性分析不足、未报告方差与重复实验统计，以及未说明草稿模型和校准确切的算力开销，这些都是在复现或依据其结果做技术选型时需要注意的信息缺口。
- **总体定位**：SPICE 是一篇系统层面的、面向显存受限 MoE 推理加速的高质量工作，其“以恢复成本而非命中率为中心”的设计思路具有示范意义，对未来 MoE 推理系统的研发具有重要的参考价值，尤其在边缘设备、单卡推理和成本敏感型部署场景中具有直接的应用潜力。
