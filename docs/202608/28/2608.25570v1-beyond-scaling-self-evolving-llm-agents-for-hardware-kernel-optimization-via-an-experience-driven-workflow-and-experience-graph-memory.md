## 摘要
硬件内核优化需要反复进行编译、正确性测试、性能分析和修订。LLM智能体可以将这一过程的某些部分自动化，而更强的基座模型、更长的上下文窗口和更长的执行时间跨度已提升了单个任务内的优化能力。然而，仅靠这些进展并不足以让智能体从已完成的优化运行中学习。现有的内核优化智能体很少保留一项决策、其观察到的执行反馈以及后续基于该证据所做的决策。保留全部先前轨迹也不切实际，因为不断增长的历史记录会与当前任务争夺上下文资源。我们提出了KOPE，一种用于硬件内核优化的经验驱动框架。KOPE在经验图内存中记录带有正确性和性能反馈的优化轨迹，然后使用主动上下文管理与注入，在固定token预算下检索相关经验。该图保留了决策顺序、观察到的结果和备选分支，使得在目标硬件上收集的证据能够为后续优化步骤和任务提供信息。在相同的GLM-5.2设置下，KOPE的每个算子加速比几何平均是CANNBot（最强竞争基线）的1.54倍。在完整的53算子消融实验中，主动上下文管理与注入将通过率从60.0%提升至84.6%，将评估器报告的正向字段几何平均从0.0382提升至0.0661，并将优化token消耗从159亿降低至11.13亿（与被动智能体主导的上下文构建相比）。启用经验图内存将整套测试通过率从55.2%提升至84.6%，并在有效时序比较上产生1.43倍的几何平均加速。这些结果支持在基座模型保持固定的情况下，通过外部经验进行持续优化。

## Abstract
Hardware kernel optimization requires repeated compilation, correctness testing, profiling, and revision. LLM agents can automate parts of this process, and stronger foundation models, longer context windows, and longer execution horizons have improved optimization within individual tasks. These advances alone do not enable an agent to learn from completed optimization runs. Existing kernel-optimization agents seldom preserve a decision, its observed execution feedback, and the later decisions that use that evidence. Retaining every prior trajectory is also impractical because an expanding history competes with the current task for context. We present KOPE, an experience-driven framework for hardware kernel optimization. KOPE records optimization trajectories with correctness and performance feedback in Experience Graph Memory, then uses Active Context Management and Injection to retrieve relevant experience under a fixed token budget. The graph retains decision order, observed outcomes, and alternative branches, allowing evidence collected on the target hardware to inform later optimization steps and tasks. Under the same GLM-5.2 setting, the geometric mean of KOPE's per-operator speedups is $1.54\times$ that of CANNBot, the strongest competing baseline. In a complete 53-operator ablation, Active Context Management and Injection raises pass rate from 60.0\% to 84.6\%, increases the evaluator-reported positive-field geometric mean from 0.0382 to 0.0661, and reduces optimization token consumption from 15.9B to 1.113B tokens relative to passive agent-led context construction. Enabling Experience Graph Memory raises full-suite pass rate from 55.2\% to 84.6\% and yields a $1.43\times$ geometric-mean speedup on valid timing comparisons. These results support continual optimization through external experience while the foundation model remains fixed.

## 2. 方法论

**核心思想：**
- KOPE采用**经验驱动的工作流**，在固定基座模型参数的前提下，通过外部经验记忆实现"自我进化"——进化的对象是外部经验与上下文供给策略，而非模型参数。

**关键技术细节：**

- **经验驱动优化工作流**：闭环流程，将每次优化尝试视为一次学习事件。每个迭代的形式化过程为：
  - `z_t,k = R(s_t,k, M_t,k)`：检索相关经验
  - `C_t,k = I(s_t,k, z_t,k; B)`：在token预算B下组装提示词
  - `a_t,k = π_θ(C_t,k)`：固定参数的LLM代理生成候选
  - `y_t,k = E(a_t,k)`：执行环境返回编译诊断、正确性和性能
  - `M_t,k+1 = U(M_t,k, s_t,k, a_t,k, y_t,k)`：更新记忆
  - 记忆在任务内部迭代间和任务之间均持续存在（`M_t+1,0 = M_t,K_t`）
  - 执行策略为"先正确性、后性能"，只有正确的候选且性能改善时才替换现役代码。

- **经验图内存（KOPE-Mem）**：
  - 每个事件以**双重表示**记录：append-only的Markdown Journal（叙事性总结）和结构化JSON Case（操作符、输入场景、优化思路、前后代码、反馈、正确的性、绝对加速比、置信度、会话/步骤/前驱ID等）。
  - 构建**决策到结果的经验图** `G=(V,E)`：每个节点记录一个决策及其结果，边 `(u,v)` 表示v从u的优化状态出发。当前schema每个节点最多一个前驱、可有多个后继，形成有向无环森林。
  - 边记录的是**血缘/谱系关系**，不做因果识别断言。
  - **图感知的检索与排序**：先通过精确过滤器（操作符、优化层、思路ID、结果标签）和语义搜索构建候选池；再以折扣下游结果得分 `d(v) = 0.5·r_v + 0.5·0.7·Σ_{u∈succ(v)} d(u)` 排序（其中 `r_v = a_v / a_prev(v)` 为步骤加速比），结果标签分为有效/部分/无效/负面四档。

- **主动上下文管理与注入**：
  - 每次迭代前重建提示词，而非反复累积历史。
  - **三级上下文层级**：热上下文（必需任务状态：内核规格、现役代码、最新反馈、优化目标）、温上下文（当前状态检索到的经验）、冷上下文（更广泛的文档和跨类别知识）。
  - 在预算约束 `B_k = max(0, W - S - G - R)` 下（W=模型窗口、S=系统提示词、G=生成预留、R=近期预留），按优先级依次准入热/温/冷内容。
  - 与KV缓存驱逐的边界：KOPE在模型调用**之前**选择外部材料，KV缓存驱逐在解码**期间**选择内部状态，二者可结合。

## 7. 优点

- **问题定位精准**：识别出现有系统"一次性优化"的根本缺陷——执行反馈仅指导当前运行而不累积为可复用证据，并提出针对性的解决方案。
- **图结构记忆创新**：不只是存储文本轨迹，而是以有向图保留决策顺序、观测结果和备选分支，支持沿血缘关系追溯下游后果，检索时可纳入"后见之明"信号（折扣下游结果得分）。
- **预算约束的上下文管理**：将上下文视为有限资源，通过三级分层和显式token预算分配，既保证必需任务状态，又注入相关经验，避免了"长上下文=有效上下文"的误区（呼应Lost in the Middle等研究）。
- **固定基座模型、外部经验进化的范式**：不依赖模型参数更新，在难以大规模微调的专有模型场景下尤其实用。
- **实验设计严谨**：统一评估器、缺失计为失败、从存档产物重算数值、精确交集诊断、跨硬件验证整体泛化性，这些做法增强了结论的可信度。
- **诚实报告局限**：明确区分覆盖率与条件性能、承认单次运行无法估计方差、明确图连接不构成因果识别，体现了学术严谨性。

## 8. 不足与局限

- **实验覆盖的局限性**：
  - 每个模型/系统配置仅有一个存档运行，**无法估计运行间方差**，统计显著性未建立。
  - 加速比指标仅在正字段上计算几何平均，排除了缺失和非正值字段，可能使小返回子集看起来更强。
  - Deepseek-V4-Pro上，KOPE在31算子交集上的条件得分低于CANNBot（952.53 vs 1015.38），说明优势主要在覆盖率而非所有条件性能指标。

- **偏差风险**：
  - 正字段几何平均的统计方式可能产生选择性偏差。
  - 主实验聚焦于单一硬件（Ascend 910C）和单一kernel语言（AscendC），跨硬件验证局限于附录的RISC-V实验，且组合记忆的0.786×仍低于PyTorch同等性能（parity）。

- **方法层面的局限**：
  - 当前经验图schema只支持每个节点一个前驱，无法建模"多个父决策共同导致一个结果"的复杂场景。
  - 检索的折扣下游结果得分是**启发式**，作者明确声明非因果估计。
  - 上下文层级的容量上限（Qw、Qc）为固定值，**在线学习这些上限被排除在当前实现之外**。
  - 主动上下文消融同时改变了选择、压缩、注入三个环节，**无法区分单个内部操作各自的贡献**。

- **应用限制**：
  - 跨硬件实验中，Ascend源记忆虽然提高了覆盖率但降低了性能（0.388×→0.145×），说明源硬件经验可能在性能上存在"误导性"，需要目标侧经验进一步修正。
  - 论文整体证据范围有限：一个完整的主动/被动上下文对比、每个表1单元格一个存档工件、一个412案例的配对时序比较。
