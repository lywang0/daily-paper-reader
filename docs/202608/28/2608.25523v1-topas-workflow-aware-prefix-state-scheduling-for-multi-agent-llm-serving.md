## 摘要
前缀缓存在多智能体大语言模型（LLM）服务中引入了一个基本权衡：为某个智能体保留长的系统提示词键值（KV）缓存可加速其未来调用，但会减少可用于批处理并发请求的GPU内存。在多阶段工作流中，现有调度器倾向于优先考虑即时前缀局部性或整体工作流进度。然而，在共享KV缓存预算下，孤立地优化任一目标都可能通过下游延迟或频繁的前缀替换而延长任务级作业完成时间（JCT）。为取得平衡，我们在此提出TOPAS，一种面向任务的前缀感知调度器，它联合决定将哪些智能体前缀保留在缓存中以及调度哪些请求执行。TOPAS通过权衡每个任务最长剩余服务路径的预期缩减与下游前缀复用的近期收益，并考虑前缀移动和抢占的成本，来对候选决策后状态进行评分。还引入了任务级老化机制以防止饥饿。我们在SGLang框架内实现了TOPAS，并在三个合成DAG和两个MetaGPT软件开发工作流上评估其性能。与每个工作负载和指标上表现最佳的基线相比，TOPAS在合成工作负载上将平均/第99百分位JCT降低了最多39.8%/49.4%，在MetaGPT-SOP上将平均JCT降低了9.8%，在MetaGPT-TL上将平均/第99百分位JCT降低了22.0%/26.6%。

## Abstract
Prefix caching introduces a fundamental tradeoff in multi-agent large language model (LLM) serving: retaining a long system-prompt key-value (KV) cache for an agent accelerates future calls, yet it reduces the GPU memory available for batching concurrent requests. In multi-stage workflows, existing schedulers tend to prioritize either immediate prefix locality or overall workflow progress. However, under a shared KV cache budget, optimizing either objective in isolation can prolong tasklevel job completion time (JCT) through downstream delays or frequent prefix replacement. To strike a balance, we here propose TOPAS, a Task-Oriented Prefix-Aware Scheduler that jointly decides which agent prefixes to keep in the cache and which requests to schedule for execution. TOPAS scores candidate post-decision states by trading off the expected reduction in each task's longest remaining service path against the near-term benefit of downstream prefix reuse, accounting for the costs of prefix movement and preemption. A task-level aging mechanism is also incorporated to prevent starvation. We implement TOPAS within the SGLang framework and assess its performance on three synthetic DAGs and two MetaGPT software-development workflows. Compared with the best performing baseline for each workload and metric, TOPAS reduces the mean/p99 JCT by up to 39.8%/49.4% on the synthetic workloads, while lowering mean JCT by 9.8% on MetaGPT-SOP and mean/p99 JCT by 22.0%/26.6% on MetaGPT-TL.

## 1. 论文的核心问题与整体含义

- **背景**：多智能体 LLM 应用通过多个角色化智能体之间的相互依赖请求完成复杂任务。每个请求都带有智能体特定的静态前缀，该前缀的 KV 缓存可在同一智能体的不同任务请求之间复用。
- **核心矛盾**：保留长系统提示词的 KV 缓存可以加速后续调用（减少预填充计算），但会占用有限的 GPU 内存，降低可同时批处理的并发请求数量。
- **现有不足**：主流调度器（如 SGLang）主要在请求级别进行优化，忽略请求间依赖和任务级进度；已有的工作流感知调度（如 Parrot、Autellix、KVFlow）虽然考虑了应用数据流或缓存放置，但通常将前缀驻留与请求准入解耦，导致异构前缀共驻缓存、有效批处理容量下降，或频繁的智能体切换引起前缀替换/重载开销。
- **本文问题**：如何在共享 KV 缓存预算下，协调前缀驻留（prefix residency）与请求准入（request admission），以最小化任务级作业完成时间（JCT）？
- **核心贡献**：提出 **TOPAS**（Task-Oriented Prefix-Aware Scheduler），一个联合优化前缀驻留和请求准入的在线调度器，显式地把前缀驻留作为调度决策的一部分，而非请求排序和缓存淘汰的间接结果。

## 2. 方法论

### 2.1 核心思想
- 在每个调度时刻，TOPAS 直接选择一个“决策后状态” $S'=(R', Q')$，其中 $R'$ 是驻留智能体前缀集合，$Q'$ 是运行请求集合。
- 该状态必须满足联合 KV 容量约束：$\sum_{a\in R'}\ell_a + \sum_{r\in Q'}d_r(t) \le B_t$。
- 通过评分函数对候选状态排序，贪心地选择得分最高的状态执行，并在下一个调度事件重新评估。

### 2.2 关键技术细节

#### 基础转移效用（Base Transition Utility）
- 评分公式：$U_{\text{base}}(S'|S_t) = J_{\text{admit}} - J_{\text{move}} - J_{\text{redo}} - J_{\text{revoke}}$
- $J_{\text{admit}}$：请求完成后对任务剩余 LLM 服务路径（longest remaining path）的期望缩减量，使用历史工作经验分布计算条件残差。
- $J_{\text{move}}$：前缀在 GPU/CPU 之间迁移的串行时间成本。
- $J_{\text{redo}}$：被抢占请求需要重新解码生成 token 的重复计算成本。
- $J_{\text{revoke}}$：撤销未完成请求此前获得的进度信用，避免重复获益。

#### 短视前缀复用（Short-Horizon Prefix Reuse）
- 用一个一步前瞻项 $V_{\text{reuse}}$ 评估保留某些前缀对即将就绪的下游分支的收益，仅看一个工作流转移，因为更远期的依赖不确定。

#### 任务级老化（Task-Level Aging）
- 引入年龄权重 $g_i(t)=1+\rho\log(1+\frac{t-\tau_i}{H_{\text{age}}})$，防止新到达任务反复抢占旧任务。
- 将老化权重乘入准入进度项，得到完整评分：$\text{Score}(S'|S_t)=J_{\text{admit}}^{\text{age}} - J_{\text{move}} - J_{\text{redo}} - J_{\text{revoke}} + V_{\text{reuse}}$。

#### 分层状态搜索（Hierarchical State Search）
- 将前缀集合生成与请求分配分离：先枚举/搜索前缀集合，再用贪心打包（GREEDY PACK）在给定前缀集下分配请求。
- 小规模智能体池（$|A_t|\le M$）枚举所有子集；大规模池使用单智能体添加、双智能体配对、单删除/交换修复，复杂度 $O(|A_t|^2)$。
- 每次调度事件从生成的可行候选中选择得分最高的状态执行。

## 6. 主要结论与发现

- **合成工作负载**：相对每个工作负载和指标上表现最佳的基线，TOPAS 将 mean JCT 降低 27.5%（Chain-3）、39.8%（DAG-4）、27.7%（DAG-10-Wide）；p99 JCT 降低 31.7%、49.4%、30.8%。
- **MetaGPT-SOP**：相对最强的 mean-JCT 基线 SPF，TOPAS 将 mean/p99 JCT 降低 9.8%/4.5%，请求吞吐量提高 6.7%。
- **MetaGPT-TL**：相对 SPF 和 Parrot-FCFS（各指标最佳基线），TOPAS 将 mean JCT 降低 22.0%，p99 JCT 降低 26.6%。
- **消融结论**：相对 TOPAS-base，完整策略在 MetaGPT-TL 上 mean/p99 JCT 降低 60.5%/53.6%；相对单个组件变体，完整策略进一步降低 mean JCT 44.9%–51.0%，p99 JCT 44.2%–48.5%，说明未来复用和老化机制均有显著贡献。
- **核心发现**：显式地把前缀驻留作为工作流级调度决策，与请求准入联合优化，可以在有限 KV 缓存下有效协调批处理效率与任务进度，显著优于纯局部性或纯进度优先策略。
