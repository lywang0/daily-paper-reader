## 摘要
分块预填充流水线并行（CPP）是LLM推理的一项关键技术。然而，等大小块表现出不平衡的延迟，因为后面的块需要关注更长的前缀KV缓存并产生更高的注意力成本，导致流水线气泡。现有方法通过动态块大小调整（动态CPP，DCPP）来缓解这种不平衡，但我们的测量表明，这以调度开销换取负载均衡，在长序列上变得不利。在本研究中，我们提出了虚拟流水线并行（VPP），它保持块大小固定，并通过虚拟阶段优化流水线布局。V形虚拟阶段遍历将每个块昂贵的中间阶段与其相邻块的较轻头部和尾部阶段重叠，同时异步通信和流水线打包进一步减少通信停滞和跨请求排空气泡。我们在vLLM-Ascend中实现了VPP，并在16个Ascend 910C NPU上对三个基于MoE的LLM进行了长达100万token序列的评估。在长序列上，VPP比DCPP的吞吐量提高了高达13.1%，在混合工作负载上提高了6.7%，同时在短序列上保持了性能。在512K-token DeepSeek-V3.1预填充工作负载上，VPP将流水线气泡率从6.4%降低到0.1%，与DCPP相比减少了98.0%。

## Abstract
Chunked prefill pipeline parallelism (CPP) is a key technique for LLM inference. However, equal-size chunks exhibit imbalanced latency, as later chunks attend longer prefix KV caches and incur higher attention costs, leading to pipeline bubbles. Existing approaches mitigate this imbalance through dynamic chunk resizing (Dynamic CPP, DCPP), but our measurements show that this trades scheduling overhead for load balancing, which becomes unfavorable on long sequences. In this study, we propose Virtual Pipeline Parallelism (VPP), which keeps chunk sizes fixed and optimizes the pipeline layout through virtual stages. A V-shaped virtual-stage traversal overlaps each chunk's expensive middle stages with the lighter head and tail stages of its neighbors, while asynchronous communication and pipelined packing further reduce communication stalls and cross-request drain bubbles. We implement VPP in vLLM-Ascend and evaluate it on three MoE-based LLMs with sequences up to 1M tokens on 16 Ascend 910C NPUs. VPP improves throughput by up to 13.1% over DCPP on long sequences and 6.7% on mixed workloads, while preserving performance on short sequences. On a 512K-token DeepSeek-V3.1 prefill workload, VPP reduces the pipeline bubble ratio from 6.4% to 0.1%, achieving a 98.0% reduction compared with DCPP.

## 1. 核心问题与整体含义（研究动机与背景）

- 随着 LLM 应用（如智能代理、多轮对话、工具调用、复杂推理）的发展，推理请求的上下文长度不断增长，可达数十万乃至百万 token。长提示词的预填充（prefill）阶段计算密集、占用加速器时间长，会引发队头阻塞（HOL blocking）、TTFT 延迟增大、ITL 抖动等问题。
- 分块预填充（Chunked Prefill, Agrawal et al., 2023）通过将长提示拆分为较小的块，使其能与解码和其他短请求交错执行，缓解了排头阻塞。
- 在多设备场景中，流水线并行（PP）因仅传输相邻阶段间的中间激活，通信开销低于张量并行（TP）和序列并行（SP），成为大规模长上下文推理的重要方案。分块预填充与 PP 结合即为 CPP（Chunked Prefill Pipeline Parallelism）。
- **核心矛盾**：在 CPP 中，等大小分块会因因果注意力导致严重负载不均——越靠后的块需要处理越长的前缀 KV 缓存，注意力成本随块索引近似线性增长，导致各块延迟递增，产生大量流水线气泡（pipeline bubbles）。
- **现有方案（DCPP）的缺陷**：动态调整块大小（Dynamic CPP, DCPP）虽然能缓解负载不均，但引入额外调度开销、运行时校准和参数调优复杂度，并使执行碎片化。作者通过测量发现，在长序列下碎片化导致的算子效率下降和通信暴露增加，最终会超过负载均衡带来的收益，甚至出现性能倒退。
- **论文的核心主张**：块延迟的不均衡增长不是随意的，而是近似线性的、可预测的。与其消除这种不均（动态调整块大小），不如利用其规律性，通过优化流水线布局本身来吸收不均衡——这就是 VPP 的核心思路。

## 2. 方法论：核心思想、关键技术细节与算法流程

### 2.1 核心思想

- **保持块大小固定**，不动态调整块边界；通过将模型划分为多个“虚拟阶段”（virtual stages）并以 V 形折叠方式映射到物理流水线 rank 上，使计算负载在 rank 间保持平衡。

### 2.2 技术细节一：V 形阶段遍历（V-shaped Traversal）

- 以 2 个物理 rank（pp₀, pp₁）为例，模型被划分为 4 个虚拟阶段 s₀, s₁, s₂, s₃，其中边界阶段 s₀ 和 s₃ 放在 pp₀，中间阶段 s₁ 和 s₂ 放在 pp₁。每个块 C_k 的路径为：s₀(pp₀) → s₁(pp₁) → s₂(pp₁) → s₃(pp₀)，即先正向传播、再折返，构成“V”形。
- **负载均衡的依据**：设块 C_k 的每阶段延迟近似为 τ_k = (k+1)t，其中 t 为第一个块的单阶段延迟。当 pp₁ 执行 C_k 的两个中间阶段时，耗时为 2τ_k = 2(k+1)t；与此同时，pp₀ 可以执行上一块的尾阶段 s₃/Cₖ₋₁（延迟 τₖ₋₁ = kt）和下一块的头阶段 s₀/Cₖ₊₁（延迟 τₖ₊₁ = (k+2)t），两者总延迟为 kt + (k+2)t = 2(k+1)t，恰好与 pp₁ 的执行时间匹配。这样，相邻块的轻量头尾阶段填充了中间块昂贵中间阶段的执行窗口，从而消除负载不均造成的气泡。

### 2.3 技术细节二：异步通信与跨块阶段重排序（VPP-Async）

- 朴素 VPP 中跨 rank 的同步发送/接收会把通信延迟直接暴露在关键路径上，且存在双向同时传输造成的相互等待。
- 解决方法：对本地阶段的执行顺序进行重排（交换 Cₖ₋₁ 的尾阶段 s₃ 与 Cₖ₊₁ 的头阶段 s₀），使每个传输都在对端执行有效计算时发出，实现通信与计算的重叠，消除大部分暴露的通信停顿。

### 2.4 技术细节三：流水线打包（Pipelined Packing）

- 单个长请求的收尾阶段不可避免地产生 drain 气泡（末尾块陆续完成，一个 rank 无事可做）。由于实际服务系统中请求持续到达，可将后续请求 R′ 的前导块填入请求 R 的尾部气泡窗口，实现跨请求的重叠，压缩有效 drain 时间。

### 2.5 实现要点

- 基于 vLLM-Ascend 实现，控制面（虚拟阶段调度器、折叠层分配、逐批流水线状态机）用 Python 编写，注意力与 MoE 内核复用现有优化实现。
- 支持不均匀层划分与用户指定层范围，便于内存和计算均衡。
- 采用双队列调度器（初始虚拟阶段队列 + 跨过折叠点后的延续队列），支持异步任务句柄，避免阻塞调度循环。
- 使用两个交替的 HCCL 通信组执行点对点 send/recv，避免双向传输死锁。

## 6. 主要结论与发现

- **DCPP 在长序列上的局限性得到量化验证**：DCPP 通过动态分块有效减少了气泡（在 512K DeepSeek 工作负载下气泡时间减少 47%，气泡率从 12.5% 降至 6.4%），但碎片化执行导致计算时间增加 10.48%（+26.48s），暴露通信增加 36.05%（+6.01s），净效果是 TTFT 反而比 CPP 增加 4.65%。
- **VPP 在长序列上的优势显著**：
  - 相比 DCPP，吞吐量提升最高 13.1%（DeepSeek 512K），多数配置下为 3.7%–8.7%（Qwen）和 2.6%–13.1%（DeepSeek）。
  - 在 512K-token DeepSeek-V3.1 预填充工作负载上，气泡率从 6.4% 降至 0.1%，减少 98.04%；TTFT 相较 DCPP 降低 12.53%。
- **VPP 在混合工作负载上表现良好**：吞吐量比 DCPP 提升最高 6.7%（DeepSeek），并优于 CPP 9.0%–13.8%。
- **VPP 在短序列上不损害性能**：与 DCPP 相当或略优，仅在 Qwen（3.3B 激活参数较小）上出现最高 6.8% 的退化，原因是调度开销在小模型和短序列上难以摊销。
- **VPP 收益主要来自消除气泡而非加速计算**：消融实验表明三种变体间计算时间差异不超过 0.42%；VPP-Async 将通信重叠率从 0.02% 提升至 54.03%；流水线打包将跨请求气泡延迟降低 33.2%。
- **VPP 以额外的通信暴露为代价**：暴露通信比 DCPP 增加 35.05%，主要是 AllGather 辅助开销平均单次延迟增加 11× 所致，但整体通信重叠量大幅提升（从 0.01s 增至 32.86s）。
- **稀疏注意力削弱 VPP 的优势**：GLM 的 DSA 稀疏注意力降低了注意力成本随上下文长度的增长率，破坏了近线性延迟假设，使 VPP 的优势随序列增长而收窄，但在 512K 以下仍保持正收益。

## 7. 优点

- **方法创新性强**：将“动态调整块大小”的流行思路反转为“保持块大小固定、优化流水线布局”，利用块延迟增长的规律性（近线性）而非对抗它，为流水线调度提供了新视角。
- **理论分析简洁且有说服力**：通过简单的延迟模型 τ_k = (k+1)t 推导出 V 形遍历的负载均衡条件（等式 3），清晰直观。
- **工程实现完整**：在成熟的 vLLM-Ascend 系统上实现，涵盖调度器、通信组管理、折叠点处理等实际问题，不是纯理论方案。
- **实验设计系统全面**：覆盖了端到端性能、性能分解归因、消融研究、块大小敏感性分析等多个层面；动机实验（DCPP vs CPP）为问题定义提供了扎实的经验证据。
- **评估客观诚实**：明确报告了 VPP 在短序列 Qwen 上的退化、通信暴露增加、稀疏注意力模型上优势收窄等负面结果，可信度较高。

## 8. 不足与局限

- **模型与架构覆盖有限**：仅评估了 MoE 模型，未测试稠密 Transformer 模型；稀疏注意力实验只覆盖了 GLM 一个模型。
- **流水线深度未扩展**：所有实验仅在 PP=2（2 个流水线 rank）下进行，未验证 VPP 在更深流水线（PP=4/8）下的扩展性——而 V 形遍历的负载均衡论证依赖于 2-rank 的特殊配置，扩展到更多 rank 可能需要更复杂的布局设计。
- **硬件平台单一**：仅在华为 Ascend 910C 上测试，未在 NVIDIA GPU 等其他主流硬件上验证；HCCL 通信特性可能与 NCCL 存在差异，结论能否推广到其他平台未知。
- **DCPP 对比的公平性有一定争议**：DCPP 采用 vLLM-Ascend 的“推荐配置”（最小块 4096、平滑因子 1.0），但该配置未必是 DCPP 的最优配置；论文仅对 chunk-size budget 做了扫描，未对 DCPP 的其他超参数进行同样细致的调优。这可能在一定程度上放大了 VPP 的相对优势。
- **稀疏注意力的适配不足**：论文承认 DSA 稀疏注意力破坏了 VPP 依赖的线性延迟假设，且未提出针对稀疏注意力模型的改进方案，仅作为局限指出。
- **跨节点/大规模部署未涉及**：单节点 16 NPU 的测试规模相对有限，生产环境中的跨节点通信开销、多租户干扰、动态请求到达模式等未纳入评估。
- **缺乏与更广泛基线（如 gLLM、SGLang 等）的对比**：相关工作部分提到了这些系统，但实验中未直接比较。

## 附：TL;DR

VPP 通过固定分块大小 + V 形虚拟阶段遍历，将长上下文预填充中块延迟的近似线性增长转化为负载均衡的调度优势，辅以异步通信重叠和跨请求流水线打包，在长序列上相比 DCPP 实现最高 13.1% 的吞吐提升，并将 512K DeepSeek 预填充的气泡率从 6.4% 压至 0.1%。
