## 摘要
结合神经处理单元（NPU）与存内处理（PIM）的异构架构正被越来越多地用于加速LLM推理。先前的工作侧重于构建统一内存，使NPU和PIM能够无需复制即可共享数据。然而，这些设计隐含地假设每个张量绑定到固定的执行设备，因此依赖于静态的、偏向设备的数据映射。我们观察到这一假设在现代LLM工作负载中并不成立。由于阶段变化（例如，预填充与解码）以及诸如MoE路由等动态行为，同一张量的最优执行设备可能在运行时发生变化。在这种动态执行下，偏向设备的映射变得与访问模式不匹配，导致显著的带宽利用不足和性能损失。本文提出PFM（PIM作为灵活内存），一种双视角内存系统，将物理数据布局与访问者可见的逻辑视图解耦。PFM以联合优化的物理布局存储数据，并向NPU和PIM呈现不同的逻辑解释，从而在无需数据复制或重新布局的情况下实现跨设备的高效访问。我们进一步设计了访问者感知的地址转换和运行时调度机制，以支持LLM工作负载波动及最优执行设备动态变化时的动态执行。我们在多种LLM上的评估表明，PFM将端到端吞吐量提升最高达2.32倍，展示了其作为NPU-PIM系统统一内存管理解决方案的有效性和广泛适用性。

## Abstract
Heterogeneous architectures that combine neural processing unit (NPU) and processing-in-memory (PIM) are increasingly adopted to accelerate LLM inference. Prior work focuses on building a unified memory that allows NPUs and PIM to share data without duplication. However, these designs implicitly assume that each tensor is bound to a fixed execution device, and therefore rely on static, device-biased data mappings.   We observe that this assumption does not hold in modern LLM workloads. Due to phase changes (e.g., prefill vs. decode) and dynamic behaviors such as MoE routing, the optimal execution device for the same tensor can change at runtime. Under such dynamic execution, device-biased mappings become mismatched to access patterns, leading to substantial bandwidth underutilization and performance loss. This paper presents PFM (PIM-as-Flexible-Memory), a dual-view memory system that decouples physical data layout from accessor-visible logical views. PFM stores data in a jointly optimized physical layout and exposes different logical interpretations to NPUs and PIM, enabling efficient access across devices without data duplication or relayout. We further design accessor-aware address translation and runtime scheduling mechanisms to support dynamic execution when LLM workloads fluctuate and the optimal execution device dynamically changes. Our evaluation across LLMs shows that PFM improves end-to-end throughput by up to 2.32$\times$, demonstrating its effectiveness and broad applicability as a unified memory management solution for NPU-PIM systems.

## 1. 论文的核心问题与整体含义

- **背景**：LLM 推理呈现出明显的异构特征——部分算子为计算密集型（如 prefill 阶段的 GEMM），部分为访存密集型（如 decode 阶段的注意力、低算术强度的 MoE 专家）。NPU-PIM 异构架构通过让 NPU 执行计算密集算子、PIM 执行访存密集算子来加速推理，被业界广泛采用。
- **核心问题**：现有 NPU-PIM 统一内存系统（如 IANUS、FACIL）假设每个张量在分配时被绑定到一个固定执行设备，并采用静态、设备偏向（device-biased）的地址映射。然而，LLM 推理具有强动态性：
  - 同一算子在 prefill 与 decode 阶段的最优执行设备不同；
  - MoE 路由导致专家激活模式和算术强度在不同解码步骤间剧烈波动，同一专家张量的最优执行设备可能随步骤切换。
- **后果**：当运行时访问者（NPU 或 PIM）与预先设定的布局偏向不匹配时，有效带宽可跌至峰值的 20% 以下；即便采用最灵活的先验统一内存设计（FACIL），也只能达到理想 oracle 性能的 29.5%。频繁动态重布局（relayout）又会引入巨大数据搬移开销，不现实（Relayout 策略比 oracle 低 13.6%–53.6%）。
- **整体含义**：问题的根源不是物理内存分隔，而是“逻辑到物理映射的刚性”。PFM 通过解耦物理布局与访问者可见的逻辑视图，让单一物理布局同时高效服务 NPU 与 PIM，为动态 LLM 推理提供真正灵活的统一内存管理。

## 2. 论文提出的方法论

### 核心思想
- **双视角内存（Dual-View Memory）**：将物理数据布局与访问者可见的逻辑视图解耦。数据以“联合优化”的物理布局存储一次，不复制、不重布局；NPU 看到的是通道交织的连续访问视图，PIM 看到的是 bank 并行、局部连续的计算视图。
- 以 2 MB superpage 为粒度进行映射优化，利用大页的空间容纳能力同时满足两种设备的布局偏好。

### 关键技术细节

#### （1）PFMMalloc 与映射优化
- 提供轻量级用户态 API `PFMMalloc` 替代标准分配接口（如 cudaMalloc），分配时根据张量形状、数据类型、内存布局（行主序/列主序）触发离线映射优化。
- 将 PA-to-HA（物理地址到硬件地址）映射建模为 **多目标混合整数线性规划（MILP）**：
  - 变量：二进制矩阵 \(X \in \{0,1\}^{m \times n}\)，表示每个地址位分配给哪个内存层级（channel、bank group、bank、row、col）。
  - 约束：容量约束（每个层级的地址位宽有限）、结构约束（每个地址位只映射到一个层级）。
  - **NPU 目标**：最大化带宽利用率，\(NPU(f) = B_{NPU}/B_{peak}\)，通过分析模型估计行激活次数、列访问次数，推导出访存时间；
  - **PIM 目标**：最大化 bank 级并行度，\(PIM(f) = \frac{\#active\ banks}{\#banks\ total} \cdot \frac{T_{ref}}{T_{bank}(f)}\)，其中 \(T_{bank}(f)\) 考虑 DRAM 内部访问时间与外部 I/O 流送时间的流水瓶颈。
  - 联合目标：\(\max_f NPU(f) + \alpha \cdot PIM(f)\)，\(\alpha\) 由算子特性（算术强度、复用窗口）决定。
- 使用 COIN-OR/PuLP 求解器离线搜索，每个张量最多耗时 30 分钟，不影响运行时。

#### （2）双视角地址重映射单元（ARU）
- 位于内存控制器中，包含 **Mapping Descriptor Table (MDT)** 和 **地址生成单元 (AGU)**。
- 请求格式扩展：保留位中嵌入 `MapID`（选择映射方案）和 PIM 指令类型字段（如 `PIMMAC`），不影响常规 DRAM 协议的兼容性。
- 运行时按 MapID 实时将物理地址拆解为硬件坐标（channel、bank、row、col），并将请求路由到 NPU 或 PIM 专用队列。

#### （3）灵活访问调度器（FAS）
- 对 NPU 请求：按预计算映射优先调度跨通道并发组，利用 bank state tracker 优先行命中请求，减少行冲突；relayout buffer 将跨通道碎片聚合后按逻辑顺序交付 NPU。
- 对 PIM 请求：聚合跨 bank 的指令，批量广播执行，提高命令并行效率。
- 优先级仲裁：先服务刷新等强制维护；非空队列时优先 NPU 突发访问，在 NPU 计算窗口内机会性排空 PIM 批；PIM 长执行期间利用空闲 bank 预取 NPU 请求。

#### （4）运行时设备调度
- 基于 roofline 模型的轻量预测器：
  - \(T_{NPU} = \max(n \cdot d_{in} \cdot d_{out}/P_{NPU},\ |W|/B_{NPU})\)
  - \(T_{PIM} = \max(n \cdot d_{in} \cdot d_{out}/P_{eff}^{PIM},\ |W|/B_{eff}^{PIM}) + T_{setup}\)
- 每一步动态比较 T_NPU 与 T_PIM，选择预估延迟更低的设备执行；通过统一 `PFMlaunch` 接口透明调度 NPU 或 PIM 内核。

## 6. 主要结论与发现

- **静态设备偏向映射在动态 LLM 推理中是性能瓶颈**，理想动态设备切换可带来最高 2.26× 收益，而现有统一内存（FACIL）仅捕获 29.5%。
- **PFM 双视角内存能有效弥合 NPU 与 PIM 的布局偏好差异**：
  - 端到端吞吐相比 NPU-only 平均提升 1.20×（最高 1.95×），相比 PSM 平均 1.06×（最高 2.29×），相比 PUM 平均 1.55×（最高 2.32×）。
  - 小批延迟：相比 PUM 平均加速 2.23×，相比 PSM 平均 2.10×。
  - prefill 阶段相比 PUM 降低 3.43× 延迟（得益于保持 NPU 侧带宽效率）。
  - decode 阶段达到 oracle 效率的 96.8%，近似最优。
  - MoE 块延迟相比 NPU-only/PSM/PUM 分别降低 1.76×/2.01×/2.05×。
- **带宽平衡**：PFM 在 NPU 侧达到 92.10% 平均带宽利用，PIM 侧 94.85%；而 PUM 只保证 PIM 侧高（95.33%），NPU 侧极低（平均仅 17.43%）。
- **硬件开销可接受**：ARU+FAS 仅占 A100 内存接口区域 4.95%。

## 7. 优点

- **问题洞察深刻**：率先指出现有统一内存“张量绑定固定设备”的隐含假设在 MoE 动态路由下失效，并用量化数据（带宽下降、oracle 差距）清晰证明。
- **方案创新性强**：双视图内存概念优雅，通过“一次分配、双设备高效访问”避免复制/重布局，同时给出从离线多目标优化到在线轻量调度的完整软硬件协同设计。
- **建模细致**：将地址映射形式化为 MILP，N P U/PIM 目标函数均基于 DRAM 时序参数推导，兼顾通道交织、bank 并行、行激活/列访问开销；支持张量布局（行/列主序、KV cache 分块）的灵活建模。
- **工程完整性高**：提供用户级 API、MDT 映射复用、superpage 兼容现有 GPU 大页机制、硬件面积经综合评估、请求格式扩展不破坏 DRAM 协议，具有较强可落地性。
- **实验较全面**：覆盖多种模型架构、批大小、序列长度、阶段分解、带宽利用率与硬件开销，验证充分。
- **性能提升显著**：最高 2.32× 吞吐提升，且在小批延迟和大批吞吐两种场景下均优于所有 baselines。

## 8. 不足与局限

- **离线优化成本**：每个张量映射搜索最长 30 分钟，虽发生在编译期，但若部署模型频繁更新或超大规模模型张量形状较多，总离线时间可能很长。
- **动态适应性有限**：MDT 仅有 32 个条目，若服务模型集合或专家激活模式发生剧烈变化，可能需要重新 profiling 或扩展 MDT；论文未深入讨论条目替换策略和冲突处理。
- **调度模型简化**：运行时设备选择基于 roofline 模型，忽略算子间数据依赖、流水线重叠和跨算子带宽竞争等二阶效应，复杂交错访问下预测精度可能下降。
- **实验平台以 GPU 模拟 NPU**：论文明确指出用 GPU 代表 NPU 侧（GPGPU-Sim 模拟），真实 NPU（如 TPU、Ascend、自研 NPU）的微架构差异（调度器、缓存层次、访存模式）可能影响 PFM 的普适性结论。
- **对比基线时效性**：PUM 主要表征 PIM 偏向统一内存，对 FACIL 在大批次下按 PSM 等价处理；但 FACIL 本身支持多种映射切换机制，论文对其能力的简化可能低估先验系统在部分场景下的性能。
- **缺少对不同 DRAM 技术（HBM3、LPDDR）和不同 PIM 微架构（如 AiM、UPMEM）的敏感性实验**：虽然声称通用，但未验证。
- **未报告统计变异性**：实验均为单次归一化结果，未给出误差条或多次运行的波动范围，影响置信度。
- **面积开销评估局限于控制器部分**：未评估 MDT 查找、调度器决策对访存延迟的精确时钟级影响（虽然声称 RTL 测量已计入，但未细粒度披露）。
