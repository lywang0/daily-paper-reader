## 摘要
由于内存和带宽的严重限制，在边缘设备上部署大型语言模型（LLM）进行推理具有挑战性。虽然推测解码和混合专家模型（MoE）已被提出用于提升推理效率，但简单地将它们结合往往会带来过度的验证开销和较差的专家重用，限制了它们在内存受限的边缘场景中的有效性。在这项工作中，我们提出了S2-MoE，一种面向边缘设备MoE推理的高效自推测解码框架。S2-MoE通过路由感知的自适应推测扩展减少冗余验证，通过重用感知的专家门控提高验证效率，并通过共享上下文对齐草稿与目标执行。S2-MoE在llama.cpp中实现，在边缘设备上的多种MoE模型和数据集上，相较于标准自回归解码实现了高达5.3倍（平均约2.0倍）的加速。代码可在https://github.com/angerybob/S2-MoE获取。

## Abstract
Deploying large language models (LLMs) for inference on edge devices is challenging due to severe memory and bandwidth constraints. While speculative decoding and Mixture-of-Experts (MoE) have been proposed to improve inference efficiency, naively combining them often incurs excessive verification overhead and poor expert reuse, limiting their effectiveness in memory-bound edge settings. In this work, we propose S2-MoE, an efficient self-speculative decoding framework for MoE inference on edge devices. S2-MoE reduces redundant verification through routing-aware adaptive speculative expansion, improves verification efficiency with reuse-aware expert gating, and aligns draft and target execution via shared context. Implemented in llama.cpp, S2-MoE achieves up to 5.3x speedup (about 2.0x on average) over standard autoregressive de?coding across diverse MoE models and datasets on edge devices.Code is available at https://github.com/angerybob/S2-MoE.

# S2-MoE 论文详细总结

## 1. 论文核心问题与研究动机

- **背景挑战**：在边缘设备（如 Jetson、边缘 GPU）上部署大语言模型（LLM）推理时，面临严重的内存容量和内存带宽限制。边缘推理通常批大小很小（甚至为单批），参数重用率低，导致吞吐量主要受限于内存带宽。
- **关键瓶颈**：将吞吐量分解为“输出密度”（每迭代生成的 token 数）与“参数密度”（每迭代访问的参数量）之比乘以带宽。因此，提升效率要么增加每轮生成 token 数，要么减少每轮访问参数量。
- **现有技术及其局限**：
  - **推测解码**（Speculative Decoding, SD）：通过轻量草稿模型生成候选 token，再由目标模型并行验证，可提高输出密度，但在 MoE 模型上效果不佳——草稿 token 可能激活不同专家，导致验证阶段参数重用率低、验证成本高。
  - **MoE 稀疏激活**：可减少参数密度，但与 SD 结合时，被拒绝的草稿 token 仍可能触发额外专家激活，造成“冗余验证开销”。
  - **外部草稿模型方法**（如 EAGLE-3）：token 级置信度无法反映专家级验证成本；MoE 模型本身已高度稀疏，难以构建既轻量又对齐良好的草稿。
- **自推测解码的机遇**：从目标模型自身构建轻量草稿，可与目标行为更好对齐；但朴素自推测在 MoE 上仍有三大问题：草稿保真度不足、拒绝 token 导致冗余验证、专家参数重用不足。
- **本文目标**：设计一个同时保证高草稿保真度、低冗余验证和强专家参数重用的 MoE 推测解码框架，记为 **S2-MoE**。

## 2. 方法论：核心思想与关键技术

S2-MoE 由三个互补组件构成，整体流程为“草稿生成 → 自适应扩展 → 并行验证”，具体如下：

### 2.1 路由感知自适应推测扩展（Routing-aware Adaptive Speculative Expansion）

- **动机**：MoE 验证成本取决于草稿 token 激活的专家集合，而 token 置信度不能反映这一点。因此用“效用分数”联合衡量接受概率与验证代价。

- **期望收益**：对第 \(i\) 个草稿 token，若其前缀置信度为 \(p_i\)，则期望收益 \(B_i = p_i \times T_{AR}\)，其中 \(T_{AR}\) 为一次目标模型自回归步的平均延迟。

- **路由感知成本估计**：边际验证成本为
  \[
  \Delta C_{ver}(i|S) = |E_i \setminus \bigcup_{j \in S} E_j| \cdot T_{exp}
  \]
  其中 \(E_i\) 为草稿阶段预测的 token \(i\) 会激活的专家集合，\(S\) 为已选入扩展树的 token 集合，\(T_{exp}\) 为引入一个额外专家的延迟（通过运行时测量或离线 profiling 获得）。该估计利用草稿阶段的路由信号预测目标路由，已在多模型上验证与实测延迟高度相关（\(R^2=0.943–0.999\)）。

- **自适应扩展**：定义效用
  \[
  U_i = \frac{B_i}{\Delta C_{ver}(i|S)+C_i^{draft}}
  \]
  若 \(U_i \ge 1\) 则将该候选加入扩展树，否则剪枝。相比固定宽度或纯置信度剪枝，此机制能排除“高成本低收益”的候选分支，降低冗余验证。

### 2.2 复用感知专家门控（Reuse-aware Expert Gating）

- **动机**：MoE 中相邻 token 常被路由到不同专家，推测验证时专家参数重用率低，导致内存流量大。许多低分专家功能冗余，可适度牺牲评分换取跨 token 复用。

- **跨 token 专家重要性聚合**：对每个待验证 token \(b\)，用其 token 置信度 \(w_b\) 作为权重，对目标模型给出的专家 logits \(\ell_b\) 加权求和：
  \[
  g_e = \sum_{b \in B} w_b \cdot \ell_{b,e}
  \]
  这样高置信度 token 的专家偏好占据主导，因为其更可能被接受。

- **全局优选专家选择**：从聚合得分中选择数量受限的“复用偏好专家”集合 \(E^*\)，容量 cap 不小于路由 top-\(k\)，保证原始 top-\(k\) 专家仍可被选择。

- **软路由偏置**：对每个 token 的门控 logits 加上 \(\lambda_b \cdot 1[e \in E^*]\)，其中 \(\lambda_b\) 与 top-1 专家和 top-\((k+1)\) 专家之间的得分差距成正比，从而只影响边界专家而不破坏强主导选择。这使得低置信度 token 更可能被引导到已激活专家，提高跨 token 专家复用。

- **实现**：以轻量融合 CUDA kernel 实现，几乎不引入额外开销。

### 2.3 上下文对齐自推测解码（Context-aligned Self-speculative Decoding）

- **问题**：若草稿模型维护独立上下文，预测误差会逐步累积，导致草稿与目标分布之间 KL 散度随解码步数快速上升。
- **方案**：草稿与目标共享同一 KV Cache。目标模型先处理提示并建立缓存；草稿直接读取该共享上下文；草稿产生的临时 KV 更新在验证前回滚，只有被接受的 token 才提交到缓存。这样错误被限制在单个推测步内，不会跨迭代传播。

### 2.4 系统实现与专家级卸载

- 在 **llama.cpp** 中完整实现，适应边缘部署。
- 针对 MoE 专家稀疏性，实现 **专家级参数卸载**（而非 layer 级）：非专家和共享参数常驻显存，个别专家按需从 SSD（Jetson）或 CPU 内存（RTX 4090）取回；如果内存允许，则基于离线 profiling 将高频专家常驻显存。

## 6. 主要结论与发现

- S2-MoE 在边缘设备上为 MoE 模型带来显著端到端加速：
  - Jetson Orin 上相对自回归解码达 **1.3×–5.3×** 加速；

- 相较于 EAGLE-3 和 Cascade，S2-MoE 在不同模型、任务和内存约束下加速更稳定；在内存越紧张时优势越明显。
- 朴素 ES/LS 自推测基线在紧凑内存下经常低于自回归基线，说明仅靠草稿对齐不够，必须同时解决验证开销和专家复用问题。
- 质量方面：S2-MoE 在任务准确率上与原始模型相当（差异小且非系统性），长上下文分数接近，PPL ratio 约 1.012–1.013，Top-1 一致性高于 89%，说明复用感知门控引入的路由偏差是可接受的。

1. **问题意识切中要害**：明确指出 MoE 下推测解码的两个关键瓶颈——验证成本与专家复用——并用数据（图 2）佐证，动机扎实。
