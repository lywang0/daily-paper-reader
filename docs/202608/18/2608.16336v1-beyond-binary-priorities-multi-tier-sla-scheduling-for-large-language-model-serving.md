## 摘要
现代LLM服务部署必须同时满足不同用户层级的异构服务级别目标（SLO），从延迟关键的API调用到后台批处理。Llumnix引入了一个动态的、可迁移的多实例调度器用于LLM推理，通过统一的“空闲度”度量实现负载均衡、碎片整理、优先级排序和自动伸缩。然而，Llumnix的优先级模型仅限于两个级别（高和普通），这种抽象过于粗糙，无法表达生产环境中常见的更丰富的SLA类别。在这项工作中，我们将Llumnix的优先级模型扩展为支持任意数量的层级，并使用高保真LLM推理模拟器Vidur，在三种现实的优先级分布（均匀、高斯、企业）下评估了这种扩展的效果。我们在Vidur的分层调度框架内实现了具有指数衰减的每层余量、层级感知的调度顺序以及完整的Llumnix迁移流水线。我们将扩展后的调度器与INFaaS（全局路由基线）、vLLM、Orca和Sarathi-Serve（每副本基线）进行比较，扫描优先级级别从1到10。我们的实验表明，四个优先级层级能够产生最佳的成本效益权衡，与INFaaS相比，预填充阶段平均加速比高达8.3倍，端到端P99加速比高达3.1倍，每延迟成本改善46%至68%，同时保持了跨层级的强SLO区分。我们进一步证明，系统在10个优先级级别下仍能维持这些收益，没有尾部延迟崩溃，开销集中在预填充阶段。

## Abstract
Modern LLM serving deployments must simultaneously satisfy heterogeneous service-level objectives (SLOs) across a diverse population of user tiers, ranging from latency-critical API calls to background batch processing. Llumnix introduced a dynamic, migration-capable multi-instance scheduler for LLM inference that achieves load balancing, defragmentation, prioritization, and auto-scaling through a unified "freeness" metric. However, Llumnix's priority model is restricted to two levels (high and normal), an abstraction too coarse to express the richer SLA classes common in production deployments. In this work, we extend Llumnix's priority model to support an arbitrary number of tiers and evaluate the effects of this extension under three realistic priority distributions (uniform, Gaussian, enterprise) using Vidur, a high-fidelity LLM inference simulator. We implement per-tier headroom with exponential decay, tier-aware dispatch ordering, and the full Llumnix migration pipeline inside Vidur's hierarchical scheduling framework. We compare our extended scheduler against INFaaS (global routing baseline), vLLM, Orca, and Sarathi-Serve (per-replica baselines), sweeping priority levels from 1 to 10. Our experiments demonstrate that four priority tiers yields the best cost-effectiveness tradeoff, achieving prefill mean speedups of up to 8.3x and end-to-end P99 speedups of up to 3.1x over INFaaS with cost-per-latency improvements of 46 to 68%, while preserving strong SLO differentiation across tiers. We further show that the system sustains these gains at 10 priority levels without tail latency collapse, with overhead concentrated in the prefill phase.

## 1. 论文的核心问题与整体含义（研究动机和背景）

- **背景**：现代 LLM（大语言模型）服务部署需要同时满足异构的服务层级目标（SLO），从延迟敏感的 API 调用到后台批处理任务，不同用户的延迟要求差异极大。然而，LLM 推理请求具有高度的不可预测性（token 数、内存占用、执行时间在生成完成之前无法确定），加上突发的到达模式和异构的延迟需求，使得传统的单实例 FCFS 服务方式难以胜任。
- **已有方案的不足**：vLLM、Orca、Sarathi-Serve 等单实例调度器虽然优化了单副本的吞吐和内存效率，但本质上假设同质负载，采用一次性调度（一次分发后就无法迁移），无法应对内存碎片化、跨实例负载失衡和高优先级请求的再隔离问题。Llumnix 通过运行时重调度和实时迁移解决了上述问题，但其优先级模型仅支持二元分类（"高优先级"和"普通"），这一粒度过于粗糙，无法表达生产环境中常见的多级 SLA 类别（如铂金、金、银、标准、免费层级）。
- **核心研究问题**：(1) 对于一个支持迁移的 LLM 服务系统而言，多少级优先级是最合适的？(2) 隔离余量（headroom）应如何在各优先级层级之间分配？
- **整体含义**：本文突破了 Llumnix 的二元优先级框架，将多层级 SLA 调度引入 LLM 服务，为生产环境中差异化用户分层提供了可量化、可扩展的调度方案，并给出了"四层优先级最优"的实证结论。

## 2. 论文提出的方法论：核心思想、关键技术细节、公式或算法流程

### 2.1 核心思想

在 Llumnix 的"freeness"（空闲度）统一指标基础上，将二元优先级泛化为 K 级优先级（K ≥ 2），每一层级分配独立的隔离余量预算，实现细粒度的 SLO 区分，同时保持迁移、负载均衡、自动伸缩等能力。

### 2.2 系统架构

系统采用两层级架构：全局调度器（Llumnix Global Scheduler）位于多个副本调度器（Llumlet）之上。全局调度器负责分发请求、决定迁移、发出自动伸缩建议；每个 Llumlet 负责维护优先级队列、计算虚拟使用量、管理 KV 缓存分配和执行分阶段实时迁移。

### 2.3 空闲度（Freeness）指标

单个副本的空闲度定义为：

**F = (M − Σᵣ V(r)) / B**

其中：
- *M*：副本的总 KV 缓存块容量
- *V(r)*：请求 r 的虚拟使用量
- *B*：当前批次大小（活跃运行请求数）
- *F > 0* 表示有可用容量；*F < 0* 表示副本负载超限，触发迁移

### 2.4 虚拟使用量的 K 级优先级扩展

虚拟使用量的计算根据请求状态而异：
- 队首请求：消耗等于其需求（demand）
- 排队请求：消耗为 0
- 运行中请求：消耗 = 物理使用量 + 该优先级层级的余量 H(p)
- 排空实例：消耗设为 ∞

### 2.5 每层余量的指数衰减

第 **p** 层优先级的余量预算为：

**Hₚ = M · h_max · e^(−λp)**

其中 *h_max* = 0.20（最高优先级层保留 20% 容量），λ 使得最低层的余量趋近于 0。总虚拟余量为所有活跃优先级的余量预算之和。指数衰减的设计动机是：低优先级层级之间的隔离需求递减，同时保护整体系统效率。

### 2.6 优先级感知分发与迁移

- **分发**：严格按优先级从高到低分发（同层内 FCFS），选择空闲度最高且未排空的副本。
- **迁移**：基于时间间隔和负载失衡阈值触发。迁移候选优先选择排队请求（无 KV 状态，迁移成本低），其次是低优先级、KV 占用小的运行中请求。运行中请求采用多阶段迁移，请求在迁移过程中继续执行，仅在手机关机时产生短暂排队延迟。
- **自动伸缩**：使用排除优先级余量的"正常优先级空闲度"做伸缩决策，防止优先级隔离被误判为容量短缺。

## 6. 论文的主要结论与发现

1. **四层优先级（K=4）为最优配置**：在所有三种分布和两种请求规模下均取得峰值或接近峰值的性能。原因在于四层足以区分关键/高/标准/后台流量，而不会过度细分队列导致负载均衡启发式失效。
2. **显著性能提升**：相比 INFaaS+vLLM 基线，prefill 平均延迟最高加速 **8.3 倍**（10K 请求），端到端 P99 最高加速 **3.1 倍**，成本效率提升 **46–68%**（10K 请求）和 **24–53%**（15K 请求），超过原 Llumnix 论文报告的 16–36%。
3. **支持 10 级优先级不产生尾部延迟崩溃**：增加优先级粒度不会大幅增加整体延迟，开销主要集中在 prefill 阶段；decode 阶段性能稳定甚至略有改善。
4. **优先级收益与负载相关**：在高负载（15K）下，prefill P99 加速降至 2.0–3.2 倍，因为所有副本接近饱和时，空闲度差异缩小，迁移机会减少；中负载时收益最大。
5. **优先级粒度权衡原则**：更细的粒度提供更精确的 SLA 区分，但也增加总余量消耗（每个活跃层级都贡献完整预算），降低有效批处理容量。K=4 是所有负载分布下鲁棒的最优点。
6. **企业分布（生产场景）效果最佳**：关键流量占比小使得余量预算不常被竞争，中优先级队列保持良好的人口密度，有利于批量归一化。

## 7. 优点

- **方法创新**：将 Llumnix 的二元优先级推广为任意 K 层优先级，提出指数衰减的余量分配策略，设计简洁而有效（仅需两个超参数：h_max 和 λ）。
- **工程设计完整**：实现了完整的迁移流水线、优先级感知分发、排空机制和自动伸缩，并区分了"完整空闲度"与"正常优先级空闲度"用于不同决策目的，避免了优先级隔离引发的误伸缩。
- **实验框架严格**：使用高保真模拟器 Vidur 进行可复现实验；对基线进行了公平的一致化处理；同时报告了平均与尾部延迟的完整视图。
- **结果实用性强**：给出了明确的部署建议（四层 SLA 模型），并识别了负载与优先级收益之间的交互规律，具有直接的生产参考价值。
- **开源贡献**：提供完整源代码，便于后续研究复现和扩展。
- **诚实评估**：明确指出模拟器与真实硬件之间的差距、调度器比较实验的负载限制等局限性。

## 8. 不足与局限

- **模拟器固有偏差**：Vidur 模拟无法完整捕捉所有硬件效应（如迁移时的 PCIe 带宽竞争、CUDA kernel 启动开销），迁移成本的真实性存疑。论文建议未来需在 A100/H100 上做硬件验证。
- **缺少真实负载 trace**：使用合成长度分布而非实际生产 trace，可能无法完全反映真实工作负载的复杂突发模式。
- **调度器比较实验负载偏低**：QPS = 10 低于饱和，无法展示高负载下预期的层级分化；论文承认需要在更高利用率和按层报告的场景下验证优先级区分效果。
- **静态余量分配**：指数衰减参数是手动设定的静态值，未实现自适应调整；未来可探索基于实时 SLO 达成率动态调整的机制。
- **层级固定不可变**：请求到达后优先级不可动态调整，缺少 MLFQ 风格的提升/降级机制；低优先级请求在持续高负载下可能饥饿。
- **硬件与负载规模的推广性**：4 副本、最多 15K 请求的模拟规模有限，更大集群下迁移协调开销与优先级交互需要进一步验证。
- **未与其他多级优先级方案（如 SCORPIO、SLOs-Serve）直接对比**：仅对比了 INFaaS 和不支持多优先级的单副本调度器，未与同样支持多级 SLO 的调度器进行横向比较。
