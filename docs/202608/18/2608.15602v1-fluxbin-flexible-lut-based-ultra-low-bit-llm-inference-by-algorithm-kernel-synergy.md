## 摘要
虽然二值量化在理论上承诺了对大型语言模型（LLM）的极端压缩和加速，但现有研究常常忽视专用硬件内核的必要性，因此由于持续依赖昂贵的浮点运算或运行时反量化开销，未能释放全部加速潜力。为弥合这一差距，我们提出了FluxBin（基于灵活查找表的超低位宽二值基执行），一种算法-内核协同设计，将训练后量化与高度优化的CUDA内核相结合。在算法层面，我们引入了分离的行-列二值分解来增强表示能力，同时保持硬件效率，并辅以Hessian引导的显著性感知混合基以保留关键信息。在内核层面，我们实现了一种带有缩放融合的查找表构建方法，以减少浮点运算，并采用虚拟列映射将不规则、稀疏和显著的矩阵转换为密集执行。大量评估表明，FluxBin在多种模型架构上实现了高达5.92倍的加速和10.19倍的能耗节省，同时提供了与重度微调方法相当的精度。这有效地使得70B规模模型能够在单个A100 GPU上部署，内存减少4倍。代码可在https://github.com/nicyyyy/FluxBin获取。

## Abstract
While binary quantization theoretically promises extreme compression and acceleration for Large Language Models (LLMs), existing research often overlooks the necessity of specialized hardware kernels, thus failing to unleash the full acceleration potential due to persistent reliance on expensive floating-point arithmetic or runtime dequantization overheads. To bridge this gap, we propose FluxBin (\textbf{F}lexible \textbf{L}UT-based \textbf{U}ltra-low-bit e\textbf{X}ecution with \textbf{Bin}ary bases), an algorithm-kernel co-design that synergizes post-training quantization with a highly optimized CUDA kernel. Algorithmically, we introduce Decoupled Row-Column Binary Decomposition to enhance representational capacity while maintaining hardware efficiency, complemented by a Hessian-guided saliency-aware hybrid bases that preserve critical information. At the kernel level, we implement a Lookup Table Building Approach with Scale Fusion to reduce floating-point arithmetic, featuring a Virtual Columnar Mapping that transforms irregular, sparse, and salient matrices into dense execution. Extensive evaluations demonstrate FluxBin achieves up to $5.92\times$ speedup and $10.19\times$ energy savings across diverse model architectures, delivering comparable accuracy to heavily fine-tuned methods. This effectively enables the deployment of 70B-scale models on one single A100 GPU with a $4\times$ memory reduction. Code is available at https://github.com/nicyyyy/FluxBin.

### 1. 核心问题与整体含义（研究动机和背景）

- **背景**：大型语言模型（LLM）规模庞大，推理时面临严重的存储和带宽瓶颈。训练后量化（PTQ）是无需重训练即可降低位宽的标准方案，其中二值量化（binary quantization）在理论上将压缩推向极限（权重仅需 1 比特），是最具吸引力的方向。
- **核心问题**：尽管二值量化理论效率极高，现有方法（如 BiLLM、ARB-LLM、HB-LLM 等）普遍存在三个关键缺陷：
  - **未充分利用硬件的免乘法潜力**：多数算法仅注重量化精度（如模拟量化），推理时仍需将权重反量化为 FP16，位运算的硬件优势并未转化为实际端到端加速。
  - **显著性粒度与硬件效率难以兼顾**：非结构化稀疏方法（如 SPQR、PB-LLM）受限于不规则内存访问和元数据开销；粗粒度方法（如 SLiM-LLM）则以高精度保留整组非显著元素，造成位宽冗余。
  - **低位宽内核实现效率低**：自回归生成阶段本质上是内存密集型，即使 INT8 精度也受硬件吞吐限制。现有 W4A16 方法因动态反量化产生可观运行时开销，而现有 LUT 内核也难以处理混合精度带来的不规则内存访问。
- **论文主张**：现有理论压缩与实际推理加速之间存在显著鸿沟，必须通过**算法与内核的协同设计**才能真正释放超低位宽（ultra-low-bit）推理的加速潜力。FluxBin 即为此目标提出的算法-内核联合设计方案。

### 2. 方法论：核心思想、关键技术细节

#### 2.1 总体框架概览

FluxBin 由**算法层（PTQ 量化方法）**与**内核层（CUDA LUT 内核）**两部分构成，二者协同工作。算法层提供高保真、支持混合精度的量化权重；内核层针对该量化格式设计免乘法、少浮点的 GEMV 内核，实现端到端加速。

#### 2.2 算法层：FluxBin 量化

**(1) 解耦行列二值分解（Decoupled Row-Column Binary Decomposition）**

- 传统二值基方法仅使用行缩放；FluxBin 引入**列方向缩放**，以捕捉 LLM 权重各向异性的分布特征。
- 形式上，第 k 阶基的权重近似为：

  \[
  \hat{W}^{(k)} = (\alpha_r^{(k)} \alpha_c^{(k)\top}) \odot B^{(k)}
  \]

  其中 \(B^{(k)} \in \{-1,+1\}^{M \times N}\) 为二值基，\(\alpha_r^{(k)} \in \mathbb{R}^M\)、\(\alpha_c^{(k)} \in \mathbb{R}^N\) 分别为行、列缩放向量。最终权重为 \(K_b\) 个基之和：\(\hat{W} = \sum_{k=1}^{K_b} \hat{W}^{(k)}\)。
- **参数优化**：采用交替最小化（alternating minimization），固定二值基和其中一个缩放向量时，另一个缩放向量有闭式最优解（式 5）。当 \(K_b \ge 2\) 时，采用联合优化而非贪婪逐阶提取；对每个元素位置穷举 \(2^{K_b}\) 种二值符号组合，寻找最优二值基分配（式 6）。

**(2) Hessian 引导的结构化显著性搜索**

- 借鉴 OBQ（Optimal Brain Quantization）框架，利用逆 Hessian 矩阵 \(H^{-1}\)（通过 Cholesky 分解高效计算）衡量权重敏感度。
- 将逐元素误差聚合成**列级显著性分数**：\(S_j = \sum_i W_{ij}^2 [H^{-1}]_{jj}^2\)。
- 为保证负载均衡，将列划分为大小为 g 的组，每组选择 s 个得分最高的显著列，形成二元掩码 \(M\)。

**(3) 显著性感知的混合基（Salient-Aware Hybrid Bases）**

- 最终量化权重 = **全局基近似** + **显著性精化**（仅作用于显著列）：

  \[
  \hat{W} = \underbrace{\sum_{k=1}^{K_b} Q(W; \Theta_k)}_{\text{Global Base}} + \underbrace{\sum_{k=1}^{K_s} Q(R_{\text{base}}; \Phi_k) \odot M}_{\text{Salient Refinement}}
  \]

- 全局基捕捉整体权重结构，显著性精化在残差上补偿关键列的误差，实现"细粒度保护 + 结构规整"的统一。
- 该方法为纯 PTQ，无需微调或蒸馏。

#### 2.3 内核层：LUT-based CUDA Kernel

**(1) 背景：LUT 乘法原理**

- 在二值权重矩阵中，不同行经常出现相同的权重子模式（如 [+1,+1,−1]），导致对同一输入子向量重复计算点积。
- LUT 方法将输入维度划分为大小为 μ 的子向量，为每个子向量预计算 \(2^\mu\) 种可能的线性组合并存入查找表。推理时直接用 μ 位二值权重模式作为内存地址取回部分和，以查表替代乘法。

**(2) LUT-BSF（Lookup Table Building with Scale Fusion）**

- 利用列缩放 \(\alpha_c\) 被所有行共享的特点，将其直接融合进 LUT 构建过程（即 LUT 基于 \(X \odot \alpha_c\) 构建），从而把列缩放从 GEMV 主循环中解耦，消除相关浮点运算。
- LUT 表项为：\( \text{LUT}[p] = \sum_{n=1}^{\mu} (X_{\text{sub}}[n] \cdot \alpha_{c,\text{sub}}[n]) \cdot (2b_n(p) - 1) \)。

**(3) 虚拟列映射（VCM, Virtual Columnar Mapping）**

- 解决显著性精化分支中稀疏列导致的不规则内存访问问题。
- 将逻辑上稀疏的显著列重新映射为物理上连续的稠密矩阵（按 \(I_{\text{sal}}\) 收集列），运行时仅需通过翻译层收集对应激活和缩放因子。
- 从而将稀疏操作转化为稠密 GEMV，实现全局基和显著性精化两个分支的**统一内核执行**。

**(4) LUT 读取与归约**

- 内核直接以压缩的 Uint32 权重流式读取，而非反量化为 FP16。通过位运算提取 μ 位子块模式索引，从共享内存 LUT 中获取预计算部分和，最终在寄存器中进行行缩放并累加写回。

**(5) 矩阵分块**

- 权重矩阵划分为 \(M_{\text{tile}} \times N_{\text{tile}}\) 的 tile 映射到线程块；块内共享 LUT，供所有线程查询。

### 6. 主要结论与发现

1. **极限加速**：FluxBin 在 LLaMA-2-7B 上达到 **254.39 tokens/s**，较 FP16 基线提速 **5.92×**；解码阶段（BS=1）提速达 6.3×~6.6×，且在大 batch 下优势持续保持，突破了传统 weight-only 量化大 batch 下优势递减的惯例。
2. **极致能效**：总能耗较 FP16 降低 **10.19×**（13B 模型），平均功率从 ~225W 降至 ~115W，源于更少的数据搬运和以 SRAM 查表替代 FP16 浮点运算。
3. **高保真精度（无需训练）**：作为纯 PTQ 方法，FluxBin-2b-s16-g128 在 LLaMA-2-7B 上平均零样本准确率 59.15%，与需要微调的 QuIP#（59.41%）相当，优于 AQLM（58.64%）。
4. **大模型单卡部署**：LLaMA-2-70B 可在单张 A100 上以约 20GB（2b-g128）内存运行（FP16 下 OOM），实现 **4× 以上内存压缩**。
5. **架构无关性与可扩展性**：在 LLaMA-3.1（含最新 70B 模型）和 Qwen3（含 GQA 架构）上均保持一致的高吞吐与精度优势；尤其在敏感的 LLaMA-3.1-70B 上，FluxBin 平均精度 67.81%，较 AQLM 提升 +17.5%。
6. **加速来源明确**：①权重存储压缩 8×，缓解 HBM 瓶颈；②LUT 将 μ 次 FMA 替换为 1 次查表（复杂度降低 μ/Kb = 4×）；③用 SRAM 访问替代 ALU 密集的反量化指令，均与 batch size 无关。

### 7. 优点

- **算法-内核协同设计**：真正将"理论压缩"转化为"实际加速"，而非停留在量化精度层面，直击现有二值量化方法的痛点。
- **解耦行列二值分解**：相比仅行缩放的方法，列缩放更好地捕捉 LLM 权重分布的各向异性，提升表示能力。
- **混合精度设计巧妙**：以 Hessian 引导的显著性精化仅作用于少量关键列（如 6.25%），以极小额外存储（有效位宽仅 ~2.63~2.75 bits）换取显著精度提升。
- **VCM 虚拟列映射**：将稀疏操作变换为稠密执行，兼顾稀疏保护与内核执行效率，设计思路新颖（借鉴 OS 内存虚拟化）。
- **LUT-BSF 尺度融合**：将列缩放融合到 LUT 构建中，从主循环中剔除大量浮点运算。
- **实验非常全面**：涵盖多种模型架构、规模、配置，包括吞吐/精度/能耗/内核级多维度评估，以及多组消融（组件、组大小、校准样本数、子向量大小、tiling 参数），对关键设计选择有充分论证。
- **客观清晰的局限性披露**：主动指出共享内存扩展性限制和 PTQ 精度天花板。

---

### 8. 不足与局限

- **共享内存约束**：LUT 存储随子向量大小指数增长（\(2^\mu\)），在共享内存较小的 GPU 上（如消费级卡）需降低 μ 或 batch size，可能影响加速效果；论文实验仅在 A100 上验证，缺乏对其他硬件平台的覆盖。
- **纯 PTQ 的精度天花板**：虽与微调方法持平，但与充分微调的模型仍存在微小差距；论文承认未来可探索轻量级 PEFT 以进一步缩小差距。
- **对比公平性存疑**：与其他方法的速度对比中，FluxBin 拥有自研高度优化的 CUDA 内核（并配合 CUDA graphs），而部分 baseline（如 AQLM、QuIP# 的端到端实现）可能未经过同等优化水平，速度对比可能偏高 FluxBin 一侧。不过逐算子内核对比在一定程度上缓解了该问题。
- **扩展实验的精度缺失**：在 LLaMA-3.1/Qwen3 扩展实验中，部分 baseline（AQLM、GPTQ）的吞吐数据缺失，且 Qwen3 对比中缺少 QuIP#、AQLM 等强 baseline，使架构泛化性的说服力有所折扣。
- **能效评估口径**：GPU 利用率/内存利用率的定义和解释不够详尽（文中也承认 GPU busy time 是占用率而非算力饱和度的度量），能耗数据基于快速解码段采样，对全生命周期（含 prefill 阶段）的能效未充分展开。
- **校准集敏感性**：校准样本数量存在明显的"先升后降"趋势，说明方法对校准数据量有较高敏感性，实际部署中需要仔细调节 \(N_{\text{cal}}\)，可能增加使用门槛。
- **二值基数量限制**：穷举搜索最优二值基组合的复杂度为 \(2^{K_b}\)，基数量较多时（如 4-base 以上）计算开销可能成为瓶颈，论文未讨论大规模基数量下的可扩展性。
