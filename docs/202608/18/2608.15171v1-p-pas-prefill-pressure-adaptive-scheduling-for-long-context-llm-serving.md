## 摘要
长上下文LLM应用，如检索增强生成（RAG）和智能体系统，通常处理数万输入令牌以产生短输出，这使得端到端请求延迟成为重要的服务目标。我们表明，最大批量令牌数（MBT）——控制vLLM中令牌调度预算的参数——对延迟具有依赖于调度压力的影响。在低调度压力下，较大的令牌预算可以减少延迟，而在高压力下，较小的预算则更受青睐。因此，没有任何单一的静态MBT能在所有负载情况下表现最佳。我们引入了预填充压力自适应调度（P-PAS），一种轻量级策略，根据并发预填充和解码状态动态调整调度预算。P-PAS在低压力下保持较大的令牌预算，并随着压力增加限制预填充工作。在不同模型、工作负载和GPU上，P-PAS在变化的负载情况下保持低端到端延迟，避免了固定MBT的局限性。内核级分析表明，大的预填充块可以在低调度压力下提高执行效率，但这种优势因模型-硬件配置而异。随着调度压力的增加，较小的块反而可以减少与活动解码的干扰，这解释了观察到的负载相关的MBT敏感性。用于复现我们结果的代码和工件可在 https://github.com/TimoSaemann/ppas-vllm 获取。

## Abstract
Long-context LLM applications such as retrieval-augmented generation (RAG) and agentic systems often process tens of thousands of input tokens to produce short outputs, making end-to-end request latency an important serving objective. We show that the maximum number of batched tokens (MBT), which controls the token scheduling budget in vLLM, has a scheduling-pressure-dependent effect on latency. Larger token budgets can reduce latency under low scheduling pressure, while smaller budgets become preferable under higher pressure. Consequently, no single static MBT performs best across load regimes.   We introduce Prefill-Pressure Adaptive Scheduling (P-PAS), a lightweight policy that dynamically adapts the scheduling budget based on concurrent prefill and decode state. P-PAS retains a large token budget under low pressure and constrains prefill work as pressure increases. Across models, workloads, and GPUs, P-PAS maintains low end-to-end latency across changing load regimes, avoiding the limitations of a fixed MBT.   Kernel-level profiling shows that large prefill chunks can improve execution efficiency under low scheduling pressure, but that this advantage varies across model--hardware configurations. As scheduling pressure increases, smaller chunks can instead reduce interference with active decoding, explaining the observed load-dependent MBT sensitivity. Code and artifacts for reproducing our results are available at https://github.com/TimoSaemann/ppas-vllm .

## 1. 论文的核心问题与整体含义（研究动机和背景）

- **研究对象**：长上下文 LLM 服务场景（如 RAG、智能体系统），典型特征是 prompt 长达数万 token 而输出极短（数十 token），端到端请求延迟是核心服务质量指标。
- **核心观察/问题**：vLLM 中控制单次调度迭代 token 预算的 最大批处理 token 数（MBT, Maximum Batched Tokens） 对端到端延迟的影响依赖于调度压力（scheduling pressure）：
  - 低调度压力下，**大 budget（如 MBT 16k）** 通常更好，因为大块 prefill 执行效率更高；
  - 高调度压力下，**小 budget（如 MBT 2k）** 反而更优，因为能减少 prefill 对活跃 decode 的干扰。
- **关键矛盾**：突发性（bursty）工作负载往往在同一服务运行周期内跨越多个负载区间，**任何单一固定 MBT 都无法在所有负载状态下保持最优延迟**。该观察构成了论文的核心动机。

## 2. 论文提出的方法论：P-PAS

**核心思想**：根据调度器当前状态动态调整 prefill token 预算，在低压力时保留大预算以利用 prefill 执行效率，在压力升高时收紧预算以限制 prefill 与 decode 的相互干扰。

**关键技术细节**：

- 在 vLLM 调度器上增加一个轻量扩展，不改变全局 MBT，而是引入对单次迭代中**聚合 prefill token 数的额外约束**。
- 调度决策仅依赖调度器已有状态，**无需离线负载预测、无需预设请求速率阈值、无需额外 profiling**。
- 决策每个迭代都重新评估，压力消退后立即恢复大预算。

**算法流程**（文字描述）：

1. 计算当前运行中 + 等待中的 prefill 请求数 Np；
2. 计算当前运行中的 decode 请求数 Nd；
3. 若 Np ≥ Nth 且 Nd > 0（存在 prefill 压力且有活跃 decode），则本轮 prefill 预算设为小值 Bcap；
4. 否则，prefill 预算保持为大值 Bmax；
5. 将本轮调度中所有 prefill token 总数限制在所选预算内。

**评估配置**：Nth = 2，Bmax = 16384，Bcap = 2048（该配置在整个实验过程中固定不变，且在所有模型、负载和 GPU 上保持不变）。

## 6. 论文的主要结论与发现

- **P-PAS 有效性**：在主要配置（Qwen2.5-3B, RTX 5090）的完整 sweep 中，相比 MBT 2k 平均端到端延迟降低 8.5%，相比 MBT 16k 降低 11.3%；P95 延迟相比 MBT 16k 降低 10.0%。
- **跨配置鲁棒性**：在三种模型、三种 prompt 长度、三种 output 长度、A100 GPU 上，P-PAS 总体均优于两个固定 MBT 基线；个别例外（如 30k prompt 时 P95 相比 MBT 2k 差 2.7%，最高 burst 1.4 时相比 MBT 2k 略差）。
- **MBT 敏感性的成因**：
  - **低压力**：大块 prefill（16k 单块）相比多个 2k 小块在 FlashAttention 和 fused gate-up projection 等主导 kernel 上运行时间更短，总 prefill 时间减少 10.5%–11.6%（Qwen2.5-0.5B/3B）；
  - **高压力**：大 MBT 使 prefill 与 decode 在同一个长迭代中互相干扰，decode 推进频率降低、TPOT 恶化；小块预算将 prefill 分散到多个迭代，decode 获得更频繁的推进机会；
  - 大块 prefill 效率优势不是普适的：Qwen2.5-7B 上仅减少 0.6% prefill 时间（L2 命中率降低、DRAM 压力大幅上升，SM 吞吐几乎不变），对应的 MBT 敏感性和 P-PAS 收益也大幅减弱。

## 7. 优点

- **轻量且实用**：P-PAS 仅依赖调度器已有状态（Np、Nd），无额外推理开销，可直接嵌入 vLLM 调度器。
- **自适应能力强**：不依赖离线预测和预设请求速率，可随负载动态在两种预算之间切换，适应突发性负载。
- **实验设计较全面**：在模型、负载、硬件多维度验证了鲁棒性，且 P-PAS 配置在所有实验中固定不变，增强了结论的可推广性。
- **机制解释深入**：通过 Nsight Compute/Sys tems 的 kernel 级分析揭示了 MBT 敏感性的微观根源（大块 prefill 效率优势 — 缓存行为差异 — decode 干扰），而非停留在端到端延迟的宏观观察层面。
- **开源可复现**：提供了代码和复现工件链接。
- **结果客观**：报告了固定 MBT 在特定负载下优于 P-PAS 的反例（如最高 burst 时 MBT 2k 略优；Qwen2.5-7B 上 P-PAS 收益微弱），并未选择性呈现有利数据。

## 8. 不足与局限

- **模型规模覆盖有限**：最大模型为 7B，未覆盖当前主流的 30B–数百 B 参数规模；论文也自认未来需扩展。P-PAS 在 7B 上收益已大幅衰减，更大模型的适用性存疑。
- **对比基线不够全面**：仅对比固定 MBT，未与 Sarathi-Serve、FlowPrefill、Layered Prefill 等其它 prefill 调度策略直接对比。
- **P-PAS 自身配置固定不自适应**：Nth、Bmax、Bcap 均为手工设定且跨实验不变；论文承认未来方向之一是让这些配置本身自适应。
- **小规模/短 trace**：50 秒的 trace 时间较短；场景为单 GPU 单节点；未考虑多 GPU、多节点分布式服务及 MoE 架构。
