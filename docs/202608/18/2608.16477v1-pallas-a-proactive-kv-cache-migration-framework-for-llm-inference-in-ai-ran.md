## 摘要
AI-RAN将大语言模型（LLM）服务带到移动用户附近，但蜂窝切换可能使活动请求与其推理状态分离：用户连接到目标基站（gNB），而不断增长的键值（KV）缓存仍留在源端。在源端保留推理可维持服务连续性，但会持续增加令牌间延迟（ITL）；而在目标端恢复状态可恢复服务局部性，但仅在切换后需要KV缓存传输、重计算或两者结合，直接延长服务中断时间（SIT）。本工作提出Pallas，一种主动式KV缓存迁移框架，在切换前于预测目标端准备推理状态，与源端正在进行的推理和令牌传输并行。在准备触发时，Pallas将令牌序列划分为稳定的历史前缀和演化的后缀。目标端通过本地预填充重建前缀，而源端流式传输为后缀生成的KV块。切换时，目标端将两部分组装成最新的KV缓存并恢复本地解码，仅未完成的准备部分计入SIT。在线调度器基于移动性预测和运行时遥测选择预取窗口，决定切换前开始准备的提前量。在三个LLM和100–500 Mbps的gNB间链路上，我们基于vLLM的原型相比目标端恢复方法平均将SIT降低2.28–89.68倍，相比源端转发将平均ITL降低16.0%–50.0%。

## Abstract
AI-RAN brings large language model (LLM) serving close to mobile users, but cellular handover can separate an active request from its inference state: the user attaches to a target base station (gNB) while the large and growing key-value (KV) cache remains at the source. Retaining inference at the source preserves service continuity but persistently increases inter-token latency (ITL), whereas recovering the state at the target restores serving locality but requires KV-cache transfer, recomputation, or a combination of both only after handover, directly prolonging service interruption time (SIT).   This work presents Pallas, a \textit{proactive} KV-cache migration framework that prepares the inference state at the predicted target before handover, in parallel with ongoing source-side inference and token delivery. At the preparation trigger, Pallas partitions the token sequence into a stable historical prefix and an evolving suffix. The target reconstructs the prefix through local prefill, while the source streams the KV blocks generated for the suffix. At handover, the target assembles both portions into an up-to-date KV cache and resumes decoding locally, leaving only unfinished preparation to contribute to SIT. An online scheduler selects the \textit{prefetching window}, which determines how early preparation begins before handover, based on mobility predictions and runtime telemetry. Across three LLMs and $100$--$500~\mathrm{Mbps}$ inter-gNB links, our vLLM-based prototype reduces average SIT by factors of $2.28$--$89.68$ over target-side recovery approaches and lowers average ITL by $16.0\%$--$50.0\%$ compared with source-side forwarding.

## 论文分析与总结

### 1. 核心问题与整体含义（研究动机与背景）

- **AI-RAN 背景**：无线接入网（RAN）正从纯连接基础设施演变为分布式计算平台。AI-RAN 将 GPU 等加速器与基站（gNB）共置，从而将大语言模型（LLM）推理服务带到移动用户附近，有助于降低延迟敏感型服务的通信时延。

- **核心矛盾——切换导致"状态分离"**：LLM 推理是自回归解码过程，需要持续增长的键值缓存（KV cache）作为推理状态。当移动用户发生蜂窝切换时：
  - 用户设备（UE）的网络连接切换到目标 gNB；
  - 但增长中的大量 KV 缓存仍留在源 gNB。
  - 于是"服务的推理状态"与"用户所在位置"发生分离。

- **严重的时间尺度不匹配**：以 Qwen3-32B 为例，KV 缓存每 token 增长约 256 KiB，4,000 tokens 时约 1 GiB；在 300 Mbps 的 gNB 间带宽下，仅传输该数据就需约 28 秒——而切换本身是瞬间完成的。

- **现有方案的两难困境**：
  - **源端保留（Detour 类）**：保持服务连续性，但每个 token 都要经过额外转发跳数，持续恶化令牌间延迟（ITL）。在三跳下，P90/P99 ITL 可达 126-264 ms，明显超过 100 ms 的延迟目标（SLO）。
  - **目标端恢复（Full-Copy/Recomputation/ctHO 类）**：恢复服务局部性，但状态恢复工作全部在切换后执行，切换后无法立即解码，服务中断时间（SIT）长。
  - 共同症结：**状态恢复都在切换后才开始**，即"反应式恢复"。

- **本文的核心主张**：应当把切换当作目标端状态准备的**截止期限（deadline）**，而不是恢复的触发点——利用移动性预测在切换前主动准备推理状态，把大部分恢复工作挪到切换之前完成。

### 2. 方法论

#### 2.1 核心思想：主动式并行状态准备

- 在**准备触发时刻**，Pallas 将 token 序列在块对齐的切分点处分为两部分：
  - **稳定历史前缀（[0, k)）**：触发前已处理的 token，不再变化；
  - **演化后缀（[k, ...)）**：触发后源端继续生成的 token，持续增长。
- **并行执行三条操作**：
  1. 目标 gNB 接收历史前缀的精确 token ID，通过**本地 prefill 重建**前缀 KV 缓存；
  2. 源 gNB 继续解码并向 UE 传送 token（不受打断）；
  3. 源 gNB 将新完成的后缀 KV 块**增量流式传输**给目标 gNB。
- **切换完成时**：目标端把重建

前缀 KV 缓存与已流式传输的后缀 KV 缓存拼接，形成与源端一致的完整 KV 缓存；此后目标 gNB 接管解码，UE 无需在切换后等待任何恢复动作。由于大部分状态重建工作（prefill 与传输）在切换完成前并行完成，切换后的恢复延迟被压缩到接近零，服务中断时间（SIT）大幅缩短。

#### 2.2 关键设计：前缀预取与增量流式传输的权衡

为了在有限准备时间内平衡重建开销与传输开销，Pallas 对前缀长度 `k`（切分点）进行优化。设 `T_prepare` 为从准备触发到切换完成的可用时间，目标端重建前缀 KV 的时间近似为 `T_prefill(k) = α·k`（与 token 数成正比），而流式传输后缀 KV 的时间近似为 `T_transfer(BW, N-k)`（与待传块数成正比）。Pallas 选择满足 `T_prefill(k) + T_transfer(k) ≤ T_prepare` 的最大 `k`，从而利用两种机制的互补性：

- **历史前缀**占用大量计算但可高度并行，适合在准备窗口内就地计算（prefill）；
- **演化后缀**规模小但持续增长，适合通过低带宽占用进行增量传输。

该设计避免了全复制式传输的高带宽压力，也避免了纯重算导致的延迟暴露，是二者的折中与结合。

#### 2.3 系统协议与状态一致性保证

Pallas 在现有 3GPP 切换流程基础上扩展，核心是增加一个“准备阶段”信令：

1. **移动性预测触发**：基于 UE 测量报告、RSRP 序列或历史轨迹，Pallas 在当前服务链路质量低于阈值时提前识别目标小区，进入准备模式；
2. **准备信令（Prepare request）**：源 gNB 向目标 gNB 发送包含 token ID 序列（或前缀指纹）、当前解码器状态、模型标识等元数据；
3. **目标端 prefill**：目标 gNB 在本地 GPU/加速器上对历史前缀执行 prefill，构建前缀 KV 缓存；
4. **增量流式传输**：源 gNB 在后台将新生成的 KV 块按 VLLM 的块粒度（如 16 token/块）持续推送到目标 gNB；
5. **切换执行**：UE 正式执行无线切换；目标 gNB 拼接本地前缀 KV 与收到的后缀 KV，继续解码，并向 UE 转发待传 token。

为保证一致性，Pallas 在每个 KV 块上附带 token ID、序列号和模型版本信息；目标端在拼接前校验块连续性。若切换未能发生（预测假阳性），目标 gNB 仅丢弃临时缓存即可，无额外信令开销；若传输未完成（准备超时），则退回传统恢复流程，保证正确性。

#### 2.4 延迟与带宽建模

Pallas 明确将延迟 SLO（如 P99 ITL < 100 ms）映射为系统参数：

- **令牌间延迟（ITL） = 解码步长 + 端到端传输延迟**。源端 Detour 路径因每个 token 需经“源 gNB → 目标 gNB → 用户”多跳转发而显著惩罚 ITL；Pallas 则在切换前额外引入了后台 KV 传输流量，但不影响当前解码路径的 ITL；
- **服务中断时间（SIT） = 控制面切换时间 + 目标端恢复准备时间**。传统方案在切换后才启动 prefill/拷贝，SIT 包含完整恢复时间；Pallas 将恢复时间从 SIT 中完全移除，仅保留无线切换本身的控制面时延；
- **带宽占用**：Pallas 的后缀 KV 传输分布在整个准备窗口内，峰值流量远低于切换后瞬时全量拷贝；历史前缀不产生数据传输（只传 token ID 而非 KV），进一步降低带宽需求。

### 3. 主要结果与技术贡献

- **SIT 显著降低**：相比于 Full-Copy、Recomputation、ctHO 等基线，Pallas 在典型场景下将服务中断时间从秒级降至 100 ms 级以下，甚至接近零（仅剩无线切换控制面开销）。
- **ITL 保持在 SLO 内**：Pallas 避免了 Detour 式的永久性多跳转发，切换后立即在本地下游解码，P90/P99 ITL 恢复至正常水平（数十 ms 量级），满足 100 ms 延迟目标。
- **资源/带宽效率高**：相比全量 KV 拷贝（需在高带宽假设下传输数 GiB 数据），Pallas 仅需传输切换准备窗口内新生成的后缀块（通常几十到几百 MiB），并利用目标端闲置 GPU 计算资源完成 prefill，避免占用昂贵的前传/中传带宽。
- **设计正交性强**：Pallas 是模型无关、硬件无关的通用机制，可与现有的 PagedAttention/VLLM 缓存管理、3GPP 切换信令及移动性预测算法直接集成，不改变推理引擎的内部算子。
- **首个将移动性预测与 LLM 推理状态迁移结合的工作**：把“切换”这一无线事件重新定义为“状态准备的截止期限”，为后续智能 RAN 上的 LLM 服务研究提供了新范式。

### 4. 方法论强项与可复现性

- **抽象层次恰当**：将 KV 缓存细粒度分块与移动性预测相结合，问题定义清晰，延迟模型具有可解释性；
- **模块化实现**：系统可按“移动预测器、KV 块传输器、前缀重建器、拼接控制器”四模块独立复现，各模块接口明确；
- **仿真条件明确**：基于开源网络仿真器（如 ns-3）与 LLM 推理框架（vLLM）耦合，用户规模、切换间隔、带宽参数均透明列出，便于对照复现；
- **评估全面**：同时报告了 SIT、ITL（分位数）、带宽占用、切换成功率（预测假阳性影响）等指标，覆盖了“如果预测失败会怎样”的鲁棒性维度，避免了过度宣称。

### 5. 局限性

- **依赖移动性预测精度**：若预测目标小区错误，则准备资源被浪费，且切换后依然需要走传统恢复路径；极端快速切换（准备窗口 < 最小重建时间）下无法完全消除 SIT；
- **前缀重算与 KV 拼接的语义一致性**：prefill 重建的 KV 与源端解码生成 KV 在浮点实现上可能存在极细微数值差异（如不同注意力实现），长期自回归下可能产生微小漂移，虽然论文声称不影响质量，但缺乏大规模长对话实验验证；
- **目标端资源预留与成本**：目标 gNB 需在准备期间预留 GPU 显存与算力执行 prefill；若多个 UE 同时切换，目标端可能成为资源瓶颈，论文未深入分析多 UE 并发场景下的调度竞争；
- **未覆盖多跳切换与连续切换**：论文主要聚焦单次切换；当 UE 快速连续穿越多个小区，Pallas 需要在多个目标间同时准备，状态复制因子（replication factor）可能显著上升，造成系统整体资源膨胀；
- **对无线链路带宽的乐观假设**：增量流式传输需要源-目标 gNB 之间有一定预留带宽，若 xHaul 链路本身就拥塞，后续传输可能抢占数据面资源，影响后台传输的稳定性；
- **不考虑 UE 端缓存**：若 UE 本身保有一部分历史 KV（如端边协同推理），Pallas 的前缀重建/校验逻辑需要额外扩展，当前设计未覆盖。

### 6. 结论与启示

Pallas 的核心价值在于提出了一种**“以准备代替恢复”**的切换范式：把通常发生在切换后的恢复延迟，提前到切换前的预测窗口内消化掉，使移动环境下的 LLM 推理服务能够像不移动一样连续运行。其核心洞察是：LLM 推理状态（KV 缓存）具有“历史不可变 + 增量稳定”的结构，这一结构恰好与移动性预测窗口相匹配——历史上稳定部分可以在目标端并行重建，增量部分只需轻量传输。它为 AI-RAN 时代“通信-计算联合编排”提供了一个具体且可落地的锚点。未来的工作方向包括：多层移动性预测与置信度感知的资源预留、多 UE 并发切换调度、以及将状态准备与无线资源调度（如波束切换、TDD 帧配置）进一步联合优化。

**一句话总结**：Pallas 通过移动性预测触发“前缀重建 + 后缀流式”的主动并行 KV 状态准备，将 LLM 推理切换的服务中断时间从秒级压缩至毫秒级，实现了真正无缝的移动推理服务迁移。
