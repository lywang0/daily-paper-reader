## 摘要
大语言模型（LLM）日益依赖稀疏性来降低推理成本，但以往大多数工作针对单一稀疏源——要么是权重稀疏，要么是激活稀疏——并针对批量多用户推理进行优化。双稀疏性结合了非结构化权重剪枝与运行时激活稀疏性，在单用户解码中提供了模型大小、准确性和延迟之间颇具吸引力的权衡，但其形式化为稀疏矩阵-稀疏向量（spMspV）工作负载，现有GPU内核处理不佳。我们提出了Celty，一种协同设计的稀疏格式、GPU内核和SIMT微架构，用于LLM推理中的高效spMspV。在内核层面，Celty引入了一种游程长度压缩的CSC（RLC-CSC）格式，能够向量化加载压缩权重列，并利用两种稀疏源跳过不必要的内存访问，使用共享内存进行分散的部分积累。在微架构层面，Celty稀疏SIMT核集成了流水线化RLC解码器，消除软件级索引重建，并重新利用局部寄存器文件进行无冲突累加——直接对相同的RLC-CSC格式操作，无需数据布局更改。Celty GPU内核相比cuBLAS实现了最高2.8倍加速，相比Flash-LLM实现了2.4倍加速。借助稀疏SIMT核，在70%双稀疏度下，加速比最高可达cuBLAS的5.3倍。

## Abstract
Large Language Models (LLMs) increasingly rely on sparsity to reduce inference cost, but most prior work targets a single sparsity source-either weight or activation-and optimizes for batched multi-user inference. Dual-sparsity, which combines unstructured weight pruning with runtime activation sparsity, offers a compelling tradeoff among model size, accuracy, and latency for single-user decoding, but formulates as a Sparse Matrix-Sparse Vector (spMspV) workload that existing GPU kernels handle poorly. We propose Celty, a co-designed sparse format, GPU kernel, and SIMT microarchitecture for efficient spMspV in LLM inference. At the kernel level, Celty introduces a Run-Length Compressed CSC (RLC-CSC) format that enables vectorized loading of compressed weight columns and exploits both sparsity sources to skip unnecessary memory accesses, with shared memory used for scattered partial-product accumulation. At the microarchitecture level, the Celty Sparse SIMT Core integrates a pipelined RLC decoder to eliminate software-level index reconstruction and repurposes local register files for conflict-free accumulation-operating directly on the same RLC-CSC format without data layout changes. The Celty GPU kernel achieves up to 2.8x speedup over cuBLAS and 2.4x over Flash-LLM. With the Sparse SIMT Core, speedups reach up to 5.3x over cuBLAS at 70% dual-sparsity.

## 1. 核心问题与研究动机

- **背景**：大语言模型（LLM）的端侧部署面临两大瓶颈——模型权重日益增大导致内存压力，以及自回归解码受限于内存带宽（尤其单用户场景）。稀疏化是应对这两大瓶颈的自然手段，能同时减小模型体积和计算量。
- **单稀疏的缺陷**：以往工作大多只利用单一稀疏源——
  - **非结构化权重剪枝**（SparseGPT、Wanda）精度好、压缩率高，但GPU上加速有限（Flash-LLM在70%稀疏度下仅比cuBLAS快1.3×），且针对批量多用户推理（spMM）。
  - **结构化剪枝**（ShortGPT、BlockPruner）易加速但精度退化严重；2:4半结构化模式精度也不佳。
  - **激活稀疏性**可实现运行时列跳过加速解码，但模型无法压缩（全量权重须驻留内存）。
- **双稀疏的提出**：DuoGPT将非结构化权重剪枝与运行时激活稀疏结合，既压缩模型又加速推理，在单用户解码中形成理想权衡。但其计算模式为**稀疏矩阵–稀疏向量乘法（spMspV）**，现有GPU内核（多为图计算设计、面向近99%极端稀疏）无法高效处理。
- **核心研究问题**：如何为LLM推理中**中等稀疏度（30%–70%）**的spMspV负载设计高效的软硬件协同方案？

## 2. 方法论

### 2.1 总体设计理念
三层协同设计：稀疏格式（RLC-CSC）→ GPU内核（Celty Kernel）→ SIMT微架构（Celty Sparse SIMT Core），全程统一操作同一RLC-CSC格式，无需任何数据布局转换。

### 2.2 内核级设计（Celty spMspV GPU Kernel）

- **避免Warp发散**：同一warp内32个线程共享同一个输入激活值b，warp按需跳过零值输入列（if b≠0才加载对应权重列），从根本上消除因激活稀疏模式导致的控制流分歧。
- **2D Tile + Split-K调度**：每个warp分配256行×64列的2D tile，M维跨warp切分，K维内循环迭代；内循环大小64为最优平衡点（大于64并行度不足，小于64原子合并开销过大）。
- **RLC-CSC稀疏格式**：
  - 每个非零权重的行索引用n-bit游程长度编码（RLC），编码该非零值之前零的个数，间隙超过2ⁿ-1时插入零值填充项。
  - 采用4-bit RLC，50%稀疏度下压缩效率约63%，与bitmap部署效率（~64%）相当，但**严格保持索引与值的一一映射**，从而支持固定宽度的128位向量化加载（每线程一次加载8个FP16权重+8个索引）。
- **算法1：warp内行索引重建**通过并行前缀和（结合shfl_up_sync）将RLC编码还原为绝对行地址，用于scatter累加。
- **共享内存散射累加**：部分积先在块内SMEM缓冲中累加，全部列处理完后一次性写回全局内存，比直接全局原子累加平均快14.4×。

### 2.3 微架构级设计（Celty Sparse SIMT Core）

针对内核profiling暴露的两个无法在软件层解决的瓶颈，提出硬件增强：

- **寄存器文件无冲突累加**：将每个SIMT核心（SM子分区）内空闲的本地寄存器文件（如M=5120时每核心预留1280个寄存器）划分为部分积缓冲区，替代SMEM完成散射累加。寄存器访问延迟更低、带宽更高，彻底消除SMEM bank冲突（>81%迭代存在≥3周期stall）。寄存器分配比例可调（0%–100%），越界时回退到SMEM保证正确性。
- **3级流水线硬件RLC解码器**：
  - 硬件直接实现前缀和树，每周期吞入8个RLC索引、输出8个重建后的绝对行索引，消除软件级索引重建（最高占内核耗时40%）。
  - 第7个输出（y₆）通过减法器并行回溯，省去额外前向进位级。
  - 8路输入来自8个不同线程lane，离线压缩时交错排列，利用scatter累加的顺序无关性保证正确性。
  - 面积开销小于0.01%（Hopper上0.009%），可同时支持稠密和稀疏两种模式。

## 7. 方法亮点

- **问题定位精准**：首次系统指出双稀疏LLM推理=spMspV、现有内核不适配的核心矛盾，填补了中等稀疏度（非99%图计算）场景的空白。
- **软硬件全栈一致格式**：RLC-CSC贯穿存储→加载→解码→计算全链路，无格式转换开销，充分挖掘"格式即数据流"的设计思想。
- **优雅的warp发散规避**：利用warp内线程共享输入值b的特性，将激活稀疏转化为warp级粗粒度跳过，化劣势为优势。
- **硬件增强极简**：仅增加一个小型RLC解码器+复用现有寄存器文件，面积开销0.009%，远低于Tensor Core改造方案（DASP等），精准匹配N=1内存受限场景。
- **工程细节扎实**：ROMA对齐保证向量化加载合法性；Split-K平衡调优；寄存器/SMEM混合累加比例可调、兼顾性能与占用率；结果可直接复现（代码开源）。

## 8. 不足与局限性

- **评估硬件单一**：仅A5000单卡实测，未在A100/H100/消费级GPU等更广泛平台上验证，结论的架构泛化性存疑；资源（功耗、时长、吞吐）报告不完整。
- **稀疏SIMT核为仿真估计**：基于修改内核模拟硬件效果，无法完全捕捉真实微架构的延迟、拥塞、调度等非理想效应；寄存器文件共享的硬件实现细节（跨

寄存器分配的硬件仲裁机制、跨warp共享时的冲突处理、关键路径时序影响等）语焉不详；RLC解码器仅报告了面积开销，未给出功耗、时序裕量、时钟频率影响等关键物理指标，其与前端取指/解码流水线的耦合方式也未展开说明，硬件可信度打折扣。
- **RLC参数未充分优化**：固定采用4-bit RLC，虽然论文通过实验说明50%稀疏度下压缩效率与bitmap相当，但未给出对RLC位宽（如3-bit、5-bit）的完整扫描；在极端稀疏度（>80%）下长游程频繁出现时，4-bit编码需要插入大量填充项，压缩效率会劣化，而这一边界场景恰是图计算类负载的常态，论文未讨论。
- **稀疏度-延迟-精度三方联合分析不足**：精度报告与延迟报告分离呈现（表2与图8数据点不完全对应），未能给出同一稀疏配置下"加速比-困惑度"的帕累托前沿曲线；且精度实验统一为50%稀疏度，未考察30%–70%区间内精度随稀疏度的连续退化曲线，读者难以据此直接选型。
- **端到端评测范围偏窄**：仅报告LLaMA-2-13B在ShareGPT上的单token解码延迟；未涉及更大的13B以上模型、多轮对话场景、前缀缓存命中场景、批大小>1场景（双稀疏在批处理下的优势会减弱，这一边界未被量化）。
- **上游稀疏化方法的耦合依赖**：双稀疏模式依赖于DuoGPT等激活稀疏化方法的预测准确性，若某层激活稀疏度实际低于预期（如输入分布偏移），则性能回退到近稠密水平，论文缺乏对该鲁棒性问题的敏感性分析。
- **与图计算spMspV内核的对比缺失**：尽管论文声称target是中等稀疏度，但与Gunrock、GraphBLAS等成熟图计算稀疏内核的直接对比缺失，仅对比了Macko一个RLC-CSR方案；由于Macko面向的是近99%稀疏度，其劣势在一定程度上是设计目标不同所致，对比说服力有限。

## 9. 适用场景与部署建议

- **最佳适用条件**：单用户（batch=1）自回归解码、权重非结构化剪枝率与激活稀疏率均处于30%–70%、权重驻留内存带宽受限的端侧/边缘侧场景。该条件下Celty的加速比随稀疏度单调上升，峰值可达5.27×。
- **不适用或收益有限的场景**：
  - 多用户高并发批处理：此时spMM的权重复用率远高于spMspV，传统Tensor Core路径（如Flash-LLM）仍是更优选择；
  - 极端稀疏（>90%）：RLC填充开销增大、warp级跳过命中率下降，图计算类定制内核可能更合适；
  - 推理服务端高吞吐场景：延迟优化诉求弱于吞吐，双稀疏的精度代价占比不值得。
- **工程落地建议**：硬件增强部分（RLC解码器）面积代价极低，可与现有稀疏Tensor Core方案共存于同一芯片，作为N=1低延迟模式的补充路径；软件内核可直接集成到llama.cpp/vLLM的稀疏后端，无需改动上层API；实际部署时应按层选择稀疏策略——对激活稀疏度稳定的层启用双稀疏，对激活稠密的层回退到稠密内核，以规避鲁棒性风险。

## 10. 未来研究方向

- **跨架构真机验证**：在Hopper（H100）及消费级Ada/Lovelace GPU上实现RLC解码器原型或FPGA验证，消除仿真误差，验证架构泛化性。
- **自适应稀疏格式**：根据运行时统计的激活稀疏模式，动态切换RLC位宽（如4-bit↔8-bit）或退化为稠密格式，避免填充项开销。
- **与推测解码/投机采样的协同**：双稀疏的激活稀疏性与推测解码的token预测天然互补，可将两套机制在解码流水线中叠加。
- **联合稀疏度规划**：以端到端延迟-精度帕累托为目标，自动化地为每层分配最优权重剪枝率与激活稀疏率（目前DuoGPT的稀疏度分配是启发式的）。
- **硬件-稀疏协同的NAS**：将RLC解码器面积、寄存器累加缓冲比例等硬件参数纳入神经网络架构搜索空间，实现面向特定芯片的联合最优。

## 11. 综合评价

Celty是一篇**问题定义清晰、软件-硬件协同设计完整、工程实现扎实**的高质量系统论文。其核心贡献在于：首次将"双稀疏LLM推理"精确建模为中等稀疏度spMspV问题，并据此设计了一套从稀疏格式到GPU内核再到微架构增强的全栈解决方案。相较于动辄数平方毫米的稀疏Tensor Core改造方案，Celty以不足0.01%的面积开销换取2–4倍的解码加速，投入产出比极为突出，具有很高的工程落地潜力。

不过，其评估充分性相较系统顶会标准仍有一定差距：单一GPU架构实测、硬件部分依赖仿真、端到端仅覆盖单模型单场景，这三项短板限制了结论的推广强度。若后续能在多架构真机（或FPGA）上验证，并补充稀疏度-延迟-精度的联合帕累托分析，该工作有望成为端侧稀疏LLM推理的标杆性方案。

总体而言，Celty在**“用极小硬件代价解决真实软件瓶颈”**这一系统研究命题上提供了优秀范例，其对warp发散规避、寄存器复用、RLC格式贯穿全栈的设计思想，对后续稀疏推理内核与专用硬件设计均有重要借鉴意义。
