## 摘要
混合专家（MoE）模型已成为大规模AI服务的主流架构，但在地理分布的异构边缘服务器上部署它们仍然具有挑战性。当一个Token的Top-k激活专家分布在多台服务器上时，最优路由取决于跨服务器链路带宽、异构GPU计算能力、GPU-CPU专家加载延迟、瞬时排队积压以及副本级量化质量损失。现有的分布式推理和MoE服务方法分别处理这些因素，并未提供统一的在线多服务器协同路由框架。本文提出HetRoute，一种面向分布式边缘MoE推理的异构成本感知协同路由框架。HetRoute引入了一个统一的按分配成本模型，明确捕获四个成本组成部分：跨服务器传输、GPU-CPU卸载、带排队的GPU计算以及量化引起的质量惩罚。在该模型的指导下，离线阶段通过路由成本耦合部署算法确定专家服务器放置、GPU-CPU驻留和副本精度，而在线阶段通过精确枚举或束搜索最小化瓶颈层成本，将Top-k激活专家集作为一个整体进行路由。理论分析建立了回退可行性、参与服务器数量的界限、小候选域的每层最优性以及在线计算复杂度。在异构10服务器边缘测试平台上对三个MoE模型的轨迹驱动评估表明，与代表性基线相比，HetRoute将平均推理延迟降低高达59.0%，P99延迟降低高达58.0%，跨服务器流量减少高达72.1%，吞吐量提升2.13倍，同时将质量下降保持在配置预算内。

## Abstract
Mixture-of-Experts (MoE) models have become a dominant architecture for large-scale AI services, yet deploying them over geo-distributed heterogeneous edge servers remains challenging. When the Top-k activated experts of a token are spread across multiple servers, the optimal routing depends jointly on cross-server link bandwidth, heterogeneous GPU computing capability, GPU-CPU expert loading delay, instantaneous queueing backlog, and replica-level quantization quality loss. Existing distributed inference and MoE serving methods address these factors separately and do not provide a unified framework for online multi-server collaborative routing. In this paper, we propose HetRoute, a heterogeneous-cost-aware collaborative routing framework for distributed edge MoE inference. HetRoute introduces a unified per-assignment cost model that explicitly captures four cost components: cross-server transmission, GPU-CPU offloading, GPU computation with queueing, and quantization-induced quality penalty. Guided by this model, the offline stage determines expert server placement, GPU-CPU residency, and replica precision through a routing-cost-coupled deployment algorithm, while the online stage routes the Top-k activated expert set as a whole by minimizing the bottleneck layer cost via exact enumeration or beam search. Theoretical analysis establishes fallback feasibility, a bound on the number of participating servers, per-layer optimality for small candidate domains, and online computational complexity. Trace-driven evaluation on three MoE models over a heterogeneous 10-server edge testbed shows that HetRoute reduces average inference latency by up to 59.0% and P99 latency by up to 58.0%, cuts cross-server traffic by up to 72.1%, and achieves 2.13x throughput improvement compared with representative baselines, while keeping quality degradation within the configured budget.

- **核心问题**：当 MoE 模型以分布式协作方式部署在多台异构边缘服务器上时，一个 Token 的 Top-k 激活专家可能分布在多个服务器上，**最优路由决策取决于五类因素的联合影响**：
  1. 跨服务器链路带宽的异构性；
  2. GPU 计算能力的异构性；
  3. GPU-CPU 专家加载延迟（专家是否常驻 GPU）；
  4. 瞬时排队积压（各服务器负载动态）；
  5. 副本级量化精度差异（不同副本精度不同引入质量损失）。
- **现有方法不足**：
  - 密集模型协作推理工作（如 EdgeShard、Petals）针对块级/层级串行切分，不适用于稀疏专家级并行路由；
  - MoE 服务系统（如 MoE-Infinity、SiDA-MoE、Prism）侧重单机缓存/预取或静态放置优化，未建模普通互联网链路的动态变化，也未考虑多专家之间的扇入/扇出耦合；
  - 模型划分与内存感知卸载（如 FlexGen、Neurosurgeon）大多假设密集执行路径或单一节点内存层次结构。
  - 因此，**缺少一个统一框架对多服务器在线协同路由进行端到端建模**——特别是存在一个关键场景：**远程 GPU 常驻热专家可能比本地 CPU 常驻冷专家更快**，这是传统"本地优先"假设无法处理的。

## 2. 论文提出的方法论：核心思想、关键技术细节与算法流程

- **总体核心思想**：将分布式边缘 MoE 推理形式化为"异构成本感知的 Top-k 协同路由问题"，通过离线部署与在线路由的两阶段协作优化（offline-online co-design），实现延迟与质量之间的灵活权衡。

- **统一成本模型（公式 9）**：每个"目标专家 E → 副本副本 E' → 服务器 s_n"的赋值包含四部分代价：
  - **跨服务器传输**：若目标服务器与当前驻留服务器不同，传输 hidden state 所需时间；
  - **GPU-CPU 卸载**：若副本为 CPU 驻留，需加载进 GPU 的延迟；
  - **GPU 计算与排队**：计算负载 w 加上当前 GPU 积压 Q_n(t) 除以计算能力 F_n，反映瞬时排队延迟；
  - **质量惩罚**：量化损失 q 与替代执行损失 Q_sub 的加权项（λ）。
  - 该模型打破了"本地执行默认最优"的假设，使远程 GPU 热专家与本地 CPU 冷专家的真实代价可统一比较。

- **层延迟为瓶颈形式（公式 10）**：k 个专家并行执行，层延迟 = 最大分支延迟（fan-out 传输 + 并行计算 + fan-in 聚合），而非求和。

- **离线阶段（Algorithm 1：路由-成本耦合的专家部署）**——分三阶段：
  1. **路由概率加权 GPU 驻留**：利用校准流量模拟在线路由器，得到每个副本的实际被选概率 p_route，GPU 驻留收益 = 激活频率 × 选择概率 × 卸载延迟节省，按此贪心分配 GPU 内存（而非按原始激活频率）；
  2. **统一成本驱动的冗余复制**：计算添加新副本的边际收益 b = 期望在线统一成本降低 − 内存代价 μv，只添加正收益副本，精度选择同时考虑内存占用与质量损失；
  3. **驻留全局重优化**：新增副本后重新全局分配 GPU 驻留，并引入"边际收益递减防护"防止同一专家的第二个 GPU 副本挤掉其他更有价值的专家。

- **在线阶段（Algorithm 2：通信感知的在线协同 Top-k 路由）**：
  - **精确优先生成候选集（exact-first）**：先构建目标专家的精确副本候选集，若存在满足质量守卫与稳定性守卫的候选则不用替代专家；仅当精确候选全部不可用时才激活相似性替代候选集；
  - **两道在线守卫**：硬性质量守卫（累计质量损失不得超过每 Token 预算）和常规稳定性守卫（单窗口内不超服务器计算容量）；
  - **集合级选择**：路由决策以集合为单位（而非逐专家贪心），目标是最小化瓶颈层成本 D_{i,l}。小候选域（≤ R）用精确枚举，大域用束搜索（beam search）+ 1-exchange 局部搜索；
  - **支配快速路径**：当所有专家在本服务器 GPU 驻留、本地队列轻、本地代价严格优于任何远程分支时才本地执行——是有条件的最优选择，不是无条件的本地优先；
  - **应急回退**：所有正常候选均不可用时，路由到全精度精确副本（由约束 c.4 保证），质量守卫绝不放松，稳定性守卫可放宽为排队延迟。

- **理论性质**（共 5 条）：
  - 回退可行性：算法总能返回完整且质量可行的路由；
  - 参与服务器数上界：|P_{i,l}| ≤ k；
  - 小候选域下每层全局最优性；
  - 大域下束搜索 + 交换精炼达到 1-exchange 局部最优；
  - 在线复杂度为 O(LkRB)（束搜索）或 O(LR^k)（精确枚举），与服务器总数 N 无关，仅依赖平均副本数 R。

## 6. 论文的主要结论与发现

- **核心性能提升**（在 Mixtral-8x7B 上）：
  - 平均延迟 156 ms，较 EdgeShard 降低 59.0%、较 Petals 降低 49.5%、较 MoE-Infinity 降低 38.6%、较 Prism 降低 28.1%；
  - P99 延迟 286 ms，较 EdgeShard 降低 58.0%、较 Prism 降低 33.2%；
  - 跨服务器流量 1.24 GB/千 token，较 EdgeShard 降低 72.1%；
  - 吞吐量 1490 token/s，为 EdgeShard 的 2.13 倍、Prism 的 1.35 倍；
  - CPU 卸载比率降至 14%（MoE-Infinity 为 42%、Prism 为 31%）。

- **路由行为特征**：46% 为本地 GPU 精确执行、24% 为远程 GPU 精确执行，替代执行占 14%，应急回退仅 2%——说明延迟降低主要来自"将执行组合转向 GPU 驻留的精确副本"，替代/回退不再是降延迟的主要来源。

- **质量保持**：相比中央全精度模型，WikiText-103 困惑度 5.32→5.39，SQuAD F1 86.7→86.1，GSM8K 准确率 56.8%→56.0%，所有模型质量保留率 ≥98.6%。

- **质量预算的平滑权衡**：预算从 0.5% 放松至 3.0% 时，延迟从 188 ms 降至 142 ms，实际退化始终低于配置预算。

- **集合级路由的必要性**：Top-k 越大，集合级路由相对逐专家贪心的优势越明显（k=4 时延迟降低 29.8%）；参与服务器数量分布显示 54% 用 1 台、46% 用 2 台，表明路由策略是"成本优先"而非"本地优先或远程优先"。

- **负载鲁棒性**：80 req/s 时 HetRoute 的 P99 为 472 ms，SLA（300 ms）满足率 73%，明显优于 Prism（51%）、MoE-Infinity（43%）、EdgeShard（21%）。

- **实验设计系统**：多种对比基线、跨模型规模验证、消融分解、预算权衡、负载鲁棒性测试等多个维度相互印证，特别是执行类型分解（图 3b）有助于理解方法为何有效。

## 8. 不足与局限

- **测试平台规模有限**：仅 10 台服务器、单一网络拓扑，未验证更大规模（如 30–50 台）或更复杂拓扑（多层边缘-云）下的可扩展性。
- **算力细节缺失**：未报告具体 GPU 型号、数量、推理框架开销、离线校准时间等，影响复现性和能耗评估。
- **未报告统计波动性**：实验未提供多次运行的标准差或置信区间，难以判断性能差异的统计显著性；流量、延迟等在高动态网络下存在天然噪声。
- **质量损失模型为加性近似**：累积质量退化采用一阶加性代理（公式 8），论文虽验证了与任务指标的相关性，但对更长序列/更复杂任务（多轮对话、长文档生成）的误差累积行为未讨论。
- **分解优化的最优性差距未定量**：P0 为非因果关系的最优基准，论文采用的离线-在线两阶段分解是启发式近似，虽然理论上识别了这一点，但未在更大规模的系统上定量评估与全局最优的差距（Property 4 提到的离线 oracle 对比未在正文呈现具体结果）。
- **应用限制**：未考虑模型更新/专家激活分布漂移（论文在结论中承认这是未来工作）；未讨论多租户、安全隔离、故障恢复等生产环境的工程约束；单点故障风险未分析。
- **替代执行机制的边界**：相似性驱动的替代执行依赖预定义的可行替代集 V(E)，其定义方式与鲁棒性（替代专家是否真的能在不同输入分布下保持相近输出）未深入讨论。
