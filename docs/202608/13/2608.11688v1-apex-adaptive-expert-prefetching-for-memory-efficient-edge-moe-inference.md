## 摘要
混合专家（MoE）模型因其在仅激活每个token的一小部分参数的同时提供高模型容量、提升计算效率的特性，对于边缘部署颇具吸引力。然而，边缘端的MoE推理从根本上受限于内存。专家参数规模庞大，且由于容量、成本和功耗限制，往往驻留在片外内存中，使得专家加载成为关键路径。我们提出APEX：自适应专家预取，一种预测性资源管理框架，将专家加载与有效计算重叠。APEX引入了一个轻量级预取路由器，在注意力块之前预测候选专家，利用学习到的置信度模型动态获取额外的专家。这种自适应策略实现了超过99%的重叠准确率，显著优于固定的top-k预取技术。APEX支持两种执行模式：一种保持正确性的模式，保证精确的路由语义；另一种无停顿模式，通过操作可用专家来消除残余停顿，对应用精度影响可忽略不计。在多个MoE模型上，与最先进的基线相比，保持正确性的模式将每token延迟降低了高达26%，并将能量延迟积（EDP）改善了高达41%，而无停顿模式则提供了额外的效率提升，且对应用精度的影响可忽略不计。这些结果确立了自适应、置信度驱动的专家预取作为边缘系统上高效MoE推理的有效方法。

## Abstract
Mixture-of-Experts (MoE) models are attractive for edge deployment because they provide high model capacity while activating only a small subset of parameters per token, improving compute efficiency. However, MoE inference at the edge is fundamentally limited by memory. Expert parameters are large and often reside in off-chip memory due to capacity, cost, and power constraints, putting expert loading to the critical path. We present APEX: Adaptive Expert Prefetching, a predictive resource management framework that overlaps expert loading with useful computation. APEX introduces a lightweight prefetch router that predicts candidate experts before the attention block to dynamically fetch additional experts using a learned confidence model. This adaptive strategy achieves over 99% overlap accuracy, significantly outperforming fixed top-k prefetching techniques. APEX supports two execution modes: a correctness-preserving mode that guarantees exact routing semantics, and a stall-free mode that eliminates residual stalls by operating on available experts with negligible impact on application accuracy. Across multiple MoE models, the correctness-preserving mode reduces per-token latency by up to 26% and improves energy-delay product (EDP) by up to 41% over state-of-the-art baselines, while the stall-free mode provides additional efficiency gains with negligible impact on application accuracy. These results establish adaptive, confidence-driven expert prefetching as an effective approach for efficient MoE inference on edge systems.

# APEX: 面向内存高效边缘 MoE 推理的自适应专家预取——论文详解

## 1. 核心问题与研究动机

- **背景**：MoE（Mixture-of-Experts）模型通过每次仅激活少量专家，将模型容量与单 token 计算量解耦，非常适合边缘部署。但边缘设备的片上内存容量有限，专家参数往往存储在片外内存（如 LPDDR5X）中，通过 PCIe 等慢速接口加载。
- **核心问题**：专家加载（expert loading）成为 token 生成的关键路径，产生"内存墙"瓶颈。论文测量显示：在代表性边缘加速器上运行 Granite-3.1-3B-A800M 模型时，专家加载占延迟的 43%、能量的 29%，且加载期间计算单元处于空闲但持续耗电。
- **现有方法的不足**：已有预取方案（如 ProMoE、Fate、HOBBIT 等）均采用固定 top-k 预取策略，无法适应两层异质性：
  - 高平均重叠率不保证无停顿（缺少任一被路由专家就会产生修正停顿）；
  - 不同 token 和层的路由不确定性差异大，固定预算要么浪费通信能量、要么覆盖不足；
  - 运行时决策必须足够轻量，才能利用注意力计算时间窗口完成预取。
- **关键洞察**：大多数路由预测错误可通过少量额外专家修正。论文发现，只需将预取集合从 top-k 扩展到 top-(k+δ)，δ 较小（如 2 或 4）时即可显著提升覆盖率，接近 oracle 水平。因此核心问题是：如何为每个 token 自适应地选择最小的 δ。

## 2. 方法论

### 核心思想

在注意力块前增加一个轻量级 **prefetch router**，预测当前层的专家排序；再通过一个学习到的置信度模型（logistic CDF）为每个 token 动态选择额外预取预算 δ^(x)，预取 top-(k+δ^(x)) 专家，使专家传输与注意力计算重叠。

### 技术细节

- **Prefetch router**：与原始 MoE router 结构相同（线性层 + softmax），放置在每个 MoE 层的注意力块之前，从层隐藏表示中预测专家概率分布。
- **训练方式（蒸馏）**：使用 KL 散度损失，让 prefetch router 的专家分布逼近原始 router 的分布。基础 MoE 模型保持冻结，只训练辅助组件。
- **CDF 置信度模型**：定义覆盖概率 pδ(x) = Pr(δ ≥ δ*, x)，其中 δ* 为 oracle 最小预算（即 Prefetched 集合完全包含原始 router 选中专家所需的最小额外数量）。用序数 logistic 公式建模：
  - pδ(x) = σ(θδ − wᵀx)，其中 θ₀ ≤ θ₁ ≤ ... ≤ θ_{N-k} 保证单调性（CDF 性质）。
  - 训练目标为累计二元交叉熵损失。在运行时，选择满足 pδ(x) ≥ τ 的最小 δ 作为预取预算。
- **两个执行模式**：
  1. **Correctness-preserving mode**：严格遵循原始 router 语义。若预取集合缺失个别被路由专家，则先计算已加载专家，同时异步补取缺失专家（利用专家间独立性），最后用原始路由权重聚合，保证精确语义。
  2. **Stall-free mode**：若所有被路由专家都已预取，则完全按原始语义执行；若有缺失，则从预取集合中按原始 router 权重选取最高分的替代专家，消除修正停顿，但引入可忽略的近似误差。

## 3. 实验设计

### 数据集与模型

- **模型**：4 个不同规模的 MoE LLM：
  - Granite-1B（24 层，N=32，k=8）
  - Granite-3B（32 层，N=40，k=8）
  - Phi-7B（32 层，N=16，k=2）
  - DeepSeek-16B（27 层，N=64，k=6，另含 2 个共享专家）
- **训练数据**：WikiText（用于训练 prefetch router 和 CDF 模型，无任务特定微调）。
- **评估基准**：WikiText 困惑度，以及 ARC、MMLU、WinoGrande、TruthfulQA 四个下游任务的平均分。

### 系统设定

- 目标架构：类边缘加速器（4 个 16×16×32 向量处理阵列，24 TFLOPS @ 750 MHz，8 MB SRAM），专家权重存于片外 LPDDR5X，经 PCIe 6.0×16 传输（256 GB/s），片上 HBM 带宽 819 GB/s。
- 模拟方法：CHIPSIM 计算-通信协同模拟框架 + RTL 综合（TSMC 28nm）+ Ramulator DRAM 模拟 + UCIe 片间互连模型。异步 DMA 传输受带宽和排队延迟约束，不假设完全隐藏。

### 对比基线

- No Prefetch（常规按需加载）
- ProMoE（最先进的预测式 top-k 预取）
- 静态过度预取 top-(k+x) 和 top-(k+y)，其中 x/y 因模型而异，使用与 APEX 相同的 prefetch router 排序，仅将自适应 δ 替换为固定值，以隔离自适应预算的贡献。

### 消融实验

- 置信度阈值 τ 的影响（0.60 / 0.90 / 0.97）；
- 与 Oracle δ* 的逐层对比；
- 每 token 预取预算分布；
- I/O 带宽敏感性（32–1024 GB/s）；
- 专家权重精度敏感性（4/8/16/32-bit）。

## 4. 资源与算力

- 训练硬件：NVIDIA RTX 3090（Granite 和 Phi 模型）、NVIDIA A100（DeepSeek-16B）。
- 训练配置：学习率 5×10⁻⁴，batch size 8，序列长度 1024，训练 1000 步。
- 训练时间：
  - Granite-1B：约 10 分钟；
  - Granite-3B：约 30 分钟；
  - Phi-7B 和 DeepSeek-16B：约 1 小时。
- 能耗/延迟评估：硬件综合与协仿真在 TSMC 28nm 工艺上完成，使用 Synopsys PrimeTime、Ramulator 2.0、CHIPSIM 等工具。论文未说明用于训练的具体 GPU 数量。

## 5. 实验数量与充分性

- **覆盖面较广**：4 个不同规模/拓扑的 MoE 模型 × 3 种上下文长度（512/1024/2048）× 多类指标（重叠率、延迟、能量、EDP、应用精度）。
- **消融实验充分**：包括 τ 阈值扫描、与 Oracle 对比、per-token 分布、带宽敏感性和精度敏感性，从多个角度验证方法有效性。
- **对比公平性**：静态过度预取基线使用与 APEX 相同的 prefetch router，仅改变预算选择策略，能较好隔离自适应机制的贡献。
- **实验较为客观**：使用周期级协同模拟，包含传输排队、带宽竞争、静态功耗等实际约束，避免理想化假设。

## 6. 主要结论与发现

- APEX 在四个模型上均实现超过 97% 的逐层重叠率，置信度阈值 τ=0.97 时超过 99%，接近 oracle；而 ProMoE 在多个层显著退化（约 79–87%）。
- **性能收益**：正确性保持模式相对 ProMoE 降低每 token 延迟最高 26%，EDP 改善最高 41%；无停顿模式额外带来 2–14% EDP 提升（Phi-7B 时收益最大）。
- **能量权衡**：APEX 的额外专家传输增加 I/O 能量（如 Granite-3B 从 48→56 mJ），但通过重叠隐藏加载延迟，将 idle/leakage 能量从 57→8 mJ，总能量净降 12%。静态过度预取（如 k+8）导致 I/O 能量升至 97 mJ，总能量反而上升，证明过度预取不免费。
- **自适应有效性**：APEX 选出的预算与 oracle δ* 紧密匹配，在简单层接近最低预算、在困难层略高以留安全余量，优于任何固定预算策略。
- **精度影响**：正确性保持模式与基线精度完全一致；无停顿模式在 k=8/6（含共享专家）的模型中影响可忽略（如 Granite-1B 平均分 43.3→42.8），但在低 top-k 模型（Phi-7B, k=2）上退化较明显（64.6→60.4 @τ=0.90），建议此类模型以正确性保持模式为默认。
- **带宽鲁棒性**：在 32–1024 GB/s 带宽范围内，APEX 均持续降低延迟（14–42%），低带宽下收益受限于注意力窗口容量但仍优于基线；高带宽下依然有效。
- **量化友好性**：APEX 与专家权重量化互补——量化减少数据量，APEX 减少暴露的传输时间。

## 7. 优点

- **创新性**：首次将预取预算视为 per-token 自适应决策问题，用序数 logistic CDF 建模，方法简洁且理论性质好（单调性即 CDF）。
- **非侵入性强**：不修改原始 MoE 模型，只添加轻量辅助组件（参数增加 <0.06%，性能开销 <0.05%），可即插即用于已有模型。
- **两种执行模式设计合理**：正确性保持模式适合精度敏感场景，无停顿模式允许在精确性与性能间权衡，部署灵活。
- **评估方法严谨**：使用 RTL 综合 + DRAM 模拟 + 通信建模的多层次协同仿真，能量分解清晰（表 V 明确展示 I/O 能量与 idle 能量的权衡）。
- **覆盖多模型规模**：从 1B 到 16B、不同 top-k 配置，结论具有较强的普适性。
- **充分的位置敏感性分析**：如带宽扫描结果显示方法对部署条件鲁棒，不是仅针对单一硬件点调优。

## 8. 不足与局限

- **缺乏硬件原型验证**：仅在仿真环境中验证，未在 FPGA/硅片原型上部署，系统性效应（如 IOMMU 开销、OS 调度干扰）只以固定成本建模，真实世界可能有额外开销。
- **训练分布单一**：prefetch router 和 CDF 模型仅在 WikiText 上训练，虽声称可泛化到下游任务，但未系统评估跨领域/跨语言泛化能力。
- **低 top-k 模型风险**：Phi-7B（k=2）在无停顿模式下精度下降较显著，意味着该方法对路由稀疏度敏感的模型不太适用，论文未提供针对该情况的缓解方案。
- **批量推理覆盖不足**：实验聚焦单用户延迟敏感场景，多请求并发下的预取竞争、缓存复用、调度复杂性问题未深入评估。
- **未量化实际量化损失**：精度敏感性实验只改变专家权重的传输/计算规模，没有结合真实量化模型的精度损耗，可能低估或高估实际部署效果。
- **假设专家可独立加载**：方法依赖 "专家粒度可独立寻址和调度" 的实现假设，某些推理引擎可能采用融合存储或分组加载，限制方法适用性。
- **高带宽场景收益递减**：在接近 NVLink-C2C 级别的高带宽下，预取优势缩小，说明该方法主要针对带宽受限的边缘场景。
