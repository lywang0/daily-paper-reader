## 摘要
大型语言模型日益部署在功率和面积预算紧张的边缘设备上。虽然混合精度GEMM降低了算术复杂度，但量化推理通常受限于反量化操作和非线性算子。基于查找表的方法通过预计算输出并用表查找替代重复算术来缓解这些成本，但现有设计面临显著的容量和查找延迟开销。本文提出PALUTE，一种基于查找表的存内计算加速器，构建在单片3D DRAM上，用于高效的边缘大语言模型推理。PALUTE能够在DRAM内执行查找表查询，利用M3D DRAM存储阵列瓦片的垂直组织实现高并行性和低面积开销。近内存查找表生成器支持针对GEMM和逐元素一元非线性算子的低延迟查找表生成，而系统级分层与调度策略最小化跨内存层的数据移动。通过周期精确仿真和RTL综合评估，在Qwen3-4B模型、W4A4配置下，PALUTE在0.16W功耗下达到1,264 TPS的端到端吞吐量，相比CHIME能效提升12.8倍，相比FIGLUT能效提升1.6倍，相比PIMPAL面积效率提升2.0倍。

## Abstract
Large language models are increasingly deployed on edge devices with tight power and area budgets. While mixed-precision GEMM reduces arithmetic complexity, quantized inference is often dominated by dequantization and nonlinear operators. Lookup Table (LUT)-based method mitigates these costs by precomputing outputs and replacing repeated arithmetic with table lookups, but existing designs incur significant capacity and lookup-latency overheads. This paper presents PALUTE, a LUT-based Processing-In-Memory accelerator built on Monolithic 3D DRAM for efficient edge LLM inference. PALUTE enables in-DRAM LUT queries that exploit the vertical organization of M3D DRAM memory array tiles to achieve high parallelism with low area overhead. A near-memory LUT generator supports low-latency LUT generation for both GEMM and element-wise unary nonlinear operators, while a system-level tiering and scheduling strategy minimizes data movement across memory tiers. Evaluation using cycle-accurate simulation and RTL synthesis shows that PALUTE achieves 1,264 TPS end-to-end throughput at 0.16 W, improving energy efficiency by 12.8$\times$ over CHIME and 1.6$\times$ over FIGLUT, improving area efficiency by 2.0$\times$ over PIMPAL under W4A4 across Qwen3-4B models.

## 1. 核心问题与整体含义（研究动机与背景）

- **背景**：大型语言模型向边缘设备部署面临功率、面积和内存带宽的严格约束。量化推理（如W4A4）虽降低算术复杂度，但**反量化操作**与**非线性算子**（Softmax、GELU等）成为新的瓶颈，反量化可占运行时20%–90%。此外，**数据移动**是系统能耗的主要来源（平均占62.7%）。
- **核心问题**：现有查找表（LUT）方法虽能通过预计算避免重复算术和反量化，但在传统DRAM或ASIC中实现时，**LUT容量开销大、查询延迟高、并行度受限**，无法高效支持边缘LLM推理。
- **整体含义**：需要一种新型存内计算架构，利用垂直3D DRAM的高度并行性和低延迟特征，将LUT查询内置于存储阵列，并配合近存LUT生成与系统级调度，从根本减少数据移动和计算开销，实现能效与面积效率的突破。

## 2. 方法论：核心思想与关键技术细节

- **核心思想**：基于**单片3D DRAM（M3D DRAM）** 的**垂直位线（VBL）** 组织，将LUT存储在DRAM存储阵列瓦片（MAT）中，利用垂直方向大量MAT并行查询；近存LUT生成器在逻辑裸片上快速生成GEMM和一元非线性算子的LUT；系统级分层调度最小化跨层数据移动。
- **关键技术细节**：
    1. **In-DRAM LUT查询机制**：每个M3D DRAM MAT包含水平字线（WL）和垂直位线（BL）。LUT按行存储（每个WL对应一个索引）。查询时，匹配逻辑扫描所有行，激活匹配WL，通过垂直BL并行读出多组LUT结果（每笔128位突发可输出最多32个4位结果）。整个芯片最多支持**8,388,608**并发LUT查询。
    2. **半表（Half-table）逻辑**：利用符号对称性，只存储非负权值组合对应的LUT结果，负数通过符号翻转映射后查询，再将结果取反，将LUT容量减半。
    3. **LUT生成器**：位于逻辑裸片，每个DRAM bank配一个生成单元，包含GEMM核心和一元非线性核心。GEMM核心通过三周期流水线（先计算|w1|x1，再计算±|w2|x2，最后相加）枚举所有部分和，实现3周期生成一张完整LUT。
    4. **系统分层与调度**：M3D DRAM中不同层WL延迟不同。PALUTE将低频数据放在靠近逻辑裸片的下层，LUT放在中层，KV缓存放在上层，以减少WL遍历代价。调度流程：权重和初始令牌→逻辑裸片→LUT生成→写回DRAM→索引查询→bank级累加。

- **公式/算法**（文字说明）：
    - GEMM分段：将长点积 `X·W` 分割为长度为2的短向量段 `x_seg·w_seg`，`w_seg` 为4位量化，其组合数有限（2^(2*4)=256种），预计算所有可能值存入LUT。运行时用权值索引直接查询。
    - 一元非线性：对输入 `x` 的所有可能4位值（-8..7）预计算 `f(x)`，查询时以 `x` 为索引。

## 7. 优点

- **架构创新**：首创将LUT查询与M3D DRAM垂直MAT结合，实现超大规模并行（800万+并发查询），面积开销远低于TSV堆叠方案。
- **端到端优化**：覆盖LUT生成、存储、查询、累加，消除反量化与非线性算子瓶颈；系统级分层调度考虑M3D内部延迟非对称性。
- **高能效**：0.16W即可运行4B模型，适合电池供电设备。
- **评估全面**：包含多种模型、灵敏度分析、开销分解，对比了不同类别基线。

## 8. 不足与局限

- **仿真层面**：实验基于周期精确模拟器与RTL综合，未流片验证，实际M3D DRAM制造良率和热效应未考虑。
