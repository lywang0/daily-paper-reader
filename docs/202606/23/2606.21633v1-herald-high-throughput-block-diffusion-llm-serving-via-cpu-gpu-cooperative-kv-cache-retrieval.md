## 摘要
扩散LLM（dLLM）通过每次前向传播生成多个词元，提高了GPU利用率，但其KV缓存仍随上下文线性增长，限制了长上下文下的吞吐量。将KV缓存卸载到主机DRAM可缓解这一内存压力，但有限的PCIe带宽使得只能召回稀疏的KV条目子集。在块dLLM中，相关KV条目在一个块内的去噪步骤中保持一致，因此可以通过一次识别top-k条目并在所有去噪步骤中复用来实现高精度选择。这一特性对于卸载具有吸引力，因为它将选择开销分摊到整个块上，但这需要对完整KV缓存进行精确注意力计算，而在卸载情况下代价过高。我们提出了HERALD，一个针对块dLLM的KV卸载系统，通过两个机会解决了这一问题：将所需的选择计算量减少一个块大小的因子，并使选择能够与去噪重叠。在三个块dLLM和五个长上下文任务中，HERALD在5-10%的KV预算下实现了近乎无损的精度，每块延迟降低至多1.59倍，吞吐量比纯GPU推理提升至多2.47倍，且加速比随上下文长度增加而增长。

## Abstract
Diffusion LLMs (dLLMs) improve GPU utilization over autoregressive decoding by generating multiple tokens per forward pass, but their KV cache still grows linearly with context, limiting throughput at long contexts. KV cache offloading to host DRAM alleviates this memory pressure, but the limited PCIe bandwidth necessitates recalling only a sparse subset of KV entries. In block dLLMs, the relevant KV entries remain consistent across denoising steps within a block, enabling high-accuracy selection by identifying the top-k entries once and reusing them throughout all denoising steps. This property appears attractive for offloading as it amortizes the selection overhead across the entire block, but it requires exact attention over the full KV cache, which is too expensive under offloading. We present HERALD, a KV offloading system for block dLLMs that resolves this through two opportunities that reduce the required selection compute by a factor of the block size and enable selection to be overlapped with denoising. Across three block dLLMs and five long context tasks, HERALD achieves near-lossless accuracy at 5-10% KV budget and up to 1.59x lower per block latency and 2.47x higher throughput over GPU-only inference, with speedups growing with context length.

# 论文详细中文总结

## 1. 核心问题与整体含义（研究动机和背景）

- **背景**：扩散LLM（dLLM），尤其是块扩散LLM（block dLLM），通过每次前向传播生成多个token（块大小为B），提升了GPU利用率。然而，其KV缓存仍随上下文长度线性增长，在长上下文场景下（如32K token）会消耗绝大部分GPU HBM，导致可支持的批处理大小受限，吞吐量下降。
- **问题**：将KV缓存卸载到主机DRAM可缓解GPU内存压力，但PCIe带宽远低于GPU内存带宽（约两个数量级），全量传输KV缓存代价过高（8K上下文时传输延迟已为模型前向的3.1倍，32K时达7.6倍）。因此需仅召回稀疏子集的KV条目。对于块dLLM，现有稀疏注意力方法（如MAGE）利用块内去噪步骤间注意力一致性，在第一步进行精确全KV注意力选择top-k，后续步骤复用，但这一步需要全量KV缓存，在多GPU卸载场景下代价极高。
- **挑战**：实现该策略面临两个障碍：
  - **硬件映射挑战**：全量KV缓存位于CPU DRAM，若在CPU上计算精确注意力，由于需要处理B个查询token，CPU缺乏矩阵乘法单元，延迟过高；若在GPU上计算，则需全量传输KV缓存经PCIe，PCIe带宽成为瓶颈。
  - **依赖挑战**：块N+1的选择需要块N的最终token作为前缀，但块N的去噪尚未完成，存在数据依赖，导致选择操作无法提前与去噪重叠。

## 2. 论文提出的方法论：核心思想、关键技术细节

### 2.1 核心思想
HERALD通过两个结构性的机会解决上述挑战，实现CPU-GPU协作的KV缓存检索：
- **机会1：单个中心[MASK]查询即可代表整个块**。由于选择时当前块所有位置均为[MASK] token，它们共享相同的词嵌入，仅RoPE位置编码不同。使用块中心位置的单一[MASK] token作为查询，可恢复84%（B=32）的top-k选中的条目，从而将CPU侧的注意力计算量减少B倍（实测22-24倍加速）。
- **机会2：Step-0 logits提供免费的语义代理**。在块N的step-0，模型对所有B位置产生logits，置信度调度器仅保留高置信度位置，丢弃其余logits。对这些丢弃的logits进行argmax解码，可得到块N的草稿块（draft block），其KV缓存作为块N+1选择的前缀上下文。草稿虽不精确，但足以指导top-k选择，仅需少量额外KV预算即可接近无损精度，从而打破数据依赖。

### 2.2 系统设计：双流流水线与双缓冲稀疏KV池
- **双缓冲**：GPU上维护两个稀疏KV池，一个用于当前块去噪（活跃池），另一个正在被填充（空闲池）。
- **主流（Main Stream）**：在GPU上执行块的去噪过程。每块开始时，step-0前向产生logits，并立即用argmax生成草稿块。step-1与草稿前向融合为一个2B token的联合前向（利用自定义注意力掩码），既完成去噪的第一步，又生成草稿KV。之后GPU继续剩余的去噪步骤。
- **检索流（Retrieval Stream）**：在草稿KV生成后立即触发。CPU使用中心[MASK] token作为查询，对完整的KV缓存（包含草稿块）执行融合的在线softmax与top-k选择内核，每层选出top-k KV条目。同时，GPU在检索流中执行QKV投影和FFN。CPU将选中的松散条目收集到连续缓冲区，并通过异步DMA传输到GPU空闲池，该传输与下一层的CPU全KV选择重叠。
- **协作细节**：每个Transformer层处理分为三步：GPU QKV投影 → CPU融合注意力+top-k选择（全量KV在CPU DRAM） → GPU FFN。通过流水线化和双缓冲，整个检索流的延迟被隐藏在主流的去噪步骤内，从而不增加块边界延迟。

### 2.3 优化CPU内核
- 融合注意力与top-k选择：以单个KV头为粒度，流式读取KV缓存tile，累积所有查询头的原始注意力分数，同时维护在线softmax统计量，最后融合多个查询头的分数为一个重要性向量，仅需一次min-heap top-k即可选出每个KV头最重要的K个位置，避免每个查询头独立top-k。
