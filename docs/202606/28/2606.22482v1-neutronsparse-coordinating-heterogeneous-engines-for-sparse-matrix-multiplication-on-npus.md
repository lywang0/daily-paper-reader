## 摘要
稀疏矩阵-矩阵乘法（SpMM）是大规模稀疏数据处理的基础数据操作。随着NPU因其性能和能效在数据中心中日益普及，在这些平台上加速SpMM是自然的选择。然而，NPU上的高性能SpMM带来了数据管理挑战，因为不规则稀疏性需要高效的数据组织和调度。在Ascend 910B上，官方MindSpore实现仅达到NVIDIA A100上基于GPU的稀疏库（如cuSPARSE）性能的36.3%。为此，我们对NPU与GPU上SpMM执行进行了深入的架构分析，并指出NPU上SpMM的关键性能瓶颈在于基于分块执行模型下异构计算单元之间缺乏有效的协调。因此，我们提出了NeutronSparse，一种面向NPU的协调优先的SpMM框架。NeutronSparse集成了两项关键技术：(i) 稀疏感知的异构引擎协调，它在异构计算单元之间自适应地分区和平衡工作负载以保持它们忙碌；(ii) 局部性感知的分块编排，它重新组织和重用数据块以减少冗余计算和内存移动开销。在Ascend 910B上的评估表明，NeutronSparse相比NPU基线实现了1.26倍至7.78倍的加速，相比NVIDIA A100上的领先GPU库实现了1.03倍至3.07倍的加速，揭示了NPU在稀疏计算中尚未开发的潜力。

## Abstract
Sparse matrix-matrix multiplication (SpMM) is a fundamental data operation for large-scale sparse data processing. With NPUs increasingly deployed in data centers for their performance and energy efficiency, accelerating SpMM on these platforms is a natural choice. However, high-performance SpMM on NPUs poses a data management challenge, as irregular sparsity demands efficient data organization and scheduling. On Ascend 910B, the official MindSpore implementation achieves only 36.3% of the performance of GPU-based sparse libraries such as cuSPARSE on NVIDIA A100. To this end, we conduct an in-depth architectural analysis of SpMM execution on NPUs versus GPU and identify that the key performance bottleneck for SpMM on NPUs lies in the lack of efficient coordination across heterogeneous compute units under tile-based execution model. Therefore, we propose NeutronSparse, a coordination-first SpMM framework for NPUs. NeutronSparse integrates two key techniques: (i) Sparsity-aware coordination of heterogeneous engines, which adaptively partitions and balances workloads between heterogeneous compute units to keep them busy, and (ii) Locality-aware tile orchestrating, which reorganizes and reuses data tiles to reduce redundant computation and memory movement overhead. Evaluations on Ascend 910B show that NeutronSparse achieves 1.26x-7.78x speedup over NPU baselines and 1.03x-3.07x speedup over leading GPU libraries on NVIDIA A100, revealing untapped potential of NPUs for sparse computation.

- **研究意义**：揭示NPU稀疏计算潜力，首次实现NPU SpMM性能超越GPU旗舰库，对推动NPU在数据密集型AI（GNN、LLM）中的应用有重要价值。

## 2. 方法论：核心思想、关键技术细节

### 核心思想
以“协调优先”（coordination-first）为设计原则，通过**稀疏感知的异构引擎协调**和**局部性感知的瓦片编排**，使NPU的两个异构引擎（AIC、AIV）并发高效执行SpMM。

### 关键技术细节
1. **稀疏感知的异构引擎协调**：
   - **体系结构感知的成本模型**：通过微基准测试获得AIC和AIV的吞吐率 \(P_{\text{AIC}}\)、\(P_{\text{AIV}}\)，推导稀疏度阈值 \(\alpha = r \cdot P_{\text{AIV}} / P_{\text{AIC}}\)（r=2 表示每AI Core有两个AIV一个AIC），用于指导初始负载划分。
   - **两阶段行-列提取划分**：先基于行稀疏度将稀疏行分配给AIV、稠密行给AIC；再对AIC子矩阵按列稀疏度进一步提取稀疏列给AIV，最终形成AIC处理的稠密核心（BitMap存储）和AIV处理的稀疏边缘（COO存储）。
   - **自适应运行时协调流水线**：监控每个epoch两引擎执行时间差，若不平衡度超过阈值（5%），则将瓶颈引擎的剩余工作迁移到空闲引擎：AIC瓶颈时，迁移稀疏瓦片到AIV；AIV瓶颈时，将相对稠密的向量打包成矩阵瓦片迁移到AIC。迁移量按成本模型平衡。

2. **局部性感知的瓦片编排**：
   - **全局-局部重排序**：全局阶段用Rabbit Order将稀疏矩阵聚成粗粒度簇；局部阶段在每个簇内基于Jaccard相似度按行重排序，使同一行窗口内的行具有相似稀疏模式，便于列压缩和形成更稠密的瓦片。
   - **层次化瓦片重用**：
     - 跨AI Core重用：利用全局重排序后的簇，将热点稠密B矩阵行主动驻留到L2缓存，其他访问绕过L2。
     - AI Core内部重用：根据缓冲容量（L0A/L0B各64KB，L0C 256KB）和双缓冲约束，选择最优瓦片形状 \((M,N,K) = (128,256,64)\)，最大化计算密度并减少输入流量和写回开销。

### 算法流程（文字说明）
1. 输入稀疏矩阵A和稠密矩阵B；
2. 预处理：基于成本模型计算阈值α，进行两阶段行-列提取，得到AIC和AIV工作负载；同时对AIC部分进行全局-局部重排序；
3. tile准备：形成128×256×64的固定shape tiles，根据重排序结果压缩空列；
4. SpMM计算：每个AI Core内AIC和AIV并发执行，主机线程通过逐epoch监控执行时间差，动态迁移负载以保持平衡；
5. 输出结果矩阵C。
