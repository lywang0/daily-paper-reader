## 摘要
最近的手机级移动SoC为设备上视觉语言模型（VLM）推理提供了实用的NPU执行路径，但开发人员仍缺乏针对跨异构后端映射VLM管道的阶段级指导。我们展示了在Qualcomm SM8750（骁龙8 Elite）上对VLM推理的硬件在环特征描述，涵盖了阶段吞吐量、缓存状态影响、100次运行的热稳定性、能耗、异构CPU/NPU管道配置以及视觉令牌预算敏感性。以FastVLM-0.5B作为端到端案例研究，结合四种架构系列的仅编码器测量，我们表明阶段至关重要：NPU执行高度依赖于阶段，预填充阶段实现1.64倍加速，但解码阶段仅为1.18倍，而视觉编码器相比CPU实现20-45倍加速。这些收益转化为稳态温度降低10.47摄氏度，能耗降低2.52倍，从而在始终开启的设置中避免热节流。最后，我们展示了一个四步图重写使得先前不支持的编码器（如Phi-3.5-V）能够到达QNN路径，实现高达22倍的加速，为移动VLM部署提供了实用的移植方法。

## Abstract
Recent phone-class mobile SoCs expose practical NPU execution paths for on-device vision-language model (VLM) inference, but developers still lack phase-level guidance for mapping VLM pipelines across heterogeneous backends. We present a hardware-in-the-loop characterization of VLM inference on the Qualcomm SM8750 (Snapdragon 8 Elite), covering phase throughput, cache-state effects, 100-run thermal stability, energy, heterogeneous CPU/NPU pipeline configurations, and visual-token-budget sensitivity. Using FastVLM-0.5B as an end-to-end case study, together with encoder-only measurements across four architecture families, we show that phase matters: NPU execution is highly phase-dependent, delivering 1.64x speedup for prefill but only 1.18x for decode, while vision encoders achieve 20-45x speedups over CPU. These gains translate into 10.47 degrees C lower steady-state temperature and 2.52x lower energy, avoiding thermal throttling in always-on settings. Finally, we show that a four-step graph rewrite enables previously unsupported encoders, such as Phi-3.5-V, to reach the QNN path with up to 22x speedup, providing a practical porting recipe for mobile VLM deployment.

- **背景**：VLM推理可分解为三个硬件亲和性不同的阶段：视觉编码（计算密集、静态形状）、预填充（计算密集、批处理GEMM）、解码（带宽受限、动态形状）。统一对待这些阶段会导致延迟、能耗和热预算的浪费。先前工作主要针对纯文本LLM，缺少对视觉编码阶段、热行为以及编码器移植路径的系统研究。

- **核心思想**：将VLM推理分解为三个硬件不同的阶段，分别测量CPU和NPU上的吞吐量、延迟、能耗和热行为；分析异构管道配置（如混合使用CPU和NPU）的效果；研究缓存状态对冷启动的影响；提出四步图重写方法以支持不兼容的视觉编码器。
- **关键技术细节**：
  - **硬件平台**：Qualcomm SM8750 (Snapdragon 8 Elite)，3nm SoC，含Oryon CPU、Adreno GPU、Hexagon NPU（标量/向量/张量引擎+VTCM）。使用W4A8 INT4权重打包以减少VTCM带宽。
  - **运行时**：CPU路径使用LiteRT + XNNPACK FP16；NPU路径使用LiteRT + Qualcomm AI Engine委托；W4A8量化路径使用QAIRT INT4权重/INT8激活。

## 6. 主要结论与发现
- **阶段重要性**：NPU加速高度依赖阶段——预填充1.64倍，解码仅1.18倍；视觉编码器20-45倍。
- **热优势**：NPU路径稳态温度比CPU低10.47°C（40.78°C vs 51.25°C），且无热节流；CPU路径在持续负载下出现延迟异常值。NPU能耗降低2.52倍。
- **冷启动不可忽视**：NPU执行器初始化开销536ms（vs CPU 84ms），通过持久化工作进程可摊销。
- **最佳管道配置**：Hybrid-PD（预填充在NPU，编码器和解码在CPU）提供最佳冷/热平衡（冷启动6240ms，热启动2640ms）。
- **视觉令牌预算**：可作为零成本延迟调节旋钮（从24到224 tokens，TTFS从0.361s到0.850s），无需重新编译模型。W4A8混合在64 tokens时达到97.5 tok/s，TTFS 0.497s。
- **编码器选型是关键**：NPU上不同编码器延迟范围14.3-103.5ms（7倍差距），比后端切换的影响更大。
- **GPU不如NPU**：GPU在编码器上比NPU慢1.7-6.9倍。
- **移植方法有效**：四步图重写使Phi-3.5-V加速22.1倍（103.5ms vs 2286.1ms CPU），96.8% FLOPs在NPU上执行。
- **输出精度可接受**：INT8 NPU路径比FP16 CPU路径CIDEr下降仅0.4点，VQAv2准确率下降0.3%。

## 7. 优点
- **分阶段细粒度分析**：揭示了不同阶段的硬件亲和性差异，为异构调度提供直接指导。
- **热行为和冷启动的系统性测量**：将温控和冷启动作为一级部署维度，具有实际工程价值。
- **实用移植方法**：四步图重写方法可一般化到多数ViT家族编码器，降低开发门槛。
- **广泛的编码器测试**：覆盖四种不同架构家族，结果具有代表性。
- **缓存状态分类清晰**：S1/S2/S3三种状态区分了不同部署场景，避免稳态基准的误导。
- **输出质量验证**：使用COCO和VQA标准评估量，证明INT8量化不影响功能性。

## 8. 不足与局限
- **单硬件平台**：仅测试了骁龙8 Elite，结果可能不适用于其他移动SoC（如联发科天玑、三星Exynos、苹果A系列）。
- **固定输入尺寸**：所有测试使用固定336×336图像和固定64+128 token序列，未探索不同分辨率和序列长度的影响。

- **热稳定性测试仅100次**：虽然足以展示趋势，但更长测试（如1000次）可能揭示更长期老化效应。
