## 摘要
Transformer模型为机器学习任务设定了新的性能标准。然而，在资源受限的边缘设备上部署这些模型以实现无云的片上Transformer推理仍然具有挑战性。ARM计算库（ARM-CL）框架为基于ARM的边缘设备提供了低延迟的CNN推理，但缺乏对Transformer推理的支持。在这项工作中，我们在ARM-CL中实现了多个新的Transformer内核以支持原生Transformer执行。与基于ARM的嵌入式板上的最先进CPU/GPU实现相比，我们扩展的ARM-CL实现了高达三倍的Transformer推理加速。此外，为边缘设备提供动力的异构多处理器片上系统同时集成了嵌入式CPU和GPU。我们引入了协作式CPU-GPU Transformer推理，该推理在CPU上执行内存密集型操作，同时利用GPU处理高度可并行化的计算密集型操作。与ARM-CL上最佳单处理器推理相比，这种以最小开销实现的协作执行进一步将Transformer推理延迟降低了高达15.72%。

## Abstract
Transformer models have set new performance standards for machine learning (ML) tasks. However, their resource-intensive deployment on resource-constrained edge devices for cloud-free, on-chip transformer inference remains challenging. The ARM Compute Library (ARM-CL) framework provides low-latency CNN inference on ARM-based edge devices but lacks support for transformer inference. In this work, we implement several new transformer kernels in ARM-CL to support native transformer execution. Our extended ARM-CL achieves up to three times faster transformer inference compared to state-of-the-art CPU/GPU implementations on an ARM-based embedded board.   Furthermore, heterogeneous multi-processor system-on-chips (HMPSoCs) powering edge devices provide both embedded CPUs and GPUs. We introduce cooperative CPU-GPU transformer inference, which executes memory-intensive operations on the CPU while utilizing the GPU for highly parallelizable, compute-intensive operations. This cooperative execution, implemented with minimal overhead, further reduces transformer inference latency by up to 15.72% compared to the best single-processor inference on ARM-CL.

- **研究背景**：Transformer已成为NLP、视觉、音频等领域的基石，但在边缘设备上部署面临巨大的计算和内存带宽需求。ARM HMPSoC（如Amlogic A331D）广泛用于边缘设备，但缺乏针对Transformer优化的库。作者首次在ARM-CL中实现Transformer内核，并探索CPU-GPU层间切换的协同推理策略。

## 2. 论文提出的方法论：核心思想、关键技术细节

- **核心思想**：扩展ARM-CL以支持Transformer原生推理，并利用CPU与GPU的层间性能异质性，将每层分配到最优处理器上执行，实现低开销的CPU-GPU协同推理。
- **关键技术细节**：
  - **单处理器Transformer推理**：在ARM-CL中新增Embedding、Multi-Head Attention（MHA）、Scaled Dot-Product Attention（SDPA）、Layer Normalization等自定义内核，使用NEON intrinsics（CPU）和OpenCL（GPU）加速。
  - **层间性能特征分析**：通过微基准测试，对五种Transformer层（Embedding、Attention Linear、SDPA、FF、Add&Norm）进行CPU/GPU延迟比（\(T_{CPU}/T_{GPU}\)）分析。结果表明：Embedding和Add&Norm层在CPU上更快（内存密集）；Attention Linear和FF层在GPU上更快（计算密集）；SDPA层两者接近。且当序列长度\(L \ge 128\)时，GPU优势因缓存不足而减弱。
  - **CPU-GPU层切换推理**：利用HMPSoC的共享内存空间避免显式memcpy开销。对于连续在同一处理器上的层使用单目标张量；在CPU-GPU切换点使用多目标共享张量，采用“upscale”方法将CPU张量提升为GPU可访问的共享张量，通过OpenCL映射实现直接读写。
- **算法流程**：模型图构建 → 层分配决策（基于微基准或在线决策） → 配置共享张量 → 执行推理时按层切换处理器。

## 6. 论文的主要结论与发现

- 扩展的ARM-CL在CPU和GPU上分别比TVM平均加速2.34倍和2.23倍；与ExecuTorch相当（CPU）。
- CPU-GPU层切换推理在五种模型上均优于最佳单处理器，延迟降低最高15.72%（平均10.95%）。
- 性能异质性主要源于层计算/内存特性与硬件缓存大小的交互：当序列长度L ≥ 128时，GPU因缓存不足（128 KB L2）而优势下降；CPU在内存密集层（Embedding、Add&Norm）始终占优。
- 基于共享内存的CPU-GPU通信几乎无额外开销，使得层切换可行。

## 7. 优点：方法或实验设计上的亮点

- **首次在ARM-CL中实现原生Transformer推理**：填补了ARM-CL在Transformer支持上的空白，代码开源。
- **细致的微基准分析**：不仅给出延迟对比，还深入分析了不同层在不同参数下的性能瓶颈（缓存、计算量、内存访问模式），为层切换决策提供理论依据。
- **低开销的CPU-GPU协同策略**：利用硬件共享内存避免数据拷贝，实现“无痛”切换。
- **覆盖多种Transformer架构**：包括BERT及其变体（蒸馏、压缩、卷积化）和GPT-2，验证了方法的通用性。

## 8. 不足与局限

- **实验覆盖有限**：仅在一个特定平台（Khadas VIM 3 BASIC）上测试，无法确认对其他ARM HMPSoC（如高通Snapdragon、瑞芯微RK3588）的可迁移性。GPU缓存大小差异可能影响结论。
- **未考虑动态序列长度**：实验固定L=32，实际推理中序列长度可变，GPU缓存瓶颈可能在不同场景下波动，未提供自适应策略。

- **缺乏真实应用场景验证**：仅测量延迟，未在图像分类、文本分类等具体任务上测试准确性是否因层切换而受影响（理论上无损失，但未确认）。
