## 摘要
当前的大语言模型（LLM）推理系统普遍采用张量并行（TP）和流水线并行（PP）的组合来部署超大规模模型。然而，现有系统将模型并行拓扑视为静态配置，无法在运行时灵活调整。这种僵化设计与现实场景中动态变化的推理工作负载产生了根本性矛盾。最先进的系统缺乏在线重配置能力，只能通过重启服务来切换配置，导致数分钟的服务中断、KV缓存丢失以及高昂的重计算开销。为解决此问题，本文提出了ReMP——一种支持低停机时间的运行时模型并行重配置框架。ReMP通过三项关键技术实现动态调整：（1）将模型并行拓扑与运行时状态解耦，避免完全重构服务；（2）设计二维KV缓存迁移机制，在TP/PP改变后保留可复用的缓存状态；（3）实现端到端在线重配置。实验表明，在7B到70B参数的模型上，ReMP能在1-7秒内完成大多数拓扑切换，相比重启方法实现了数十至上百倍的加速。此外，ReMP在动态工作负载下显著优于固定配置，在TTFT、TPOT和输出吞吐量方面均展现出优越性能。

## Abstract
Current large language model (LLM) inference systems universally deploy ultra-large-scale models using a combination of Tensor Parallelism (TP) and Pipeline Parallelism (PP). However, existing systems treat the model parallelism topology as a static configuration that cannot be flexibly adjusted at runtime. This rigid design creates a fundamental contradiction with the dynamically changing inference workloads in real-world scenarios. State-of-the-art systems lack online reconfiguration capabilities and can only switch configurations by restarting the service, resulting in several minutes of service interruption, KV cache loss, and prohibitive recomputation overhead. To address this problem, this paper presents ReMP, a runtime model parallelism reconfiguration framework that supports low downtime. ReMP achieves dynamic adjustment through three key techniques: (1) decoupling the model parallelism topology from runtime state to avoid full service reconstruction; (2) designing a two-dimensional KV cache migration mechanism to preserve reusable cache states after TP/PP changes; and (3) implementing end-to-end online reconfiguration. Experiments demonstrate that ReMP can complete most topology switches within 1-7 seconds on models ranging from 7B to 70B parameters, achieving speedups of tens to over a hundred times compared to the restart approach. Moreover, ReMP significantly outperforms fixed configurations under dynamic workloads, delivering superior performance in terms of TTFT, TPOT, and output throughput.

## 1. 核心问题与整体含义（研究动机和背景）
- 当前LLM推理服务系统普遍采用张量并行（TP）和流水线并行（PP）的组合来部署超大规模模型，但**所有现有系统都将TP/PP拓扑视为静态部署配置**，在服务启动后无法动态调整。
- 现实场景中，LLM推理工作负载具有显著的动态性（如每日高峰/低谷流量波动），不同负载区间需要不同的最优TP/PP组合：低负载时追求低延迟（高TP），高负载时追求高吞吐（高PP）。
- 现有系统的**僵化设计**导致只能通过重启服务来切换拓扑，重启过程涉及模型检查点重载、进程销毁与重建、初始化、KV缓存丢弃等，造成**数分钟的服务中断**和昂贵的重计算开销，使得动态调整在实践中不可行。
- 本文旨在**消除这一矛盾**，将模型并行拓扑从静态部署参数转变为运行时可动态调整的系统资源。

## 2. 论文提出的方法论：核心思想、关键技术细节
### 核心思想
- ReMP的核心是**解耦运行时状态与启动时拓扑**，使模型权重、KV缓存、通信组、工作进程、调度器等不再永久绑定到特定拓扑，从而在切换时只需更新受影响的组件，避免完全服务重建。

### 关键技术细节
- **共享模型权重存储（Shared Weight Store）**：服务启动时将完整模型状态字典加载到CPU共享内存中；拓扑切换时，每个工作进程直接从共享内存中提取自己所需的参数切片（根据目标TP/PP的层分配和头切片规则），避免从磁盘重载检查点。
- **二维KV缓存迁移（Two-dimensional KV Cache Migration）**：PP维度决定层归属，TP维度决定KV头切片归属；ReMP通过构建迁移计划（Algorithm 1），对每个目标层和头范围，从旧拓扑的对应rank中通过P2P通信或本地拷贝迁移KV块；采用**逐层流式迁移**（layer-wise streaming）限制峰值内存开销；在容量不足时调度器会抢占部分请求并回收块。
- **MPU状态空间（MPU State Space）**：预先为多个候选拓扑构建并行状态快照（包含TP/PP组、rank映射等），切换时直接应用，避免运行时重建通信组。
- **工作进程生命周期管理（Worker Lifecycle Management）**：将工作进程分为active和standby状态；缩放时通过standby/wakeup机制复用进程，避免进程创建/销毁开销。
- **调度器适配**：切换时暂停调度、冻结KV元数据；切换后根据目标容量调整块管理器，必要时回收或新增块；更新PP批处理队列。
- **重叠优化**：模型权重从CPU加载到GPU的过程与KV缓存迁移过程在依赖允许时并发执行，使切换关键路径由两者中的最大时长决定而非总和。

- **重配置速度**：ReMP在**1-7秒内**完成大多数TP/PP拓扑切换（H100上Llama2-7B约1-2秒，Llama2-70B约4-7秒；RTX 5090上类似），相比重启方法实现**数十倍至超过100倍的加速**。

- **核心发现**：模型并行拓扑不是静态固有属性，而是可运行时调整的资源；低停机切换使自适应服务变得可行。

## 7. 优点

- **设计简洁有效**：通过共享权重存储、二维KV迁移、MPU状态空间、工作进程生命周期管理等组件，将切换降级为轻量级状态转换，而不是完全重启。
