## 摘要
现代CPU越来越多地集成矩阵扩展，如Arm可扩展矩阵扩展（SME），使得CPU内部能够进行高吞吐量的矩阵执行。然而，对于大语言模型（LLM）推理而言，这些单元并不能普遍替代传统CPU核：预填充、解码、注意力和KV缓存操作表现出不同的算术强度、向量行为和布局要求，同时SME单元和CPU核仍共享内存带宽。本文通过基于屋顶线的SME使能CPU特性化研究这种不匹配，并利用所得模型指导算子级执行选择。我们提出了SMEPilot，一个LLM推理引擎，它为每个算子形状选择仅CPU、仅SME或SME+CPU协作执行。SMEPilot在磁贴粒度上将矩阵工作分区到SME和CPU核之间，在注意力中重叠SME适合的矩阵阶段与CPU适合的向量阶段，并维护布局状态，以便打包的张量表示被重用而不是在关键路径上重复构建。在手机、PC和服务器平台上，针对Llama-3.2-3B、Qwen3-4B和Qwen3-30BA3B，SMEPilot将端到端推理性能提升高达3.94倍。

## Abstract
Modern CPUs increasingly integrate matrix extensions, such as Arm Scalable Matrix Extension (SME), that provide high-throughput matrix execution within the CPU. For LLM inference, however, these units are not a universal replacement for conventional CPU cores: prefill, decode, attention, and KV-cache operations expose different arithmetic intensities, vector behavior, and layout requirements, while SME units and CPU cores still compete for shared memory bandwidth. This paper studies this mismatch through a roofline-based characterization of SME-enabled CPUs and uses the resulting model to guide operator-level execution choices. We present SMEPilot, an LLM inference engine that selects CPU-only, SME-only, or cooperative SME+CPU execution for each operator shape. SMEPilot partitions matrix work across SME and CPU cores at tile granularity, overlaps SME-suitable matrix stages with CPU-suitable vector stages in attention, and maintains layout state so packed tensor representations are reused rather than repeatedly rebuilt on critical paths. Across Llama-3.2-3B, Qwen3-4B, and Qwen3-30BA3B on phone, PC, and server platforms, SMEPilot improves end-to-end inference performance by up to 3.94$\times$.

### 论文提出的方法论：核心思想与关键技术细节

- **核心思想：** 基于“多屋顶线”（Multi-Ceiling Roofline）模型进行硬件感知的算子级执行计划生成。该模型考虑了SME单元和CPU核心的“近似可加计算吞吐量”和“共享内存带宽”这两个关键特性，将性能空间划分为三个区域，指导对不同算子选择不同的执行后端。
- **关键技术细节：**
    1.  **多屋顶线模型：** 构建一个统一的性能模型，拥有共享的内存带宽天花板和三个不同的计算天花板（CPU-only、SME-only、Mixed SME+CPU）。算子的算术密度决定了它处于哪个区域：
        - **内存受限区（Memory-bound）：** 对CPU和SME都受限于内存带宽，适合使用CPU执行。
        - **后端非对称脊线穿越区（Ridge-crossing）：** 对CPU是计算受限，对SME是内存受限，适合SME-only执行，利用其高计算吞吐量。
        - **计算受限区（Compute-bound）：** 对两者都是计算受限，SMEPilot将采用混合SME+CPU执行以利用近相加的计算能力。
    2.  **Tile级工作分区：** 为了解决“空间利用率缺口”，对于大型矩阵算子（如预填充FFN），SMEPilot并不将整个算子分配给单个后端，而是在输出维度上以tile粒度进行分区，将一部分tile分配给SME工作者，另一部分分配给CPU工作者，使两个后端能同时贡献计算能力。分区比率通过在线规划器根据测算的SME和CPU有效吞吐量以及tile对齐约束来动态确定。
    3.  **相位感知流水线执行：** 为了解决“时间气泡缺口”，针对注意力机制，SMEPilot设计了阶段间流水线。将矩阵密集型阶段（如`QK^T`和`PV`）分配给SME，向量密集型阶段（如softmax）分配给CPU核。通过让不同的attention tile在流水线的不同阶段并行执行，实现了SME和CPU工作负载的重叠，减少了硬件空闲时间。
    4.  **布局感知运行时：** 为了解决“布局兼容性缺口”：
        - **离关键路径打包：** 模型权重是静态的，可以在模型加载时仅执行一次打包操作，后续所有请求都重用此打包后的布局。
        - **生产者侧打包：** 对于在线生成的激活张量（如KV缓存），在生产者（如K Projection）计算时就直接写入SME友好的打包布局中，避免了下游消费者（如注意力计算）在关键路径上重复进行布局转换。
