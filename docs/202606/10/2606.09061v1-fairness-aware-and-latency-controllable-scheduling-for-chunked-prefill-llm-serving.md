## 摘要
随着大语言模型（LLM）在高度异构的工作负载下部署日益广泛，分块预填充执行已成为主流的服务架构。在此类环境中平衡调度公平性和延迟稳定性至关重要；否则，严重的队头阻塞和请求饥饿将降低用户体验。然而，现有系统依赖僵化的先来先服务（FCFS）策略和静态令牌预算，导致公平性下降和不可预测的延迟抖动。为解决这些问题，我们提出了一种面向分块预填充LLM引擎的公平感知与延迟可控调度框架。具体而言，我们设计了一种轻量级的基于老化（aging）的调度策略，利用累积等待时间和剩余预填充工作动态计算优先级。此外，我们开发了基于延迟预测的请求调度（LPRS）和主动预填充控制（APC），以目标时间约束替代静态预算，并主动调节预填充并发度。我们在NVIDIA GPU和昇腾加速器上使用真实工作负载评估了我们的调度框架。结果显示，与FCFS相比，老化策略将平均端到端延迟降低了10%以上。此外，LPRS和APC显著降低了P99尾延迟并抑制了预填充碎片，证实了结构性预填充控制与时间性延迟约束具有根本上的互补性。所有代码已在GitHub上发布。

## Abstract
As large language models (LLMs) are increasingly deployed with highly heterogeneous workloads, chunked-prefill execution has emerged as a mainstream serving architecture. Balancing scheduling fairness and latency stability in such environments is critical; otherwise, severe head-of-line blocking and request starvation will degrade user experience. However, existing systems rely on rigid First-Come, First-Served (FCFS) policies and static token budgets, leading to fairness degradation and unpredictable latency jitter. To address these issues, we propose a fairness-aware and latency-controllable scheduling framework for chunked-prefill LLM engines. Specifically, we design a lightweight aging-based scheduling policy that dynamically calculates priorities using accumulated waiting time and remaining prefill work. Furthermore, we develop Latency-Prediction-Based Request Scheduling (LPRS) and Active Prefill Control (APC) to replace static budgets with target-time constraints and actively regulate prefill concurrency. We evaluated our scheduling framework on NVIDIA GPUs and Ascend accelerators using real-world workloads. Results show the aging policy reduces mean end-to-end latency by over 10\% compared to FCFS. Moreover, LPRS and APC significantly reduce P99 tail latency and suppress prefill fragmentation, confirming that the structural prefill control and the temporal latency constraints are fundamentally complementary. All codes have been released in Github.

# 论文总结：Fairness-Aware and Latency-Controllable Scheduling for Chunked-Prefill LLM Serving

## 1. 核心问题与整体含义（研究动机和背景）
- **研究动机**：分块预填充（chunked-prefill）已成为主流LLM服务架构，但现有系统使用僵化的先来先服务（FCFS）调度和静态令牌预算，导致：
  - **公平性退化**：长请求阻塞短请求，造成短请求TTFT延长；短请求持续到达可能饿死长请求。
  - **延迟抖动**：静态令牌预算无法适应动态混合工作负载，导致实际执行时间偏离预期，GPU利用率波动。
- **核心问题**：在混合工作负载（短交互查询、长上下文预填充、长生成任务共存）下，如何兼顾调度公平性、延迟稳定性和系统效率？
- **整体含义**：需要设计轻量级、可配置的调度机制，在请求排序、时间预算控制和预填充结构三个层面协同优化，而非孤立优化吞吐量或平均延迟。

## 2. 论文提出的方法论
### 2.1 老化调度（Aging-Based Scheduling）
- **核心思想**：优先级由等待时间和剩余预填充工作量共同决定，实现短请求快速响应与长请求防饿死的平滑折中。
- **优先级公式**：
  \[
  P_i(n) = \alpha \cdot (t - a_i) + \beta \cdot r_i(n)
  \]
  其中 \(\alpha > 0\)（等待时间权重），\(\beta < 0\)（剩余工作量权重），\(a_i\) 为到达时间，\(r_i(n)\) 为剩余预填充令牌数。
- **等价排序键**：\(K_i(n) = -\alpha a_i + \beta r_i(n)\)，用最大堆维护，每次调度仅更新被选中请求的键，复杂度 \(O(k \log n)\)。
- **调度语义**：解码请求优先，预填充候选按老化优先级排序，分配剩余预算；更新剩余令牌后重新入堆。

### 2.2 基于延迟预测的请求调度（LPRS）
- **核心思想**：将调度目标从最大化令牌填充转为最小化与目标延迟预算的偏差。
- **离线延迟预测器**：轻量级三层MLP（隐藏层128→64→32，ReLU，dropout 0.1），输入16维特征（11个原始+5个衍生），使用加权不对称Huber损失训练（更惩罚低估）。
- **在线候选取与评分**：
  - 候选集：\(C_i = \{1, h_i\} \cup \{k\Delta \mid 1 \le k\Delta \le h_i\}\)，\(h_i = \min(r_i, B_{\max} - U_t)\)。
  - 用预测模型估计每个候选的批量执行时间 \(\hat{T}_{t,i}(c)\)。
  - 不对称评分函数：\(Score = \lambda_u(T^* - \hat{T})\)（欠填充惩罚）或 \(\lambda_o(\hat{T} - T^*)\)（超时惩罚，\(\lambda_o > \lambda_u\)）。
  - 选择评分最小的候选。

### 2.3 主动预填充控制（APC）
- **核心思想**：限制活跃预填充请求数，防止预算碎片化和微进度（极小chunk）。
- **动态活动上限**：
  \[
  C_t = \min\left(C_{\max},\ S_{\max} - |D_t|,\ \lfloor (B_{\max} - U_t)/L_{\min} \rfloor\right)
  \]
  同时受序列槽、剩余令牌、最小有效chunk大小约束。
- **最小有效进度**：\(m_i = \min(r_i, L_{\min})\)。
- **决策规则**：若LPRS推荐的chunk满足活动上限且≥最小进度则接受；否则若当前无活跃预填充则触发“温启动”（强制分配最小chunk），否则拒绝。

## 6. 主要结论与发现
- **老化策略**：显著降低混合负载下的平均E2E延迟（10.24%~6.75%）和TTFT（11.27%~7.11%），P95也改善；优势来自排队延迟减少而非执行时间加速；chunk size越小效果越明显；在昇腾平台上也可部署。
- **LPRS**：在高并发下有效降低P99预填充延迟（从924.22ms降至889.45ms）和P99请求延迟（从986.93ms降至952.56ms）；常规负载下与基线相当。
- **APC**：通过限制无效并发，平均请求E2E延迟降低22.26%，P90降低24.62%；平均活跃预填充数从5.32降至0.46，平均chunk大小从0.78增至6.29。
- **互补性**：LPRS（时间控制）和APC（结构控制）共同作用比单独使用更优，证明了结构性预填充控制与时间性延迟约束的互补性。

## 7. 优点
- **轻量级**：老化使用堆实现O(k log n)，LPRS用轻量MLP，APC规则简单，均几乎无额外计算开销。

- **实验全面**：覆盖单/多GPU、不同架构、参数敏感性、消融研究，且开源代码。
