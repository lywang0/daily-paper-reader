## 摘要
多轮LLM智能体将模型调用与外部工具调用交替进行，将服务从无状态请求处理转变为有状态程序执行。服务这些工作负载需要利用程序级上下文的调度、KV缓存管理和路由策略，包括轮次依赖、工具引入的空隙和可复用的KV状态。直接在真实系统上评估此类策略成本高昂，因为每个设计点可能需要在不同到达率、模型规模、服务实例数量和内存层次结构上投入专门的加速器时间。模拟提供了一种可扩展的替代方案，但现有的LLM服务模拟器针对无状态请求级工作负载，因此忽略了智能体服务的核心动态：多轮程序执行、跨轮缓存局部性以及工具空隙期间的KV缓存驻留。我们提出了AGENTSERVESIM，一种用于多轮LLM智能体服务的硬件感知模拟器。AGENTSERVESIM通过可组合的模块在程序粒度上评估服务策略：程序编排器维护程序身份和轮次顺序，工具模拟器实现工具引入的空隙，会话感知路由器维护程序到实例的亲缘性以实现缓存感知调度，KV驻留模型跟踪策略定义的跨HBM、主机DRAM/CXL和驱逐的KV放置。在真实服务部署和硬件配置上，AGENTSERVESIM在关键性能指标上以6%以内的误差复现了真实系统行为，同时完全在商用CPU上运行。这些结果表明，AGENTSERVESIM无需在昂贵加速器上进行详尽部署，即可实现对智能体服务策略的受控、可重复探索。

## Abstract
Multi-turn LLM agents interleave model calls with external tool invocations, shifting serving from stateless request processing to stateful program execution. Serving these workloads requires scheduling, KV-cache management, and routing policies that use program-level context, including turn dependencies, tool-induced gaps, and reusable KV state. Evaluating such policies directly on real systems is costly, since each design point may require dedicated accelerator time across arrival rates, model scales, serving-instance counts, and memory hierarchies. Simulation offers a scalable alternative, but existing LLM serving simulators target stateless request-level workloads and therefore omit the core dynamics of agent serving: multi-turn program execution, cross-turn cache locality, and KV-cache residency during tool gaps. We present AGENTSERVESIM, a hardware-aware simulator for multi-turn LLM agent serving. AGENTSERVESIM evaluates serving policies at program granularity through composable modules: a Program Orchestrator preserves program identity and turn order, a Tool Simulator materializes tool-induced gaps, a Session-Aware Router maintains program-to-instance affinity for cache-aware dispatch, and a KV Residency Model tracks policy-defined KV placement across HBM, host DRAM/CXL, and eviction. Across real serving deployments and hardware configurations, AGENTSERVESIM reproduces real-system behavior within 6% error across key performance metrics while running entirely on commodity CPUs. These results show that AGENTSERVESIM enables controlled, repeatable exploration of agent-serving policies without requiring exhaustive deployment on costly accelerators.

## 1. 核心问题与整体含义（研究动机和背景）

多轮LLM智能体（如自动编码助手、函数调用管道、搜索代理等）将模型调用与外部工具调用交替执行，服务形态从无状态请求处理转变为有状态程序执行。这种转变引入了几项关键挑战：
- **轮次依赖与工具间隙**：工具的调用时长从毫秒到分钟不等，影响用户感知的作业完成时间（JCT）。
- **KV缓存管理**：跨轮次的KV状态需要妥善保留、交换或丢弃，以平衡内存压力与未来预填充成本。
- **调度与路由**：需要利用程序级上下文（如已获服务量、缓存局部性）优化性能。

直接在真实系统上评估这些策略成本极高——每个设计点（不同的到达率、模型规模、实例数、内存层次）都可能需要专门的加速器时间。现有LLM服务模拟器（如Vidur、APEX、LLMServingSim）面向无状态请求工作负载，无法捕捉智能体核心动态（多轮执行、工具间隙、KV驻留）。因此，亟需一个能忠实复现智能体服务行为、且运行成本低廉的模拟器。

论文提出 **AGENTSERVESIM**，旨在填补这一空白，使智能体服务策略的设计空间探索变得可控、可重复，且无需昂贵加速器。

## 2. 方法论：核心思想与关键技术细节

### 核心思想
以智能体**程序**（而非单个LLM请求）为执行单位，通过可组合模块模拟多轮程序执行、工具间隙、会话感知路由和跨轮KV驻留。四个核心模块：

| 模块 | 功能 |
|------|------|
| **程序编排器** | 维护程序身份和轮次顺序；记录每程序的轮次索引、待定工具标志，在工具完成前阻止下一轮次释放。 |
| **工具模拟器** | 支持两种模式：**回放**（使用捕获的工具时长）和**生成**（按工具名采样分布）。工具间隙期间KV状态由KV驻留模型管理。 |
| **会话感知路由器** | 在多个模型服务组（MSG）间保持程序到实例的亲缘性：默认将连续轮次路由到同一实例；当主实例过载时，支持等待、迁移或重预填充，并将成本信号传递给调度器。 |
| **程序感知批调度器** | 以程序身份为键的队列，暴露程序级状态（已获服务量、历史）给可插拔策略钩子；支持请求级FCFS、程序级FCFS、已获服务优先等策略，底层引擎实现复用。 |
| **KV驻留模型** | 为每程序的KV节点标记策略定义的截止时间；在HBM、主机DRAM/CXL、驱逐之间跟踪KV放置。采用RadixAttention风格的前缀缓存，支持时间感知保留与逐出。 |

### 算法流程（文字说明）
1. 初始化：构造每个LLM对应的模型服务组，绑定设备，安装策略。
2. 运行时循环：
   - 程序编排器生成**New Turn**事件。
   - 会话感知路由器将事件路由到目标MSG。
   - MSG内：调度器入队，KV驻留模型管理KV状态，系统模拟器执行算子图（基于LLMServingSim 2.0的算子映射与调度，以及ASTRA-sim/Chakra后端）。
   - 轮次完成后，工具模拟器注入下一个轮次的工具间隙。
3. 循环直到所有程序完成。

## 3. 实验设计

### 数据集/场景
- **工作负载**：SWE-Bench Verified轨迹（使用mini-swe-agent、Qwen3.6-plus，共50个程序）。
- **轨迹特征**：每个程序平均~42轮，工具时长呈重尾分布（均值1161ms，标准差4125ms），跨轮前缀复用率中位数η≈0.95。

### Benchmark对比方法
共四种策略，均在真实系统（vLLM）和模拟器中实现：
- **vLLM-FCFS**：请求级FCFS，轮次结束后KV立即释放。
- **Autellix**：程序级已获服务量调度。
- **InferCept**：中断感知KV管理（基于成本决策保留、交换或丢弃）。
- **Continuum**：程序级FCFS + 基于成本模型的KV保留（固定2s阈值）。

### 硬件平台
- RTX 3090（24 GB GDDR6X）
- H100-SXM（80 GB HBM3）
- B200（180 GB HBM3e）

每个平台使用单节点vLLM部署，AGENTSERVESIM在商用CPU上运行。

## 6. 主要结论与发现

1. **模拟精度高**：在80个验证单元上，程序JCT的预测误差在-4.79% ~ +4.70%之间，瞬时吞吐量误差低于2%。
2. **会话路由关键**：在多实例部署中，会话感知路由使前缀缓存命中率稳定在96.26%，而轮询/最少负载路由损失3.3~3.6个百分点，导致P95 JCT增加1.2~5.1秒。
3. **前缀缓存是首要优化**：在相同调度策略下，开启前缀缓存可获得1.24×~1.71×的加速比（随负载上升），而关闭缓存时P95 JCT翻倍。
4. **策略选择在高前缀复用率下至关重要**：当前缀复用率η≥0.5时，InferCept比Autellix低3倍P95 JCT；η<0.3时差距缩小至误差范围内。
5. **工具延迟增大时，智能体感知策略优势扩大**：当工具时长缩放因子k≥1时，Continuum比vLLM-FCFS降低26.7%的JCT，缓存命中率提升8.5个百分点。
6. **二层内存（CPU DRAM/CXL）提供显著增益**：当负载饱和时，HBM+CPU相比HBM-only降低最多28%的平均JCT；CXL带宽在中等负载下额外提供最高9.8%的改进，但饱和负载下仅改善尾部延迟。

## 7. 优点

- **首创程序级模拟框架**：首次将程序身份、工具间隙、会话路由和跨轮KV驻留整合到单一硬件感知模拟器中，填补了现有模拟器空白。
- **高精度**：在多种异构硬件和模型规模上误差<6%，策略排名保真度高，可用于可靠的设计空间探索。
- **低成本可扩展**：完全在CPU上运行，无需GPU，并行支持多单元，可探索真实系统中难以或昂贵测试的配置（如大集群、假想内存层次）。
- **模块化可插拔设计**：策略接口清晰，易于实现和比较新调度、缓存、路由算法。
- **丰富的设计空间分析**：通过系统性消融和扫描，揭示了前缀缓存、会话路由、KV保留等策略之间的耦合关系，为算法设计和系统部署提供指导。

## 8. 不足与局限

- **继承底层模拟限制**：沿用LLMServingSim 2.0的分析网络和基于profile的算子假设，无法模拟非确定性的网络竞争和算子级动态。
- **工具间隙非确定性**：回放模式假设工具行为与轨迹完全一致，生成模式虽提供分布但未验证其预测有效性。
- **验证范围有限**：仅覆盖两个模型规模（8B、70B）和三个GPU平台（RTX 3090、H100、B200），未扩展到TPU、MoE模型（如Mixtral）或更复杂的异构集群。
- **负载特性单一**：仅使用SWE-Bench这一种编程类智能体工作负载，其他领域（如信息检索、对话代理）的工作负载特性可能不同，有待验证。
- **策略排名差异小**：在所测工作负载下，四种策略的JCT差异不大（±3%以内），难以评估模拟器在大差异情况下的排序能力。作者承认这是局限（§7）。
- **缺少端到端容错建模**：未考虑虚拟内存、分页、中断等真实系统的硬件事件对KV驻留的细粒度影响。
