## 摘要
高效地服务大语言模型（LLM）推理任务对于用户感知的延迟（如首个令牌生成时间TTFT）和GPU利用率都至关重要。然而，LLM请求路由——即将每个推理请求分配给GPU实例——尤其具有挑战性：执行高度依赖输入；批处理和KV缓存复用造成了强烈的跨请求耦合；延迟对上下文长度、模型/引擎设置以及异构加速器的响应是非线性的。因此，简单的传统负载均衡算法，甚至针对LLM推理量身定制的启发式方法，都难以实现良好的性能。我们提出了Lodestar，一种面向分布式GPU集群的、基于学习的请求路由系统。Lodestar持续在每请求级别收集集群快照，包括实时实例状态、请求特征和观察到的性能，并训练一个在线奖励预测器，用于将推理请求路由到能够最大化给定奖励（例如最小化TTFT）的实例。Lodestar是云原生的，可与现有服务堆栈（vLLM）无缝协作。通过持续在线适应变化的工作负载和基础设施条件，与最先进的前缀缓存和负载感知启发式方法相比，Lodestar在平均TTFT上降低了1.41倍，在P99 TTFT上平均降低了1.47倍（在同构集群上最高可达2.15倍/1.86倍，在异构集群上最高可达4.38倍/4.42倍），并且基于在公有云GPU集群中的实验，Lodestar在大约5分钟内学习到这些高效的路由策略。

## Abstract
Efficiently serving large language model (LLM) inference tasks is crucial both for user-perceived latency such as time-to-first-token (TTFT) and for GPU utilization. However, LLM request routing, that is, assigning each inference request to a GPU instance, is particularly challenging: execution is highly input-dependent; batching and KV-cache reuse create strong cross-request coupling; and latency responds nonlinearly to context length, model/engine settings, and heterogeneous accelerators. As a result, simple traditional load balancing algorithms, and even heuristics tailored for LLM inference, fail to achieve good performance. We present Lodestar, a novel learning-based request routing system for distributed GPU clusters. Lodestar continuously collects a snapshot of the cluster at per-request level, including real-time instance state, request characteristics, and observed performance, and trains an online reward predictor that it uses to route inference requests to the instance that will maximize given reward (e.g., minimizing TTFT). Lodestar is cloud-native and works seamlessly with existing serving stacks (vLLM). With continuous online adaptation to changing workloads and infrastructure conditions, Lodestar achieves 1.41x lower average TTFT and 1.47x lower P99 TTFT on average (up to 2.15x/1.86x on homogeneous and 4.38x/4.42x on heterogeneous clusters) compared to a state-of-the-art prefix cache and load-aware heuristic, and learns these efficient routing strategies within about 5 minutes, based on experiments in a public cloud GPU cluster.

## 1. 核心问题与整体含义（研究动机和背景）
- **问题**：在大规模LLM推理集群中，请求路由（将每个推理请求分配给GPU实例）极具挑战性。原因包括：
  - 执行高度依赖输入（输入长度差异大）；
  - 批处理与KV缓存复用导致跨请求耦合；
  - 延迟对上下文长度、引擎设置、异构加速器呈非线性响应。
- **现有方法不足**：简单负载均衡（如轮询、最小请求数）和手动设计的LLM启发式规则（如前缀缓存+负载感知）无法捕捉复杂动态，性能不稳定。例如，固定阈值或加权规则无法适应负载与工作负载变化。
- **本文动机**：提出**在线学习**方法，从实时数据中自动学习路由策略，自适应动态集群环境，以最小化用户感知延迟（TTFT）。

## 2. 方法论
- **核心思想**：训练一个**在线奖励预测器**（神经网络），预测每个请求路由到每个实例的奖励（负TTFT），然后贪婪地选择预测奖励最高的实例。
- **关键技术细节**：
  - **特征设计**：三类特征——请求特征（输入token长度）、预期KV缓存命中率（由全局前缀树计算）、实例状态（运行/排队请求数、预填充/解码inflight token数、GPU内存利用率、GPU模型名称）。排除GPU利用率等噪声指标。
  - **模型架构**：MLP，3层隐藏层（128单元），ReLU激活，Dropout(0.1)。参数在不同实例间共享，不依赖实例ID，支持弹性扩展。
  - **在线学习**：持续收集每请求的（特征、实际TTFT）数据，定期重训练模型。采用**两池数据选择**：FIFO缓冲区（5000个最新样本）+重放缓冲区（5000个通过梯度核心集准则选取的多样样本），兼顾时效性与多样性。
  - **缓解贪婪次优性**：引入**一致哈希过滤**：当集群GPU内存饱和度超过阈值（如80%）时，将候选实例缩小至与共享前缀组一致哈希的k个实例（文中k=2），再从中选取最佳预测，减少KV缓存碎片。
  - **系统架构**：
    - **状态网关**（Go实现）：收集集群快照、运行前缀树、触发路由决策，内置回退启发式（冷启动/超时/OOD时使用）。
    - **路由服务**（Python实现）：运行模型推理和异步训练，与网关隔离，保证关键路径低延迟（~3ms）。
  - **回退机制**：冷启动、输入超出分布、超时或错误时，自动切换回预计算启发式策略。

## 6. 主要结论与发现
- Lodestar**显著优于**所有现有启发式方法：平均TTFT降低1.41x，P99降低1.47x（同构最高2.15x/1.86x，异构最高4.38x/4.42x）。
- **在线学习至关重要**：快速适应工作负载变化（约5分钟）；离线训练或冻结模型性能大幅下降（循环依赖）。
- **一致性哈希过滤**有效缓解贪婪路由的尾延迟问题（P99降低1.78x）。
- 两池数据选择策略平衡了时效性与多样性，优于仅用FIFO或全部历史。
- 在异构集群中，Lodestar自动学习各GPU模型性能差异（如V100不支持前缀缓存），找到更优的负载分配，避免热点。
- 路由开销极小（~3ms），远小于TTFT节省（数百毫秒）。
