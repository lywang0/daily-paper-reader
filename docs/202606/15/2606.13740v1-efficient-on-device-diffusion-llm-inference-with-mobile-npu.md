## 摘要
扩散大语言模型（dLLMs）通过并行去噪多个token来加速生成，使其适用于延迟敏感的移动端推理。然而，重复去噪给智能手机带来了大量计算。移动神经处理单元（NPU）提供高吞吐量的密集矩阵计算，但高效利用它们仍然具有挑战性：token确认使得每块有效工作负载缩小，token修正使KV缓存复用复杂化，且NPU可见地址空间有限导致昂贵的重映射和数据传输开销。在本文中，我们提出了llada.cpp，这是首个面向NPU的推理框架，用于加速智能手机上的dLLM。llada.cpp通过三种技术将块级dLLM推理与移动NPU的执行特性对齐。（1）多块推测解码用推测的未来块token填补当前块解码后期不断缩小的工作负载。（2）双路径渐进修正允许已确认的token在稳定前可被修正，并通过CPU侧路径刷新不稳定token而不阻塞密集的NPU执行。（3）交换优化内存运行时紧凑化NPU可见地址布局，并使数据预取与NPU计算重叠以减少重映射和传输开销。我们将llada.cpp实现为一个端到端框架，并在多种硬件平台和dLLM工作负载上进行了评估。在使用前缀KV缓存复用的情况下，llada.cpp将LLaDA-8B的生成延迟相较于CPU基线降低了17倍至42倍，同时保持了生成质量。

## Abstract
Diffusion large language models (dLLMs) accelerate generation by denoising multiple tokens in parallel, making them attractive for latency-sensitive mobile inference. However, repeated denoising introduces substantial computation on smartphones. Mobile neural processing units (NPUs) offer high-throughput dense matrix computation, but efficiently exploiting them remains challenging: token commitment shrinks per-block effective workloads, token revision complicates KV cache reuse, and limited NPU-visible address space incurs costly remapping and data transfer overheads.   In this paper, we propose llada.cpp, the first NPU-aware inference framework for accelerating dLLMs on smartphones. llada.cpp aligns block-wise dLLM inference with the execution characteristics of mobile NPUs through three techniques. (1) Multi-Block Speculative Decoding fills the shrinking workload in late-stage current-block decoding with speculative future-block tokens. (2) Dual-Path Progressive Revision keeps committed tokens revisable until stable and refreshes unstable tokens through a CPU-side path without stalling dense NPU execution. (3) Swap-Optimized Memory Runtime compacts NPU-visible address layouts and overlaps data staging with NPU computation to reduce remapping and transfer overheads. We implement llada.cpp as an end-to-end framework and evaluate it across diverse hardware platforms and dLLM workloads. llada.cpp reduces LLaDA-8B generation latency by 17x-42x over the CPU baseline with prefix KV cache reuse, while preserving generation quality.

- **核心问题**：静态移动 NPU 执行模型与动态块状 dLLM 推理之间的不匹配，导致 NPU 利用率低、延迟收益被内存开销抵消。
- **整体含义**：提出首个 NPU 感知的 dLLM 推理框架 **llada.cpp**，通过算法-系统协同设计，将 dLLM 的并行去噪特性与移动 NPU 的密集张量计算能力对齐，实现端侧高效生成。

## 2. 方法论：核心思想、关键技术细节

### 核心思想
以块状解码为基础，将 dLLM 推理过程适配移动 NPU 执行特性：利用 NPU 处理规则、密集的大矩阵计算，将动态行为（token 承诺、修正、内存访问）通过三个关键技术转化为静态高效执行。

### 关键技术与算法流程（文字说明）

#### ① 多块推测解码（Multi-Block Speculative Decoding）
- **问题**：块内解码后期剩余掩码 token 减少，NPU 有效工作负载下降。
- **方案**：将解码窗口扩展至未来块，将未来块 token 作为草稿（draft）与当前步一起处理。
  - **连续滑动**：随着左边界 token 确认，窗口向右滑动，保持固定大小并引入未来块 token。
  - **自适应前瞻**：当剩余掩码 token 低于阈值时，主动扩展窗口，利用 NPU 延迟阶梯特性（步进式增长）以微小边际延迟换取更多并行工作。
- **效果**：增加有效工作负载，提高 NPU 利用率，解码语义由块级提交顺序保证。

#### ② 双路径渐进修订（Dual-Path Progressive Revision）
- **问题**：已确认 token 可能因后续上下文变化需要修订，而密集的 KV 缓存刷新不适合 NPU 规则执行。
- **方案**：
  - **三阶段状态机制**：每个 token 经历 **不可见（IV）→ 可见（V）→ 稳定（S）** 状态转变。可见 token 可参与后续解码但可被修订，稳定 token 才永久嵌入前缀 KV 缓存。
  - **稀疏缓存刷新**：CPU 侧路径异步重算可见 token 的置信度、身份和 KV 状态，使用专有 CPU 核解码 NPU 专用权重格式（HMX tile 布局），避免布局转换。采用延迟合并策略，在步骤边界统一更新，避免 CPU-NPU 同步阻塞。
  - **选择性 logits 跳过**：稳定 token 的输出投影、置信度评估和采样逻辑全部跳过，减少 CPU 端冗余计算。
- **效果**：保持生成质量的同时，将稀疏操作卸载给 CPU，NPU 专注密集去噪。

#### ③ 交换优化内存运行时（Swap-Optimized Memory Runtime）
- **问题**：NPU 可见地址空间有限，无法同时容纳权重、KV 缓存、激活和工作空间，导致频繁缓冲区重映射和数据搬运。
- **方案**：
  - **图引导缓冲区映射**：利用计算图分析张量生命周期，分为常驻（long-lived）和临时（short-lived）两类；在地址预算约束下，通过配置文件决定哪些常驻数据保留、哪些临时数据映射，并紧凑排列以减少映射次数。
  - **流水线数据迁移**：通过双缓冲隐藏数据搬运延迟。NPU 消费一个槽位时，CPU 预取下一个槽位的数据并验证映射；遵循图依赖顺序提前准备缓冲区描述符。
- **效果**：减少可避免的 VA 交换，将不可避免交换的延迟隐藏于 NPU 计算之后。

### 算法集成流程
1. 每次去噪步骤中，NPU 执行当前解码窗口的前向计算（含当前块和未来块 token）。
2. 同时 CPU 侧执行稀疏缓存刷新（针对不稳定可见 token）和选择性 logits 计算/跳过。
3. 步末根据置信度阈值更新 token 状态，确定提交的稳定 token；解码窗口根据剩余掩码数和 NPU 延迟表动态调整。
4. 块完成后，前缀 KV 缓存仅合并稳定 token，可见但未稳定的 token 继续通过 CPU 路径跟踪。

## 6. 主要结论与发现

1. **显著延迟加速**：llada.cpp 将 LLaDA-8B 端到端生成延迟相比 CPU（含前缀 KV 缓存）降低 17×–42×，在 SM8750 和 SM8850 上甚至快于等规模自回归 Llama。
2. **质量保持**：组件消融显示，仅多块推测解码可能降低质量，但加入双路径渐进修订后质量恢复至接近 CPU 基线。
3. **组件贡献**：最大收益来自分段 token 稳定（STS，单独贡献 3.65× 加速），其余组件贡献 1.04×–1.78×。
4. **NPU 利用条件**：单纯 NPU 卸载不足（NPU 基线比 CPU 只快 1.78×），需要系统性对齐（加速达 50×+）。
5. **内存边界**：无交换优化时，大 token 预算无法运行；llada.cpp 的图引导映射和流水线搬移使系统可支持 512 token 输出。
6. **能量效率**：llada.cpp 在 LLaDA 上平均功耗 2.9W、能量 25J，优于 CPU（3.8W、581J）和 Llama NPU（5.3W、145J），表明充分并行才能发挥 NPU 能效优势。

## 7. 优点

- **首创性**：首个专门面向移动 NPU 的 dLLM 推理框架，填补了端侧扩散模型加速的空白。
- **系统级协同优化**：不限于单一组件，而是从算法（推测解码、状态管理）到系统（内存布局、流水线搬运）全面对齐硬件特性。
- **实验严谨性**：多平台、多模型、多数据集、完整的消融与敏感性分析，结果可复现。
- **实用落地**：基于常见开源框架（llama.cpp）修改，代码开源，可直接在商用手机上运行，具备真实部署潜力。
- **能量与延迟双优**：通过提高 NPU 利用率同时降低整体能耗，适合移动端交互场景。

## 8. 不足与局限

- **硬件局限性**：仅适配高通 Hexagon NPU，未在其它移动 NPU（如 Apple Neural Engine、MediaTek APU、三星 NPU）上验证。这些硬件的地址空间、布局约束、编程模型可能差异大，迁移需额外工程。
- **模型规模限制**：仅测试 7B–8B 模型，未验证更大参数（如 13B+）或更小的 dLLM。随着模型增大，NPU 内存压力更大，当前方法是否可扩展未知。

- **双路径 CPU 依赖**：稀疏刷新和 logits 跳过部分仍依赖 CPU，若 CPU 负载过高（如其他应用运行）可能成为瓶颈。论文未提供 CPU 占用率分析。
