## 摘要
随着大语言模型（LLM）进入生产服务阶段，从业者必须快速评估不同硬件、模型和服务参数下的推理性能，以满足成本和延迟目标。然而，LLM的端到端行为将服务层策略与底层GPU内核执行及快速演进的架构耦合在一起，导致缓慢、特定于部署的基准测试难以泛化。我们提出KernelSight-LM，一种细粒度推理模拟器，它建模词元级执行并产生内核级延迟分解。它将每个服务步骤分解为具有学习效率项的屋顶线内核模型、通信模型和主机开销模型，通过离散事件调度器组合，该调度器还捕获前缀缓存和连续批处理等机制。KernelSight-LM提供两个预测层级，以目标GPU数据换取准确性。跨代层级不使用目标GPU测量，仅使用硬件规格和先前分析GPU的内核微基准测试，在未见过的GPU代上预测每个内核延迟误差为12.1%，比屋顶线基线（22.0%）提升1.8倍。第二个目标测量层级在目标GPU上增加一次与模型无关的内核微基准测试扫描，将每个内核误差降至3.8%，比可比基线（27.7%）提升7.3倍。两个层级所需的目标GPU数据远少于它们扩展的先前系统。在我们的模拟器中，这些预测在六个模型系列上产生端到端中位数（p50）误差，跨代层级分别为15.4%、12.8%和3.0%（TTFT、TPOT、吞吐量），目标测量层级分别为14.3%、6.2%和2.7%，与专用性能分析工具匹配，同时收集的机载数据更少。除预测外，其内核级瓶颈分解支持硬件/软件协同设计和容量规划。

## Abstract
As large language models (LLMs) move into production serving, practitioners must rapidly evaluate inference performance across diverse hardware, models, and serving parameters to meet cost and latency targets. However, the end-to-end behavior of LLMs couples serving-layer policies with low-level GPU kernel execution and rapidly evolving architectures, forcing slow, deployment-specific benchmarking that is hard to generalize.   We present KernelSight-LM, a fine-grained inference simulator that models token-level execution and produces kernel-level latency breakdowns. It decomposes each serving step into a roofline kernel model with a learned efficiency term, a communication model, and a host-overhead model, composed through a discrete-event scheduler that also captures mechanisms like prefix caching and continuous batching.   KernelSight-LM offers two prediction tiers that trade target-GPU data for accuracy. The cross-generation tier uses no target-GPU measurements, only hardware specifications and kernel microbenchmarks from previously profiled GPUs, and predicts per-kernel latency on an unseen GPU generation to 12.1% error, a 1.8x improvement over the roofline baseline (22.0%).   A second target-measured tier adds one model-agnostic kernel-microbenchmark sweep on the target GPU, sharpening per-kernel error to 3.8%, a 7.3x improvement over a comparable baseline (27.7%). Both tiers require far less target-GPU data than the prior systems they extend.   In our simulator, these predictions yield end-to-end median (p50) errors across six model families of 15.4%, 12.8%, and 3.0% (TTFT, TPOT, throughput) in the cross-generation tier and 14.3%, 6.2%, and 2.7% in the target-measured tier, matching dedicated profiling tools while collecting far less on-device data. Beyond prediction, its kernel-level bottleneck breakdowns support hardware/software co-design and capacity planning.

## 1. 论文的核心问题与整体含义（研究动机和背景）

- **研究动机**：大语言模型（LLM）在生产部署中，从业者需要快速评估不同硬件、模型和服务参数下的推理性能，以在成本和延迟目标之间取得平衡。然而，LLM 推理的端到端行为耦合了服务层策略（如批处理、前缀缓存）与底层 GPU 内核执行，导致传统的部署特定基准测试既缓慢又难以泛化。现有的三类方法各有局限：
  - **基于测量的估计**（如 Vidur、AIConfigurator）需要针对每个模型-硬件对进行完整分析，无法外推至未测试的 GPU。
  - **跨设备性能预测**（如 NeuSight）可以跨 GPU 代迁移，但忽略了生产服务中的请求到达、排队、批处理、KV 缓存管理等动态行为。
  - 两类方法均未显式建模主机侧开销（CPU/GPU 重叠、调度启动等）。
- **整体含义**：本文旨在弥合“服务保真度”与“硬件可移植性”之间的鸿沟，提出一种能同时在未见 GPU 上进行零样本预测并保持服务级精度的内核级推理模拟器。

## 2. 论文提出的方法论：核心思想、关键技术细节

### 核心思想
- 将每个服务步骤分解为三个核心模型：
  1. **带学习效率项的屋顶线内核模型**：每个 GPU 内核的延迟 = max(屋顶线延迟 × 效率因子, 启动下限)。
  2. **通信模型**：建模 Tensor Parallel 下的 All-Reduce 延迟。
  3. **主机开销模型**：建模 CPU/GPU 重叠、调度尾延迟等。
- 通过离散事件调度器组合上述模型，并显式模拟前缀缓存、连续批处理等高级机制。
- 提供两个预测层级（Tier A 和 Tier B），用户可根据可用目标数据选择。

### 关键技术细节

#### 效率预测公式
\[
t = \max(t_{\text{roof}} \cdot \eta, t_0), \quad t_{\text{roof}} = \max\left(\frac{F_{\text{comp}}}{P_{\text{peak}}} u, \frac{F_{\text{mem}}}{BW_{\text{peak}}}\right)
\]
- \(F_{\text{comp}}, F_{\text{mem}}\)：内核的计算量和访存量。
- \(P_{\text{peak}}, BW_{\text{peak}}\)：峰值算力和带宽。
- \(u = \lceil B / N_{\text{SM}} \rceil N_{\text{SM}} / B \ge 1\)：波次量化修正（当线程块数不能整除 SM 数时）。
- \(\eta\)：学习效率因子，由每个内核族独立学习。Tier A 使用跨 GPU 的通用模型，Tier B 通过目标 GPU 微基准测试插值获得。
- \(t_0\)：启动下限，固定常数。

#### 通信模型（Ring All-Reduce）
\[
t_{\text{ar}} = \alpha_0 + \frac{2(P-1)}{P} \cdot \frac{S}{\beta_{\text{eff}}}
\]
- \(P\)：Tensor Parallel 分片数，\(S\)：消息大小，\(\beta_{\text{eff}}\)：有效互联带宽。

#### 步骤聚合
\[
t_{\text{step}} = \max(t_{\text{gpu}} + n c_{\text{disp}}, \ell) + \max(0, c_{\text{ovl}} - t_{\text{gpu}}) + c_{\text{tail}}
\]
- \(t_{\text{gpu}}\)：GPU 主体延迟（各层内核 + LM head + embedding + All-Reduce 之和）。
- 各 \(c\) 为主机开销常数（从 Tier B 的短服务扫描中测量，Tier A 使用最近亲缘的校准值）。

#### 层级差异
- **Tier A（零样本跨代）**：仅使用目标 GPU 的规格参数（峰值算力、带宽、SM 数量等）和源 GPU 上预收集的微基准数据库，通过学习的效率模型（每个内核族选择一个低容量回归器，如线性模型、梯度提升树、小 MLP 集成或 NeuSight 的有界解析形式）预测 \(\eta\)。无目标设备测量。
- **Tier B（目标测量改进）**：在目标 GPU 上执行一次与模型无关的微基准扫描，对每个形状插值测量到的效率残差（\(\eta\)），并测量主机开销常数。对于超出测量凸包的外推形状，回退到 Tier A 的学习模型。

#### 模拟器扩展
- 重新实现了 vLLM v1 调度器（逐行验证，Spearman 相关系数 0.985）。
- 支持两级（GPU/磁盘）前缀缓存。
- 显式支持混合预填充-解码步骤（连续批处理中的 chunked prefill）。

## 6. 论文的主要结论与发现

1. **Tier A（零样本跨代）**：预测未见 GPU（GB200）的每个内核延迟 MAPE 为 12.1%，比 NeuSight 的 22.0% 提升了 1.8 倍。提升主要来自内存绑定和注意力内核，这些内核的效率形状随形状和设备变化更大，而计算绑定内核（GEMM、LM head）改进较小。
2. **Tier B（目标测量）**：在添加一次微基准扫描后，每个内核 MAPE 降至 3.8%，比 AIConfigurator 的 27.7% 提升了 7.3 倍。优势来源于（a）显式测量了 AIConfigurator 忽略的小元素级/内存内核（这些内核仅使用固定解析式，误差达 30-64%）；（b）对注意力等操作符使用效率残差插值而非原始延迟插值，更平滑。
3. **端到端服务指标**：
   - TTFT：Tier A p50 15.4%，Tier B p50 14.3%，最差情况（长上下文）达 149%。
   - TPOT：Tier A p50 12.8%，Tier B p50 6.2%。
   - 吞吐量：Tier A p50 3.0%，Tier B p50 2.7%。
   - 与 AIConfigurator 相比，KernelSight-LM 在 TTFT 上尤为显著（AIConfigurator 的 TTFT p50 高达 59%，因其缺乏主机开销模型）。
4. **主机开销建模的重要性**：Tier A 和 Tier B 均显式建模主机开销（CPU/GPU 重叠等），这是低延迟请求（短提示）TTFT 准确性的关键。
5. **局限性**：注意力内核的效率因子在不同 GPU 代之间转移最差（图 10-11），当 \(\eta\) 离开源设备包络时无法插值，需要至少一次按架构的注意力校准。

## 7. 优点：方法或实验设计上的亮点

- **双层次设计**：自然适应不同数据可用场景（零样本 vs 可测量），且基层共用同一公式，新数据只需更新效率因子。
- **效率残差插值**：在 Tier B 中插值 \(\eta\)（有界残差）而非原始延迟，使插值面更平滑，提升外推稳健性。
- **内核级粒度 + 服务模拟**：结合了跨设备预测与完整的事件驱动服务模拟（连续批处理、前缀缓存、chunked prefill），比纯操作符级方法更能捕捉实际系统中的端到端行为。
- **显式主机开销建模**：通过校准常数将 CPU/GPU 重叠、调度尾延迟等纳入模型，显著提升了短提示 TTFT 的准确性（比 AIConfigurator 低 4 倍）。
- **诚实讨论局限性**：在附录 B 中专门讨论注意力效率因子不可迁移性，并给出量化分析（图 10-12），增强了研究的透明度与可信度。
- **丰富的实验对比**：在多个模型族、规模、并行度、负载下测试，覆盖了关键服务指标的不同百分位，并提供了热图直观展示。

## 8. 不足与局限：覆盖偏差、风险、应用限制

- **跨代预测仅限于一个目标**：仅将 GB200 作为完全留出的跨代目标，未在更多未见架构（如未来 Blackwell 变体、Intel 或 AMD GPU）上验证，外推可靠性有待更多设备验证。
- **注意力内核的弱可迁移性**：观察到的注意力效率因子设备依赖性（图 11）意味着 Tier A 对注意力的预测误差可能较高（但仍比 NeuSight 好 2.8 倍）。作者建议至少一次按架构的注意力校准，这限制了 Tier A 的真正零样本能力。
- **假设主机开销常数可迁移**：Tier A 使用“最近亲缘” GPU 的主机开销校准常数，但主机开销因 CPU、驱动程序、引擎版本而异，跨代误差可能增大。
- **实验饱和分析有限**：附录 C 显示当负载接近容量（\(\rho \approx 1.2\)）时 TTFT 误差飙升至 74%，但作者认为 SLO 导向部署通常在 \(\rho \approx 0.6-0.8\)，故实际影响有限。但这限制了工具在极高并发场景下的适用性。
