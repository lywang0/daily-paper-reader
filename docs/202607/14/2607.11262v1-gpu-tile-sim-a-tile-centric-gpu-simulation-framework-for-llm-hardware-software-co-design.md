## 摘要
现代LLM（大语言模型）工作负载越来越依赖通过硬件-软件协同设计优化的GPU内核。这些内核通过细粒度依赖调度和计算-内存重叠实现高性能。因此，它们给现有的GPU性能模型带来了新的挑战。指令驱动的模拟器难以适应不断变化的架构，而分析模型又过于粗略，无法捕捉内核的特征。我们提出GPU-Tile-Sim，一个面向LLM硬件-软件协同设计的以Tile为中心的GPU仿真框架。其关键见解在于，现代LLM内核性能更多地受控于控制执行顺序和重叠的依赖结构，而非单个指令延迟。因此，GTSim将内核执行表示为warp级别的Tile图，其节点捕获Tile级操作，边编码数据和顺序约束。利用这种表示，我们设计了自动Tile图前端和图驱动的仿真后端。我们针对代表性的GEMM、注意力以及端到端LLM推理工作负载评估了GTSim。在A100和H100上，针对传统和高度优化的内核，GTSim实现了高性能建模精度（MAPE，平均绝对百分比误差，1.22%–8.71%）。我们进一步将GTSim扩展到Blackwell并进行了初步验证，展示了其在分析软件和架构设计选择中的有效性。

## Abstract
Modern LLM (large language model) workloads increasingly rely on optimized GPU kernels through hardware-software co-design. These kernels achieve high-performance through fine-grained dependency scheduling and computation-memory overlap. As such, they incur new challenges on existing GPU performance models. Instruction-driven simulators are costly to adapt to evolving architectures, while analytical models are too coarse to capture kernels' characteristics. We propose GPU-Tile-Sim, a tile-centric GPU simulation framework for LLM hardware-software co-design. The key insight is that modern LLM kernel performance is governed less by individual instruction latency than by the dependency structure that controls execution order and overlap. Accordingly, GTSim represents kernel execution as a warp-level tile graph whose nodes capture tile-level operations and whose edges encode data and ordering constraints. Using this representation, we design an automatic tile-graph frontend and a graph-driven simulation backend. We evaluate GTSim on representative GEMM, attention, and end-to-end LLM inference workloads. On A100 and H100 across both conventional and highly optimized kernels, GTSim achieves high performance-modeling accuracy (MAPE, Mean Absolute Percentage Error, 1.22%--8.71%). We further extend GTSim to Blackwell with preliminary validation, and demonstrate its effectiveness in analyzing software and architectural design choices.

### 1. 核心问题与整体含义（研究动机和背景）

- **问题**：现有GPU性能模型在LLM工作负载的硬件-软件协同设计中面临根本性矛盾：指令驱动模拟器（如GPGPU-Sim、Accel-Sim）具有高保真度，但难以扩展至不断演进的架构（如Hopper、Blackwell）；分析模型（如TileFlow、LLMCompass）虽易于适应新架构，但过于粗粒度，无法捕捉现代GPU内核（如内核融合、异步流水线、warp specialization）中的细粒度依赖、重叠和协作。
- **动机**：LLM性能关键内核（GEMM、注意力等）的调度效率越来越取决于**tile级操作之间的依赖结构**（数据流、顺序约束），而非单条指令延时。因此，需要一种既能显式建模依赖结构、又能轻量扩展至新架构的模拟框架。

### 2. 提出的方法论：核心思想、关键技术细节

- **核心思想**：将GPU内核执行抽象为一个**warp级别的有向无环图（DAG）——tile图**。图中节点表示warp或warp组执行的tile级操作（如TMA加载、Tensor Core MMA、标量计算），边表示两种依赖：
    - **数据边**：生产者-消费者关系，定义数据流。
    - **顺序边**：非数据依赖的顺序约束（如同warp程序顺序、跨warp信号/等待、buffer复用约束）。
- **前端（自动tile图生成）**：从TileLang DSL的编译器IR出发，经过三步提取：
    1. 恢复执行上下文（warp角色、循环范围、同步范围）。
    2. 识别原始操作（TC指令、TMA、同步等），映射为节点。
    3. 推断节点描述符、数据边（SSA风格版本化）、顺序边（程序顺序+同步原语）。
    也可由用户手动构建图（粗粒度）。
- **后端（图驱动仿真）**：
    - **执行流**：threadblock调度器将TB绑定到SM，初始就绪节点进入子分区队列。节点状态：阻塞→就绪→发射→执行→完成。发射时释放顺序边，完成时释放数据边，更新后继依赖计数。只有所有传入边满足的节点才变为就绪。
    - **硬件建模**：吞吐导向模型，包括计算管线（Tensor Core、CUDA Core、SFU的延时/宽度）、内存管线（通过tile描述符导出事务，TMA作为批量传输）、SM簇NoC（DSMEM）和L2/DRAM延时-带宽模型。
    - **并发控制**：计算节点按管线吞吐分解为子操作，允许不同节点重叠。多warp操作（如wgmma）同步发射。
- **可扩展性**：新增硬件特性只需添加新节点类型、资源模型或边规则，无需修改指令解码、scoreboard等底层逻辑。

### 5. 实验数量与充分性

- **实验丰富**：涵盖多种内核类型（4种GEMM、3种注意力、端到端推理、动态路由），每种都有多个参数扫描点（GEMM 64种配置，注意力多种序列长度/批次/KV长度，Llama-3-8B下16种decode配置）。

- **公平性**：与两种主流分析模型（TileFlow、LLMCompass）在相同硬件和配置下对比，并尽可能调整其参数以适应H100。对于指令级模拟仅A100可用处做了对比。
- **充分性**：实验覆盖面广，既包含传统内核也包含高度优化内核（FlashAttention、FlashMLA），并扩展至Blackwell初步验证，结果一致表明GTSim精度优于对比方法。

### 6. 主要结论与发现

- **高精度**：GTSim在A100和H100上对所有测试工作负载的MAPE为1.22%–8.71%，且Pearson相关系数>0.995。端到端Llama-3-8B decode MAPE 7.06%–8.71%。
- **优于现有模型**：对比TileFlow和LLMCompass，GTSim在所有任务上MAPE更低（后者常超过100%），尤其在融合和异步流水线内核上表现显著提升。
- **软件流水线分析**：不同流水线设计（naive 2-stage, WS cooperative, WS ping-pong, WS 3-stage）的性能表现依赖内存/计算边界，GTSim准确捕捉其开销和重叠收益。
- **NoC融合**：使用片上NoC取代DRAM可平均加速1.65×；拓扑感知映射可减少NoC停留时间1.47×。
- **Blackwell扩展**：只需修改11.3%的模拟器核心即可支持B200；成功解释FA4相对于FA3的优势（更多wave数、更大tile、更深的解耦）。

### 7. 优点

- **抽象级别恰到好处**：warp级tile图既比指令模型简单、易于扩展，又比粗粒度映射模型更细，能显式表示warp专业化、异步流水线和依赖结构。
- **自动化程度高**：前端可从TileLang DSL自动生成图，用户也可手动构建；后端图驱动仿真无需处理指令流。
- **轻量且准确**：吞吐导向硬件模型+依赖驱动调度，在保持A100/H100 MAPE<9%的同时，仿真速度比Accel-Sim快约4倍。
- **可扩展性验证**：成功扩展到Blackwell（修改少、重用大部分组件），并初步验证FA4的准确性。
- **分析能力**：支持软硬协同设计探索（流水线、NoC拓扑、块放置）。

### 8. 不足与局限

- **前端依赖**：自动提取仅支持TileLang DSL，对于原生CUDA或Triton需额外工作（文中提到可通过CuBridge或TLX等进一步集成，但未完整实现）。
- **硬件模型简化**：L2缓存模型仅为全关联LRU，可能不够精确；TMA模型参数来自微基准但未涵盖所有情况；NoC模型为简化拓扑，未模拟复杂路由协议。
- **Blackwell验证有限**：仅与已发表的FA4数据对比，未在真实B200硬件上测量，精度需进一步确认。
- **多GPU扩展缺失**：仅支持单GPU内核仿真，未建模跨GPU网络通信。
- **状态跟踪粒度**：虽分解为子操作，但子操作间并发受管线宽度限制，可能无法完美再现真实硬件中复杂调度器的动态行为。
