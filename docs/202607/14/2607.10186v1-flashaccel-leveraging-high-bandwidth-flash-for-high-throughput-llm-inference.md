## 摘要
大语言模型（LLM）推理日益受到GPU中高带宽内存（HBM）容量的限制，因为模型权重和KV缓存快速增长。高带宽闪存（HBF）提供比HBM更高的容量，同时保持相当的带宽，使其成为容量受限的LLM推理的有前途的基板。然而，其固有的高访问延迟、低带宽利用率以及缺乏对异构资源管理的支持，使得将HBF集成到GPU中进行LLM推理变得困难。我们提出FlashAccel，一种协同设计的系统，利用HBF实现高效的LLM推理。FlashAccel将HBF集成到基于HBM的GPU中，提供架构支持以减轻访问延迟。它通过针对模型权重和KV缓存的专用数据布局提高带宽利用率，并引入HBF感知的存储管理层以及编程模型，以组织HBF中的持久数据并在系统级别协调异构内存资源。实验结果表明，将六个HBF堆栈集成到GPU中，使得FlashAccel在100ms延迟约束下，每GPU吞吐量和能效分别比纯HBM GPU平均提高2.54倍和1.93倍。

## Abstract
Large language model (LLM) inference is increasingly limited by the capacity of High-Bandwidth Memory (HBM) in GPUs, as model weights and KV cache grow rapidly. High-Bandwidth Flash (HBF) provides higher capacity than HBM while retaining comparable bandwidth, making it a promising substrate for capacity-constrained LLM inference. However, its inherently high access latency, low bandwidth utilization, and lack of support for heterogeneous resource management make it difficult to integrate HBF into GPUs for LLM inference. We present FlashAccel, a co-designed system that enables efficient LLM inference using HBF. FlashAccel integrates HBF into HBM-based GPUs, providing architectural support to mitigate access latency. It improves bandwidth utilization through specialized data layouts for both model weights and KV cache, and introduces an HBF-aware storage management layer together with a programming model to organize persistent data in HBF and coordinate heterogeneous memory resources at the system level. Experimental results demonstrate that integrating six HBF stacks into the GPU enables FlashAccel to deliver an average improvement of 2.54$\times$ and 1.93$\times$ in throughput per GPU and energy efficiency over the HBM-only GPU under 100ms latency constraint, respectively.

## 1. 核心问题与整体含义（研究动机和背景）

- **背景**：大语言模型（LLM）的推理过程严重受限于 GPU 高带宽内存（HBM）的容量。模型参数规模持续增长，KV 缓存因长上下文和多轮交互而急剧膨胀。
- **矛盾**：HBM 容量增长远慢于模型参数与 KV 缓存的增长，导致批处理大小受限、KV 缓存命中率低、需要多 GPU 部署从而增加系统复杂度和通信开销。
- **HBF 的潜力**：高带宽闪存（HBF）提供与 HBM 相当的带宽，但容量高出约 8 倍，有望突破容量瓶颈。
- **HBF 的挑战**：
  - 高访问延迟（~4 μs vs. HBM ~100 ns），直接拉长端到端延迟；
  - 低带宽利用率：需要极高并行度（数千个平面）才能达到峰值带宽，但权重张量通常小于超页（hyper page）尺寸，且 KV 缓存在运行时可变的请求集合下导致平面负载不均衡；
  - 缺乏异构资源管理：现有存储栈（如 FTL）开销大，HBF 应作为可直接访问的 GPU 内存，而非经过 HBM 的间接层。

## 2. 方法论：核心思想、关键技术细节、算法流程

- **核心思想**：通过硬件-软件协同设计，将 HBF 集成到 GPU 中，利用 SRAM 预取隐藏延迟、优化数据布局提升带宽利用率、提供 HBF 感知的存储管理层和编程模型来协调异构内存资源。

- **硬件设计**：
  - **集成方式**：共位集成（CLI）或级联集成（CSI）。CSI 保留更多 HBM 堆栈，CLI 用 HBF 替换部分 HBM。
  - **HBF 堆栈**：每堆栈含 8 个闪存芯片、96 平面/芯片、SLC 类型，每平面集成 32KB SRAM 缓存，基底芯片也有 8MB SRAM，用于预取流水线。
  - **预取机制**：通过 `SramPrefetch` 接口，在计算核函数启动前将 HBF 数据读入 SRAM，并与计算重叠执行，使用双缓冲。

- **数据布局设计**：
  - **权重**：按推理图中的执行顺序将每个算子的权重切分为页面大小，以轮转方式跨所有平面和通道放置，使整个权重集全局平衡，提升带宽利用率。
  - **KV 缓存**：
    - 将每个请求的 KV 缓存组织为持久对象，构建“组对象”抽象以支持批量读写。
    - **写入策略**：尽可能将非驻留 KV 块聚合成完整超页写入 HBF；剩余小块随机放置以避免热点。
    - **再平衡**：通过 `GroupArrange` 接口将过载平面的 KV 块卸载到 HBM，使每步解码时平面负载平衡。
    - **加载策略**：以超页粒度从 HBF 读取 KV 块，利用 FlashAttention 进行部分注意力计算，最后按请求规约。
    - **缓存写回**：新生成的 KV 块暂存于 HBM，待累积满一超页后再写入 HBF。
    - **KV 块大小**：选取 256KB，在平面平衡与 HBM 压力之间折衷。

- **系统软件设计**：
  - **HBF 感知存储管理层**：消除传统 FTL（闪存转换层），利用模型权重和 KV 缓存的仅追加写入模式，直接记录物理地址到对象元数据中，实现轻量级持久化。
  - **编程模型**：
    - `NandMmap`：将 HBF 中的权重对象映射到虚拟地址空间，页表指向 HBF 物理地址。
    - `GroupMmap`、`GroupWrite`、`GroupArrange`：分别用于 KV 缓存分组映射、追加写入和平面卸载。
    - `SramPrefetch`/`SramRelease`：将 HBF 数据预取到 SRAM，并支持异步执行与计算重叠。
  - **调度**：运行时维护预取队列，按计算图拓扑顺序异步提前发起预取，计算核函数访问时若预取未完成则仍可访问 HBF 原始地址。

## 6. 主要结论与发现

- **吞吐量提升**：8×CSI 在所有模型和 SLO 下平均提升 2.15×（100ms SLO 时可达 2.54×），主要得益于 HBF 大容量支持更大 batch size。
- **能效提升**：8×CSI 比 8×H200 能效平均提升 1.93×，8×CLI 提升 1.66×。尽管 HBF 读能耗较高（8 pJ/bit vs. HBM 2.99 pJ/bit），但高吞吐量弥补了功耗增加。
- **KV 缓存命中率**：8×CSI 和 8×CLI 可存储所有会话的 KV 缓存，达到理想命中率（~100%），而 8×H200 仅约 50%，需计算 token 减少 89%。
- **消融结论**：预取对性能影响最大（关闭后吞吐下降 55%），KV 缓存布局次之（下降 15%），权重布局影响最小（下降 7%）。三者共同作用才能使 HBF 接近 HBM 延迟（差距~4%）。
- **可扩展性**：8×HBF 系统每 GPU 吞吐优于 16×HBM 系统，因为 HBF 容量减少了 GPU 数量和跨节点通信（RDMA）瓶颈。

## 7. 优点

- **硬件-软件协同设计**：将 HBF 的物理特性（平面并行度、高延迟）与 LLM 推理的访问模式（权重只读、KV 缓存仅追加）紧密结合，针对性地优化数据布局和预取，而非简单替换 HBM。
- **创新的数据布局**：权重按执行顺序轮转放置、KV 缓存以超页粒度聚合并动态再平衡，有效解决了 HBF 带宽利用率的根本问题。
- **系统抽象简洁**：消除 FTL 层，利用仅追加写入模式直接管理物理地址；编程模型（NandMmap/GroupMmap 等）提供统一虚拟地址空间，简化异构内存使用。
- **全面的实验评估**：涵盖多种现代 LLM、两种典型工作负载、严格延迟 SLO、多 GPU 规模，并进行了详细的消融分析，结论可信度高。
- **实际可行性分析**：讨论并解决了 KV 缓存写入 HBF 的耐久性担忧，利用新注意力机制（MLA/GQA）降低写量，表明 SLC HBF 可满足 5 年部署的写入需求。
