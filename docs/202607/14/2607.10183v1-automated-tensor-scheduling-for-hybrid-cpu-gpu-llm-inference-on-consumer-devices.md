## 摘要
在笔记本电脑和台式机等消费设备上运行大型语言模型具有挑战性，因为模型权重通常超过GPU内存容量，因此需要借助CPU内存进行卸载推理以扩展有效模型容量。然而，现有的卸载系统通常依赖于粗粒度的层级或专家级调度，忽略了同一层内张量之间的显著异质性，并且难以适应此类设备上不断变化的硬件负载条件。本文提出了ATSInfer，一种用于消费设备的混合CPU-GPU推理系统，它在张量粒度上执行卸载。ATSInfer结合了静态张量放置与负载感知的动态传输，并引入了异步CPU-GPU协调，以在异构后端上高效调度硬件存储、数据移动和计算。我们实现了ATSInfer，并在代表性的消费平台上使用密集模型和MoE模型进行了评估。与现有系统相比，ATSInfer将预填充吞吐量提高了最多1.94倍，解码吞吐量提高了最多3.29倍，同时提高了GPU利用率并更有效地利用了PCIe带宽。这些结果表明，ATSInfer能够显著改善个人消费设备上本地大语言模型部署的用户体验。

## Abstract
Running large language models on consumer devices such as laptops and desktops is challenging because model weights often exceed GPU memory capacity, making offloading inference necessary to extend effective model capacity with CPU memory. Existing offloading systems, however, typically rely on coarse layer-level or expert-level scheduling, which overlooks substantial heterogeneity among tensors within the same layer and adapts poorly to changing hardware load conditions on such devices. This paper presents ATSInfer, a hybrid CPU-GPU inference system for consumer devices that performs offloading at tensor granularity. ATSInfer combines static tensor placement with load-aware dynamic transfer, and introduces asynchronous CPU-GPU coordination to efficiently schedule hardware storage, data movement, and computation across heterogeneous backends. We implement ATSInfer and evaluate it on representative consumer platforms using both dense and MoE models. Compared with existing systems, ATSInfer improves prefill throughput by up to 1.94$\times$ and decode throughput by up to 3.29$\times$, while also increasing GPU utilization and making more effective use of PCIe bandwidth. These results show that ATSInfer can substantially improve the user experience of local LLM deployment on personal consumer devices.

## 1. 核心问题与整体含义（研究动机和背景）

- **问题**：在消费级设备（笔记本、台式机）上本地部署大语言模型（LLM）时，模型权重常超过GPU显存容量，必须将部分模型卸载到CPU内存。现有卸载系统多采用**粗粒度**的层级或专家级调度，忽略了同一层内不同张量在执行效率上的显著异质性，且调度策略通常是**静态的**或仅依赖输入信号（如序列长度、专家激活），无法适应消费设备上动态变化的硬件负载（如后台任务干扰、热降频）。
- **整体含义**：粗粒度卸载和负载无感知调度导致CPU成为新瓶颈，GPU利用率低，端到端延迟不稳定。本文提出**张量粒度**的混合推理系统ATSInfer，通过静态放置与负载感知动态传输相结合，显著提升本地LLM推理的吞吐和响应速度，使消费设备上的本地部署更实用。

## 2. 方法论：核心思想、关键技术细节

### 核心思想
- **张量粒度卸载**：将每个权重张量作为调度单元，而非整个层或专家。
- **静态放置 + 动态传输两阶段决策**：离线根据性能度量确定哪些张量常驻GPU；在线根据实时负载动态选择部分CPU驻留张量临时提升到GPU并重叠传输与计算。
- **异步CPU-GPU协调**：通过精心设计的内存布局、双CUDA流（计算流与传输流）以及复制引擎/零拷贝内核分工，最大化数据移动与计算的重叠。

### 关键技术细节

#### (1) 内存布局（图7）
- **GPU驻留区**：静态放置选中的张量，常驻GPU。
- **CPU固定内存存储**：其余张量保存在映射、锁定的主机内存，支持高效异步传输。
- **GPU临时缓冲区**：用于存放动态提升的张量，按生命周期复用，减少显存占用。

#### (2) 异步CPU-GPU调度（图8）
- 使用两个CUDA流：计算流执行算子及必要的激活传输；传输流处理动态权重的异步移动。
- 激活传输（小数据量）由GPU SM上的零拷贝内核执行；权重传输（大数据量）由专用复制引擎处理，避免阻塞。
- 通过轻量级GPU事件进行跨流同步，避免全局同步。

#### (3) 静态张量放置（算法1）
- **经验性能密度**：定义 `k_b_i = t_b_i / s_i`，其中 `t_b_i` 为张量 `i` 在后端 `b` 上的实测执行时间，`s_i` 为内存占用。该指标综合反映每单位内存的延迟收益。
- **优化目标**：最大化GPU驻留带来的延迟减少总和减去后端切换成本，约束为GPU内存预算M。
- **求解**：对稠密模型直接用动态规划（O(nM)）；对MoE模型先分割专家/非专家张量，再分别求解，保持多项式复杂度。

#### (4) 负载感知动态传输（算法2）
- 问题建模：给定静态放置结果，决定每个CPU驻留张量是否在当前轮次提升到GPU。目标是最小化端到端延迟，考虑重叠收益。
- 定义重叠窗口 `seg(j,i)` 为从上一次CPU端点j到张量i之间的默认计算+激活传输时间；暴露传输时间 `delta_i = max(0, w_i - seg(j,i))`，其中 `w_i` 为权重传输时间。
- 动态规划算法：O(n²) 时间，枚举每个CPU驻留张量可能的提升起点，找到最优提升集合。
- **负载重调度（算法3）**：当实测性能与上次调度偏差超过阈值（15%）且距上次重调度时间足够（≥5倍TPOT），才触发重新调度，避免频繁重构。
