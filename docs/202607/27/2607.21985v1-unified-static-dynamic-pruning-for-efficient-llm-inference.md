## 摘要
大语言模型（LLM）的日益部署加剧了自回归解码中的计算和内存瓶颈，其中低计算强度和带宽受限的内核主导推理成本。权重剪枝提供了一种有前景的解决途径，但现有方法仍局限于静态剪枝（SP）或动态剪枝（DP）：前者永久移除冗余权重但缺乏自适应性，后者适应输入稀疏性但引入运行时不规则性。本文提出SPDP，一种统一的稀疏推理框架，将非结构化SP与输入自适应DP相结合，用于GPU上高效的LLM推理。SPDP协同设计了一种新的分块列向位图压缩（Tiled-CBC）格式和两个互补的GPU内核：（1）基于CUDA核心的spMspV内核，采用混合激活感知动态共享内存位图解压（HAD-SMBD），实现细粒度的运行时激活跳过；（2）针对预填充计算优化的张量核心SpMM内核。这种联合格式-内核设计协调了静态和动态稀疏性，在LLM推理的两个阶段都保持了带宽高效的内存访问和高计算强度。在推理优化GPU上的全面评估表明，SPDP相比最新稀疏框架（如SpInfer）实现了1.24倍至1.37倍的平均加速（最高2.51倍），同时在稀疏度提高高达25%的情况下保持了相同的困惑度。SPDP推进了推理效率-质量帕累托前沿，表明统一静态-动态剪枝可以在大规模LLM服务中带来显著的吞吐量和每瓦性能提升。

## Abstract
The increasing deployment of large language models (LLMs) has magnified the computational and memory bottlenecks of autoregressive decoding, where low compute intensity and bandwidth-bound kernels dominate inference cost. Weight pruning offers a promising remedy,   but existing methods remain confined to either static pruning (SP), which permanently removes redundant weights but lacks adaptivity, or dynamic pruning (DP), which adapts to input sparsity but introduces runtime irregularity. This paper presents SPDP, a unified   sparse-inference framework that integrates unstructured SP with input-adaptive DP for efficient LLM inference on GPUs. SPDP co-designs a new Tiled-Column-wise Bitmap Compressed (Tiled-CBC) format and two complementary GPU kernels: (1) a CUDA-core spMspV kernel   featuring Hybrid Activation-aware Dynamic Shared-Memory Bitmap Decoding (HAD-SMBD) for fine-grained, runtime activation skipping, and (2) a Tensor-Core SpMM kernel optimized for prefill computation. This joint format-kernel design harmonizes static and dynamic   sparsity, maintaining bandwidth-efficient memory access and high compute intensity under both phases of LLM inference. Comprehensive evaluations on inference-optimized GPUs demonstrate that SPDP achieves 1.24x-1.37x average speedup (up to 2.51x) over state-of-the-   art sparse frameworks such as SpInfer, while matching. perplexity with up to 25% higher sparsity. SPDP advances the inference efficiency-quality Pareto frontier, showing that unified static-dynamic pruning can deliver substantial throughput and performance-per-watt   improvements in large-scale LLM serving

## 1. 核心问题与研究动机

- **问题背景**：大语言模型（LLM）推理面临严重计算和内存瓶颈，尤其是自回归解码阶段，该阶段内核具有低计算强度且受内存带宽限制，导致推理成本高昂。随着测试时缩放（test-time scaling）和智能体AI系统的兴起，每会话生成的token数量激增，解码阶段的内存带宽和延迟成为关键瓶颈。
- **现有方法的局限**：
  - **静态剪枝（SP）**：离线移除冗余权重，减少内存占用和带宽需求，但缺乏对输入的适应性，可能移除关键参数。
  - **动态剪枝（DP）**：根据输入自适应跳过不重要激活，实现上下文感知的稀疏性，但通常采用结构化粒度，缺乏灵活性，且计算时仍需加载稠密权重，内存节省有限。
- **核心挑战**：静态和动态剪枝虽然理论上互补（SP作用于权重维度，DP作用于激活维度），但现有系统级不兼容：SP内核是行主序且针对SpMM优化，DP造成列方向稀疏性，导致spMspV问题；Tensor Core无法高效处理每token激活稀疏性；不同阶段需要统一格式。

## 2. 方法论：核心思想与技术细节

### 2.1 核心思想
- **SPDP框架**：首次统一非结构化静态剪枝与输入自适应动态剪枝，通过联合格式-内核协同设计，实现端到端加速。
- **关键洞察**：SP与DP的稀疏模式正交，综合稀疏度接近乘积，理论上能显著提升计算强度和吞吐量。

### 2.2 关键技术细节

#### (1) Tiled-CBC格式（分块列向位图压缩格式）
- **设计目标**：使静态压缩权重在列粒度直接可寻址，支持运行时DP跳过非活动列，同时保留分块表示以兼容GPU执行。
- **结构**：
  - 权重矩阵层次划分为GTiles（每格覆盖 `TILE_M × TILE_K` 元素）。
  - 每列作为一个微块（`TILE_M × 1`），用四个uint64位图编码非零位置。
  - 存储五个数组：`TileOffset`（GTile索引）、`Values`（非零值）、`Bitmap`（位图）、`ColInfo`（包含列偏移和列非零数）、可选对齐元数据。
  - `ColInfo`：两个16位字段分别存储 `TileOffset_Col` 和 `NNZ_Column`，用于低开销跳过非活动列。
- **内存开销公式**：`4B*(NGT+1) + 4B*(NGT*TILE_K) + 8B*N_BM + 2B*NNZ`（详见论文公式）。

#### (2) 解码阶段：SPDP-spMspV内核（基于CUDA核心）
- **核心方法**：采用HAD-SMBD（混合激活感知动态共享内存位图解压），是SpInfer的SMBD扩展，支持动态激活掩码。
- **执行流程**（每个线程块5步）：
  1. **ColInfo加载**：协同加载列元数据到共享内存。
  2. **XTile加载**：加载输入激活向量小块。
  3. **GTile加载**：使用ColInfo和激活信息选择性提取相关列（实现DP）。
  4. **WTile解压**：HAD-SMBD列主序解压，两阶段：相位I计算前缀秩并加载非零元素，相位II复用基址、轻量调整解析配对元素。
  5. **CUDA核心GEMV**：解压后与激活向量执行矩阵-向量乘法。
- **异步流水线设计**：
  - 采用三独立异步拷贝组：ColInfo预取、XTile加载、GTile加载。
  - 双重缓冲GTile和XTile，元数据预取实现“元数据先于数据”的预取流水线，最大化计算-内存重叠。
- **实现优化**：使用`cp.async`（LDGSTS.128）高效全局到共享内存传输；`TILE_M=256, TILE_K=16`；基于TEAL的幅度阈值DP。

#### (3) 预填充阶段：SPDP-SpMM内核（基于Tensor Core）
- **核心方法**：复用Tiled-CBC格式，增加布局对齐阶段，将列主序解码后的权重块转换为行主序以适应Tensor Core。
- **布局对齐**：在共享内存内通过填充方案避免bank冲突，使用`ldmatrix.x4`加载。
- **异步流水线**：类似spMspV，但移除DP阶段，增加XTile加载到寄存器、布局对齐等阶段。预填充阶段输出宽度大，计算强度高，因此可充分利用Tensor Core。

## 6. 主要结论与发现

1. **性能提升显著**：SPDP在A10G上相比cuBLAS平均加速1.88×（最大3.32×），相比SpInfer平均加速1.24×（最大1.70×）。在L4上分别为2.11×和1.37×。
2. **质量保持更好**：在相同困惑度下，SPDP可实现比SpInfer高出高达25%的总稀疏度，说明DP补偿了SP的质量损失。
3. **硬件利用率更高**：SPDP-spMspV内核达到更高SM占用率（66% vs 48-38%）、更低bank冲突（74 vs 3817-4491），同时维持相似内存带宽。
4. **预填充兼容**：SPDP-SpMM内核在预填充阶段虽不一定超越密集cuBLAS，但统一格式避免了额外存储开销。
5. **量化兼容**：结合4-bit量化后困惑度趋势稳定，可叠加压缩增益。
6. **帕累托前沿推进**：统一静态-动态剪枝实现了更好的速度-质量权衡。

## 7. 优点

- **理论分析扎实**：通过roofline模型量化联合稀疏性对计算强度的提升，并通过实验验证SP和DP重叠稀疏度接近乘积，证实互补性。
- **系统设计巧妙**：Tiled-CBC格式巧妙对齐列主序和激活稀疏性，支持运行时选择性加载；HAD-SMBD解码高效融合DP跳过。
- **全栈协同设计**：从布局、调度到执行端到端考虑，覆盖解码和预填充两个阶段，统一格式避免转换开销。
- **实验全面**：覆盖多个GPU架构、多种LLM模型尺寸、多种任务类型、多种稀疏度范围，并包含详细的硬件剖析。
- **代码开源**：提供GitHub仓库，促进可复现性。

## 8. 不足与局限

- **模型规模有限**：主要评估在7B模型上（Llama-2-7B），未在更大规模（如70B、175B）上验证。虽然内核测试使用了多种矩阵形状，但端到端结果缺乏更大模型验证。
- **预填充加速有限**：在预填充阶段，SPDP未能超越密集cuBLAS，因此主要收益来自解码。在预填充-解码分离部署中可能需额外处理。
- **批量处理支持不足**：当前DP机制基于每token独立阈值，未支持批量DP（batch wise dynamic pruning），也未探索连续批处理场景下的适用性。
- **非LLM场景不通用**：在极稀疏的SuiteSparse矩阵上性能不敌cuSPARSE，说明SPDP专为中等稀疏度的LLM解码优化，非通用稀疏线性代数库。

- **动态剪枝依赖离线校准**：TEAL需要离线构建ECDF，虽然运行时无开销，但无法实时适应分布漂移。
- **实验细节缺失**：未说明内存带宽利用率具体值、未报告每个实验的方差或置信区间、未进行统计分析。
