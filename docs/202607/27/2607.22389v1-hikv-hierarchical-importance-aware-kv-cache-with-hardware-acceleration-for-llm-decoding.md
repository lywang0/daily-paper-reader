## 摘要
随着长上下文大语言模型（LLM）的快速普及，解码过程中不断增长的KV缓存已成为关键的内存瓶颈。为解决这一挑战，我们提出HiKV，一种通过层级重要性感知利用KV缓存冗余的算法-硬件协同设计方案。算法层面，HiKV在两个粒度上压缩KV缓存：第一阶段在固定预算内驱逐不重要令牌，第二阶段进一步仅加载每个保留令牌中的重要元素，达到单一粒度无法实现的压缩比。架构层面，我们开发了一种专用加速器，其核心是可重构重要性排序器，可在各阶段所需的差异化排序数据路径之间切换，以最小开销将两阶段加速统一在一个电路中。在代表性LLM上的评估显示，与普通KV缓存基线相比，HiKV在注意力计算中实现了高达7.95倍的加速和90%的能耗降低，且精度损失可忽略不计（1%）。在等精度约束下，HiKV比最先进的基于重要性的方法额外减少了1.82~4.87倍的外部内存访问。这些优势得益于专用硬件组件，系统面积仅增加8%。

## Abstract
With the rapid adoption of long-context large language models (LLMs), the continuously growing KV cache during decoding has become the critical memory bottleneck. To tackle this challenge, we propose HiKV, a novel algorithm-hardware co-design that exploits KV cache redundancy through hierarchical importance awareness. Algorithmically, HiKV compresses the KV cache at two granularities: Stage I evicts unimportant tokens within a fixed budget, and Stage II further loads only the significant elements of each retained token, reaching compression ratios unattainable at a single granularity. Architecturally, we develop a dedicated accelerator centered on a reconfigurable importance sorter that switches between the distinct sorting datapaths each stage requires, unifying the two-stage acceleration in one circuit with minimal overhead. Evaluated on representative LLMs, HiKV achieves up to 7.95x speedup and 90% energy reduction in the attention computation over the vanilla KV cache baseline within negligible 1% accuracy loss. Under iso-accuracy constraints, HiKV outperforms state-of-the-art importance-based methods by achieving an additional 1.82~4.87x reduction in external memory accesses. These benefits are enabled by specialized hardware components that add only 8% to the system area.

-   **核心问题**：如何在不显著牺牲模型精度（≤1%）的前提下，大幅减少KV缓存占用的内存空间和访问流量？

#### 2. 论文提出的方法论

-   **核心思想**：KV缓存的冗余存在于两个层面：**token层面**（不重要的token）和**元素层面**（重要token中的不重要的向量元素）。HiKV通过一个两阶段的重要性压缩算法，系统地消除这两个层面的冗余。

-   **关键技术细节**：
    1.  **第一阶段 (Stage I)：粗粒度 Token 级管理**
        -   **目标**：在固定预算内保留最重要的token，减少需要加载的token数量。
        -   **双桶结构**：将KV缓存预算分为“近期Token桶 (R)”和“重要Token桶 (I)”。
        -   **局部累积策略**：重要性分数（IS）通过对近期桶内token在解码过程中的注意力权重进行累积来计算，避免了全局排序的高昂开销。
        -   **维护机制**：使用最小堆（min-heap）数据结构管理重要Token桶，每次只需O(log N)的复杂度即可完成Token的淘汰或提升（promotion），显著降低了排序开销。

    2.  **第二阶段 (Stage II)：细粒度 元素级管理**
        -   **目标**：对于已保留的每个token，只加载其最显著的元素，减少每次加载的数据量。
        -   **不对称读写**：解码时，Query (Q) 和P (softmax后的权重) 向量很小，而K和V缓存矩阵很大。因此，通过在Q和P上进行元素级选择，来指导从内存中加载K和V的对应元素。
        -   **查询向量（Q）**：由于Q的维度（head dimension, dh）很小（通常64或128），直接进行全局排序，选择top-BII个元素。
        -   **权重向量（P）**：P的长度可能很大（数千），全局排序开销大。因此采用**分块排序**策略，将P划分为多个大小为dh的块，在每个块内独立进行top-BII元素选择。实验证明，此近似策略的召回率可达95%以上。

-   **算法流程**：
    1.  **QK^T阶段**：利用第一阶段选出的Token集合和第二阶段对Q选出的元素索引，只加载K缓存的对应部分进行计算。
    2.  **重要性维护**：计算得到P向量后，更新近期桶内Token的IS，并利用堆决定是否将旧Token提升到重要桶或淘汰。
    3.  **PV阶段**：利用第二阶段对P向量进行分块排序，选出重要的元素索引，只加载V缓存的对应部分进行计算。

-   **硬件架构**：核心是**可重构重要性排序器（RIS）**，它基于统一的2输入双调排序器构建，通过配置不同的控制信号，支持四种操作模式，无缝切换服务两个阶段。
    -   **第一阶段**：支持最小堆的 `HEAPIFY_UP`（建堆）和 `HEAPIFY_DOWN`（维护）操作，通过向量化并行比较加速。
    -   **第二阶段**：支持 `GLOBAL_SORT`（用于全局排序Q）和 `CHUNK_SORT`（用于分块排序P）操作，通过多轮并行排序和合并实现。一旦确认某个区间不在top-k范围内，即可提前终止排序，降低动态功耗。
