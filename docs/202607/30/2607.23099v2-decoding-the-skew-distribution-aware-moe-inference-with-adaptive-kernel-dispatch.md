## 摘要
混合专家模型（MoE）推理由稀疏专家GEMM组成，其形状随运行时路由分布而变化。现有服务系统通常使用静态令牌计数桶来选择融合MoE内核，忽略了决定瓦片填充、内存重用和内核效率的每专家路由分布。我们引入了一个分布感知框架，用于建模和基准测试MoE推理。该框架将紧凑的有效专家指标与基于狄利克雷的反向建模程序相结合，生成可控的路由分布，以进行系统的硬件研究。利用该框架，我们展示了最佳融合MoE内核随路由偏斜和令牌数量而变化。我们进一步提出了DA-MoE，一种在NVIDIA GPU上运行的GPU驻留内核调度运行时，它将实时路由直方图与离线调优分布匹配，并在无需CPU-GPU同步的情况下选择接近最优的融合MoE内核。在HumanEval-X服务轨迹上，DA-MoE将DeepSeek-V3的几何平均融合MoE延迟提升了1.16倍，Kimi K2提升了1.29倍，峰值加速分别达到1.40倍和1.56倍。

## Abstract
Mixture-of-Experts (MoE) inference consists of sparse expert GEMMs whose shapes vary with the runtime routing distribution. Existing serving systems typically select fused-MoE kernels using static token-count buckets, ignoring the per-expert routing distribution that determines tile padding, memory reuse, and kernel efficiency. We introduce a distribution-aware framework for modeling and benchmarking MoE inference. The framework combines the compact Effective Experts metric with a Dirichlet-based reverse-modeling procedure that generates controllable routing distributions for systematic hardware studies. Using it, we show that the best fused-MoE kernel changes with routing skew and token count. We further present DA-MoE, a GPU-resident kernel-dispatch runtime for NVIDIA GPUs that matches the live routing histogram to offline-tuned distributions and selects a near-optimal fused-MoE kernel without CPU--GPU synchronization. On HumanEval-X serving traces, DA-MoE improves geomean fused-MoE latency by 1.16X on DeepSeek-V3 and 1.29X on Kimi K2, with peak speedups of 1.40X and 1.56X.

## 1. 论文的核心问题与整体含义

- **研究动机**：混合专家模型（MoE）是当前主流的大语言模型架构，通过稀疏激活降低计算成本。然而，MoE推理中的关键瓶颈在于每个专家接收的令牌数量（路由分布）高度动态且偏斜（skew），这导致专家GEMM的形状（特别是令牌维度N）不断变化。
- **现有问题**：现有MoE服务系统（如TensorRT-LLM、FlashInfer、vLLM）使用**静态令牌计数桶**（如按batch size 32、64、128等）来选择融合MoE内核，忽略了每专家的路由分布。路由分布直接决定**tile padding**（填充零带来的浪费）、**内存重用效率**和**内核性能**。因此，静态策略在分布偏斜时表现不佳。
- **整体含义**：本文首次系统性地揭示：**最优的融合MoE内核（包括tile形状、软件流水线深度、内存加载路径）随路由偏斜和令牌数量动态变化**，静态选择无法覆盖所有场景。需要一种**分布感知**的运行时调度方法。

## 2. 方法论：核心思想、关键技术细节

### 核心思想
- 提出**“有效专家数”（Effective Experts, `eff_exp`）**指标，量化路由分布的集中程度。`eff_exp`取值范围[1, E]，均匀分布时等于E，所有令牌流向单一专家时等于1。
- 基于**狄利克雷分布（Dirichlet distribution）**的**反向建模**方法：给定目标`eff_exp`值，通过二分搜索确定Dirichlet分布的浓度参数α，从而生成与真实路由分布类似的合成分布。该方法称为`ddist:X`（X为偏斜乘数）。
- 离线阶段：针对每个令牌计数桶，用合成的路由分布（覆盖不同偏斜水平）对TRTLLM的所有融合MoE内核变体进行基准测试，记录每个分布对应的最优内核ID，构建**分布-内核映射表**。
- 在线阶段：每次MoE层调用时，**在GPU上**构建实时路由直方图，排序并L2归一化后，与离线映射表中的exemplar向量做余弦相似度匹配，选出最匹配的内核ID，通过**条件CUDA Graphs**直接启动，**无需CPU-GPU同步**。

### 关键技术细节
- **Effective Experts公式**：`eff_exp = (Σ t_i)^2 / Σ t_i^2`，其中`t_i`是分配给专家`i`的令牌数。
- **Dirichlet反向建模算法**（Algorithm 1）：给定目标`eff_exp*`，在[α_min, α_max]内二分搜索，每次从Dir(α_mid)抽取S个样本，计算平均`eff_exp`，调整搜索区间，直到收敛。
- **离线自动调优**：对每个令牌计数桶（32,64,128,256,512），生成7种不同偏斜水平的合成分布（α = 1.1,1.3,1.5,1.7,2.0,2.5,4.0），每种分布下用S=10个样本，对所有可用TRTLLM融合MoE内核进行基准测试，选择最快的那个内核。
- **在线调度**：
    - 构建每专家令牌直方图 → 降序排序 → L2归一化得到查询向量。
    - 与当前令牌计数桶的exemplar表做余弦相似度（点积），选出最相似的exemplar对应的内核ID。
    - 通过条件CUDA Graphs（`cudaGraphConditional`节点）在GPU上启动该内核，无需CPU介入。
- **条件CUDA Graphs**：CUDA 12.8引入的功能，允许在GPU内部做数据依赖的分支，避免CPU同步。DA-MoE用此实现完整的GPU驻留选择-启动流程。

1. **观测1**：MoE路由偏斜随层和令牌计数变化，同一模型内`eff_exp`变化超过2倍，静态策略无法适配所有层。
