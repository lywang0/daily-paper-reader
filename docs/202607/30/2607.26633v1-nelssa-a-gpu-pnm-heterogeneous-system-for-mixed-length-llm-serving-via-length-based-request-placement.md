## 摘要
现代大语言模型及其代理应用正在拓宽服务工作负载的范围，涵盖从数百个令牌到数十万个令牌的上下文长度。由于这些请求经常在同一服务窗口内交错，LLM服务系统必须高度异构地处理混合长度工作负载。这种混合长度工作负载暴露了以GPU为中心的服务架构的根本性低效问题，其吞吐量依赖于受内存约束的大批量处理。在本文中，我们提出了NELSSA，一种将GPU与真实世界的近内存处理（PNM）加速器设备集成的LLM服务系统，以高效支持混合长度工作负载。NELSSA采用基于长度的请求放置，将短上下文请求路由到GPU，长上下文请求路由到PNM层，并集成运行时迁移以适应动态上下文增长而无需重新计算。我们将NELSSA原型化为端到端系统，在PNM上实现设备级稀疏注意力、GPU解码内核，以及主机端运行时，该运行时通过支持RPC和RDMA的CXL基础设施协调调度和跨层内存移动。在混合长度LLM工作负载中，与纯GPU基线相比，NELSSA将解码吞吐量提升高达5.5倍（令牌/秒），并将P99延迟降低高达15倍。我们的端到端原型和实验结果表明，基于CXL解聚的集成GPU-PNM服务，是支持不断演进工作负载的可扩展且灵活的LLM基础设施的一种有前途的系统范式。

## Abstract
Modern LLMs and their agentic applications are broadening the range of serving workloads, spanning context lengths from a few hundred tokens to hundreds of thousands. As these requests frequently interleave within the same serving window, LLM serving systems must handle highly heterogeneous mixed-length workloads. Such mixed-length workloads expose fundamental inefficiencies in GPU-centric serving architectures, whose throughput depends on large, memory-constrained batches. In this paper, we present NELSSA, an LLM serving system that integrates GPUs with real-world Processing-near-Memory (PNM) accelerator devices to efficiently support mixed-length workloads. NELSSA employs length-based request placement to route short-context requests to GPUs and long-context requests to the PNM tier, incorporating runtime migration to accommodate dynamic context growth without recomputation. We prototype NELSSA as an end-to-end system, implementing device-level sparse attention on PNM, GPU decode kernels, and a host-side runtime that orchestrates scheduling and cross-tier memory movement over a CXL-enabled infrastructure with RPC and RDMA support. Across mixed-length LLM workloads, NELSSA improves decode throughput by up to 5.5x in tokens/sec and reduces P99 latency by up to 15x compared to GPU-only baselines. Our end-to-end prototype and experimental results suggest that integrated GPU-PNM serving, enabled by CXL-based disaggregation, is a promising system paradigm for scalable and flexible LLM infrastructures that support evolving workloads.

## 1. 核心问题与整体含义（研究动机和背景）

- **问题背景**：现代LLM服务面临越来越明显的混合长度工作负载，请求长度从数百个token到数十万token不等，且经常在同一服务窗口内交错出现。这种异构性在GPU-centric服务架构中造成根本性低效：
  - 长上下文请求消耗大量KV缓存，迅速占满有限的GPU显存，导致有效批大小坍塌，吞吐量下降。
  - 短请求与长请求共同调度时，长请求引起队头阻塞（Head-of-Line blocking），显著放大尾延迟。
  - 即使是少量的长上下文请求，也会严重降低整体系统效率。
- **现有方法的局限性**：
  - KV缓存缩减技术（压缩、量化、剪枝）会以牺牲精度为代价。
  - 内存解聚与卸载（CPU offloading）受限于PCIe带宽瓶颈。
  - 现有的稀疏注意力+PNM方案（如LongSight、ScalablePNM）存在三个不足：
    1. 仅优化长请求，忽视短请求在GPU上的效率优势；
    2. 缺乏对动态上下文增长的支持（静态路由）；
    3. 缺乏完整的端到端系统集成与真实硬件验证。
- **本文目标**：提出NELSSA，一种将GPU与真实PNM加速器集成的LLM服务系统，通过基于长度的请求放置和运行时迁移，高效支持混合长度工作负载，实现更高吞吐、更低延迟。

## 2. 方法论：核心思想、关键技术细节

### 2.1 核心思想
- **基于长度的请求放置**：根据硬件推导的交叉点阈值 \( T_{\text{input}} \)，将短请求路由至GPU执行密集注意力，长请求路由至PNM执行稀疏注意力，实现专用化分工。
- **分离批处理（split-batch hybrid routing）**：GPU全局批处理所有请求的QKV和MLP计算，但注意力阶段分叉：短请求在GPU上完成FlashAttention；长请求将全局稀疏注意力异步卸载至PNM，GPU仅处理本地注意力窗口（sink+recent tokens），结果通过online softmax合并。
- **无缝后台迁移**：针对动态上下文增长（如推理、代理工作流），当请求的上下文长度超过阈值且GPU内存压力触发时，在后台流中异步迁移KV缓存至PNM，无需中断生成本身，实现一次性的执行权转交（one-way handoff）。

### 2.2 关键技术细节
- **路由阈值推导**：建立GPU密集注意力延迟模型 \( T_{\text{GPU}}(L) = L \cdot M_{kv} / BW_{\text{GPU}} \) 和PNM稀疏注意力延迟模型 \( T_{\text{PNM}}(L,N) = \frac{L \cdot M_{kv}}{C \cdot BW_{\text{GPU}}} + \frac{L \cdot S \cdot M_{kv}}{N \cdot BW_{\text{eff}}^{\text{PNM}}} + T_{\text{comm}}(N) \)。通过求解 \( T_{\text{GPU}}(L) = T_{\text{PNM}}(L,N) \) 得到硬件相关的交叉点 \( L_{\text{crossover}}(N) \)，并以此作为路由阈值 \( T_{\text{input}} \)。
- **PNM执行**：使用查询驱动的聚类选择稀疏注意力，KV缓存以cluster形式存储在PNM的DDR5 DRAM中；采用头维度划分（head-wise partitioning）实现多PNM负载均衡。
- **系统架构**：采用预填充-解码解聚架构，增加专用PNM节点（NELSSA Node）。Prefill Node完成长请求的分段K-means聚类（与预填充并行）；Decode GPU Node执行短请求注意力及所有FFN计算，保留轻量级质心元数据用于路由；NELSSA Node包含多个PNM模块，执行稀疏注意力并返回结果。
- **通信与数据路径**：控制路径（初始化、KV缓存分配）使用gRPC/TCP；性能关键路径（KV缓存卸载、查询/输出向量交换）使用RoCEv2 RDMA，绕过内核，实现微秒级延迟。

## 6. 主要结论与发现

1. **吞吐提升**：在混合长度负载下，NELSSA相比1×GPU基线实现高达5.5×的解码吞吐提升，相比2×GPU基线实现3.6×提升。
2. **延迟降低**：GPU内存利用率和批大小稳定，P95 TPOT降低6倍，P99 TPOT降低15倍（注入单个256K长请求后测量）。
3. **混合比例鲁棒性**：当长请求比例从0%上升到24%时，GPU-only吞吐急剧下降，而NELSSA仅轻微下降，始终保持更高吞吐。
4. **动态增长支持**：在1:2输入输出比场景下，NELSSA通过后台迁移保持稳定吞吐（提高29%），而基线频繁预取导致吞吐坍塌。迁移引入的延迟抖动微小，增量聚类开销远小于重计算开销。
5. **网络开销可控**：在150 tok/s的严格目标下，GPU-PNM通信延迟占整体解码延迟的比例不超过2.1%（即使100G网络），证明了该架构的网络可行性。
6. **精度保持**：在4%及以上稀疏选择率下，NELSSA在RULER benchmark上维持与GPU-only基线相同的精度，同时保持高吞吐。

## 7. 优点

1. **创新性的长度感知路由**：基于硬件特性推导路由阈值，而非启发式，确保了每个请求在最合适的计算层上执行。
2. **分离批处理优化**：将全局FFN与QKV计算批处理，仅注意力阶段分叉，最大化GPU利用率并避免干扰。
3. **无缝后台迁移**：首次在真实PNM硬件上实现了推理过程中KV缓存的异步迁移，无需重计算或中断，解决了动态增长这一实际挑战。
4. **端到端系统实现**：在真实PNM硬件（ARM Neoverse V2、DDR5、CXL）上完整实现了从通信、调度到设备级稀疏注意力的全部软件栈，验证了可行性。
5. **解聚架构**：通过CXL与RDMA实现GPU与PNM的独立扩展，为大规模部署提供了灵活性和可伸缩性。
6. **实验严谨性**：结合直接硬件测量与测量驱动的仿真，确保结果可靠；投影方法保守（仅扩展内存，其他参数保持不变）。

## 8. 不足与局限

1. **硬件原型限制**：当前原型PNM设备仅32GB DRAM，最大批大小受限，投影依赖估计（虽然误差控制在±5.6%以内）。
2. **稀疏选择率与精度权衡**：虽然4%选择率能保持精度，但在某些任务或更长上下文中可能需要更高选择率，可能影响吞吐。
3. **缺乏真实代理工作负载**：动态增长实验基于合成负载，未使用真实agent/coding辅助等复杂工作负载的trace，可能未完全反映实际场景。
4. **与CPU卸载方法的对比不充分**：仅与RetroInfer对比，未与其他近期工作（如InfiGen、FlexGen）直接比较，也未展示选择率变化对CPU卸载系统的影响。
5. **可扩展性验证有限**：当前评估仅使用1-2个GPU和4个PNM设备，大规模集群（例如数十个GPU+PNM节点）下的效果仅基于投影，未实际验证。
6. **硬件实现细节未公开**：PNM模块的具体微架构（如稀疏注意力加速器设计、实际功耗等）未详细说明，影响结果的可复现性。
7. **缺少多模型支持**：论文仅评估Llama3-8B-1048K，未测试更大型模型（如70B、405B）或MoE架构，PNM的执行效率可能因模型不同而变化。
