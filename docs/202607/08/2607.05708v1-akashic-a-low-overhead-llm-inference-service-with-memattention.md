## 摘要
当前基于LLM的智能体系统在多轮交互、工具调用和跨会话工作流中不断累积上下文。为每个请求重放全部历史很快变得不切实际：长上下文增加预填充成本，可能超出上下文限制，并且常常将与任务相关的证据埋没在不相关的内容中，从而降低服务效率和输出质量。我们提出Akashic，一种围绕MemAttention构建的低开销记忆系统，它将上下文组织成有界块，并对跨块的语义关系进行建模，无需重复重写整个历史即可保留跨块证据。Akashic进一步应用硬件-软件协同设计的记忆布局，将可能共同检索的块共置，减少检索碎片化和I/O开销。在四个代表性工作负载和三种模型规模上，与强先前的记忆基线相比，Akashic将任务准确率提升高达10.2个百分点，吞吐量提升高达1.21倍，可持续请求率提升高达1.88倍。

## Abstract
Recent LLM-based agent systems continuously accumulate context across multi-turn interactions, tool invocations, and cross-session workflows. Replaying the full history for every request quickly becomes impractical: long contexts increase prefill cost, may exceed context limits, and often bury task-relevant evidence in irrelevant content, degrading both serving efficiency and output quality. We propose Akashic, a low-overhead memory system built around MemAttention, which organizes context into bounded chunks and models semantic relationships across chunks, preserving cross-chunk evidence without repeatedly rewriting the full history. Akashic further applies hardware-software co-designed memory placement to co-locate likely co-retrieved chunks, reducing retrieval fragmentation and I/O overhead. Across four representative workloads and three model sizes, Akashic improves task accuracy by up to 10.2 points, throughput by up to 1.21x, and sustainable request rate by up to 1.88x over strong prior memory baselines.

# Akashic: A Low-Overhead LLM Inference Service with MemAttention 深度解读

## 1. 论文的核心问题与整体含义（研究动机和背景）

**核心问题**：LLM agent 系统在多轮交互、工具调用和跨会话工作流中会持续累积长上下文。如果为每个请求都重放完整历史，会导致：
- **预填充成本激增**：长上下文使 Transformer 的 prefill 阶段计算量和内存访问量呈二次增长。
- **可能超出上下文窗口限制**：即使模型支持超长上下文（如百万 token），实际延迟也会显著增加（OpenAI 报告 ~1M token 时 TTFT 可达约一分钟）。
- **无关内容干扰**：相关证据被埋没在无关上下文中，导致模型性能下降（lost-in-the-middle 效应）。

**整体含义**：现有外部记忆系统（如 Mem0 的全局总结、MemGAS 的片段级独立总结）面临一个**粒度权衡**：全局压缩维护成本随历史增长而增长且易引入噪声；片段级压缩会割裂语义关联的证据，削弱多跳推理。此外，现有系统通常只优化语义相关性，忽略了物理存储布局——即使只检索少量相关记忆，若它们物理上分散在多个页/块中，检索延迟仍然很高（称为“局部性鸿沟”）。因此需要一种既能控制维护开销、又能保留跨块证据、同时降低检索 I/O 的低开销记忆系统。

## 2. 论文提出的方法论

### 核心思想
Akashic 围绕 **MemAttention** 构建，核心思路是：
- **有界分块维护**：将上下文切分为固定大小的块（默认 1024 token），每次只对一个块进行压缩/更新，避免重写整个历史。
- **跨块推理**：压缩新块时，通过模型进行语义匹配，找出最相关的 top-5 旧块，然后联合压缩以保留跨块证据、更新或淘汰过时记忆。
- **查询感知检索**：推理时同样用模型匹配当前查询与候选块元数据，选出 top-5 相关块注入 prompt。
- **硬件-软件协同内存放置**：依据模型推断的关联性，将频繁一同访问的块物理共置；采用异位更新（out-of-place update）和后台压缩（无效比例 ≥75% 时触发），降低检索碎片和 I/O 开销。

### 关键技术细节
- **块门控压缩**：累积 token 数超过阈值 τ_c 时触发一次压缩，最坏维护开销 O(τ_c) 而非 O(总历史长度)。
- **模型驱动的统一语义匹配**：既用于压缩时的跨块联合（更新/淘汰），也用于检索时的候选选择，避免了手动设计相似度函数。
- **Memory Manager**：
  - **在线重定位**：联合推理后，对共同访问的块进行异位重写，标记旧副本无效。
  - **后台块压缩**：当块无效比例 ≥0.75 时，提取存活块，按 user_id/session_id 分区，再用模型分组后重写入新块，释放旧块。
- **元数据结构**：每个记忆块记录 user_id、session_id、元数据关键词，支持逻辑隔离和时空排序。

### 公式与算法
- **保留率** ρ = L_eff / L_raw，衡量上下文信息密度。
- **无效比例** φ(B) = N_invalid(B) / N_total(B)，决定块是否需要压缩。
- **算法 1 (MemAttention)**：输入新对话 x_t → 追加到活动块 → 若块长度 ≥ τ_c → 压缩活动块并提取元数据 → 用模型选择 top-p 相关旧块 → 联合压缩产生新块（可能更新/删除旧块）→ 写入块表 → 开始新活动块。推理时：从当前查询提取关键词 → 模型选择 top-p 相关块 → 取出后按时间排序与查询拼接。
- **算法 2 (Memory Manager)**：在线路径：收到检索到的块集合 S → 模型识别应共置的子集 → 异位重写入新块，标记旧副本无效。后台路径：扫描无效比例 ≥0.75 的块 → 提取存活块 → 按用户/会话分区 → 模型分组 → 重写入新块，释放旧块。

## 6. 论文的主要结论与发现

1. **任务质量提升**：在 LoCoMo、BrowseComp 上准确率提升最多 8.4–10.2 点，在 SWE-bench 上提升 4.6–6.6 点。
2. **吞吐量提升**：单请求下比最强基线（Mem0/MemGAS/RMM）提升 1.08×–1.56×（取决于数据集）；并发场景下可持续请求率提升 1.26×–1.88×。
3. **局部性改善**：通过共置相关块，每请求访问的块数减少 17.1%–50%，p95冷缓存检索延迟降低 18.2%–42.1%。
4. **存储效率可控**：空间放大 1.17×、写放大 1.34×，优于无垃圾回收或过度重定位的策略。
5. **消融验证**：有界分块维护是效率提升的主要来源；跨块推理显著改善质量；模型驱动检索优于纯稠密检索。
6. **参数不敏感**：chunk gate 1024、memory budget 1536、association threshold 0.7、GC invalid-ratio 0.3 为良好默认值附近。

## 7. 优点

1. **方法创新性强**：将系统设计思想（有界维护、异位更新、后台压缩）引入 LLM 记忆管理，同时利用模型本身的语义能力（统一匹配机制）来驱动压缩和检索，避免了外部嵌入模型。
2. **软硬协同**：首次明确关注物理布局与语义相关性的不匹配，并通过在线重定位和后台压缩优化局部性，降低 I/O 开销。
3. **实验极其充分**：覆盖 3 种模型规模、4 种代表性工作负载、多个并发级别、存储指标、消融和参数敏感性，对比了 5 种强基线，结果可信度高。
4. **开源承诺**：计划将代码合并到 RedKnot 框架并开源，便于复现与扩展。

## 8. 不足与局限

1. **模型范围有限**：仅测试 8B–70B 参数规模的 decoder-only 模型，未评估 MoE 或更大规模（如 180B+）模型；相关性分析也仅使用了 OPT-30B，可能在其他模型上分布不同。
