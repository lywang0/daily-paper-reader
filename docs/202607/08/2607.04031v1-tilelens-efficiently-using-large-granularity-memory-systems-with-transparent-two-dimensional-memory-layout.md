## 摘要
大型语言模型（LLM）推理受限于GPU高带宽内存（HBM）的容量和带宽。近期提出的方案（如High-Bandwidth Flash (HBF) 和 RoMe）提供了比HBM更高的容量或带宽，但要求最小访问粒度为千字节。我们表明，这些大粒度内存系统（LGMS）可能使LLM推理中的主导操作——分块矩阵乘法——的性能下降高达一个数量级。性能下降的根本原因是读放大，即内存请求获取的数据远多于分块实际需要。这种浪费源于计算分块的二维性质与一维内存布局之间的根本性不匹配，导致每次请求都溢出到分块边界之外。为缓解读放大，我们提出在LGMS中使用分块主导布局。分块主导布局不是将数据存储为一维条带，而是将每个连续内存块重塑为二维矩形，使内存粒度与分块边界对齐。为便于在GPU上采用分块主导布局，我们提出TileLens，这是一种轻量级的软硬件扩展，共同覆盖了主要的GPU内核类别。TileLens-SW扩展了GPU领域特定语言（DSL），使得基于DSL的内核只需更改布局描述符即可在全局内存中采用分块主导布局。TileLens-HW扩展了张量内存加速器（TMA），为基于TMA的内核提供透明的分块主导支持，无需更改代码。我们使用来自Qwen-3 30B和Llama-3.1 70B的矩阵乘法内核，在周期级模拟器上评估了TileLens。将分块主导布局与自适应硬件预取器相结合，TileLens在配备HBF的GPU上实现了接近HBM的性能，其中HBF NAND读取延迟为5微秒，将几何平均性能下降从传统布局的1.61-6.49倍降低到仅比纯HBM基线高1%以内。

## Abstract
Large Language Model (LLM) inference is bottlenecked by the capacity and bandwidth of GPU High-Bandwidth Memory (HBM). Recent proposals, such as High-Bandwidth Flash (HBF) and RoMe, offer higher capacity or bandwidth than HBM, but require a minimum access granularity of kilobytes. We show that these Large-Granularity Memory Systems (LGMS) can degrade the performance of tiled matrix-multiplication, which is the dominant operation in LLM inference, by up to an order of magnitude. The root cause of the slowdown is read amplification, where memory requests fetch far more data than the tile actually needs. This waste stems from a fundamental mismatch between the two-dimensional nature of compute tiles and the one-dimensional memory layout, leading to each request spilling well beyond the tile boundaries.   To mitigate read amplification, we propose to use tile-major layout for LGMS. Rather than storing data as a one-dimensional strip, tile-major layout reshapes each contiguous memory block into a two-dimensional rectangle, aligning memory granularity with tile boundaries. To ease the adoption of tile-major layout on GPUs, we propose TileLens, lightweight software and hardware extensions that collectively cover major classes of GPU kernels. TileLens-SW extends GPU DSLs so that DSL-based kernels can adopt tile-major in global memory by changing only the layout descriptor. TileLens-HW extends the Tensor Memory Accelerator (TMA) for transparent tile-major support in TMA-based kernels without code changes. We evaluate TileLens on a cycle-level simulator using matrix-multiplication kernels from Qwen-3 30B and Llama-3.1 70B. Combining a tile-major layout with an adaptive hardware prefetcher, TileLens achieves near-HBM performance on HBF-augmented GPUs with a 5us HBF NAND read latency, reducing the geomean slowdown from 1.61-6.49x with conventional layouts to within 1% of an HBM-only baseline.

## 1. 论文的核心问题与整体含义（研究动机和背景）

- **背景**：LLM 推理性能受 GPU 高带宽内存（HBM）容量和带宽的双重瓶颈限制。新兴的大粒度内存系统（Large-Granularity Memory Systems, LGMS），如 High-Bandwidth Flash（HBF，堆叠 NAND 闪存，容量为 HBM 的 8–16×）和 RoMe（将 HBM 访问粒度增至 4KB 以获得额外带宽），虽然提升了容量或带宽，但要求最小访问粒度达到千字节级（例如 4KB），远大于 HBM 的 32B。
- **核心问题**：GPU 上的矩阵乘法采用分块（tiled）方式，每个计算 tile 是二维的（宽度通常 64–512 字节）。当使用一维的内存布局（row-major 或 column-major）时，每个 4KB 请求会获取一条远超出计算 tile 边界的一维条带，导致严重的**读放大**。读放大不仅浪费带宽，还会因 straggler 效应（慢请求阻塞多个依赖的 CTA）而进一步恶化性能，使执行时间最多增加一个数量级。
- **整体含义**：本文旨在解决 LGMS 中读放大这个根本性瓶颈，提出一种与计算 tile 对齐的二维内存布局，使 LGMS 能够在不牺牲性能的前提下发挥其容量/带宽优势。

## 2. 论文提出的方法论：核心思想、关键技术细节

### 核心思想：Tile-Major 布局（分块主导布局）

- 将每个连续的 4KB 内存块从一维条带重塑为二维矩形（称为**内存 tile**，memory tile），使其恰好包含在一个计算 tile 内。例如，对于 FP8 数据（1 字节/元素），4KB 区域可塑成 64×64 矩形，与常见计算 tile（如 128×128）对齐，消除读放大。

### 关键技术细节

1. **地址翻译公式**：
   - 对于矩阵元素 `(i, j)`，内存 tile 尺寸为 `(a, b)`（满足 `a·b·s = 4096`，s 为元素字节数），分解为 tile 间索引 `(T_i, T_j)` 和 tile 内索引 `(i', j')`。
   - 字节偏移：`offset_tile = (T_j · K/a + T_i) · 4096 + (j' · a + i') · s`。
   - 由于 a、b 均为 2 的幂，计算仅需移位和掩码。

2. **TileLens-SW（软件扩展）**：
   - 扩展 GPU DSL（如 CuTe），将二维矩阵视为四维张量：`shape=(a, b, K/a, N/b), stride=(1, a, a·b, K·b)`。
   - DSL 内核只需更改布局描述符即可采用 tile-major，无需修改计算逻辑。

3. **TileLens-HW（硬件扩展）**：
   - 修改 TMA（Tensor Memory Accelerator）的地址计算逻辑，增加两个描述符字段：内存 tile 尺寸 `(a,b)` 和 leading stride `K`。
   - TMA 在计算 tile base address 时，通过 split & sum 单元将多维坐标分解为行/列索引，再利用 tile-major 公式计算基地址；在生成内部请求地址时，将列计数器拆分为内层（步长 a，重复 b 次）和外层（步长 b·K，重复 v/b 次）。
   - 硬件开销极小（约 3–4K 门，相当于一个 32 位乘法器）。

4. **系统级支持（针对 HBF）**：
   - **数据放置**：只读权重放在 HBF，激活和 KV Cache 放在 HBM。
   - **混合粒度 L2 缓存**：HBF 请求返回 4KB 块时整块插入 L2，MSHR 以 4KB 粒度追踪。
   - **自适应步长预取器**：基于 CTA 数量和 NAND 延迟动态调整预取深度 d，公式 `d = min(floor(2·B·L / p_wave), K/TILE_K)`，保持总线饱和。

## 6. 论文的主要结论与发现

- 传统列主/行主布局在 LGMS 上因读放大导致几何平均性能下降 1.61–6.49 倍。
- Tile-major 布局配合自适应预取器，在 5 μs HBF 延迟下将性能损失降至 HBM-only 基线的 **1% 以内**（即几乎无损失）。
- Row-major 布局虽然减少带宽浪费，但 straggler 效应导致严重延迟，性能仍然远差于 tile-major。
- 预取器是隐藏 HBF 长延迟的关键；在无预取时，tile-major 会因取消隐式预取而劣于 row-major。
- 内存 tile 形状需与计算 tile 对齐才有最佳效果；窄高形状仍会引起读放大。
- RoMe 由于低延迟，straggler 效应不明显，tile-major 与 row-major 性能接近，仅列主布局表现差。
