## 摘要
将大型语言模型（LLM）推理的预填充和解码阶段分离到两组不同的节点上，在当今的LLM服务系统中被广泛采用。然而，这种架构对在租用云实例上自托管LLM部署提出了重大挑战，因为在分离节点之间传输大量键值（KV）缓存很容易使有限的节点间网络带宽饱和。在本文中，我们提出通过选择性跨阶段传输必要的KV缓存条目来缓解网络瓶颈。实现选择性KV缓存传输面临两个挑战，即预填充阶段的精确KV选择，以及解码阶段的高效KV获取。为解决这些挑战，我们设计了SmartGen，一个KV缓存传输引擎，通过三条数据传输路径实现无缝的分离式LLM推理。具体而言，我们利用1）基于配置文件的自适应预取路径，在预填充阶段识别并将必要的KV缓存条目推送到解码节点；2）并行按需传输路径，在解码阶段同时获取远程和本地KV缓存条目；3）推测性传输路径，最终将所有KV缓存交付到解码节点。实验结果表明，与典型的全量KV缓存传输方法相比，SmartGen将到第二个令牌的时间最多缩短4.3倍，同时提供相当的后续解码性能和准确性。

## Abstract
Disaggregating the prefill and decoding stages of large language model (LLM) inference into two separate sets of nodes is widely adopted in today's LLM serving systems. However, such an architecture poses significant challenges for self-hosted LLM deployments on rented cloud instances, since transferring enormous key-value (KV) caches between disaggregated nodes can easily saturate the limited inter-node network bandwidth. In this paper, we propose to mitigate the network bottleneck by selectively transferring essential KV cache entries across the two stages. There are two challenges to achieve selective KV cache transfer, i.e., accurate KV selection during the prefill stage, and efficient KV fetching during the decoding stage. To address these challenges, we design SmartGen, a KV cache transfer engine that allows seamless disaggregated LLM inference with three data transfer paths. Specifically, we leverage 1) a profile-based proactive transfer path to identify and push essential KV cache entries to the decoding node during the prefill stage, 2) a parallel on-demand transfer path to simultaneously fetch remote and local KV cache entries during the decoding stage, and 3) a speculative transfer path to finally deliver all KV caches to the decoding node. Experimental results show that SmartGen reduces time-to-second-token by up to 4.3x compared with the typical full KV cache transfer approach while offering comparable subsequent decoding performance and accuracy.

## 1. 核心问题与研究动机

分离式（P/D Disaggregated）LLM推理架构将计算密集的预填充（Prefill）阶段与访存密集的解码（Decoding）阶段分别部署在不同节点上，以提升资源利用率和吞吐量，已被现代LLM服务系统广泛采用。然而，该架构面临一个关键瓶颈：

- **KV缓存传输开销巨大**：每次推理请求都需将KV缓存从prefill节点传输至decoding节点。在长上下文场景下，KV缓存大小随序列长度、批次大小、模型规模线性增长，而云GPU实例普遍只提供有限的网络带宽（如10–35 Gbps），容易导致传输延迟远超prefill计算延迟。
- **阶段转换停滞（Stage-Transition Stall）**：论文实验表明，在Llama-3.1-8B和Qwen3-14B模型、48K token输入下，全量KV缓存传输耗时是prefill计算的6.5倍；仅考虑网络时，差距可达7.1倍（15 Gbps带宽）。这直接拉高了**time-to-second-token（TTST）**，造成用户感知的停顿。
- **现有方案不足以解决根本问题**：已有系统（DistServe、Splitwise、Mooncake）通过层级传输或高带宽网络来缓解，但无法从根本上解决低带宽自托管云环境下的网络饱和问题。

论文的核心洞察是：**KV缓存存在动态稀疏性，并非所有KV条目在解码阶段都同等重要**。因此可以借鉴稀疏注意力思想，通过选择性地传输关键KV条目来大幅降低跨节点数据传输量，从而消除阶段转换停滞。

## 2. 方法论：SmartGen设计

### 2.1 核心思想

SmartGen将KV缓存条目划分为三类，分别采用三条数据传输路径：

| 类别 | 含义 | 传输路径 |
|------|------|----------|
| 普遍重要（Universally Important） | 与具体输入无关、位置相对固定的重要条目 | 基于画像的主动传输（Profile-based Proactive Transfer） |
| 上下文相关（Context-Dependent） | 仅在特定query下重要的条目 | 并行按需传输（Parallel On-demand Transfer） |
| 较不重要（Less Important） | 剩余条目，用于保证最终精度 | 推测式传输（Speculative Transfer） |

### 2.2 基于画像的主动传输

该路径解决“prefill阶段无法准确选择重要KV条目”的挑战。受静态KV稀疏性启发，论文发现：

- **位置相似性（Positional Similarity）**：重要KV条目倾向于出现在序列中的一致区域，且该分布模式在不同数据集、不同提示长度下保持稳定（如图5所示）。
- **离线画像**：使用校准数据集进行一轮推理，统计每个KV条目在解码阶段被稀疏注意力算法选中的频率S(e)，据此计算每个KV块的重要性I_l,m（公式1）。前两层注意力层的KV块强制设置为最高优先级。
- **主动推送**：根据画像得到的top-Kr重要KV块（公式2），在prefill计算过程中，利用RDMA WRITE边计算边将重要KV块推送至解码节点的KV缓存池，并同步更新解码侧的KV掩码（通过doorbell batching合并写入）。

### 2.3 并行按需传输

该路径解决“解码阶段远程KV获取引入网络往返开销”的挑战。核心是**双通道KV获取（Two-lane KV Fetching）**：

- **掩码式索引拆分（Mask-based Index Splitting）**：在解码节点GPU上为每层维护一个B×N的int8 KV掩码矩阵，标记KV条目状态（0=填充token，1=本地，2=远程）。KV选择算法生成的KV索引通过轻量级的GPU索引操作（Algorithm 1中的算子①-③）拆分为本地索引和远程索引。
- **重排式KV聚合（Reordering-based KV Gathering）**：利用注意力计算对KV条目沿序列维度的顺序不敏感这一性质，将远程KV条目重排到每行前端（算子④-⑤），使其连续传输，并利用RDMA NIC的DMA scatter能力将接收的连续数据块分散写入GPU内存，避免额外scatter kernel。

### 2.4 推测式传输

该路径利用解码阶段注意力计算期间出现的**空闲CPU和RDMA NIC资源**，通过在每层开始前通知prefill节点，后台推测性地传输尚未送达的KV块。为防止与前台按需传输争用资源：

- 限制单次传输的块数比例（默认**speculative ratio=10%**），使全部剩余KV块在约10次解码迭代内完成传输，且几乎不干扰前台操作。

### 2.5 通用性与适应性

- **兼容多种KV选择算法**：通过统一的KV索引抽象，可适配InfiniGen、HATA等动态稀疏注意力算法。
- **适应动态工作负载**：支持周期性重画像和分组画像。
- **适应动态网络负载**：通过公式2的分析模型，低负载时自动回退到全量传输。
- **适配无GDR环境**：将KV掩码维护在主机内存，索引拆分在CPU侧完成，远程KV需额外一次host-to-device拷贝。

## 6. 主要结论与发现

1. **SmartGen显著降低TTST**：相比全量KV传输，最多降低**4.3倍**（GovReport任务），同时保持后续解码性能和准确性基本不变。
2. **渐进式性能改善**：SmartGen的CTL在全过程中保持最佳，早期无全量传输的延迟尖峰；TBT逐步趋近理想情况（全量本地缓存）。
3. **组件有效性**：profile-based主动传输（TBT降低约1.03×–1.1×）、并行按需传输（约1.1×–1.2×）、推测式传输（约1.2×–1.3×）均带来独立增益，三者叠加效果显著。
4. **优于量化方案HACK**：HACK在LongBench上相对精度最低仅为13%–77%，而SmartGen精度接近全缓存基线（96%–120%），说明动态KV选择性传输在长上下文精度关键任务上优于激进量化。
5. **带宽越低收益越大**：从32 Gbps到15 Gbps，SmartGen相对全量传输的TTST改善从2.5×提升至3.3×。
6. **与现有系统的关系**：SmartGen与已有的层重叠、KV量化、前缀缓存等技术正交，可组合使用。

## 7. 优点与亮点

- **创新视角**：首次将KV稀疏性从计算优化迁移到网络传输优化，直击分离式推理的带宽瓶颈。
- **三类别/三路径设计**：思路清晰，将动态稀疏性带来的不确定性问题系统性地分解为可预测、可并行、可后台处理的三部分。
- **工程化深度高**：涉及RDMA WRITE/SEND、GDR、doorbell batching、NIC scatter-gather等底层优化，技术细节扎实；KV掩码设计轻量（2.5MB/64K tokens）。
- **通用性与兼容性**：基于统一的KV索引抽象，可插入不同KV选择算法；提供了无GDR环境的适配方案，增强了在低成本云实例上的实用性。
- **实验设计严谨**：将2WikiMultihopQA预设为校准集防止泄漏；对比了多种基线（全量、朴素Partial、量化HACK、静态稀疏StreamingLLM）；在多平台（L20、V100S）上验证。

## 8. 不足与局限

- **对离线画像的依赖**：核心的位置相似性假设基于经验观察，在极端不同分布或超长上下文（>16K）下可能失效；虽然设计了周期性与分组画像，但更新流程和收敛性未在文中验证。
- **精度受KV选择算法上限约束**：SmartGen自身不提供新的KV选择算法，若底层算法选件精度不足，系统整体精度将受影响（虽然实验显示InfiniGen/HATA表现良好）。
- **网络低带宽下的剩余开销**：15 Gbps下SmartGen的TTST超过了“理想情况”，因为前两层KV缓存和元数据张量传输仍会饱和带宽；论文将此列为未来工作。
- **推测式传输的干扰风险**：在突发网络负载或大批量并发下，10%的推测式比例可能仍与前台按需传输冲突；论文在单一负载下验证，缺乏并发场景测试。
- **实验长度限制**：输出长度默认为64 token，未验证长生成场景下推测式传输的累计收益；批处理规模（最大96K token）对16K以上长上下文的覆盖有限。
