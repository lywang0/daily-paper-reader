## 摘要
在笔记本电脑和台式机等消费设备上运行大型语言模型颇具挑战，因为模型权重常超出GPU内存容量，需借助卸载推理以利用CPU内存扩展有效模型容量。然而，现有卸载系统通常依赖粗粒度的层级或专家级调度，忽视了同层内张量间的显著异质性，且难以适应此类设备上变化的硬件负载条件。本文提出ATSInfer，一种面向消费设备的CPU-GPU混合推理系统，其在张量粒度执行卸载。ATSInfer结合静态张量放置与负载感知的动态传输，并引入异步CPU-GPU协调，以高效调度异构后端上的硬件存储、数据移动与计算。我们实现并评估了ATSInfer，在典型消费平台上使用稠密模型和MoE模型进行测试。与现有系统相比，ATSInfer将预填充吞吐量提升高达1.94倍，解码吞吐量提升高达3.29倍，同时提高了GPU利用率并更有效地利用了PCIe带宽。这些结果表明，ATSInfer能显著改善个人消费设备上本地LLM部署的用户体验。

## Abstract
Running large language models on consumer devices such as laptops and desktops is challenging because model weights often exceed GPU memory capacity, making offloading inference necessary to extend effective model capacity with CPU memory. Existing offloading systems, however, typically rely on coarse layer-level or expert-level scheduling, which overlooks substantial heterogeneity among tensors within the same layer and adapts poorly to changing hardware load conditions on such devices. This paper presents ATSInfer, a hybrid CPU-GPU inference system for consumer devices that performs offloading at tensor granularity. ATSInfer combines static tensor placement with load-aware dynamic transfer, and introduces asynchronous CPU-GPU coordination to efficiently schedule hardware storage, data movement, and computation across heterogeneous backends. We implement ATSInfer and evaluate it on representative consumer platforms using both dense and MoE models. Compared with existing systems, ATSInfer improves prefill throughput by up to 1.94$\times$ and decode throughput by up to 3.29$\times$, while also increasing GPU utilization and making more effective use of PCIe bandwidth. These results show that ATSInfer can substantially improve the user experience of local LLM deployment on personal consumer devices.

- **问题**：消费级设备（笔记本、台式机）的GPU显存有限，通常不足以容纳完整的LLM模型权重，必须通过“卸载”（offloading）将部分权重存储在CPU内存中，并在推理时按需传输到GPU。然而，现有系统采用粗粒度的卸载策略（如按层或按专家），忽略了同一层内不同张量在计算强度、内存访问模式上的显著异质性，导致资源利用低效。此外，消费设备环境负载多变（后台任务、热节流），现有固定策略或仅输入驱动的调度无法适应实时硬件负载变化，成为性能瓶颈。
- **整体含义**：本文旨在通过**张量粒度的精细调度**，结合**静态放置**与**负载感知的动态传输**，并利用**异步CPU-GPU协调**，显著提升消费设备上本地LLM推理的响应速度和资源利用率，使私有化、离线部署更实用。

## 2. 方法论：核心思想、关键技术细节、公式与算法流程

### 2.1 核心思想
将模型推理的卸载单位从“层/专家”细化到“张量”，对每个权重张量决定其默认驻留在GPU还是CPU；在运行时，根据当前硬件负载（CPU/GPU/PCIe状态）动态选择部分CPU张量临时提升到GPU执行，并利用异步重叠隐蔽传输开销。

### 2.2 关键技术细节

- **异步CPU-GPU协调**：
  - 设计三层内存布局：**GPU常驻区**、**CPU锁定内存存储**、**GPU临时缓冲区**（按张量生命周期复用）。
  - 使用**双流调度**：计算流（Compute Stream）执行算子及激活传输（通过SM驱动的拷贝内核）；传输流（Transfer Stream）通过CUDA拷贝引擎搬运权重，避免小激活传输被大权重传输阻塞。
  - 通过GPU事件实现轻量级跨流同步。

- **静态张量放置**（离线）：
  - 定义**经验性能密度** \( k_b^i = t_b^i / s_i \)（后端b上每MB执行时间），反映每字节内存带来的计算价值。
  - 将放置问题建模为带切换惩罚的**背包优化**：
    \[
    \max \sum_i r_i \mathbf{1}\{b_i=GPU\} - \sum_{i=2}^n c_i \mathbf{1}\{b_i \neq b_{i-1}\}
    \]
    约束：常驻张量总大小 ≤ GPU内存预算。
  - 对稠密模型用标准DP求解，对MoE模型先分离专家/非专家张量，再分段求解（算法1）。

- **负载感知动态传输**（在线）：
  - 针对每个推理轮次（prefill或decode），基于实时测量的CPU/GPU执行时间、传输时间，重新决策哪些CPU张量提升到GPU。
  - 考虑**重叠窗口**：前一个CPU节点到当前节点的计算+激活传输时间，隐蔽权重传输。
  - 目标最小化端到端延迟，形式化为带重叠暴露项的DP（算法2），复杂度\(O(n^2)\)。
  - 引入**重调度机制**（算法3）：当实测偏差超过阈值（15%）且距上次重调度超过5倍TPOT时才触发，避免频繁重建图。

### 2.3 公式与算法流程（文字说明）
- 性能密度公式：\(k_{gpu}^i = t_{gpu}^i / s_i\)，\(k_{cpu}^i = t_{cpu}^i / s_i\)，收益\(r_i = t_{cpu}^i - t_{gpu}^i\)。
- 静态放置求解：离散化到MB粒度后跑DP，回溯得到每个张量的默认后端。
- 动态传输DP：遍历张量，维护dp[i][后端]状态；对CPU默认张量，枚举上一个CPU端点j，计算暴露传输时间\(\delta = \max(w_i - seg(j,i), 0)\)，取最小路径。
- 重调度：computeDeviation()比较当前测量与上次测量，超过阈值且时间间隔足够才重新调度。

1. **张量粒度卸载比层/专家粒度更优**：利用性能密度，能优先放置高收益张量到GPU，显著提升效率。

## 7. 优点

- **细粒度调度**：突破层/专家边界，充分发掘张量间性能差异。
