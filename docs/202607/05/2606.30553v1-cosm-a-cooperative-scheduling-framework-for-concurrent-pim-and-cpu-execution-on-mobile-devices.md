## 摘要
终端大语言模型（LLM）的发展受到隐私保护和快速响应需求的双重驱动。移动设备上高能耗的数据传输使得存储内处理（PIM）成为有效解决方案。由于严格的DRAM成本约束、电路板上有限的物理面积以及应用程序与LLM之间的交互，CPU和PIM必须在共享内存空间内并发运行。然而，这可能会引发存储体冲突和总线拥塞等挑战，可能削弱PIM的性能和能效优势。为应对这一挑战，我们提出COSM，一种协同调度框架，旨在支持移动平台上PIM和CPU任务的并发执行。我们的关键创新包括：1）一种低干扰的PIM控制接口，能在不干扰CPU内存访问的前提下生成最大数量的PIM指令；2）一种空闲感知调度方法，将PIM指令集成到CPU访问序列中的可用空闲时间窗口内。COSM不仅向CPU隐藏了PIM的执行延迟，还实现了PIM执行与数据传输的重叠。在LLM与移动工作负载（包括移动应用和计算密集型内核）并发执行的实验中，与基准调度方法相比，COSM将PIM吞吐量提升高达2.8倍，同时CPU性能损失低于2.0%。

## Abstract
The development of on-device large language models (LLMs) is driven by the need for privacy and fast response times. Energy-intensive data transfer on mobile devices makes Processing-in-Memory (PIM) an effective solution. Due to stringent DRAM cost constraints, limited physical footprint on circuit boards, and the interaction between applications and LLMs, it is imperative for the CPU and PIM to operate concurrently within a shared memory space. However, challenges such as bank conflicts and bus congestion can arise, potentially diminishing the performance and energy benefits of PIM. To address this challenge, we introduce COSM, a cooperative scheduling framework designed to facilitate the concurrent operation of PIM and CPU tasks on mobile platforms. Our key innovations include: 1) a low-interference PIM control interface that generates the maximum number of PIM commands without disrupting CPU memory accesses; 2) an idleness-aware scheduling method that integrates PIM commands into available idle time windows within the CPU's access sequence. COSM not only hides PIM execution latency from the CPU, but also overlaps PIM execution with data transfer. Experiments on concurrent execution of LLMs and mobile workloads, including mobile applications and compute-intensive kernels, demonstrate that COSM improves PIM throughput by up to 2.8x compared to the baseline scheduling method with less than 2.0% CPU performance loss.

- **研究动机**：移动设备上部署大语言模型（LLM）需要在保护隐私的同时实现低延迟推理。处理‑in‑Memory（PIM）通过将计算单元集成到DRAM内部，可大幅降低数据搬运能耗并提升内部带宽，但实际部署时CPU和PIM必须共享同一物理内存空间并发执行，导致bank冲突和总线拥塞，从而抵消PIM的能效优势。
- **核心问题**：现有PIM调度策略（CPU‑first、row‑hit‑aware等）无法同时兼顾CPU的低延迟需求和PIM的高吞吐；同时，PIM控制接口（如固定长度命令、全bank命令）存在指令总线饱和、CPU被阻塞等问题；CPU‑mediated数据传输（输入/结果搬运）也会严重干扰CPU内存访问。
- **整体含义**：需要设计一种协同调度框架，在不显著牺牲CPU性能的前提下，充分利用CPU访问的空闲带宽来执行PIM操作，实现资源受限移动平台上CPU与PIM的高效并发。

### 2. 论文提出的方法论：核心思想、关键技术细节

- **核心思想**：通过软硬件协同设计，在内存控制器中实现“低干扰PIM控制接口”+“空闲感知调度”，将PIM命令（执行和数据传输）插入CPU访问的空闲时间窗口内，既隐藏PIM执行延迟，又实现执行与数据传输的重叠。

- **关键技术细节**：
  1. **低干扰PIM控制接口**：
     - **可抢占PIM执行命令（PIM_Exec）**：允许PIM单元连续执行多个列操作（持续时间`nPTL`），无需频繁下发命令，减少命令总线压力；同时引入**PIM_Pause命令**，使CPU请求能快速抢占PIM单元，暂停后保留状态，恢复时从断点继续。
     - **带宽解耦的数据传输命令**：将传统的CPU‑mediated传输拆分为**外部传输**（PIM_RdBuf/PIM_WrBuf，占用外部总线）和**内部传输**（PIM_LdBuf/PIM_StBuf，仅占用内部带宽）。二者可独立调度，避免同时占用内外带宽，使数据传输能够利用碎片化的总线空闲窗口和bank空闲窗口。
  2. **空闲感知调度（Idleness‑aware Scheduling）**：
     - **空闲窗口估计器（IWE）**：通过分析CPU请求队列，预测每个bank和内存总线的未来空闲时间窗口。算法基于FR‑FCFS调度顺序，模拟最下一条请求的服务时间，输出各bank的`window_bank`和总线的`window_bus`。
     - **命令仲裁器**：当CPU请求需要激活行（ACT）时，若该bank空闲窗口足够长，则推迟ACT，先执行PIM；当PIM正在执行而CPU请求到来时，在最晚不延迟CPU的时间点才发送PIM_Pause。
     - **PIM调度器**：在重叠执行阶段，优先调度外部传输命令以充分利用总线空闲，其次调度内部传输命令，最后才执行PIM计算命令。通过将工作负载分块，实现“输入传输(Ti+1)+PIM执行(Ti)+结果收集(Ti-1)”三级流水重叠。
