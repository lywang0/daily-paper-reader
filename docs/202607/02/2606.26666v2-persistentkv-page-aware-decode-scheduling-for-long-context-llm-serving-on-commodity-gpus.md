## 摘要
自回归大语言模型（LLM）服务日益受到键值（KV）缓存移动而非密集矩阵乘法的限制。现代分页注意力系统减少了碎片，而像FlashInfer这样的成熟内核提供了高度优化的解码注意力。然而，最佳的单内核实现并非总是最佳的服务调度方案：低活跃度的长上下文解码可能使GPU利用不足，而混合序列长度则在许多精确长度的启动和粗糙的批量填充之间引入矛盾。  我们提出PersistentKV，一种原生块表解码注意力引擎和面向分组查询注意力（GQA）的页感知调度研究。PersistentKV按KV头组映射工作，直接在原生页表上执行，并添加一个紧凑的工作队列调度，仅执行非空的行-KV头-序列-分割任务。  在RTX 3060（FP16，页大小16，Hq=32，Hkv=8，d=128）上，一个经过校准的类屋顶线策略为小的活跃批次选择FlashInfer，为批量大小1（B1）长上下文步骤选择PersistentKV序列分割，并为支持的B8长上下文GQA步骤选择PersistentKV工作队列调度。在成本模型常数固定于校准轨迹的情况下，五个保留的随机种子在B8双峰、均匀和齐夫型工作负载上平均将墙钟解码令牌吞吐量提高了1.04倍至1.08倍，在B1分桶轨迹上提高了1.40倍。对于B4边界情况和非校准的GQA比率，该策略通过路由到FlashInfer避免了性能退化。我们还报告了一个注意力加MLP时间代理和工作负载计数器，显示工作队列调度将保留的双峰B8上每步的启动扇出从16.00降至2.00。这些结果表明工作分配是一个关键的服务系统变量。

## Abstract
Autoregressive large language model (LLM) serving is increasingly limited by key-value (KV) cache movement rather than dense matrix multiplication. Modern paged-attention systems reduce fragmentation, and mature kernels like FlashInfer provide highly optimized decode attention. However, the best single-kernel implementation is not always the best serving schedule: low-active long-context decode can under-utilize GPUs, while mixed sequence lengths introduce tension between many exact-length launches and coarse padded batches.   We present PersistentKV, a native block-table decode attention engine and page-aware scheduling study for grouped-query attention (GQA). PersistentKV maps work by KV-head group, executes directly over native page tables, and adds a compact workqueue schedule executing only non-empty row-KV-head-sequence-split tasks.   On an RTX 3060 (FP16, page size 16, Hq=32, Hkv=8, d=128), a calibrated roofline-style policy selects FlashInfer for small active batches, PersistentKV sequence splitting for batch size 1 (B1) long-context steps, and PersistentKV workqueue scheduling for supported B8 long-context GQA steps. With cost-model constants fixed on calibration traces, five held-out seeds improve mean wall decode-token throughput by 1.04x to 1.08x on B8 bimodal, uniform, and Zipf-like workloads, and by 1.40x on a B1 bucketed trace. For the B4 boundary case and uncalibrated GQA ratios, the policy avoids regressions by routing to FlashInfer. We also report an attention-plus-MLP timing proxy and workload counters showing workqueue scheduling reduces launch fan-out from 16.00 to 2.00 launches per step on held-out bimodal B8. These results show that work assignment is a decisive serving-system variable.

## 1. 核心问题与整体含义（研究动机和背景）
- **背景**：大语言模型（LLM）自回归推理中，解码阶段的主要瓶颈已从密集矩阵乘法转变为KV缓存移动。现代分页注意力系统（如PagedAttention）减少了KV缓存碎片，FlashInfer等成熟内核提供了高度优化的原生分页解码注意力。然而，**单一内核的顶尖实现并不等同于最优服务调度**：低活跃度（active batch小）的长上下文解码会因GPU SM利用率不足而性能不佳；混合序列长度场景下，精确长度启动（exact-length launch）和粗粒度填充批次之间存在矛盾，导致调度效率低下。
- **核心问题**：能否通过原生块表（native block-table）解码引擎，在已有强基线（FlashInfer）的基础上，进一步改善商品GPU上长上下文LLM服务的吞吐量？**工作分配调度（work assignment scheduling）而非仅注意力计算本身，是服务系统的关键变量**。
- **整体含义**：提出一种自适应的、页感知的调度策略，根据请求状态选择不同的内核调度方式（FlashInfer、PersistentKV序列分割、PersistentKV工作队列），以在不同场景下取得整体最优性能，避免单一方案在所有情况下的性能退化。

## 2. 方法论：核心思想、关键技术细节
- **核心思想**：PersistentKV是一种原生块表解码注意力引擎，针对分组查询注意力（GQA）设计。它按KV头组（KV-head group）映射工作，直接在原生页表（native page table）上执行，无需将KV缓存重排为连续张量。通过引入紧凑工作队列（compact workqueue）调度，仅执行非空的“行-KV头-序列分割”任务，避免批量填充和启动膨胀。
- **关键技术细节**：
  1. **原生块表执行**：KV页以`[physical page, H_kv, page size, d]`形式存储；每个请求拥有块表（block table）逻辑页到物理页的映射。内核使用页访问器逐token索引翻译为物理地址，每次处理32 token的tile，采用在线softmax精确计算。
  2. **序列分割（Sequence Splitting）**：低活跃度解码下，每个请求和KV头仅分配一个CTA（Cooperative Thread Array）不足以利用GPU。因此将序列维度分为S个不相交范围，每个范围计算部分在线softmax状态（m, ℓ, a），然后通过合并内核精确组合。
  3. **行局部有效长度（Row-Local Effective Length）**：分割边界、tile预取等均基于每行真实序列长度`N*_i`而非桶长度，空分割直接返回中性状态，避免填充读取。
  4. **紧凑工作队列调度**：对于每个活跃行`i`、KV头`g`、行局部分割`s`，仅当tile区间非空时发射一个任务。CUDA网格为一维任务列表。第二个合并内核负责分段softmax归约。这避免了长度桶调度中因不同活跃长度导致的多重启动（B8下从16次降至2次），同时保留序列并行。
  5. **校准成本模型**：采用轻量级类屋顶线（roofline）策略，估计每种路由方案的耗时：`T_r = KVBytes / β * max(1, C_min/C_r) + L_r * λ + MergeBytes / β`。其中β为设备拷贝带宽，C_r为估算的CTA工作负载，L_r为启动次数，λ为启动开销（8.19 μs）。路由器使用保守提升阈值：B8需要估计1.05倍加速，B4需要1.50倍或显式标志。未校准的GQA比例（G=1,8）和短上下文（<16K tokens）自动走FlashInfer。
  6. **实现选择**：使用索引Q/O读取、零tile提前退出、紧凑工作队列；CUDA图回放和融合合并（Fused merge）在RTX 3060上并未带来正向收益，作为消融保留。

## 6. 主要结论与发现
- **PersistentKV在低活跃长上下文解码（B1）中有效**：在B1分桶trace上，墙钟解码令牌吞吐量提升1.403 ± 0.065倍（5种子均值）。
- **紧凑工作队列在B8场景中带来正收益**：B8双峰、均匀、齐夫trace上，墙钟吞吐量提升1.044-1.080倍；注意力+MLP代理下提升1.105 ± 0.061倍。
- **调度器启动扇出大幅减少**：从FlashInfer的1次启动，到持久化桶的16次，到工作队列的2次（每个解码步）。
- **B4和未校准GQA（G=1,8）应路由到FlashInfer**：B4无法稳定获益，G=1和G=8需要新的映射才能使用PersistentKV；当前策略通过路由避免退化。
- **工作分配调度是服务系统关键变量**：单个最优内核并非在所有情况下最佳；页面感知调度和紧凑工作队列可以弥补强基线的调度低效。

## 7. 优点
- **聚焦实际瓶颈**：识别出解码阶段KV缓存移动和调度启动开销是主要瓶颈，而非注意力计算本身。
- **方法创新**：原生块表执行+行局部有效长度+紧凑工作队列，避免了填充和启动膨胀，同时保留序列并行。
- **系统级视角**：不追求单一万能内核，而是提出自适应调度策略，根据请求状态选择最合适的内核，是一个健全的工程方案。
- **实验设计严谨**：使用多个随机种子、校准种子与保留种子分离、统一页面布局和正确性检查、包含墙钟和CUDA事件双重计时、提供调度器计数器解释增益来源。
- **可复现性**：提供外部CSV trace接口和重分发测试夹具，方便复现和扩展。
- **消融全面**：研究了CUDA图、融合合并、分割数、GQA比例等，明确了各组件贡献。

## 8. 不足与局限
- **合成trace**：所有实验基于合成trace，未使用真实生产服务日志，可能无法反映实际工作负载模式（如预填/解码干扰、内存压力、请求到达分布）。

- **部分服务栈**：仅测量解码循环，未包含完整transformer层（仅单层注意力+MLP代理）、采样、网络、CPU队列、预填解码混合等生产要素。

- **B4和G=1/8未解决**：B4未能稳定超越FlashInfer；G=1和G=8当前只能路由到FlashInfer，未提供PersistentKV版本来取得正收益。

- **未讨论内存分配真实效应**：合成页面分配使用随机物理页和空洞，未模拟生产分配器的局部性。
- **缺乏统计显著性区间**：虽然报告了标准差，但种子数仅5个，未进行假设检验。
