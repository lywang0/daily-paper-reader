## 摘要
LLM服务日益受到来自智能体、推理模型和扩展对话的长且动态的解码工作负载主导。当突发性长上下文需求超出部署容量时，现有服务系统通常通过启动额外服务实例并复制模型来进行横向扩展。这种实例级弹性仅通过提供模型完整副本来增加KV容量，继承了启动延迟、内存开销和批处理碎片化问题。我们提出KernelFlume，一种以解码为中心的架构，将稳定的投影/FFN路径与核心注意力计算解耦：权重节点执行密集投影/FFN内核，而无权重注意力节点存储令牌范围KV分区并根据请求状态需求进行扩展。为实现这种分离的弹性，KernelFlume维护一个路由表，将令牌范围映射到注意力节点端点。它在令牌边界更新路由，并使用主机可见的图信号在捕获的CUDA图之外驱动预注册的UCX端点通信。为在解耦后保持低每令牌延迟，KernelFlume将查询优先的核心注意力调度与层间内核流水线相结合，使得远程注意力和通信与本地投影/FFN工作重叠。在真实GPU测试平台（节点内A6000和跨节点H100）上，服务于Llama-3.1-8B的动态长上下文智能体工作负载下，KernelFlume在A6000上保持约74 ms的平坦p99 TPOT，在H100上约34 ms，同时相对于使用最先进的实例启动方法ServerlessLLM进行全实例弹性扩展，每百万输出令牌成本分别降低高达32%和61%。在模拟中，对更大模型规模重放相同轨迹，预期比ServerlessLLM降低56-66%的成本，当使用更便宜的异构注意力节点硬件时，成本降低扩大到80-85%，并持续到百万令牌上下文范围。

## Abstract
LLM serving is increasingly dominated by long and dynamic decode workloads from agents, reasoning models, and extended conversations. When bursty long-context demand exceeds deployed capacity, existing serving systems typically scale out by launching additional serving instances with model replicas. This instance-level elasticity increases KV capacity only by provisioning another full copy of the model, inheriting startup latency, memory overhead, and batch fragmentation.   We present KernelFlume, a decode-centric architecture that disaggregates the stable projection/FFN path from core-attention computation: weight nodes execute dense projection/FFN kernels, while weightless attention nodes store token-range KV partitions and scale with request-state demand. To make this separation elastic, KernelFlume maintains a routing table that maps token ranges to attention-node endpoints. It updates routes at token boundaries and uses host-visible graph signals to drive pre-registered UCX endpoint communication outside the captured CUDA Graph. To preserve low per-token latency after disaggregation, KernelFlume combines query-first core-attention dispatch with inter-layer kernel pipelining, overlapping remote attention and communication with local projection/FFN work. On real GPU testbeds (intra-node A6000 and cross-node H100), under a dynamic long-context agentic workload serving Llama-3.1-8B, KernelFlume sustains flat p99 TPOTs of ~74 ms on A6000 and ~34 ms on H100, while lowering cost per million output tokens by up to 32% and 61%, respectively, relative to full-instance elastic scaling with ServerlessLLM, a state-of-the-art instance-startup method. Replaying the same trace at larger model scale in simulation projects a 56--66% cost reduction over ServerlessLLM, widening to 80--85% with cheaper heterogeneous attention-node hardware and persisting into the million-token context range.

## 1. 论文的核心问题与整体含义（研究动机和背景）

- **核心问题**：LLM 服务日益被智能体、推理模型、多轮对话等长上下文解码工作负载主导。这类工作负载中，KV 缓存随着会话持续增长，而模型权重固定不变。现有弹性扩展方法（如 ServerlessLLM）采用全实例复制，即增加一个完整的模型副本，导致：
  - 高启动延迟（实例冷启动需数秒，即使优化后也需 1.1 秒）；
  - 内存效率低，因为每个新实例都携带完整权重，消耗了本可用于 KV 缓存的 HBM；
  - 批处理碎片化，拆分请求后每个实例的批次变小，降低 GEMM 利用率。
- **整体含义**：需要一个更精细的弹性单元——将 KV 容量与模型权重解耦，使 KV 侧能独立、轻量地扩展，从而在不复制权重、不打断解码流的前提下应对突发长上下文需求。

## 2. 论文提出的方法论

### 核心思想
将解码过程中的 **投影/FFN** 与 **核心注意力** 计算分离：
- **权重节点（Weight Nodes, W 节点）**：执行 QKV 投影、FFN、注意力合并等，保持固定权重和较大批次。
- **无权重注意力节点（Attention Nodes, A 节点）**：仅存储令牌范围的 KV 分区并计算局部核心注意力，不携带任何模型权重，可弹性增减。

### 关键技术细节
1. **弹性路由控制平面**：
   - 使用路由表将逻辑令牌范围映射到 UCX 端点句柄，而非固定集体通信组。
   - 路由更新仅在令牌边界执行（7.2 μs），不改变 CUDA Graph、不重新加载模型、不重建通信器。
   - 权重节点 CUDA Graph 仅包含本地计算和主机可见信号写，CPU 轮询线程读取信号、咨询路由表后通过预注册的 UCX 端点发送张量。
2. **查询优先注意力调度（Query-First Attention, QFA）**：
   - 一旦 Q 投影完成，立即将 Q 发送给所有持有历史 KV 的 A 节点，使 A 节点能早开始计算，与权重节点剩余的 K/V 投影重叠。
   - 对于持有最新令牌范围的尾节点，还需等待 (K_new, V_new) 到达后追加再计算。
3. **层间内核流水线**：
   - 将批次拆分为多个微批次（microbatch），权重节点在等待远程注意力结果的同时，可以处理上一个微批次的 FFN 等后注意力工作，使权重节点和注意力节点几乎连续忙碌，逼近 2 倍加速比上限。
4. **弹性缩放策略**：
   - 根据 KV 容量约束（HBM 限制）和 TPOT SLO 约束（带宽驱动）计算每个 A 节点的阈值 C_thresh。
   - 预测当前尾节点填满时间，提前预热新的 A 节点（背景进行 UCX 端点创建、GPU 缓存分配），然后通过路由表发布，实现接近零开销的扩展。

### 公式与算法流程（文字说明）
- **每节点阈值**：C_thresh = min( β_mem * C_kv_cap, β_slo * T_max_A * BW_HBM )，其中 T_max_A 由 SLO 预算除以层数再减去非注意力开销得到。
- **缩放预测**：对每个持有尾节点的 A 节点 i，估计当前增长速率下的填满时间 τ_fill = (C_thresh - b_i) / (n_i * 2H_kv d_h L * 2B)。若 τ_fill * T_step < T_prewarm，则开始后台预热。
- **流水线加速比**：G_pipe = (T_p + T_A + T_f) / max(T_p + T_f, T_A)，其中 T_p 为投影时间，T_f 为后注意力时间，T_A 为注意力侧时间。

## 6. 论文的主要结论与发现

1. **弹性核心注意力扩展有效**：添加无权重 A 节点使总 KV 容量线性增长，而 p99 TPOT 保持平坦（约 72ms 在 A6000 上）。
2. **拓扑切换开销极低**：预预热后的路由安装仅 7.2 μs（scale-up），无需模型加载或通信器重建。
3. **QFA 和流水线显著恢复性能**：QFA 将解耦延迟从最多 11% 降至接近甚至低于非解耦参考（MHA 模型可快 4%）；流水线实现 1.87-1.94 倍加速，接近 2 倍上限。
4. **端到端成本大幅降低**：
   - A6000：比 ServerlessLLM 降低 21-32%；H100：降低 27-61%。
   - 同时保持 100% SLO 达成率，而基线存在欠配置超 SLO 或过配置浪费。
5. **模拟至更大模型**：Llama-70B 成本降低 56-66%；异构节点（H20 做 A 节点）可达 80-85%；百万令牌上下文范围仍保持优势。

## 7. 优点

1. **创新性解耦**：将注意力计算与投影/FFN 在推理阶段内部解耦，比 prefill/decode 解耦更细粒度，更贴合长上下文解码的资源不对称性。
2. **工程实现优雅**：利用路由表 + 主机可见信号 + UCX，在不修改 CUDA Graph 的前提下实现弹性，避免昂贵的通信组重建。
3. **低开销弹性**：路由更新仅微秒级，且缩放策略可预测性预热，使得弹性几乎不影响延迟。
4. **优化全面**：QFA 和层间流水线共同消除了解耦引入的通信开销，使总延迟接近甚至优于非解耦方案。
5. **实验验证充分**：真实硬件（A6000, H100）+ 真实轨迹 + 多种基线对比 + 模拟扩展到更大模型，结果可靠。

## 8. 不足与局限

1. **实验覆盖有限**：
   - 实际端到端仅在 8B 模型、单节点（A6000）或双节点（H100）上运行，更大规模多节点场景仅依赖模拟。
   - 未评估混合工作负载（同时有 prefill 和 decode 混合）下的表现；论文明确将 prefill 独立处理。
2. **潜在偏差风险**：
   - 基线 ServerlessLLM 虽为最先进，但可能未针对本工作负载做最优调度；论文未在对比中调优 ServerlessLLM 的分批策略。
   - 静态基线使用“最强 DP×CP 容量包络”，但可能隐藏了实际部署中常见的调度碎片。
3. **应用限制**：
   - 仅适用于解码阶段，对于需要频繁预填充的场景（如短对话）可能不适用。
   - 当前仅支持序列范围分区（sequence-range partitioning），未来需扩展到混合分区（序列+批次+头）。
   - 依赖 UCX 和 CUDA Graph，对传统 GPU 集群的兼容性可能受限。
4. **未讨论错误处理与恢复**：节点故障时如何迁移 KV 缓存、路由表一致性等问题未提及。
5. **模拟假设较强**：模拟使用线性模型假设通信和计算，实际可能因内存带宽竞争、NUMA 跨节点等引入额外开销。
