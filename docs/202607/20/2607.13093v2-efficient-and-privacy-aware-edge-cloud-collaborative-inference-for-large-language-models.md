## 摘要
设备端大语言模型推理面临响应延迟、硬件资源有限和用户隐私的三难困境。全云推理提供强大算力，但暴露用户提示和对话数据，而独立设备端推理对于大多数消费级和嵌入式边缘设备不可行。本文提出一种基于端点认证KV缓存的以隐私为中心的边缘-云协同LLM推理框架。本地端点处理输入预处理、嵌入计算、自适应特征优化、KV缓存认证、推测解码和低维模型头部计算，而云端进行认证解码器推理、KV缓存管理、令牌验证和高维词汇投影。端点融合部分输出，应用语言自适应掩码并采样目标令牌。所有传输数据和截断logits均经过量化和AES-GCM加密以保护隐私，核心轻量模块、草稿参数和缓存访问策略保留在本地以避免泄露。该框架通过优化流式处理、批处理和量化ONNX部署，支持包括纯CPU、GPU设备和嵌入式设备在内的异构设备。评估表明，与基线分割推理相比，该框架将每令牌延迟降低最多46.1%，下行负载降低最多67.4%，同时保持与全云推理相当的性能。

## Abstract
On-device LLM inference faces a trilemma of response latency, limited hardware resources and user privacy. Full cloud inference delivers strong computing power but exposes user prompts and dialogue data, while standalone on-device inference is unfeasible for most consumer and embedded edge devices. This paper presents a privacy-centric edge-cloud collaborative LLM inference framework built on endpoint-authenticated KV cache. Local endpoints handle input preprocessing, embedding computation, adaptive feature optimization, KV cache authentication, speculative decoding and low-dimensional model head calculation, while the cloud conducts authenticated decoder inference, KV cache management, token verification and high-dimensional vocabulary projection. Endpoints fuse partial outputs, apply language-adaptive masking and sample target tokens. All transmitted data and truncated logits are quantized and AES-GCM encrypted for privacy, with core lightweight modules, draft parameters and cache access policies kept local to avoid leakage. The framework supports heterogeneous devices including CPU-only, GPU-equipped and embedded devices via optimized streaming, batching and quantized ONNX deployment. Evaluations demonstrate that the framework reduces per-token latency by up to 46.1\% and downlink payloads by up to 67.4\% over baseline split inference, retaining comparable performance to full cloud inference.

  - 现有拆分推理（Split Inference）虽然能降低本地计算负担，但缺乏对KV缓存的控制、设备自适应能力和全面的隐私保护机制（仅加密传输不足以防御隐藏状态泄露）。
- **整体含义**：本文提出一种**边缘-云协同的LLM推理框架**，旨在在保持**较低延迟**和**可接受通信量**的同时，**显著降低隐私暴露**，支持多种异构端点（CPU、GPU、嵌入式设备），使部署更实用。

## 2. 论文提出的方法论：核心思想、关键技术细节

### 2.1 核心思想
- 将隐私敏感决策和轻量计算保留在**端点**端，将**重量级解码器计算**交由**云端**执行，并由端点**控制KV缓存授权**。
- 云端只接收特征张量（而非原始文本），端点通过融合部分logits完成最终采样，避免传输完整输出分布。

### 2.2 关键技术细节

#### 1）端点控制的KV缓存授权（KV-cache authorization）
- 端点生成控制元组 `c = (flag_Cache, L_Cache, d_type, ℓ)`，决定是否启用历史KV缓存以及授权长度。云端仅能在授权范围内使用缓存。
- 新会话可禁用缓存重用；进行中会话可缩小授权窗口以满足更高隐私要求。

#### 2）设备自适应特征准备（Device-adaptive feature preparation）
- **纯CPU端点**：将初始隐藏表示按列分成 `N_b` 块，流式传输，解密与计算重叠以隐藏网络延迟。
- **GPU端点**：模型切片、张量并行、本地批处理。
- **边缘设备**：使用ONNX Runtime量化部署（8位），支持硬件加速器。

#### 3）分布式词汇投影（Distributed vocabulary projection）
- 将LM-head的权重矩阵沿隐藏维度分割：`W_lm = [W_end; W_cloud]`，隐藏维度 `D = D_end + D_cloud`。
- 端点计算 `z_end = h_end * W_end`，云端计算 `z_cloud = h_cloud * W_cloud + b`。
- 端点通过逐元素相加重建logits：`z = z_end + z_cloud`。
- 同时引入**语言自适应掩码**：若生成仅限于特定语言（如中文、英文），仅需传输/计算对应词汇子集 `V_ℓ`，可大幅降低下行负载（实验表明减少56%～67%）。

#### 4）端点推测解码与云端验证（Endpoint speculative decoding and cloud verification）
- 端点含有轻量草稿模块 `g_ϕ`，基于云端返回的隐藏状态提出未来 `N`个token（draft length）。
- 云端使用目标模型验证草稿token，接受则加入KV缓存并跳过相应计算，拒绝则从最后一个接受位置重算。
- 草稿长度 `N` 设备自适应：GPU端使用较长草稿（N=5），CPU/边缘使用较短草稿（N=2）。

#### 5）传输保护与隐藏状态保护
- 传输前对张量进行**量化**（默认8位），然后使用**AES-GCM**加密（带关联数据认证）。
- 端点的轻量模块（嵌入、局部投影、草稿模块）使用LoRA适配（低秩矩阵 `∆W=BA`），这些权重**保留在端点本地**，不传输给云端，增加隐藏状态反推难度。
- **注意**：上述措施提供系统层保护，但并非正式差分隐私或安全多方计算。

#### 算法流程（文字说明）
1. 端点对用户输入进行分词、嵌入计算，检测语言标识符，设置缓存控制参数。
2. 端点根据设备类型对特征进行自适应准备，将加密后的张量块和控制元组发送至云端。
3. 云端进行授权的解码器推理（使用或忽略历史KV缓存），返回加密的隐藏状态（或隐藏状态块）。
4. 对于每个生成步骤：
   - 端点计算局部投影分数 `z_end[V_ℓ]`，并生成草稿token序列。
   - 云端计算并返回对应的云端投影分数 `z_cloud[V_ℓ]`。
   - 端点融合logits，应用语言掩码，温度采样得到下一个token。
   - 端点将采样的token和草稿序列发送至云端验证。
   - 云端接受草稿token（更新KV缓存）或拒绝（重算）。
5. 直至遇到终止条件（eos或最大长度）。

### 2.3 公式
- 隐藏表示：`h_0 = E_tok(u) + E_pos(p) + E_type(t)`
- 投影分割：`W_lm = [W_end; W_cloud]`，`z = h_end W_end + (h_cloud W_cloud + b)`
- 语言掩码后采样：`p(y_t | ...) = softmax(̃z/τ)`，其中`̃z_i = z_end,i + z_cloud,i`（若`i∈V_ℓ`），否则 `-∞`。
- LoRA更新：`W = W_0 + BA`（`A∈R^{r×d}, B∈R^{d×r}`）

## 6. 论文的主要结论与发现
1. **延迟降低显著**：与朴素拆分推理相比，每token延迟降低26.8%～46.1%。绝对延迟在CPU端151.4 ms/token，GPU端96.0 ms/token，边缘端164.0 ms/token。

5. **隐私暴露减少**：框架避免发送原始提示、完整日志、本地模块权重；仅传输必要的加密特征张量和缓存控制参数。但并非形式化隐私保证。
