## 摘要
设备端的大语言模型推理面临响应延迟、硬件资源有限和用户隐私的三难困境。全云推理提供强大算力，但暴露用户提示和对话数据，而独立设备端推理对大多数消费类和嵌入式边缘设备不可行。本文提出一个以隐私为中心的边缘云协同LLM推理框架，基于端点认证的KV缓存。本地端点处理输入预处理、嵌入计算、自适应特征优化、KV缓存认证、推测解码和低维模型头部计算，而云端执行认证解码器推理、KV缓存管理、令牌验证和高维词汇投影。端点融合部分输出，应用语言自适应掩码并采样目标令牌。所有传输数据和截断的logits被量化并通过AES-GCM加密以保护隐私，核心轻量级模块、草稿参数和缓存访问策略保留在本地以避免泄露。该框架通过优化流式传输、批处理和量化ONNX部署，支持异构设备，包括仅CPU、配备GPU和嵌入式设备。评估表明，与基线拆分推理相比，该框架将每令牌延迟降低高达46.1%，下行有效载荷降低高达67.4%，同时保持与全云推理相当的性能。

## Abstract
On-device LLM inference faces a trilemma of response latency, limited hardware resources and user privacy. Full cloud inference delivers strong computing power but exposes user prompts and dialogue data, while standalone on-device inference is unfeasible for most consumer and embedded edge devices. This paper presents a privacy-centric edge-cloud collaborative LLM inference framework built on endpoint-authenticated KV cache. Local endpoints handle input preprocessing, embedding computation, adaptive feature optimization, KV cache authentication, speculative decoding and low-dimensional model head calculation, while the cloud conducts authenticated decoder inference, KV cache management, token verification and high-dimensional vocabulary projection. Endpoints fuse partial outputs, apply language-adaptive masking and sample target tokens. All transmitted data and truncated logits are quantized and AES-GCM encrypted for privacy, with core lightweight modules, draft parameters and cache access policies kept local to avoid leakage. The framework supports heterogeneous devices including CPU-only, GPU-equipped and embedded devices via optimized streaming, batching and quantized ONNX deployment. Evaluations demonstrate that the framework reduces per-token latency by up to 46.1\% and downlink payloads by up to 67.4\% over baseline split inference, retaining comparable performance to full cloud inference.

## 1. 论文的核心问题与整体含义

- **三难困境**：大语言模型在用户端设备部署面临 **低延迟**、**有限本地计算资源** 和 **用户隐私暴露** 之间的根本矛盾。
- **现有方案缺陷**：纯云推理暴露原始提示和对话历史；纯端侧推理在消费级CPU/GPU/嵌入式设备上不可行。
- **整体意义**：提出一个 **隐私感知的边缘-云协同推理框架**，核心在于将隐私敏感决策和轻量计算保留在端点，而将繁重的解码器计算交给云端，且由端点控制缓存访问授权，在不显著牺牲质量的前提下降低延迟和通信开销。

## 2. 论文提出的方法论

### 核心思想
- **端点认证KV缓存**：端点决定是否允许使用历史KV缓存及授权长度，避免不必要的上下文泄露。
- **分布式词汇投影**：将LM head按隐藏维度拆分为低维（端点计算）和高维（云端计算）两部分，端点融合后采样。
- **语言自适应词汇剪枝**：仅传输生成语言对应的词汇子集logits，减少下行传输量。
- **端点推测解码**：轻量草稿模块提出未来令牌，云端验证接受，减少交互轮次。
- **设备自适应执行**：CPU采用块流式传输，GPU采用模型切片和张量并行，边缘设备使用量化ONNX Runtime。
- **安全传输**：所有张量和logits量化后经AES-GCM加密；端点本地LoRA模块参数不传输。

### 关键技术细节
- **控制元组**：`c = (flag_Cache, L_Cache, d_type, ℓ)` 控制缓存授权、设备类型、语言标识。
- **分布式投影公式**：
  - 端点：`z_end = h_end * W_end`
  - 云端：`z_cloud = h_cloud * W_cloud + b`
  - 融合：`z = z_end + z_cloud`，然后语言掩码，温度采样。
- **推测解码**：草稿模块生成N个令牌，云端验证后接受或回退，维护KV缓存一致性。
- **量化加密**：`q = Qb(r)` → `C = AES-GCM(K, IV, q, aad)`。

### 算法流程
1. 端点tokenize输入，检测语言，设置控制元组。
2. 端点根据设备类型适配特征张量并加密发送。
3. 云端按授权使用缓存，执行解码器推理，返回隐藏状态。
4. 端点计算局部投影和草稿令牌，云端计算高维投影并返回部分logits。
5. 端点融合logits，语言掩码，采样令牌，发送令牌和草稿序列给云端验证。
6. 云端提交接受令牌，必要时回退重算，更新KV缓存。

## 6. 论文的主要结论与发现

- **延迟提升**：每令牌延迟比Naive split inference降低最多46.1%（GPU端点），CPU端点29.4%，边缘26.8%。
- **带宽节省**：英文独占下行负载降低67.4%，中文降低56.2%~57.6%。

- **组件贡献**：推测解码对延迟降低最关键，语言剪枝主要节省带宽，拆分投影和块流式均有贡献。
- **隐私改善**：避免传输原始提示、历史ID、全logits和端点私有参数，但云端仍可见必要特征张量，不提供正式差分隐私保证。

## 7. 优点

- **系统级隐私设计**：将缓存授权、局部模块、加密传输、语言剪枝等多层防护集成到架构中。
- **异构设备适配**：CPU/GPU/边缘各有针对性的优化策略（块流式、模型切片、ONNX），实用性强。
- **可配置性与权衡**：拆分维度、推测长度、缓存授权均可调，适应不同隐私-性能需求。
- **实验设计完整**：对比baseline、消融、敏感度分析、生成质量、隐私暴露对比，分析严谨。
- **性能平衡佳**：在接近全云模型质量的前提下显著降低延迟和带宽，优于朴素拆分推理。

## 8. 不足与局限

- **安全性有限**：仅抗半诚实云，不防恶意云，无差分隐私或MPC的正式保证，云端仍可能逆向推断特征张量。
