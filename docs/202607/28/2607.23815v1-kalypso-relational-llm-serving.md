## 摘要
大型语言模型越来越多地被用作语义操作符，用于过滤、提取、排序、连接和转换非结构化数据。现有的语义查询处理系统调用的是以请求为中心的LLM服务系统，这些系统不了解查询计划，因此留下了大量未利用的性能机会。本文引入了关系型LLM服务，这是一种抽象，使LLM服务能够感知语义查询结构，同时保留查询语义和输出准确性。关键机会是跨语义操作符的流水线执行：当中间元组直接从某个操作符流向下一个操作符时，其KV缓存状态可以被重用，而无需重新计算。我们提出了Kalypso，一个关系型LLM服务系统，它公开了语义查询计划的API，并使用一种自适应、内存感知的调度算法来执行这些计划。Kalypso解决了一个新的在线调度问题，其中流水线操作符执行与GPU内存压力管理相结合，以在驱逐前重用服务引擎中的KV缓存状态。其调度器持续调整内存分配，以平衡上游并行性、下游进度和GPU利用率。我们的评估显示，与使用以请求为中心的LLM服务的基线相比，Kalypso改善了查询完成时间，在不同工作负载下加速比高达4.57倍，表明查询感知的LLM服务可以显著提高语义查询执行的效率。

## Abstract
Large language models are increasingly used as semantic operators for filtering, extracting, ranking, joining, and transforming unstructured data. Existing semantic query processing systems invoke request-centric LLM serving systems that are unaware of the query plan, leaving substantial performance opportunities unused. This paper introduces relational LLM serving, an abstraction that makes LLM serving aware of semantic query structure while preserving query semantics and output accuracy. The key opportunity is pipelined execution across semantic operators: when intermediate tuples flow directly from one operator to the next, their KV-cache state can be reused instead of recomputed.   We present Kalypso, a relational LLM serving system that exposes an API for semantic query plans and executes them using an adaptive, memory-aware scheduling algorithm. Kalypso addresses a new online scheduling problem in which pipelined operator execution is coupled with GPU memory pressure management to reuse KV-cache state in the serving engine before eviction. Its scheduler continuously adjusts memory allocations to balance upstream parallelism, downstream progress, and GPU utilization. Our evaluation shows that Kalypso improves query completion time over baselines using request-centric LLM serving, with speedups up to 4.57x across diverse workloads, demonstrating that query-aware LLM serving can substantially improve the efficiency of semantic query execution.

#### 1. 核心问题与整体含义（研究动机和背景）
-   **核心问题**：现有的语义查询处理系统（Semantic Query Processing Systems, SQPS）在调用大型语言模型（LLM）执行语义操作符（如过滤、提取、排序）时，采用的是一种“以请求为中心”（request-centric）的LLM服务范式。这种服务系统不了解底层的查询计划（query plan），导致中间元组在跨操作符流动时，其KV缓存（KV-cache）状态无法被有效重用，造成大量的重复计算和GPU内存资源浪费。
-   **整体含义**：本研究旨在弥合“语义查询处理”与“LLM服务”之间的鸿沟。作者提出“关系型LLM服务”（relational LLM serving）这一新范式，即让LLM服务引擎感知查询计划的结构，从而利用跨操作符的流水线执行（pipelined execution）来提升KV缓存的命中率，最终显著提高语义查询的执行效率。

#### 2. 方法论：核心思想、关键技术细节与算法
-   **核心思想**：通过将LLM服务从“请求感知”升级为“查询感知”，实现语义操作符之间的流水线执行和KV缓存状态重用。当中间元组直接由上游操作符传递给下游操作符时，其共享的Prompt前缀所对应的KV缓存可以被直接复用，无需重新计算。
-   **关键技术细节**：
    -   **API设计**：提出一个通用API，允许SQL风格的SQPS（如Lotus）注册其语义操作符。每个操作符需要声明三个属性以支持调度：是否可流水线化（Pipelining）、是否为过滤谓词（Predicate）、是否生成笛卡尔积（Cartesian Product）。
    -   **查询执行模型**：将查询计划中的操作符分组为“阶段”（Stages，由笛卡尔积操作符分隔），每个阶段对一个输入元组的执行构成一个“任务”（Task）。
    -   **自适应内存感知调度算法**（核心贡献）：解决一个全新的在线调度问题，即在有限的GPU KV缓存容量下，平衡上游并行度、下游进度和GPU利用率。
        -   **算法1**描述了单流水线的调度流程。核心步骤包括：
            1.  **启动任务 (Launch)**：在某个阶段有可用内存预算时，从等待队列中取出任务并执行。
            2.  **完成任务 (Complete)**：
                -   *令牌重试*：若任务因超出预估的Token上限而被中断，则增加预算后重新入队。
                -   *笛卡尔积执行*：如果当前阶段不是最后一个，则执行笛卡尔积，生成下游子任务并放入下一阶段的队列。
                -   *内存追踪与释放*：追踪父子任务依赖关系，只有当所有子任务都完成时，才释放父任务的内存。
            3.  **重新平衡预算 (Rebalance)**：持续监控每个阶段的等待队列长度。根据预定义的高、低阈值，判断阶段是处于“饥饿”（starving，队列过短，需要为上游分配更多内存）还是“饱和”（saturated，队列过长，需要为下游分配更多内存）。然后动态地在阶段间转移内存预算，例如从饱和阶段转移到最后一阶段，或从下游“饥饿”阶段转移给上游。
    -   **内存管理机制**：
        -   **Token上限估计**：通过在线监控，使用99分位的输出/输入Token比率作为预估预算，避免过度预留或频繁重试。
        -   **虚拟钉选与显式钉选**：提供两种避免缓存驱逐的机制。虚拟钉选仅靠调度控制，无需LLM服务引擎支持；显式钉选则直接锁定缓存块，但可能引入死锁。
        -   **死锁检测与恢复**：调度器定期检查LLM服务引擎内部是否有请求在等待但无请求在运行，若检测到死锁，则解除所有钉选，临时切换到虚拟钉选模式。
