## 摘要
大型混合专家（MoE）语言模型对端侧部署具有吸引力，因为每个词元仅激活少量专家，但路由专家权重常常超出加速器内存。我们针对延迟关键的单用户场景，其中路由专家按需从CPU内存加载到GPU或从闪存加载到移动NPU。在此场景下，自推测解码面临新的瓶颈：增加草案专家集可提升准确率但引入额外专家加载，而廉价的小规模草案接受率低；此外，验证多词元块会激活目标专家的并集，不再接近单步目标。我们提出DraftExpert，一种面向专家卸载MoE推理的扩展感知自推测解码框架。DraftExpert通过从冻结的目标MoE自蒸馏残差、logit/词元和路由一致信号，为每层训练一个轻量级常驻加速器的草案专家。推理时，它使用固定规模的共享+top-1+草案专家起草器，结合置信度-扩展截断和目标专家预取，同时最终词元仍由目标模型精确验证。在DeepSeek-V2-Lite和Moonlight-16B-A3B上，跨CPU-GPU和闪存-NPU卸载，DraftExpert平均提升解码吞吐量1.45倍，将草案接受率提高到84~87%，并实现86~88%的预取命中率。

## Abstract
Large Mixture-of-Experts (MoE) language models are attractive for end-device deployment because only a small subset of experts is active per token, but their routed expert weights often exceed accelerator memory. We target latency-critical single-user settings where routed experts are staged on demand from CPU memory to a GPU or from Flash to a mobile NPU. In this setting, self-speculative decoding faces a new bottleneck: increasing the draft expert set improves accuracy but triggers extra expert loading, while cheap small-footprint drafts have low acceptance; moreover, verifying a multi-token block activates the union of target experts and is no longer close to one target step. We propose DraftExpert, an expansion-aware self-speculative decoding framework for expert-offloaded MoE inference. DraftExpert trains one lightweight accelerator-resident draft expert per layer by self-distilling residual, logit/token, and router-agreement signals from the frozen target MoE. At inference time, it uses a fixed-footprint shared+top-1+draft-expert drafter together with confidence--expansion truncation and target-expert prefetching, while final tokens are still exactly verified by the target model. On DeepSeek-V2-Lite and Moonlight-16B-A3B across CPU-GPU and Flash-NPU offload, DraftExpert improves decode throughput by 1.45x on average, raises draft acceptance to 84~87%, and achieves 86~88% prefetch hit rates.

## 1. 核心问题与整体含义（研究动机和背景）

- **背景**：大型 MoE 语言模型因每个 token 仅激活少量专家（如 DeepSeek-V2-Lite 中每个 token 激活 top-6/64），适合部署在端侧设备。但路由专家占模型总参数量 90% 以上，超过加速器内存（如 GPU 24GiB 或移动 NPU 共享 DRAM），因此必须将路由专家卸载到 CPU 内存或 Flash 并按需加载。
- **核心问题**：在端侧专家卸载场景下，自推测解码（Self-Speculative Decoding）的三个经典条件（草案廉价、验证接近单步、高接受率）均被打破：
    - **草案廉价**：增大草案 top-r 路由专家数（如 top-2、top-3）虽提升准确率，但加载更多卸载专家，草案速度下降（从 top-1 的 4.7× 降至 top-3 的 2.0×）。
    - **验证接近单步**：多 token 验证块会激活目标专家并集，专家加载成本随块长增长（K=16 时验证成本升至单步 5.8×）。
    - **高接受率**：廉价的 top-1 草案接受率仅 22%，即使 top-3 草案接受率也不足 50%。
- **研究目标**：提出一种扩展感知的方案，优化“每个新加载专家对应的接受 token 数”，同时保持草案固定开销、控制验证扩展、恢复高接受率。

## 2. 方法论

### 核心思想
- 用**固定开销的草案路径**（共享路径 + top-1 路由专家 + 每层的轻量级草案专家）替代传统的 top-r 路由草案，草案专家通过**自蒸馏**从冻结的目标 MoE 中学习缺失路由专家的残差、logits 和路由器对齐信息。
- 推理时结合**置信度-扩展动态截断**（当草 token 低置信且边际专家扩展量高时停止起草）和**草案路由器预取**（提前加载预测的目标验证专家），精确验证不变。

### 关键技术细节
1. **固定开销草案路径**：
    - 每 MoE 层添加一个常驻加速器的草案专家 \(E_l^d\)，草案输出为：
      \[
      y_l^d = S_l(h_l) + g_{l,e_1}E_{l,e_1}(h_l) + \gamma_l E_l^d(h_l)
      \]
      其中 \(e_1\) 为 top-1 路由专家。仅草案专家和可学习标量 \(\gamma_l\) 可训练。
2. **自蒸馏训练**：
    - **残差损失**：草案专家拟合缺失路由专家残差 \(m_{l,t}^*\)。
    - **logit/token 损失**：蒸馏目标 logits 分布和 top-1 token。
    - **路由器一致性损失**：使草案隐藏状态下的路由器分布接近目标隐藏状态下的路由器分布，提升预取准确性。
    - 总损失：\(\mathcal{L} = \mathcal{L}_{\text{logit}} + \alpha\mathcal{L}_{\text{tok}} + \beta\mathcal{L}_{\text{res}} + \eta\mathcal{L}_{\text{router}}\)。
3. **推理策略**：
    - **置信度-扩展截断**：对于第 i 个草案 token，若置信度 \(q_i < \tau\) 且边际专家扩展量 \(\Delta_i > B_i\)（预算），则停止起草。
    - **专家预取**：根据草案路由器预测的验证专家集，异步预取不在缓存中的目标专家，与后续草案计算重叠。
    - 所有最终 token 仍由冻结的目标 MoE 精确验证。（见算法 1）
