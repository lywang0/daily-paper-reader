## 摘要
Apple Silicon SoC通过统一内存系统共享CPU、GPU和神经网络引擎，这引出了一个问题：通过跨单元拆分单个算子能否加速Transformer推理？先前的尝试（包括我们自己的）要么失败，要么产生了混淆精度的胜利。我们找到了原因：MLX的惰性图调度器在单个求值图内，当CPU流操作消费未物化的GPU结果时，会串行化跨流工作；因此，使用物化输入运行速度快1.38倍的行分割矩阵乘法，在惰性图内部反而比纯GPU慢0.66倍；而积极的物化边界恢复了并发性（1.34倍）。基于这一修复，\sys{}实现了面向Transformer预填充的、逐层且考虑争用的CPU+GPU行分割。在五款芯片和三代Apple Silicon上评估（社区复现），该分割方法使Llama结构的解码器块预填充加速1.15–1.38倍（在全32块深度下保持不变），并在通过标准MLX-LM服务的真实Qwen2.5-7B检查点上实现1.18–1.25倍的首令牌延迟加速，输出令牌一致且解码吞吐量不变。我们同样仔细刻画了边界：解码无法受益，受限于共享带宽，协同执行不会增加；精度匹配的训练在全部五款芯片上损失0.86–0.97倍；ANE调度开销使其无法在层粒度使用；在内存压力下，无退化的运行时门控变得自我挫败，因为探测替代模式会驱逐活动模式的工作集。代码、原始结果和生成记录已发布。

## Abstract
Apple-Silicon SoCs share CPU, GPU, and Neural Engine over one unified memory system, raising the question of whether transformer inference can be accelerated by splitting single operators across units. Prior attempts, including our own, failed or produced precision-confounded wins. We identify the cause: MLX's lazy-graph scheduler \emph{serializes} cross-stream work whenever a CPU-stream operation consumes an unmaterialized GPU result inside one evaluation graph, so a row-split matmul that runs \x{1.38} faster with materialized inputs runs \x{0.66} slower than GPU-only inside a lazy graph; an eager materialization boundary restores concurrency (\x{1.34}). \sys{} implements a per-layer, contention-aware CPU+GPU row split for transformer prefill built on this fix. Evaluated across five chips and three Apple-Silicon generations, community-replicated, the split accelerates Llama-shaped decoder-block prefill by \x{1.15}--\x{1.38}, unchanged at full 32-block depth, and reaches \x{1.18}--\x{1.25} faster time-to-first-token on a real Qwen2.5-7B checkpoint served through stock MLX-LM, with token-identical outputs and unchanged decode throughput. We characterize the boundaries equally carefully: decode cannot benefit, bound by shared bandwidth co-execution does not add; precision-matched training loses \x{0.86}--\x{0.97} on all five chips; ANE dispatch overhead excludes it at layer granularity; and a no-regression runtime gate becomes self-defeating under memory pressure, where probing an alternative mode evicts the active mode's working set. Code, raw results, and generation transcripts are released.

## 1. 论文的核心问题与整体含义（研究动机和背景）
- **动机**：Apple Silicon SoC（如M系列）采用统一内存架构，CPU、GPU和Neural Engine共享物理内存，这为在单个算子内部跨单元并行计算提供了可能性（例如将矩阵乘法的行在CPU和GPU上同时计算）。然而，前人尝试（包括作者自己）要么失败，要么因精度不匹配（如FP16对比FP32）而误报加速。核心问题在于：**这种intra-operator的CPU+GPU协同执行在统一内存平台上是否真正有效？其机制和边界是什么？**
- **背景**：MLX是Apple的数组框架，采用惰性图求值。作者发现Lazy-graph调度器在CPU操作依赖GPU未物化结果时会**序列化**跨流工作，导致协同执行反而更慢。这是问题的根源。

## 2. 论文提出的方法论：核心思想、关键技术细节
- **核心思想**：通过引入**急切物化边界**来修复MLX惰性图的序列化问题，实现CPU+GPU在prefill阶段的真正并发。具体提出FusionML系统，仅作用于prefill（预填充）阶段，decode阶段不做拆分。
- **关键技术细节**：
  - **逐层行分割**：每个decoder block中的线性层（QKV投影、门/上/下投影等）按行分割；CPU流计算前ρM行，GPU流计算剩余行，结果拼接。Attention和归一化等操作留在GPU。
  - **竞争感知的比例校准**：比例ρ通过在实际并发执行下测量候选网格（ρ ∈ {0,0.10,…,0.50}）确定，而非基于单单元吞吐量（因为并发时GPU自身吞吐量会因共享带宽而下降）。
  - **无退化运行时门控**：维护三个竞争模式（split、编译基线、急切基线），通过短时试用选最快模式，并定期重探测（每10次调用，指数移动平均跟踪，3%切换滞后）。由于基线执行路径本身就是门控的一个分支，因此理论上性能下限不会低于基线（减去探测开销）。
- **算法流程**（文字说明）：
  1. 对于每个prefill层的线性算子，读取输入张量。
  2. 执行`mx.eval`（急切物化边界）以确保输入已就绪。
  3. 根据校准的ρ将输入行分成两部分，CPU流和GPU流分别执行矩阵乘法。
  4. 等待两流完成，拼接结果。
  5. 后续算子（如Attention）继续在GPU上执行。
  6. 运行时门控在多次调用后自适应选择最快速模式（split/baseline）。

## 6. 论文的主要结论与发现
- **prefill阶段CPU+GPU协同有效**：块级加速1.15–1.38×（主动散热芯片所有序列长度获胜），全32块深度基本不变（1.12-1.24×）。端到端TTFT加速1.18–1.25×，输出令牌基本一致（仅一次因FP16约序差异产生轻微分歧），解码吞吐量中性。
- **decode阶段无效**：由于共享带宽限制，协同执行无法增加带宽，反而增加竞争。
- **精度匹配的训练反而变慢**：0.86–0.97×（在所有芯片上），先前声称的训练加速是FP16 vs FP32的假阳性。
- **ANE（神经引擎）因调度开销和崩溃问题**无法用于层粒度协同（固定开销20–24ms + 7μs/row）。
- **内存压力下运行时门控出现“观察者效应”**：探测替代模式会驱逐当前工作集，导致测量偏差和重载代价，连续探测不可行。
