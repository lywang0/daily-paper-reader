## 摘要
预填充-解码分离（PD）和基于屋顶线的算子放置是将大语言模型（LLM）推理划分到异构系统上的常见策略，但在实践中往往不够充分。端到端延迟还取决于工作负载形状、运行时设备争用以及持久权重布局。我们提出了DOPS（动态算子调度），这是一个硬件感知的闭环框架，联合优化算子调度和分块权重布局。DOPS构建了一个阶段感知的有向无环图（DAG），并集成了两个组件：用于动态算子到设备分配的双焦点调度器（Bifocal），以及用于在严格内存约束下选择硬件高效权重布局的权重布局仲裁器（WLA）。在结合神经处理单元（NPU）和存内处理（PIM）设备的代表性异构系统上，Bifocal相对于PD基线实现了1.20倍到2.23倍的几何平均加速。WLA相对于Bifocal/Linear提供了额外的1.28倍到1.33倍的几何平均加速。DOPS还支持对LLM服务的工作负载敏感性和硬件可扩展性进行系统分析。源代码可在https://github.com/YIAI-02/TriForm获取，可视化工具演示见https://youtu.be/Ya_oMCyYno0。

## Abstract
Prefill-decode disaggregation (PD) and roofline-based operator placement are common strategies for partitioning Large Language Model (LLM) inference across heterogeneous systems, but they are often insufficient in practice. End-to-end latency also depends on workload shape, runtime device contention, and persistent weight layout. We present DOPS (dynamic operator scheduling), a hardware-aware, closed-loop framework that jointly optimizes operator scheduling and blockwise weight layouts. DOPS constructs a stage-aware directed acyclic graph (DAG) and integrates two components: the Bifocal scheduler for dynamic operator-to-device placement and the Weight Layout Arbiter (WLA) for selecting hardware-efficient weight layouts under strict memory constraints. Across representative heterogeneous systems combining neural processing units (NPUs) and processing-in-memory (PIM) devices, Bifocal achieves geometric-mean speedups of 1.20$\times$ to 2.23$\times$ over the PD baseline. WLA provides an additional geometric-mean speedup of 1.28$\times$ to 1.33$\times$ over Bifocal/Linear. DOPS also supports systematic analysis of workload sensitivity and hardware scalability for LLM serving. The source code is available at https://github.com/YIAI-02/TriForm, and the visualization tool is demonstrated at https://youtu.be/Ya_oMCyYno0.

## 1. 论文的核心问题与整体含义（研究动机和背景）

- **背景**：大语言模型（LLM）推理面临服务成本和延迟挑战，尤其在资源受限的边缘平台。预填充阶段（Prefill）和自回归解码阶段（Decode）具有截然不同的计算特性：Prefill 算术强度高，Decode 则频繁流式加载权重和不断增长的 KV 缓存。为此，现有系统常采用预填充-解码分离（PD）策略将两个阶段分配到不同设备，并结合基于 Roofline 模型的静态算子放置规则。
- **核心问题**：然而，静态的 PD 分离和 Roofline 放置忽略了三个关键因素：**工作负载形状**（预填充/解码长度、批大小）、**运行时设备争用**（队列等待、资源竞争）以及**持久权重布局**（不同设备偏好不同的物理排布）。这些因素导致实际端到端延迟远非最优。实验表明（图 1b），即使固定模型和硬件，最佳算子-设备映射也随工作负载参数发生变化，没有任何单一静态策略能全局占优。此外，权重布局与算子放置高度耦合：不同设备需要不同的 tiling 格式，单副本会导致运行时重排开销，而双副本又超出边缘内存预算。
- **研究意义**：本文提出 **DOPS**（Dynamic Operator Scheduling），一个硬件感知的闭环框架，联合优化动态算子调度和块级权重布局，用于解决 NPU–PIM 异构系统上 LLM 推理的端到端延迟最小化问题，同时提供系统瓶颈分析和硬件可扩展性评估工具。

## 2. 论文提出的方法论：核心思想、关键技术细节

### （1）整体框架
DOPS 输入三部分：LLM 模型卡片（支持量化和稀疏化等优化）、硬件抽象（含性能模型和通信拓扑）、工作负载配置（长度、批大小、目标 SLO）。框架构建一个**阶段感知的有向无环图（DAG）**，每个顶点代表一个可调度算子（可融合或分片），边表示数据依赖和通信开销。在 DAG 上，两个内置优化引擎协同工作：**Bifocal 动态算子调度器**决定每个算子放在哪个设备并生成执行时间线；**Weight Layout Arbiter (WLA)** 选择每个权重块的存储格式。输出为算子-设备映射、优化后的布局和模拟延迟，最后通过闭环验证部署。

### （2）Bifocal 动态调度器
Bifocal 是一个启发式列表调度器，采用 **双焦点评分函数** 为每个就绪算子选择一个设备，使得端到端 makespan 最小：

\[
\text{Score}(v,k) = C_{\text{near}}(v,k) + C_{\text{far}}(v,k)
\]

其中：
- **近焦点项** \(C_{\text{near}} = (1-\gamma)\text{EFT} + \gamma\hat{T}_H\)：  
  - EFT 是当前设备最早完成时间（考虑前驱到达、设备可用性、算子执行时间和缓存引起的权重重载惩罚）。  
  - \(\hat{T}_H\) 是通过在短后继窗口（最多 H 个顶点）内执行轻量仿真得到的下游影响估计，避免局部最优。
- **远焦点项** \(C_{\text{far}} = B_{\text{phase}} + B_{\text{token}}\)：  
  - \(B_{\text{phase}}\) **阶段复用偏差**：保持同一权重块在多个步骤中被相同设备消费的倾向，减少迁移开销；在预填充阶段还能对总容量足以容纳全部权重的设备给予负偏置（即奖励）。  
  - \(B_{\text{token}}\) **令牌摊销偏差**：在解码阶段，将当前单次开销与假设重复使用同一放置时未来剩余令牌的平均开销比较，允许为远期收益接受近期额外代价。

算法流程（Algorithm 1）：初始化就绪集，对每个就绪算子遍历合法设备计算 Score，选出最小 Score 的 (算子, 设备) 对提交，更新系统状态（设备可用时间、缓存状态、近远期提示图），重复直到 DAG 结束。

### （3）Weight Layout Arbiter (WLA)
WLA 优化块级权重格式映射 \(\phi: \mathcal{B} \to \mathcal{F}\)（\(\mathcal{F}=\{\text{Linear, NPU\_OPT, PIM\_OPT}\}\)），目标是最小化 Bifocal 在当前布局下的预测 makespan \(T(\phi)\)。采用**两阶段块坐标搜索**：
- **外层阶段（优势分配）**：基于上一轮调度产生的逐块装载压力（\(\tilde{\ell}_{b,\text{NPU}}\) 与 \(\tilde{\ell}_{b,\text{PIM}}\)），为每个块分配一个粗粒度的更优格式（NPU\_OPT / PIM\_OPT / Linear）。
- **内层阶段（目标精炼）**：对当前映射中仍与装载行为不一致的候选块，分别尝试其余两种格式，仅接受能降低预测 makespan 超过阈值 \(\epsilon\) 的翻转。交替进行，直至收敛或达到预算。

初始化全 Linear，全程依赖 Bifocal 的调度结果作为反馈。

## 6. 论文的主要结论与发现

1. **动态调度远优于静态规则**：Bifocal 在全部 64 个工作负载上均优于 PD 基线，几何平均加速比达到 1.20×–2.23×（不同模型-平台组合），而静态策略（AF、PD+FFN 等）常有部分配置劣于 PD。
2. **权重布局优化是重要补充**：在固定 Bifocal 调度下，WLA 选择混合布局（Linear + NPU\_OPT + PIM\_OPT）相比全 Linear 额外提供 1.28×–1.33× 几何平均加速，且无需双副本内存翻倍，尤其对短序列收益更大。
3. **Bifocal 的三个关键组件皆贡献显著**：
   - 阶段复用偏差（\(B_{\text{phase}}\)）：移除后延迟增加 7%–10%。
   - 令牌摊销偏差（\(B_{\text{token}}\)）：对于长解码，移除后延迟增加 16%–25.6%。
   - DAG 窗口 lookahead（\(\hat{T}_H\)）：对 Qwen-1.8B 移除后延迟增加 6.4%–11.8%。
4. **硬件扩展边际收益遵循规律**：更长的预填充/解码长度、更大的批大小以及更大的模型规模，都会将最高边际收益的 PIM 容量点推向更高端配置。
5. **BurstGPT 追踪实验验证实际服务优势**：Bifocal 同时改善中位数和尾部 TTFT、TBT、端到端延迟。

## 7. 优点

- **问题定义新且切实**：将 LLM 异构推理建模为耦合的调度-布局优化问题，超越了简单 PD 分离和 Roofline 规则。
- **算法创新**：Bifocal 的双焦点评分巧妙地结合本地最优和远期影响，尤其是 token 摊销偏差利用了解码自回归特性；WLA 的两阶段搜索高效。
- **系统完整性**：DOPS 是端到端闭环框架，从输入、建模、优化到验证部署，并提供可视化工具。
- **实验全面且严谨**：大规模扫描、消融、扩展性、追踪驱动，且验证对比显示模拟精度高。
- **开源**：代码和工具公开，便于复现和进一步开发。
- **对硬件-软探探讨有价值**：通过硬件扩展分析，为 PIM 容量配置提供定量指导。

## 8. 不足与局限

1. **实验验证覆盖有限**：真实硬件验证仅针对 Qwen-1.8B 和 Llama-7B 的部分配置，对于更大模型（如 Llama-70B）以及更多 PIM 设备（如 HP128）的验证仅停留在模拟层，可能存在模拟与实际差距未完全排查。
2. **局限于 NPU–PIM 架构**：框架理论上可扩展，但实验仅覆盖 Ascend NPU + GDDR6-PIM 这一特定组合，未评估其他异构系统（如 GPU+PIM、CPU+NPU 等）。
3. **调度器搜索开销**：论文未量化 Bifocal 搜索的计算时间或内存开销。在离线部署场景下可接受，但若用于在线调度（如追踪实验中的批量服务）可能需考虑实时性（论文中使用 Bfinish-time 离线优化，实际在线通过复用了静态策略）。
4. **权重布局格式有限**：仅考虑三种静态格式，未探索更灵活的动态格式变换或自适应压缩。
5. **假设权重加载可完全重叠计算**：在性能模型中假设计算与重量加载可完全重叠，现实硬件中可能因资源竞争无法达到。
6. **未考虑 KV 缓存专用优化**：虽然 KV 缓存默认置于 PIM，但未深入探索其布局优化对性能的影响。
