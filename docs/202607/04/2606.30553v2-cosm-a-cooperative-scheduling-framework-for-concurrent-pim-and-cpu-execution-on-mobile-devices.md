## 摘要
设备上大语言模型（LLMs）的发展由隐私保护和快速响应时间的需求驱动。移动设备上高能耗的数据传输使得存内处理（PIM）成为一种有效的解决方案。由于严格的DRAM成本约束、电路板上有限的物理空间以及应用程序与LLM之间的交互，CPU和PIM必须在共享内存空间内并发运行。然而，可能出现的存储体冲突和总线拥塞等挑战会削弱PIM的性能和能效优势。为应对这一挑战，我们引入了COSM，一种旨在促进移动平台上PIM与CPU任务并发执行的协作调度框架。我们的关键创新包括：1）一种低干扰的PIM控制接口，在不干扰CPU内存访问的情况下生成最大数量的PIM命令；2）一种空闲感知调度方法，将PIM命令集成到CPU访问序列中可用的空闲时间窗口内。COSM不仅对CPU隐藏了PIM执行延迟，还将PIM执行与数据传输重叠。在LLM与移动工作负载（包括移动应用和计算密集型内核）并发执行的实验中，与基准调度方法相比，COSM将PIM吞吐量提升了多达2.8倍，而CPU性能损失小于2.0%。

## Abstract
The development of on-device large language models (LLMs) is driven by the need for privacy and fast response times. Energy-intensive data transfer on mobile devices makes Processing-in-Memory (PIM) an effective solution. Due to stringent DRAM cost constraints, limited physical footprint on circuit boards, and the interaction between applications and LLMs, it is imperative for the CPU and PIM to operate concurrently within a shared memory space. However, challenges such as bank conflicts and bus congestion can arise, potentially diminishing the performance and energy benefits of PIM. To address this challenge, we introduce COSM, a cooperative scheduling framework designed to facilitate the concurrent operation of PIM and CPU tasks on mobile platforms. Our key innovations include: 1) a low-interference PIM control interface that generates the maximum number of PIM commands without disrupting CPU memory accesses; 2) an idleness-aware scheduling method that integrates PIM commands into available idle time windows within the CPU's access sequence. COSM not only hides PIM execution latency from the CPU, but also overlaps PIM execution with data transfer. Experiments on concurrent execution of LLMs and mobile workloads, including mobile applications and compute-intensive kernels, demonstrate that COSM improves PIM throughput by up to 2.8x compared to the baseline scheduling method with less than 2.0% CPU performance loss.

# COSM：面向移动设备上PIM与CPU并发执行的协作调度框架 —— 论文深度总结

## 1. 核心问题与整体含义（研究动机和背景）

- **核心问题**: 如何在移动设备上，高效地实现存内处理单元（PIM）与中央处理器（CPU）在共享内存空间中的并发执行，同时解决由此引发的存储体冲突、总线拥塞等问题，以加速本地大语言模型（LLM）推理，并最小化对CPU性能的影响。
- **研究动机与背景**:
    - **移动端LLM需求**：设备端运行LLM（如1B-3B参数模型）能增强隐私保护和降低延迟，是未来趋势。
    - **PIM的机遇**：移动设备上数据传输能耗极高。PIM通过在DRAM内部集成计算单元，能直接处理数据，绕过有限的外部带宽，显著降低功耗（如三星LPDDR5-PIM原型降低70%功耗）。
    - **共享内存的必要性**：出于DRAM成本、物理空间和应用交互的考虑，CPU和PIM必须在共享的物理内存空间内运行，而非静态隔离。这带来了新的内存管理挑战。
    - **并发执行的关键矛盾**：CPU对内存访问延迟极为敏感；而现有PIM设计在执行（PIM执行命令）和数据传输（CPU介导传输）过程中会对CPU访问造成严重干扰。根源在于PIM控制接口和内存调度策略。
- **核心洞察**：CPU工作负载具有高外部带宽需求但低内部带宽需求（因为行命中率低），而PIM工作负载则相反。这提供了一个机会：可以利用CPU访问的空闲内部带宽来执行PIM任务，从而提升整体效率。

## 2. 方法论：核心思想、关键技术细节

- **核心思想**：COSM是一种**协同调度框架**，通过“低干扰PIM控制接口”和“空闲感知内存调度”的软硬件协同设计，将PIM命令智能地插入到CPU访问序列的空闲时间窗口中，实现两者高效并发，对CPU性能影响极小。
- **关键技术细节**：
    - **低干扰PIM控制接口**:
        1.  **可抢占的PIM执行命令**：引入 `PIM_Exec` 命令，支持PIM单元在无CPU干扰时持续执行（长命令长度），并通过 `PIM_Pause` 命令实现快速抢占，使CPU请求可立即获得服务。这解决了长命令提升PIM性能与短命令保障CPU延迟之间的固有矛盾。
        2.  **带宽解耦的数据传输命令**：将传统的CPU介导的PIM数据传输分为外部带宽传输（`PIM_WrBuf`/`PIM_RdBuf`，使用外部总线）和内部带宽传输（`PIM_StBuf`/`PIM_LdBuf`，仅访问DRAM内部存储体）。这使得两类传输可以被独立调度，避免了对外部和内部空闲窗口的同时需求，从而更好地利用碎片化空闲时间。
    - **空闲感知内存调度**:
        1.  **空闲窗口估计器（IWE）**：通过分析CPU请求队列，预测每个DRAM存储体**未来可用的内部空闲窗口**（因CPU请求间隔或行激活与访问之间的延迟）以及**内存总线空闲窗口**。
        2.  **PIM调度器**：基于IWE提供的信息，从PIM执行队列（PEQ）和数据传输队列（PRWQ）中选择合适的PIM命令（PIM执行或数据搬运），优先利用预测出的空闲窗口。
        3.  **命令仲裁器**：采用严格优先级策略。当无CPU请求可用时，才调度PIM命令。在CPU请求到来时，在最后可能的时间点才发出PIM_Pause命令，最大化PIM执行时间。
        4.  **重叠调度**：将PIM工作负载划分为多个无数据依赖的“图块”，实现一个图块的输入数据传输、另一个图块的PIM执行和第三个图块的结果收集三者重叠进行，进一步提升吞吐量。

## 8. 不足与局限

- **依赖模拟器**：全部实验基于模拟器（Ramulator2），结果高度依赖模拟器模型和参数的准确性，缺乏真实芯片的验证。实际芯片的时序、功耗和干扰可能更加复杂。
