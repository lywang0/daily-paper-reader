## 摘要
CPU是设备端大语言模型（LLM）推理最通用的目标，但现有的低位量化方法要么提供粗粒度的操作点，要么提供细粒度的混合精度，后者难以在CPU上高效执行。我们提出PolyQ，一种面向CPU的编译器/量化协同设计方法，用于在用户指定的平均位宽预算下实现激活感知的逐通道位分配。PolyQ从{2,3,4,8,16}中为每个通道指定位宽，然后使用编译时模型编译器将通道置换并聚类成位同质块，生成兼容SIMD和LUT的内核，并跨算子合并兼容的置换，从而将布局正则化移出运行时路径。这将细粒度的预算适配转化为一种适用于纯CPU推理的实用分数位部署方法。在WikiText-2数据集上，针对Falcon-H1-3B、Llama2-13B和Qwen3-32B模型，PolyQ在3-6比特范围内提供稳定的质量缩放，并在3比特目标下相对于先前方法将困惑度降低了2.4-32.1%。在三个代表性CPU（工作站、笔记本电脑和移动设备）上的端到端测量表明，编译器布局正则化将激活重排序流量降低高达70.8%，预填充延迟和解码吞吐量几乎与配置的位预算成比例缩放，并且相对于优化的基于LUT的后端，每个token的能量开销保持在2%以下。这些结果表明，分数位CPU部署在多种边缘目标上是实用、可预测且节能的。

## Abstract
CPUs are the most universal target for on-device LLM inference, but existing low-bit quantization methods offer either coarse operating points or fine-grained mixed precision that is difficult to execute efficiently on CPUs. We present PolyQ, a CPU-oriented compiler/quantization co-design for activation-aware channel-wise bit allocation under a user-specified average-bit budget. PolyQ assigns per-channel bit-widths from $\{2,3,4,8,16\}$, then uses a compile-time model compiler to permute and cluster channels into bit-homogeneous blocks, generate SIMD- and LUT-compatible kernels, and merge compatible permutations across operators to keep layout regularization off the runtime path. This turns fine-grained budget fitting into a practical fractional-bit deployment method for CPU-only inference. Across Falcon-H1-3B, Llama2-13B, and Qwen3-32B on WikiText-2, PolyQ provides stable quality scaling from 3--6\,b and improves perplexity by 2.4--32.1\% over prior methods at a 3\,b target. End-to-end measurements on three representative CPUs -- workstation, laptop, and mobile -- show that compiler layout regularization reduces activation reorder traffic by up to 70.8\%, prefill latency and decode throughput scale nearly proportionally with the configured bit budget, and energy/token overhead stays below 2\% relative to an optimized LUT-based back-end. These results show that fractional-bit CPU deployment is practical, predictable, and energy-efficient across diverse edge targets.

## 1. 核心问题与整体含义（研究动机和背景）

- **背景**：LLM正被部署到笔记本电脑、边缘服务器和嵌入式控制器等设备端，CPU是这些设备通用性最强的计算核心，但面临严格的内存和功耗限制。设备端推理通常工作在batch=1场景，受限于权重存储和DRAM流量，需要高效的模型压缩。
- **核心问题**：现有CPU低位量化方法存在两大缺陷：
  - **粗粒度统一精度**（如W3或W4）只能提供少数离散操作点，当可用内存被碎片化、预算为分数（如3.8比特/权重）时，要么浪费内存要么超出预算，无法灵活适应实际内存约束。
  - **细粒度混合精度方法**（如SliM-LLM）虽能在层内进行比特分配，但其使用的b±1调色板包含5-7比特条目，与CPU的LUT（查找表）内核不兼容（LUT大小随2^b指数增长），且缺乏8/16比特来保护激活异常值，同时缺乏分数预算控制能力。
- **整体含义**：需要一个联合量化与编译协同设计的框架，使得CPU上能够实现**可部署的分数位混合精度推理**，在保证精度的同时让运行时性能随位预算预测性缩放。

## 2. 方法论：核心思想、关键技术细节

### 核心思想：量化与编译协同（Quantizer-Compiler Co-Design）

PolyQ将细粒度的位预算适配与规则化执行解耦：量化器按通道分配比特（从{2,3,4,8,16}中选择），编译器在编译时通过排列、聚类和内核生成来规则化布局，并传播兼容的排列以减少运行时重排序开销。

### 关键技术细节

1. **激活感知的逐通道误差代理**：
   - 对于每个线性层，对每个输入通道j，计算在不同比特宽度b下的权重重构误差，并乘以激活能量E[x_j²]（来自校准集），得到误差代理E_b[j]。
   - 对于b=16视为无量化，误差为0。
   
2. **分数位预算下的注水分配（Waterfilling）**：
   - 将每个线性层的比特分配视为离散资源分配问题：在用户指定的平均位预算B下，最小化总误差。
   - 从所有通道设为2比特开始，计算剩余预算Δ，然后迭代地从堆中选择每比特误差降低最大的通道升级（如2→3，3→4，4→8，8→16），直到预算耗尽或无法精确匹配。

3. **ISA感知的SIMD量子匹配**：
   - 将水分配结果中每种比特的通道数四舍五入到后端友好的块大小（如SIMD微内核的对齐要求），并通过误差感知的通道重分配（使用相同增益度量）来微调通道归属，确保最终布局符合硬件约束，同时接近目标预算（最大偏差0.045比特）。

4. **基于编译器通道排列与聚类**：
   - 对每个线性层引入排列矩阵P_W，将相同比特宽度的输入通道排列成连续块，形成比特同质块。
   - 低比特块（2/3/4）分配给基于LUT的GEMM/GEMV内核，高比特块（8/16）分配给OpenBLAS SIMD MAC内核。

5. **跨层合并排列**：
   - 利用公式O' = A × (W × P^T) × (P × W')，将激活排列吸收到权重端，使得中间激活无需显式重排序。
   - 非线性和归一化等算子保持通道顺序不变，可传递排列。

6. **基于DAG的图级布局正则化**：
   - 将整个模型视为静态算子DAG，为每条边分配通道基标签，通过拓扑传播和局部冲突解决，最大化兼容排列区域，仅在不可合并的边界插入显式重排序。

## 6. 主要结论与发现

1. **分数位CPU部署是实用的**：PolyQ能精确实现用户指定的分数平均比特预算，在3比特目标下困惑度比先前方法降低2.4%–32.1%，在低比特崩溃点附近（如2.5→2.6比特）实现质量恢复，且峰值内存随预算连续可调。
2. **编译器布局正则化显著减少重排序开销**：激活重排序流量比最佳先前策略降低最多70.8%，将大部分布局管理移出运行时路径。
3. **运行时性能随位预算预测性缩放**：预填充延迟和解码吞吐量与比特预算近乎线性比例变化（2→3比特延迟增加1.56×，3→4比特增加1.38–1.46×），能量/令牌开销低于2%。
4. **协同设计是成功关键**：低比特LLM CPU效率不仅是量化问题，更是量化器与编译器协同设计问题。目标比特宽度成为可控设计变量，同时影响质量、内存和吞吐量。

## 7. 方法优点

- **新颖的分数位控制**：首次在CPU上实现激活感知通道级比特分配，且支持{2,3,4,8,16}连续分数预算，解决了整数粒度与内存碎片化矛盾。
- **联合编译优化**：将量化输出的不规则比特映射通过编译时排列/聚类转化为规则执行块，并跨层传播排列，避免运行时重排序开销，兼顾精度与执行效率。
- **硬件兼容性**：调色板中低比特（2/3/4）直接利用高效LUT内核，高比特（8/16）使用SIMD MAC，无需对5-7比特进行INT8反量化。
- **实用性强**：在多个CPU目标（工作站、笔记本、移动）上验证，能量开销极小，性能缩放可预测，可直接部署。
