## 摘要
大语言模型（LLM）彻底改变了人工智能应用，但大规模部署它们仍面临重大挑战。我们提出RTP-LLM，一个用于工业级LLM部署的高性能推理引擎，已成功部署在阿里巴巴集团，服务超过1亿用户。RTP-LLM通过集成设计解决了基本瓶颈问题。它通过文件顺序驱动的I/O和并行I/O-通信重叠优化了模型加载。预填充-解码分离架构将计算密集型的预填充阶段与内存受限的解码阶段解耦，结合分层多级KV缓存管理实现了高效的缓存重用。此外，RTP-LLM集成了支持多种算法的模块化推测解码、自适应KV缓存量化和解耦的多模态处理，并支持多级并行性。针对不同模型架构（8B-235B参数）进行了全面评估，使用了控制基准测试和实际生产工作负载。结果表明，与vLLM和SGLang相比，RTP-LLM具有优越性能：模型加载速度提升4.7倍-6.3倍，生产流量调度中TTFT P95延迟降低35%-37%，缓存重用提升215%，推测解码和多模态推理的吞吐量分别提升1.12倍-2.48倍和1.86倍-2.52倍，量化推理中批量延迟降低35%-40%，TTFT提升1.9倍-3.0倍。RTP-LLM经过生产验证的架构和开源可用性使其成为工业级LLM部署的全面解决方案。

## Abstract
Large Language Models (LLMs) have revolutionized AI applications, but deploying them at scale presents significant challenges. We present RTP-LLM, a high-performance inference engine for industrial-scale LLM deployment, successfully deployed across Alibaba Group serving over 100 million users. RTP-LLM addresses fundamental bottlenecks through integrated design. It optimizes model loading via file-order-driven I/O and parallel I/O-communication overlapping. The Prefill-Decode Disaggregation architecture decouples compute-intensive prefill from memory-bound decode phases, combined with hierarchical multi-tiered KV cache management enabling efficient cache reuse. In addition, RTP-LLM incorporates modular speculative decoding supporting multiple algorithms, adaptive KV cache quantization, and decoupled multimodal processing, with support for multi-level parallelism.   Comprehensive evaluations across diverse model architectures (8B-235B parameters) have been conducted, where both controlled benchmarks and real production workloads are used. The results demonstrate RTP-LLM's superior performance against vLLM and SGLang: 4.7x-6.3x model loading speedup, 35-37% TTFT P95 latency reduction with 215% cache reuse improvement in production traffic scheduling, 1.12x-2.48x and 1.86x-2.52x throughput improvements in speculative decoding and multimodal inference, respectively, and 35-40% batch latency reduction with 1.9x-3.0x TTFT improvement in quantized inference. RTP-LLM's production-proven architecture and open-source availability make it a comprehensive solution for industrial LLM deployment.

## 1. 核心问题与整体含义（研究动机和背景）
- **核心问题**：大规模LLM在生产部署中面临四个根本性挑战：
  - **GPU利用率低**：动态顺序性工作负载导致计算单元空闲。
  - **KV缓存内存耗尽**：KV缓存随序列和批次线性增长，传统内存分配存在碎片化。
  - **系统僵化**：无法高效处理MoE、多模态等异构架构。
  - **运维脆弱**：模型加载耗时过长，缺少容错、滚动更新等生产级能力。
- **整体含义**：现有系统（如vLLM、TensorRT-LLM、FlashAttention）仅优化孤立组件，缺乏系统性的一体化解决方案。RTP-LLM旨在通过集成设计解决所有四个挑战，提供经过大规模生产验证的高性能推理引擎。

## 2. 方法论：核心思想、关键技术细节、算法流程
### 核心设计理念
采用**集成系统级优化**，而非孤立的组件优化。核心思路：将模型加载、内存管理、调度、并行、量化、多模态等统一到单一框架中，通过协同设计最大化性能。

### 关键技术细节
- **高效模型加载**（解决挑战IV）：
  - **文件顺序驱动I/O**：改变传统按照模型结构读取的方式，改为按文件顺序依次读取所有张量，最大化FUSE预取效率。
  - **混合分布式读取**：集成IBM fastsafetensors库，每个模型文件由单个进程读取，然后通过PyTorch广播共享给所有Tensor Parallel进程，消除冗余读取。
  - **共享内存复用**：复用单一共享内存缓冲区，避免重复注册固定内存的开销（每2GB节省约600ms）。
  - **并行I/O-通信重叠**：将文件读取与广播并行化，降低总体加载延迟。
- **预填充-解码分离（PD-Disaggregation）**（解决挑战I、II）：
  - 物理上将计算密集型的预填充（Prefill）和内存受限的解码（Decode）部署到独立节点，实现独立扩缩和资源最优分配。
  - 支持PD-Fusion（共置）和PD-Disaggregation（分离）两种模式。
- **分层多级KV缓存管理**（解决挑战II）：
  - 四级存储：GPU显存（L1）、本地CPU内存（L2）、远程CPU内存 via RDMA（L3）、分布式存储3FS（L4）。
  - 采用**统一哈希前缀匹配**（Unified Hash Map）：将所有worker的缓存键合并为统一哈希表，实现O(B)复杂度的前缀查找（算法2）。
  - **采样前缀哈希**（Sampled Prefix Hashing）：对超过208 token的块每隔4个位置创建哈希条目，平衡粒度与存储开销。
  - 缓存匹配与调度集成：结合本地和远程缓存匹配得分，加上worker负载信息，进行决策（公式2）。
- **流量调度**（解决挑战I）：
  - 预填充请求：Master根据队列状态、KV缓存占用和预测完成时间（公式1）进行负载均衡。
  - 解码请求：优先利用KV缓存亲和性（chat ID）进行路由。
  - 动态窗口调整：窗口大小w = max(DP_size, |R|) 基于DP组大小和队列深度调整。
- **推测解码**（解决挑战I）：
  - 模块化框架：ProposeExecutor、ScoreExecutor、SpeculativeSampler、SpeculativeUpdater。
  - 支持多种算法：朴素推测采样、MTP（DeepSeek-V3）、Eagle、Prompt Lookup（n-gram匹配，算法3）。
- **自适应KV缓存量化**（解决挑战II、III）：
  - 逐张量/逐块动态缩放，将KV缓存量化为INT8/INT4/FP8，降低内存带宽压力。
- **多级并行性**（解决挑战III）：
  - Tensor Parallelism（TP）、Pipeline Parallelism（PP）、Data Parallelism（DP）、Expert Parallelism（EP）集成，支持MoE模型。
- **多模态解耦处理（EPD）**（解决挑战III）：
  - 将视觉Transformer（ViT）与语言模型分离部署，实现计算重叠和内存优化，减少单设备显存占用。

## 6. 主要结论与发现
- RTP-LLM在所有评估场景中**全面超越**vLLM和SGLang：
  - **模型加载**：1.4x-6.3x加速（大型235B模型达4.7x-6.3x）。
  - **生产流量调度**：TTFT P95降低35-37%，缓存重用提升215%（内部机器人从26.6 token增加到83.8 token），预填充机器数量减少75%。

- 核心原因：集成设计产生协同效应，而非孤立优化。
