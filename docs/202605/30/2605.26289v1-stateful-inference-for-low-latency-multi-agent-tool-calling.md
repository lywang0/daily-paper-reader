## 摘要
多智能体工具调用正成为基于LLM系统的主导交互模式，然而现有的推理框架将每次工具调用视为独立请求，从头重新处理整个对话，尽管85-95%的提示与上一轮相比未发生变化。我们提出了一种有状态推理架构，将传统服务的每轮O(n_t)成本转换为仅处理增量的O(Δ_t)成本：一个持久化的KV缓存跨轮次存在，仅通过吸收新令牌来推进，而基数前缀缓存将这一机制扩展到交错的多智能体流量中，提示查找推测解码器加速结构化输出。在与vLLM和SGLang的对比中，在全新的完全生成的工作负载上，参考实现在6轮智能体工作流中每轮速度快2.1倍，在35轮工作流的中位轮次中快4.2倍，端到端耗时减半。这一优势来自有状态重用和推测，而非缓存。

## Abstract
Multi-agent tool calling is becoming the dominant interaction pattern for LLM-based systems, yet existing inference frameworks treat each tool call as an independent request, re-processing the entire conversation from scratch even though 85-95% of the prompt is unchanged from the previous turn.   We present a stateful inference architecture that converts the $O(n_t)$ per-turn cost of conventional serving into an $O(Δ_t)$ delta-only cost: a persistent KV cache lives across turns and advances by ingesting only the new tokens, while a radix prefix cache extends this across interleaved multi-agent traffic and a prompt-lookup speculative decoder accelerates structured output. Against vLLM and SGLang on novel, fully-generated workloads, the reference implementation is $2.1\times$ faster per turn on a 6-turn agentic workflow and $4.2\times$ on the median turn of a 35-turn one, halving end-to-end wall time. The advantage comes from stateful reuse and speculation, not caching.

# 论文《低延迟多智能体工具调用的有状态推理》详细中文总结

## 1. 核心问题与整体含义（研究动机和背景）

- **背景**：多智能体工具调用（Multi-agent tool calling）已成为基于LLM系统的主导交互模式。典型场景中，一个编排器向多个专用代理（如旅行规划、代码审查、数据分析等代理）分发工具调用，每个代理维护自己的对话历史（包括系统提示、工具模式和累积的工具结果）。
- **核心问题**：现有推理框架（如vLLM、SGLang）将每次工具调用视为独立请求，即使前后轮对话中85–95%的提示完全相同（如系统提示、历史消息），仍会从头重新处理整个提示（full re-prefill）。这种冗余计算导致极高的延迟和GPU资源浪费。对于多轮对话，传统框架的每轮计算复杂度为 $O(n_t)$（$n_t$ 为第t轮的总提示长度），而真正需要处理的新增令牌（delta）通常只占5–15%。
- **整体含义**：本文旨在通过状态化推理（stateful inference）消除冗余预填充，将每轮成本从 $O(n_t)$ 降至 $O(\Delta_t)$（$\Delta_t$ 为新增令牌数），从而大幅降低多轮、多智能体场景下的推理延迟和GPU FLOPs浪费。

## 2. 方法论：核心思想、关键技术细节

### 2.1 核心思想
- **持久化KV缓存**：为每个智能体会话维护一个跨轮次存活的KV缓存，每轮仅处理新增令牌并追加到缓存中，避免重新计算历史前缀。
- **基数前缀缓存（Radix Prefix Cache）**：在统一的KV缓存中通过元数据级别的序列别名（metadata-only sequence aliasing）实现多智能体间共享前缀的常数时间恢复，将每轮成本从 $O(n_t)$ 变为 $O(\Delta_t)$。
- **提示查找推测解码（Prompt-Lookup Speculative Decoding）**：针对结构化工具调用（如JSON格式）的重复模式，利用当前槽位的历史令牌预测未来令牌，并通过单次前向pass进行批量验证，加速生成过程。
- **响应缓存（Prompt-Deterministic Response Cache）**：对完全重复的提示（如重试、轮询），通过FNV-1a哈希使采样器产生确定性输出，直接返回缓存结果，零GPU工作量。

### 2.2 技术细节（9个机制）
| 机制 | 描述 |
|------|------|
| 1. 有状态会话 | 持久KV缓存跨请求存活，只处理新增令牌 |
| 2. 序列池 | 预分配的命名序列ID集合（暂态池+会话池），避免每请求上下文构造开销 |
| 3. 基数前缀缓存 | 基于基数树（radix trie）共享前缀，通过元数据级别序列别名实现常数时间恢复，增量保存仅提交当前轮产生的增量单元 |
| 4. 单元预算接纳与分组预填充 | 连续批处理调度器，根据KV缓存单元上限接纳预填充，对共享相同字节前缀的槽位进行“领导者-追随者”分组预填充，将N次冗余前向pass合并为一次 |
| 5. 提示确定性响应缓存 | LRU缓存，通过FNV-1a哈希种子使得相同提示在任何温度下输出相同结果；命中时零GPU工作 |
| 6. 并发上限提示查找推测 | 每个槽位从近期令牌缓冲区中查找最长后缀匹配的n-gram作为推测草稿，通过自适应上限防止吞吐量崩溃，验证通过则接受 |
| 7. 流式工具调用验证器 | 基于括号平衡的JSON解析器，在结构化工具调用关闭时触发提前停止，过滤虚构工具名，节省20–40%解码令牌 |
| 8. 设备贪婪采样 | 直接在GPU上执行argmax，消除每令牌的主机同步开销 |
| 9. RAII会话生命周期 | 异常安全的序列槽位自动获取/释放，防止多智能体并发泄漏 |

### 2.3 成本公式
传统方式： $T(t) = T_{\text{prefill}}(n_t) + m \cdot T_{\text{decode}}$  
本文有状态+推测方式： $T(t) = T_{\text{restore}} + T_{\text{prefill}}(\Delta_t) + \lceil m/(k+1) \rceil \cdot T_{\text{decode}}$  
其中 $k$ 为成功推测的令牌数（典型值约11），$\Delta_t \ll n_t$，因此速度随轮次加深而提升。完全重复的提示则通过响应缓存返回，无需GPU计算。
