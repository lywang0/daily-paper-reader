## 摘要
将Transformer推理分布在嵌入式边缘设备上可以缓解单个设备的内存和计算限制，但在实际硬件上的实际效益尚不明确：先前的工作主要依赖于忽略硬件特定通信开销的模拟。我们展示了在通过WiFi连接的NVIDIA Jetson Orin Nano设备上进行的硬件原型研究。我们的关键发现是，主要的瓶颈不仅是网络带宽，还有通信过程中的CPU-GPU分阶段处理。由于Jetson的集成GPU架构缺乏NCCL所需的PCIe/NVLink通路，所有设备间数据通信应通过GLOO路由并在CPU内存中分阶段处理；这种开销随通信数据量增加而增大，使得对于ViT等中等规模模型，全张量交换在批量大小下比单设备推理更慢。因此，我们评估了Prism，它将分段均值压缩与轻量级离线性能剖析相结合，以在运行时自适应选择本地执行或分布式执行。实验表明，相对于静态分布式执行设置中的全张量交换，该策略将延迟降低了65%-77%，能耗降低了34%-52%，证明了基于性能剖析的自适应对于嵌入式硬件上的实际分布式Transformer推理至关重要。

## Abstract
Distributing Transformer inference across embedded edge devices can alleviate individual memory and compute constraints, yet practical benefits on real hardware remain unclear: prior work relies largely on simulations that overlook hardware-specific communication overheads. We present a hardware prototype study on NVIDIA Jetson Orin Nano devices connected over WiFi. Our key finding is that the dominant bottleneck is not just network bandwidth but also the CPU-GPU staging during communication. Because Jetson's integrated GPU architecture lacks the PCIe/NVLink pathway that NCCL requires, all inter-device data communication should be routed through GLOO and staged in CPU memory; an overhead that scales with communication data volume and makes full-tensor exchange slower than single-device inference across the batch sizes for medium sized models such as ViT. We therefore evaluate Prism by combining Segment Means compression with lightweight offline profiling to adaptively select between local and distributed execution at runtime. Experiments show that this strategy reduces latency by 65%-77% and energy consumption by 34%-52% relative to full-tensor exchange in static distributed execution setup, demonstrating that profiling-driven adaptation is essential for practical distributed Transformer inference on embedded hardware.

## 2. 论文提出的方法论：核心思想、关键技术细节、公式或算法流程

- **核心思想**：采用 master-worker 架构，终端设备沿序列维度将输入划分给多个边缘设备；每个设备只处理自己分到的 token 分区，但通过交换**紧凑的 Segment Means（分段均值）**来近似全局上下文，从而大幅降低通信量。同时引入离线 profiling 阶段，收集不同 batch size、压缩率、网络带宽下的性能元数据，运行时根据当前条件查询性能地图，自适应选择单设备或分布式执行（及最佳压缩率）。

- **关键技术细节**：
  1. **Segment Means 压缩**：  
     对于每个分区 Xₚ ∈ ℝ^(Nₚ×D)，将其均匀分为 L 个不重叠段，取每段列平均，得到 Zₚ ∈ ℝ^(L×D)。  
     通信量从 Voltage 的 (P−1)·(N/P)·D 降为 (P−1)·L·D，其中 L ≪ N/P，压缩率 CR = N/(L·P)。  
     每个设备收到其他所有设备的 Segment Means 后，与自己的原始分区拼接成增强表示 Ĥₚ，然后计算自注意力（query 来自自身分区，key/value 来自增强表示）。
  2. **缩放感知 softmax 重构**：利用增强表示的重复结构避免冗余 K/V 重计算，减少每设备 GFLOPs（两设备时最高减少 50.11%）。
  3. **离线 profiling**：一次性离线阶段，遍历 batch size B ∈ {1,2,4,8,16,32}、压缩率 CR ∈ {3.3, 4.95, 9.9}、网络带宽 BW ∈ {200,300,…,900} Mbps，记录每种组合下的总延迟、每样本延迟、每样本能耗以及计算/通信/CPU-GPU I/O 三部分 breakdown。数据存储为轻量 JSON 文件。
  4. **运行时决策**：当新 batch 到来，终端设备获取当前 batch size 和实测网络带宽，查询性能地图，选择最小化每样本延迟或能耗的执行模式（单设备 vs 分布式+最佳 CR）。

- **算法流程（文字说明）**：  
  训练/部署前：一次离线 profiling → 生成性能地图 → 部署到终端设备。  
  推理时：输入 batch → 终端设备观察 B 和 BW → 查询地图 → 若单设备最优则本地执行；否则执行分布式：分区→计算 Segment Means→GLOO 通信→增强表示→自注意力→输出。  
  自适应切换减少了不必要的小 batch 分布式的固定开销。

## 6. 论文的主要结论与发现

1. **GLOO staging 是实际瓶颈**：在 Jetson 上全张量交换（Voltage）的 CPU-GPU staging 开销占主导，使得分布式推理在任何 batch size 下都慢于单设备。
2. **Prism 压缩有效**：Segment Means 压缩（CR=9.9）减少了约 90% 的通信量，将 staging 降为次要因素，使得大 batch 下分布式推理优于单设备。
3. **自适应交叉点**：batch size ≤4 时，单设备推理更优；batch≥8 时，分布式 Prism 胜出。该交叉点依赖于模型和硬件，需 profiling 确定。
4. **性能增益**：相比 Voltage，Prism 延迟降低 65%-77%，能耗降低 34%-52%（在不同 batch 下）。
5. **准确率小幅下降**：CR=9.9 时 CIFAR-10 准确率从 98.01% 降至 95.64%，微调后可恢复至 97.43%（仍略低于原始）。较低 CR（3.3）可保持 97.06% 但通信节省较少。
6. **带宽影响**：Voltage 对带宽高度敏感，Prism 在 340 Mbps 以上即可优于单设备。
